## 排查标准

- 分开测量模型等待、主进程执行、IPC 等待、受保护界面读取和浏览器绘制。不能以模型响应慢解释窗口缩放卡顿。
- 复现正在回复、工具运行、长历史滚动、会话切换以及窗口宽高变化。静止页面和小型组件单测通过，不能代替运行中的应用验收。
- 前后比较保持输入、历史长度、工具调用和采样安排一致。性能测量独占测试负载，避免同时构建或跑全量测试。
- 记录中位数、P95、最大等待、加载慢样本和内存；不能只挑平均值。CPU profile 用于定位，最终还要复测用户路径。
- 不通过延长 5 秒提示阈值、裸文本回退、缓存授权结果或忽略插件撤销来让结果变好。

## 已确认的问题

1. 流式受保护正文的结果已通过同一来源、同一前缀链的有效性判断，却再次被“必须等于最新输入版本”的判断丢弃。快速持续输出时可能始终不能显示。
2. 固定位置的灵件在纯宽高变化时撤掉原有受保护呈现，等待新读取。主进程忙时，调整窗口也会变成加载占位。
3. 主进程多层历史校验反复读取线程和解释相同元数据；只减少 JSON 解析不能消除数据库调用和完整校验的放大。

## 修复边界

流式正文可显示已经验证的同源前缀，旧输入动作保持禁用；换线程、内容替换、截断或源撤销仍使旧结果失效。布局变动只允许经过范围检查的几何字段保留旧呈现，新读取完成前旧动作不可调用。窗口与 ResizeObserver 通知合并到动画帧。

元数据缓存只保存有上限的、完全相同原始文本的纯解析结果，每次仍读取当前数据库状态。历史批量读取只适用于可确认的原生运行时与原生存储方法，其他路径保留原校验。批次提交前后仍要检查来源和内容，独立回检发现的问题必须修完再测性能。

Store 的原生线程身份读取另增加了传输去重：同一条 SQL 同时返回当前创建时间、原文是否完全相同，以及变化后的元数据。只有 SQLite TEXT 且 BINARY 精确相等时才复用之前的原始字符串；单个读取器只保留最近线程、最多 512 KiB 文本。删除、重建、NULL、类型变化和关闭数据库仍走当前数据库结果。未扩大到普通可覆写读取器，也未改变 JSON 解析或身份判断语义。真实 SQLite 窄测覆盖 NOCASE 列、BLOB、数值、中文、代理字符及可变返回行。

原生 run facts 身份检查复用同一读取器。投影 receipt 在单次 pin 内的第二、第三次读取增加了相同原文传输去重；第一次仍读取完整载荷，后续仍读取全部原校验字段、精确比较原始 TEXT，不以长度或 digest 代替原文相等。非原生适配器、不可无损传输的字符串保留原路径。没有缓存授权结果、延长凭据寿命或减少实时检查次数。

工具执行采样另定位到 Store 的两个联合身份查询仍重复传输完整 metadata；现已覆盖普通联合查询和带高水位的联合查询。所有 JOIN 条件、身份列、创建时间及高水位仍在同次 SQL 中读取。独立回检指出新增参数须扩展防重入资格检查；已补齐 Store 四参数、run facts 两参数，以及预热后失去资格时绕开两参数缓存、回到原单参数读取的兼容路径。此项没有改动 checkpoint 消息方法或放宽消息纯度要求。

### 剩余主进程热点的独立复核
