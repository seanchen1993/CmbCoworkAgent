# ui.log 桌面适配

```ts
$.ui.log("已读取当前配置")
$.ui.log("缓存未命中", { to: "debug" })
on("ui.log", ($, event, next) => next({ ...event, to: "debug" }))
```

默认 `to: "transcript"`：在当前会话展示区追加带插件名称的暗色日志行，同时写入应用
受保护的主进程调试日志。`to: "debug"` 只写调试日志。该方法返回 void，宿主会在 hook
结束前结算未 await 的调用；日志操作会经过其他 hook，跳过调用方当前 registration。
插件不能指定或重写归属名称。两个输出通道都在宿主发布过滤之后接收文本。

日志与消息记录、模型上下文、检查证据和 checkpoint 回执分离。日志顺序按调用预约序号
保持，异步过滤不会颠倒前后条目；被拒绝的条目不会堵住后续条目。嵌套日志不会等待
外层预约完成，因此不产生自锁。延期展示仍保留原始 dispatch 的取消边界和当前授权。

每条最多 10000 字符，同时待结算条目最多 32，展示历史最多 64 条/256KiB UTF-8；UI 有
独立滚动高度限制，40ms 合并刷新，没有空闲轮询。关闭、撤权和 runtime 替换会清除展示
状态与待结算队列，debug 的既有记录仍是历史日志。renderer 重载会读取仍存活的 session。

对照官方 2.1.278 的 `ui.log` 声明标为 **adapted**：目前展示历史为 session 内记录，
没有把它写入可导出的持久会话 transcript，也没有 headless/SDK 的 `ui_log` 输出通道。
它不等同于 `ui.notice`（打开的工具对话框提示）或 `ui.ask`（原生问答工具），后两项仍
单独实现。host revision v43，已有授权需要按新摘要重新确认。
