# 跨会话搜索 P0 试测

实施基线为本地 `uat-without-mods` 的 `f0bcc2a4a`，开发分支为
`codex/conversation-search`。

## 复现

Windows 上的初测使用 Node 20 运行脚本。当前脚本用 electron-vite 打包应用实际使用的
`?nodeWorker` 入口，生成临时 ASAR，再用仓库安装的 Electron 启动并打开只读 SQLite。
测试数据库和应用数据保存在临时目录内。

```powershell
node tests/run-thread-search-probe.mjs
```

默认每组测量 30 次，快速试测可设置 `CMB_THREAD_SEARCH_PROBE_ROUNDS=3`。
夹具种子为 1729，包含 10,000 个会话、100,000 条消息和约 252.6 MiB 的正文源数据。
消息包含 Markdown、结构化文本、工具摘要和分片，近期及最老的唯一正文命中跨越分片边界。
当前探针使用应用的搜索 schema，校验预期会话 ID、覆盖状态和结果页序列化大小，
并验证两种全量场景均处理全部 10,000 个会话。下文的 P0 历史数据来自接入前的试测。

## 代码检视与回归

- 候选冻结后，每批读取在同一 SQLite 读事务内复核会话身份。同 ID 删除重建不会把新会话正文归到旧结果。
- 先读取分片字节数并计入剩余预算，通过预算后才读取正文。超限行会推进游标并留下跳过计数。
- 搜索和历史消息恢复共用正文及工具调用的裁剪逻辑，坏的工具调用项不会阻塞同一行里的可见正文或有效摘要。
- 已单独展示的推理从正文搜索投影剔除。正常回顾旧消息时仍可定位同一条消息的可见回复。
- Markdown 普通文本按片段投影，遇到特殊分隔符时保留原处理规则。从同一随机种子生成的 20,000 个样本与基线逐项比对一致。

最终改动通过 67 项相关单测，另通过 `tests/thread-messages-db.spec.ts`、构建、类型检查和改动文件 lint。
真实 Electron 聊天导航 E2E 通过 18 项，覆盖持久化、快捷键、历史窗口定位、高亮、文件面板与受控流式回复。
独立 `f0bcc2a4a` 工作树复现了浏览器扩展测试文件缺失。全仓测试和 lint 的失败仍需在发布前处理。

真实应用 E2E 命令如下。脚本用受控 producer 替换模型调用，保留实际 Electron、preload、IPC、SQLite 和渲染路径。
E2E 截图存放在配置的产物目录，默认位于 `output/chat-navigation/e2e`。

```powershell
npm run test:chat-navigation:e2e
```

断点续跑与首次布局从只读快照核验持久化来源和真实正文。发布时核对结构版本、消息版本、

重新打开会话也会保留旧正文并清理未发布的分片。隐式 ID 通过用户轮次和相邻持久化消息确认归属，
新 checkpoint 可以改写尚未发布的尾部。无共同消息的已确认子 checkpoint 接在父历史之后。
