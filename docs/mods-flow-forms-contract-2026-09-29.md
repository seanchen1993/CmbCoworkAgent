# DIY 使用成本迭代：参数表单与输入来源契约

本轮在 codex/mods-v2 增量实现。目标是让用户配置常见插件动作和 MCP 参数时不必手写 JSON，
同时保留已有输入、授权与运行语义。无所属插件的流程、组件拆分属于后续授权契约升级，
本轮不通过隐藏或绕过授权实现它们。

## 需要双评审确认的契约

1. 在动作导出增加可选 configSchema，与 inputSchema/outputSchema 采用同一个宿主校验器，
   包装清单及源码摘要仍覆盖声明。省略 configSchema 的旧包保持原行为；不得自动填 schema 默认值。
   目录传递 configSchema，准备阶段及实际调用前由宿主校验 config，不能只依赖页面。
2. 表单只支持明确可无损编辑的 schema 子集：对象根、顶层字符串/数字/整数/布尔/简单枚举；
   复杂属性或未知字段必须保留且有明确 JSON 高级入口，不能切换视图时删值/改类型。
   不为缺失 schema 猜测模型字段。可选字段支持不设置，false/0/空串不能与缺失混淆。
3. 使用稳定的来源身份（pluginId + actionId + digest；MCP provider + toolName + schemaDigest）
   取 schema。旧摘要在新目录找不到时提示重新选择，不借用同名新版 schema 更改旧步骤。
4. 无效 JSON 或未完成数字草稿阻止保存/运行，不能回退到上一份有效值静默保存。
   切换步骤或编辑模式保留草稿；切换提供者不得偷偷丢参数，不运行任何插件/模型发现表单。
5. 来源绑定沿用现有 inputFrom 对象语义、固定输入覆盖同名字段。提供“完整输出”及已知对象路径
   选择，保留高级 JSON Pointer。声明只能做编辑提示，运行时仍验证真实结果及后置 inputSchema。
   不假装有逐字段映射、任意表达式、输出 schema 完整推导或隐藏转换。
6. 表单标题、说明、必填及类型清晰；浅色/暗色、窄屏可操作。提供短说明：保存不执行，应用后用
   聊天中的“执行流程”。错误指向具体步骤/字段，不让用户仅看到内部异常码。

## 两位评审提出的实施前约束

- inputFrom 已绑定时，必填输入可能来自前一步，不能用固定 input={} 判缺失而阻断编辑；
  已填写常量仍校验类型，实际合并后由宿主完整校验。config 独立，按 config??{} 无条件校验。
- 动作身份必须包含 pluginId/plugin/digest/actionId；MCP 必须含 provider 的 id/name/digest、
  toolName、schemaDigest，不能对同名新版借用 schema。
- 编辑器独立上报 dirty 和 valid。无效 JSON/数字即使未写入 definition，也必须阻止保存、
  运行和到聊天，并参与切流程/复制/离开本面板的未保存提示。禁止默默运行旧的有效参数。
- 切步骤/编辑视图保留草稿；明确放弃、重载、新 revision 用独立编辑会话 key 清掉旧局部草稿。
- schema 新字段有值才进入新规范化声明；旧包未声明时保留旧摘要及授权语义。

## 验收

- 实际 Autobiz prepare-review 的 feature/path 可表单填写；Review 前步完整输出通过选择配置；
  有作者 configSchema 时可编辑配置，旧无 schema 配置仍保留 JSON。
- 正常/缺失/错误 config、旧包兼容、声明摘要更新、更新前旧引用、无效草稿、false/0/空串、
  未知嵌套值、模式切换、前步输出及常量覆盖均有回归。
- 两位 agent 分别评审设计和实现；类型、定向 lint、构建、完整单元回归、真实浏览器表单与
  Electron 原跨插件/Flow/传统 Plugin 模式回归。记录既有失败，不宣称全仓全绿。
- 文档同步哪些限制已消除、哪些仍存在；不修改 UAT、不提交生成包或日志。
