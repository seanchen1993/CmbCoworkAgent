# 主版本稳定：重新测量共享任务

交付包保持冻结，附加接口不开放。上一轮真实共享任务完成了全部七项业务检查，
父任务用时 40.144 秒，超过 30 秒目标。该记录使用了测试专用观察器，旧 CPU
采样又早于多项修复，不能据此继续删除权限检查或缓存仍可能变化的状态。

## 本次最小方案

只改两个测试文件：允许现有 `session-append-shared` 专项显式启动交付包，
复用已经通过检查的包启动助手，核对实际程序、ASAR、打包状态和无测试入口。
普通构建及其可选 APP_DIR 启动保持；包模式其它明确指定的专项先拒绝，不能
把默认包检查冒充用户指定专项已通过。

在包模式下明确跳过开发目录里的私有观察器，不能仅依赖那个文件碰巧不存在。
结果写明生产包无此观察器，不能将没有采集的数据写成零次检查。
真实模型、两个共享子助手、工具、历史、提醒、退休拒绝及后续普通聊天检查保持。
首次复合任务仍用原 60 秒功能上限，记录 30 秒性能目标；后续普通聊天仍用 30 秒。

两位独立设计及源码审查后，先用同一已交付包关闭所有可选采样做真实测量。
若仍慢，再单独开启已有 Main CPU 采样；记录覆盖的真实阶段，保留首错误和
采样器关闭结果。不同层的嵌套时间不能相加，也不能把整个检查的总时间当父任务耗时。
检查前后包摘要核对，不重建、不修改交付包、不安装 NSIS。

本次先取得可信测量，再决定是否需要修改业务代码；不承诺尚未测得的性能提升。

本轮没有修改业务代码或交付包，也没有宣称性能达标或不可适配的框架限制。

后续已在同一包的主进程里完成[隔离读取比较](mods-main-fresh-settings-read-study-2026-10-07.md)：

若继续优化，先按已有采样拆清具体调用责任，或在隔离文件上测量新鲜读取方式。

本次面客主版本交付的前置条件。主版本的其它主要链路及存量功能验收记录继续保留。
