# 插件用户配置迁移与项目试用配置

本功能是工程扩展。原 `userConfig` 的字段类型、枚举、默认值及原配置存储保持兼容；`userConfigSchema` 不是 Claude Code 的既有配置协议。

## 必需兼容声明

声明迁移的文件必须同时声明以下兼容标记。例如原生 `mods/manifest.json`：

```json
{
  "apiVersion": "cmb.mods/v2",
  "id": "example-config",
  "entry": "register.ts",
  "cmbCompatibility": {
    "modelProtocol": "result-v1",
    "userConfigMigrations": "v1"
  },
  "userConfig": {
    "label": { "type": "string", "title": "名称", "description": "用户名称" }
  },
  "userConfigSchema": {
    "version": 1,
    "migrations": [{
      "fromVersion": 0,
      "toVersion": 1,
      "changes": [{ "kind": "rename", "from": "oldLabel", "to": "label" }]
    }]
  }
}
```

`userConfig`、`userConfigSchema` 和兼容标记应放在同一配置声明文件。原生声明和原包声明不可重复定义。只写 schema 或只写标记均拒绝加载。旧客户端原 `cmbCompatibility` 解析器只接受 `modelProtocol` 一个字段，因而会明确拒绝带新标记的包；不会在忽略迁移规则后继续加载。该标记不修改宿主版本或所有现有插件的授权摘要。

## 迁移约束

无版本声明的非空旧记录视为版本 0，需要显式连续迁移链。每步只支持字段重命名或删除，不执行作者脚本，也不能声明迁移已经完成。已有目标值冲突、未知旧字段、类型或枚举不兼容、降级和缺少迁移链均保留旧记录并给出诊断；不会重置为默认值。

迁移须由用户在原生配置面板和本机确认框中确认。确认绑定当前源码摘要、工作目录、保存版本与迁移摘要。敏感字段重命名由主进程使用原操作系统保护服务解密，并按新字段身份重新加密；明文不进入模型、导出包或状态接口。操作系统保护不可用、配置版本变化或原生页面/会话身份失效时拒绝写入。插件迁移不能覆盖平台配置项。

## 项目与隔离试用

项目原生权限面板复用同一个用户配置编辑器和存储。配置来源由宿主从当前项目保留的包快照解析，不接受模型提供的路径。存储身份使用实际编译名称和实际项目工作目录，不使用显示名猜测。未安装的试用包也可以填写必需参数、选择本机目录和保存敏感字段。

保存配置不授予代码执行权限。必需参数有效、迁移完成后，仍须确认当前源码的原生权限。项目操作运行中或结果未知时不能修改参数；已准备操作的输入指纹包含原配置身份，参数变化后必须重新核对。项目配置面板不重新加载同名聊天会话，后续项目操作通过原执行通道读取保存值。

## 回归证据

`src/main/mods/v2/loader.test.ts` 实际执行仓库 HEAD 中的旧解析器验证拒绝新标记，并验证新解析器的严格字段边界。

`src/main/ipc/project-runtime-mods.test.ts` 使用真实项目快照、原配置 SQLite 存储和原权限探针，覆盖未安装试用包配置、敏感值脱敏、保存版本冲突、来源与目录核对，以及目录选择/迁移确认期间原试用身份失效时保留原记录。
