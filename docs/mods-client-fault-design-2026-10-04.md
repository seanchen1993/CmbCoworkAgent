# 组件出错后的通知与一次恢复：实施方案

原版依据见 mods-latest-289-audit-2026-10-04.md。固定 289 实际原版十项对照已通过。本方案先把已经能运行 Client 的桌面 Pane 链路补齐；其它绘制位置仍需后续接真实 Client 宿主，不冒称本阶段覆盖所有位置。

## 用户能看到的效果

原来组件一旦出错，只能显示“组件已停止”。现在作者可以收到实际故障通知，显示备用内容；异步点击也能正常修改本地状态。聊天、其它面板和其它正常组件继续使用原来的入口。

## 基础边界

1. 将 Client 内部 listener 与同步 draw 分为两次实际 VM 调用。listener 真正 await；拒绝为 run，成功后 draw 抛错或不合格树为 render，加载失败为 load。阶段由宿主调用位置决定，不信任组件错误码或自报字段。初次 render/frame 只调用 draw，避免增加无必要往返。保留 message、dirty、定时器、控制句柄及单实例串行语义，draw 仍拒绝 Promise。
2. 只有实际 VM 加载、listener 和 draw 内部故障能生成通知。普通参数拒绝、宿主内容保护失败、撤权、关闭或过期身份不是模块故障。复核当前真实所属组件、Session、原批准、实例对象、面板对象及 generation 后才允许通知。停止 Client VM 后使用独立故障回执信号，绝不复用已取消的 Client 执行信号或恢复其权限。
3. ui.fault 仅派发到失败组件所属插件，包含固定 surface/component/requestId/element/module/phase/reason。所有字段固定，省略沿用，改写拒绝；结果为观察用的空对象。reason 只取错误文本，规范成 1–200 字单行、去控制字符、长文本加省略号；经过原内容保护后再提供给插件。不按它执行任何动作，不把它作为权限依据，也不先显示未保护的异常。
4. 失败实例先停止，再独立调度通知。不能在 Client.serial 或 Pane.snapshot 内等待自动重画，避免等待自己。通知完成后，由私有 Pane 回执确认仍是同一个实际面板和 generation，只把该面板标记为 dirty，再从独立队列触发真实 snapshot。关闭、替换、显式刷新、撤权或重载使旧回执失效；迟到故障不得动新实例。
5. Pane 保存私有故障刷新来源，只标记这次恢复绘制中新出生的 Client。它再次失败仍通知，但不自动重画。相同 generation 的多个故障合并一次恢复；原有正常实例不会因父面板重画丢状态。显式 invalidate 清除待恢复来源，但同 key/module 的停止实例仍保持停止；换 key、移除再加入或真正重载才是新实例。
6. 故障通知最多对应现有受限 Client 数，不额外暴露 SDK 发送入口。独立入口保持只读后台身份，沿用原活动记录和真实 finally；关闭/移除时中止故障回执。对 native 宿主 publication 失败保留 fail-closed，不按错误码猜模块异常。新增宿主行为更新版本，现有批准不能悄悄取得新行为。

## 验证与评审

正式实现前取得两位独立方案评审。先补真实 QuickJS 回归并跑红：三阶段故障、只通知所属者、字段固定、原因保护、异步 listener 成功/拒绝、handler 后 draw 错误；一轮恢复与新实例再次失败、同 key 停止状态保留、多组件/多面板、同时故障、迟到替换、撤权/关闭、恶意原因、内容保护拒绝、串行等待和残留活动。

真实 Electron 安装、批准、打开面板、点击及备用内容恢复；检查 utility process、真实原聊天继续和撤权/关闭，保留截图。运行 Client/focus/busy/Pane/内容保护邻近回归、类型和本阶段 lint、冻结受控广域回归。测实际连续点击样本和恢复样本，不将 VM 本地性能说成模型或网络性能。两位实现检视通过并记录准确范围后，继续下一阶段。

两位独立正式方案及最终静态复审已通过；实际验证账本见 mods-client-fault-stage-2026-10-04.md。整体对齐目标继续进行中。
