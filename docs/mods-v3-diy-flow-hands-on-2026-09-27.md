## 这次终于能 DIY 什么

现在可以直接在界面编排“谁做什么、先后顺序、何时执行、失败交给谁、哪里由人确认”。宿主按保存的版本执行，主模型不能自行忽略这些步骤。不是在聊天里换一种 `/my-claw` 提示词，也不只是勾选完成检查。

例如同一个订单导出任务可以保存成：

| 用途 | 你的配置 | 实际执行效果 |
| --- | --- | --- |
| 快速修小问题 | 编码 → 单元测试 | 少一次独立评审 Agent 调用 |
| 正式交付 | 需求分析 → 编码 → 独立评审 → 单元测试 → 人工验收 | 多一个只读角色审查；最后停下来等你确认 |
| 失败自动修复 | 单元测试失败 → 编码，最多回退 2 次 | 真正重新调用编码 Agent，然后重新测试；不是把失败结果改为通过 |
| 高要求交付 | 正式交付 + E2E + Autobiz 阶段推进 | 运行项目 E2E 脚本、上游验收器，合格且确认后推进一个合法阶段 |

Agent 步骤能单独选择角色和模型。真实检查使用项目脚本或原生验收器，不能用“模型说测试通过”代替退出码与验收证据。

## 从哪里进入

1. 在上述开发目录按 `.nvmrc` 使用 Node 22，运行 `npm run dev`。
2. 打开一个**普通本地项目会话**，选中你的 Autobiz 项目目录。
3. 首次使用，在「自定义 → Function Mods」安装/授权 Autobiz Mods，并开启 Mods。安装和权限仍由这个页面管理。
4. 在「自定义 → DIY 流程」进入流程编辑器。聊天任务区也有「DIY 流程」入口。
5. 从 Autobiz 模板新建，选择已授权 Mods，填写任务目标。安装与运行授权和流程保存是独立操作。

普通插件、Mods 安装授权、应用完成规则、DIY 流程是不同层次：插件承载扩展代码；授权决定能做什么；完成规则设定必须达到的底线；DIY 决定本次任务怎么做。关闭 DIY 的某个检查不等于取消管理员的强制完成规则。

## 一个可重复的体验：订单 CSV 导出

演示项目位置见交付报告中的“演示材料”。项目包含 `requirements.md`、有缺陷的 `order-export.cjs`、7 项真实业务断言和 Autobiz `order-export` Feature，起点为 `requirements_eval_in_progress`。

任务目标填写：

> 按 requirements.md 修复 order-export.cjs。保留原始需求、business.spec.cjs 和 package.json。实际运行测试，按本 Feature 当前阶段的要求记录验证结果；不得直接编辑 state.json 或 STATE.md 来跳过验收。

第一次体验建议：启用「编码与修复」「独立代码评审」「单元测试」「人工验收」；暂不启用需求分析、方案设计、E2E、阶段推进。为编码选择可用模型，评审保留 `verification` 只读角色或选择你已有的只读评审 Agent。点击保存，再启动。

观察这些具体区别：

1. 界面出现冻结的版本号与每个步骤的运行记录。运行中修改草稿只影响下次运行。
2. 测试若失败，流程按你指定的失败路线回退；达到次数上限仍失败就停止。
3. 若有文件编辑、执行命令等权限请求，流程页会提示“原生审批待处理”。点击返回当前任务，使用原有审批卡片处理，再从任务入口回流程页。人工成果验收与工具权限审批是两回事。
4. 末尾人工验收在最终真实检查后只询问一次。点击同意才能完成，点击拒绝立即停止。
5. 关闭独立评审并另存/保存新版本再次运行，运行记录应显示该步骤跳过，少一次评审 Agent 调用。
6. 对两个没有依赖关系的分析步骤使用上移/下移，保存后再次运行，真实调用顺序随保存顺序改变。存在条件依赖的步骤不能任意调换，编辑器会说明无效原因。

## 配置条件和失败路线

每一步的“执行条件”只能引用前面已启用步骤的业务通过/不通过结果。未执行、已跳过、已失效的结果不能满足条件。

例如：评审通过走到单元测试，评审不通过回到编码，最多 2 次。回退后旧结果会标记失效，重跑产生新记录。工具被用户明确拒绝、取消、宿主异常不沿业务失败路线继续执行。

部分既有工具把只读/文件边界拒绝作为普通工具错误返回给模型，模型仍可能把它解释成业务失败并触发已配置的回退。这个区别不会让被禁止的工具操作获得权限，也不会让后续 Agent 继承更高权限。

## 打开 Autobiz 阶段推进

选择真实 Feature `order-export`，核对当前起始 checkpoint，再启用位于末尾的「Autobiz 验收并推进阶段」。程序会运行所选检查、应用强制规则及上游 Autobiz 验收，核对成果指纹，完成必要的人审，然后以原生 CAS 方式推进一个合法阶段。

如果没有对应阶段要求的文件、测试失败或人工拒绝，阶段不会推进。阶段推进是单个 checkpoint 转换，不表示从任意阶段自动完成整个 Autobiz 生命周期。

等待确认时有人修改项目，旧同意不能覆盖新成果：系统会刷新确认，并重新验收和展示新结果。持续改动达到最多 3 轮最终验收或总时间/执行次数上限后会停止，需要稳定产物后重跑。

## 当前边界

- 首版面向普通本地项目；Harness、远端、子任务、自动调度入口不提供此流程编辑执行能力。
- 每条流程最多 64 个步骤，最多 256 次执行，总时间最多 60 分钟，**包含人工等待**。每任务保留最近最多 20 次运行，并受总大小上限约束。
- 相同项目的 DIY 流程互斥。其他工具/会话仍可能改动项目，因此使用指纹重验，不宣称全项目所有写入都被锁住。
- 重启后未完成运行标为中断/结果未知，不自动重放可能已生效的动作。先核对产物再建立新运行。
- 不提供任意代码表达式、无限循环、跨项目并发画布和通用暂停恢复。它们不影响本轮步骤选择、排序、角色模型、条件回退、人审与验收的主要目标。
