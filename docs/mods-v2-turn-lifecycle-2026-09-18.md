# Mods v2：真实轮次事件与停止链路

实施分支 `codex/mods-v2`，代码起点 `16029109`。宿主修订
`desktop-turn-lifecycle-v20`。本记录仅覆盖本次接入，B3–B8 的整体验收尚未完成。

## 用户可见效果

更新并重新批准 `function-commands` 示例后，正常聊天轮次结束会显示插件附加说明。
输入 `/claw-turn` 可查看真实轮次状态，运行时输入 `/claw-turn abort` 停止当前轮次。
这些命令不发起额外模型请求。结束 hook 的文本作为附加说明显示，不修改模型回复。

公开入口为 `on("turn.start", ...)`、`on("turn.complete", ...)` 和
`$.turn.abort({ turnId })`。主会话开始、普通完成、失败、取消和暂停恢复使用同一生命周期。
模型初始化重试不重复开始事件；审批暂停不会提前完成，恢复时保留本轮观察到的用量。
实际模型响应没有用量或模型名时不捏造统计。

## 宿主边界

- 轮次身份来自实际执行入口，取消回调直接连接该次运行的 AbortController。
  workspace、thread、turn 和当前物理执行实例均核验，旧回调不能停止新轮次。
- 完成前清除活动轮次，完成 hook 等待物理线程租约释放。不得持有租约等待一个又要
  排队取得该租约的命令或压缩操作。
- 取消成功的调用只保留本次结果发布凭据，不恢复已经失效的运行时权限；新增 SDK 调用
  仍需核验存活的执行范围。凭据不能跨 workspace、thread、新调用或已结束的异步范围使用。
- 模型响应按真实响应 ID 去重；token 统计区分普通输入、缓存读取和缓存写入。
  中断时保留已发布的最后一段模型文本，不把 reasoning 块算作回答。
- 活动及待完成轮次上限 100；单轮最多记录 10000 个响应身份；附加说明最多保留
  64 条且总序列化结果不超过 1 MiB。配置变化、线程关闭和管理器关闭都会清理。
- 文本进入 hook 前和最终显示前均经宿主输出策略。附加文本为空或等于原回答时不重复显示。
