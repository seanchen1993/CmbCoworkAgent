# Sparks 整体回检与体验优化

本轮按用户要求重新检查开发分支的运行时、连续使用体验、UAT 存量回归和新增能力。
所有产品修改限定在 `C:/ai/CmbCoworkAgent-mods-v2` 的 `codex/mods-v2`。
两名既有 medium 子 agent 分别审查运行时和产品流程，再交叉检查修复。

**本轮回检和修复已完成：全仓主测试首次三项超时，原时限复测通过，后续 15 个独立测试链全部通过；120 秒热切换门槛仍未达标。**
首次失败和复测结果分别保留，不将复测通过改写为原始完整命令通过。

## 发现与修复

| 问题 | 用户影响 | 本次处理 |
| --- | --- | --- |
| 失效开发 scope、停止实例和 prepared 内存记录未正确回收 | 多次创作或停止后耗尽名额，停止一个组件后仍不能试用另一个 | 仅回收宿主已证明停止且没有活动或清理中的记录；活动、排空中和未知状态保留 |
| 删除开发会话没有可靠结算旧实例 | 永久占用名额，迟到回调可能与新会话混淆 | 捕获旧实例和会话代次，等待实际 close/drain；任一失败记 unknown，不更改重建的会话 |
| 正式复用的操作回执随页面卸载丢失 | 安装后切到其他设置页，返回时无法准确继续 | 有界进程内缓存绑定精确来源与版本；返回后只读核对真实状态，再允许继续 |
| 成功应用 Claw 后仍可重复执行 | 重复保存新的组合 | 保留已应用组合的精确身份，禁用重复应用；部分成功结果继续显示 |
| 聊天内首次读取创作状态失败被隐藏 | 用户看不到失败，也无法重试 | 显示紧凑错误和重试；正常关闭创作时仍不显示卡片 |
| 阅读说明需要离开当前任务 | 难以发现用法，文档与当前版本不易对应 | 模块顶部加入“官方说明”超链，八章随应用打包，应用内离线阅读 |

复用缓存不是授权缓存：不保存用户同意勾选，不恢复运行权限。缓存满时给出等待、关闭其他步骤和重试提示，
不淘汰已挂载或仍在执行的回执。主进程继续核对真实工作区、源码摘要、安装记录、权限与 Claw 配置。

删除开发会话的异常处理会保留 close 和 drain 的双失败信息。普通 UAT 会话的关闭分支保持原语义。
新代码检视中的 lint 错误已经修复；初次失败日志仍保留。

## 文档和界面

入口为 **自定义设置 → 创作者模式 → Sparks 灵件 → 官方说明**。
八章来自 [Sparks 官方说明](sparks/README.md)，支持章节搜索、内部链接、前后翻页、键盘关闭与窄屏阅读。
打开说明不会卸载创作编辑器，关闭后保留未保存输入。

阅读器只使用随包内容，不新增文件读取 IPC；仓库源码引用显示为参考文字。
外部 HTTPS 参考链接由现有 Electron 桥显式打开，失败时仍可继续离线阅读。
主要入口与提示已使用 Sparks／灵件，内部协议、工具名和历史错误代码保留兼容标识。

“普通模式”和“创作者模式”目前是导航组织方式。切换普通模式不会自动停止已经启用的能力，
停止、禁用和撤权使用明确入口，避免把界面偏好误作运行权限。

## 与 Claude Mods 和 DeepSeek Harness 的关系

比较基线是 [Claude 官方创建说明](https://code.claude.com/docs/zh-CN/plugins/mods/create)、
本地 Claude Code 2.1.295 的只读模块研究，以及
[DeepSeek Harness 固定版本源码](https://github.com/deepseek-ai/deepseek-harness/tree/d743267388641bc76f17c45ce8b4c231aed1d32c)。
它们支持设计对照，不能替代同条件运行评测。

| 方向 | DevClaw 已有的具体实现 | 判断与边界 |
| --- | --- | --- |
| 对话制作扩展 | 随包创作 Skill、当前宿主能力目录、真实源码与检查、确认后本会话试用、继续对话更新 | 已形成闭环；开发试用只开放明确的受限能力，不能运行任意 Claude 示例 |
| 定制行为和界面 | 支持的事件处理、命令、多个桌面显示位置及原生工具结果展示 | 有实际宿主实现；支持目录、授权范围和真实桌面效果分别验证 |
| 从尝试到复用 | 停止试用、预览、安装、正式权限、保留已有选择的 Claw 组合、新会话使用 | 适合桌面用户持续复用；每个产生效果的步骤仍明确操作 |
| Harness 执行可信度 | 版本绑定的真实检查、执行记录、固定任务比较、受限恢复、Skill 候选采纳与回退 | 有适用于本工程的价值；未知副作用不自动重放，固定 Flow 评测不是通用动态 UI 评测 |
| 生命周期组织 | 授权与代次隔离、真实排空、旧回调拒绝、可回收记录 | 本次修复暴露了分散状态表的维护成本；DSH 的统一 Scope/Effect 和事件记录仍值得进一步借鉴 |

可以确认 DevClaw 把创作、桌面定制、组合复用和实际检查串起来了。本轮改进了连续使用的可靠性和文档可达性。
**没有同任务、同模型、同预算的竞品对照，不能宣称总体质量、费用或速度已经胜过两者。**

### 新版切换的耗时问题

本轮受控桌面主链未通过 120 秒内看到新版画面的检查，不能声称即时热更新或性能优于竞品。
首次观测 revision 3 排队为 65.144 秒，82.063 秒首次采样到预检，98.244 秒因
`MODS_DEVELOPMENT_BUSY` 回到排队；115.762 秒再次预检，120.523 秒宿主已生效且摘要匹配。
最终实际等待 122.115 秒后该检查失败，原门槛没有放宽。

后续新版按钮、真实命令、停止后原生结果、普通聊天、正式复用与新会话命令均通过，
没有永久切换失败或 unknown 的证据。功能结果与上述耗时失败分开记录。
首次排队后的等待仍约 55 秒，不能全部归因于模型生成；现有阶段时间戳不足以精确拆分编译、
资源排空和界面重挂成本。阶段计时与切换延迟是后续优化的明确优先项，不能用调大测试门槛替代优化。

## 仍需明确的边界

- 同一创作 scope 的持久准备版本最多 16 个或 4 MiB；新草稿和重启不清零。
  后续可设计有引用保护的版本归档，当前不自动删除源码；继续操作见[排障说明](sparks/troubleshooting.md)。
- 导航恢复使用进程内回执。应用重启不会自动恢复这张多步复用卡及未持久回执，
  可能需要从正式管理入口核对安装和组合后继续；不恢复临时同意和执行权限。
- 现有插件适配保留 Skill/MCP 等原来源，不等于任意 Plugin 自动转为可运行灵件。
- 所有模型验证使用隔离环境及受控 loopback 服务。真实模型质量、付费服务、组织登录、客户安装包和部署验收未在本轮完成。

后续优化应先记录生成、检查、排队、排空、发布和画面更新各阶段耗时，定位并缩短热切换等待，
继续保留原 120 秒验收门槛。其次是有引用保护的版本归档、重启后可核对的复用进度，以及统一生命周期记录。
用固定真实任务做同模型效果与成本比较，才能进一步判断与竞品的实际差距。
这些属于待实施、待验证的后续能力，不能凭本轮回归结果标记完成。
