# Mods v2：共享子代理轮次

开发分支 `codex/mods-v2`，代码起点 `d4ed53f8`，宿主修订
`desktop-child-turns-v22`。固定对照为 Claude Code 2.1.273。

## 实际效果与对照依据

已知共享任务代理完成时发送独立的 `turn.complete`，包含实际 `agentId`、独立
`turnId`、回答、时长和提供商用量。子任务不发送主轮次 `turn.start`，也不把完成
Hook 返回的文字添加到主聊天通知。示例 `/claw-turn` 增加 `lastChild` 和
`childCompletions`，主任务状态不受子任务完成影响。

冻结还原产物 `mzn/Qos`（格式化 chunk 第 133447–133513 行）为子任务生成独立轮次，
不等待主线程空闲即可分发完成事件；`CUn` 仍将主轮次完成放到空闲后处理。
本批依照这个区别实现，没有让父任务等待自己的完成 Hook，避免线程租约循环等待。

真实工具与 MCP 动态绑定使用当前私有子实例的轮次，审计继续保留父 task receipt。
共享后端构造时的固定所有者不随异步环境改写。未知或自定义 opaque 代理仍不推测
权限，不能仅凭 task 名称获得宿主能力。

## 检视与边界

- 主、子轮次共用 100 项在途预算。子代理观察器按私有实例绑定，同名替换后旧完成
  不能删除新实例；关闭或撤销取消待分发事件，不会恢复旧能力。
- 实际 `afterModel` 响应统计完整用量。真实流按宿主写入的 task owner 元数据归属，
  还要核对父物理运行 ID；忽略压缩流及正文伪造的 owner。主轮次不重复计入子用量。
- 父控制器取消传播到子模型连接，完成原因优先为 aborted；尚未完成的响应不编造
  用量，但保留已经收到的回答片段。
- 检视发现完成回调可继承父 task 的 AsyncLocalStorage。现改用宿主独立入口，同时
  清除执行上下文、Mod call 和 SDK receipt 上下文。真实图回归检查三者均不泄漏。
- classic Hook 的宿主逻辑轮次尚未随本批改写；其完整映射仍需独立核对。
