# 创建与修改灵件

你可以让 DevClaw 根据自然语言编写灵件，也可以在高级源码编辑器中维护 TypeScript。
两种方式都需要检查代码、核对能力并确认实际效果。

[返回概览](README.md) · [绘制界面](interface.md) · [安装与复用](reuse.md)

## 让 DevClaw 编写

### 准备当前会话

打开关联本地项目目录的聊天，配置可用模型，在输入框旁选择 **创造者模式**，直接描述需求并点击 **发送消息**。
尚未关联目录时，按提示选择目录并进入创造者模式。
也可以从自定义助手总览点击“进入创造者模式”回到原聊天。
此操作会准备应用和项目的灵件功能；新作品的试用能力仍需你确认。

普通模式用来处理日常任务，创造者模式用来创建、修改或组合功能。切回普通模式保留已生效的
Mods；需要停止某个试用时，再使用对应的停止操作。不必先选择添加功能、常用搭配或执行步骤。

当前聊天保持不变，未发送的输入、附件和已选择的 Skill 会保留。创作工具只在符合条件的当前
本地聊天中提供；后台、IM 和流程执行不能据此获得会话开发权限。

### 描述一个具体效果

例如：

> 为当前会话创建一个灵件，在输入框上方显示工具调用次数。保留原工具的执行方式，不读取文件、
> 不调用外部服务。请先检查代码，再请求我确认试用。

也可以直接说“把已有的文件编辑提醒和用量面板一起用在这段聊天”。助手会读取当前可用版本，
保留已有设置，再提交组合。已授权的组合在本轮结束、聊天空闲后应用；缺少授权或来源变化时
会明确说明原因，不会代为扩大权限。组合状态与新功能试用分别核对。

DevClaw 使用内置创作 Skill 和 `mod_authoring` 工具，读取当前构建的接口说明，保存真实源码并
执行检查。生成模板只是起点；需求需要落实为代码，不能把描述原样放进模板就算完成。

### 确认并试用

出现“确认灵件试用”时，查看用途与权限概括。
点击 **确认并应用到这段聊天** 即可试用，无需另勾确认框。批准针对当前版本和目标聊天；完整权限和技术详情可以展开查看。
模型可以请求试用，但不能替你批准。

首次批准同时允许这个组件在本会话、已批准能力范围内的后续更新。更新要等当前轮次真正结束、
旧资源可以安全释放时才能生效。看到“本会话已生效”后，再触发一次工具调用检查计数。

“已生成”“检查通过”“已排队”分别说明不同阶段，都不等于组件已运行。

文件、网络、模型和公开业务动作可以申请 **需授权的真实试用**，核对源码、当前目标与权限后直接验证，
无需先正式安装。看到“版本已生效，真实结果待核对”后触发动作，再读取实际结果；
原有文件和工具批准仍有效。详见[真实试用、配置与生命周期](platform-authoring-lifecycle.md)。

显示“试用失败”时，点击 **修复并重新检查**，会直接向当前聊天提交修复要求，让助手修改并重新检查，无需复制错误或手动发送提示。
有待发送内容、运行任务或待确认事项时，先按提示处理，原输入会保留。
失败不是待批准，无需寻找确认按钮。若提示快捷指令重名，让助手更换指令名称即可。
制作被中断时，回到聊天继续制作。聊天仍在回答时，等待回答结束；面板会显示当前等待原因。

### 保存后继续使用

同一聊天中的源码会保留，切回普通模式后可继续使用已生效版本。重启后运行不会自动恢复；
回到原聊天，点击 **恢复这个灵件**，核对源码、状态和权限后重新确认试用。无需为同聊天恢复先正式安装。

需要正式保存并在其他聊天使用时，点击 **保存并在其他聊天复用…**，核对卡片里的版本、用途和项目权限，
再点击一次 **确认保存并复用**。这会安装正式版本、授予当前项目所列权限、保存可复用组合并加入当前聊天，保留其他选择。
使用默认继承设置的其他聊天也会包含本项目已授权的功能；保存本身不会发送消息或执行任务。
完成后，在 **任务进展 → 高级设置** 查看该灵件的命令；点击命令会填入输入框，补齐参数后点击 **发送消息**。
只有需要配置的灵件才会显示设置表单。

例如，一个“编辑文件后播报天气”的灵件，需要先按它的说明设置城市或天气，再让助手编辑文件。
单纯发一句问候不会触发编辑事件。若使用的是演示天气，界面显示的是设置的内容，不是实时天气。

### 在原聊天继续修改

> 把计数改成一个按钮，点击打开明细；保留当前聊天的其它功能。

助手再次保存、检查并请求试用。已批准范围内的更新可自动排队；新增能力仍需你确认。
准备阶段失败时旧版本保持可用；如果停止旧版后的清理无法确认，界面会显示待核查状态，
按[排障说明](troubleshooting.md)处理。

模块变量会在重新加载后重置。需要保存数据时，应明确提出保存要求并使用支持的存储接口。

## 自己编写一个最小灵件

下面是当前作者工具使用的 v2 包结构。可以在高级草稿编辑器中保存这三个文件，再执行检查和预览。
已有文件夹也可以从正式安装入口导入；直接编辑安装目录不会获得会话试用授权。

```text
tool-counter/
├── plugin.json
└── mods/
    ├── manifest.json
    └── main.ts
```

`plugin.json` 描述插件包：

```json
{
  "name": "tool-counter",
  "version": "0.1.0",
  "description": "在输入框上方显示工具调用次数",
  "mods": "mods/manifest.json"
}
```

`mods/manifest.json` 指定运行协议和入口：

```json
{
  "apiVersion": "cmb.mods/v2",
  "id": "tool-counter",
  "entry": "main.ts",
  "modelProtocol": "result-v1"
}
```

`mods/main.ts` 注册处理程序：

```ts
import type { Register } from "claude-code"

export const register: Register = (on) => {
  let calls = 0

  on("tool.call", async ($, event, next) => {
    calls += 1
    $.ui.invalidate("ui.render")
    return next(event)
  })

  on("ui.render", { component: "AbovePrompt" }, ($, event) => {
    const { Text } = $.ui.resolve(event)
    return Text({ children: "工具调用：" + calls })
  })
}
```

工具事件增加计数后调用 `next(event)`，继续原有处理。界面事件返回要显示的文本。
本例计数的是经过该处理程序的工具调用尝试，不代表成功完成的工具数；组件重载后从零开始。
本例直接提供 `AbovePrompt` 内容，组合多个界面灵件时需要处理内容合并，见[绘制界面](interface.md)。

`claude-code` 在这里是当前作者检查器提供的类型声明名称，`import type` 不会加载 Claude Code
程序。不要因此安装同名运行依赖，也不要把协议字段改为尚不存在的 `sparks/v1`。

## 检查真正的效果

保存后先运行检查，再根据用途验证：

1. 确认实际生效版本与刚保存的候选一致。
2. 触发一次工具调用，观察计数变化；确认工具仍按原权限执行。
3. 修改展示文字，检查后请求更新，确认新画面出现。
4. 停止试用，确认自定义内容消失，普通聊天仍可使用。

检查通过只能证明相应的编译、类型和接口检查通过；按钮、工具结果和业务逻辑需要实际触发。
正式复用前，也应验证失败、取消和重复点击时的行为。

下一步：保留当前会话，从聊天的灵件面板直接保存复用；需要手工管理时再进入“自定义助手 → 添加功能 → 自己制作”，
[将已验证的灵件保存并复用](reuse.md)。
