# 事件与 API

灵件入口导出 `register`，通过 `on` 注册处理程序。事件描述发生了什么，宿主 API 提供允许执行的
操作，二者都受当前来源、版本、会话与授权约束。

[返回概览](README.md) · [开发参考](reference.md)

## 观察、修改或自行处理

处理程序接收 `($, event, next)`：`$` 是宿主 SDK，`event` 是事件数据，`next` 继续后续处理。

| 方式 | 写法 | 含义 |
| --- | --- | --- |
| 观察 | 记录需要的信息后 `return next(event)` | 让后续逻辑按原事件继续 |
| 修改 | 构造符合该事件契约的新参数，再调用 `next` | 让后续逻辑使用修改后的数据 |
| 自行处理 | 返回符合事件契约的结果，不调用 `next` | 接管此次处理，不执行下游逻辑 |

需要继续时通常只调用一次 `next`。重复调用可能重复业务效果；省略调用也不是一个通用的
“静默放行”方法。返回值必须符合具体事件契约，例如工具结果不能随意返回 UI 元素。

### 普通 Hook 的错误恢复

普通 Mods Hook 是可恢复的扩展。抛错不等于拒绝执行；未由注册的 `.catch(...)` 成功处理时，
宿主按下列规则恢复：

| 出错时机 | 恢复行为 |
| --- | --- |
| 尚未调用 `next` | 跳过出错的 Hook，使用它收到的原事件继续下游 |
| 已调用 `next` | 等待并保留最后一次下游调用的结果，不重新执行该调用 |
| 下游本身失败或执行被取消 | 传播失败或取消，不通过重跑下游恢复 |

注册的 `.catch(...)` 可以返回符合事件契约的替代结果；恢复处理程序中的 `next` 会复用已经发起的
下游调用。不要为了恢复错误手动重发命令或工具调用：下游一旦开始，可能已经产生实际效果，
返回替代结果也不会撤销它。普通处理程序主动调用两次 `next` 仍会执行下游两次，并非自动去重。
显式 Claw 动作提供者等严格执行路径另按其契约处理错误。

危险命令提示灵件（例如 Blast Radius）提供识别、说明和交互确认，不能作为强制宿主策略。
它的 Hook 出错时也可能按上述规则跳过或保留下游结果。必须执行的限制应放在宿主最终参数检查、
权限检查和审批中；不能依靠 Hook 抛错或确认面板是否显示来保证拦截。

灵件不能通过修改事件绕过宿主对最终参数、权限和来源的检查。观察界面与获得文件、进程、网络
权限是不同的事情。

## 当前会话试用的事件

| 事件 | 典型用途 |
| --- | --- |
| `ui.render` | 提供支持位置的界面 |
| `tool.call` | 观察或按契约处理工具调用 |
| `command.run` | 处理本地命令 |
| `session.start` | 组件实际会话初始化时注册必要内容 |
| `turn.complete` | 处理轮次完成事件 |

这五个事件属于基础本地试用范围。经原生确认的真实试用还可申请当前能力目录中有实际适配的
事件；范围外事件不会因模型生成了代码而自动获准。`turn.complete` 返回也不等于旧版本资源
已经全部释放；版本切换由宿主决定。

正式安装的事件范围更广，包括部分提示、模型和工具等接点。具体支持等级和参数必须查当前
能力目录；“已有适配”不表示所有参数、重载和执行场景均已支持。

## 技能使用前后扩展

`classic.PreSkillUse` 与 `classic.PostSkillUse` 是本应用提供的技能生命周期扩展。
它们分别接入真实技能激活前、已激活技能完成后的检查，不是普通消息发送事件，也不表示
注册任意技能名称就会执行该技能。它们不属于上游固定事件清单，未改变其兼容数量。

```ts
import type { Register } from "devclaw-mods"

export const register: Register = (on) => {
  on("classic.PreSkillUse", { skill_name: "review" }, ($, event, next) => {
    $.ui.log("准备使用技能：" + event.skill_name)
    return next(event)
  })
  on("classic.PostSkillUse", { skill_name: "review" }, ($, event, next) => {
    $.ui.log("技能完成检查：" + event.skill_name)
    return next(event)
  })
}
```

将 `review` 换成当前实际加载的技能名称。省略 matcher 可观察所有实际技能激活；匹配字段
使用 `skill_name`。这是观察示例，不会自动批准操作、判定产物合格或推进业务状态。

| 数据或结果 | 约定 |
| --- | --- |
| 技能身份 | `skill_name`、`skill_path`、`skill_root`、`skill_trigger_tool_name` 来自真实激活记录，均不可由 `next` 改写 |
| 运行身份 | `hook_event_name`、`session_id`、`cwd`、`transcript_path` 及可选的权限、Agent 信息由宿主提供 |
| 原调用事实 | 可选 `tool_name`、`tool_input`、`tool_response`、`plugin_id/name/root`、`stop_context` 保留真实来源；不能当作可任意填写的执行参数 |
| `block: "原因"` | Pre 阻止技能激活；Post 进入原修订流程，不伪装为技能成功 |
| `preventContinuation: true` | 请求原执行链终止，可配合 `stopReason`；不能构造批准或成功回执 |
| `additionalContext: ["说明"]` | Pre 按原上下文规则处理；Post 非阻断输出仅用于观察，不单独触发修订 |

技能身份、工具结果和完成上下文均由宿主固定。正常观察使用 `return next(event)`；拒绝时返回
符合该事件契约的结果。普通 Mod 的异常仍遵循前述可恢复规则，不能将抛错当作强制校验。
原插件必需的 Hooks、产物检查及权限检查仍在宿主执行链中必经，Mod 省略 `next` 也不能跳过。
后置检查请求修订时保留该技能的待验状态，修订后重新执行检查；只有通过或明确停止后才消费
该记录。重复不合格会耗尽原修订预算并失败，不将“模型已修改”直接视为验收通过。
因此后置事件可能因修订再次执行，不能作为天然的一次性提交通知。有写入或外部副作用的
处理器需要保证幂等，并复用业务已有的操作标识与对账；接口本身不提供跨系统原子提交。

这些事件接通现有技能激活与标准完成链。独立协调器 worker 使用自己的 Stop 完成链，当前
未统一接入技能后置检查，不能将普通子会话覆盖理解为所有 worker 类型都已支持。

创造者通过 `mod_authoring` 的 `catalogSection="events"` 与 `"types"` 读取精确声明；
真实试用需要对当前源码及这些新增事件重新确认。旧的基础本地试用范围不会自动扩大。
接通事件不代表原 Python/Shell Hooks 已自动转换为 Mod；迁移时仍须保留原知识、配置、
唯一状态写入器及校验语义，并通过实际业务运行验证。

## 当前会话试用的宿主接口

| 类别 | 允许的方法 |
| --- | --- |
| 界面 | `ui.open`、`ui.close`、`ui.panes`、`ui.resolve`、`ui.invalidate`、`ui.log`、`ui.status`、`ui.toast` |
| 私有存储 | `store.get`、`store.set`、`store.keys`、`store.delete` |
| 会话信息 | `session.usage`、`session.version` |
| 时间读取 | `clock.now` |
| 本地命令 | `command.register`、`command.list` |

这是宿主允许范围，方法的作者类型声明可能更窄。编写 TypeScript 时还要读取实际声明并通过
检查；不能仅凭此表猜测参数。时间读取也不等于定时器已获准。

基础本地试用不提供模型调用、进程、网络、文件、跨插件状态或自定义工具注册。需要这些能力时，
可以请求原生确认的真实试用，核对精确源码、用途、目标及新增权限；实际调用仍经过原执行与
权限链。无需为验证这些能力提前正式安装。具体方法与参数以当前构建的作者目录为准。

## 原生工作流与工作树能力

`platform.list()` 可发现 `native.workflow` 提供的 `runs@1.0.0`。发现只读取声明，不启动工作流、
订阅或模型。原生模块与作者提供的能力使用相同的 `read/subscribe/poll/unsubscribe/act` 接口。

- `read` 返回当前会话原运行器的活动运行，或最近的持久运行；不包含提示词、脚本、日志及 journal。
- 工作树中的 `agentIndex` 由原工作树创建流程记录。旧记录缺少关联时返回 `null`，不会按名称猜测。
- 终态落盘失败时使用原运行器保留的、属于同一工作区与会话的真实终态。重启后仅有旧的“运行中”磁盘记录而没有活动运行时，返回 `unknown`，不将其当作仍在执行；最新记录不可读取时明确报错，不悄悄改报更旧的结果。
- `subscribe` 连接原运行事件；`poll` 的 `resync` 为真时重新 `read`。停用或关闭时退订，迟到结果
  不能写入旧作用域。
- `inspect` 动作接受 `runId`、`agentOffset`、`worktreeOffset` 和 `limit`，分页读取真实任务与工作树。
  返回下一页偏移及 `hasMore`；它表示仍有完整页面可读取，不能将当前页当作全部任务。
  个别目录显示被缩短时，该行的 `directoryTruncated` 为真。完整分页不使用命令输出的
  `truncated` 标记，默认项目输出保护仍会抑制真正不完整的命令输出。
- `cancel` 只针对当前活动运行，必须通过原生确认；确认后再次核对运行身份，委托原运行器取消并
  等待实际清理。记录过的请求编号不重复取消，已产生的成果按原规则保留。

目标始终为宿主绑定的当前会话和工作区；参数中不能添加另一会话或任意目录。读取或展示不授予
管理权限，结果未知时应重新读取原状态，不能换一个请求编号重放副作用。

## 注册与运行命令

在合适的初始化事件中使用 `command.register` 声明名称和说明，使用 `command.run` 匹配并处理。
开发试用命令进入实际命令队列，并核对当前会话、版本和授权；它不是绕过正在运行任务的后台捷径。
正式命令按当前宿主的 `immediate` 语义或排队规则执行，不能笼统认为所有命令都能立即运行。

命令本身可以直接返回结果，无需模型解释；若其实现调用模型、工具或流程，相应约束仍然适用。
请在应用的命令列表选择已发现的命令，避免把旧版 `/mod` 用法和新入口混用。

## 给创作模型的接口

内置 Skill 使用 `mod_authoring` 完成目录查询、草稿读写、检查、请求试用以及插件资产分析。
它没有用户批准、正式安装或修改 Claw 的自动授权能力。

`catalog` 可按 `overview`、`types`、`events`、`sdk` 获取内容；返回 `nextCursor` 时继续读取下一页。
检查错误会反馈给模型修正，检查通过仍需要实际使用验证。模型不应在同一轮里反复等待候选变为
active，因为该轮本身尚未结束。
