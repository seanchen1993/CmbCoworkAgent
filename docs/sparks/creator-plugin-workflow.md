# 插件制作、试用、验收与保存

创造者聊天保存需求与修改过程；“创作工作区”集中展示候选、试用、检查和交付。
阶段执行会话是同一轮试用的执行记录，无须逐个打开会话来猜测是否成功。

## 从哪里开始

- 制作新功能：在普通聊天进入创造者模式，描述目标、输入和希望得到的产物。
- 改造已有业务 Mods：指定已安装的来源插件，说明要保留、增加或调整的模块。
- 首次拆分原始插件：说明“把插件 X 拆为可组合 Mods，保留知识、配置、Hooks 和检查”。
  助手先检查原始源码，展示迁移方案，由用户确认创建独立源码候选，再继续组合。

首次模块化不会修改原插件。能够识别的 Host 阶段可生成迁移候选；共享 Skill 使用独立
别名时保持原资源的相对目录。不能证明原 Hook、上下文或执行语义可保留时，必须先完成
映射。原始文件仍在不等于行为已经保持，不能删除校验或改执行标签来消除诊断。

## 四步工作区

| 页面 | 用户操作 | 可以确认的结果 |
| --- | --- | --- |
| 制作 | 在原聊天描述、修改；核对首次模块化方案 | 候选源码与明确的来源版本已准备 |
| 试用 | 填写本次目标，核对配置与权限，创建独立试用并开始原阶段 | 原运行器实际开始执行 |
| 验收 | 查看本轮阶段、产物、原生检查及待人工确认事项 | 当前候选在原规则下的实际检查结果 |
| 保存 | 指定新名称与版本，准备后确认安装，或导出 ZIP | 独立插件已安装或插件文件已导出 |

创建项目、模型回复“完成”、单次会话结束、包检查通过和安装成功分别属于不同事实。
整轮通过要求原执行链完成、各阶段检查凭据完整、必需产物有检查、人工批准已处理、来源
与候选仍匹配。缺收据、记录不完整或来源失效时显示待核对，不将其补成成功。

## 试用时如何操作

1. 在“试用”页核对候选版本与本次目标，按提示创建隔离试用。
2. 在同一工作区查看原项目的阶段操作。需要时确认源码、工具和人工审批，再推进阶段。
3. 在“验收”页查看当前阶段的检查与产物。长流程默认收起已结束阶段及完整会话正文。
4. 效果不符合预期时，填写反馈，提交回原创造者聊天；助手读取实际试用记录后修改候选。
   新候选需要重新检查、确认并从起点试用，旧执行不自动重放。

切换阶段保留原执行器的会话隔离，并通过原项目、运行、阶段与候选版本关联回制作聊天。
人工工具确认仍通过原生入口处理。关闭工作区或试用窗口后可回原聊天继续输入。

## 如何判断成功

- **整轮试用已通过**：原生阶段检查与推进证据完整，且属于当前候选；仍须判断业务效果。
- **检查通过，待确认推进**：当前阶段完成检查，尚需在原项目执行原有推进或人工确认。
- **未通过**：查看具体检查和产物，在原聊天描述修改要求。
- **待核对／历史版本**：缺真实收据、未知执行结果、来源失效或候选已修改；不自动重跑。

Host 使用原检查回执；插件拥有状态的流程使用受审适配器和原 Hook/checkpoint 收据。
未提供受支持校验契约的插件必须补齐契约，不能仅依据其日志或模型文本显示整轮通过。
展示的是当时校验过的产物证据，不代表状态页持续重读、重新验证所有磁盘文件。

## 如何保存为自己的插件

Host 候选在“保存”页填写独立的新插件标识和版本，例如 `my-data-review`、`1.0.0`，点击
“准备保存为新插件”。主进程冻结并重新检查完整源码；再选择“确认安装新插件”或
“导出新插件 ZIP”。新名称不能覆盖已经安装的同名插件，原插件与试用数据保留。

业务 Mods 组装候选通过原确认卡保存并安装独立插件，也可导出插件包。原同名更新包继续
使用原 ZIP 更新入口。保存尚未完成验收的源码不等于验收通过，改名后的新包也没有因此
自动重跑。导出不携带本机目录绑定、账户配置或批准，其他环境须重新配置和授权。

本轮不提供阶段快照、回退或中间阶段重新执行；这些能力属于仍暂缓的 S6。
