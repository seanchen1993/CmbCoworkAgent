# 安装与复用

会话试用帮助你制作灵件，同一聊天的源码会保留。正式复用把已确认的源码保存为安装版本、
授予当前项目权限并保存可复用组合。草稿、安装版本和正在运行的版本分别显示，不能互相代替。

[返回概览](README.md) · [创建与修改](create.md) · [排障与限制](troubleshooting.md)

## 在当前聊天继续使用

切回 **普通模式** 后，已生效的 Mods 继续使用。重启后源码仍保存在原聊天，运行需重新确认；
点击 **恢复这个灵件**，先核对当前源码与运行状态，再重新检查、请求并确认试用。
只想在同一聊天继续使用时，无需正式安装或跨聊天复用；未知操作也不会因此重放。

## 保存并在其他聊天复用

完成实际使用检查后，保留当前聊天，打开灵件试用面板，点击 **保存并在其他聊天复用…**。
准备完成后，核对卡片中的准确版本、用途、当前项目权限和目标聊天，再点击 **确认保存并复用**。
无需逐页安装、授权和手动加入组合。

这一次确认会安装正式版本、授予当前项目所列权限、保存可复用组合并加入当前聊天，同时保留原有其他功能和设置。
你可以在其他聊天选择这份组合；使用默认继承设置的聊天也会包含本项目已授权的功能。
这不是只影响当前聊天的权限授权。保存不会发送消息、开始业务任务或自动启动已保存的 Flow。

源码、编译版本或目标选择变化后，旧确认不再有效，按提示 **重新准备最新版本**。
显示已保存、当前聊天已使用后，再实际触发灵件的命令或界面核对效果。

## 高级：分步安装与复用

需要分别检查安装过程或手动管理源码时，展开 **高级：源码与手动复用**；
进入复用工作台后，可展开 **高级：分步安装与复用**。如果试用仍在运行，按提示点击
**停止此试用并继续正式复用**。原手工流程仍可逐项操作：

1. **预览。** 对当前选定源码运行实际检查与隔离预览，查看结果。
2. **准备和安装。** 核对源码变化、版本和能力，明确应用安装。
3. **正式授权。** 阅读正式版本的权限说明，勾选并授权准确版本。
4. **应用组合。** 核对所选聊天的功能，保留已有选择，加入该版本后保存并应用。
5. **继续使用。** 选择“继续当前聊天”，或“新聊天使用此助手”，实际触发灵件的命令或界面。

正式授权的范围可能大于开发试用，不能把第一次试用确认当成永久授权。工作台会展示正式权限。
项目授权也适用于该项目中使用默认继承设置的聊天；专用组合的手动应用则更新所选聊天的功能选择。
创建新会话不会自动发送业务任务。

如果只想保留源码，选择“保存复用并打开源码”。这会保存正式草稿，进入高级编辑器；
它本身不安装、不授权，也不改变当前组合。

## 安装已有插件包

在“自定义设置 → 基础功能 → 灵件与使用设置 → 我已添加”选择上传 ZIP 或从文件夹安装。选择真正的插件根目录：根目录应包含可识别的
插件清单，而不是把多个独立插件的父目录一起上传。

AutoBiz 等项目与技能插件按原方式安装使用时，无需手动转换。安装后在卡片上点击“启用插件”，通过“设置使用”查看原有技能、工具和检查；含项目功能的插件可以继续“新建项目”。原有 Hooks 和阶段规则保持不变。

包含灵件模块的插件还需核对项目权限。普通聊天的界面和工具可在 **创造者模式** 直接描述如何搭配；
需要手工选择时使用 **自定义设置 → 高级自定义 → 搭配管理**。项目里的独立能力和完整流程，在项目会话标题栏的“项目能力”中搭配。
安装或保存配置不会自动开始任务。

配置页顶部可以直接选择目标聊天。应用助手组合只更新该聊天的功能选择；插件的通用参数由同一项目中的聊天共享，表单中会说明范围。

项目组合的完整操作见[在一个项目里搭配多个插件](project-platform.md#在一个项目里搭配多个插件)。

如果已有插件没有完整流程选项，可在 **自己制作** 中参考它创建新副本，点击 **用于完整流程组合**。
先预览新增配置，再 **确认保存完整流程配置**；之后检查、安装并启用副本，回到项目会话的 **项目能力** 选择流程。
确认保存只准备配置，不会开始任务。完整流程按插件具体版本开放，以 **项目能力** 的可用状态为准；暂不支持时，按页面提示使用原项目入口。

## 与 Claw 和 Flow 配合

开发新插件或复用旧节点，请按[插件开发入门](plugin-cookbook.md)的四个练习操作。

已有项目插件也可以添加项目能力说明。安装完整能力包并在项目模式绑定后，打开需求详情，
可以集中阅读阶段指导、前置检查规则、完成验收规则、产物问题和历史 Hook 记录。
面板内的“使用帮助”可直接展开阅读，不必离开应用寻找文档。

“准备下一步会话”会创建原项目技能会话并填入指令，发送后才执行；指令来自当前阶段状态，
也可以是原插件在该阶段结束后提供的下一步技能。已有运行或人工确认应在原入口处理。
这些说明和辅助灵件不会替换原 Hooks、领域验证器或状态提交链，也不会将历史成功认作当前验收。

开发者在已有项目插件根目录添加 `devclaw.project.json`，使用 `devclaw.project/v1` 协议，
声明 `name`、`description`、`help`（标题和正文）及 `stages`（节点 ID、指导、前置和后置规则）。
节点 ID 对齐原工作流；无声明的旧插件保持原使用方式。声明为纯文本规则，不接受执行命令或审批结果。

日常使用在普通聊天描述需求并点击 **发送消息**，在原任务卡或 **任务进展 → 当前任务 / 结果** 查看进展与成果。
Claw 保存“使用哪些能力”；Flow 保存手工编排的固定任务方案。选中一个灵件不会自动执行整条流程，
也不会自动把它的每个功能转换为 Flow 动作。模型目前没有自动启动已保存 Flow 的工具。

高级用法需要重复执行“实现 → 检视 → 测试 → 确认”时，可创建实际存在的步骤，绑定模型、工具和检查并保存。
回到聊天，打开 **任务进展 → 高级设置 → 高级：为下一条消息使用预设任务**，明确选用已保存方案，
再在同一个聊天输入框填写任务，点击 **发送消息**。保存、绑定、选择或取消都不会执行任务。
选用只用于下一条消息；成功启动后恢复普通发送，预检失败时输入和选择保留。可点 **取消本次选择** 恢复普通发送。
当前步骤、人工确认与结果在原任务卡和 **任务进展 → 当前任务 / 结果** 持续更新；
命令和插件面板在 **高级设置** 中，历史尝试和技术记录按需展开。

评测可比较固定任务上的基线与候选流程。模型意见和实际测试回执应分别查看，缺失数据不能
当作零成本或成功。恢复只适用于产品明确支持的流程类型与状态，不会自动重放结果未知的操作。

## 更新与回退

修改正式草稿后，先预览再准备更新。核对这次准确的源码与能力，安装后按需要重新授权并应用。
旧版本仍可能在已有会话中显示；以该会话实际运行状态为准。

需要回退时，在版本管理中选择已保留的旧版本，执行检查与正式应用流程。回退恢复的是代码版本，
不会撤销已经写入文件、发送请求或产生的其它外部效果。随后重新核对授权、组合和实际命令结果。

旧版本占满容量时，可以在安装面板的“查看空间用量，清理旧版本”中核对并清理已不需要的版本。
清理会永久删除所选源码并放弃对应回退能力；当前版本、最近回退和仍被运行引用的版本受保护。
草稿历史和评测记录分别管理，详见[容量处理说明](troubleshooting.md)。

## 中途失败怎么办

单确认复用卡显示失败或结果待核对时，点击 **核对复用状态**，先读取真实状态，不要重复安装或授权。
已完成的步骤会保留；例如安装成功但后续读取失败时，先核对安装状态。高级工作台的分步操作也按已保存记录处理，
不要因为后续页面报错反复点击安装或新建会话。

若当前项目、会话或组合已被其它操作改变，应重新读取并核对，不用旧卡片强行覆盖新配置。
结果不明时按[排障说明](troubleshooting.md)处理。
