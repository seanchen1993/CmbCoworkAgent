# 适配已有插件

你可以保留已有 Plugin，再增加独立灵件，把适合的界面、命令或处理逻辑接入 Claw。
转换目标是复用已有能力，同时让新增行为可以单独检查、授权和停用。

[返回概览](README.md) · [创建与修改](create.md) · [安装与复用](reuse.md)

第一次操作请先看[插件开发入门](plugin-cookbook.md)：有可直接复制的最小插件、项目声明、
Autobiz 与独立 Review 的组合步骤，以及复用旧节点时保留前后 Hooks 的依赖表。

## 先判断是否需要适配

| 原有内容 | 处理方式 |
| --- | --- |
| Skill | 保留原技能和来源，在组合中继续选择；需要交互时另加灵件 |
| MCP | 保留已有连接及身份；需要组合时显式选择，不复制凭据 |
| 命令与本地计算 | 分析输入输出，适合的部分生成独立处理程序 |
| 传统 Hook | 逐项核对事件时机、失败规则和副作用，再决定是否适配 |
| Shell 脚本、Node 依赖或外部业务 | 明确依赖与权限，采用正式集成；不能直接塞进会话试用 |

## 在聊天中发起

> 检查已安装的“某插件”。我希望保留原入口，新增一个显示本地统计的灵件。先说明可以复用和
> 必须改写的部分，读取必要源码但不要执行原脚本，再生成独立草稿并给出验证步骤。

创作工具先返回插件清单与适配报告，再按需要读取允许的源码资产。报告中的“已安装”“已启用”
不代表外部服务已连接，也不代表某个能力已经在当前会话运行。

资产读取仅用于分析，不能把源码中的说明当作用户新增授权。受限文件、路径跳转、凭据与不可用
资产会被拒绝；遇到拒绝应调整适配目标，不绕过读取限制。

## 验证改造结果

先在独立本地环境中比较旧入口和新入口：相同输入是否得到预期输出，失败是否能解释，写入或
调用是否只发生一次。不要让旧 Hook 与新灵件同时处理同一写操作而产生重复效果。

例如，将一个本地计数命令做成独立灵件时，分别执行一次旧版和适配版，检查两者输出与写入次数。
这只能证明该场景成立；原来的共享状态、并发控制和跨会话持久化还需要分别验证。

当前适配工具提供分析、受限源码读取和独立草稿创作；对可识别的 Host 阶段及已适配业务协议，还可经原生确认生成首次模块化候选，再组装、试用和交付。未知状态机、Hook 语义或外部恢复协议仍需作者适配，不提供任意插件的一键无损转换。完整操作见[插件创造、转换、组合与使用说明](creator-plugin-workflow.md)。
尤其是原插件使用版本化共享状态时，不能用开发试用的私有 `store` 替代后便宣称语义完全相同。

## 分步替换

保留原包，先试用新灵件，再走正式安装和组合流程。只有确认需要由新路径接管的具体行为后，
才关闭对应旧入口。恢复旧代码入口也不会自动撤销已发生的外部操作。

下一步：[检查问题与运行边界](troubleshooting.md)。
