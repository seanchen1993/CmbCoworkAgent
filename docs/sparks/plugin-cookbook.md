# 从已有插件创建与组合

以 AutoBiz 为基础制作自己的业务插件，可以保留已经调通的检查步骤，集中修改技能和业务要求。
日常任务无需先完成这些手工配置：在普通聊天描述需求并点击 **发送消息**，在原任务卡或 **任务进展 → 当前任务 / 结果** 查看进度。
创建、修改或组合 Mods 时，优先在 **创造者模式** 直接描述需求；下列安装、原插件适配和固定方案保留为高级操作。

## 例一：从 AutoBiz 创建数据开发助手

已有 AutoBiz 文件夹也可以直接安装：进入 **添加功能 → 我已添加 → 从文件夹安装**，选择 `autobiz_kanban`，在出现的插件卡片上点 **启用插件 → 新建项目**。原有技能和阶段检查保留，无需手动转换为灵件；想定制一份独立插件，点卡片上的 **从此插件创建**。

1. 打开 **自定义助手 → 添加功能 → 自己制作 → 从已有插件创建**。
2. 选择 AutoBiz。没有安装时，点 **选择本地插件文件夹**，选中完整插件目录。
3. 填写 `my-data-autobiz`，点 **创建我的插件**。
4. 在 **告诉我你想怎么改** 写下“增加数据口径、转换 SQL 和数据质量报告要求，保留原有检查”，点 **生成修改建议**。
5. 查看摘要并展开真实 `SKILL.md` 的修改前后内容。需要调整时补充需求重新生成；核对后点 **确认保存修改**，整组修改才写入独立副本。无需手工修改 Skill。
6. 若要选择项目步骤，点 **添加自选步骤选项**。展开 `board_core/board_config.json`，核对新增入口与完整修改前后，再点 **确认添加自选步骤选项**。这一步由应用确定生成，无需模型，不改变原有模板、检查或人工确认。取消不会保存；不支持的来源继续使用原模板。
7. 点 **检查能否安装**。通过后点 **安装新插件 → 启用新插件 → 新建项目**。
8. 填写新项目，选择独立目录，在原项目入口开始需求。

**结果：** 应用中保留原版和新插件。原项目继续使用原版，新项目使用你的版本。Hooks 和阶段验证按原规则执行，不会因为复制插件而自动跳过。

**需要继续修改？** 在页面底部展开“继续修改已创建的插件”，选择已保存副本。安装后的版本需要再次衍生才能编辑，避免影响正在使用它的项目。

## 例二：搭配用量天气和危险命令确认

已安装并授权这两个功能时，可以在 **创造者模式** 直接发送：“这段聊天一起使用用量天气和危险命令确认，保留其他功能。”
助手会核对真实可用版本和冲突后提交组合。新权限仍需你确认，不能用一句话代替权限批准。

需要手工挑选时：

1. 在 **添加功能 → 挑选使用** 添加 Weather 和 Blast Radius。
2. 打开 **常用搭配 → 一起使用**，选择这两个插件。
3. 起名“我的开发助手”，点 **保存并核对应用**，核对后应用。
4. 回到聊天，查看 Weather 的用量趋势；遇到匹配的高风险命令时，由 Blast Radius 显示确认面板。

**结果：** 两项功能在同一聊天中使用。Weather 与 Replay 占用相同位置，不能按这个例子同时展示；页面会说明冲突。

需要添加更多插件、技能、工具或模型时，点 **在高级编辑中继续此草稿**，带着当前名称和选择继续配置。
已有未保存的高级草稿时会先询问是否替换；取消会保留两处草稿。继续编辑不会自动应用组合或开始任务。

Blast Radius 的识别和确认面板是辅助提示，不能代替宿主的强制规则。普通 Mods Hook 在调用
`next` 前抛错，未被 `.catch(...)` 成功处理时会被跳过，并以原事件继续下游；调用后抛错则保留
最后一次下游结果，不重跑该调用。下游已经开始时可能已产生实际效果，不能靠抛错或替代返回值
撤销，也不要在错误恢复中手动重复执行。必须拦截的命令应由宿主最终参数检查、权限检查和审批
落实。作者应同时验证 Hook 失败路径，详见[普通 Hook 的错误恢复](events-and-api.md#普通-hook-的错误恢复)。

## 例三：高级固定方案——读取需求后进行检视

准备已安装并授权的 AutoBiz 文件读取动作和独立 Review 插件。完整 AutoBiz 包与灵件适配包的公开能力可能不同，只有出现在动作列表中的操作才能连接。
如果只是一次性读取和检视需求，可先在普通聊天直接描述并发送；以下步骤用于明确需要手工保存并重复使用固定方案的情况。

1. 打开 **常用搭配 → 先后执行**。
2. 第一步选 AutoBiz 的需求读取操作，填写真实需求和文件。
3. 第二步选 Review 的检视操作，将第一步结果接入第二步。页面仅提供兼容的连接。
4. 点 **保存并核对应用**，核对两个操作与所需权限后应用。
5. 点 **去这段聊天使用**。打开 **任务进展 → 高级设置 → 高级：为下一条消息使用预设任务**，核对并选用本次方案。
   回到聊天的唯一输入框填写任务，点击 **发送消息**。保存、绑定和选择本身不会执行，模型也没有自动启动已保存 Flow 的工具。
6. 在原任务卡或 **任务进展 → 当前任务 / 结果** 查看读取、检视、人工确认和最终结果。成功启动后本次选择用完，下一条恢复普通发送；预检失败则保留输入和选择，先核对原因。

**文件没找到？** 核对需求名称及相对路径，选择存在的文件后重新执行。检视通过不代替 AutoBiz 的阶段检查；阶段仍在原项目入口完成。

需要继续调整时，点 **保存步骤并继续高级编辑**。当前步骤、参数和输入输出连接会先保存，再带入高级组合草稿；
组合仍需核对后应用，流程仍需明确开始。

## 例四：选择 AutoBiz 原流程节点

1. 新插件的项目创建后，在完成卡片中点 **选择这个项目的步骤**。已有项目也可从带项目目录的聊天进入 **自定义助手 → 常用搭配 → 选择项目步骤**。
2. 在项目节点选择面板中查看真实节点，选择目标步骤，再点 **检查并预览步骤**。
3. 核对自动补齐的必要前置节点及最终原生顺序。原插件标记的可选资料未启用时会明确列出；必需资料缺失会阻止继续。
4. 点 **在项目里创建需求**，直接进入原需求表单的工作流页，填写名称和工作目录后创建。
5. 从原项目入口开始，按原 Hooks、阶段检查和人工审批完成执行。

这个入口无需公开动作或手写配置，只组合所选项目绑定插件的原生节点，不支持跨插件任意混排。创建需求不会自动执行；不支持原生节点选择的插件会说明原因。

## 运行占用与项目版本维护

打开 **添加功能**，展开 **聊天组件占用** 可查看当前运行名额和具体聊天。
最多同时保留 6 组运行组件。名额不足时，宿主会自动回收仅完成登记、尚未使用且没有待决任务的实例；
下一次使用会重新核对来源并登记。真正启动、调用过 Hook、匹配器或 SDK 的组件保持驻留，保留其闭包状态。
离开页面会卸载绘制，但不会据此销毁已使用的虚拟机。

对已经结束任务的聊天，可以点 **停止并释放**，阅读该聊天卡片内的确认后执行。
临时变量会丢失，持久设置、数据和聊天记录保留；组件保持停止，直到点 **明确恢复组件**。
仍在操作、持有后台资源、承担强制完成检查或无法确认退出的实例会保留名额。
停止和恢复都核对原聊天身份，恢复不代表旧任务的外部效果可以再次执行。

展开 **项目插件版本维护**，点 **检查可清理版本** 查看四类运行快照的占用。
每类最多保留 64 个版本。确认清理只处理这次检查中列出的候选，执行前会再次审计全部历史记录、
组合单元、项目能力选择和实际读取租约；已完成或已停用的历史引用仍会保留。
检查不会启动模型、Hook 或 MCP。引用损坏、未知格式、仍在读取或退出未确认时，相关版本会保留。
升级前的旧快照由迁移基线保护，只有可信系统重启边界才能解除旧进程可能持有的保护；
无法确认的旧格式不会按文件年龄或 PID 消失自动失效。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 新名称已存在 | 换一个名称；创建不会覆盖旧插件 |
| 插件目录变化 | 重新选择和检查来源，再创建 |
| 生成失败或没有可用模型 | 先检查当前会话模型设置；需求草稿保留，可重试 |
| 副本已变化，建议不能保存 | 取消旧建议，点“检查能否安装”更新副本信息，再生成并核对新差异 |
| 目标要求删除原协议或跳过检查 | 生成仅增加业务要求，原协议与检查保留；核对未满足的要求 |
| 安装检查没通过 | 按错误提示补齐文件或修复配置 |
| 组合里找不到某个动作 | 核对插件是否已安装、已授权并公开该动作 |
| 两个动作不能连接 | 使用页面提示的兼容字段，或选择其他动作 |
| 当前应用未开放原项目模式 | 副本可保留和编辑；开放该模式后再设置项目 |

## 开发者参考：从零制作

只想调整已有插件时，按前面的步骤操作即可。需要自己编写功能时，可从以下最小示例开始。

### 创建一个打招呼的灵件

在插件目录中创建 `mods/manifest.json`：

```json
{
  "apiVersion": "cmb.mods/v2",
  "id": "my-first-spark",
  "entry": "hello.ts"
}
```

再创建 `mods/hello.ts`：

```typescript
import type { Register } from "claude-code"

export const register: Register = (on) => {
  on("session.start", async ($, event, next) => {
    await $.command.register({
      name: "hello-spark",
      description: "向输入的名字打招呼",
      argumentHint: "[名字]",
      immediate: true
    })
    return next(event)
  })
  on("command.run", { command: "hello-spark" }, async ($, event) => {
    const name = (event.args ?? "").trim().slice(0, 80) || "新朋友"
    return { text: `你好，${name}！第一个灵件已运行。` }
  })
}
```

`Register` 来自当前作者检查器提供的 `claude-code` 类型声明；这里只导入类型，无需安装同名运行依赖。
在源码仓库根目录可执行 `openwork plugin inspect ./examples/sparks-hello --types --strict-compatibility`，检查类型和兼容性。

在 **添加功能 → 我已添加 → 从文件夹安装** 导入示例并批准能力，再到 **常用搭配** 加入
`my-first-spark`，保存并核对应用到所选聊天。回到聊天输入 `/hello-spark 小明`，即可看到问候。

### 为已有项目插件补充节点说明

在插件根目录创建 `devclaw.project.json`。将 `dev.code` 改为原工作流中实际存在的节点名称：

```json
{
  "apiVersion": "devclaw.project/v1",
  "name": "我的开发项目",
  "description": "为已有项目插件补充节点说明。",
  "help": [
    {
      "title": "使用方式",
      "body": "将本文件保存为插件根目录的 devclaw.project.json，节点名称须与原工作流一致。原技能与 Hooks 继续负责执行和检查。"
    }
  ],
  "stages": [
    {
      "nodeId": "dev.code",
      "guidance": "根据需求完成代码修改。",
      "before": [
        "确认需求和输入资料。"
      ],
      "after": [
        "运行原插件的检查，保存结果后按原流程提交。"
      ]
    }
  ]
}
```

这份声明提供页面说明。技能、节点执行和阶段检查继续使用原插件的实现；它不会替代验证器或改变审批规则。
