# 会话切换与搜索定位优化验证

分支：`codex/fix-thread-switch-search`。基线：`7f12780d`。环境：Windows、Node 22.23.2、仓库安装的 Electron / Chromium。

2026-09-10 更新：二次检视发现的 3 项问题已修复，最终实现和验证边界见 [修复验证报告](chat-navigation-fix-validation-2026-09-10.md)。本文及 [二次检视报告](chat-navigation-review-2026-09-10.md) 保留历史数据，不代表当前实现。

## 原因与修复

1. `ChatContainer` 随会话重新挂载，首轮渲染尚未取得滚动容器。原 `ChatMessageVirtualList` 对不超过 100 条的消息先完整渲染普通列表，随后再挂载 Virtuoso，造成 Markdown 的重复解析和组件挂载。现在首轮仅渲染容器、历史入口和页脚，取得滚动容器后直接进入虚拟列表。
2. 搜索虽创建了关键词 Range，却对整个消息行执行居中滚动。同一消息高于视口时，不同命中落在同一位置。现在根据活动 Range 的矩形定位；展开后等待连续帧的布局稳定，避免 Virtuoso 高度测量再次改变视口位置。收敛最多 60 帧，取消后不继续定位。
3. 长回答的搜索投影沿用了流式预览的首尾片段，折叠的中段根本没有进入索引。现在已完成内容允许在既有文档预算内索引中段，定位时展开 Markdown。正在输出的回答仍使用首尾预览，结束时更新搜索文档缓存。数据库历史搜索使用相同的已完成内容投影。
4. 历史分页加载后，旧回调可能仍引用加载前的消息索引。现在异步加载完成后调用最新已提交的回调。
5. 流式内容刷新原本可能取消正在进行的定位，或者重新挂载已经滚出视口的活动命中。现在刷新只重绘已挂载行，待执行的导航单独管理；换词、关闭、卸载及滚轮/触摸输入使旧导航失效。

用相同夹具加载基线代码与当前代码，记录取得滚动容器之前的工作量。`CHAT_NAVIGATION_BASELINE_REF=7f12780d` 可运行基线对照；旧版本预期违反新回归断言而返回非零。

| 1 | 1 | 0 | 10.8 ms | 0.8 ms |

这些数值衡量被消除的首轮重复渲染，不代表整个会话切换耗时，也不是不同硬件上的性能保证。实际 Electron 测试另外记录点击事件至目标消息挂载的耗时，以及包含自动化等待的总交互时间。

最终 Electron 运行的 6 次切换：259.7–411.3 ms，中位数约 285.7 ms，每次仅挂载 1–2 条消息。时间由页面内点击事件、MutationObserver 和下一帧标记记录；自动化定位器的轮询等待不计入该数值。受控生产者在导航与搜索过程中累计发出 156 段内容，最终 renderer 无未处理错误。

旧版本还复现了：长消息两个关键词都不在视口内、折叠中段没有匹配、流式刷新重新发起定位、异步历史加载使用旧回调、手动滚动未取消待执行定位。

## 全仓库检查与限制

`npm test` 的 Vitest 阶段结果为 312 文件通过、34 文件失败；2461 用例通过、52 失败、43 跳过，另有 3 个未处理错误。默认并发下存在 Worker / Git / 性能断言超时，也存在缺少 Chrome 扩展脚本、Windows socket / SQLite 清理及既有契约失败。原命令在 Vitest 失败后未执行后续独立套件，已另外逐项执行并保留每项退出码。

后续独立测试共执行 71 项命令，69 项通过。`workflow-worktree.spec.ts` 达到执行器设置的 180 秒上限后仍未结束，已终止该测试进程树，未宣称其通过；`im-remote-approval.spec.ts` 在文件写入审批文本断言处失败，已在 `7f12780d` 原始源码复现同一断言。独立套件统计按命令计数，不与 Vitest 用例数相加。

从 `7f12780d` 导出原始源码，在独立目录复跑了 8 个失败文件，复现 19 个失败用例（21 个通过）：`open-in-ide`、Chrome popup / service-worker / cookie bridge、`managed-run-store`、IM native adapter、Harness artifact isolation / settings。其余全量失败不能据此一概认定为基线问题。

全量 `npm run lint` 返回 88 个错误及大量既有格式警告，扫描范围包含已有辅助脚本和本地生成目录。本次修改文件的定向检查无错误，不能把全仓库 lint 描述为通过。

搜索继续保留现有预算：单文档扩展投影最多 256 Ki 字符；历史搜索保留数据库扫描、响应及内容加载预算。超出预算的内容不是无界全文检索。定位折叠回答会展开全文，超大单条回答仍有一次性的全文渲染成本。原有跨 Markdown 文本节点的整句匹配限制不在此次修改范围内。
