# 插件组合工作台：现场操作

这段占总演示约 4 分钟。展示两个独立插件配合，使用真实本地任务；不调用商业模型，不联网，不用动画模拟任务。

## 会前准备

1. 使用本轮交付应用。创建新的普通聊天，项目目录选择本交付包的 `workspace`，并在该目录运行 `node --version`，确认 Node 可用。目录最初只有 16 份真实输入文件。
2. 从 **自定义助手 → 找功能 → 挑选灵件** 进入 **挑选使用**，在“挑一个小帮手”找到本工程示例。先添加并使用 **任务能力提供方**，再添加并使用 **个人任务工作台**。每次核对当前聊天、项目及版本权限后确认。
   若应用仍是旧包，使用 **上传插件（ZIP）** 分别导入 `plugins/task-provider.zip` 和 `task-workbench.zip`，在同一聊天明确授权并加入组合；不要同时安装同名不同内容版本。
3. 可选安装本工程的 **前缀提醒**、**精简提醒** 和 **编辑提醒**，分别核对授权。行为插件登记不代表已替换原行为，稍后仍需预览并确认。
4. 在聊天输入框写一句未发送的草稿，再打开 **个人任务工作台**。任务默认约 3 秒；每次真实读取文件后输出名称和大小。不要将等待间隔当作产品速度指标。

## 现场顺序

| 时间 | 操作与真实结果 | 汇报内容 |
| --- | --- | --- |
| 0:00–0:40 | 展示提供方和工作台来自两个独立目录，打开 `sources/task-workbench/hooks/register.ts`，定位 `$.platform` | 提供方负责真实任务，消费方负责页面；以版本化契约复用，不需要改 Electron、IPC 或原生 UI 源码。 |
| 0:40–1:30 | 在工作台填任务名、点 **启动实际任务**；核对原有命令/文件批准后允许本次；看表格状态和真实输入文件输出 | 原任务权限、进程和执行证据由平台接管；增加页面不等于获得执行权限。 |
| 1:30–2:00 | 如需展示取消，第二次启动后立即点 **取消 …**，等状态核对；若已完成，按实际结果说明 | 取消按资源退出确认；页面关闭只停止展示订阅。示例每聊天最多 8 项任务，排练和正式演示使用新聊天。 |
| 2:00–3:10 | 打开 **行为设置**，两个替代实现同时选择时 **预览顺序与影响** 会提示冲突；每个处理点只保留“前缀提醒”，重新预览、**确认应用**；回工作台点 **核对通知样式** | 用户明确选择行为实现；本例仅替换通知和输入建议，不能推导全部业务已支持替换。 |
| 3:10–4:00 | **停用全部并恢复原实现**，再次核对通知；**返回聊天** 看原草稿；可选 **工作台设置** 改标题 | 支持撤回和继续配置。扩展局部更新，聊天与草稿保留。 |

编辑提醒作为备选镜头：打开 **编辑提醒** → **明确写入示例文件**，核对批准后查看 `edit-reminder.txt` 的实际内容与宿主完成提示。该动作仅新建，不覆盖已有文件；复演使用新工作区，不删除用户文件。

## 如何解释开发方式变化

以前新增一个这样的原生功能，通常需要主进程、IPC、preload、页面、权限和打包的配合。现在，这个例子的提供方和消费方分别在插件中声明动作、状态和展示位置，复用平台已有的授权、执行、订阅、控件和诊断机制。

作者仍需编写业务代码、明确契约并验证行为；“这个受支持的插件不用修改平台源码”有证据，“任何功能零代码、全部页面均可替换”没有证据。

## 故障与复演

- 找不到工作台：核对同一聊天的两个插件都已应用、源版本授权有效、灵件已开启。安装和正在使用不是同一个状态。
- 命令不可用：会前检查系统 Node；不要在现场自动安装环境或改用假结果。包检查通过不等于已启动业务任务。
- 任务太快：展示真实完成和文件输出，取消是选讲；不要用固定进度冒充仍在运行。
- 结果未知或批准被拒绝：保留记录、重新读取真实状态；不换请求键盲目重跑。
- 需要再演：新建聊天；文件写入演示另用新目录。打包脚本拒绝覆盖旧交付目录。

已有工作台截图属于之前固定 ASAR 的真实执行证据，不能替代本次安装后核对；长测已经按用户要求暂停，不汇报性能全面验收通过。
