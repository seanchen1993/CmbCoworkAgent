# 项目模式演示：两个插件交接一份真实成果

这是 15 分钟总演示中的 3–5 分钟片段。现场展示的是插件定义流程、宿主保留检查与确认、不同插件交接成果。业务模型实时生成文件，耗时取决于所选模型；不承诺所有模型都在五分钟内跑完。

## 演示前准备

在本仓库使用 Node 22，运行 `npx tsx scripts/package-project-demo-kit.ts` 得到交付目录；默认目录必须不存在。
复演另打一份时用 `npx tsx scripts/package-project-demo-kit.ts output/deliveries/project-leadership-demo-rehearsal-02`，同样只创建新目录，不覆盖旧交付。
打包后可执行 `npx tsx scripts/verify-project-demo-kit.ts output/deliveries/project-leadership-demo-20261016`，核对 ZIP 哈希、原安装检查入口与空工作区。
不要把整个交付目录作为一个插件安装。

1. 在 **自定义助手 → 添加功能 → 我已添加** 的原插件区域，使用 **上传插件（ZIP）** 分别导入 `plugins` 中三个 ZIP，确认并启用。
   如果当前布局把上传放在插件管理入口，仍选择 **上传插件（ZIP）**；安装不等于批准或运行。
   若已安装同名同版本的 `autobiz-project-composition-demo`，直接复用并启用，不替换原生产 AutoBiz。首次进入项目模式若弹出使用引导，点 **知道了，不再提示**，再进入项目。
2. 选择实际可用模型。`requirements/goal.txt` 是待执行的真实输入；`requirements/orders.csv` 是同一份输入数据，均不是预制成果。
3. 已有项目直接进入项目对话。没有项目时，提前在 **项目模式 → 新建项目** 创建演示容器：项目编号 `MODSDEMO`、名称“订单日报演示”、系统编号 `LOCAL`、系统名称“本地演示”、插件 `autobiz-project-composition-demo`、插件工作区根目录选择交付目录下 `workspace`，本项目产物文件夹 `order-report`。项目编号检查完成后创建，不启动 AutoBiz。
   该旧插件容器需 Python；请会前检查 `python --version`。现场不做企业关联、不配置企业 MCP、不部署、不提交或推送。
   企业编号查询未配置或失败时，页面显示“关联精益项目失败”，本地创建仍可继续；先等编号检查结束。不要通过数据库或测试钩子伪造项目。
4. 进入该项目的对话，确认标题栏有 **项目能力**。本地项目任务的单模板阶段入口是另一条路径，不将它冒称多插件组合。
5. 打开 **项目能力**，依次添加 **起草并审核需求文档 · leadership-project-docs** 和 **数据口径、开发与验收 · leadership-project-data**。
6. 第二套流程的 **前一套流程的需求文档** 选择第一套流程的 `draft`。文档流程的可选 **前序已检查资料与源码变更** 留空，本主线没有运行 AutoBiz，不假称使用了它的源码。
7. 将 `requirements/goal.txt` 全文粘贴到 **这次要做什么**，点 **保存流程草稿**。确认这是演示项目，不是业务项目。

输入在共同任务中提供。平台不会自动把交付目录的任意文件复制到隔离运行；不能声称模型已读未映射的 CSV。这里只有显式选择的 `draft` 由宿主交接。

**严格 3–4 分钟场合**：会前可按正常入口启动这次真实任务，停在第一套的人工确认处。现场从查看真实草稿、确认批准、交接到第二套开始讲；明确说明起草已在会前执行，不把它说成现场即时生成。模型等待超过时间预算时保留原状态，展示已完成的排练记录。完整冷启动路径仍按下表操作。

## 失败时怎样复演

- **安装/目录不可用**：使用交付目录的新路径，确认插件已启用；不要覆盖现有业务插件。三个包名字独立，原始示例不变。
- **模型慢或连接失败**：保留现场状态，切到已有证据并明确说明；不把历史产物写入当前运行，也不手改数据库或阶段状态。
- **第一套检查失败**：展示第二套仍未执行，打开原文件核对；修复后按原入口检查/恢复。结果未知时先核对，不重复启动有副作用操作。
- **拒绝工具或阶段确认**：这是真实拒绝。解释记录后结束该次；需要新一轮时重新预览并明确启动，不“批准全部”或伪造回执。
- **会前排练**：在新演示容器完整跑一遍，记录实际模型、耗时与产物；明天另用新容器或新组合运行，原排练记录保留。`workspace` 初始没有任何业务成果。
