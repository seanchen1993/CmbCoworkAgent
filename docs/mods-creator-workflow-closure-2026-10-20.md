## 二、实际使用流程

1. 在创造者聊天描述需求；改造原始插件时指定来源，要求保留知识、配置、Hooks 和产物检查。助手检查真实源码并提出首次模块化方案，用户在原生确认卡审查后创建独立候选。
2. 打开“插件创作工作区”，进入“运行试用”，核对候选、目标、参数及权限，创建独立试用并通过原项目运行器启动阶段。阶段会话无需逐一打开才能判断整轮进度。
3. 在“验收结果”查看阶段、必需产物、原检查及推进凭据。效果不足时提交反馈回原聊天，修改候选后重新核对和试用；不自动重放未知操作。
4. 在“保存为插件”指定新名称和版本，准备并检查源码，再确认安装或导出 ZIP。安装后到“添加功能 → 我已添加”找到并启用新插件，再从其项目入口使用；首次使用填写参数并确认权限。新环境重新配置知识目录、用户参数和权限。保存、安装和导出均不等于业务验收完成。

Host 组装来源与项目候选同时存在时，按 planId、copyId、digest 严格关联，只提供一套当前试用与交付主入口；原组装预审、来源和诊断保留。旧试用表单返回 Host 请求后自动接回原工作区，不停留在无法继续的 Legacy 表单。

## 三、平台、适配器与插件边界

| 层次 | 职责 |
| --- | --- |
| 平台公用能力 | 作用域及版本身份、不可变源码候选、原生确认、项目与阶段事实绑定、检查回执投影、通用来源观察接口、独立安装与导出 |
| 创造者 | 理解需求、读取受限原源码、生成明确的契约和组合方案、读取实际试用结果、依据用户反馈修改源码；不能自行批准或授予权限 |
| Mods 与插件 | 声明实际阶段、知识和资源、配置、产物、检查、人工审批及扩展能力；原文件与资源闭包必须可核对 |
| 受审适配器 | 解释原运行器的状态、上下文和校验协议；AutoBiz 的专有 checkpoint 与知识装载解释保留在适配器中 |
| Hooks | 继续承担原生命周期校验和阻断职责；观察者读取真实成功收据，不能覆盖必需校验、人工门禁或原提交决定 |

此次未新增 AutoBiz 专用平台流程分支。独立供应商准入案例使用通用 Host 线性适配器，将主体资料、独立资质 Mod 和准入报告组合为三阶段，实际传递用户配置、知识正文和上下游产物。错误资质即使模型正常结束也会被原生 Schema 检查阻止推进，修正后才完成全流程。

## 四、首次模块化的保真与安全边界

安全快照范围内的原资源完整保留；缓存、运行态和敏感文件按既有规则排除并列示。追加文件只允许受限命名空间、文件数和字节量，不覆盖原身份、运行时或原文件。共享 Skill 别名保留同层目录与相对引用；需要生成别名时，技能生命周期 Hook 或未知 Hook 声明会阻止自动改名，须先明确映射。未知协议、资源遗漏或契约不等价也会阻止迁移。

配置读取采用结构感知的脱敏投影，不修改原文件及摘要；此能力不是任意文本秘密扫描。原插件身份、目录、源码摘要与确认范围在首次检查、迁移、组装至 Host 请求准备等关键原生操作中重新核对。形成独立 Host 草稿后，交付核对该固定草稿及实际文件，不持续依赖原插件的后续版本。不复制原插件运行授权；本次首次模块化和交付事务的批准不随重启恢复。

Host 整轮验收依据原项目完成、全部阶段真实检查与推进凭据及必需产物检查；当前版本可交付还要求候选版本匹配。旧版本的原通过记录保留。Legacy 缺少受审契约或收据时，整轮验收投影保持未知，原执行器自身的完成历史仍保留。历史回执只证明检查时的产物，不持续重验磁盘；超过记录展示上限时保守拒绝整轮通过。

## 六、明确保留的限制

- S6 阶段快照、回退、隔离阶段调试与中间阶段重跑继续暂缓；本轮同阶段修正属于既有运行器能力。
- 不自动推断任意原始代码、未知动态流程、原生 Function 首次拆分或未映射的强制 Hook 与上下文协议。
- 保留原能力声明不等于新增 DAG、并行阶段调度或执行授权；Host 组装仍遵循原支持的流程契约。
- 确定性本地模型验收证明实际工具及原运行链路，不证明外部模型质量、业务审批结论或完整 AutoBiz 生命周期。
- 本轮没有测量 token 节约、响应延时或性能收益，不提供定量提升结论。
- 操作结果未知时不自动重放，交付未知态也不承诺自动恢复。技术检查通过仍需要业务效果评审。
