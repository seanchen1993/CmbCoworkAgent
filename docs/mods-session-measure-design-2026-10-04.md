# 任务后的用量通知

桌面交互之后，继续补上 `session.measure`。用户不需要点新的按钮：实际任务结束且真实用量发生变化时，已启用的组件可以更新自己的用量提示。它是通知，不会修改模型回答、账单或任务结果。

依据是 [官方事件用法](https://code.claude.com/docs/en/plugins/mods/events) 和本机核验的 Claude Code 2.1.288 内置类型声明 `SessionMeasureInput`、`SessionMeasureResult`。不能把本地没有的数据填成 Claude 账户统计。

## 数据与触发

- 只接在实际主助手图任务的 `afterAgent` 收尾链路，保存真实最终状态之后、原运行释放之前通知。使用已经加载的会话，不额外启动模组或模型。子助手完成不冒充主会话用量变化。
- 已加载的处理函数没有 `session.measure` 事件名匹配（包括通配符）时，直接返回，不查询用量、不发布事件、不创建定时器。不会调用可能加载新会话的通用处理函数查询。按数据筛选的条件必须读取真实输入之后才判断，不承诺这类条件也零查询。
- 用量来自现有 `session.usage` 的真实宿主读取。提供模型窗口与已有模型响应报告的输入量；没有报告时不填输入量。不要从回答字数推算令牌。
- 当前本地没有 Claude 订阅额度和美元成本账本，因此 `rateLimits` 保持实际空数组，`cost` 省略。第一份有效测量通知 `context`；只有实际数字变化才再次通知。不发送空的 `changed`。
- 不提供 `breakdown`；作者可自行调用已有的 `$.session.usage({breakdown})`。不增加不存在的 `$.session.measure()` SDK 方法。

## 处理与安全

- 用量、变化类别全部是宿主固定事实；处理函数改写后传给下游时恢复原事实，无法伪造。`next(e)` 回答原 `changed`，处理函数自己的返回值不改变任何宿主数据。
- 每个会话同时只运行一份通知；同一通知在处理期间出现多次新请求，只保留最后一份待处理请求，不无限排队。待处理请求各自保留原宿主作用域，不能继承另一任务的身份。
- 在 `afterAgent` 捕获原物理运行绑定，读数据前后、内容保护前后、每个处理函数和 SDK 边界都复核原绑定、批准和取消状态。沿用传入的原生主助手 authority、turnId、agentId 的执行上下文，`leased=true`、`userInitiated=false`，不生成替代身份。会话替换、关闭、撤权后不能向新会话发布旧通知。直接使用宿主真实用量读取，不经可以改写的 SDK `session.usage` 处理链。
- 事件输入和返回沿用内容保护；事件不能扩大组件已批准的 SDK 能力。观察处理函数使用原任务已有的身份，不新建执行身份。
- 整份通知从真实读取、保护、处理到 SDK 共用 5000 毫秒预算。超时会取消通知及它的 SDK 请求；只有通知的错误、超时或缺少真实用量不改变已经完成的回答。原来的最终状态保存和 peer 清理保留，原 capture 异常及任务自身取消继续按原任务处理。期限后的回调不能继续发布或调用能力。
- 通知结束时终止它自己派生的计时器和进程资源，不取消原任务或其他通知的资源。需要长期后台服务的组件应在原有会话启动或明确命令入口启动，不在这个短期测量通知中留下后台服务。这是本次有限通知的明确适配范围。
- 测量基线在已通过保护、筛选匹配、真实 guest 通过并发帧限制并接纳调用，且再次检查原绑定之后原子前进。接纳之前取消、失效、读取、保护或并发容量失败不推进；接纳之后的处理函数错误或通知超时不回滚已发出的测量。使用私有运行时接纳回执，组件不能通过 SDK 伪造它。全不匹配不推进。关闭会话销毁基线和待处理项。
- “已发出”不代表回调已经执行或成功。宿主提交基线到运行进程收到接纳回执之间仍可能取消或卸载；回调可能尚未执行，基线保持，也不自动重发同一数字。新的实际变化仍会通知。此处采用官方声明的“上次发出的测量”含义，不提供跨进程必达或只执行一次保证。

## 验证

真实 QuickJS 测试首次通知、不变不通知、变化通知、改写与伪造返回无效、两个插件组合、查询细分类别、重入与合并、错误和超时、取消、撤权、绑定替换与保护期间的竞态。宿主集成验证实际图任务收尾入口、子助手跳过和无订阅零查询。特别验证已有 `turn.complete` 在释放后才发出的行为仍保留，测量不从该逻辑通知重新认领已死亡的物理身份。真实 Electron 运行一条离线模型任务，组件读取通知并更新右侧显示；关闭 Mods 后沿用原有聊天结果。

性能分别记录没有订阅时的开销和实际小组件通知的用时。此阶段没有订阅额度后台刷新源，不能称为与 Claude 的所有测量来源完全一致；后续接入真实来源时复用同一通知机制。

## 原始实现复核与回归修订

校验过的 2.1.288 软件包中，可读 `extracted/chunk-xg8vtq37.js` 的测量程序先更新上次已发出的基线，再调用 `session.measure`，失败后只记录问题、不回滚。当前私有接纳回执选择更谨慎的宿主接纳点，但不能将其宣称为插件回调已经执行的必达保证。

真实 Electron 回归发现 policy-only 普通聊天开关冲突。经两位独立方案审查后，真实宿主模型入口使用整体活动状态，插件 SDK 授权仍使用插件启用状态；空插件链保护输入、逐帧及终值，原生子任务沿用自己的身份。提示入口统一双向保护，覆盖启用但没有组件、未就绪及缓存命中场景；上下文以每一边的实际值同步，附件专用校验在发布前后进行。所有新增等待后的下一步调用再次复核原绑定、设置版本和取消状态。无组件路径不加载插件，原 transport 保留。
