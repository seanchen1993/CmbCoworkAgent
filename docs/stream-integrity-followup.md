# 流式完整性修复与检视

分支：`codex/fix-stream-snapshot-white-screen`。本轮基于白屏修复提交 `b020724b`，修复先前检视中发现的三处数据丢失，并补齐端到端测试发现的快照续写问题。

## 问题与修复

1. **合法增量被误判成累计快照。** `"哈"`、`"哈"`、`"，你好"` 和 `"a"`、`"ab"` 都是合法增量；文本前缀不能证明生产者发送的是快照。标准 `AIMessageChunk` 现在默认按增量处理。累计生产者须通过事件元数据或 `messageChunkModes` 明确声明正文、reasoning、工具参数各自的协议。完整 `AIMessage` 仍按快照处理。未修改输入消息及图状态。
2. **消息引用抽样漏掉中间工具结果替换。** `values` 优化现在逐项比较当前轮次的消息引用，并复制引用槽位，能识别新数组及原数组的槽位替换。确认前缀不变后才发送 append/tail。稳定消息正文和旧轮次历史仍不重复序列化。
3. **文本抽样漏掉中间内容更正。** 明确的快照做完整前缀比较；单调增长发送差值，缩短、更正及清空发送替换快照。正文、reasoning、工具参数使用相同规则。
4. **更正后 SDK 仍从旧正文继续累计。** 实际 Electron 测试暴露：custom 替换事件更新了页面，但未更新 SDK 分片缓存；后续低优先级消息还会被页面保留的快照挡住。适配器现在同步替换该消息的累计起点，并让其后续消息保持相同内容优先级。仅处理明确包含正文的助手快照；纯 reasoning 事件仍走原回调，不逐 token 重建缓存。短 `values` 漏掉该消息时，仍从 SDK 缓存保留未完成工具参数。其他消息、工具流、普通局部快照均保留；重试和新提交清理状态。

前三项在未修改的序列化器上均已复现。第 4 项通过新增 Electron 用例及两项失败单测定位；检视新实现时又补测了“局部 values → 更正 → 工具参数继续”，在提交前修正其参数缓存保留行为。

## 协议和性能约束

- 不再自动猜测非标准累计 `AIMessageChunk`。应用当前的 OpenAI Completions 适配器处理 SSE delta；自定义累计生产者迁移时必须声明协议。元数据可覆盖序列化器的字段默认值，各工具调用可独立声明参数模式。
- 引用比较依赖 LangGraph reducer 的消息对象不可变约定。支持替换数组槽位，不承诺检测保持对象引用不变的任意深层原地修改。
- 普通增量不扫描已经收到的正文。`values` 检查成本为当前轮次消息引用数；快照文本比较成本与收到的快照长度有关。不能再声称抽样校验提供完整相等性证明，也不能声称所有累计快照的 CPU 成本与最终输出长度线性。
- 显式累计快照的完整比较比旧抽样更耗 CPU。传输量仍只包含增长差值或必要的替换内容。这是正确性修复的明确取舍，应优先在生产者端输出标准增量。

## 检视的模块边界

产品改动集中在主进程序列化器、共享协议说明和 renderer 流适配器。没有修改提示词、技能加载、工具执行器、LangGraph 状态 reducer、Goal/Stop 的判定算法、审批协议或工作流脚本。

序列化数据也进入持久化、trace、Stop 上下文及 Goal 子轮快照，不能将其视作纯 UI 数据。新增测试通过实际 SSE 解析器、三种模型适配器、真实 `createAgent` 图、工具执行和 TurnCompletionGate：工具收到 `haha`；空回复触发一次续跑；流、缓冲输入、最终快照和 Goal 文本均保留 `哈哈，你好。`；每一帧投影与完整序列化结果比对；原始输入在序列化前后不变。

这些验证覆盖标准增量和完整 values 路径。HTTP 响应使用固定 fixture，没有调用真实模型服务，不能据此声称真实模型质量或所有第三方累计协议的验收结果已经测量。

## 复验入口

使用 Node 22、具备桌面会话的干净工作树，运行 `npm run test:stream-white-screen`。此命令覆盖序列化、工具/正文累计、模型图、关闭行为、真实工具卡片及 Electron 场景。`npm test`、`npm run typecheck` 和 lint 另行运行。

测试创建隔离用户目录，仅替换模型/IPC fixture 和原生对话框回答，不覆盖用户安装、不操作用户会话、不自动重试真实任务。日志、性能对照和截图在 `output/stream-integrity-fix/` 与 `output/stream-white-screen/`，均不提交。
