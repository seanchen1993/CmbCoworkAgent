# 完成证据主动失效

宿主在每次完成检查通过后，保存有界的重新核对入口。现有 workspace watcher 的文件或
Git 元数据通知，以及插件配置写入，会合并触发核对；核对只捕获当前证据，不重新执行
插件、模型、单元测试或业务 validator。同内容写入不会使 PASS 失效。

文件、需求、diff、插件源或完成规则变化后，宿主追加 `invalidated / stale` 记录，撤销
相应 checkpoint 的活跃证据入口，并刷新当前任务 UI。已有执行记录保持原始事实。
撤权、关闭、runtime 替换和 session 关闭会停止定时器并中止核对。重启后的历史记录读取
不会加载 guest；没有原运行时的 PASS 会补记失效，不能恢复为当前执行授权。

每个 session 最多保留 32 个核对入口，通知合并窗口 75ms，每次核对整体上限 10 秒。
达到容量上限的旧入口明确失效；核对失败或超时不会被解释为仍然通过。关闭模块时不做
文件扫描、不发现插件、不创建 runtime，也没有常驻轮询。证据存储失败不会阻断撤权
或 runtime 关闭；活跃推进入口仍先被移除。

主动通知沿用应用现有物理 workspace watcher 的覆盖范围，不新增每个插件的递归监听。
历史记录不表示未监听期间文件始终不变。实际完成门禁每次重新捕获，checkpoint 推进
仍执行既有完整核验；通知和 UI 展示均不能代替 validator 或成为推进权限。

UI 摘要按最新执行记录及其绑定匹配失效事件，避免旧 runtime 的迟到事件覆盖新检查。
已确认的 checkpoint 推进是历史提交事实，不会因随后文件变化被伪装成从未提交。

验证见 `output/mods-v2-validation/2026-09-23-completion-freshness.md`。
