## 本轮方向

**先把灵件平台底座做完整，再接项目模式和各类业务插件。** 暂不推进 AutoBiz、衍生插件和项目模式的专项改造，也不把它们作为平台建设的前置条件。

全范围 DIY 仍是最终目标。当前阶段要交付的是可供各业务模块复用的扩展机制：作者能够注册能力、读取状态、接收变化、执行动作、增加页面、替换业务行为，并完成试用、配置、升级和恢复。后续业务模块接入同一机制，而不是每个场景再造一套接口和运行系统。

本方案调整[全范围 DIY 报告](devclaw-sparks-capability-gap-and-target-report-2026-10-15.md)的近期实施顺序。报告中的全业务清单保留为最终验收范围；平台底座通过不等于所有业务模块已经接入。

界面与使用路径遵循[交互布局与文字优化说明](devclaw-ui-ux-optimization-review-2026-10-15.md)：配置与执行连贯、一个任务输入位置、同处查看进度和结果、简单与高级共用草稿。扩展机制不应继续增加割裂的任务入口。

## 平台首先提供什么

### 一套业务能力协议

每项能力具有稳定身份、来源、协议版本、输入输出类型、可用范围和所需权限。平台同时支持内置模块提供能力和作者增加新业务能力；增加新的业务类型不要求修改平台核心代码。

| 能力 | 具体要求 |
| --- | --- |
| 注册与发现 | 能列出实际可用的能力、版本、用途和不可用原因；发现过程不执行 Hook、启动任务或调用模型 |
| 状态读取 | 返回有来源和版本的真实状态；无法确定时明确表示未知，不从界面文字猜测结果 |
| 变化通知 | 按目标订阅，支持退订、有界缓冲、重复与迟到消息处理，断线后重新读取；不广播全量聊天历史 |
| 动作执行 | 输入校验、当前授权、目标校验、取消、结果记录和失败原因走原执行链 |
| 对外复用 | 另一灵件可以在获准范围内发现、读取和调用作者注册的能力；不能因此继承提供方的全部权限 |
| 版本协商 | 能判断可兼容版本、缺失能力和失效配置；旧授权不能因接口升级静默获得新权限 |

能力注册不等于执行授权。主进程确定真实会话、工作区、运行、来源和版本，调用方不能靠传入标识取得其他目标的权限。动作的可取消性、重复请求语义和外部副作用需要声明；结果不明时不盲目重试。

平台协议按真实用例逐步形成，先交付最小完整链路，不先构造覆盖所有业务的巨大通用对象。原生 IPC 不能直接作为不受控的灵件接口。

### 一套界面与行为扩展机制

界面支持注册独立页面、导航项、侧栏、卡片、操作入口和设置表单。使用同一组数据与动作接口，提供常见的列表、表格、树、图表、日志及交互表单组件；后续按需要补充编辑等组件。

行为扩展点区分前处理、后处理、策略选择和实现替换，声明顺序、依赖及冲突。替代实现可以明确委托原实现；用户可以预览、应用、停用和恢复原版。先接通少量真实处理点验证机制，再逐步覆盖完整业务清单，不能声称注册机制已经自动接通所有模块。

自定义界面失败只影响所属区域，保留可信的停用与恢复入口。组件、订阅和局部刷新不重建整块聊天历史，不通过反复卸载聊天树来刷新扩展。可信授权证明、隔离、凭据保护和真实结果不能被替换实现绕过。

### 一套制作、配置和生命周期

普通用户的主路径为：**描述需求 → 看效果与影响范围 → 确认试用 → 核对效果 → 保存使用。** 继续修改时显示修改前后差异，不要求用户理解接口名称。

- 本地预览、隔离测试、授权后的真实验证明确区分。实时网络和实际工具调用需要真实验证，不能以演示数据标记完成。
- 权限围绕用途、目标和影响展示，技术清单折叠。待确认、排队、正在试用、失败和已生效分别显示明确的下一步。
- 配置目标直接选择；安装库、目标实际启用项、应用级与局部配置区分清楚。适用范围由宿主校验。
- 停用、撤权、取消、升级和删除覆盖订阅、计时器、页面、待完成调用及后台资源。旧版本迟到结果不能更新新版本。
- 升级先验证兼容和新增权限，切换失败保留可用版本或给出回退入口；恢复不能重复执行结果未知的操作。
- 持续任务明确关闭窗口、退出应用和重启后的语义。退出后不能执行的任务如实停止；可恢复任务先核对状态和权限，不承诺应用退出后仍凭普通计时器运行。

## 用独立小示例验证底座

示例只用于证明通用机制，不依赖改造项目模式或原业务插件。测试使用隔离目录、受控模型或本地服务，不执行真实外部业务。

首条闭环采用“个人任务工作台”：一个独立示例包提供可取消的本地任务、真实状态、事件和动作；另一个独立包通过公开接口制作页面与设置。任务使用获准的隔离文件或本地进程实际执行，展示启动、进度、完成、失败与取消，不用倒计时动画冒充任务。该用例贯穿 G1–G3，避免先堆协议再找使用方。

| 示例 | 验证什么 | 不能替代的验收 |
| --- | --- | --- |
| 编辑提醒 | 宿主已有真实文件编辑动作完成后发出事件；示例更新卡片，并允许用户执行一个需授权的文件动作 | 只手动模拟发事件或改变文字，不算真实执行链接入 |
| 个人任务工作台 | 一个作者包注册新的业务数据、动作和事件，另一个作者包提供页面、导航和设置，实际任务可取消；获准后跨包组合使用 | 只有内置模块或测试代码能注册、只有假进度，不算作者可扩展 |
| 界面与行为替换 | 两个独立扩展竞争同一处理点，预览冲突、选择顺序或替代实现，再停用恢复原版 | 只增加卡片，不算实现替换；替代后绕过原权限也不算通过 |
| 真实试用与版本更新 | 获准后通过本地 HTTP 或隔离文件验证真实调用；新增权限升级、失败回退和资源清理 | 模拟天气、批准成功或安装成功，不代表实际能力已经生效 |

## 成组实施顺序

| 工作组 | 集中交付 | 退出条件 |
| --- | --- | --- |
| G1：能力协议与真实闭环 | 注册、发现、状态、通知、动作、作用域、版本及最小 guest SDK 接线；个人任务示例的提供与消费，接入一个真实宿主动作 | 经实际 guest、主进程及展示入口走通调用；另一灵件可获准复用；拒绝跨目标访问，停用后退订 |
| G2：页面与行为扩展 | 通用页面、导航、侧栏、设置注册；业务处理链的组合、替换、冲突与回退；自建工作台示例 | 作者无需改平台源码即可新增页面和替换已接通行为；禁用恢复原生体验，原聊天连续可用 |
| G3：制作与运行保障 | 分级真实试用、配置目标、简明操作、升级回退、任务及资源生命周期、统一诊断 | 创建到正式使用、继续修改、升级失败和恢复均走通；结果未知不重放、资源清理可核对 |
| G4：集中验收与接入规范 | 独立示例、作者模板、接口版本说明、性能与完整回归、双 agent 回检 | 底座的实际用户流程与开发者流程通过；明确已接通的原生处理点和仍待接入的业务模块 |

有依赖的协议先定，互不依赖的实现可并行成组推进。在集成节点集中做完整回归；授权、来源、并发、持久化及清理边界先做针对性测试。每组完成后自主进入下一组，不要求用户逐组提醒。

## 验收与保护要求

1. 新作者从模板注册一个新业务能力和页面，另一灵件能发现并组合，不修改平台源码，不硬编码示例名称。
2. 数据读取、事件、动作、页面和行为替换使用实际 guest 与主进程链路；不能只验证类型、纯函数或模拟前端。
3. A/B 会话及不同工作区隔离，配置目标明确；撤权、来源变化、停用和迟到事件不会串数据或越权执行。
4. 事件突发、订阅恢复、版本切换、失败、取消及真实资源释放可验证；未知副作用不自动重放。
5. 新权限升级须确认；旧授权、旧灵件、旧普通聊天和未应用自定义的原生体验保持可用。
6. 在固定构建与环境下验证长会话、会话与模式切换、冷启动、最小化恢复及热更新；观察消息区域消失、闪屏、重复回答、输入响应和内存。沿用既有有效门禁，不放宽指标掩盖退化。
7. 完成至少 20 轮流式对话与至少 60 分钟活动观察，记录订阅和资源数量；单次短例通过不替代持续观察。
8. 运行窄回归、类型检查、完整测试链及隔离实包 E2E；保留首轮失败和后续修复证据。两名中等强度子 agent 检视实际代码与使用流程，确认范围内无未关闭 P2 及以上问题。
9. 作者文档和普通用户指引随构建更新，图片与实际入口一致，主界面只展示状态、结果和下一步。

本阶段不修改 AutoBiz 原包，不迁移现有项目，不把新接口默认应用到存量聊天。现有项目和插件作为回归保护对象，而不是本轮专项改造对象。所有代码与文档只在 `codex/mods-v2`；后续是否更新用户安装包按最终候选验收与应用退出状态处理。

## 后续如何扩展到全范围 DIY

底座验收后，再把项目模式、业务插件、Git 工作树、模型与连接管理等业务按完整清单接入。届时主要工作应是让既有业务实现公开这套协议，而不是再次设计授权、事件、页面、试用和生命周期。

如果接入一个新业务仍需复制整套宿主框架、修改全局主循环或另做一套状态面板，说明底座仍有缺口，应先完善通用机制。最终完成标准仍是全范围报告中的业务操作逐项验收，本阶段只是先把实现这些目标的平台基础做好。
