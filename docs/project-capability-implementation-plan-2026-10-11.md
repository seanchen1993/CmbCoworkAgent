# 项目能力包与灵件接入方案

## 授权与范围

用户于 2026-10-11 授权按分析方向实现，先经两名 medium 子 agent 评审，再连续实现相关能力，集中回归和体验检视。唯一代码工作树 C:/ai/CmbCoworkAgent-mods-v2，分支 codex/mods-v2。不修改 UAT、外部 Autobiz 仓库和真实业务数据，不自动提交已有混合工作树。

## 本次交付目标

将已有项目模式、插件和灵件连成可复用的项目能力包接入方式：同一 Feature 内提供阶段指导、前后检查规则、实际产物与 Hook 诊断、进入原阶段会话入口。开发者通过有版本的声明复用控制台，无须自己再编写看板、路径/状态推断和命令入口。Autobiz 为首个实例，第二个最小非 Autobiz 示例验证通用性。

阶段执行继续经过项目模式原会话/Skill/PreToolUse/PostToolUse/人工门禁/状态写入链。没有新的业务状态文件、阶段调度器或绕开原 Hooks 的 shell/IPC。原 Hooks、领域验证器、受控跳过、动态阶段、批次 Review/UTest/合并行为原样保留。声明和界面不授予权限，也不把历史成功日志解释成当前有效验收。

本次完成的是兼容现有执行链的通用接入版本。统一事务状态存储、任意 Python 自动翻译、原生 Flow 直接提交新版 Autobiz 阶段不是本次接口承诺；现有固定旧提交的 native Autobiz 适配不接管新版插件。后续可在兼容测试基础上替换底层实现，不改变本次声明及用户入口。

## 连续实施批次

### A：通用声明与宿主接入

- 新增 `devclaw.project.json` 可选静态声明，固定版本 `devclaw.project/v1`。含能力包名称、简介、内嵌中文使用说明，以及以 workflow node id 关联的阶段说明、前置检查说明、后置验收说明。说明只描述规则，不携带可执行命令、审批结论或可写状态。
- shared 中定义严格有界 schema/parser，未知字段/重复节点/过长文本拒绝；无声明时保持旧详情结构与行为。
- 主进程从当前已绑定插件根读取声明：有界异步读取、路径/链接边界检查，格式错误显示局部诊断，不阻断原项目模式。将解析结果附加到详情可选字段，纳入既有 IPC 大小限制；不得因静态声明加载执行插件或扫描目录。
- 通用投影函数连接现有节点、产物、Hook 日志与 nextAction。分别显示声明的规则和实际证据；未知、缺失、历史失败、仅生成文件不冒充通过。节点说明缺失时仍展示实际阶段，动态节点可使用通用说明。

### B：统一项目控制台与真实操作入口

- 在已有 Feature 详情加入独立、可测试的项目能力面板，仅声明存在时启用。直接复用现有产物预览、阶段选择、运行事件、人工审批和托管控制，不复制状态机。
- 默认展示当前阶段、待解决的产物问题、最近 Hook 诊断和下一步说明；前置规则/验收规则/使用说明折叠展开，不堆到聊天输入框上方。
- “进入当前阶段会话”复用原创建项目会话链，明确只是准备原技能会话，不能写成已执行/已验证；执行前重新读取当前详情/nextAction，不使用过期页面数据。已有托管运行或人工门禁时指向原记录/审批，不发起竞争执行。
- 查看其他阶段时不误触发当前阶段以外动作；加载、错误、未知阶段、无 nextAction、已完成、被删除、运行中、人工待确认均有明确禁用/提示。键盘和窄屏可用，无外部链接注入或 HTML 注入。
- 点击新入口后须重新评估普通项目会话 stream/workflowRunning、托管运行和独立 notifications 中的人工门禁；刷新 detail 不能代替后两项检查。已有运行指向原会话，待审批指向原审批，状态无法确认则阻止新建并提示刷新。同步 in-flight 防重复点击；覆盖刷新期间出现普通运行/人审、连续点击的真实回调回归。此限制仅作用于新能力入口，旧通用“新增会话”行为保持。
- 当前阶段始终以 run.currentNodeId 显示；选择历史/其他节点显示“正在查看”，避免将 selectedNode 标成当前执行阶段。

### C：Autobiz 与通用作者体验

- 在 examples/autobiz-fullstack-mods 中增加声明和使用说明，覆盖实际节点规则、前后检查、产物与过期验收。保持原 hooks 文件逐字节不变；现有打包器将声明随附进完整插件，不修改原 stage validator 或默认降级校验。
- 新增最小非 Autobiz 项目能力声明样例与作者指南，解释如何与已有 board_config/Skills/Hooks 配合，字段和示例须被同一 parser 验证。
- 为打包示例增加静态合同检查与隔离导出验证：当前已核对 upstream 504e327d / 1.0.87 的身份和原文件 SHA 保留；拒绝未审阅上游漂移，不改旧 native 8db1ec9 固定源。
- 文档明确哪些能力是现有运行链提供，哪些是声明/界面提供，哪些仍不支持。新能力包帮助在面板内直接阅读。

## 方案评审补充约束

- 2026-10-11 运行时 medium APPROVE；产品 medium 指出防竞争必须覆盖普通会话和独立人审的 P2，本稿补入 B 后产品再次 APPROVE，再开始实现。
- 声明绑定已解析插件根，不按名称二次搜索。空/坏/过大/链接/读取变化为局部诊断；取消仍按原请求退出。声明导致接近 2 MiB IPC 总预算时降级或省略增强数据，不能让原合法详情失败。
- 打包在创建输出前验证固定 upstream commit/version。声明不改变 Hooks，原文件摘要必须逐项一致。

### D：集中验收与复核

- 每条新增行为有回归：schema/限额/异常隔离/旧插件无声明/绑定来源、状态投影、当前与选中阶段、最新 nextAction、并发/人审阻止新会话、使用帮助、实际回调。
- 原 Autobiz hook/validator 字节和版本保持验证；新增包不执行外部业务，原工具/Skill Hook 回归覆盖执行链。
- 完成 A-C 后集中运行相关测试、Node/Web typecheck、范围 lint、生产 build、浏览器组件交互与截图；再完整 npm test 链，失败保留原日志，不用扩大 timeout 或弱化断言伪造通过。
- 两名 medium 复核实际实现和体验；P2 及以上问题修复后复验，直到本次交付范围内无未解决 P2+。如验收受环境限制必须准确记录，未验收不能标完成。
