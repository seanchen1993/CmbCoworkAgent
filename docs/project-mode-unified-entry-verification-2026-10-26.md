# 项目模式统一入口修复与验收记录

适用分支：`codex/mods-v2`。应用版本固定为 `2.0.0`。本轮只修改该工作树；上线分支的远端提交仍为已合入的 `f3aa8ea8`。

## 问题与修复

原普通项目目录要求插件存在 `board_core/board_config.json`，并按旧项目协议分类。新版 Host 插件即使已经安装、启用且能解析阶段，也被普通“新建项目”过滤。刷新和重新导入不能改变这一判断。

本轮将有效原生模板纳入普通目录，以 `runtimeMode` 区分运行机制。原生模板的旧看板兼容性仍为 false，不会调用旧项目脚本。普通“新建项目”使用同一个插件选择入口，按所选插件展示对应配置，分别调用既有原生或兼容服务。原生项目并入项目列表，创建和重新打开使用原阶段界面，取消独立的“本地项目任务”板块。创造者“开始使用”也定位到统一创建入口。

普通创建增加模板身份核对：选择时固定安装 ID、名称、版本和源码摘要。插件在填写期间更新、同版本内容变化、停用或卸载后，旧选择不能悄然绑定新内容。普通入口复用原快照身份检查，不冒用创造者会话授权；创造者原 `expectedPlugin` 和 `startUseScope` 约束保留。

首次项目引导及三章内置说明同步为“选择插件、配置、创建、核对阶段后执行”，兼容插件继续保留原必要配置与权限。

## 完整执行发现的运行时竞态

初次完整执行时，第一阶段成功；第二阶段模型、写入、编辑及 PostSkillUse 已返回，结束确认却在 capture 阶段报 `MODS_RUNTIME_SESSION_BUSY`，原操作保留为 `unknown / project_runtime_retirement_unconfirmed`。退出应用后的 `PROJECT_HOST_OPERATION_SCOPE_CHANGED` 是后续日志，不能倒因为先行原因。原失败证据保留在 `r3-platform/`。

确定性回归证明，已进入的界面读取尚在真实 finally 收尾时，同步空闲检查会拒绝退休。本轮修正为：捕获精确只读界面请求，以原准入门阻挡新请求，等待这些请求真正结束；重新核验生命周期、源码、授权、配置、实例和全部资源后，才关闭界面队列、撤销原所有者并执行原物理 drain。实际 IPC 桥一并透传该顺序。

真实动作、后台资源、未完成初始化、源码变化、撤权或实例替换仍拒绝结束。不以超时判成功，不清空未知状态，不自动重跑。旧日志没有细分忙碌项，因此不追溯声称已确定旧失败的具体占用；新增固定布尔和计数诊断供后续定位。修复后的同一实际两阶段链路已通过，历史失败未被覆盖。
