# Mods v2：后台轮次与用量聚合

开发分支 `codex/mods-v2`，代码起点 `5e4def91`，宿主修订
`desktop-background-turns-v21`。冻结对照版本仍为 Claude Code 2.1.273。

## 实际效果

定时任务、心跳及旧远程执行入口现在发送真实 `turn.start/turn.complete`。
它们使用实际用户消息 ID、物理运行 ID、模型响应及取消控制器，与桌面主轮次共用
观察器。插件可用已有 `/claw-turn` 示例观察这些会话，也可调用 `$.turn.abort`
停止正在执行的后台轮次。

完成事件在任务释放线程租约后到达。远程执行入口不替外层传输释放租约；其本地
停止信号与传输取消信号组合，插件停止不伪造外层控制器状态。模型切换重试与完成
修订保留同一逻辑轮次；前者不重复开始，后者累计实际模型用量。

心跳使用独立用户消息 ID。静默 `HEARTBEAT_OK` 可以按原流程清理本轮检查点，
插件的完成事实仍来自实际响应。切换心跳项目时先关闭旧 Mods 会话，撤销旧能力，
再执行异步检查点和目录清理；清理失败不会恢复旧执行权限。

## 复核的底层边界

- 新增 `modTurnRunId` 专用于观察，后台任务不会因此获得前台消息队列或沙箱 ACL
  所有权。统一工厂以实际运行租约覆盖调用方提供的观察 ID。
- 桌面与后台共用流归属过滤，排除压缩器和子代理内部消息。完整用量只读取真实
  `afterModel` 响应；中断时可以保留真实主流片段。
- 还原代码 `fzn/gUe/Ryt` 使用同响应 ID 的最后一次有效用量，跳过缺失用量；
  本次修正了 v20 的首值计数及任一缺失导致全部隐藏的问题。没有真实模型名、
  无效统计和整数溢出不生成虚构用量，仍保留回答。
- 实际图测试发现 LangChain 的异常包装会隐藏内层 HTTP 状态。重试判断现在有界
  读取 cause 链；取消、400、401、403 优先禁止重试。真实检查点续跑测试证明
  模型重试不重复 `turn.start`，并只统计成功响应的实际用量。
- 完成清理错误不能阻止传输释放租约；同源租约移交后旧回调不能停止替代运行。
