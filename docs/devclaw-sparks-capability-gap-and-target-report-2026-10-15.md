# DevClaw 全范围 DIY 能力补齐方案与缺口报告

日期：2026 年 10 月 15 日  
适用范围：`codex/mods-v2` 当前工作代码。本文说明现有能力与后续建设目标，不作为 UAT 或其他发行版本的能力清单。

最新实施顺序：先实施[通用灵件平台底座](devclaw-sparks-platform-foundation-plan-2026-10-15.md)。G1–G3 已形成实际运行闭环；用户随后要求暂停性能验收，优先准备 10 月 16 日、面向技术与产品负责人的 15 分钟演示，并补齐影响演示使用的能力。当前复用已有项目组合链，不重写 AutoBiz 原包。下文保留全范围最终目标，不把示例通过等同于所有业务模块已经接入。

## 核心结论

DevClaw 已具备灵件的创作、试用、安装、授权、组合及运行框架。当前开放重点是聊天执行链、指定聊天界面位置和已声明的项目能力；各原生业务模块尚未完成统一接入，当前不能表述为“基本所有功能都可以自行 DIY”。

最终目标是：**把 DevClaw 做成全范围可定制的产品。所有面向用户的业务模块都应能通过灵件扩展、组合，并在用户选择后替换相应界面或业务行为；用户无需修改 DevClaw 源码，也无需为每个需求等待平台单独开发。** 普通用户通过描述需求制作，开发者通过统一接口开发，还可以增加新的业务模块。

**当前没有接口的地方，就是必须补齐的开发任务。** 能力清单、可行性检查和缺口提示用于指导实现，不能替代接口交付，也不能把缺接口的模块从最终目标中删除。近期先用独立小示例验证平台机制；多工作树进度看板等业务用例在后续模块接入时验证，不作为底座建设的前置。

平台保留的最小内核是身份与权限裁决、隔离、凭据保护、可信批准和执行证据等不可绕过的机制。业务页面、工作流程、配置体验、调度策略和业务规则仍应开放定制；“内核保障执行”不等于“这个业务模块不能 DIY”。原项目强制验证链继续有效，有权限的作者可以增加规则或经原批准流程更新规则。

## 当前已经具备的能力

| 能力 | 当前可实现的内容 | 使用条件 |
| --- | --- | --- |
| 灵件创作与交付 | 自然语言生成草稿、检查、请求试用、明确批准、停止、保存及正式复用 | 生成成功和批准成功均不等于功能已经生效，仍需核对实际状态与效果 |
| 界面扩展 | 聊天挂点、内嵌面板，以及页面、导航、侧栏、操作栏、设置五种通用入口；表格、树、图表、列表、日志和表单 | 已通过独立工作台示例验证；不表示现有所有原生业务页已可替换，不直接注入任意 DOM |
| 跨作者业务能力 | 作者注册版本化能力，其他插件发现、读取、订阅并调用公开动作；状态来自真实任务 | 提供方与调用方分别校验来源、版本、范围及权限；目录发现不启动任务 |
| 业务行为替换 | 对已接通的输入建议和通知呈现预览冲突、选择实现、确认应用，停用后恢复原生实现 | 当前处理点是 `prompt.suggest`、`ui.toast`，其他业务处理点仍需逐项接入 |
| 快捷指令与执行事件 | 注册指令，处理已接入的聊天、工具、模型和部分生命周期事件 | 事件需要有实际提供器，不能仅凭事件名称判断支持 |
| 外部与执行能力 | 正式授权后的文件、进程、网络、模型及已配置 MCP 工具调用 | 同时满足当前接口支持、作用域及权限要求 |
| 助手与流程组合 | 组合已经公开的能力、技能、工具和保存流程，按聊天应用 | 项目专用能力按声明与项目归属筛选，不混入不适用的普通聊天 |
| 项目能力接入 | 已接入的公开节点和完整项目流程可组合，执行继续经过原检查点、Hooks 和人工确认 | 以兼容检查通过的来源和版本为准，不自动接纳任意开发版本 |
| 基础运行保障 | 私有状态存储、受控热更新、版本授权、部分定时任务和恢复机制 | 停用、撤权、取消、重启及未知结果仍有相应边界 |

制作现已区分本地预览、隔离验证和明确批准后的原生能力试用。已实现的 SDK 桥接可进入真实试用，文件写入和命令仍经过原批准链；试用权限只对指定来源、版本和会话临时有效，不形成正式授权。固定实包作者闭环已验证读写、增权重审、失败保旧、恢复、停止、正式安装及重启不重放。模型协议可使用受控提供方验证，但这不构成商业模型质量结论。**正式安装不会自动补齐平台尚未开放的业务接口。**

完整回归和持续性能验收尚未完成；用户已要求暂停。当前可汇报“机制已有真实闭环”，不能汇报“全范围 DIY 全部完成”或“性能问题全部解决”。

## 当前缺口及其影响

下表中的“待补接口”表示缺少稳定、受控的灵件接入方式。部分需求可以通过专用脚本或现有公开动作完成，但尚不能作为普通作者可直接复用的统一平台能力。

| 领域 | 当前缺口 | 用户受到的影响 | 完整目标 |
| --- | --- | --- | --- |
| Workflow 与多工作树 | 原生状态和事件已有，灵件缺少专用读取、订阅及明确关联接口 | 无法稳定制作展示每个工作树真实任务进度的通用看板 | 按获准的会话和运行提供状态、变化通知，以及工作树与任务的明确关联 |
| 插件自管运行状态 | 通用版本化状态、订阅及动作协议已经实现；AutoBiz 的批次、租约和验证尚未逐项接入 | 新插件可按协议公开状态；不能直接把任意原插件内部文件当作已接通的通用状态 | 逐个插件接入真实状态、产物和动作，插件保留业务状态权威 |
| 项目看板与阶段 | 已有公开能力组合，观察与订阅接口尚未统一 | 能执行流程，但难以自由制作跨插件阶段看板和提醒 | 公开阶段状态、检查结果、审批等待及产物引用；推进继续经过原验证链 |
| 原生业务界面 | 已能新增通用页面、导航、侧栏、操作栏和设置；现有项目页、Git 面板及业务设置尚未全部逐项接入替换协议 | 作者能增加独立工作台；不能宣称所有既有页面与行为已可替换 | 全部业务区域按明确契约支持扩展及用户选择的替换 |
| Git 与终端资源 | 已有文件和进程能力，平台管理资源的生命周期接口不完整 | 可以调用命令，但难以可靠联动平台的工作树、合并记录和终端会话 | 公开资源状态与归属，逐步接入有检查、有取消及结果记录的管理动作 |
| 模型、技能与连接管理 | 已有调用和受控 MCP 连接能力；原生来源管理、安装、配置、测试、升级入口尚未按通用业务契约完整接入 | 不能由调用 SDK 推断已经能够定制整个管理模块 | 按业务操作补齐目录、安装、配置、连接、测试、更新和停用，敏感输入通过可信表单完成 |
| 任务队列与全局通知 | 已有文字任务提交和部分事件，缺完整的任务观察与管理协议；部分事件只有结构定义 | 无法通用展示排队原因、所有适用任务状态或模块变化 | 在明确范围内提供队列状态、等待原因、变化通知和受控取消 |
| 持续后台与跨重启恢复 | 已有持久数据和运行期间定时器，缺通用的持久任务协议 | 保存了数据，不代表退出后继续执行或重启后自动恢复 | 保存任务身份、执行证据和恢复条件，重启后重新核对授权与实际状态 |
| 社区接口兼容 | 部分事件、工具和界面契约仍缺适配 | 安装成功或少量示例通过，不能保证任意社区包可用 | 按明确版本公布兼容矩阵，提供实际验证和可执行的迁移建议 |

“应用内部已经有 IPC 接口”“SDK 里存在名称”“可以执行一段脚本”与“已经向灵件提供稳定业务接口”应分别认定，不能互相替代。

## 全范围 DIY 的完整覆盖清单

“全范围”以当前产品的全部用户业务模块为分母，而不是只统计已有灵件接口。每个模块都要按实际业务补齐五项能力：**读取数据、接收变化、执行动作、定制界面、组合或替换行为。** 不适用的单项要说明原因，不能整模块标为“宿主负责”后退出验收。后续新增原生模块也必须同步接入。

下面是依据当前 App、设置入口、preload 和主进程业务模块形成的初始清单。实施时需细化到用户操作并核对遗漏；本表不是已经完成的覆盖率报告。

| 业务模块 | 最终必须支持的 DIY | 验收示例 |
| --- | --- | --- |
| 聊天、会话与输入输出 | 自定义输入辅助、附件处理、上下文组装、消息与工具展示、会话组织及跨会话协作 | 制作专用代码助手，同时更换输入区和回答卡片；原聊天记录保持可核对 |
| Agent、模型与执行行为 | 定制任务分派、模型路由、上下文策略、工具选择、结果后处理和协作方式 | 一个助手负责实现，另一个负责评审；按任务选择模型，仍经过原工具权限检查 |
| Workflow、多任务与工作树 | 编排串并行任务、选择隔离方式、观察每个任务、取消、恢复与收集成果 | 自建多工作树研发流程和进度页，编码、检查、修复到合并可连续操作 |
| 项目、阶段与业务看板 | 定义节点、条件、阶段界面、验证规则，组合独立能力与完整项目流程 | AutoBiz 和数据开发插件在同一项目协作，原 Hooks 和批准链真实执行 |
| 文件、编辑与终端 | 定制目录视图、预览、编辑操作、终端工具及其生命周期 | 建立项目专用文件工作台，执行命令并查看进程、退出结果和清理状态 |
| Git、差异审阅与合并 | 定制审阅布局、批次基线、检查和合并策略，管理获准资源 | 制作按需求分组的变更审阅页，核对测试证据后发起原合并动作 |
| 技能、工具、MCP 与插件 | 搜索、安装、配置、连接、调用、派生、组合、升级与卸载；增加新业务来源 | 描述需求生成插件，复用已有节点并接入新工具，无需改平台源码 |
| 记忆、知识、产物与交付 | 定制知识组织、检索和沉淀规则、产物检查、交付适配器 | 数据插件与文档插件共享经授权的成果，发送前核对产物与接收目标 |
| 队列、定时、后台与通知 | 定制排队策略、计划任务、目标任务与协作调度、持续任务、提醒方式、重启后核对与恢复 | 制作每日检查助手和项目待办中心，重启后可核对任务，不重复提交 |
| 浏览器、IDE、LSP 与外部渠道 | 定制已有连接的操作、结果卡片和协作入口，注册新的适配器 | 浏览器检查、代码诊断与项目步骤串联，使用当前工程已实现的渠道验证 |
| 运行过程、Trace、度量与看板 | 定制进度、失败、耗时、成本、返工和审批等待的展示与规则 | 自建项目运行驾驶舱，点击失败项定位原任务和证据 |
| 设置、导航、页面与外观 | 新增页面、标签、侧栏和设置表单；替换业务视图，定制主题与布局 | 安装后出现自建工作台，可设为项目默认界面，停用后回到原生界面 |
| 创作、试用、评测与发布 | 自然语言生成和修改、差异预览、分级试用、调试、升级、回退及导入迁移 | 非开发者从描述到实际效果走通闭环，作者可发布带设置和示例的能力包 |
| 团队、机器人与个性化 | 定制协作角色、专家团队、机器人交互、个人展示和宠物等辅助体验 | 新建业务专家团队和个性化入口，角色权限、数据来源和应用作用域可核对 |
| 内置能力与应用级入口 | 项目规范、变更审阅、组织策略、执行度量、扩展开发助手、项目提示，以及导览、通知、机器人等业务入口均能通过公开契约扩展 | 内置能力和第三方灵件使用相同业务接口；组织策略可扩展，最终执行检查不能绕过 |

原生模块、用户自建模块和插件提供的模块应使用同一套注册、权限、设置、版本、组合与诊断机制。内置功能可以保留原实现，但不能长期依赖仅内置代码能调用的业务特权接口。

## 最小内核与业务定制的关系

以下机制必须真实有效，但不豁免任何业务模块的接入：

| 内核机制 | 业务层仍可 DIY 的部分 |
| --- | --- |
| 身份、目标作用域和真实用户同意 | 申请流程、辅助说明、业务审批页及授权后的操作入口 |
| 凭据保管和敏感输入隔离 | 新连接的配置表单、连接测试及凭据引用，灵件不直接获取明文秘密 |
| 执行隔离、资源限额、所有权与租约 | 调度方式、并行策略、执行实现和资源展示；不能越权使用其他任务资源 |
| 事务提交、版本校验、幂等与取消清理 | 提交前后的业务规则、重试和恢复体验；不能伪造提交或跳过清理核对 |
| 执行证据与审计真实性 | 记录的展示、统计和提醒；不能把未执行或失败的操作改成成功 |
| 内核完整性和安全恢复通道 | 常规设置、更新提示和恢复引导的业务界面；始终保留停用扩展及恢复原版的可信入口 |

“保留 AutoBiz 原验证链”表示按当前选定版本和规则真实执行，不是禁止插件作者继续优化其规则。作者可以按版本、权限和原批准机制更新 Hooks 与业务验证，平台不能旁路伪造旧规则通过。

## 完整目标及平台分工

### 面向用户的目标

用户可以描述“把当前流程的多个工作树做成进度看板”“组合两个插件的步骤”“换成适合数据开发的项目工作台”等需求。助手应能生成相应界面、业务行为和配置，并通过试用验证后应用。用户可以继续描述修改、组合其他作品、发布或恢复原版。

制作前检查当前版本能否实现。暂缺接口时明确给出平台待办；开发目标是消除这些业务缺口，而非仅改善“不支持”的提示。只有绕过最小内核等要求不属于业务 DIY 目标。每个业务模块都登记数据、事件、动作、界面与行为覆盖度，不能靠缩小模块清单得到“全覆盖”。

### 通用业务接口

每项公开能力应按需提供以下契约：

| 契约 | 应当解决的问题 |
| --- | --- |
| 能力目录 | 完整业务模块及其操作、当前实现进度、普通聊天与项目适用性、试用和正式授权条件 |
| 状态查询 | 返回当前真实状态、来源、版本、更新时间和结果未知的原因 |
| 变化通知 | 状态变化时按范围通知，支持退出订阅、断线后重新读取及迟到消息丢弃 |
| 受控动作 | 明确输入、权限、目标版本、取消和重复请求语义，以及执行结果与后续处理 |
| 界面位置 | 明确可以添加或替换的区域，提供原生回退、键盘操作、窄屏和错误边界 |
| 行为扩展与替换 | 声明前后处理、策略、执行实现和替代对象；明确优先级、组合顺序、原实现委托和冲突处理 |
| 新业务接入 | 作者声明新的数据、事件、动作、页面和设置，平台自动接入组合、授权与运行过程 |
| 版本与诊断 | 接口升级可判断兼容性，失败能说明原因、影响和下一步 |

这些接口应复用既有服务和执行器。原执行系统产生真实状态；灵件可以定制策略和实现，但执行仍经过统一授权、资源管理与结果记录。观察现有系统时不另建竞争状态；自建新业务时可以拥有自己的状态，并通过同一协议公开。

不能简单把任意原生 IPC 转发给插件来宣称全覆盖。每项业务操作都需要明确类型、来源、权限、作用域、取消、结果和版本；也不能只加通用读取接口而遗漏动作、行为替换与界面。

### 用户可以控制与宿主继续负责的内容

| 用户可以定制 | 宿主或原插件继续负责 |
| --- | --- |
| 展示布局、筛选、排序、摘要和提醒 | 原始执行记录、结果归属与数据访问范围 |
| 公开步骤和能力的组合、条件与输入输出 | 实际执行权限、资源隔离、取消和物理清理 |
| 全部业务区域的扩展页面、替代界面和操作入口 | 可信批准身份、凭据隔离和最终授权决定 |
| 调度、模型路由、工具实现、业务规则和验证器；有权限时通过原批准机制更新规则 | 规则更新权限、强制检查的执行、证据有效性和原人工确认 |
| 已批准范围内的升级与复用 | 新权限确认、版本冲突处理及原生回退 |

全页面、自建导航、业务设置与业务行为替换均为必须交付的能力。当前尚未实现的完整页面接点需要补齐。界面应支持表格、树、图表、实时日志、编辑和交互表单等常用业务组件，扩展通过注册机制和数据契约完成，不要求作者修改 Electron 应用源码。

用户可以设计审批页的辅助说明、申请流程和策略诊断，但不能伪造批准身份、读取明文凭据或把失败改成成功。权限检查不取消整个审批或配置模块的可定制性。停用自定义实现后，原生入口和已有数据应能继续使用。

## 多工作树进度看板的目标实例

### 数据来源

DevClaw 原生 Workflow 提供运行阶段、子任务开始与结束等执行事实。原始 AutoBiz 的 Code 阶段调用原生 Workflow 调度任务，但其 Batch 工作树由插件脚本创建和维护；批次、租约、验证和合并状态以插件 scheduler 为准。

因此，这个看板需要两类提供器：平台提供 Workflow 执行投影，AutoBiz 提供自身业务状态投影。两者通过明确的运行、批次、任务和工作树标识关联，不能从分支名称猜测对应关系。

### 应看到的效果

下表是目标展示示例，不是当前任务的执行结果：

| 工作树 | 负责内容 | 当前状态 | 用户可操作入口 |
| --- | --- | --- | --- |
| A | 登录功能 | 正在编码 | 查看当前任务和公开输出 |
| B | 报表功能 | 检查已通过 待合并 | 查看检查证据和代码差异 |
| C | 权限功能 | 测试失败 | 查看失败原因与修复建议 |

卡片显示真实阶段、耗时、最近更新和可追溯结果。测试通过以实际检查记录为依据，不能把模型声称完成当作通过。只有计划总量明确时才展示“完成 2 项 共 4 项”；总量未知时显示阶段和状态。

查看、停止、修复和合并应分别对应明确动作。可以先实现只读状态以验证数据链，但该用例只有覆盖实际操作和结果核对后才算完成；不能交付只读看板就宣称补齐。对 AutoBiz 的改造保留原 Hooks、阶段检查、工作树归属和合并验证，不通过旁路写状态。

### 对其他插件的复用

其他开发者按同一协议声明状态、产物和公开动作，即可复用看板组件、订阅、权限和诊断。数据开发插件可以公开数据任务与质量检查，文档插件可以公开产物和审核状态；平台共用接入机制，插件保留各自业务含义。

## 统一制作与使用体验

用户路径应收敛为：**描述需求 → 判断可行性 → 预览 → 确认并试用 → 核对效果 → 保存复用。**

1. 描述需求后先给出能力结论。可直接制作、需要授权验证、需要平台补接口和涉及绕过最小内核的要求应明确区分。平台缺口进入实施清单，不列为永久不支持。
2. 预览集中说明“会出现什么效果、影响哪段聊天或哪个项目、需要哪些设置和权限”。完整权限和技术详情按需展开。
3. 主卡只显示当前状态和下一步。失败、待确认、排队和已生效不能混写；状态以平台最新查询为准。
4. 同一处完成试用控制和效果核对。保存后可从原入口继续修改、查看版本、停用或卸载。
5. 配置对象可直接选择，未保存草稿得到保护。安装库、所选聊天实际启用的能力及项目共享参数分别说明。
6. 检测命令和界面位置冲突，给出可预览的处理方案；不得擅自停用其他灵件来掩盖问题。
7. 停用、升级、删除或失联时，说明已完成操作、尚未确认的结果和可执行的恢复步骤。恢复不自动重放结果未知的操作。

## 补齐实施顺序与交付要求

本节是全范围业务接入的目标拆分，近期执行优先级已由[平台底座优先方案](devclaw-sparks-platform-foundation-plan-2026-10-15.md)调整：先完成通用底座 G1–G4，再推进以下业务接入。项目与插件改造暂缓，完整业务范围保留。正式实施账本需逐项列出模块与操作，不以“已加一个接口”或“已能显示看板”代替闭环。

| 阶段 | 重点交付 | 完成条件 |
| --- | --- | --- |
| 基础前置：通用平台底座 | 先按平台底座方案完成 G1–G4，用独立任务工作台验证能力注册、状态、事件、动作、页面、行为和生命周期 | 两个独立示例包经实际公开接口互用；不依赖项目或 AutoBiz 改造。底座通过仅代表接入机制可用 |
| 第二阶段：研发与项目能力补齐 | Workflow、工作树、Git、文件、终端、项目节点、原插件状态和产物；AutoBiz 与其他场景共用接入 | 多工作树完整操作与跨插件组合通过；原验证链有效；新业务无需修改平台核心 |
| 第三阶段：聊天与资源管理补齐 | 会话、Agent、上下文、模型路由、工具实现、技能、插件、MCP 管理、浏览器及 IDE 连接 | 能定制界面和业务行为，并完成安装、配置、执行、修改及停用闭环；仅查询目录不算完成管理接入 |
| 第四阶段：持续业务与应用模块补齐 | 队列、定时、后台、通知、记忆、知识、交付、运行度量、设置、导航及其余业务入口 | 新建后台与业务页面可使用统一协议；重启恢复有依据；完整清单不留未经说明的业务空洞 |
| 第五阶段：普通用户制作与社区兼容收口 | 分级试用、自然语言修改、组合与替换预览、作者脚手架、版本迁移、Claude 接口适配及示例 | 全业务操作逐项通过；普通用户无需改源码；内置能力无专属业务捷径；文档与相同构建验收一致 |

互不依赖的接口和界面可成组并行开发，在集成节点集中做完整回归。涉及授权、并发状态、持久化、取消和恢复的改动应先完成针对性回归，再并入集成版本。只有实施和验收都完成的项目才能标为已支持。

每个工作包需交付实际实现、端到端用例、性能证据和最新说明。既有可用能力直接复用，补齐缺失部分，不为了统一形式重写全部执行器。UAT 存量语义和 AutoBiz 原验证链是持续回归对象；灵件开启但未应用自定义时，应继续使用原生体验。

## 整体验收标准

以下是完整目标的验收要求，不表示当前已经全部通过。

| 场景 | 必须验证的结果 |
| --- | --- |
| 全业务覆盖 | 全部原生业务模块和用户操作完成清点；逐项验证数据、变化、动作、界面及行为组合或替换。未接入项仍计为缺口；新增模块同步纳入 |
| 无需改平台源码的新业务 | 作者注册此前不存在的数据、动作、事件、设置和页面，可被另一灵件发现和组合，能调试、发布、升级及卸载 |
| 实际界面和行为替换 | 替换项目工作台、聊天业务展示及一项执行策略，能调用原实现、处理冲突并恢复原版；不绕过权限或原记录 |
| 自然语言制作实时天气 | 制作前说明试用限制和正式授权路径；本地演示与实时数据清楚区分 |
| 自定义原生业务页面 | 实际生成、应用、交互和停用一套页面与导航；未实施挂点的模块不能靠“不支持”提示通过最终验收 |
| 授权后的真实试用 | 文件、网络、模型等按申请范围验证，效果与结果可核对；费用与外部副作用提前明确，停止后清理真实资源 |
| 完整制作闭环 | 创建、预览、批准、试用、停止、正式复用、再次编辑和卸载均可实际完成 |
| 多灵件与项目组合 | 命令冲突可理解；公开节点及完整流程可组合，输入输出与审批保持关联 |
| 多工作树并发 | 覆盖不少于 8 个工作树的排队、执行、验证、失败和合并状态；同时包含平台托管和插件托管的来源 |
| 多会话与多项目 | A 中配置 B 不改变 A；切换、删除重建、撤权和迟到通知不会串数据或执行到其他目标 |
| 取消与跨重启恢复 | 等待真实清理结果，已确认成果可核对；未知结果不伪造成功或自动重放 |
| 升级与兼容 | 新权限明确确认，不兼容版本得到诊断；失败时保留可用版本或提供明确回退入口 |
| 原项目验证链 | AutoBiz 原 Hooks、阶段检查、产物校验、人工批准和合并规则均真实执行；其他插件按相同协议验证 |
| 性能与界面连续性 | 在约定测试环境下完成至少 20 轮流式对话及多次会话、模式切换；监测整表消失、重复消息、订阅泄漏和响应时延 |
| 长时间观察 | 活动任务连续观察至少 60 分钟，确认订阅数和内存不随重绘持续累积；隐藏页面释放非必要观察 |
| 使用体验与文档 | 375 像素窄屏、键盘、空状态和失败修复可操作；说明按需展示，示例图片和步骤对应实际版本 |

性能门槛需在固定机器、数据量和模型条件下确定并记录。20 轮样本或个别示例通过不替代 60 分钟观察、其他插件兼容和完整目标清单验收。

最终交付应包含完整模块及操作清单、实际开放的接口与版本、可直接运行的示例、普通用户指南、作者接入说明，以及与相同构建对应的验收记录。当前状态按“已支持、授权后可用、待补齐”呈现；最小内核约束另列，不用“宿主负责”豁免整个业务模块。

只有完整业务清单验收通过，才能宣称全范围 DIY；在此之前应明确仍在补齐。有限的验收清单用于证明当前产品版本的业务覆盖，不声称验证了所有未知第三方代码或未来任意组合。
