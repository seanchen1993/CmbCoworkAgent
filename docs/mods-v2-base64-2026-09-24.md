# Function guest Base64 全局函数

官方Claude Code v2.1.280声明中的 `atob(data)` / `btoa(data)` 已进入本工程hooks和独立Client VM，宿主修订v64；新批准摘要不会复用旧版本授权。这两个函数只在guest内计算，不增加Node、Buffer、网络、文件或宿主权限。

```ts
btoa("foo") // "Zm9v"
atob("Zg") // "f"，允许省略padding
atob(" Zg==\n") // "f"，只忽略ASCII空白
```

`btoa` 输入是每字符0–255的字节字符串，不是Unicode文本编码器；直接传中文会失败。`atob` 输出也是字节字符串。格式遵循[HTML Base64接口](https://html.spec.whatwg.org/multipage/webappapis.html#atob)与[Infra forgiving-base64](https://infra.spec.whatwg.org/#forgiving-base64-decode)；拒绝URL-safe的 `-` / `_`、非法padding和非ASCII空白。

兼容状态为partial：全局是只读绑定；输入上限512 Ki UTF-16 code units（包含被忽略的空白），超限为RangeError/MODS_BASE64_LIMIT；非法编码为名叫InvalidCharacterError的Error，尚无DOMException类。既有16 MiB内存、50ms计算片段和JSON传输上限继续有效，输入在上限内也不豁免预算。缺少参数、Symbol及作为构造器调用均拒绝，其他参数按字符串转换。

这不构成 `fs.read({as:"bytes"})`、TextEncoder/Decoder或完整浏览器全局兼容声明。其他9个尚未开放的全局仍保持原矩阵状态；不改变发布过滤或authority/lease/generation检查。测试先验证真实QuickJS与旧Electron均缺少函数，再核对独立native向量、0–255字节、padding/错误/原型修改、真实utility与桌面Client。当前完整验收数字见[验证记录](../output/mods-v2-validation/2026-09-24-base64.md)。
