## 用户能做什么

| 能力 | 入口与效果 | 边界 |
| --- | --- | --- |
| 项目规范 | 当前助手 → 运行过程，查看主会话和子任务的规范来源、范围及请求时检查 | 是实际装载与请求边界记录，不证明模型服从；文字冲突仍需人工核对 |
| 变更审阅 | 运行过程，按当前执行、阶段或整个本地项目查看修改及检查结果 | 缺少原始基线时明确不可用；旧插件仅显示有证据支持的范围 |
| 组织策略 | 运行过程，解释原审批、工具限制、Hook 与策略拒绝及下一步 | 执行权仍在原宿主；关闭界面不能关闭限制 |
| 执行度量 | 查看耗时、重做、审批等待与可关联的模型调用 | 未知用量、费用、审批时间不当作零，不按不可靠的时间范围拼接旧记录 |
| 扩展开发助手 | 制作灵件，在聊天里描述项目，生成、检查、修正、隔离试用，再打包正式安装 | 创建不开始；实际执行经过原 Skill、工具授权和审批；会话草稿需及时打包保存 |
| 项目提示 | 本地规则提示；明确开启后才能请求模型建议，可忽略、停止、关闭 | 模型建议默认关闭、有并发和预算限制，不读取业务文件正文或获得执行工具 |

项目列表里的“本地项目任务”提供选模板、填目标、按阶段完成的入口，无需企业项目编码。复杂旧项目仍由原插件维护阶段和验证状态，不把轻量项目状态强加给 AutoBiz。

制作时可以复用已安装插件的公开动作，明确绑定版本及输入输出，不复制内部实现。隔离试用采用完整固定快照：试用期间保存新版会排队，当前项目继续旧版，结束后由用户创建下一次试用。正式安装与普通聊天不受草稿更新影响。

离线使用说明已由项目入口链接到应用内文档，含 [项目插件教程](sparks/project-plugin-cookbook.md) 的制作、试用、公开动作复用、失败修复和版本管理例子。导览覆盖七章 28 步及两种失败修复案例，支持跳过和重新打开。
