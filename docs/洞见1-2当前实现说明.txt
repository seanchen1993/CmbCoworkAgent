# 洞见 1/2 当前实现说明

实现日期：2026-07-01  
实现分支：`codex/insight-1-2-mvp`  
实现范围：工具结果字段投影/裁剪 MVP、工具失败熔断 MVP。

## 1. 总体说明

本次实现按“先做最小闭环，再扩产品化能力”的原则落地，目标不是一步到位完成 sidecar、Harness 聚合、UI 面板等完整闭环，而是先让两个核心能力进入真实执行链路：

1. 大工具结果可以按字段投影，并有字符/数组上限兜底。
2. 同一 turn 内重复出现的同类工具失败可以被识别、提示，并在达到阈值后停止本轮。

当前实现仍保持默认兼容：不传投影参数时，`invoke_deferred_tool` 的成功返回仍是旧结构：

```json
{
  "ok": true,
  "data": "..."
}
```

只有显式传入 `required_fields`、`max_result_chars` 或 `max_array_items` 时，才返回 `_projection` 元数据。

## 2. 工具结果投影

### 2.1 新增核心模块

新增文件：

```text
src/main/mcp/result-projection.ts
src/main/mcp/result-projection.test.ts
```

核心能力：

1. `projectResultData(data, options)`
   - 支持字段路径白名单。
   - 支持数组条数上限。
   - 支持最终字符上限。
   - 输出投影元数据。

2. `deriveFieldPathsFromJsonSchema(schema)`
   - 从 MCP `output_schema` 推导可用字段路径。

3. `deriveFieldPathsFromValue(value)`
   - 从已脱敏的历史结果样例推导字段路径。

4. `hasProjectionOptions(options)`
   - 判断本次调用是否显式启用了投影或裁剪。

字段路径当前支持简单 JSONPath 子集：

```text
id
name
items[].id
items[].status
data.records[].customerId
data.records[].score
```

当前没有引入完整 JSONPath 引擎，避免第一版增加复杂语义、安全边界和性能风险。

### 2.2 MCP result-utils 接入

修改文件：

```text
src/main/mcp/result-utils.ts
```

改动：

1. 将原 `getUsefulMcpResultData(result)` 的内部逻辑拆出为 `extractUsefulMcpResultData(result)`。
2. 新增 `projectMcpResultData(result, options)`。
3. 保持 `getUsefulMcpResultData(result)` 的旧行为不变。

这样旧链路仍能继续使用完整“有用数据”，新链路可以显式选择投影。

### 2.3 invoke_deferred_tool 接入

修改文件：

```text
src/main/agent/tools/tool-search-tool.ts
```

`invoke_deferred_tool` 新增可选参数：

```ts
required_fields?: string[]
max_result_chars?: number
max_array_items?: number
```

示例调用：

```json
{
  "tool_id": "some_large_mcp_tool",
  "tool_args": {
    "query": "risk"
  },
  "required_fields": ["items[].id", "items[].name", "items[].status"],
  "max_result_chars": 4000,
  "max_array_items": 20
}
```

示例返回：

```json
{
  "ok": true,
  "data": {
    "items": [
      {
        "id": "1",
        "name": "A",
        "status": "done"
      }
    ]
  },
  "_projection": {
    "projected": true,
    "truncated": false,
    "originalBytes": 98322,
    "projectedBytes": 1024,
    "topLevelKeys": ["items", "total"]
  }
}
```

缺失字段不会导致工具失败。当前行为是：

1. 返回已经命中的字段。
2. 在 `_projection.missingFields` 中列出缺失字段。
3. 如果所有字段都没命中，回退到 preview，并返回可用 top-level keys。

### 2.4 inspect_tool 字段提示

`inspect_tool(caller="invoke_deferred_tool")` 现在会尝试返回：

```json
{
  "field_hints": ["items[].id", "items[].status"],
  "example_field_paths": ["items[].name", "items[].score"]
}
```

来源：

1. `field_hints` 来自 MCP `output_schema`。
2. `example_field_paths` 来自已保存的脱敏结果样例，只返回字段路径，不暴露完整历史结果。

这解决了模型不知道 `required_fields` 应该填什么的问题。

### 2.5 saved tool 行为

`invoke_deferred_tool` 同时支持 saved code_exec tool。当前约定：

1. saved tool 始终支持 `max_result_chars`。
2. saved tool 输出如果能解析为 JSON object/array，会 best-effort 应用 `required_fields`。
3. saved tool 输出如果是普通文本，不报错，但返回：

```json
{
  "_projection": {
    "requiredFieldsIgnored": true,
    "ignoredReason": "Saved tool output is plain text, so required_fields could not be applied."
  }
}
```

这样同一个入口不会静默忽略投影参数。

## 3. 工具失败熔断

### 3.1 新增核心模块

新增文件：

```text
src/main/agent/failure-fuse.ts
src/main/agent/failure-fuse.test.ts
```

核心类型：

```ts
export type FailureFuseAction = "observe" | "warn" | "strong_warn" | "halt"

export interface FailureFuseInput {
  threadId: string
  turnId: string
  toolName?: string
  toolCallId?: string
  toolArgs?: unknown
  signal: ToolFailureSignal
  mode: "off" | "warn" | "debug"
}
```

状态 key：

```text
threadId + turnId + fingerprint
```

这保证第一版只在同一 turn 内触发熔断，不会因为旧 turn 的失败累计导致误杀。

### 3.2 failure fingerprint

指纹包含：

1. `toolName`
2. `signal.kind`
3. `signal.errorType`
4. 标准化后的错误文本
5. 可选参数摘要

错误文本标准化包括：

1. 用户目录归一化。
2. UUID/hash/timestamp 替换为占位符。
3. 行号/列号替换为占位符。
4. 空白压缩。
5. 最多保留前 500 字符。

参数摘要当前会提取：

1. MCP/tool id 类字段。
2. `command` 的首个命令词。
3. 文件路径扩展名类别。

### 3.3 阈值策略

默认模式：

```text
warn
```

重复失败提醒默认开启。未设置环境变量时，同一轮同类同参数工具错误会在第 2 次给用户提醒、第 3 次及以后给用户强提醒；不会改写模型可见工具结果，也不会停止本轮。

若需要完全关闭用户提醒，可显式设置：

```text
CMB_AGENT_FAILURE_FUSE_WARN=0
```

重复失败提醒：

```text
CMB_AGENT_FAILURE_FUSE_WARN=1
```

| 次数 | 动作 |
|---:|---|
| 第 1 次 | observe |
| 第 2 次 | warn |
| 第 3 次及以后 | strong_warn |

该模式只发给用户 UI，不改写模型可见的工具结果，也不停止本轮。若希望 Agent 也收到防重试提示，需要单独开启：

```text
CMB_AGENT_FAILURE_FUSE_MODEL_FEEDBACK=1
```

该模式会把第 2 次 warning、第 3 次 strong warning 追加给模型，帮助 Agent 改变参数或换策略；不会给用户弹窗，也不会停止本轮。

调试模式：

```text
CMB_AGENT_FAIL_FAST=1
```

开启后任意工具失败首错即停。若“重复失败提醒”/“Agent 防重试提示”和“Debug 首错即停”同时开启，Debug 优先。

应用内入口：

```text
自定义 -> 沙盒环境 -> 工具失败提醒与调试 -> 重复失败提醒
自定义 -> 沙盒环境 -> 工具失败提醒与调试 -> Agent 防重试提示
自定义 -> 沙盒环境 -> 工具失败提醒与调试 -> Debug 首错即停
```

这些开关只影响当前 App 会话；也可以在启动前通过 `CMB_AGENT_FAILURE_FUSE_WARN=0/1`、`CMB_AGENT_FAILURE_FUSE_MODEL_FEEDBACK=1` 或 `CMB_AGENT_FAIL_FAST=1` 控制。

用户取消/Abort 不计入熔断。

同一工具在同一 turn 内后续成功时，只会重置同参数签名下的失败计数，避免无关参数的成功误清掉仍在重复的失败。

### 3.4 awaited 控制流接入

本次实现重点避免把 halt 放在 fire-and-forget 观察链路里。

已接入的 awaited 控制点：

1. MCP scoped invoke
   - 文件：`src/main/agent/runtime.ts`
   - MCP 返回 `result.isError` 后，同步调用 failure fuse。
   - 第 2 次 warning 会追加到 MCP result text/contentBlocks。
   - 第 3 次抛出 `FailureFuseHaltError`。

2. tool error middleware throw-path
   - 文件：`src/main/agent/runtime.ts`
   - 工具抛错被包装成 recoverable ToolMessage 前，先进入 failure fuse。
   - debug 模式可在这里首错即停。

3. 通用 tool hook middleware
   - 文件：`src/main/agent/tool-hooks.ts`
   - 工具返回后检测 `success:false`、`is_error:true`、`error`、非 0 exitCode、命令失败文本等。
   - warning 通过已有 hook feedback 通道追加给模型。

4. LocalSandbox PostToolUse
   - 文件：`src/main/agent/local-sandbox.ts`
   - 覆盖 `execute`、`read_file`、`grep`、`glob`、`ls`、文件写入/编辑等沙箱工具路径。
   - 保留原 `PostToolUseFailure` fire-and-forget 通知，但不依赖它做 halt。

5. IPC 顶层 catch
   - 文件：`src/main/ipc/agent.ts`
   - 捕获 `FailureFuseHaltError`。
   - pause active goal。
   - `tracer.finish("cancelled", reason)`。
   - 发送 renderer custom event：

```json
{
  "type": "failure_fuse_tripped",
  "action": "halt",
  "reason": "...",
  "toolName": "...",
  "fingerprint": "...",
  "count": 3,
  "threshold": 3,
  "lastError": "..."
}
```

6. Renderer 展示
   - 文件：`src/renderer/src/lib/thread-context.tsx`
   - `failure_fuse_tripped` 会进入现有 `hookInterruption` 中断面板，并展示 toast。
   - 面板包含工具名、重复次数、fingerprint、lastError，避免用户看到静默停止。
   - 文件：`src/renderer/src/components/customize/SandboxPanel.tsx`
   - 沙盒设置页新增“工具失败熔断调试”说明和“Debug 首错即停”开关。
   - 文件：`src/renderer/src/components/chat/ChatContainer.tsx`
   - 熔断面板标题展示为“工具失败熔断已停止本轮”，不再误显示为 Hook 停止。

## 6. 当前价值

本次 MVP 已经能带来实际收益：

1. 减少大 MCP 结果直接塞进模型上下文。
2. 让模型可以按字段拿数据，而不是靠完整 JSON 截断后猜。
3. 降低长链路任务中重复失败工具调用带来的 token 浪费。
4. 调试模式下能更快暴露首个真实错误。
5. 用户显式开启提醒后，模型能看到为什么不该继续同参数重试，而不是只收到一串工具失败。
