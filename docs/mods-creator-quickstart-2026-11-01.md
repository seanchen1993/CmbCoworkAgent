# 用对话创作、试用和再次使用 Mods

适用于包含 2026-11-01 本轮修复的 mods-v2 代码，应用版本仍为 2.0.0。原安装包不会通过重新导入插件自动更新界面。

## 创作一个功能

1. 打开带本地目录的聊天，切换“创造者模式”。
2. 描述场景、触发时机、要显示或输出什么，以及如何判断成功。例如：

   > 创建文件读取统计 Mod：在侧栏显示本聊天成功读取文件的次数，每次实际读取成功后更新；未读取时显示 0。用真实事件统计，提供清零按钮，不编造次数。

3. 助手准备候选后，打开“插件创作工作区”。先看当前版本和下一步，不需要理解源码。
4. 想修改时点“返回聊天修改”；要改某一阶段，可点“回对话修改这个阶段”。上下文会带回原对话，原来没发送的正文会保留。补充修改要求后由你发送。

阶段原文在高级展开里，适合需要直接编辑指令的作者。普通使用不需要在工作区再次填写一份“修改要求”。“让助手准备试用”是明确提交准备请求，不等于已经运行或授权。

## 试用和保存

| 当前制作的能力 | 怎样试用 | 怎样判断结果 |
| --- | --- | --- |
| 聊天功能、界面或事件规则 | 核对用途和权限，点击“确认并开始聊天试用”，回原聊天执行实际任务 | 看真实事件、界面数值或操作结果；启用成功不等于效果已验收 |
| 项目流程插件 | 在“试用”页填目标，点“准备试用环境”；补齐配置并确认所列权限，再点“开始执行” | 看阶段产物、实际检查和待确认事项；准备环境不等于运行通过 |

试用满意后，到“保存插件”页保存。若原机制允许未完成试用就保存，页面会如实标注，不会替你宣称通过。修改后的候选需要重新准备和验证；历史版本的试用或保存记录不会代表新版通过。

保存后按结果页的“开始使用”或返回聊天入口继续；若明确显示已应用到当前聊天，就无需再次激活：

- 聊天功能进入相应聊天，按其用途实际使用。
- 项目插件进入原项目创建表单；建立项目后，在原特性/需求列表创建需求，在需求详情完成配置并用“托管运行当前特性”执行。
- 导出 ZIP 用于分发。导出、安装、授权、启用和实际运行是不同动作。

## 任务侧栏怎么看

- “当前任务”：看执行到哪、是否需要确认，以及停止操作。
- “输出与面板”：看命令记录和插件提供的交互界面。面板可能是操作入口，本身不是任务完成或检查通过的证明。
- “高级设置”：看本聊天可用的能力；项目依赖按真实归属收起。可用不表示项目正在运行。插件管理只在此保留一个明确入口。

Mods 能制作独立工具、界面、事件规则和流程，也能组合已有能力；插件是保存与分发这些能力的载体。

## 已启用的功能从哪里打开

- 提供页面、侧栏或工具栏界面的插件，在使用卡的“此插件提供的界面”中点击具体入口。当前已生效的创作试用也有对应入口；打开成功后会回到原聊天显示，关闭后原草稿保留。
- 仅提供自动规则或 MCP 工具配置的插件，可以查看插件设置并返回聊天。声明存在不代表工具已经连接或规则已经执行，效果以实际调用和任务记录为准。
- “查找插件界面”只准备和读取已有入口。没有独立界面或声明有问题时，按页面显示的说明重新核对或返回聊天，不会代替你授权或执行。
- 回对话修改后出现新的待确认版本，工作区会显示本次试用批准入口；同一版本刷新不需要反复切回，也不会自动批准。
- 导入开发文件夹时，源码准备和聊天试用可以同时保留。依赖安装结果不确定时先核对原记录；准备完成后按真实当前候选选择试用或保存。

第一阶段具体范围见 [贯通验收](mods-continuity-phase1-verification-2026-11-01.md)。

## 试用聊天卡片、连接工具和子任务

在普通本地聊天开启创造者模式，可直接复制这段需求：

> 创建一个通用的“目录检查助手”。提供明确的显示入口，并告诉我试用生效后怎样打开聊天卡片。卡片上有“开始只读检查、刷新进度、查看记录、停止”按钮。点击开始后，让一个子任务检查当前目录的 README 和项目约定，文件不存在就如实说明，不修改文件。显示真实进度和工具结果；只有我点查看时才打开只读记录，返回后保留原聊天草稿。停止只说明请求是否被接受，等任务真正结算再更新状态。还可以列出我在此聊天明确选中的 MCP 服务；没选择时告诉我去原有连接工具设置，不自动改配置或连接其他服务。

按原路径准备、确认试用，再按交付说明的指令或界面入口显示卡片，然后使用卡片按钮。卡片固定在触发时的消息位置，后续消息接在它后面；右上角原生关闭按钮始终由应用控制。卡片不进入模型或历史，重启、重载来源或成功压缩后需重新触发显示。

MCP 先在当前聊天组合设置的“连接工具”中明确选择服务，保存并应用。插件使用宿主管理的配置与凭据；连接状态区可刷新、取消、断开和进入对应来源设置。本轮新增主动连接支持本机命令形式（stdio）；HTTP/SSE 的新主动连接尚未开放，原已配置服务的原调用流程保留。

子任务记录通过原只读分栏查看，输入仍发到原聊天。内容来自实际保留的任务运行记录；缺失、过大或压缩前不可用的内容会说明，不以结果摘要替代原文。查看不会重跑任务。

具体支持范围与验收证据见 [第二阶段验证](mods-capabilities-phase2-verification-2026-11-01.md)。这些是通用能力，不要求使用 AutoBiz，也不改变项目模式流程。

## 128K 为什么仍可能压缩

128K 是输入与输出共享的配置窗口。本次问题现场为：128000 − 输出预留 81920 − 安全量 1000 = 可用输入 45080 tokens。输入包含聊天、工具和系统指令。高输出上限会挤占输入空间；不能直接把窗口填写得更大来绕过模型真实限制。

模型设置现在会显示这笔预算。请按服务实际支持的窗口与需要的输出长度配置；系统不会静默修改你保存的值。最终请求超限时会进行一次有界恢复，固定指令/工具过大或压缩无进展时停止并解释，保留聊天和草稿。

基础能力的实际开放范围及 Claude Code 2.1.316 差距见 [能力审计](mods-claude-2.1.316-capability-audit-2026-11-01.md)。
