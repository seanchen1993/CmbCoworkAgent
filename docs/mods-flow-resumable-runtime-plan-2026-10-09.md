# 可恢复 Flow 原生执行接线

本细化服务最终方案 B3。已落地的历史 CAS、产物观察和纯诊断仅是基础，不等于用户已经可以续跑。先完成显式选择的文本流程真实链路，再完成文件修改型链路；文本子集不代表 B3 或最终方案完成。

## 第一条可用链路

用户显式选择版本化的可恢复文本执行配置，流程仍为宿主直线 Agent、原生检查和人工确认。不更改普通 Flow、普通聊天、Harness 和 UAT 的默认行为。配置说明该模式的 Agent 步骤只使用固定提示词和前序文本结果，不读写文件、不调用业务工具、MCP、Skill、子任务或动态扩展。保留唯一的宿主结果工具 structured_output，不能被同名工具替换。项目强制最终检查和确认仍执行；检查脚本的不明结果仍禁止重放。

复用 FlowNativeHost → runWorkflowSubagent → prepareStandardThreadRuntimeFactory → createAgentRuntime → 既有 provider/graph/checkpointer。不得用裸模型调用代替鉴权、用量、取消、工具结果协议及子线程回收。可在现有图构建器内增加封闭的能力配置分支，但不另建业务调度循环。

## 封闭配置及宿主证明

在任何依赖装配之前识别该配置，明确关闭工作区提示词、AGENTS、Memory、Skill、MCP、文件工具、shell、动态工具、子任务和非必需步骤 Hook 的装配。只设置 allowedToolNames 不足以证明准备阶段没有调用其他能力。普通路径不走新增分支。

宿主以实际运行器装配事实产生私有证明；Renderer、模型、JSON 中的布尔标记不能授予资格。Factory 合并 Harness 选项以后再做约束，不能由后续展开覆盖。动态模型／步骤策略如果是强制的且尚无法纳入证明，给出具体原因并拒绝该受限模式的恢复资格，不静默关闭强制策略。

证明至少绑定运行器协议版本、最终模型输入与固定系统／角色提示词、模型引用及配置摘要、强制策略摘要、唯一结果工具的宿主身份、父线程实例与当前权限。执行实例字段与稳定依赖分开；凭据不落盘。真正没有文件依赖时使用准确的 prompt-and-prior-receipts 覆盖类型，不要求对无关 node_modules 做虚假的完整快照。

## 持久化与恢复入口

每个新执行开始前写入 executionId，实际结算及证明持久化后发布结果。查询不 prepare、不创建线程、不连接服务。恢复由 UI 明确点击：校验查询来源摘要，隔离旧 owner，取得新租约，重新准备并核对证明，在开始新步骤前执行历史 CAS。准备失败、写入失败、撤权、来源改变都停止，不能退化为从头执行。

新运行引用原前缀，旧回执内容保持可追溯；实际新输入须包含有效复用文本。现有完成指纹包含运行实例，不能直接冒充稳定恢复证明，也不能通过覆盖原输出指纹破坏 provenance。恢复执行必须显式处理复制回执与当前完成检查的关系：历史执行事实不等于本次最新产物验证，最终检查必须产生新证据。

沿用根 deadline 和整条父链真实调用预算，复制记录不新增模型用量。原审批 nonce 不复用，最终提交已开始或结果不明均禁止恢复。已消费来源不可覆盖；新运行崩溃后只可核对新来源，不能再消费父来源。

## 最小验收

真实原生运行器与受控模型完成“生成 → 审阅 → 确认”：第一步结算后在第二步前结束进程，重启后核对并续跑。记录 provider 调用次数证明第一步没有重复执行，第二步收到前序文本，完成强制检查和新审批。再验证租约/线程实例/模型/权限/策略变化、重复点击、写失败、未知检查和未知调用、超预算以及过期UI响应。

必须有实际进程测试与 UI/preload/IPC 链路。Fake host 和纯函数只验证局部契约，不计入真实恢复验收。文件修改型恢复仍需实际文件依赖、ignored产物、写入隔离和启动前复验，保留为后续必做项。
