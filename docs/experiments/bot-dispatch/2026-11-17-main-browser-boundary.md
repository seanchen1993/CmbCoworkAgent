# 主 Bot 浏览器角色边界修复与计划回检

2026-11-17，基于 `codex/merge-uat-into-bot-beta` 的 `0f13fc512b6bfe4a7a37399882c8e2704c473d8d`，使用本次未提交改动构建并验证。macOS arm64、Node 22.23.5，真实模型为 `deepseek-v4-flash`。各轮构建、源码指纹、输入和退出码见下面的记录。

## 问题与假设

用户内网截图显示主 Bot 先打开网页、确认登录、操作门户，直到前台预算耗尽才创建独立任务。前一轮[诊断记录](supplementary/2026-11-17-main-browser-boundary-diagnosis.json)用真实预算中间件和模拟工具处理器确认：前 4 次浏览器调用获准，第 5 次被预算拒绝；不是 UAT 合并引入。

此前仅拆分沟通提示词、禁用同步子代理，没有移除主对话的 `bot_browser` 和 `bot_request_browser_help`；上下文还要求主 Bot 申请接管并等待。已有部分测试甚至要求主用户轮存在浏览器工具。这是实现与原计划不一致，不能归因于模型不听提示词。

假设：从模型可见工具和运行时执行权限同时移除浏览器，统一提示词，并保留执行器与宿主通知链路，网页请求就可以直接交给独立任务，无需先消耗前台预算。

## 修复与回检

| 项目 | 检查与处理 |
| --- | --- |
| 私聊、招乎私聊/群聊主用户轮 | 不构造两个浏览器工具；运行时 denylist 拒绝旧历史/恢复调用，且发生在预算、工具副作用之前。短 Shell、任务控制、提问保留。 |
| 首次聊天及期间的 steer | 初始化轮也使用沟通角色和前台预算，避免一条补充消息继承执行器权限；原有新手提问/真实回答校验继续生效。真实用户来源判定仍与沟通角色判定分开。 |
| 内置/MCP 浏览器 | 复用已有 Bot MCP scope，验证 eager/lazy 工具发现、旧别名重新解析和执行拦截；普通文档工具仍可用。内置工具依赖的浏览器 capability 不会出现在这个 scope。 |
| 电脑页 | 默认展示等待接管的任务；不再默认选择“主对话的浏览器”。例行与后台工作仍可查看。仅当前页面轮询，原任务页归属及请求代次不变。 |
| 接管、状态、结果、群归属 | 独立任务仍可操作浏览器和请求接管；主对话的关注卡片以及原群/私聊通知继续使用原任务身份。补测回传、状态查询、撤销绑定后的通知过滤。 |
| 调度与资源锁 | 验证任务创建/查询/补充不等待工作目录执行锁；浏览器与文件写入仍受原归属约束。没有新增全局锁或额外模型分类请求。 |
| 原文、技能、steer | 独立任务原文与技能传递、运行中补充、Feature 根运行 steer 回归通过。本次不改变等待提问时新消息的既有行为。 |
| 尚未统一的 Feature 交办 | `bot_feature_update.message` 仍承载 Bot 整理的指令，尚未接入独立任务的原文引用协议；已明确列为计划未完成项。Feature 仅子运行活跃时不向任意子代理注入，这仍是现有保护边界。 |

用户明确推迟讨论预算错误展示和交办措辞，本次没有改这部分体验。没有改 IM 网关、DDL 或 ES 查询。例行工作、内部协作和 App 多 Bot 群仍保留其既有执行合同。

## 真实模型实验

通过真实 Electron App、Runtime、浏览器和模型执行。模型请求透明转发，没有重写工具、强制创建任务或模拟路由决定。网页由本机测试服务提供，只含虚构数据。隔离 profile 使用测试授权的 YOLO，不改用户配置，不连接内网招乎。

输入为“打开 `<本机测试页面>` 看一下今天的代发情况，告诉我总笔数和总金额。”，没有指定独立任务或后台执行。任务真实浏览器回执中读取到 37 笔、128640 元，最终汇报也核对这两个数值。

| 运行 | 观察 | 交办 / 主轮结束 | 业务验证 |
| --- | --- | --- | --- |
| [第一轮](runs/20261117T073245Z-c20ecf7b/record.json) | 主动委派，没有前台浏览器调用或预算兜底 | 3.1 / 5.0 秒 | 独立任务实际浏览后回传，整段 11.8 秒；同轮问候直接回复，短 Shell 直接执行且未创建任务。 |
| [第二轮](runs/20261117T073517Z-9257ffe4/record.json) | 同一网页输入，新增主对话并行问答观察 | 3.3 / 4.9 秒 | 浏览器结果回传，整段 9.2 秒；主轮结束后另问 2+3，1.1 秒收到回答，查询时任务仍在执行。 |

第二轮正确答出 5，但额外附带了一句任务状态，`exactFormat=false`；只答数字的格式要求未完全满足，不能记成格式通过。第一轮没有插入并行提问，相关指标缺失不能算成零。两个网页样本均通过业务校验，实际沟通角色请求中的浏览器工具数量均为 0；不能由此声称稳定命中率或内网固定响应时间。
