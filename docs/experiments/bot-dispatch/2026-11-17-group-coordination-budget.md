# 群查询预算分类修复与缓存审查

日期：2026-11-17，Asia/Shanghai。

## 范围与假设

用户要求暂缓文件路径规则调整、继续讨论角色拆分与 KV cache，并修复错误的群查询工具名。本轮产品改动只涉及前台预算的协调工具集合，没有修改工具对外名称、提示词、模型配置或 IM 网关。

实际注册工具为 `bot_list_groups`，预算集合误写为 `bot_group_list`，因此查群会消耗执行次数并启动执行计时。另一个未注册的旧名称 `bot_group_send_message` 一并移除；实际发送工具 `bot_send_message` 已在集合中，继续保留。

## 条件与验收

- Node 22.23.5、Vitest 3.2.4；纯单元测试，不使用真实或模拟模型，不发送群消息。
- 命令：`node node_modules/vitest/vitest.mjs run src/main/agent/foreground-work-budget.test.ts`。
- 在既有未提交工作上增加一个回归用例，再修正集合；分支、HEAD、两份相关源码的 SHA-256 和各轮时间分别保存在 JSON 中。未构建应用，未测 Windows 包。
- 用例设置执行额度为 1 次、时间预算为 30 ms，使用手动时钟：查群后推进 31 ms，再协调发送消息；首次文件读取仍应获准，下一次文件修改应被拦截。执行额度用尽后，查群与群消息协调仍应可用，且不能伪造已成功交办。

## 缓存静态审查，未实施重构

- 当前 Bot 沟通角色使用专用基础提示；`work_result` 关闭工具，但因不属于沟通角色仍落入通用执行基础提示。代码中未发现为 KV cache 特意维持这一组合的说明，不能据此推断原作者意图。
- 对照已有真实请求 [20261117T083040Z-741c3d3a](runs/20261117T083040Z-741c3d3a/record.json)，沟通/执行/汇报分别为 30/24/0 个工具；其系统提示分别为 14569/28162/12811 字符。这里是字符数，不是 token 数或命中量，也不是本轮新增模型样本。
- 该样本的汇报系统提示在字符索引 134 处已有 `Current time`，文件引用规则在 7884 处，汇报规则在 10075 处。当前普通 Bot 运行仍在系统提示前部插入本轮时间。跨轮时间变化会影响后续相同内容的前缀复用；同一次运行内不应据此推断每次模型调用都会失配。
- [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/kv_cache/)以已持久化的匹配前缀为命中依据；[Claude 官方说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)明确工具定义、系统提示和消息按顺序参与缓存。两者都不能直接证明内网部署的实际缓存行为。
- 后续设计应区分代码角色模块化与请求前缀变化：固定角色内的提示和工具顺序，动态事件靠后；避免为一次结果汇报改写携带长历史的主会话前缀。轻量汇报应保留原需求、后续修订、真实回执和必要上下文，不能只压缩提示而丢失用户约束。
- 本轮没有缓存命中率、首字耗时或服务端计费对照数据，不宣称角色拆分能提升或不影响缓存。后续需比较实际未命中 token 数、首字与总耗时、调用次数和结果正确性，不能单看命中百分比。
