# 主 Bot 斜杠技能传给独立任务：实现与验收

日期：2026-11-17，Asia/Shanghai。分支 `codex/merge-uat-into-bot-beta`，基线 `0aa0e8e2a`，测试包含本轮未提交改动。具体构建哈希、源码指纹和测试脚本见各轮 `record.json`。

## 问题与处理

主 Bot 已保存用户通过 `/` 选择的技能标记，但之前独立任务只得到原始请求文本，没有进入显式技能激活流程。模型可能自行读取技能，但启动钩子与技能作用域不能依赖这一行为。

本轮由宿主从当前交办的真实用户消息、已经应用的用户补充中提取选择，传入独立任务原有 `trustedExplicitSkill` 入口。任务侧按自己的会话、工作目录和技能范围重新校验、激活。原始消息超过分页长度时也能提取；运行中交办的补充也传递选择，使用原运行的技能激活流程。历史引用、模型编写的交办摘要与外部渠道文本不作为显式技能选择来源。

不复制主 Bot 的钩子运行状态，不扩展技能权限。技能被禁用、不在 Bot 技能范围或文件不可用时仍走原有拦截。没有数据库结构、网关或用户操作路径变更。

读取复用原有来源查询，每批最多 64 个已捕获 ID；没有新增逐条查询、会话历史扫描或模型调用。未做生产耗时测试。

## 真实模型验收

环境：macOS arm64、Node 22.23.5、隔离构建的真实 Electron 应用，使用现有 `deepseek-v4-flash` 配置。模型请求经过透明本地转发，不改写提示词或工具调用。测试技能、三份输入材料与工作目录均为临时合成数据；仅在隔离配置中启用自动审批，不修改用户配置，不连接真实招乎。

测试通过与聊天框相同的 `getQueuedBotMessageInput` 构造斜杠选择；本轮没有自动点击技能下拉框。技能包含实际 `PreSkillUse`/`PostSkillUse` 钩子和 `verify.mjs`，要求生成 `prd.md`、执行脚本校验、调用 `bot_deliver_files`。

| 轮次 | 验收结果 | 证据 |
| --- | --- | --- |
| 1 | 失败：测试把 macOS 的 `/var` 与 `/private/var` 当成不同目录，过早中止产物校验；不能算通过。之后仅将目录断言改为比较 `realpath`。 | [完整记录](runs/20261117T030426Z-0b8b50b0/record.json) |
| 2 | 通过：独立任务启动时 `PreSkillUse.trigger=skill_select`，读取技能不重复激活；Post 钩子结束，生成文件、执行配套脚本、交付文件并回传主 Bot。交办 7.5 秒，主轮 9.5 秒，整体 29.6 秒。 | [完整记录](runs/20261117T030535Z-cc0c92d4/record.json) |
| 3 | 通过：增加产物哈希校验和不再选择技能的继续修改案例。首次交办 5.0 秒，主轮 7.2 秒，整体 28.9 秒。随后只发文字把借期从 14 天改为 21 天，继续同一个任务与目录，重新校验并回传；修改整体 23.5 秒。 | [完整记录](runs/20261117T030721Z-9a56fc91/record.json) |

轮次 2、3 的首次激活均由宿主显式传入，不依赖模型偶然读取 `SKILL.md`。轮次 3 的后续修改保留任务原对话中的技能要求，无需用户重新选技能；没有把这项选择设置为 Bot 全局永久默认。后续修改的证据是同一任务、同一目录、更新后的内容、脚本回执与文件哈希、结果回传；不宣称后续每轮都会重新触发显式选择。

三个运行目录独立保存，不覆盖失败轮次。这些案例明确要求创建独立任务，不能算作“不提示创建任务时的主动委派率”样本。

随后新增了 [只选技能、不要求独立任务的三次实验](2026-11-17-slash-skill-natural-routing.md)，独立记录自然分流、技能读取顺序及耗时；没有回填或改写上面三轮结果。

复现：先运行 `node --import tsx scripts/run-bot-integration-e2e.mjs --build-only`，设置 `BOT_TEST_APP_OUT`、现有模型配置目录 `BOT_ROUTING_MODEL_PROFILE` 与模型 ID `BOT_ROUTING_MODEL_ID`，再以 `BOT_ROUTING_CASE=slash-skill` 运行 `node --import tsx tests/bots-task-routing-app.spec.ts`。账号配置、密钥、内部地址及临时目录不写入实验文档。
