# 主 Bot 如何汇报独立任务的结果

2026 年 11 月 19 日，上海时间。在集成分支 `codex/merge-uat-into-bot-beta` 的 `606b232c6` 上测试本轮改动。对照版本在两项普通任务中由宿主发布执行器的原文，遇到独立复核或发前确认才进入主 Bot。[上一版实测](2026-11-19-unified-work-delivery.md)

## 交付行为

桌面私聊、招乎私聊和招乎群聊中，主 Bot 在对话里交办的独立任务完成后，宿主把原请求、已采纳的修改、执行结果和正式文件名送回发起交办的主 Bot。结果在原会话排队，正在处理的用户消息继续执行。主 Bot 根据用户关心的内容作答。能从回执回答时可以直接收尾，有具体缺项时可以续办原任务，用户要求独立复核时可以读取正式版本。正式附件由宿主按留存版本投递，传输状态使用各渠道的真实回执。

要求发前确认时，草稿在独立任务内等发起人批准。为完成工作而提出的问题、操作审批和浏览器接管仍按当前请求的归属发出。取消或解绑仍由宿主校验。本轮覆盖对话交办。固定提醒、日程触发的执行和静默条件仍遵循日程设置。

## 真实模型

各轮均使用 macOS arm64、Node v25.5.0、隔离的 Electron、已经配置的 DeepSeek V4 Flash 和合成数据。网页及源文件来自本地夹具，技能案例在聊天框实际选择技能。每个案例使用独立会话。端到端用时从该条请求开始到原会话可见最终结果。会话响应测试使用另一条简单问题，另外记录是否与后台执行重叠。

| 运行 | 改动和观测 |
| --- | --- |
| [第一轮完整记录](runs/20261119T002349Z-b3862c32/record.json) | 网页日报、斜杠技能、独立复核、发前确认全部通过，每项均产生一次主 Bot 汇报轮和一次正式发布。日报和 PRD 未重读证据。后台期间，两个探针分别在 1.1 秒和 1.3 秒内获得回复。复核回复解释了过多文件读取细节，PRD 回复还提到脚本和校验值。 |
| [第二轮完整记录](runs/20261119T003420Z-86893d01/record.json) | 调整了汇报措辞。四例通过当时的断言，日报与 PRD 均只发布一次。人工检查发现确认案例转述了执行器所派代理的结论，主 Bot 没有亲自读正式版本，且附件里多了输入文件 counts.txt。该案例用时 217.4 秒。这一轮不能计作通过独立复核质量验收。 |
| [第三轮完整记录](runs/20261119T004518Z-faa16945/record.json) | 只在明确要求独立复核时，宿主用原有权限和摘要校验读取一份小型正式文件，把带状态的正文送入主 Bot 的真实请求。两次复核分别读到 total.md、approval.md 的实际数值 7、4、11，后者只附上了需求指定的文件。四例各一轮主 Bot 汇报、一次正式发布，仍发现批准后的正文末尾在询问是否发布，随后补了对应的验收断言。 |
| [单独复测发前确认](runs/20261119T004857Z-ff34a458/record.json) | 主 Bot 看到了 approval.md 的正式正文，确认卡和发布均只有一次，但最终消息只有“查看原任务结果”链接，缺少正式附件链接。按新的验收标准判定失败。当轮没有留存版本选择原因。随后区分了确定文件版本和批准发送两件事，增加了记录待选原因、留存文件名和必交文件名的观测。 |
| [最终四例复测](runs/20261119T005157Z-d05f9e65/record.json) | 四项均通过，每项均只有一次主 Bot 汇报和一次正式发布。请求独立复核的两例中，主 Bot 分别拿到了 total.md 和 approval.md 的正式正文，核对出上午 7 件、下午 4 件、合计 11 件。发前确认只出现一次，批准后正文带有 approval.md 附件，原始输入 counts.txt 留在任务内。 |

第三轮独立复核用时 34.6 秒，发前确认 26.0 秒，网页日报 12.8 秒，斜杠技能 PRD 25.7 秒。PRD 执行期间另一个问题在 1.3 秒得到回答。该轮日报探针在 1.5 秒得到回答，但采样时后台已结束，不能算作并行响应。主会话的 8 次请求对比中，工具定义和系统提示保持一致。测试未测服务商的缓存命中率。

最终轮网页日报用时 12.3 秒，主 Bot 回报 37 笔、128,640 元。斜杠技能用时 30.2 秒，正式附件为 prd.md。两个后台执行期间，各发了一条简单问题，主 Bot 分别在 2.1 秒和 1.3 秒答复。独立复核用时 34.7 秒，需要本人批准的案例用时 91.6 秒。7 次汇报请求与各自会话的主 Bot 请求具有相同的系统提示和工具定义。PRD 回复仍提到了校验脚本及摘要，确认案例的正文也复述了文档内的“待确认版本”字样。用户实际只需批准一次。

## 招乎群与回归

- 真实 Electron、IPC、本地 SQLite 和 WebSocket 模拟网关串起私聊交办到招乎群的流程。初次用例验证群只收到主 Bot 的一条整理结果，独立任务的原文可在任务详情查看。扩展用例让独立任务先漏掉验收条件，主 Bot 把具体缺项交回同一个任务、同一个线程。群里只收到补齐后的汇报，未出现两次执行的原文，也未混入私人会话内容。[群内端到端用例](../../../tests/bots-private-group-app.spec.ts)
- 经过宿主和 IM 服务验证私聊和群聊各自的普通发布和发前确认。批准前没有排队发件，重复确认发布回执后仍只有一份正文和一份附件。另一群历史为空。另用 20 个正式附件覆盖模型预览最多 16 个文件名时的完整投递。[IM 服务用例](../../../src/main/bots/im-channel.test.ts) · [队列及批量附件用例](../../../src/main/bots/work-result.test.ts)
- 第一轮定向回归 543 项中有一项失败。20 文件夹具一次提交了超过单次工具上限的文件，修正为三次合法的提交，每次分别为 8、8、4 个文件。另一次并行回归中，私聊断线附件用例的测试时钟与真实绑定激活时钟有先后偏差。改为先激活全部测试绑定，再固定两个发布事件的时间，保留了同时间戳和离线去重的用例条件。独立的运行时、任务工具、续办和停止等回归为 847/847。
- 修正后，12 个相关套件串行通过 1,184 项。加入正式正文、不可用版本、较大文件和普通汇报不预读的检查后，14 个套件通过 1,284 项。发前确认和文件选择改动另复测了 4 个相关套件中的 648 项。普通对话、Workflow 等 14 项系统提示检查及主进程类型检查通过。单独的 Electron 日程回归触发一次固定提醒、两次原任务执行，验证一次技能选择和结果回传。在受控后台任务保持运行时，两轮测得主对话分别在 232 毫秒和 297 毫秒回复。

## 复现

在隔离的桌面测试构建上，用已有的测试模型配置运行下列入口。真实模型运行会分别创建新的实验目录，并保存所测构建指纹、逐轮模型请求摘要和审批记录。

```sh
BOT_ROUTING_CASE=delivery-review,delivery-confirm,browser-lookup,slash-skill-natural \
BOT_ROUTING_PROBE_RESPONSIVENESS=1 \
node --import tsx tests/bots-task-routing-app.spec.ts

BOT_FEEDBACK_ONLY=1 node --import tsx tests/bots-private-group-app.spec.ts
```

此处的招乎发送、群归属和重复投递验证均使用本地传输。真实模型的单次响应时间包含服务端波动，各轮独立保留。
