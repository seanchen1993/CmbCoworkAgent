# 主 Bot 斜杠技能固定交办

日期：2026-11-17（Asia/Shanghai）。在已有未提交的 Bot 提示、结果排队和交办反馈改动上继续开发；本轮未提交、推送或修改 IM 网关。

## 假设、实现与范围

主 Bot 先读技能再决定是否委派，会占用主会话并可能触发预算续办。用户通过 `/` 选择技能后，固定走“选目的地 → 接受交办 → 首回复 → 任务执行 → 结果回传”，可以去掉这段前台执行。

- 仅本机主 Bot 的当前用户技能选择触发 `bot_skill_dispatch`。普通文字提到技能、普通对话、项目模式及独立任务中的输入保持原入口。模型只选短标题、目录和目的地，不再决定是否委派。
- 新工作创建任务；已有工作沿用 work、thread、工作目录。可按当前快照 ID 或任务名称选择，名称不唯一时返回实际阻塞。恢复已完成任务与补充入队在一个事务内，失败回滚；稳定请求键防止重试重复创建或误恢复已完成任务。Bot、受众、会话绑定和运行租约校验继续生效。
- 原始请求和技能选择由宿主传递。主 Bot 不触发技能 Hook，不读取 SKILL.md、业务文件或执行 Shell；执行器显式激活技能，保留原校验和配套脚本。
- 主轮强制调用交办工具，并在工具 Hook 前增加执行校验。接受回执后由宿主首回复一次、展示任务入口并结束主轮，不再调用模型生成二次确认。实际错误保留，拒绝创建时不声称已启动。
- 主 Bot 忙时的新 `/` 选择排队，不 steer 到旧运行；短调度期间其他输入也排队。独立任务的正常补充仍沿用现有 steer。任务结果仍进入原会话队列，不注入当前用户轮。

## 模型兼容性

第一版在 DeepSeek 思考模式直接指定 `tool_choice.function`，两个技能案例均返回 `400 Thinking mode does not support this tool_choice`，没有创建任务。这不是成功或快速响应。

修正后只有这次短调度调用采用非思考、非流式、单工具调用，用于填写目的地参数；未经回执验证的模型前置文字不作为首回复展示。执行器、其他主轮和项目模式保持各自模型配置，用户配置未变。协议测试和真实请求均验证了这个边界。

工具定义仍保留在稳定的主 Bot 工具集里，非技能轮误调用因缺少可信选择被拒绝。通过的真实运行包含 10 次汇报前缀校验：系统提示与完整工具 schema 不变，汇报为 `tool_choice: none`。没有服务端 KV cache 命中或计费数据，不能据此声称缓存收益。

## 环境与验收

macOS arm64、Node 22.23.5；实际 Electron App、隔离临时 profile、真实 `deepseek-v4-flash`。沿用虚构图书借阅材料与 `slash-prd-fixture` 技能，凭据只读；没有连接生产招乎、ES 或业务网页。

沿用原自然输入：仅通过斜杠选技能，不要求独立任务，指定目录，综合需求、约束和现有接口生成 `prd.md`。校验实际文件章节、数字、技能标记、自带脚本生成的 SHA-256 回执、显式技能 Hook、附件交付及完成事件回传。增加主轮只有交办工具、一次模型调用、接受后一次首回复、主线程零技能 Hook、无预算兜底的断言。另测普通修改、再次选技能修改、完成后恢复、问候与短 Shell。

## 回归与失败留档

- 最终核心回归 **496/496**，技能选择、普通/项目提示和工具范围等边界回归 **21/21**。实际 App 配合模拟模型的任务闭环通过，16 次模拟调用验证创建、继续、文件交付、完成后恢复及界面切换；不计入真实模型效果样本。
- 类型检查、源码和构建快照、全部日志见[验证汇总](supplementary/2026-11-17-slash-skill-fixed-dispatch/validation.json)、[证据索引](supplementary/2026-11-17-slash-skill-fixed-dispatch/evidence-index.json)。
- 中途问题均保留：项目查询字段误用 `id`（应为 `projectId`）、测试泛型数组类型缺失、旧测试仍要求新技能 steer 到主运行、子操作调用 ID 含冒号不符合现有标识规则。均已修正并复测；额外验证了失败回滚和晚到重试不误恢复任务。
- 请求数统计已修正：旧脚本只看最后一条 user 消息，可能把临时开场提醒当成请求而低估调用数。新脚本跳过提醒，并匹配技能块之外的原始请求。新旧请求数字段不能直接同比；宿主计时口径未变。
- 第一次截图早于会话正文加载完成，不作为界面验收。补上正文/附件等待后，实际检查到一次首回复、任务入口、并行回答、返回结果和任务内附件卡。截图含本机临时路径，仅本机保留，Git 保存[视觉核查和原图哈希](supplementary/2026-11-17-slash-skill-fixed-dispatch/visual-review.json)。

## 结论边界

证据支持：显式 `/` 技能入口由宿主固定交办、模型只选目的地，可避免主 Bot 先执行技能，首回复紧跟接受回执；后台执行期间主会话可继续响应。

界面复核仍看到执行器“执行遇到问题”的历史入口，最终脚本、产物及交付校验通过。本轮 `toolErrors` 统计主轮，不能声称执行器全程无工具重试。最后一轮汇报写了“附件见上方卡片”，实际文件卡在任务会话、主会话提供任务跳转；该位置表述不够准确，本轮没有扩展修改通用汇报提示。执行质量与汇报准确性继续单独观察。

未实测生产招乎、Windows、长历史 Bot 和其他模型；权限、去重、错误和模式隔离的本地验证不能替代部署验收。
