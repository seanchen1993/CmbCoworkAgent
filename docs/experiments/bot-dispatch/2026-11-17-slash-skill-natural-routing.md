# 仅通过斜杠选择技能时，主 Bot 如何交办

日期：2026-11-17，Asia/Shanghai。承接 [技能传递验收](2026-11-17-slash-skill-handoff.md)。本轮只补测试和留档，没有修改产品提示词、工具或路由规则。

## 要回答的问题

用户通过 `/` 选择技能，但正文不要求创建独立任务或后台执行时，主 Bot 会直接交办、先读技能再交办，还是自行完成？前一轮技能验收明确要求独立任务，不能回答本问题。

## 环境与方法

- 同一真实 Electron 构建，模型 `deepseek-v4-flash`，Node 22.23.5，macOS arm64。运行前核对构建清单中 10 个产品源码指纹，与当前源码一致；构建基线、脏状态和完整指纹分别保存在各次记录中。
- 连续运行三次，每次为新隔离 Bot、临时配置、工作目录、虚构输入，使用同一个测试技能 `slash-prd-fixture`。模型请求透明转发，未改写模型决定或强制调用创建工具。
- 使用真实聊天框的 `getQueuedBotMessageInput` 和 `formatSkillUseBlock` 构造 `/` 选择，走 App 发送入口；没有手工点击技能菜单，不冒称完整鼠标交互验收。
- 相比前一案例，仅从用户正文删除“创建独立任务，”；附加的正式技能选择标记保持原样。该标记仍有“先使用 read_file 读取 SKILL.md”的说明。
- 记录主对话与任务各自的工具名、入参、顺序，分别核对宿主技能激活钩子、文件、配套脚本回执和结果回传。路由偏好与执行校验分开：新用例不通过断言或重发要求强迫创建任务。
- 只在一次性配置中开启测试自动审批，未修改用户配置，未连接真实招乎或运行 Windows 包。

用户正文（目录已脱敏）：

> 请使用我选择的技能，工作目录 `<测试目录>`。综合需求.md、约束.md、现有接口.md生成 prd.md，执行技能的校验并把文件交给我。资料都是虚构的，不联网，也不发送外部消息。

三次退出码均为 0，最终各创建一个独立任务。主 Bot 均未读取三份业务材料、编写 PRD 或运行校验脚本，这些步骤由任务执行。任务侧 `PreSkillUse.trigger=skill_select`，同一任务内读取技能不会重复激活；`PostSkillUse` 完成，`prd.md` 落盘、校验脚本实际运行、回执哈希匹配，调用 `bot_deliver_files` 并完成主 Bot 结果回传。

第三次不能描述为“无错误一次成功”：模型第一次错误地将技能标记名 `CMBDEVCLAW-SKILL-USE-V1` 填入 `contextMessageIds`，宿主返回“所选相关消息不可用或超过上限”。模型移除该错误引用后自行重试成功，没有创建重复任务。工具错误和两次入参完整保留。

## 结论与边界

本组 PRD 场景的观察是“主 Bot 先读技能，再主动交办”，不是省略技能读取直接交办，也不是主 Bot 自己完成整个技能流程。三次都没有依靠前台预算强制交接。

这里要区分两个步骤：宿主在主轮开始时校验显式技能并触发其生命周期；随后模型仍实际调用 `read_file` 了解 SKILL.md。独立任务获得结构化技能选择后，在自己的线程和目录中重新校验与激活。主线程与任务线程分别激活，不等于同一线程重复执行启动钩子。

当前技能选择标记要求先读说明，与这三次调用顺序一致；是否创建任务仍由模型结合沟通调度提示判断。本轮没有证明所有技能都走相同路线，尤其不覆盖短文本技能、调度技能、长历史 Bot 或复杂技能钩子。7.3–10.0 秒为成功交办耗时，9.8–11.8 秒为主轮记录占用，不是首字延迟，也没有在本轮插入并行新问题。

额外观察到两处模型文字与实际证据不一致，保留为后续质量材料：

- 轮次 1 的最终摘要写成“不做逾期提醒”，而输入与任务实际写入的 PRD 都保留了逾期提醒。文件/生命周期校验通过不代表自由文本摘要语义零错误。
- 轮次 2 的主 Bot 表述“已读取……三份输入”，但交办前工具轨迹只有技能读取和目录列表，没有读取三份材料；最终结果来自任务执行。不得用模型自述代替工具证据。

另有交办说明重复复述技能步骤的现象，说明主 Bot 虽未执行业务，沟通仍有压缩空间。本轮仅回答读取与路由机制，没有调整提示词修饰这些观察。
