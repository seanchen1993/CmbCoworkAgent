## 复测过程

首轮五组渲染器单测为 165 项通过，随后增加了跨群负例。群历史测试首次打包时误将新抽取的日程编辑器视为桩模块，执行在启动前退出（1）。将真实组件加入夹具后端到端操作通过。

私聊向招乎群交办的扩展用例初次缺少专用 Electron 测试入口（退出 1）。用 `--handoff` 构建后，“私聊交办 → 群内独立任务 → 回到原群和私聊”已走通，但后续“预算续办”的模拟模型把宿主的首回复提醒当成了用户新请求，等待任务结果超时（退出 1）。让模拟器和其他桌面用例一样，按最近一条真实用户消息选择回答，保留原断言和超时，在同一桌面产物上复测。

后续两轮均在独立任务输入阶段等待超时（各退出 1）。测试原先在新 Bot 打开时立即切换会话并输入。改为等待欢迎完成、任务原始消息可见，并在目标会话输入框逐条检查两条补充都已入队。再次运行时两条均注入成功，但模拟器将结果包里引用的原始指令误当成新执行，等待空闲超时（退出 1）。按当前汇报工具和事件识别结果轮次后，完整脚本退出 0，记录了 39 次本地模拟模型调用。以上调整均在测试夹具中。产品构建与功能断言相同。

## 复现

使用 Node.js 22，从集成工作区运行以下构建。将构建输出的绝对路径设为环境变量 `BOT_TEST_APP_OUT`，再逐条运行各场景。每组使用独立的临时配置。

```sh
node scripts/run-bot-integration-e2e.mjs --handoff --build-only
node --import tsx tests/bots-details-cards-app.spec.ts
node --import tsx tests/bots-im-conversation-browser.spec.ts
node --import tsx tests/bots-work-attention-layout-app.spec.ts
node --import tsx tests/bots-scheduled-skill-app.spec.ts
node --import tsx tests/bots-private-group-app.spec.ts
node --import tsx tests/bots-steer-stream-app.spec.ts
```
