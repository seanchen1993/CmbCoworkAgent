# 同一个 Bot 的私聊与两个招乎群使用同名任务

2026-11-19，macOS，App 1.5.7，Electron 39.8.10，Node 25.5.0。基线为 `codex/merge-uat-into-bot-beta` 的 `39b548bcf` 加本次未提交修改。

## 问题与验收

同一个 Bot 在 App 与招乎本人私聊使用同一份私人任务和日程。每个招乎群有自己的任务、日程和群内记忆。「Bot 共享」记忆按既有设置可跨会话读取。验收同时检查正常操作和误传其他会话标识的结果。

## 实际操作

Electron 使用隔离的临时资料目录和真实的渲染器、IPC、SQLite 和任务会话。测试为私聊、「设计协作群」和「资料协作群」各创建一项「同名周报」，分别写入「个人核对结论」「设计组核对结论」「资料组核对结论」。对应原始回复作为可区分的数据，不依赖模型生成。测试未连接企业招乎网关。

| 场景 | 验收与证据 |
| --- | --- |
| 从三个详情面板查看和预览 | 三个面板分别只显示一条同名任务。逐一点击预览，显示本会话的标记，其他两条任务及其回复均未出现。[私聊](private.png) · [设计协作群](design-group.png) · [资料协作群](docs-group.png) |
| 从群预览打开会话 | 从设计协作群点击「打开聊天」，在完整任务会话中读到同一条回复，再返回原群。 |
| 从 App 的群详情创建例行任务 | 在群详情实际点击新增并保存「本群周报日程」，检查日程的群归属和执行任务。另以本地宿主触发同类日程，核对工作线程及网关替身收到的目标群。 |
| 交叉操作同名任务 | 宿主测试分别从本人私聊、群 A、群 B 发起请求。六种跨会话组合的观察与删除均被拒绝，未写入删除回执。各自观察产生的通知只写入原主会话。删除群 A 的任务后，私聊和群 B 的同名任务仍可查询。 |
| 通过 Bot 删除任务 | 通过宿主与桌面清理服务检查 App 私聊、招乎本人私聊、群聊和群内需澄清的请求。明确指定唯一任务时直接删除，模糊请求在原群会话等待确认。删除后重放同一请求只读取原回执。 |
| 记忆 | 私聊、群 A 和群 B 的补充分开归并。群内自动提炼只读取本群的可修改条目，提交时重新核验归属。覆盖同名条目、私聊与共享记忆的保护、用户直接在群任务中补充与后台执行自行输出的区别。 |

## 验证方法

- 运行 `npm run typecheck` 检查主进程和渲染进程，再运行 `node scripts/run-bot-integration-e2e.mjs --build-only` 构建隔离版。
- 设置 `BOT_TEST_APP_OUT` 为该次输出目录，运行 `node --import tsx tests/bots-details-cards-app.spec.ts`。附加 `--keep-open` 可在检查通过后保留示例窗口。
- 用 Vitest 运行同目录的运行时、工作管理、会话删除、日程、记忆、IM 渠道、远程问答与前端预览测试。宿主使用真实 SQLite、受控执行器和网关替身。截屏和日志来自合成样本，不能据此推断真实模型的工具选择或内网消息送达。

## 复测过程

按运行顺序保留各轮计数，逐轮重复的用例不累加。最终汇总及关键原始日志摘录见 [验证输出](checks.txt)。

1. 首轮 277/311。预览夹具缺少新增的会话身份，另有旧断言固定了私聊限定的提示文案。更新夹具以模拟实际界面路径。
2. 第二轮 553/556。更新个人 IM 日程参数契约、预览状态和跨群观察错误文案的断言。后续单轮 792/793 中另一条旧文案断言也随之调整。
3. 三会话交叉测试暴露出 IM 删除判断读取请求时仍走桌面过滤条件，导致明确指定的任务也会被要求再确认。修复后，观察回执测试一度使用了回执中不存在的字段，改用真实的观察目标标识后两条专项测试均通过。
4. 扩展回归一轮 1107/1108，本人 IM 定时技能用例达到原有 5 秒超时。同时构建和类型检查结束后，以两个测试进程复跑通过 1120/1120。没有放宽时间限制。
5. 最后补足原生任务删除的四条入口测试。初版夹具遗漏网关运行许可的确认，导致三条 IM 请求未进入执行。补齐许可后的专项复测 4/4。桌面 UI 测试用单独资料目录重复运行。

最终构建通过主进程和渲染进程类型检查，16 个测试文件共 1140 项全部通过。Electron 窗口通过预览、原群跳转、日程及设置交互检查，并保留在可操作的示例状态。
