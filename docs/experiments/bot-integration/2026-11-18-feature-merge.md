# 无 Mods 集成分支与 Bot Beta 的功能合并验收

2026-11-18 在 macOS、Node 22.23.5、独立的 Electron 用户目录和本地模型服务上执行。集成分支起点为 `534a80e49`，Beta 的两个提交为 `d1290ea6b` 和 `9f1903ef9`。Git 报告了 52 个冲突文件。

## 合并后的用户行为

| 场景 | 验收条件 |
| --- | --- |
| 主 Bot 交办 | 主对话可继续沟通或做短查询，浏览器操作交由任务执行。主对话选定的技能随原请求到达工作线程，继续原任务时复用其会话和目录。附件只传本轮输入处理放行的版本。 |
| 任务回传 | 结果在主会话排队。普通汇报使用现有结果。需要核对的本机任务只开放该任务的结果工具，可引用已有成果或续办缺项。发布复用已有回复，并附上原任务结果和附件入口。 |
| 运行中补充 | 工作线程接受指向当前运行的文字补充。结束后的旧请求不能自动转入另一轮。尚未打开的工作会话只暂存当前回复，用户打开时显示已有内容。 |
| 导航和权限 | 点任务列表进入会话，旁边的预览入口可查看详情。切换页面后到达的回执不会夺走焦点。群聊和 Feature 保留各自归属，解绑、删除和本机接管继续校验身份。 |
| 大列表和调度 | 局部变化按受影响的 Bot、受众和任务 ID 刷新。已展开的搜索按原查询重新核对已加载页。已删除项移出列表，待清理项仍可跟进。调度继续让主对话及时获得运行机会。 |

## 本地实验

| 操作 | 观察 |
| --- | --- |
| `npm run test:bot-integration:core` | 171 个测试文件，4,064 个用例全部通过。覆盖受众隔离、取消及重放、已选技能附件、结果核对工具、用户接管、原运行补充、Feature、多任务调度和搜索分页。 |
| `npm run typecheck`、`npm run build` | 主进程、预加载和渲染端通过类型检查，Electron 应用生产构建成功。 |
| `tests/im-feature-binding-command.spec.ts` 与 `tests/managed-transport-delivery.spec.ts` | 招乎 Feature 会话选择和授权复查通过，托管传输回归通过。 |
| 默认及指定目录运行 `tests/bots-local-work-app.spec.ts` | 实际 App 中创建独立任务，任务等审批时主 Bot 能回复；写出第一版文件，继续同一任务交付第二版，两次结果均在主对话可定位。默认目录场景还覆盖完成、重开和草稿隔离。 |
| 运行 `tests/bots-steer-stream-app.spec.ts` | 本地模型先发一段回复并保持运行，随后发送、撤回和再次补充。主 Bot 观察 66 次 DOM 更新，工作线程观察 69 次，每段回复最多一个气泡。任务首次输出先于打开会话，刷新后的历史顺序一致。 |
| 运行 `tests/bots-im-conversation-browser.spec.ts` | 在模拟招乎数据下验证原群与工作会话切换、未读清除、已解绑群删除、附件导出及迟到请求；验证编辑弹窗通过关闭按钮、取消或 Escape 退出。 |
| 构建后运行 `tests/uat-without-mods-e2e.spec.ts` | 101 条独立会话、102 次本地模型调用；原生工具执行通过，旧 Mods 开关未加载运行时。 |

合并中实际出现过文件选择随技能丢失、旧任务列表过期、工作会话打开时错过首段回复，以及旧测试把内部核对和最终发布都当作一份用户结果。这些场景分别验证了实际收到的文件内容、目录成员、运行中的消息和最终可见回复。模型服务使用可控的响应以重现时序。招乎正式服务、内网模型和 Windows 客户端需要通过内网打包环境验收。

## 性能观察

在 45 个工作项及另一个 Bot 的 1,200 个历史运行上，分别读取五次 40 条任务列表。当前集成分支基线平均 2 ms，合并工作树平均 5 ms。建立同批 1,200 条运行并结算分别用时 1,573 ms 和 2,177 ms。这是本机单轮对照，合并版在这组样本上更慢。查询计划、批次、索引及独立任务并发由 `performance-regression.test.ts` 和 `work-projection.test.ts` 单独验证。流式预览只在尚未订阅的本机任务上暂存文本，最多保留 64 份、每份 32 Ki 个字符；这个上限只作用于界面预览。
