# Bot 独立任务的输入与控制权

2026 年 11 月 20 日（北京时间），在 macOS arm64、Node.js 25.5.0、Electron 39.8.10 上验证。截图中的问题发生在 Windows。本轮使用本地桌面应用、真实 IPC 和 SQLite，模型流与招乎网关由本地测试服务模拟。

## 复现条件

从 App 私聊创建一项独立任务。让模型发出第一个文本片段后保持运行，从 Bot 任务页以及普通对话模式打开同一条任务。验收标准是两个入口均只显示管理栏，宿主确认接管后才出现输入框，归还后收起。正在运行、等待回答和仅有后台活动均不能自动取得输入权。

集成分支为 `codex/merge-uat-into-bot-beta`。单元对照基于 `6c9194b80`。桌面对照使用前一晚的本地集成构建，构建清单的基础提交为 `7417088d9`，其中任务输入判定和宿主发送校验与单元对照一致。修复构建基于 `6c9194b80` 加本次修改，构建清单时间为 `2026-11-20T02:03:23.524Z`。

## 结果

| 场景 | 实际观察 |
| --- | --- |
| 修复前 | 正在执行和等待用户的任务都解锁了普通输入框。宿主也接受了携带当前运行 ID 的直接发送。三条新增回归均失败。旧桌面构建在运行中的 Bot 任务页同时显示了管理栏和编辑区。 |
| Bot 管理 | 两个入口均只显示管理栏。停止当前回复位于栏内，保留排队的后续指令。只有后台活动时，栏内隐藏该停止入口。 |
| 运行中获取控制权 | 普通对话中点击「获取控制权」进入移交等待，此时仍无输入框。取消接管后继续由 Bot 管理。回到 Bot 任务页再次接管，原运行结束后出现输入框。 |
| 已接管与归还 | 连续补充两条要求，均进入原运行，顺序在刷新后保持一致。归还控制权后输入框收起，再次接管可见归还前的未发送草稿。旧版绑定原运行的草稿无法越过接管校验，也不会误发到新一轮。 |
| 相邻流程 | 私聊向招乎群交办、结果回传、普通会话、Team、Workflow、主 Bot 和已接管任务的补充输入均通过桌面集成测试。宿主的原任务提问和审批另有单元回归覆盖。 |

定向 Vitest 测试共 10 个文件、260 项通过，分三批为 165、46、49 项。两项 Electron 测试的最终退出码均为 0。流式测试中主 Bot 和已接管任务分别记录 49 和 95 次 DOM 采样，同一段回复最多出现一个气泡。群交办套件共调用本地模拟模型 68 次。

## 测试脚本校准

旧脚本会在主 Bot 正文尚在生成时等待该正文出现在屏幕上。首轮旧版桌面对照在这里超时，退出码为 1，尚未测到任务页。改为在模型发出片段时补充要求，待宿主发布后检查主 Bot 正文，执行器仍在流式阶段检查。首次修复构建测试又把附带历史请求的模型调用计为第二次启动，退出码为 1。最终让本地模型按当前指令开头识别用例。使用相同的最终脚本再次测试，旧版在独立任务的只读管理栏断言处失败（退出 1），修复版通过（退出 0）。

## 复现命令

在仓库根目录运行第一条命令，将输出的隔离构建路径设为 `BOT_TEST_APP_OUT` 后执行两条桌面测试。

```sh
node --import tsx scripts/run-bot-integration-e2e.mjs --build-only --handoff
node --import tsx tests/bots-steer-stream-app.spec.ts
node --import tsx tests/bots-private-group-app.spec.ts
```
