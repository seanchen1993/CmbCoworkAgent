# Bot 默认对话中的非阻塞错误

2026-11-23，Asia/Shanghai。用户看到任务已经给出复核结论，前面仍有一张红色「执行遇到问题」卡片，展开是被宿主拦截的命令。复现条件为主 Bot 在复核或汇报时调用了当前回合不允许执行的工具，然后以允许的方式完成任务。

## 验收

- 已知的宿主拦截从默认对话隐藏，即使 Bot 没有重试被拦的命令。在默认私聊持续打开的情况下也不能闪出红色卡片。切到「查看执行过程」可以核对原命令、状态和原因。
- 如果一次实际操作失败，恢复须有同一次操作的成功回执。另一任务、另一附件、另一页的成功，或模型说「已经好了」，均不能清除原来的失败。缺少结果、发送状态未知、需要用户批准或接管时，保留对应提示。
- 同一任务在 App、招乎本人私聊和招乎群聊都应能正常交办和回传。检查例行任务、提问、审批、浏览器接管，以及普通会话的回归用例。

## 条件与复现

基线为 `codex/merge-uat-into-bot-beta@2ae81ae236f9`，加本轮工作区改动。macOS arm64，Node 25.5.0，Electron 39.8.10，Vitest 3.2.4。桌面用例每轮重新构建和创建隔离的用户数据，运行实际渲染进程、IPC、Bot 运行时、SQLite 及 WebSocket 客户端。模型和招乎服务均为本地可控替身。复核用例让模型先请求被限制的命令，再继续原任务。汇报用例让它改用已有结果直接作答。没有调用内网模型或招乎生产服务。

## 复测过程

1. 初次定向运行 7 个文件、234 个用例通过。扩大到 9 个文件后，416 个通过、3 个失败。更正了新增测试中对缺失回执 ID 的匹配、固定提醒实际调用的保存接口、群历史的查询入口。一次类型检查发现回执解析器缺少显式返回值，已修正。
2. 第一次桌面脚本超时。原断言在招乎群的消息列表内查找 App 专属工具错误按钮，该视图只呈现投递后的消息。改为分别断言群内收到业务原因、App 私聊显示错误入口。修正后的两轮脚本均退出 0，第二轮增加了对私聊回传过程中短暂闪现错误卡片的监测。
3. 扩展回归一轮为 636 个通过、16 个失败。在原提交的独立副本中单跑附件发布套件，得到相同的 16 个失败、56 个通过。旧用例会在本会话前一条文字或文件尚未确认时认领下一个附件，与当前按会话顺序投递的约定冲突。改为依次确认，保留文件身份、顺序和不重复发送的断言，72 个发布用例全部通过。
4. 最终定向回归 21 个文件、653 个用例通过，耗时 52.62 秒。最终桌面脚本退出 0，共 76 次模拟模型调用。交办、上下文隔离、补充要求、普通会话与工作流的既有用例一并通过。同步的类型检查发现测试辅助函数把空数组推断为 `never[]`。补上出站记录类型后，Node 和 Web 两项类型检查退出 0，单跑 72 个发布用例也全部通过。

本轮以可重复注入的故障和真实客户端展示判断结果，未测生产网络延迟、真实模型触发拦截的频率或措辞。没有宿主身份或可靠成功回执的第三方错误，仍保留原有提示。
