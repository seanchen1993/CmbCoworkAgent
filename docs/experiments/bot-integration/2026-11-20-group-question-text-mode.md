# 招乎群内独立任务的提问卡片与文字作答

2026-11-20（Asia/Shanghai）。在 `codex/merge-uat-into-bot-beta` 的 `f9b929aa2` 上验证工作区改动，使用 Node.js 25.5.0 和 Vitest 3.2.4。

## 问题与基线

用户在群里收到六道题，长选项在招乎下拉框中被截断。检查原卡片数据发现，只有多选题在题干下列出选项，单选题的说明全放在下拉框里。群任务提问也沿用了私聊的切换提示，缺少群内需要 @机器人 的说明。已有短码应当继续对应发出提问的独立任务。

本轮将完整选项和说明放在每个题干下方，单选下拉框使用对应的编号和名称。群卡片直接提示如何开启文字模式，切换回执解释新问题和当前短码的行为。个别待处理通知补发失败时，用户仍能收到切换回执和重试方式。

## 输入与结果

| 场景 | 验证结果 |
| --- | --- |
| 同一卡片含五道单选和一道多选，选项说明较长 | 六道题的完整选项均位于表单上方、各自的题干下方。单选编号与表单值逐项对应，多选保留编号输入。 |
| 群 A 已收到卡片，此时群 B 开启文字模式 | 群 B 未收到群 A 的题目，用群 A 的短码在群 B 作答也被拒绝。 |
| 群 A 切换文字，再次显式开启 | 群 A 的原问题只补发一次。第一题选 2，第二题收到新短码；第一题的旧码失效。第二题回复 `1，2` 后，原任务等待的输入返回了对应的单选和多选答案，旧卡片无法再次提交。 |
| 新请求以文字发出，答题过程中关闭文字模式 | 原短码仍能作答，第二题用“其他 最近七天”完成。下一份新提问发送卡片，群 B 继续使用文字。 |
| 卡片发送过程中切换、卡片发送失败、重复提交 | 远程输入和卡片回归脚本覆盖了在途切换、文字回退和已答请求。另用单元测试注入一次补发失败，命令回执仍返回重试方式。 |

群任务集成用例使用真实的任务输入等待、群绑定路由、SQLite 会话状态、消息发件箱与回答提交。网关发送、更新卡片、客户端展示和模型运行均未接入真实服务。选项完整性按发出的卡片结构验证，内网客户端在不同窗口宽度下的折行效果仍需真机确认。

## 选项换行复测（2026-11-20 16:29，Asia/Shanghai）

用户在招乎客户端看到题干和选项连在同一行。基线 `a370651f6` 的断言确认了正文片段的顺序，未检查片段拼接后的行边界。招乎接口文档中的内容组件支持富文本片段，示例在片段内容中使用换行符，数字样式 1 表示加粗。

本轮复用上述输入，在每个选项编号前写入换行符，并仅对编号使用加粗样式。普通机器人的网关报文按片段拼接后逐行核对，结果为题干一行、三个选项各一行。六题群卡片用例检查每题的编号样式、换行符、完整说明和表单值。两个定向 Vitest 文件共 10 项通过，远程输入脚本 15 项、卡片交互脚本 25 项通过，退出码均为 0。验证范围为本地报文和作答流程，修改后的内网客户端视觉效果尚未复测。
