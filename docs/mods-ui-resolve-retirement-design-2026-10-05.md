# 已关闭画面的等待与明确重载

本文件是 Stage21 补充方案，已通过两位独立方案评审及实现静态检视。正常取消后的真实宿主工作和
Promise 收尾已在第五轮 32 项测试中通过；本方案处理另一种情况：插件登记了永远
不结束的 Promise，关闭画面后，明确重载也一直显示忙碌。

## 用户效果

关闭旧面板后，只剩不能再执行动作的等待，用户可以明确重载组件。重载实际关闭旧
插件进程后再建立新实例。仍在执行的模型、文件或回调必须继续等待真正结束。
自动应用配置仍等待所有资源结束，不因为本次优化提前替换正在等待的插件。

## 底层判定

1. 虚拟机侧使用实际构造器占用记录观察终态。同步构造已返回；原绘制证明已失效且
   信号已取消；没有任何仍有效的宿主工作或回复工作回执（包括已经接纳但尚未调用
   宿主的 SDK），也没有运行中或已返回但结果尚未结算的回调；剩余反应全部为
   尚未进入的 queued 反应。普通 guest JSON 不能声明这个状态。
2. 仅上述不可逆终态发一次私有 quiescent 回执。实际根身份由已接纳的 native scope
   保存，插件不能挑选另一画面或另一根。已返回但等待其结果的回调不算 queued。
3. 主进程再次检查原 scope、原画面确已关闭、真实宿主调用 pending 为零、当前活动
   token 仍存在且没有失败释放。通过后将该 token 从前台任务改为可退休资源。
   它仍计入总占用；不是 drain、release，也不退还句柄或信用。
4. 明确重载沿现有 pauseIfIdle(false) 和实际资源关闭流程；自动应用继续使用全部
   size。实际 Guest dispose/物理退出与实际宿主 finally 才能完成释放。
5. 不支持借这份回执强制重载仍打开的健康画面，也不支持跳过仍在运行的宿主操作。
   新回调或 SDK 不可复活旧信号；晚来的已取消反应只做真实拒绝和收尾。

## 验证

- 实际永久 pending Promise：关画面后效果封闭，晚 SDK 为零；回执前仍是前台，
  回执后仍占总资源，真正 VM dispose 后才全部归零。
- 在执行的 SDK 忽略取消：即使关画面，host finally 之前也不降级，明确重载不放行。
- 同步未返回、正在运行的回调、已返回但结果未结算的回调、未关的画面均不降级。
- 主进程拒绝错误 scope、提前回执和重复回执；同名新画面不能替代旧画面身份。
- 自动配置不会因此提前应用；明确重载实际能退休旧 VM 并恢复新组件。
- 原正常回复、候选只读、跨插件按钮与 SDK、旧资源重载继续回归。

目前没有框架无法实现的证据。此项属于生命周期补全，不能用清空计数掩盖等待。
