# 插件的多项、文件与目录参数

这是明确重载之后继续执行的设计，尚未把计划写成已完成。

## 用户得到什么

在已有“插件参数”里增加可逐项添加、删除的文字列表，以及文件和目录选择。用户不用改插件代码或手写配置。保存之后继续使用当前的自动安全应用、明确重载和停止后明确重试；不会另建一套组合或运行按钮。

官方清单接受这三类参数，普通设置列表排除多项列表与敏感值，文件和目录仍是文字值。依据为[官方参数说明](https://code.claude.com/docs/en/plugins/manifest-reference#user-configuration)，以及已固定的 Claude Code 2.1.288 声明 1735–1905、7186–7200。敏感参数随下一阶段接入安全保存；不能因为本轮提供文件选择就声称它已完成。

## 保持一套实际参数基础

- 区分“普通设置行”与“原生作者参数表单”。普通行可以包含非敏感文件/目录，仍是 text；多项列表只出现在原生表单，不向 config.list 添加假 kind。敏感字段继续明确显示暂未支持。
- 保存器复用同一项目、插件身份与递增保存版本。数组逐项保持原值和顺序，不 trim、去重或按逗号/换行猜分隔符；一个含逗号或换行的值仍是一项。单值 string 的旧行为保持。
- multiple 仅允许 string；新表单的新保存要求数组，至多 256 项、单项 32768 字符及原总 UTF-8 容量。空数组合法；必填空串仍拒绝。固定 288 的 JK/q$e 及本工程原解析器允许 multiple 的默认与旧保存值为单个 string，optional unset 仍为 ""，这条加载兼容必须保留；不得拒绝、拆分或悄悄写回。草稿层可以将非空 scalar 显示为一项，并说明点击保存后才改为列表；空串显示未填写，实际 options 在明确保存之前不变。参数错误只指出字段，不输出其值。
- 文件/目录以作者原 type 展示，保存 string；选择路径不读取文件内容，不自动增加文件访问许可、工作目录或工具范围。实际 $.fs 调用仍由原文件授权处理。允许用户填路径，实际存在性由使用它的业务及原权限检查负责；不能因为对话项目变化去解析或访问旧路径。
- 每一次表单保存继续校验原项目、代码摘要、保存版本和窗口所有者。文件/目录参数在活跃实例中经过原 config.set 链与真实写入回执；列表没有普通设置行，使用原生参数保存器。这样不会把缺行误报为保存成功。

## 原生文件选择

增加只供原生表单使用的 IPC，不给插件 SDK 打开本机文件选择的能力。主进程只接受 threadId、pluginId、digest、workspace、revision 和字段 key，不接受 renderer 声称的 kind、标题、defaultPath 或路径列表。

先由宿主只读获取当前 schema 与原项目，确认字段实际是非敏感 file/directory。以原窗口为父窗口开启 Electron 原生选择器，单选。取消返回空结果，不保存或增加版本。选择器结束后重新核对原窗口、项目、源码摘要、保存版本、字段类型；路径经过原 host.publish 内容保护，再次检查原所有者和版本，只返回一个受保护的选择字符串给同一个表单草稿，不自动保存。保护拒绝、字段类型变化或原窗口丢失则拒绝旧结果。

表单对选择器使用独立操作序号，不能覆盖选择期间的新编辑；切插件/对话、关闭表单后丢弃迟到回执。保持原窗口已提交的保存 ACK 与刷新读 ACK 分开。多项草稿比较使用结构化数组，不能依赖 String(array)；后台刷新保留确实尚未保存的列表。

两位独立方案评审通过，以下实施条件固定：普通行资格与原生表单资格分别判断；非敏感 file/directory 必须显式成为 text 行；活跃普通字段遇到缺行、锁定、处理函数拒绝、假保存结果或保护失败不能转到直接保存器。数组直接保存仅针对实际 schema 的非敏感 string+multiple。每次手改、选择开始、关闭和重新打开都增长草稿序号，包括改后改回的情况；复验双选择倒序、广播刷新与选择/保存回执倒序、源码变化和同插件切项目。

## 验证和继续迭代

回归覆盖数组默认/持久化/顺序、scalar-array误用、边界及损坏存储；原 config.set 文件行真实保存、多项未泄漏到普通列表；必填启动前零 VM、重载采用实际数组、新任务获得新参数。IPC 验证实际 schema 固定、取消零写、选择过程中项目/版本/源码变化、原窗口失效、不能冒充 type。浏览器使用实际 React 验证增删项、逗号/换行、刷新保留、过期选择、窄屏样式。Electron 用实际插件验证 options；原生选择器的 OS 操作与受控 selector 回归分别记录，不能把受控返回当作操作系统实际点击已通过。

两位独立评审后开始实现；完成检视、回归、真实桌面测试及日志归档后直接进入敏感参数安全保存，再推进启动时模型调用与其它未对齐能力。当前没有发现这三类参数的框架限制。
