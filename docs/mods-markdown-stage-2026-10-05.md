# 模组里的富文本报告：本轮效果与验证

日期：2026-10-05。开发目录 `C:/ai/CmbCoworkAgent-mods-v2`，分支 `codex/mods-v2`。
本轮主机版本 v89。UAT 没有写入。

## 用户能感受到的变化

模组现在可以在自己的看板中显示标题、表格、列表、代码和链接。做事的模组负责报告
内容，另一个模组可以改变报告的展示；点击报告里的操作链接，仍由原模组执行操作。
这延续了上一轮“两个独立插件组合自己的 Claw”的用法。

工作目录内的文本文件可以从报告链接打开，只读预览展示经过内容保护的快照。关闭
看板、撤销许可或刷新页面后，旧链接和旧预览会失效，重新点击当前链接才能获得新预览。
显示报告和查看文件不会自动调用模型。

原聊天、普通按钮、原来的 Plugin 项目入口和 Harness 保持各自的使用流程。本轮是否
完成这些回检，以后面的实际测试记录为准。

本轮参考固定 Claude Code 2.1.289 的声明、提取代码及原版测试工具。原版 Markdown
15 项实际通过，不能据此宣称 DevClaw 与原版全部平台、全部功能一致。

## 作者怎么用

在已有模组界面中使用 `Markdown`，传入 `text`。需要点击处理时再提供唯一 `key` 和
`onLinkPress`；处理函数收到链接和点击事件。它不会因为组合了别的模组就获得对方的
权限。Client 组件可以显示 Markdown，交互使用原来的 pointer/state 方式。

需要改变另一个模组的 Markdown 展示时，在 `ui.resolve` 取得 `next(e)` 返回的组件
函数，再包装其中的 `Markdown`。保持原链接块的身份，实际点击由原作者处理。
组合安装、选择、保存和应用的步骤见
[双插件使用说明](mods-ui-resolve-usage-2026-10-05.md)。本轮增加了可执行入口，旧
Function Mods 需要批准当前版本；单独保存草稿不会改变正在使用的对话。

## 使用边界与继续方向

桌面链接以最终实际画出的安全地址为准；原版可接受列表中未画出的地址与本工程
桌面行为存在明确差别。工作区文件预览有路径、权限和大小限制，图片不会借显示报告
自行发起下载。本轮局部性能数据不代表模型、系统绘制或整机速度。

下一阶段继续打通“模组向实际会话保存补充信息”：隐藏补充信息供下一次自然模型
请求读取，系统通知保存但不发给模型，重启和历史分支恢复保持内容。当前相关基础
已实现并有真实数据库及图运行测试，**尚未接成用户可用的完整功能**，详见
[会话写入方案](mods-session-append-design-2026-10-05.md)。没有新的框架无法实现结论，
整体对齐继续。
