# Trace 上报接口开发指南

本次服务端改造只涉及 App 的 Trace 上报接口：接收 **7 个新增顶层字段**，完成校验并写入 ES。本文包含接口字段、DTO 改动、校验、入库、mapping 和接口验收要求。

## 1. 修改范围

沿用现有 `/api/traces/upload` → JSON 文件解析 → DTO → 转换器 → ES 写入链路。先搜索 `/api/traces/upload`、`unique_id`、`totalToolCalls`、`totalModelCalls`、`modelCallCount` 和 `_raw`，定位实际文件。

需要修改请求 DTO、ES 文档、字段转换/校验、写入逻辑及 mapping/template。本文 AgentTraceDTO、TraceEsDocument 是职责名称，按现有项目的实际类名修改。

接口地址、请求方式、表单结构、响应格式、鉴权、文件大小限制以及旧字段校验保持不变。

## 2. 接口与字段

接口保持不变：

```http
POST /api/traces/upload
Content-Type: multipart/form-data; boundary=客户端生成
```

| 表单字段 | 类型 | 内容 |
| --- | --- | --- |
| unique_id | string | 当前格式 `{YYYYMMDD}-{traceId}`，沿用既有幂等规则 |
| file | JSON 文件 | 文件名 `trace-{traceId}.json`，内容为 AgentTrace JSON |

**七个新字段全部位于 file 内的 JSON 顶层，不是表单参数，也不改成 application/json 请求体。** 成功状态码、响应体、鉴权和大小限制保持原样。

### 2.1 工具统计组：4 个顶层字段

| JSON 字段 | 请求 JSON 类型 | ES 类型 | 语义 |
| --- | --- | --- | --- |
| toolUsageSchemaVersion | 整数 | integer | 当前支持版本 1 |
| toolUsageComplete | 布尔 | boolean | 当前 Trace 的每工具计数是否完整 |
| toolUsage | 对象数组 | nested | 每种工具一个对象 |
| toolUsage[].name | 字符串 | keyword | 工具名，大小写敏感 |
| toolUsage[].count | 非负整数 | long | 此 Trace 内该工具调用次数 |
| userInputRequestCount | 非负整数 | long | request_user_input 调用次数 |

顶层字段为 toolUsageSchemaVersion、toolUsageComplete、toolUsage、userInputRequestCount。name/count 是数组元素的字段，不是额外顶层字段。

### 2.2 阶段统计组：3 个顶层字段

| 字段 | JSON 类型 | ES 类型 | 含义 |
| --- | --- | --- | --- |
| stageUsageSchemaVersion | 整数 | integer | 当前版本 1 |
| stageUsageComplete | boolean | boolean | 已记录总量是否完整划分到阶段桶，包括未归因桶 |
| stageUsage | 对象数组 | nested | 同一阶段名称和状态合并成一项，最多 64 项 |
| stageUsage[].nodeName | 可选字符串 | keyword，ignore_above=1024 | 阶段名称，缺失表示未归因 |
| stageUsage[].nodeStatus | 可选字符串 | keyword，ignore_above=256 | 调用开始时阶段状态，未知则省略 |
| stageUsage[].toolCalls | 非负整数 | long | 工具调用次数 |
| stageUsage[].modelCalls | 非负整数 | long | 模型调用次数 |
| stageUsage[].inputTokens | 非负整数 | long | 已采集输入 Token |
| stageUsage[].outputTokens | 非负整数 | long | 已采集输出 Token |
| stageUsage[].totalTokens | 非负整数 | long | 已采集总 Token，使用客户端原值 |
| stageUsage[].userInputRequests | 非负整数 | long | request_user_input 调用次数 |
| stageUsage[].tokenUsageReportedCalls | 非负整数 | long | 同时上报输入和输出 Token 的模型调用数 |

**stageUsageComplete=true 表示已记录总量完整划分到阶段桶，包括未归因桶；不代表所有阶段已识别，也不代表供应商返回了完整 Token。**

- 阶段无法识别：使用无 nodeName 的桶，保留全部计数。不能补成 Trace 的开始阶段，也不存固定字符串“未归因”。
- Token 未完整返回：保留模型次数，只汇总已有 Token，tokenUsageReportedCalls 小于 modelCalls。
- 采集遗漏、容量超限或总量无法核对：stageUsageComplete=false，按第 4.3 节保留或降级该组字段。
- 非项目 Trace 不要求产生阶段统计组。缺失不能填成 version=1、complete=true。

以下是字段片段，HTTP 测试时合并到已有合法 Trace，不要当作完整请求。客户端原字段 totalModelCalls 继续按服务端原规则映射为 modelCallCount。

```json
  "stageUsageComplete": true,
  "stageUsage": [
    {
      "nodeName": "plan-方案设计",
      "nodeStatus": "进行中",
```

### 2.4 零值、缺失和不完整数据

| 情况 | 正确处理 |
| --- | --- |
| 老客户端七个字段均缺失 | 七个字段全部省略，旧字段正常入库 |
| 零调用的新项目 Trace | 两个版本均为 1，两个 complete 均为 true，两个数组均为 []，请求输入及原有各总量为 0 |
| toolUsageComplete=false，合法部分工具数组 | 保留数组和 false，省略 userInputRequestCount |
| stageUsageComplete=false，合法部分阶段数组 | 保留合法数组和 false，不补齐缺失计数 |
| 只有工具统计组，没有阶段统计组 | 工具组按规则处理，阶段组保持缺失，不自行生成阶段分配 |

序列化必须保留合法的 **0、false、[]**，缺失字段省略。ES 文档使用 Integer、Boolean、Long、List；不要使用 Java 基本类型默认值、NON_DEFAULT 或会吞掉空数组的 NON_EMPTY。

## 3. 入库约束

- 字段值由 App 采集。相同工具调用多次要保留原次数；一次 request_user_input 调用计 1 次，不能按问题数量重算。
- stageUsage 是当前 Trace 按调用开始阶段划分的计数。保留 App 上报的阶段，不用 Trace 的 harnessNodeName 覆盖它；harnessNodeName/harnessNodeStatus 自身仍保持原值。
- 每条 Trace 只存自身数据。主、子 Agent 的 Trace 分别入库，不把子 Trace 开销加进父 Trace。
- 不因 outcome 为错误或取消而清零。缺失阶段名称、缺失 Token 用量按字段和校验规则处理，不推算或补填。
- 不遍历 steps/nodes/modelCalls 重算新字段，不按耗时分摊 Token，不重复加缓存 Token。保留 totalToolCalls、modelCallCount、输入/输出/总 Token、rootTraceId、parentTraceId、项目与组织字段的现有处理。

## 4. 解析、校验与降级

### 4.1 DTO 与转换器

如果接口直接把文件反序列化到强类型 DTO，新增字段使用 Long/Boolean 可能在类型错误时让整个反序列化失败。因此建议：**请求 DTO 的七个新增字段先接收为 Jackson JsonNode，单独归一化，再赋给 ES 文档的强类型字段。** 原有字段类型和校验不变。

请求 DTO 新字段示意（不要把这七个字段也用 Java 基本类型接收）：

```java
// 在现有上传 DTO 中增加；沿用项目现有 getters/setters/Lombok 风格。
@JsonProperty("toolUsageSchemaVersion")
private JsonNode toolUsageSchemaVersion;
@JsonProperty("toolUsageComplete")
private JsonNode toolUsageComplete;
@JsonProperty("toolUsage")
private JsonNode toolUsage;
@JsonProperty("userInputRequestCount")
private JsonNode userInputRequestCount;
@JsonProperty("stageUsageSchemaVersion")
private JsonNode stageUsageSchemaVersion;
@JsonProperty("stageUsageComplete")
private JsonNode stageUsageComplete;
@JsonProperty("stageUsage")
private JsonNode stageUsage;
```

ES 文档新增字段示意：

```java
// 只赋归一化结果。使用现有序列化机制保留 false / 0 / []，省略 null。
private Integer toolUsageSchemaVersion;
private Boolean toolUsageComplete;
private List<ToolUsageItem> toolUsage;
private Long userInputRequestCount;
private Integer stageUsageSchemaVersion;
private Boolean stageUsageComplete;
private List<StageUsageItem> stageUsage;

// 单独的 POJO 或静态内部类；沿用现有 getters/setters 风格。
// ToolUsageItem：String name; Long count;
// StageUsageItem：String nodeName; String nodeStatus;
// Long toolCalls, modelCalls, inputTokens, outputTokens, totalTokens,
//      userInputRequests, tokenUsageReportedCalls;
```

这里请求 DTO 与 ES 文档字段同名但类型不同，**不能继续用 BeanUtils/copyProperties/MapStruct 自动透传这七个字段**。在自动映射中排除它们，然后显式写入归一化结果。若项目自动根据 ES 文档注解建 mapping，必须同步把 toolUsage 和 stageUsage 都标成 Nested，不能让 List 默认变为 Object。

若现有解析器已经读成 JSON 树，可直接从现有树取得七个字段，复用一次解析；不要为了统计字段重复解析或深拷贝整份大 Trace。toolUsage 最多 256 项，stageUsage 最多 64 项。

不要开启全局“字符串转数字”等宽松转换。新增字段必须严格区分数字 0、字符串 "0"、null、缺失。

**处理顺序固定：先归一化工具统计组，再归一化阶段统计组。** 阶段完整性依赖校验后的工具统计与请求输入标量：工具组不可信时，不能保留 stageUsageComplete=true。反过来，阶段组错误不能破坏合法的工具统计。两组错误都不能拒绝原本合法的旧 Trace。

只将本文声明字段显式映射到 ES 嵌套对象，不透传数组元素中的未知属性，以免触发 dynamic:strict。

### 4.2 工具统计校验

本节的“四个字段”仅指工具统计组；version/complete 分别指 toolUsageSchemaVersion/toolUsageComplete。对版本 1：

1. complete 必须是 JSON boolean。数组必须是 JSON array，长度最多 256。
2. 每项必须是对象；name 匹配 `^[A-Za-z0-9_-]{1,128}$`，大小写敏感，不能 trim、转小写或截断后再当原名。
3. name 在数组中唯一。重复项不相加修复，而是判为不可信统计。
4. count 必须是 JSON 整数、非负、能装入 Java Long。拒绝 "2"、2.5、负数、null；完整统计累加使用 Math.addExact，溢出按校验失败处理；不完整统计只校验每个 count，不求总和。
5. complete=true 时，必须具有合法的原始 totalToolCalls，且所有 count 之和等于它。
6. complete=true 时，必须显式具有合法的 userInputRequestCount，且等于 request_user_input 对应 count；未出现该工具时应显式为 0。不要替客户端推算缺失标量。
7. complete=false 时允许合法的部分数组，但 userInputRequestCount 不写入 ES，即使请求中带了该字段也不当成完整值。
8. 工具名 `__invalid_tool_name__` 是客户端对异常名称的归并桶，属于合法名称，不再特殊删除。

#### 工具统计降级表

| 输入 | 新字段入库行为 | 原有 Trace 入库 |
| --- | --- | --- |
| 四个字段均缺失/null | 四个字段全部省略 | 按原逻辑处理 |
| version=1，完整且全部校验通过 | 写四个字段，保留合法 0/false/[] | 按原逻辑处理 |
| version=1，complete=false，数组合法 | 写 version=1、complete=false、部分数组；省略请求输入次数 | 按原逻辑处理 |
| version=1，字段缺失/类型错误/校验失败 | 仅写 version=1、complete=false；省略数组和请求输入次数 | 不因新增字段异常拒绝整条 Trace |
| 未知版本（例如 2） | 若版本是合法 32 位 integer，保留版本号；complete=false，省略其余新字段 | 按原逻辑处理 |
| 版本缺失/错误，但携带其它新字段 | 省略版本号，complete=false；省略其余新字段 | 按原逻辑处理 |

以上只容忍“新增统计字段不可信”。非法 JSON、原有必填字段缺失、鉴权失败、超大文件等，继续沿用原有错误处理，不能一律返回成功。

校验失败日志只记录 traceId、版本和固定原因码，如 INVALID_TOOL_USAGE / TOOL_USAGE_TOTAL_MISMATCH / USER_INPUT_COUNT_MISMATCH，不打印完整用户对话或整份上传 JSON。

#### 工具统计归一化伪代码

```text
normalizeToolUsage(request):
  if 四个新增字段都缺失或 null:
    return 空字段集合

  if version 不是 JSON integer 或不是 1:
    return {合法 32 位 integer 版本号（若有）, toolUsageComplete: false}

  if complete 不是 JSON boolean 或 toolUsage 数组结构校验失败:
    return {toolUsageSchemaVersion: 1, toolUsageComplete: false}

  checkedUsage = 按 name 唯一、count 非负 long 校验后的列表

  if complete == false:
    return {toolUsageSchemaVersion: 1, toolUsageComplete: false, toolUsage: checkedUsage}

  if totalToolCalls 非法、求和溢出、sum(count) != totalToolCalls:
    return {toolUsageSchemaVersion: 1, toolUsageComplete: false}

  expectedInputCount = request_user_input 对应 count，没有该工具则为 0
  if userInputRequestCount 缺失、非法或不等于 expectedInputCount:
    return {toolUsageSchemaVersion: 1, toolUsageComplete: false}

  return {toolUsageSchemaVersion: 1, toolUsageComplete: true,
          toolUsage: checkedUsage, userInputRequestCount: 请求中的值}
```

**不要用 `getOrDefault(..., 0)` 或 Java 基本类型默认值完成以上逻辑。**

### 4.3 阶段统计校验

本节的“三个字段”仅指阶段统计组；version/complete 分别指 stageUsageSchemaVersion/stageUsageComplete。版本 1 的数组校验：

1. stageUsageComplete 必须是 JSON boolean；stageUsage 必须为数组，最多 64 项。
2. 每项必须是对象。只将本文定义字段放进 ES 嵌套对象，不透传任意属性。
3. nodeName 缺失或 null 表示未归因，归一化后省略；若为字符串则长度 1–1024，不得为空白。不要截断、改大小写或擅自合并阶段。
4. nodeStatus 缺失或 null 时省略；若存在必须是长度 1–256 的非空白字符串，且 nodeName 必须存在。
5. `(nodeName 或缺失, nodeStatus 或缺失)` 必须唯一。重复桶判为不可信，不自行相加修复。
6. 七个计数字段必须显式存在，为非负 JSON 整数，能装入 Long。拒绝字符串、小数、布尔、null。不能用 Java 基本类型缺省为零。
7. 每桶 userInputRequests ≤ toolCalls，tokenUsageReportedCalls ≤ modelCalls。
8. modelCalls=0 的桶，其三个 Token 值及 tokenUsageReportedCalls 必须为 0。
9. stageUsageComplete=true 时，以 Math.addExact 求各指标之和；溢出或不相等即降级：

| 桶字段合计 | 必须等于上传 JSON 原始字段 |
| --- | --- |
| toolCalls | totalToolCalls |
| modelCalls | totalModelCalls |
| inputTokens | totalInputTokens |
| outputTokens | totalOutputTokens |
| totalTokens | totalTokens |
| userInputRequests | 经过工具统计组校验的 userInputRequestCount |

以上原始总量必须明确存在且合法。不能先把缺失字段补成 0 再核对。完整阶段统计还要求工具统计组是支持的 version=1、complete=true，保证请求输入总量有可信依据。

不要额外强制 inputTokens + outputTokens = totalTokens，也不要把 cacheReadTokens 再加进去。这里验证的是与原有总量守恒，而不是重定义供应商计费口径。

| 输入情况 | 三个阶段字段入库结果 |
| --- | --- |
| 三个字段都缺失/null | 全部省略，老客户端正常入库 |
| version=1、complete=true、校验及守恒通过 | 保留三个字段 |
| version=1、complete=false、数组结构及单桶校验合法 | 保留版本、false、合法部分数组；不做完整总量校验 |
| version=1，其余校验不通过 | 只写 version=1、complete=false，省略数组 |
| 未知但合法 32 位整数版本 | 保留版本、complete=false，省略数组 |
| 版本缺失或类型错误，但带其它阶段字段 | 只写 complete=false |

旧必填字段非法仍执行原有接口错误处理。只容忍新统计错误，不放宽鉴权/文件大小/旧数据校验。异常日志仅记录 traceId 和固定原因码，不输出完整对话。

## 5. ES 写入与重复上传

七个字段写入 ES 文档顶层，不能只留在 `_raw`。`_raw` 沿用原始 Trace 的保存方式，不用删掉新字段的临时 DTO 覆盖原文。

沿用现有稳定文档 ID 的整文档替换逻辑。若使用 partial update/upsert：

1. 从目标文档清除七个旧统计字段。
2. 写入本次归一化结果中存在的字段。
3. 两步必须在**同一次原子文档更新**内完成，工具组和阶段组不能拆成两次 ES 请求。

完整快照被部分、非法或旧版快照替换后，不能残留旧数组、版本、请求输入标量或 complete=true。重传是快照替换，禁止 count += incomingCount、追加数组或创建新的统计文档。保持既有身份隔离，用测试证明同一 unique_id 重传不会使文档数或次数翻倍。

## 6. 生产 ES mapping 与模板

实际索引从服务端配置读取。下面 devclaw_trace 仅为示例，先检查实际 mapping：

```http
GET /devclaw_trace/_mapping
```

确认字段尚不存在或类型兼容后，对实际索引执行 `PUT /devclaw_trace/_mapping`，请求体如下。它与附件 `es-tool-usage-mapping.json` 完全一致：

```json
{
  "properties": {
    "toolUsageSchemaVersion": {
      "type": "integer"
    },
    "toolUsageComplete": {
      "type": "boolean"
    },
    "toolUsage": {
      "type": "nested",
      "dynamic": "strict",
      "properties": {
        "name": {
          "type": "keyword",
          "ignore_above": 128
        },
        "count": {
          "type": "long"
        }
      }
    },
    "userInputRequestCount": {
      "type": "long"
    },
    "stageUsageSchemaVersion": {
      "type": "integer"
    },
    "stageUsageComplete": {
      "type": "boolean"
    },
    "stageUsage": {
      "type": "nested",
      "dynamic": "strict",
      "properties": {
        "nodeName": {
          "type": "keyword",
          "ignore_above": 1024

        "nodeStatus": {
          "type": "keyword",
          "ignore_above": 256
        },

          "type": "long"
```

- 已有 object 不能覆盖成 nested；应提交新索引与 alias 切换方案，不删除旧索引。
- 确认实际写入索引及 alias；同步滚动索引的 index template，不能只改当日索引。
- 模板更新保留原 settings、aliases 和其它 properties，不能用增量片段覆盖整份模板。
- 不将 dynamic:strict 改成 dynamic:true，不为历史文档默认补 0，不要求历史回填。

## 7. 接口验收

附件提供 55 组字段校验样例：`tool-usage-server-test-cases.json` 29 组、`stage-usage-server-test-cases.json` 26 组。

- 单元测试直接使用 input，不补齐缺失字段。
- HTTP 测试先移除现有合法旧版 Trace fixture 中的七个新字段，再合并 input；原有必填字段仍需有效。
- 标记 normalizationUnitTestOnly 的样例只测试字段校验函数。例如 totalToolCalls 缺失时，HTTP 仍执行原有必填校验，不保证上传成功。
- newStatisticsMustNotRejectOtherwiseValidTrace 表示新字段异常不能拒绝原本合法的 Trace。
- 工具样例的 expectedIndexedNewFields / expectedAbsentNewFields 只检查工具组；阶段样例的 expectedIndexedStageFields / expectedAbsentStageFields 只检查阶段组。阶段测试先完成工具组校验。

| 上传场景 | 必须断言 |

## 9. 阶段缓存用量接口扩展（兼容 schemaVersion=1）

`stageUsage` 每个桶新增两个**可选**字段，原有阶段字段和 `stageUsageSchemaVersion=1` 不变：

| 字段 | 类型 | 含义 |
|---|---|---|
| `cacheReadTokens` | 非负整数 / ES long | 此阶段所有已上报调用的缓存读取 Token 之和，包含超过 512 次明细上限的调用 |
| `cacheUsageReportedCalls` | 非负整数 / ES long | 此阶段明确上报缓存用量的模型调用次数，上报 0 也算一次 |

客户端按模型调用开始时的阶段实时累加，缓存读取属于输入 Token 的一部分，不再加进输入或总 Token。主、子 Agent 分别上报自己的数据。供应商未提供缓存用量的调用，不增加这两个字段；缺字段不能视为已测得 0。

服务端要求：

1. `TraceEsDocument.StageUsageItem` 接收并保留这两个可选字段。历史记录缺字段时省略，原有工具、模型、Token 和阶段完整性判断不变。
2. 两字段必须同时是非负整数，且 `cacheUsageReportedCalls <= modelCalls`。报告次数为 0 时，缓存读取必须为 0。字段缺失、类型错误、越界或不符合规则时，仅省略缓存字段，不丢弃已有阶段统计。
3. 阶段组完整且原始顶层 `cacheReadTokens` 为非负整数时，校验已提供的阶段缓存之和。出现不守恒或求和溢出，只清除阶段缓存字段，不改变 `stageUsageComplete` 或原有阶段 Token。历史阶段数组完全没有缓存字段时不做此校验。
4. 顶层缓存字段优先读取客户端累计值（包括有效的 0），缺失时按旧版 `modelCalls` 明细求和；详见 `trace-server-token-fix.md`。

部署：先应用 `研发阶段算力效能-ES-mapping-增量.json` 到实际 Trace 索引，再部署服务端，最后发布 App。文件保留原有 nested 阶段字段定义，只新增两个阶段缓存字段；顶层 `cacheReadTokens` 如已存在则不变。

验证：新旧 App 上报均能写入；缓存零值保留；1000 次调用的阶段缓存不被 512 条明细截断；缓存异常不会使原有阶段统计降级；写入 ES 的阶段数组保留新字段。
