# 外部代码采纳率上报 —— 对接方接口文档

> 适用对象：在 DevClaw 之外、对「不在 git 仓库内」的代码生成自行统计采纳率的外部系统（如标签开发、数据开发等，可有多个，互不假定）。
> 本文档自包含：仅凭本文即可完成对接，无需阅读 DevClaw 源码。

## 1. 背景与你要做的事

DevClaw 的运营面板按「代码生成 → 采纳 → 已推送」统计 AI 代码采纳率。正常链路依赖 git commit/push 触发测量；你们的代码不在 git 仓库里，触发不了，所以由**你们自己上报**两类事件：

- `code_gen`：每发生一次代码生成时上报（在你们的生成动作完成后）。
- `code_adopt`：代码**上线/发布**时上报，并标记为已推送，携带本次生成中最终被采纳的行数。

你只需把这两类事件 `POST` 到下面的接口，面板会自动把你们的数据纳入对应口径，无需任何面板侧改造。

## 2. 接口

| 项 | 值 |
|---|---|
| 方法 | `POST` |
| URL | `{BASE}/api/traces/external-code-events`（`{BASE}` 由我方提供） |
| Header | `Content-Type: application/json`<br>`X-Devclaw-Source-Token: <我方为你方分配的令牌>` |
| Body | 单条事件对象，或事件对象数组（最多 200 条/批） |
| 成功 | HTTP `200`，响应体见 §8 |

> 令牌仅用于鉴权（认证你方身份）；上报来源由请求体的 `source` 字段**由你方指定**，且同一令牌只能上报其被授权的 `source`（防冒充）。令牌请妥善保管、不要硬编码进可公开的代码库。

## 3. 字段总览

### 3.1 通用 / 身份字段（两类事件都要带）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `eventType` | string | 是 | `"code_gen"` 或 `"code_adopt"` |
| `source` | string | 是 | **你方系统标识，由你方指定**（如 `"tag-platform"`、`"data-platform"`）。面板据此区分上报来源；同一令牌只能上报其被授权的 `source`（见 §2） |
| `clientEventId` | string | 是 | **你方生成的全局唯一 ID**，用于幂等（同 ID 重发不重复计数）。建议 UUID |
| `sapId` | string | 是 | 开发者工号。面板的「用户维度」「数据权限」都靠它 |
| `userName` | string | 是 | 开发者显示名 |
| `ystId` | string | 建议 | 部分权限维度使用 |
| `pathName` | string | 建议 | 开发者组织全路径，用 `/` 分隔（见 §6）。面板的组织层级维度由它派生；缺省则组织维度为空 |
| `orgName` | string | 可选 | 组织名 |
| `harnessProjectId` | string | 建议 | DevClaw 项目稳定 ID，把事件归属到对应 DevClaw 项目。**hook 场景**：直接读 `HARNESS_PROJECT_ID` 环境变量 / stdin `harness_project_id` 即得（仅当该会话绑定了 DevClaw 项目时有值；非项目会话该 env 缺省）。**带上**它，事件才进入「项目运营概览」并可被其 source 筛选；**缺省**则只进「平台运营概览」（采纳率/漏斗仍正确，只是不在项目维度下出现）。`code_gen` / `code_adopt` 两类都建议带，且应取同一会话的同一值 |
| `harnessFeatureSlug` | string | 建议 | DevClaw 项目下的**特性 slug**，把事件再归到具体特性。**hook 场景**：读 `FEATURE_ID` 环境变量 / stdin `feature_id`（与 `HARNESS_PROJECT_ID` 同来源，会话绑定了特性时有值）。**带上**它，项目列表里**展开的特性行**才会计入你们的采纳率（生成量 / 提交·总量口径 / 入库，与项目级同口径）；**缺省**则只汇总到项目级、不分特性。应与 `harnessProjectId` 配套（同一会话、同一对值） |
| `harnessAdapterName` | string | 可选 | 会话绑定项目的**适配器（插件）名**。**hook 场景**：读 `HARNESS_ADAPTER_NAME` 环境变量 / stdin `harness_adapter_name`。带上后你们的采纳会进入面板的**按适配器切片**（适配器行 / 适配器占比）；缺省则不计入适配器维度（项目/特性等其它维度不受影响） |
| `harnessAdapterVersion` | string | 可选 | 适配器**版本**，与 `harnessAdapterName` 配套（面板按 名→版本 两级切片）。**hook 场景**：读 `HARNESS_ADAPTER_VERSION` 环境变量 / stdin `harness_adapter_version` |

### 3.2 `code_gen` 专有字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `lineCount` | int | 是 | 本次生成内容的**归一化非空行数**（算法见 §5）。面板「生成量」来源 |
| `generatedAt` | string | 是 | 生成时刻，ISO8601 **带时区偏移**，如 `2026-06-22T10:30:15.123+08:00` |
| `language` | string | 建议 | 语言，如 `"java"` |
| `usedSkills` | string[] | 可选 | 用到的技能标识数组。**格式 `<技能名>-v<版本>`**：连字符分隔、版本带 `v` 前缀（如 `tag-codegen-v1.0.0`；无版本用 `v1.0.0`）。**注意不是 `@`**。填了才有「技能维度采纳率」 |
| `tool` | string | 可选 | 如 `"write_file"` / `"edit_file"` |
| `modelName` | string | 可选 | 生成所用模型名，填了才有「模型维度」 |
| `relativeHint` | string | 可选 | **仅叶子文件名**（如 `Tag.java`）。**不要上报全路径/文件内容**。前向兼容字段，当前对外部数据无可见效果（见 §12）；不影响采纳率 |
| `threadId` | string | 可选 | 你方会话/任务 ID。**只随 `code_gen` 带即可，`code_adopt` 不必再带**（我方口径里 adopt 的 threadId 本就等于其配对 gen 的值）。**hook 场景**：直接读 `SESSION_ID` 环境变量 / stdin `session_id` 即得（二者就是 threadId）。前向兼容，当前对外部无可见效果（见 §12） |

### 3.3 `code_adopt` 专有字段（代码上线/发布时上报）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `genClientEventId` | string | 是 | 指向对应 `code_gen` 的 `clientEventId`，建立生成↔采纳关联 |
| `generatedLineCount` | int | 是 | 该次生成的归一化行数（**应等于**配对 `code_gen` 的 `lineCount`） |
| `adoptedLineCount` | int | 是 | 这些生成行中**最终被采纳/保留**的归一化行数（你方自测，`0 ≤ adopted ≤ generated`） |
| `generatedAt` | string | 是 | **原始生成时刻**（≈ 配对 `code_gen.generatedAt`）。⚠️ 见 §4，**不要填上线时间** |
| `pushed` | boolean | 是 | 上线即视为已推送，固定 `true` |
| `pushedAt` | string | 是 | 上线时刻 ISO8601 带时区偏移 |
| `effectiveGeneratedLineCount` | int | 可选 | 一般省略；省略时我方按 `= generatedLineCount` 处理 |
| `usedSkills` | string[] | 可选 | 同 §3.2 |
| `modelName` | string | 可选 | 同 §3.2 |

> 你**不需要**上报 `eventId / eventCategory / schemaVersion / source / userIp / upperOrgLv* / verdict / measureSource / commitSha / measuredAt`——这些由我方接收端自动补全或派生。

## 4. ⚠️ 时间字段最易错点

面板把 `code_adopt` 按 **`generatedAt`（原始生成时间）** 归入时间桶，用于和对应 `code_gen` 配对计算采纳率。

- ✅ `code_adopt.generatedAt` = 这段代码**最初生成**的时间（和 `code_gen.generatedAt` 一致）。
- ✅ `code_adopt.pushedAt` = 代码**上线/发布**的时间。
- ❌ 不要把 `generatedAt` 填成上线时间，否则采纳会落到错误的时间区间，面板里对不上生成量。

## 5. 行数归一化算法（务必照此实现）

为保证你方行数与 DevClaw 其他人群口径可比，`lineCount` / `generatedLineCount` / `adoptedLineCount` 都用下面的「归一化非空行数」：

```
normalizeLine(line):
    s = line.trim()                 # 去首尾空白
    s = s.replace(/\s+/g, " ")      # 连续空白(含 Tab)折叠成单个空格
    return s

countNormalizedLines(text):
    count = 0
    for raw in text.split(/\r?\n/): # 按换行切分
        if length(normalizeLine(raw)) > 0:   # 跳过空行/纯空白行
            count += 1
    return count
```

示例：

```
输入文本（3 个物理行，中间是纯空白行）：
"  int  a = 1;\n   \n\tb=2;"

逐行归一化：
  "  int  a = 1;" -> "int a = 1;"   (计)
  "   "           -> ""             (跳过)
  "\tb=2;"        -> "b=2;"         (计)

countNormalizedLines = 2
```

`adoptedLineCount` 同口径：对「最终采纳产物」按相同归一化后，统计其中确实来自本次生成内容的行数（具体采纳判定逻辑由你方决定）。

## 6. `pathName` 与组织维度

`pathName` 形如：`招商银行/信息技术部/XX团队/XX组`（组织路径，一般不含个人名），用 `/` 分隔。我方接收端从中派生面板用的组织层级（`upperOrgLv0..3`）。**只要 `pathName` 里包含「信息技术部」节点即可正确派生**；不含或缺省时，组织维度为空（其余统计不受影响）。

## 9. 幂等与重试

- **幂等键 = `clientEventId`**：同一 `clientEventId` 重复上报不会被重复计数，可安全重试。
- 网络失败建议指数退避重试（如 0s / 3s / 15s / 60s）。
- `code_adopt` 的 `genClientEventId` 必须指向一个你方真实上报过（或将会上报）的 `code_gen.clientEventId`。

## 10. 错误码

| HTTP | 含义 | 处理 |
|---|---|---|
| `200` | 已受理（可能部分拒绝，看响应体 `rejected`/`errors`） | 检查 `errors` 修正后重发被拒条目 |
| `400` | 整体请求格式错误（非 JSON / 超批量上限等） | 修正后重试 |
| `401` | 令牌缺失或无效 | 检查 `X-Devclaw-Source-Token` |
| `5xx` | 服务端异常 | 退避重试 |

## 11. 上报时机小结

| 时机 | 上报 |
|---|---|
| 一次代码生成完成 | 一条 `code_gen`（`generatedAt` = 此刻） |
| 代码上线/发布 | 对该次生成涉及的每个 `code_gen`，各发一条 `code_adopt`（`pushed=true`，`generatedAt` 回填为原始生成时间，`pushedAt` = 上线时刻） |

## 12. 不适用 / 降级说明（已知）

- **项目 / 特性 / 适配器维度可用**：与 `traceId` 不同，DevClaw hook **会**暴露 `HARNESS_PROJECT_ID`、`FEATURE_ID`、`HARNESS_ADAPTER_NAME`、`HARNESS_ADAPTER_VERSION` 环境变量（仅当会话绑定了 DevClaw 项目时）。带上 `harnessProjectId` → 进「项目运营概览 → 生产效能代码指标」**汇总口径**并可被 **source 下拉**筛选；再带 `harnessFeatureSlug` → 项目列表**展开的特性行**按特性切片；再带 `harnessAdapterName`/`harnessAdapterVersion` → 进**按适配器切片**（适配器行/占比）。这些都只到**聚合级**——下面的 commit 逐条下钻仍不含你们（见下条）。
- **逐行溯源**：面板对 git 提交可逐行回看采纳明细；你方数据无此底座，仅到行数计数级。
- **commit 维度**：你方无 git 提交，`commitSha` 为空 → 面板的「按 commit 下钻 / commit 链接 / commit 数」不含你们这群人。
- **技能 / 模型维度**：仅在你上报了 `usedSkills` / `modelName` 时才有。
- **文件 / trace**：我方 `code_gen` 本身就**不报文件全路径/内容**（隐私），只可选带一个叶子文件名 `relativeHint`；`traceId` 看板采纳口径**完全不使用**，无需上报——且 DevClaw hook 目前**不向脚本暴露 `traceId`**（`HookContext`/env/payload 均无），外部 hook 也取不到。如将来要做「采纳 ↔ trace」关联，需我方先把 `traceId` 注入 hook（`TRACE_ID` 环境变量 + payload `trace_id`）再纳入上报。
- **`relativeHint` / `threadId` 当前不展示你们的数据**：面板里读这两个字段的逐条钻取（commit 采纳明细 / 未提交明细 / commit 汇总）入口都按 `commitSha` 或「无采纳」筛选——你们 `commitSha` 为空且已有采纳，正好两头都不命中。所以这两个字段对外部数据**当前无可见效果**，仅作前向兼容保留；核心采纳率/漏斗/技能/组织维度不受影响。（面板取值口径：`relativeHint` 取自 `code_gen`；`threadId` 现取自 `code_adopt`，但其值就是配对 `code_gen` 的拷贝，故你们**只在 `code_gen` 带 `threadId` 即可，`code_adopt` 不必再带**——将来若让外部数据也展示，面板从配对 `code_gen` 取 threadId 即可。）

## 13. 删除接口（联调 / 测试数据清理）

联调阶段的误报或测试数据，可调用本接口删除**你方自己上报**的事件。

| 项 | 值 |
|---|---|
| 方法 / URL | `POST {BASE}/api/traces/external-code-events/delete` |
| Header | `Content-Type: application/json`、`X-Devclaw-Source-Token: <你方令牌>` |
| Body | JSON，见下 |

### 入参

| 字段 | 必填 | 说明 |
|---|---|---|
| `source` | 是 | 你方系统标识。**只能删该 source 的数据**，且必须是你令牌被授权的 source（防删到别家） |
| `from` / `to` | 见下\* | 按**上报时间**（我方接收时刻）范围删，ISO8601 带时区偏移 |
| `clientEventIds` | 见下\* | 精确删：你上报时用的 `clientEventId` 数组（≤ 1000） |
| `eventType` | 可选 | 限定 `code_gen` 或 `code_adopt`；不填两类都删 |

\* **`from`/`to` 与 `clientEventIds` 至少提供其一**——不允许只给 `source` 全量删除（防误删）。

### 安全
- 令牌只能删它**被授权 source** 的数据；删别的 source 一律拒绝。
- 删除始终按 `source` 强制过滤，绝不会动到其它来源或我方自身数据。

### 响应
```json
{ "deleted": 12 }
```

### 示例

按时间窗删：
```json
{
  "source": "tag-platform",
  "from": "2026-06-23T00:00:00.000+08:00",
  "to":   "2026-06-23T23:59:59.999+08:00",
  "eventType": "code_gen"
}
```

精确删若干条：
```json
{
  "source": "tag-platform",
  "clientEventIds": ["5f8e2a10-3b6c-4d2e-9a1f-7c0b9d4e2f11", "9b2d77c4-1e5a-4f33-8c0d-2a6b1e9f4d80"]
}
```

### 错误码
`401` 令牌无效；`403` `source` 不在令牌授权范围；`400` 既无 `from/to` 也无 `clientEventIds`（缺范围）；`5xx` 服务端异常。
