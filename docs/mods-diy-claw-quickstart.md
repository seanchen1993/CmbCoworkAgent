# DIY Claw：先用现成流程，再按需添加组件

入口核对日期：2026 年 10 月 7 日。本文按当前开发分支的实际界面说明操作；
主要操作链路已完成桌面验收，最新安装包和操作截图见[主版本使用说明](mods-main-version-delivery-2026-10-07.md)。
完整范围和后续工作见[当前能力与后续工作](mods-official-features-and-roadmap-plain-2026-10-03.md)。

## 不上传插件，先跑一次检视

1. 打开普通本地会话，关联真实项目目录，并配置可用模型。
2. 进入「自定义 → Function Mods」，开启「启用 Mods 功能（应用级）」和「启用项目 Mods」。
   确认「作用目录」是本次项目。当前没有管理口令或解锁步骤，也不需要先安装空插件。
3. 进入「自定义 → DIY 流程」，展开「Autobiz 实际项目预设」，选择「Autobiz · 只检视」。
4. 核对目标；在 Agent 步骤选择角色和已配置模型，也可沿用默认模型。点击「保存流程」，
   再点击「运行已保存版本」。
5. 在「运行与历史」看实际步骤、发现和汇报。等待人工确认时核对结果，选择
   「同意并继续」或「拒绝并停止」。

这些预设由应用运行，不要求安装 Autobiz 插件、配置 Feature 或准备其 Python 工具。
名称中的 Autobiz 不表示会自动推进业务阶段。检视仍使用真实模型与项目工具；涉及操作审批时
按原提示确认。也可以从「新建代码检视流程」开始，自行增减步骤。

## 三个预设怎么选

| 预设 | 实际效果 |
| --- | --- |
| Autobiz · 只检视 | 只读检视真实仓库，汇报发现，等待人工确认；不执行项目测试。 |
| Autobiz · 检视与测试 | 检视后运行真实单元测试，再汇报并确认；测试失败即停止。 |
| Autobiz · 修复与复检 | 检视、测试；仅失败时修改实现并复测，最多两次修复。初次测试通过会跳过修复。 |

真实测试需要项目已有受支持的测试脚本或运行器；应用不会为这个流程自动安装依赖。
检视意见、模型声称通过和真实测试回执是不同结果。没有执行测试时，汇报应明确写未执行。
流程可组合 Agent、Skill、MCP、真实检查和人工确认；MCP 需配置可用服务及工具。

如果希望“先开发，再检视和测试”，从「Autobiz · 修复与复检」开始，添加一个
「Agent 任务」，名称设为「实现需求」，在「步骤目标」写明本次开发要求，再用
「上移步骤」把它放到最前面。为实现和检视步骤分别选择已有模型，保存后运行。
这样同一流程会依次执行开发、检视、真实测试，失败时才进入修复和复测，最后汇报。
这就是自己调整助手的做事方式，不需要先制作插件。要让自制组件在发送前或完成时
自动参与，再按后面的组件安装和应用方式设置。

## 保存、应用和执行有什么区别

| 操作 | 何时生效 |
| --- | --- |
| DIY 流程「保存流程」 | 保存步骤和版本，不启动任务。随后可在本页「运行已保存版本」。 |
| 我的 Claw「保存能力组合」 | 保存模型、流程、组件等选择，不改变当前对话。 |
| 我的 Claw「应用到当前对话」→「确认应用」 | 当前对话后续使用这个版本，不发送任务。 |
| 聊天「执行流程」后发送目标 | 执行已应用组合中的流程。 |
| 普通聊天 | 按普通对话工作；不会自动启动整条流程。已选组件只在其支持的环节参与。 |

要从聊天复用流程：进入「我的 Claw」，选择已保存流程，点「保存能力组合」，
再点「应用到当前对话」并「确认应用」。回到聊天切换到「执行流程」，发送本次目标。
执行流程目前只接收文字目标；带附件、技能或浏览器选择时会保留草稿并提示切回普通聊天。
修改流程后，已应用的对话保留原版本。要使用新版，先在「我的 Claw → 组合的显式流程」
重新选择该流程的新版，再点「保存能力组合」并应用到当前对话；只重新保存组合不会更新其中的流程副本。

DIY 组合当前用于普通本地会话。协调模式沿用项目 Mods 设置，不把协调子任务当作普通对话；
这些子任务暂不支持 `session.append` 会话追加接口。组件是否执行取决于它声明的触发环节。

## 引用文件、排队和追加要求

在聊天输入框输入 `@`，选择项目里的文本文件；也可以同时上传附件。发送时会检查文件权限，
读取可用正文并遵守附件额度。文件不存在、类型不支持或正文超限时，核对界面提示再继续。
关闭 Mods 后仍可按普通附件方式发送；尚未读取的 `@文件` 引用使用实际发送时的最新正文，
已经上传的附件保留上传时的内容。

任务忙时，输入新消息并发送会加入队列，通常在当前任务结束后按顺序发送。要让当前任务接收
这条要求，在对应卡片点「追加到本轮」；「正在追加…」表示还在提交，「已追加」表示已接纳。
当前任务会在后续生成回复前接收它，不会改写已经生成的回复。自动目标运行时先暂停目标。

点「停止生成」会取消当前前台任务，包括正在准备的文件输入。尚未接纳的队列消息仍是草稿，
可编辑或删除；刷新后会恢复队列。模型不可用时草稿不会因此丢失，恢复可用配置后会自动发送，
如需修改请先在队列卡片点「编辑消息」，保存后再恢复模型。刷新会重新检查发送条件，不能用刷新
代替停止。协调模式的后台子任务需使用单独的后台停止入口。

## 什么时候需要插件组件

要先实际体验，可直接导入[主版本附带的三份示例](mods-main-version-delivery-2026-10-07.md)：
看板加样式演示跨插件组合，检视包演示部分组件、依赖和默认模型。
主版本说明附了三个 ZIP、源码和操作截图；只检视给定文本的模型意见不代表项目测试通过。

需要发送前检查、自动选择模型、完成前给出意见或自定义面板时，可以添加作者提供的组件。
在 Function Mods 安装完整 ZIP 或文件夹，检查声明的能力与版本摘要并授权，再到
「我的 Claw」选择组件、设置参数、保存并应用。

作者必须明确导出可独立选择的组件；应用不会把任意旧插件自动拆成检视、测试和汇报组件。
没有组件声明的旧包按整包选择。勾选组件不代表它每轮都会执行：命令需要调用，
事件组件在对应环节触发，完成检查还需配置项目规则。当前内置上下文计量也不等于自动质量检查。
组合方式见[使用与迁移说明](mods-devclaw-continuity-delivery-2026-10-03.md)，
自动测试与修复规则见[项目完成检查规则](mods-v2-application-completion-rules.md)。

## 停用或运行不了时

- 仅停止当前流程：在运行记录取消。关闭页面不会自动取消，已修改文件或远端操作不保证回滚。
- 恢复当前对话原配置：在「我的 Claw」点「恢复原配置」，核对预览后「确认应用」。
- 停用 Mods：关闭项目开关；应用级关闭影响所有项目。不要把关闭面板当作关闭规则。
- 卸载插件：在 Function Mods 已安装列表卸载整个来源。安装和卸载不要求开启 Mods；
  已保存组合可能留下不可用引用，需检查并重新应用。
- 模型或流程不可用：核对当前项目、应用和项目开关、模型配置及测试脚本。插件步骤还要核对授权。
  普通聊天不会因为一个流程不可用而自动执行它的替代流程。
