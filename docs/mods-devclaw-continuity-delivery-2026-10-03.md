开发位置：`C:\ai\CmbCoworkAgent-mods-v2`，分支 `codex/mods-v2`。本轮未修改 UAT，也未提交或推送代码。

**这轮的主要变化是：Claw 应用到对话后，组件能随着普通工作自动参与，不必把每件事都改成一个固定流程。** 固定流程仍然保留，适合明确要求按“开发 → 检视 → 测试 → 汇报”执行的任务。

官方依据固定为 Claude Code 2.1.288，沿用已核验的安装包、可读说明和原版验证记录。本工程继续采用桌面操作和自己的模型配置；不承诺任意官方模组都能原样运行。[官方事件说明](https://code.claude.com/docs/en/plugins/mods/events)、[制作模组](https://code.claude.com/docs/en/plugins/mods/create)、[官方接口说明](https://code.claude.com/docs/en/plugins/mods/api)。

## 1. 对使用者来说，新增了什么

| 你要做的事 | 现在得到的效果 | 范围说明 |
| --- | --- | --- |
| 普通聊天发送一句任务 | 已应用组件可以先检查、改写任务或补充背景，再交给助手 | 这轮接入普通纯文字输入。原有文件、图片和所选技能保留原路径 |
| 任务没说清楚，组件要求补充 | 该次输入不会交给主助手运行，也不会留下已接受的用户消息；界面显示原因 | 第一条被拒绝时，对话仍保持为空，工作模式仍可选择；组件自身单独分析属于另一项调用 |
| 任务执行中追加一句要求 | 追加要求经过组件处理后，送给当前正在运行的任务 | 改写后的正文与实际保存、实际入队内容一致；不能送进已结束的旧任务 |
| 让子助手按工作情况选择模型 | 在已接入助手中，每次模型请求都能经过组件的选择规则 | 实际调用所选服务；同名模型配置不会被混为一个。规则必须由组件提供 |
| 组件单独请模型做分析、分类或利用现有对话继续分析 | 这些小任务分别采用自己的工作规则 | 不把某次分析的内容误用在另一并行分析，也不改变主对话的模型设置 |
| 导入官方组件 | 检查页说明哪些规则能参与、何时参与，以及哪些暂时不能用 | 只检查登记的事件，不能把“检查通过”当作整个包已经实际运行验证 |

关闭 Mods 后，本次已经打开的已完成命令结果仍可只读查看，显示原生保护后的正文；运行中的命令、插件交互和取消按钮不会保留。该显示不发起新的插件读取；关闭后重新打开应用不会自动恢复这份临时显示。

这不意味着上传一个空插件就会自动检视代码。自动检视、自动挑模型等具体规则，仍然需要组件真正提供。

## 2. 在 DevClaw 中怎么用

### 自动参与普通工作

1. 在 Mods 中导入组件，查看其作用与使用范围，批准需要使用的能力。
2. 打开对话右侧的 Claw 工作台，加入需要的组件，设置组件选项和可使用的模型。
3. 保存组合，再确认应用到当前对话。保存的是模板，应用后当前对话才开始使用这一版本。
4. 照常发送任务，例如“检查 Autobiz 看板刷新问题，修复后执行测试”。组件在它声明的时机自动参与。
5. 查看该组件提供的状态或执行记录，确认实际发生了什么。仅仅勾选组件，不代表它在这次任务一定触发。

自动规则不要求每次发送 `/my-claw`。组件如果另外提供自己的命令，命令仍通过原有入口使用。组件若没有提供检视规则，上面的任务也不会因为“加入了 Claw”就凭空新增一道检视。

### 固定顺序执行

需要每次都按相同顺序工作时，在 Claw 中选择或编辑流程，为各步骤指定组件和模型；保存、应用后，使用“执行流程”入口发送目标。

“运行一次”执行选中的流程；它不等于以后所有普通聊天都自动跑完整流程。普通聊天与流程执行使用同一组合中的可用组件，触发方式各有明确含义。

## 3. 原有用法怎么迁移

| 原来的用法 | 在 DevClaw 中的使用方式 | 需要改什么 |
| --- | --- | --- |
| 原 Plugin 项目模式，用原项目入口和命令 | 继续照常使用 | 不必为了升级改写插件 |
| 官方模组自动参与发送、工具调用或每次工作 | 导入并批准，加入 Claw，应用到对话后自动参与 | 优先保留原事件和写法；依赖未支持功能的地方需要单独适配 |
| 官方模组提供一个命令 | 继续通过命令入口调用 | 不必为了能调用命令强行做成流程 |
| 多个插件共同组成一套工作方法 | 在 Claw 中选择不同插件的可用组件，按需要设置模型 | 插件要声明可供选择的组件；没有组件列表的旧插件仍可继续原用法 |
| 有明确步骤顺序的任务 | 用 DIY 流程组合步骤 | 顺序、失败后处理和完成条件由流程明确表达 |

以 Autobiz 为例：只想使用以前的看板功能，可以继续原项目方式；想让每次普通任务都先检查描述、在子助手检视时选择检视模型，需应用提供这些规则的组件；想每次严格执行开发、检视和测试，则使用固定流程。三种用途不要求把历史功能全部重写。

模型在本工程的设置中配置，组件选择的是允许使用的已配置模型。不要把 Claude 的账号信息或服务密钥写进组件。判断选了哪个模型，以实际调用记录为依据，不能只看界面名称。

## 4. 给组件作者的变化

保留原来的“在哪个时机参与，怎样继续下一步”写法。普通发送处理现在直接接入真实输入：继续下一步才会接受任务；直接拒绝或没有继续下一步，不会偷偷发送。

发送处理可以改写用户正文，也可以额外提供只给模型看的背景。正文在界面和保存记录中一致；额外背景不会混进可见气泡。一次输入即使重复继续，也只接受一次；已经接受后，外层返回另一个正文或拒绝结果，不能倒改已经发生的事实。

每次模型工作中的组件也可以使用已有的会话、日志和独立模型分析能力。受支持的子助手采用自己的身份与模型，不借用主助手。模组派出的助手在逐次模型和工具调用链中只跳过创建它的那一个处理规则，其他已批准规则仍可参与。

第一次运行时读取项目内配置仍然可用，但发送前准备仅允许已授权的只读访问；不能借准备阶段执行工具或写文件；它也不拥有执行中主助手的全部能力。准备过程使用独立的临时身份，不会终止原主助手或替换原会话。关闭、撤销批准、替换版本或结束任务后，旧异步调用不能继续生效。

作者接口、参数限制及逐项证据见[实现契约](mods-devclaw-continuity-contract-2026-10-03.md)和[完整功能对照](mods-v2-compatibility-matrix.json)。

## 5. 仍未完全对齐的地方

- 项目规范文件的完整读取过程、任务中的所有临时提醒和附件，还不能全部交给模组调整。
- 带图片、文件、所选技能的输入，插件代发、IM、远端发送、Goal 控制和自动续跑、内部通知、流程启动及助手间消息，没有通过本轮新接入的文字发送处理；它们保留原有路径。插件主动代发的接口也没有因此变成可用。
- 任意自定义助手、终端专属显示、声音，以及部分高级界面、设置和模型选项仍有边界。
- 安装检查只确认登记的事件及可用范围，尚不是所有接口、依赖及真实效果的完整检查。
- 常用内置组件和制作引导仍需补充。目前更容易组合和执行，不能承诺只说一句需求就自动生成任何可靠组件。

这些差距不要求老用户改变发消息的方法。带文件、图片或所选技能的任务，以及其他原有入口，仍按以前的方法执行；本轮的边界是新增的发送前处理尚未覆盖它们，不能把“这一项规则未接入”误解成“原功能不能使用”。组件是否参与，仍以它支持的触发时机和实际记录为准。

下一步优先补项目规范读取与临时材料，再扩大常见输入范围，同时提供可直接试用的检视、测试和模型选择示例。不会为了对齐而取消本工程原有授权与完成条件。

## 6. 验证记录

本轮方案和流式调用修复均经过两位独立评审。真实桌面端已通过普通发送、拒绝、恢复后隐藏背景、执行中追加要求、三类独立分析、子助手逐次切换真实服务、官方事件检查以及新旧模型返回方式等验证。

最终连续桌面回归 236 项通过，Autobiz、组合、流程、原入口和组件共存的实际测试 47 项通过，页面交互检查 57 项通过，原有功能的 9 组独立测试通过。类型检查、普通构建和性能回检通过；构建中已移除测试专用入口。检视中发现的中断原助手、丢失子助手部分回复、重复回复及关闭后丢失已打开历史结果问题已修复，并完成回归。

全仓单元测试有 5,852 项通过、5 项跳过，仍有与既有基线完全一致的 11 项失败，没有新增失败，也没有未处理的运行异常。失败来自原有 macOS 打开 IDE 测试、浏览器扩展测试所需文件缺失，以及原有固定颜色样式检查。全仓代码检查仍有 100 个既有错误，没有新增错误；不能把这些结果写成“全仓全部通过”。

测试详情和限制以 `output/mods-devclaw-continuity-final-report.json` 的最终结果为准；其中分别记录本轮定向检查、原有功能回检、性能测试和全仓已知失败，不把有失败的全仓测试写成全部通过。本文不等同于已打包发布或全部官方能力对齐。
