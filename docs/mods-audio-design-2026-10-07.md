## 实现合同

1. 用现有组件运行时、权限、操作处理链和资源清理接入两个声音接口。
   组件自己的文件、授权 URL、明确 MIME 的 base64 都是输入方式。
2. 文件仅取当前组件已批准来源内的资源。不能使用路径声明跳到项目或用户目录。
   URL 沿用 HTTP 的地址与逐次跳转授权规则；现有 HTTP 正文是文字接口，
   不将它转码后的文字冒充音频。二进制读取需要独立、有限的实际字节路径。
3. 播放支持增益、单次和带停止信号的循环；不同声音可以同时播放。
   朗读用系统合成器，支持默认或明确安装的语音；朗读之间排队。
4. 朗读文字沿用内容保护。播放和朗读都绑定实际会话、组件版本及取消状态；
   卸载、撤权、重载和退出时清理当前资源，迟到回执不能操作新实例。
5. 成功来自实际后端结束或合法停止，坏格式、无语音、无可用界面等诚实返回原因。
   已开始的声音不能假装可回滚；处理函数可以阻止新操作，但不能伪造已经播放的事实。
6. 默认不为没有调用声音能力的组件创建播放器或增加模型、网络请求。
   原 Plugin、项目、Harness、IM、Goal 的运行方法和开关保留。

## 先落地独立后端：明确文件和边界

先只实现 `src/main/mods/v2/audio-backend.ts`、`audio-renderer.ts` 及对应专项测试。
这一步不修改 Session、Manager、Guest 或界面入口，不能据此将声音能力标记为已接通。
后续公共接口顺序接线，避免与 MCP 阶段同时修改相同文件。

后端仅由 Main 使用，接收已经批准的实际字节或已经内容保护的朗读文字，
以及原调用的 `signal` 和 `assertLive`。它不接收文件路径、URL、插件自报身份、
grant 或凭据，不自行读取或下载内容，也不建立新的授权记录。
接口返回实际任务句柄 `{ started, done, stop }`，内部异步建立窗口和启动。
`started` 只在后端确认真正开始后完成；`done` 等实际自然结束或停止清理后完成。
所有 Promise 从创建时就保留拒绝观察，不产生未处理拒绝。

窗口按首次调用惰性创建，独立临时 session、隐藏、sandbox、contextIsolation，
没有 Node、preload、插件脚本或业务网页。拒绝权限、网络、导航、弹窗和外部下载。
执行的 renderer 代码为本工程固定来源；输入仅作为 JSON 数据传入。
未使用声音的会话不增加窗口、连接或模型请求。窗口崩溃或销毁时正在运行和排队的
任务诚实失败，不复播；退出清理全部资源，旧窗口的迟到结果不能影响新实例。

播放使用真正的 WebAudio AudioBufferSource 和 GainNode，增益允许 0 到 4，
单次等待 `ended`，循环保持运行直到停止；各任务节点独立，可同时播放。
严格限制单个输入和任务数量：单 clip 编码字节上限 4 MiB、活动播放 8 个、
总编码驻留 16 MiB、排队朗读 32 个、文本 4096 字符。解码后单 clip 时长不超过
120 秒，活动解码内容合计不超过 64 MiB。解码器位于独立 sandbox 后端，解码失败
或进程崩溃诚实失败，不假定编码字节上限等于解码内存上限。
启动和清理采用有限期限，不能扩大原 SDK 总预算。

`stop()` 幂等，必须涵盖尚未创建窗口、尚未解码以及已经播放的任务。
停用后不能迟到启动；返回须等待节点停止、断开及该任务缓存释放的真实确认。
局部主动停止可以完成 `done`；原父 signal 取消仍在清理后拒绝，不能写成自然结束。
崩溃无法获得 ACK 时报告清理失败，不能返回假成功；Main 生命周期仍销毁自身窗口。
没有活动播放或朗读时及时销毁隐藏窗口，避免改变原应用的窗口退出判断；
后续调用可以创建新后端，已关闭的服务实例不能复活。

朗读由 Main 队列每次只下发一个 utterance。只用本机已安装且 localService 为真的
默认或明确名称语音；空语音、不存在或远端语音诚实失败。必须观察真实开始与结束，
之后才返回 `{ via: "system" }`。取消排队项只移除该项；停止当前朗读仅取消独占
后端自己的合成器，其他项继续按队列执行，不能取消用户业务页面的朗读。

两位独立方案评审通过后再开发。专项单元测试检查同步句柄、排队、取消、启动竞态、
窗口崩溃和清理失败；实际 Electron 专项检查真实增益节点、并行、循环停止、
系统朗读队列及取消。不能用 stub 的 ended 代替实际后端验收。

## 后端之后的组件接线合同草稿

本段尚待两位独立评审，当前不修改 MCP 作者占用的公共文件。

组件通过原动态 SDK 使用 `$.audio.play(clip, options)` 和 `$.audio.speak(text, options)`。
它们走原处理链、当前组件身份、授权、内容保护和真实模块资源清理。
声音不要求打开聊天页面，合法后台及定时任务沿原 fresh resource activity 调度。
不能绕原任务资格、取消或项目范围，也不为音频另造页面授权层。

`clip` 只允许自己的相对资源、HTTP/HTTPS URL、带明确音频 MIME 的 base64 三选一。
内联解码字节最多 512 KiB，保留原 1 MiB JSON 协议限额。资源文件最多 4 MiB，
沿 loader 原记录检查已批准编译根的 device/inode，使用原 resolveModFile 及
stable file handle 完成有界读取和读后检查；不要求整个包可以配置重用，
不扫描全部源码，不读工作区、绝对路径或跳出组件根的链接。

URL 需要真实有界字节读取。原 FunctionHttpHost 文字接口保持行为和现有上限，
内部扩展复用同一地址、逐跳授权、取消、压缩与解压字节限制；不把 UTF-8 正文转回
音频，不让隐藏 renderer 下载，也不自动增加凭据。HTTP 字节上限仍沿原 256 KiB。
HTTP 和资源读取之后、实际播放之前再次检查原调用资格；失败不启动声音。
朗读文字在实际下发前经原发布内容保护，保护后不是有效文字就拒绝，不读模型凭据。

播放允许真实增益和循环，循环必须有组件自己的有效停止 signal。
Guest 的局部停止不能沿现 cancelCall 的立即拒绝当作已经停止：为本次调用分配
原资源序号，局部 abort 请求模块侧停止自己的句柄，原播放 Promise 等 Main 实际
清理确认后才完成。父任务取消、重载及撤权仍通过原模块资源拒绝并清理。
停止早于启动时保留有界取消状态，不能迟到开播；完成后的确认释放索引，
清理失败不能吞掉。句柄始终是原真实 FunctionPlugin 资源的索引，不授予权限。

处理组件可改写允许字段或拒绝新操作，但不能把资源文件改成别的插件所属资产。
朗读的成功 `{via:"system"}` 来自实际开始与结束。播放无返回正文；不能通过
伪造回执替代平台播放验证。所有等待保留原 SDK 总预算，不为了长声音延长任务期限。

预计接点：新增共享音频 validator 和 Main 资源读取叶，原 source-adoption-fence
增加 root-only 检查，http-sdk 内部字节路径，以及 Guest/Session/Manager 的窄接线。
公共事件目录和使用说明在真实 SDK 验证通过后注明能力范围。
实际验收需组件导入批准后播放 asset、base64、授权 URL 和系统朗读，
观察改写、拒绝、循环局部停止、父取消、撤权、重载、后台、零额外模型请求。
两位方案及实现评审、边界回归、真实桌面验证均独立于前面的后端实验。
