# 现在可以自定义哪些内容

适用于开发分支的桌面 Mods，当前宿主契约为 v96。应用版本仍为 2.0.0；需要运行包含当前代码的应用，旧安装包不会自动具备新能力。固定对照 Claude Code 2.1.316，不代表与其所有宿主和内部生命周期完全等价。

## 普通用户怎么改

在创造者模式中描述效果即可。已有插件先派生为自己的草稿；在对话中要求调整，检查预览、试用当前版本，满意后保存。页面里的阶段编辑用于直接精确改正文，与对话修改同一个草稿，不要求重复操作。

可以直接说：

- “创建一个资料整理插件：先澄清目标，再列清单，最后检查交付。每阶段都等我确认。”
- “从这个插件派生一份，保留资料读取和检查，去掉发布阶段。”
- “把第二阶段提示词改为：先列风险，再给两个方案；没有证据的内容标待核实。”
- “增加一个侧栏检查清单，按钮打开详细页面；关闭页面后仍回到原聊天。”
- “用我配置的 MCP 服务查询资料，让一个子助手独立检查，结果回到当前聊天。”

调整阶段、提示词、验收条件和能力引用后，先试用这份新版本，再保存。原项目模式仍从插件导入 ZIP，并沿原有创建、配置、需求管理和执行页面启动；本轮没有另造项目入口。项目业务规则由插件定义。

新建项目时，“项目描述”用一句简短用途概括（最多100字），项目编号最多15字；完整测试需求写在进入项目后创建的特性（Feature）中。工作区根目录选择实际存在的文件夹，产物文件夹填该目录下的新文件夹名；确认路径已显示后再创建项目。

## 开放范围

| 用户想改什么 | 已开放的通用机制 | 实际边界 |
| --- | --- | --- |
| 项目阶段与阶段提示词 | 创建、派生及再次派生；增删、替换、排序阶段；提示词、输入输出、验收条件和依赖组合 | 生成声明和插件内容，仍由原项目模式执行；平台不内置 AutoBiz 业务阶段 |
| 助手工作方法 | 技能、命令、工具、提示词组成、上下文规范、文字提醒、工具前后处理及完成检查 | 沿原模型、工作目录和权限执行，不能靠 Hook 伪造审批、文件写入或完成结果 |
| 聊天显示与交互 | 原聊天位置的包装与重排、独立 Pane、临时 Placed 卡片、按钮、输入、选择、Markdown、代码、SVG 和受限 Client | 真实原控件和权限身份保留；插件不能注入任意 DOM、全局 CSS 或 Node 页面脚本 |
| 页面及入口 | 公共 capability/surface 声明，组合 page/navigation/sidebar/toolbar/settings 位置及打开/关闭动作 | 使用已有通用宿主与组件，不替换存量项目模式，不承诺任意应用主窗口布局 |
| 输入框体验 | 读/填文字、建议、编辑 Hook、文字高亮与虚拟提示、复制和选择；按来源清理 | 需要当前聊天实际输入框及对应权限；文字装饰不改变真实草稿、光标或发送内容 |
| MCP | 当前组合已选择的宿管 stdio、Streamable HTTP、SSE 来源；独立连接、真实调用、状态与断开 | 插件拿来源 ID 和不透明连接句柄；URL、命令、认证由宿主配置。不能传任意凭据或自动重放工具 |
| 子助手 | 注册/启动 owned 子助手，约束模型、工具和范围；状态、分页消息、结果和停止 | 仅所属子任务；默认只读查看，用户动作显式打开 interactive 后才向该活跃子任务输入，界面明确标注发送目标 |
| 文件与持久状态 | 工作目录内受权限控制的读写/列举、Markdown 祖先规范；插件 store、命名 state 及版本条件写入 | 不自动取得全盘权限；瞬时局部变量和卡片不当作持久项目状态 |
| 代码导航和诊断 | 查询当前原生 Java 服务的定义、引用、悬停、实现、符号、调用关系和诊断 | 复用已运行服务，不自动安装或启动；诊断缓存版本未知，空结果不能证明当前文件无错误 |
| 文件预览与定位 | 打开当前工作区的安全源文本、实际定位到行列；预览内可请求已配置的外部 IDE | 不执行 HTML 脚本；外部只能确认启动请求，不能证明已显示。Windows 空白或特殊路径保留内置预览 |
| 文件变化面板 | 订阅现有工作区观察器的真实路径变化、失效与重新读取提示 | 不启动第二套监听或扫描；目录未被观察时如实不可用，upsert不冒充新增/修改分类 |
| 参数与依赖 | 用户配置表单、敏感值处理、依赖归组、汇总确认与授权、公开 config 查询与修改 | 新源码或新增权限需对当前版本确认；插件不能修改只能由本机设置控制的策略 |
| 模型与执行 | 已配置模型调用、分类、分叉；本机 process.run/spawn、受策略控制的 HTTP、定时任务 | 原模型预算、网络/命令权限和取消清理保留；插件不能绕过主机策略或拿模型密钥 |
| 进程环境 | literal 声明的 env.set/get；本插件会话内覆盖、删除，并进入之后的 process.run/spawn | 不改 Electron 全局环境、其他插件或模型工具环境；危险变量拒绝，重载清空覆盖 |
| 提醒与诊断 | toast/status/log、工具说明、原生问答、显式桌面系统通知；本地有界 telemetry 及 Hook 消费 | ui.notify 的桌面通道为明确扩展；OS show 不证明用户已看见；诊断不上传 Anthropic 或企业 collector |
| 加载策略与生命周期 | 模块加入链前的 `plugin.register`；真实本地桌面 attach/detach；owned workflow 工作树回收观察 | 只由此前准入模块审候选；同包同步登记代码仍求值，不提供同包内存隔离。工作树观察仅能读取、记本地状态和日志，不接管删除或启动写入任务 |
| 通用扩展协议 | engine.create、公共版本化 capability、查询/订阅/动作/取消/状态和受限交互页面 | 宿主核验提供者、来源、目标和双方权限；复杂业务接口、算法、企业流程仍由插件开发者实现 |

功能开关、参数和权限集中沿已有设置入口管理。桌面通知开关位于组合设置的“插件桌面通知”，关闭会收回已有通知；插件不能自行重新开启该策略。

“开发者工作台”通用示例把代码、文件预览、变化订阅、可配置检查命令和任务输出放在同一套可组合页面中。检查命令沿原进程权限执行，不用输出里的“PASS”代替真实退出回执。配置保存后重载可读回；关闭页面清观察订阅，后台任务按实际任务记录核对，未知结果不自动重跑。v95及更早的确认不会自动取得v96新增能力，当前版本需重新核对一次。

当前正式桌面验收已验证该示例的真实源码定位、文件变化、显式Node版本检查与资源清理。示例可从ZIP安装，先选带工作目录的普通聊天，再从“自定义设置→基础功能→插件”上传；到设置分类“创造者模式→灵件→我已添加”开始使用。这里的设置分类不要求把普通聊天切换为创造者模式。真实结果及仍未验证的环境边界见[验收进度](mods-nonmedia-and-phase3-verification-2026-11-01.md)；最终性能尚未结束。

## 子会话输入与返回

插件可在真实用户操作中请求 `ui.view({agentId, mode:"interactive"})`。面板就绪并激活后，发送目标显示为子助手，父聊天暂停输入和发送并保留原草稿、附件；返回、关闭、任务结束或撤权后恢复父聊天。发送成功表示真实入队，不能解释为模型已处理完成。默认不指定 mode 仍是只读查看。

## 开发者怎样找到准确接口

创造者使用定向能力查询，按事件名或 SDK 方法名读取签名、约束与分页说明，例如 `prompt.paint`、`mcp.connect`、`ui.view`、`platform.action`。完整类型仅用于编译和按需查询，不在每轮对话灌入全部 SDK。发现接口或静态编译成功均不授予执行权限。

建议先以命令或按钮为启动入口，在 `session.start` 只登记工具/命令。文件、网络、模型和长期任务放在生效后的用户动作中。创建与派生沿同一套机制；插件可以自行封装复杂实现，平台只负责公共流程和边界。

## 仍不能称为“上游全部完成”的部分

- 音频、图片、视频及媒体附件暂不纳入；`prompt.attachment` 是文字提醒接口，不等于媒体支持。
- Raster/`ui.blit`、ToolProgress 属于上游终端绘制面。当前桌面无该绘制面，不能假成功。桌面用受限 UI 元素、SVG 和 Client 实现适合的界面。
- 组织托管 `session.identity` 没有相应可信身份提供者；普通来源得到 deny，不公开本机登录令牌、组织资料或伪造 `isVerified`。`session.authorize` 无提供者时返回 null。
- `telemetry.log/mark` 当前以真实 Hook 和本地诊断适配，不提供 Anthropic 内部或企业 collector 的上游上传语义。用 `telemetry.records()` 查看自己的本地记录。
- 本地 desktop attach/detach 已接真实绑定，仍不代表 Remote Control 设备在线。`attribution.text` 没有已核实的“模型读取 Git 署名文本”生产者；不能拿自动提交字符串冒充。
- metadata-only 清单：PermissionDenied、PreModelSwitch、PostModelSwitch、PermissionRequest、TaskCreated、TaskCompleted、Elicitation、ElicitationResult、ConfigChange、WorktreeCreate、CwdChanged、FileChanged、DirectoryAdded、MessageDisplay；TeammateIdle 也不可用。WorktreeRemove 只开放上述有限观察。已有审批、模型选择及工作树创建流程，也不等于已接通上游的权限改写、cache/pricing 或路径接管契约；不会用普通 turn、待办、切页或消息快照代替这些语义。
- Button 的上游任意 keybinding action 与跨站点 hover group 等参数，只有存在明确本机实现才开放；未支持的参数应拒绝，不会静默表示生效。

因此，当前是**可组合的桌面通用能力集**，不是“除多模态外所有 Claude Code API 和内部生命周期完全等价”。本轮补齐和第三阶段的实际通过范围、未验证节点与性能结果另见验收记录。
