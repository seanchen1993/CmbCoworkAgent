# Design 局部补丁实现

实现日期：2026-10-23。方案见 [design-local-patch-proposal.md](./design-local-patch-proposal.md)。

## 实际链路

`Comment / Draw / 聊天 → patch 运行 → 宿主索引与上下文 → 模型结构化操作 → 完整候选校验 → SQLite 提交 → 文件投影 → 预览局部更新`。

- 参数面板与直接编辑仍在本地执行。
- 批注使用稳定节点身份及创建时的源码版本。绘制按路径采样多个节点，保留每个区域自己的说明；重复/重叠目标由宿主合并。
- 聊天局部改稿先提供精简目录，再通过受控补读确定目标。全局主题、重新设计等明确大范围请求走完整 Agent。
- 源码从主进程已提交会话读取，渲染进程不为 patch 请求携带整页 HTML。模型执行器不装载原 Agent checkpoint、工具历史或通用文件工具。

## 目标、HTML 与 CSS

`design-node-ids.ts` 用 parse5 建立源码节点身份，在预览中补入 `data-design-node`。现有稳定 ID 继续保留；旧页面的虚拟节点 ID 绑定版本，旧锚点不能猜测性地修改新版本。

`document-index.ts` 缓存自包含页面索引，解析 CSS 选择器、条件规则、变量依赖与字体/动画定义。工作目录中的外部 CSS/import 有深度、大小和路径边界；提交前重新核对依赖 hash。不可读样式保留为明确的未解析依赖。

`patch-context.ts` 提供目标子树、父级/兄弟摘要、相关样式、当前有效参数和可用资源目录。源码中的业务 script、内嵌 style 和事件处理器源码不直接进入目标 HTML 上下文。样式解析属于保守依赖提取，最终级联行为由 Chromium 检查。

上下文限制为 48,000 字符，并用离线估算约束整个请求（含系统提示、工具定义和修复反馈）不超过 12,000 tokens。估算仅用于路由，实际用量另行记录。不会从半截 HTML/CSS 中截断；过大任务扩大为完整改稿。

## 模型协议

优先绑定三个工具：`get_design_context`、`submit_design_patch`、`request_design_scope`。不支持工具调用的接口在明确的工具能力错误后退回严格 JSON 协议。两种形式使用同一个校验与应用入口。

支持 `set_text`、`set_style`、`set_attribute`、`replace_fragment`、`set_tweak`。流式工具参数全部接收、组装完毕后才解析；模型输出期间不会向正式文件写入半个补丁。

- 最多 25 个操作，最多两次有界补读、两轮修复。
- 子节点有独立 hash；目标范围与 contextId 由宿主核定。
- 文案只能直接修改叶子文本，避免删除按钮图标。
- 样式声明由 CSS AST 解析和验证。普通样式写入目标 inline 声明；状态/响应式样式由宿主生成精确节点选择器，保留同一节点已有补丁声明。
- 结构操作只替换目标内部内容，保留业务 ID、name、数据绑定及受脚本使用的 class；不允许新增脚本、事件属性或全局样式。
- 参数操作遵循原 schema 与绑定范围，不允许通过共享参数误改其他区域。

## 校验与提交

每个候选都检查协议、范围、hash、HTML 完整性、唯一 ID、Tweaks 和保护脚本。源码编辑按 AST 位置从后向前写回，目标之外的源片段保留原字节。

颜色等简单操作检查实际计算样式，能识别被 `!important` 或旧 inline 声明压住的修改。hover、focus-visible 在隐藏 Chromium 中强制对应伪类，disabled 通过临时禁用状态验证，结束后恢复。文案/布局操作对比当前宽度和移动宽度下的完整页面，检查新溢出与范围外的关键样式变化；结构替换另复用隐藏浏览器的运行和结构验证。校验时关闭动画/过渡以减少噪声，每批统一检查，并有取消和超时边界。

同一会话只运行一个修改任务，源码采用严格版本/hash CAS。提交前再次核对相关 Tweaks 和外部 CSS；无关参数可以继续保留，相关参数发生变化时拒绝陈旧补丁。

SQLite 同事务保存正式源码、参数、补丁 journal、运行状态与文件投影 outbox。正式文件在数据库提交后原子投影；文件写入失败不会丢掉数据库中的版本，启动、重新打开和资源包导出会重试投影。资源包使用已提交会话源码作为当前 HTML，避免导出旧投影。journal 保留最近 20 次局部事务。

撤销/重做检查当前源码和被修改参数，只恢复本次事务涉及的内容。原先未设置的参数 override 在撤销时恢复为“未设置”，不会冻结成旧默认值。后续直接修改源码会使旧补丁历史失效。

## 预览与失败行为

`design-live-patch.ts` 在正式预览里应用节点属性、文字和受控样式差量，保留节点、直接绑定的监听器、输入值、焦点和滚动。每次更新带预览实例、源码版本和 ACK。

异步资源准备完成前，预览继续使用旧内容及其对应版本；新内容和版本同时切换。漏 ACK 或基线不一致时从最新已提交内容重建预览，不重新调用模型。结构修改完成校验后加载一次新文档，使业务代码正常重新挂载。

模型失败、越界补丁、版本冲突或取消均保留当前正式页面及用户设置。需要全局上下文、新行为、过大依赖等情况明确显示扩大范围，并转现有完整 Agent。定位歧义和旧锚点则要求重新选择，避免误改同名元素。

环境变量 `DESIGN_LOCAL_PATCH=0` 可关闭局部执行器并恢复完整生成路径；默认启用。

## 验证与性能记录

- `npm run typecheck`
- `npm run build`
- `npm run test:design-sessions`：包括局部协议、上下文、CSS、事务和真实 React/Chromium 回归。
- `npm run test:design-html`：原完整 HTML、多方案、资源、业务脚本和编辑功能回归。

本机浏览器可通过 `CHROMIUM_EXECUTABLE_PATH` 指定。

每个 patch 运行保存模型调用数、输入/输出 tokens（接口提供时）、上下文字节数、补读与修复次数、校验耗时和完整路径回退原因。预览 ACK/加载完成另记录 `patchVisibleAt`，用于区分后端完成和用户真正看到修改的时间。`usageReported=false` 表示没有完整接口用量，不能将记录中的零值理解为免费调用。

测试使用确定性模型响应，另验证真实 LangChain 流式工具参数组装。没有调用在线模型，因此没有声称真实模型的 P50/P95 或固定加速倍数。任意业务脚本的所有行为无法由静态分析证明，无法保留契约的结构操作会转完整改稿或保留原页并报告失败。
