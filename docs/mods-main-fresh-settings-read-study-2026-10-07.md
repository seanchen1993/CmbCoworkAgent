# 主版本稳定：隔离比较设置文件的读取方式

本轮继续稳定已经交付的主版本，附加功能保持暂缓。
上一轮同包共享任务通过全部业务检查，但无额外采样时仍用时 39.015 秒。
采样发现读取设置文件占用了较多时间；这还不能证明换一种读取方式一定有收益。

## 先做实验，不改交付包

用同一个修复版 Windows 包启动真正的主进程，核对实际程序、资源文件及打包状态。
沿用已有隔离启动方法，用户目录、临时目录和应用数据都指向测试目录。
在另一个专用目录创建合成的设置文件，不读取用户设置、模型配置或凭据。

比较包内现有设置库的读取方法，以及直接读成文字或先读成字节再转为文字的方法。
设置库必须确实从当前包的 ASAR 内加载；指定独立目录与 `settings` 文件名，
并确认最终文件路径正是夹具文件，禁止回退到开发目录里的依赖。
也比较 Electron 提供的原始文件读取方法。每次都重新打开、读取并关闭文件，
不保留文件句柄，不缓存已开启的权限，不改变等待后的权限检查。

文件使用正常中文 JSON，约 1 KB 和 64 KB；只包含开关、序号和合成填充文字。
所有方法先做少量预热。每一种候选与现有方法分别按 ABBA 和 BAAB 顺序交替，
每组 250 次读取，记录实际次数、结果校验和耗时，以降低执行顺序带来的误差。
这里的次数指显式调用次数，不冒充底层系统调用次数。
统计的是每批平均读取耗时，不是精确计算时间或真实业务任务的耗时。

实验另行检查开启、关闭、同长度重写、原子替换、删除、损坏及非布尔开关值。
只有真正的布尔值 `true` 可以授权。设置库在文件缺失时可能返回空配置，
直接读取则可能抛错；这些差异必须保留记录，不能据此声称可以直接替换。
若错误被转为拒绝，也不能隐藏原始错误类型。
这些是顺序修改场景，不包含生产读取前后的文件指纹检查，不能证明读取中修改也安全。

## 检查与推进规则

两位独立 agent 先评审方案，再评审诊断脚本；脚本仅用于实验，不进入生产包。
分别运行两种文件大小，记录所加载的包内设置库、实际主进程和隔离目录。
实验前后核对程序和资源文件摘要，保留关闭结果，并核对自有进程退出。

只有实验显示稳定收益，且另行证明不会改变缺失、并发写入和撤权等语义后，
才提出最小业务改动。此实验不作为新增功能，也不提前宣称主任务已提速。
若没有明显收益，就保留结论，改用已有采样调查具体调用责任。

## 实际结果

两位独立方案及脚本评审通过后，已在同一生产包中完成实验，实际退出为零。
两种大小分别记录 32 批、8,000 次计时调用，另有各方法 25 次预热。
每种大小的 12 个顺序语义场景均通过；缺失和损坏时各方法的原始错误差异保留。
包内实际设置库路径、主进程和隔离目录都有记录，程序和资源摘要与上一轮完全相同。
关闭完成；随后一次系统进程快照按两次运行的实际进程和隔离目录核对，
均没有发现对应进程或当前子进程残留。

下表为四批平均值的中位数，单位是毫秒；每种候选都有自己交替执行的现有方法对照。

| 文件大小 | 候选读取方式 | 现有方法 | 候选方法 |
| --- | --- | ---: | ---: |
| 1 KB | 直接读文字 | 0.1977 | 0.1950 |
| 1 KB | 读字节后转文字 | 0.2071 | 0.2186 |
| 1 KB | 原始文件接口读文字 | 0.1976 | 0.1948 |
| 1 KB | 原始文件接口读字节 | 0.1950 | 0.2045 |
| 64 KB | 直接读文字 | 0.4746 | 0.4689 |
| 64 KB | 读字节后转文字 | 0.4779 | 0.4787 |
| 64 KB | 原始文件接口读文字 | 0.4799 | 0.4803 |
| 64 KB | 原始文件接口读字节 | 0.4712 | 0.4772 |

直接读文字只有约 1% 的差异，未排除测量波动；字节方式没有稳定优势。
这个结果不支持替换生产开关读取方法，也不证明实际共享任务可以提速。
本轮保留原实现和交付包，后文记录用已有采样调查具体调用责任的结果。
