# 插件衍生、可视化组合与快捷入口实现方案

## 用户要完成的事

1. 在“自己制作”选择“从已有插件创建”，选择 AutoBiz 或已安装项目插件，填写新名称，一次创建独立、可继续开发的完整副本；原插件和项目不变。
2. 在“助手组合”直观看到两个插件，选择“一起使用”或“先后执行”，按中文提示完成配置、应用和首次使用。
3. 输入 `/diff` 即可查看改动；项目规范、运行过程、策略、制作和使用帮助也有可发现的快捷入口。
4. 官方说明直接说明用途和操作。演练围绕一个任务，用户每一步知道点哪里、发生什么、下一步做什么。

## 工作边界与节奏

唯一代码目录为 `C:/ai/CmbCoworkAgent-mods-v2`，分支 `codex/mods-v2`。以已交付 v25 为基线，保留混合未提交工作树。UAT 及 `C:/ai/autobiz_kanban` 只读，不切换或覆盖它们。本方案经两名 medium 子 agent 审核并关闭阻断项后实施。

连续完成相互关联的能力，再集中回归；开发中只做必要边界窄测。两名审查者继续交叉检查实际实现。失败证据保留，不放宽门限来通过验收。

## A：完整插件衍生

- “自己制作”新增“从已有插件创建”主入口，支持从已安装插件选择和通过宿主目录选择器选择完整源码。自动建议独立名称/ID；普通路径不让用户手工编辑 JSON 或执行打包命令。
- 主进程完成来源检查、文件清单与摘要、独立目录创建、必要身份字段更新及中文开发入口。复用完整插件解析/安装协议，不用精简 Harness 编译器打包 AutoBiz 脚本。共享逻辑进入服务，IPC 保留当前窗口、会话、工作区和目录选择凭据校验。
- 一键创建表示“一次创建独立源码副本”；页面直接给出“查看源码”“继续修改”“检查并安装”的后续动作。安装经原安装与授权流程，绝不自动审批或运行 Hook。完整业务插件有专用脚本和外部依赖时必须如实展示，不能把静态检查当作业务验收。
- 原 Skill、Hooks、角色、流程、验证器、状态接口和必要脚本按文件保留；仅更改已识别的包身份字段，并保存来源/修改清单。禁止对整个源码进行字符串替换、改写原完成门禁或伪造阶段成功。对于任意源码形式，不支持的清单/链接/依赖明确报原因，不生成残缺的“成功”副本。
- 来源是代码包而非项目运行目录。不复制 Git 元数据、运行状态、缓存、日志和凭据；排除清单可查看，必需依赖被排除则阻断。拒绝链接/路径逃逸、超限和目标覆盖，来源变化须重新检查。新目录由宿主分配，不允许 Renderer 指定任意覆盖路径；失败清理仅限本次拥有的临时目录。
- 关键验证：原版与衍生版同时存在时，原 Hooks 不能重复执行。复用项目绑定后的有效插件范围；若现有加载器缺少衍生来源范围，只为衍生包补充宿主范围约束，保持原插件/UAT 默认行为。新项目使用独立状态目录，旧需求和运行副本不迁移、不混用。
- 给 AutoBiz 衍生副本保留完整验证链并提供一份可修改的业务说明，默认先改技能/节点说明；修改阶段结构前提示关联依赖。不声称任意旧阶段可自动拆开。

## B：可视化组合及首次使用

- 在现有“助手组合”中提供简单配置入口，使用插件卡片展示名称、用途、启用功能和缺失条件；高级编辑仍可展开，已有组合和草稿不丢失。
- “一起使用”：选择两项能力 → 命名 → 保存并核对应用。复用 Claw 来源/版本/组件/参数/权限和冲突校验，保留未修改的模型、Skill、MCP 和完成规则。冲突在确认前展示。
- “先后执行”：卡片按顺序连接为“步骤一 → 步骤二”，只列真正导出的可调用动作。表单从动作 schema 生成；只有结构明确兼容时建议传递上一步结果，否则让用户选择字段或说明无法连接，不编造动作。
- 流程和组合复用现有保存、版本与应用 API。出现保存成功但应用失败时明确恢复点，重试不重复创建；会话/工作区/来源版本变化即停止旧操作。任务执行中保持原切换限制。
- 应用后显示“现在怎么用”：命令能力提供填入输入框按钮；界面能力提供打开位置；流程提供准备首次任务入口。填入不发送，运行沿用原审批。没有公开能力的旧插件指向原项目入口，不伪装成可调用动作。
- 完整示例使用 AutoBiz 读取真实需求文件 → 独立 Review 检视。提供者缺失时引导准备/安装完整来源，不用模拟数据冒充真实运行。导览另用本地演示数据。

## C：内置快捷入口

- 统一轻量命令表：`/diff` 查看改动，`/instructions` 项目规范，`/runs` 运行过程，`/policy` 使用限制，`/create` 制作插件，`/help` 使用帮助；中文名称出现在输入 `/` 的菜单中。
- 使用现有聊天发送路径中的明确本地导航分支，不把快捷命令发送给模型、不创建空消息、不进入 Mods runtime。打开对应面板并定位具体功能；`/diff` 可按明确用户操作触发已有只读比较。
- 只匹配完整已知命令；保留已有 `/goal`、`/browser`、Skill 与插件命令路径。核对命令冲突策略，不能静默劫持既有插件同名命令。附件、草稿、会话切换、运行中打开及返回行为必须测试。
- 内置入口不依赖 Mods 开关，也不因打开面板触发额外轮询、权限申请或模型请求。

## D：官方说明与实例演练

- 统一页面名称与当前界面；删去构建日期、隔离环境、测试模型、验收过程等开发记录式文案。这些内容留在研发账本。
- 官方说明采用“用途 → 操作步骤 → 预期结果 → 常见问题”。截图用简短功能说明，不在正文反复解释截图来源。只在确实影响用户操作处说明限制。
- 演练改为任务导向：创建我的插件、搭配两个插件、查看改动与运行结果。每屏一个目标、一个主要按钮、一个变化明显的画面，简短显示“示例”即可；技术字段默认折叠。
- 保留可跳过/重看、旧用户不强弹、键盘操作、窄屏滚动与原草稿保护。失败演练采用“文件没找到 → 选择正确文件 → 重新检查 → 查看结果”，先解释问题再展示修复，不向用户灌输内部协议术语。
- 演练应能转到对应真实入口，并保留可理解的示例名称/需求草稿；真实创建/安装/执行仍由明确操作发起。

## 双审修订：实施契约（优先于上文概述）

### 完整副本与安全安装

1. 新增完整包快照服务，不复用会跳过链接的普通目录复制器或精简包白名单。宿主分配临时目录与最终目录；限制文件数、单文件和总大小；拒绝符号链接、junction、硬链接、大小写碰撞及根目录逃逸。复制前后核对整个来源清单和摘要，失败仅清理本次临时目录，原子发布后保存宿主记录。保留二进制及执行权限。排除 Git、凭据、日志、缓存和项目运行态；清单引用被排除文件即阻断，不能生成缺依赖的成功副本。
2. 支持根 plugin.json、.claude-plugin/plugin.json、.codex-plugin/plugin.json 中解析器实际支持的位置；实施时以现有解析器为准，多个有效清单身份不一致即拒绝。只结构化修改选中清单的 name（必要时 description），保留 version 和未知字段；如存在受支持的项目清单，同步其 plugin.id/name 与 version 对应关系。独立安装 UUID 由宿主生成；Mods 内部 ID 仅在协议明确要求与包名一致时修改，否则保留插件内作用域 ID。未知跨清单身份约束拒绝并说明原因，不全局替换源码。逐文件摘要和身份字段变化记录到宿主来源记录。新副本不继承批准、版本库归属、项目绑定或原项目状态。
3. 安装使用 catalog mutation 锁中的专用 create-only 协议。提交前再次验证当前来源摘要、独立名称、会话范围和目标身份；任意名称/身份冲突均拒绝，绝不进入已有包替换分支。新包初始不全局启用，批准沿用现有显式流程。创建、安装、绑定三种状态独立显示且持久可恢复，失败重试不再次复制。
4. 谱系由宿主生成并持久保存，不接受包自称的 family ID 来排除其他插件。已安装来源使用其真实安装身份，目录来源只可通过宿主核对身份及摘要关联原包。有效运行范围中同一谱系只允许本项目绑定成员，包括原版、祖先、兄弟副本；限制早于 persistent Hook 放行，同样适用于 Skill、SessionEnd、子任务和恢复。没有衍生谱系的原 UAT 行为不变。无项目绑定时衍生包不运行；保留原版默认路径。已开始运行的上下文冻结绑定，不从变化后的 UI 重建结束回调范围。
5. 完整 AutoBiz 默认走现有原生项目入口，保留 MCP 和原验证链；不删 MCP 以通过 managed 验证，也不放宽 managed 的原拒绝条件。新项目必须选择/创建独立且没有旧 AutoBiz 状态的目录，绑定前校验；不能沿用旧 PROJECT_DIR。创建成功仅说明副本完成，安装检查与当前运行模式兼容性分别展示。完整新 ID + 新项目必须实际通过原链正常/拒绝/未审批/重试用例。
6. 完成页主动作“修改这个插件”，携带宿主副本 ID 打开制作上下文和可编辑业务说明；次级“打开源码”。检查通过进入“安装到新项目”，携带副本来源到 create-only 安装及原项目绑定确认，不要求重新寻找目录。任何修改、安装、项目创建、执行均需对应显式用户操作。不能提供直连的旧步骤必须用可点击步骤及当前状态显示，不能声称已经可运行。

### 同页组合与真实演练交接

1. “一起使用”在一个页面完成选两项、名称、核对应用。“先后执行”在同页完成两个真实动作、参数表单、结果字段连接、保存并核对应用。UI 依序保存流程、固定该流程版本到组合、显示应用预览；各阶段保存 ID/revision，失败可续接而非重建。无需跳到高级编辑器删模板、写 JSON、再找绑定入口。
2. 应用后“准备首次任务”进入原聊天正确模式并选中已应用流程，只准备不发送。普通插件无导出动作时明确指向其原项目入口。已有复杂组合不能无损投影时显示“此组合包含更多设置”，保留完整对象及草稿，按原编辑路径处理，不重建简化对象。
3. 演练使用三项可独立选择的任务：创建我的插件、搭配两个插件、查看改动和运行结果；每屏只有一个目标、一个主操作和对应画面。使用类型化一次性 practice intent，包含任务、目标子功能、建议名称/文本、thread/workspace 和请求 ID；只携带可理解文本，不携带模拟插件 ID 或假路径。
4. 真实创建定位到来源选择，真实组合定位到模式及来源选择，查看定位到具体面板；来源缺失提供准备入口。已有草稿不覆盖，显示保留现有草稿或明确另建本任务的选择；取消返回原焦点。异步完成时验证 scope/request ID，切换会话/工作区丢弃旧 intent。保留原 seen key，升级不强弹。

### 本地快捷命令的明确规则

1. 六个本地命令在普通/流程模式、任务运行中均早于入队、取模型、附件转换、创建消息和 Mods 提交处理。菜单条目使用稳定 kind + ID 并标明“内置”；选中直接导航，键入完整无参数命令后 Enter/发送走同一 dispatcher。
2. 同名插件/Skill 存在时，精确文本提交显示选择器，不静默抢占；明确选中的内置菜单项无需再比较。目录尚未可用时文本提交提示先选菜单中明确目标，不猜测无冲突；Mods 关闭仍可从明确内置条目打开。插件原命令路径保留。
3. 带参数/正文，或混有选中 Skill/browser 的输入不静默导航；保留原输入并提示通过内置菜单打开。成功只在输入 revision 未变时消费本次命令文本；附件、选中项和新输入保留，导航取消不改草稿。菜单、Tab/Enter、直接发送、IME、Shift+Enter、近似前缀和冲突均覆盖。
4. 本地入口只读，零模型/消息/入队/Mods enqueue；不增加轮询或逐 token/catalog 重算。/diff 无目录或非 Git 时原地说明原因和下一步。

## 验收与交付

- 衍生：真实 AutoBiz 来源、独立名称/标识、原 Hooks/验证器/流程逐文件一致；原包与副本并存、项目绑定隔离；非法来源、重复名称、来源变化、失败恢复；实际原链正常/拒绝/未审批/重试用例。
- 组合：两插件选取、组件依赖/冲突、兼容和不兼容输入连接、保存/应用/失败重试、切换会话不串数据、真实首次任务与运行结果。
- 快捷入口：菜单发现、键盘和直接发送、零模型请求/零空消息、不抢占旧命令、工作区缺失/非 Git/运行中/会话切换。
- 文档与演练：逐屏实际操作和截图，入口可达、真实预期结果、桌面与窄屏、键盘、草稿/跳过/重开。不得只用文字断言冒充用户能看懂。
- 性能：保留 v25 首次展示方案；无新增全局监听或每 token 重算；冷启、长历史、切会话/模式、流式/最小化/热更新、无重复消息/闪动与既有输入响应门限。
- 集中运行类型检查、必要 lint、新增与相关回归、完整 npm test 和原后续链、最终同包 Electron E2E。两名 medium 回检，确认 P2+ 修复后再交付。包替换前检查用户应用已退出，原资源备份，安装后再次验收；不读取凭据、不执行真实外部业务。
