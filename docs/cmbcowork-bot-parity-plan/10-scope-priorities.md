# 必做、条件必做与可选范围

**当前部署基线（按用户 2026-10-02 补充）：首版支持 macOS 与纯 Windows 原生本机运行；Windows 禁止依赖 WSL2/Linux 容器，后续服务端为 Linux K8s。** 平台适配、存储与迁移以 [当前实施基线](12-windows-local-first.md) 为准；公共执行、恢复和授权契约继续适用。本文全量扩展保留为后续参考，不自动纳入本机首版。

本文件回答“在 CmbCowork 中实现 Grok Bot 的主要工作方式，哪些必须做，哪些可以单独选择”。这是范围取舍建议，不是已经获准删除原方案需求。原来的 260 项全量对齐清单继续保留。

当前范围已落实到 [core-scope.json](core-scope.json)：124 项核心、53 项部分核心、10 项条件纳入、73 项延期。条件项本机首版未启用；不是仍待用户回答的统一前置问题。最新部署与验收见 [第 12 文档](12-windows-local-first.md)，通用契约见 [复核](11-core-final-review.md)。

## 1. 先区分两种验收目标

- **桌面端完整 Bot 核心：** 在现有 CmbCowork 桌面中，交办目标后 Bot 能长期承接工作，在持久环境执行，与其他 Bot 协作，保留经验，通过示范/技能与计划/事件持续工作，向人请求必要授权并交付结果。手机、语音和公开市场可单独选择。
- **原版所有功能、所有端完整一致：** 已确认的原版手机、语音、Team Bots、企业功能等仍在全量范围内。某项在核心产品中可选，不等于可以在全量验收时把它记为完成。

下文的“必做”以第一个目标为依据；“全量必需”说明恢复到第二个目标时必须补齐对应功能。可选项应显示为未纳入当前交付范围，不应留占位按钮或伪装成可用。

## 2. 核心必做

| 功能 | 必须交付的边界 | 原方案定位 |
| --- | --- | --- |
| 长期 Bot 身份与职责 | 创建/编辑/删除，持续职责和会话，多次任务和重启后仍是同一 Bot；基础列表与状态管理 | BOT、ACC、M01 |
| Cmb 桌面工作区 | 聊天、附件、活动、结果、错误、等待状态、停止与补充指令；长历史、草稿、必要键盘/焦点行为 | MSG、UI、FIL、M03/M13 |

| 持久工作环境与电脑操作 | 保留文件和登录，浏览器/Shell/电脑工具；按用户隔离；Bot 独立操作屏幕、共享资源并发控制 | CPU、FIL、M04 |

| 多 Bot 协作 | 独立 Bot 直接消息、交接、结果返回、群聊、@路由和并行分工；循环/失败可收束 | COL-01～11、M05 |
| 长期记忆 | 职责/偏好/工作经验持续保存，能纠错/删除；各作用域按权限读取，自动整理不覆盖新事实 | MEM、M06 |

| 审批与受控执行 | 问题/审批/安全输入、动作绑定、拒绝/过期/撤回；同一动作不会因重试重复产生外部效果 | APR、M10 |
| 可验收结果与追踪 | 文件/代码/文档等结果可查看下载，进展和失败依据可追踪；重要操作记录能定位问题 | FIL、MSG、OPS-08 |
| 基础可靠性和上线保障 | 断网/进程重启恢复、幂等、备份还原、可回退升级、资源/预算限制、选定平台构建及 Cmb 回归 | OPS、ADM 基础子项 |

“必须”表示这些能力不能缺，不表示表中每个组的所有边缘功能都必须同时实现。例如：文件上传与成果访问必须；支持手机系统分享不由此变成必须。保留安全输入/权限/恢复等必要约束，避免用删异常流程来缩小代码量。

### 后台和手机的区别

首版本机 Host 必须脱离窗口生命周期，但本机关机、休眠或注销后不承诺继续执行。后续 Linux K8s 部署才可使运行不依赖员工电脑在线。这两种部署使用同一任务/事件语义，不混淆关闭窗口与关闭电脑。

手机客户端只是访问同一套 Bot 服务的另一个入口，可不纳入桌面核心交付。服务端身份、权限、消息记录与持久任务仍然必须具备，不能因暂不做手机端而留在桌面内存中。

## 3. 条件必做：由实际使用场景决定

| 功能 | 什么时候必须 | 怎样控制范围 |
| --- | --- | --- |
| 企业身份、账号开通与权限 | 给真实员工使用时必须有可靠身份和访问控制 | 优先复用企业/Cmb 已有设施；只有现有设施不足时才补建，不默认重做整套 SSO/SCIM 管理产品 |
| 内网、代理、证书和目标系统访问 | Bot 要操作内部仓库、流水线、工单或办公系统时 | 完成目标部署的实际网络路径；本机出口、VPN/受管网络等选择适合的一种或多种，不强制复制所有选项 |
| 项目/仓库与代码运行环境 | Bot 要承担研发项目工作时 | 复用 Cmb 项目、权限、隔离工作区、构建/测试；独立的云端编码代理产品不是唯一实现方式 |
| 招乎/其他 IM 入口 | 要从 IM 交办、审批或接收结果时 | 复用现有招乎入口接同一服务；不需要因此同时建设 Slack、Telegram 等全部入口 |
| 远端访问员工设备的桥 | 后续 Linux 服务必须使用员工电脑资源时 | 本机首版的文件/命令授权是必做；额外远程设备桥可延期，启用后补设备身份、批准、撤回与离线处理 |
| WebAuthn 代理 | 目标系统登录确实依赖本机 passkey/硬件认证时 | 先验证登录流程；可用的人工作业路径与必要代理能力按实际系统选择 |
| Team Bots | 同一个 Bot 要发布给多名员工，各自私聊且共用受控资源时 | 一旦选择就必须完整做私聊/记忆/凭据隔离，不能只做“共享入口” |
| 邮件/Slack 等编辑发送卡 | 选定任务需要对这些通道起草并发出消息时 | 对已支持通道实现真实编辑、确认、发送/丢弃和去重；没有接入的通道不显示可发送 |
| 多用户隔离、审计与运维基线 | 多员工或正式生产部署时 | 数据/电脑隔离、授权撤销、基本审计、备份、删除范围不能选掉；是否新建可视化管理后台另行判断 |
| 指定事件源 | 工作流以该供应商事件驱动时 | 事件机制必须；供应商适配按目标清单选择，每个选中的源完整实现认证/去重/失败处理 |

## 4. 可独立选择的端、交互和生态

| 可选项 | 不做对核心有什么影响 | 原方案定位 |
| --- | --- | --- |
| iOS / iPadOS / Android 客户端 | 失去手机聊天、接管、审批和推送；桌面及后台 Bot 仍可完整工作 | MOB、M14，Team Bot 手机子项 |
| 实时语音、听写、语音便笺 | 使用文字/文件交办与返回结果；执行、协作、记忆不受影响 | VOC、M12 |
| 公开模板市场和公开分享 | 缺少面向外部的发现/分发；个人技能/内部复用可继续存在 | SHR、M18 |
| 全部第三方连接器及事件源 | 仅操作明确接入的系统；不会影响平台扩展机制 | PLG/AUT 的 provider 子项 |
| 未使用的桌面 OS/CPU 架构 | 只承诺选定平台；已有 Cmb 支持能力仍需避免回归 | OPS-09 |
| 新增完整企业管理门户 | 通过已有管理设施或受控配置管理；所需权限、隔离、审计仍必须执行 | M15、ADM 界面/批量/API 子项 |
| SCIM 自动分配、复杂组策略、批量电脑管理、OTel 内容导出 | 少了对应管理便利或集成；不等于可以省掉基础身份、策略、日志和恢复 | ADM 高级子项 |
| 商业订阅、试用、商店支付、跨品牌权益关联 | 内部组织使用无需建设商业售卖链路；任务用量/预算保护仍需保留 | ACC-08、商业分发适配 |
| 多账号切换、批量侧边栏整理、所有语言和完整快捷键集合 | 主工作路径可用；对应操作便利或语言覆盖不同，需记录体验差异 | ACC-03、BOT/UI 的扩展子项 |
| Agent Network 图、广播、跨用户共享房间 | 不影响个人 Bot 直接消息与群聊；这些功能还存在公开状态待核实项 | OBS-01～03 等 |
| 图像生成等媒体扩展 | 文本、代码、文件等工作可继续；不影响电脑截图和 Teach 所需录屏 | OBS-08 |

对本次选定交付范围仍要求成熟体验：主路径、正确状态、断网恢复、可理解的错误、焦点/输入法等要正常工作。像素级全页面复刻、所有边缘快捷键和未使用语言目录，可以作为完整同款目标的后续覆盖项，而不把它们与基础可用性混为一谈。

## 5. 两组特别容易混淆的功能

### Bot 协作与 Team Bots

- **多个 Bot 帮同一用户分工、直接沟通和群聊：核心必做。**
- **将一个 Bot 发布给多名员工，形成成员私聊与共享资源：按团队分发需求选择。**

Team Bots 暂不做，不会导致同一用户不能使用多个 Bot 协作。但若选择 Team Bots，跨成员权限和数据隔离就是功能的一部分，不能删。

### 插件机制与插件市场

- **能够发现/调用可用工具、授权连接器、加载和复用技能：核心必做。**
- **公开市场、作者页、精选分类、外部模板传播：独立可选。**

现有 Cmb 插件/技能入口优先复用，避免为 Bot 再造一套重复生态。

## 6. 建议的一次性交付范围

建议将以下能力作为一个完整交付包连续实现：

**Cmb 桌面 Bot 工作区 + macOS/Windows 本机独立 Host + 持久电脑与人工接管 + 多 Bot 协作 + 长期记忆 + Skills/Teach + 计划与所选事件源 + 工具/插件接入 + 审批/安全输入 + 结果与恢复。**

面向研发使用，再加入项目/仓库/构建测试、所需内网与身份接入；使用招乎交办时复用既有入口。手机、语音、公开市场、Team Bots 和高级管理设施作为独立范围选择，不与“要不要先做半成品”绑定。

这是当前选定核心范围，原全量目标保留。Linux K8s 的平台端口、构建边界及迁移契约首版落实，实际集群交付后续实施；未实现项继续为 planned。

## 7. 对代码量估算的影响

原估算新增产品源码 8 万～15 万行覆盖全端与完整管理能力，不应直接套用到较小范围。原分项中移动端与语音约 1.8 万～3 万行，Team Bots 与企业管理合计约 1.2 万～2.2 万行，但其中基础身份、权限、审计与共享服务仍需保留，不能整项直接相减。

可选项确定后按共享依赖重新估算，分别给出移植、新写和现有改动量。本轮提供功能范围分析，没有以未经验证的新行数替换原全量估算。
