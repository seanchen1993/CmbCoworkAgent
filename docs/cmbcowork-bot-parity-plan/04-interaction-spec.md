# 交互与体验规格

当前平台见 [Windows 本机与 Linux K8s 基线](12-windows-local-first.md)。原版 0.57.1 的创建、协作和 Teach 路径已有 [实际观察](13-original-app-observations.md)；其余界面仍待逐项对照。

本文件定义需要实现、截图和实测的交互契约。功能范围以 [矩阵](02-feature-matrix.md) 为准。布局尺寸、字体、动画曲线与当前服务端开关尚未通过原版真机冻结，不能把下文当作已经测量完成的像素规格。

当前核心使用 [逐项范围](core-scope.json) 和 [最终复核](11-core-final-review.md) 筛选页面/卡片/快捷键；手机、语音、市场、Team Bots 等延期入口不出现在可用界面。多端竞争仍用两个桌面会话测试；不能以删除手机为理由删除身份、审批和接管并发约束。

## 1. 体验基准与 CmbCowork 的衔接

在 CmbCowork 主导航增加 Bot 工作区。进入后，创建、沟通、查看电脑、教技能、配置例程、团队使用等核心路径按原版组织；项目关联、Feature、招乎等 Cmb 能力从详情或工具层接入，避免在每次创建 Bot 时增加原版没有的必填步骤。

采用 Cmb 品牌、图标与文案资源。对齐功能入口、信息层级、操作结果和反馈时机。品牌差异单独记录，不拿品牌不同解释功能缺失。

P0 为每个表面保存：应用版本/构建号、OS、窗口和显示缩放、语言、账号计划与开关、测试数据、录屏、关键截图、按键与点击序列。0.18 是源码机制基线，当前官方帮助是功能基线；不能从两个版本挑选实现最容易的行为拼成“原版”。

### 1.1 当前核心 UI 必须符合 Bot 的工作方式

用户确认 UI 交互也必须符合 Bot 的操作逻辑。界面围绕长期存在的 Bot、正在推进的工作和需要用户介入的事项组织；Grok 可用的 UI 组件及交互逻辑直接移植，接入 Cmb 的状态和事件，具体流程按原版观察校准。

- **进入和切换：** Bot 有固定身份与持续历史；切换后恢复该 Bot 的对话、草稿、工作进度和所选电脑目标。先校验新目标再启用输入，不能把上一 Bot 的画面或操作带入下一 Bot。
- **持续执行：** 切换 Bot、收起电脑或关闭主窗口不取消已接收任务；侧栏持续显示工作中、等待用户和未读结果。重新打开后从 Host 恢复状态。本机休眠、关机等不可用状态如实显示。
- **运行中操作：** 补充要求、停止当前任务、暂停例程、停止整个后台使用明确且不同的入口和反馈；以 Host 确认后的状态为准。普通 Stop 不默认取消未来例程或所有协作 Bot 的任务。
- **看屏与接管：** 查看画面不取得控制权；接管经 Host 确认、对应目标的 Bot 输入停止后才启用人工操作。归还后由 Bot 重新观察再继续，界面显示当前控制者；查看器关闭与归还控制分别处理，不能隐式恢复输入。
- **协作：** 群聊显示发言者、分工、交接和等待对象；Bot 间直接沟通可查看记录，结果关联回发起工作。用户无需在不同 Bot 间复制消息来完成交接。
- **需要用户介入：** 审批、补充信息、登录和故障提示都能定位到具体 Bot、任务和操作；切换页面后仍可找回。技能学习和例程创建、修改、暂停的结果同步到相关列表，不能只有聊天口头回复。

验收使用完整操作过程：同时交办两个 Bot → 切换查看 → 向其中一个补充要求 → 接管并归还其电脑目标 → 处理协作和审批 → 关闭并重开界面 → 核对进展与结果。全部行为须与后台状态一致；仅有组件、按钮或静态页面不算完成。

## 3. 桌面布局与通用状态

### 3.1 侧边栏

- 账号、New、搜索、Plugins/市场、Bot 列表、分区、设置保持稳定入口。Plugins 与 Marketplace 的实际位置按目标版本确认，不同时堆两个功能重复的入口。
- 单项显示头像、名称、运行/待处理状态、未读；置顶和分区顺序同步。压缩侧边栏仍可识别 Bot、显示提示和切换。
- 右键菜单按对象类型显示改名、置顶、已读/未读、移动、隐藏、删除等操作。当前 Mac 0.57.1 观察入口不含复制；官方最新说明将 Duplicate 列为 iPhone 操作。Cmb 桌面保留复制能力时标为端侧扩展，不声称该按钮已在原版桌面核实。多选保留键盘与范围选择；批量失败按对象报告。
- 隐藏只改变该用户的展示和通知。隐藏的 Bot 继续工作、继续运行例程；隐藏列表可恢复。管理员强制分发的 Team Bot 不提供隐藏操作。
- 删除分区将内容移回未分区；不连带删除 Bot。删除 Bot 必须说明影响范围，Team Bot 删除尤其要说明影响所有成员。

### 3.2 主对话和详情

标题区显示对象身份，能进入详情、电脑和对应操作。对话使用虚拟列表/分页，但不能因流式输出、展开工具、收到新消息而丢失阅读位置。回到之前访问的 Bot 恢复滚动位置与草稿。

任务、技能、文件等能力可从对应入口访问，不强制塞进同一详情页；实际入口按 0.57.1 观察及后续 Windows 对照确定。各列表提供空态、加载、失败、无权限和必要分页。秘密只显示名称和用途，普通接口不返回旧值。

### 3.3 状态不是一组互斥标签

| 维度 | 状态示例 | 行为 |
| --- | --- | --- |
| Bot 可见性 | 正常、隐藏、管理员固定、已删除 | 影响列表和入口，不等同于任务状态 |
| 连接 | 在线、重连、离线、鉴权失败 | 保留草稿；不要把断网显示成任务失败 |
| 执行 | 排队、工作中、等待依赖、完成、失败、取消 | 与持久 Run 状态一致 |
| 用户交互 | 待回答、待审批、待接管、过期、已处理 | 点击回到准确卡片；失效卡片不可提交 |
| 阅读 | 未读、已读、人工标未读 | 与是否工作中独立 |
| 电脑 | 准备、可用、休眠、唤醒、恢复、失败 | 画面不可用时仍可查看消息和历史 |

## 4. 主要用户流程

### 4.1 创建、配置、持续使用

New → 创建个人 Bot → 在聊天中说明职责和目标 → Bot 准备电脑/必要资源 → 接收任务 → 显示活动与结果。创建时不用先理解模型、VM、工具图或执行器。

名称、头像和描述可以后续修改。复制生成新 Bot，并显示复制来的技能和例程；不复制聊天、记忆与附件。该用户原先共享电脑上的登录仍然可能可用，这不等于复制了新凭据。

### 4.2 发送消息与正在执行时补充

1. 编辑草稿；输入 `/` 选择技能，输入 `@` 引用准确对象。
2. 添加文件/粘贴图片，显示上传进度和失败；未就绪附件不会被伪装成已发送。
3. 发送后先进入确认中；收到持久接收回执再显示已接收。断网时重试沿用 nonce。
4. 运行时显示可理解的工作进展，并允许补充指令。新指令是“已接收/待处理/已采纳”中的哪一种，必须与执行器一致。
5. Stop 停止后续动作；对正在外部提交的动作显示结算状态。已发送邮件不能变成“未发送”。
6. 回复某条消息打开分支；返回主线不丢定位。表情回应不触发动作批准。

### 4.3 结果和交互卡片

| 卡片 | 用户操作 | 不能遗漏的行为 |
| --- | --- | --- |
| 工具活动 | 展开/折叠、复制必要信息 | 稳定 ID 增量更新；失败有原因，不伪装成成功 |
| 普通问题 | 选项/文本、提交、取消 | 当前允许回答者、卡片版本、已回答状态 |
| 动作审批 | 查看目标和修改内容、批准/拒绝 | 参数被改写或过期后必须重新审批 |
| 本地权限 | 选择授权方式或拒绝 | 明确执行设备，不与云端动作审批混用 |
| 安全输入 | 输入、掩码、提交/取消 | 内容走专用通道，失败不明文回显 |
| 邮件/Slack 草稿 | 改收件人/主题/正文、发送、丢弃 | 提交最后编辑版本；重复点击去重；发送失败可核对 |
| 文件成果 | 预览、下载、打开来源 | 权限、文件就绪、版本和过期链接恢复 |
| 电脑活动 | 看屏、接管、全屏、归还 | 观看不抢控制；关闭窗口不停止任务 |
| 语音记录 | 播放、暂停、展开转写 | 失效媒体地址重新取票据；跨端读取一致 |

0.18 重建 UI 中部分按钮是占位实现。验收必须通过真实外部效果或可靠测试端点确认，不以“点击没报错”为准。

### 4.4 多 Bot 协作

New chat 选择 2–6 个 Bot → 调整名称 → 交办共同目标。普通消息由群编排器分配响应者；@ 一个、多个、everyone 都使用实体 ID。界面可看到哪个 Bot 正在承担哪部分工作、交给谁、等待什么。

直接 Bot 消息异步投递，接收方稍后回复，不要求用户打开它的窗口。发起对话显示已发送/收到的记录，可打开只读的 Bot 间交流视图，再由发起 Bot 回答用户；此路径已实际观察。群聊中的任务交接和最终产物应能回到发起消息。Bot 到群的交接按已确认的文字范围实现，图片可通过 Bot 直接消息传递，不能混淆这两个能力。

删除、移出群聊、接收者失败和达到协作上限都要能收束；不能让用户面对无限轮次的 Bot 相互确认。

### 4.5 电脑操作与接管

首次准备 → 可用画面 → Bot 操作 → 请求登录/人工步骤 → 用户接管 → 用户归还 → Bot 重新观察后继续。

接管期间界面明确显示控制权，服务端同时阻止 Bot 的所有同屏输入通路。手机和桌面不能各显示自己拥有控制。接管断线要能重连或明确释放，不能自动点击用户尚未确认的页面。

电脑不可达时在错误状态提供 Recover；Settings → Updates 中保留 Update/Reset，不能混为同一个入口。显示影响范围、当前备份/同步时间及失败状态；恢复不是承诺所有未同步文件零丢失。管理员 terminate/delete-data 属于不同操作。若选择本地执行或设备网络出口，设备离线时任务明确等待，不能声称关闭该设备仍可访问它。

### 4.6 Teach 与 Skills

在个人对话点击 Teach → 立即进入电脑录制 → 演示 → 停止并保存 → 自动发送学习请求 → Bot 分析并保存技能 → 查看/修改技能 → 用户选择是否换输入试跑。原版不要求先填目标表单，也不强制经过草稿启用向导；目标不明时可提问，已保存与已验证状态分别记录。

上限 10 分钟且不采集麦克风的要求保留为文档基线，本轮未实测时限。受控安全输入时暂停各采集通道；未知画面不承诺自动识别所有秘密，提供可见暂停、丢弃和敏感片段审阅。普通录制停止后进入自动学习，不额外增加强制确认步骤。录制中断、学习失败和权限缺失均有可恢复状态。

技能库支持查看、编辑、版本、启停和删除；Bot 只使用已授权技能。自动保存不表示已完成验证；试跑须由用户选择，不自动产生业务写入。后续无人值守执行仍检查权限和审批，失败显示依据与修改入口。

### 4.7 Routines 与事件

在聊天中提出周期或事件任务 → Bot 创建并返回关联事件 → 个人对话详情中的例行任务列表查看。本次原版没有额外的必经确认表单。当前样本详情包含 Instructions、When to run、暂停/恢复、Edit、Delete；Test 按例程能力显示，不假设每条都有。Cmb 补充下次时间和运行记录用于核验，不把它们写成原版固定控件。

当前专项帮助的 Edit 会把编辑指令放回聊天，由 Bot 协助修改；不能直接用一个 cron 表单替换全部自然语言流程。删除有确认。Test 会产生真实运行和外部效果，须按同一权限执行；不能显示测试成功却没有任务记录。

创建/修改回执、列表和详情使用已提交的同一配置 revision；打开中的详情也要更新。单次与周期计划分别建模，展示时区及可核验的未来触发点。原版已观察到年度描述冲突及编辑后需切换对话才刷新，复刻不要求保留这些问题；详情见 [运行观察](13-original-app-observations.md)。

Webhook 详情提供 URL、密钥/认证方式及复制；返回接收成功不表示任务已完成。Slack 的频道、关键词、提及、回应等条件能解释为什么触发；连接器授权和事件订阅状态分别显示。邮箱、GitHub、Linear、Sentry、PagerDuty 均有真实事件样本验收。

### 4.8 插件授权与重连

浏览目录 → 安装 → 配置变量/授权 → 等待回调 → 服务端验证 → 可用。安装、未授权、已断开、等待回调、管理员限制和供应商错误用不同状态；重开授权窗口不创建第二套混乱连接。

按供应商能力显示多账号入口；不能统一承诺所有插件多账号。工具开关、自定义指令、连接器范围可查看。用户撤回后工具立即按有效授权检查，不能依赖页面图标变灰来阻止执行。

### 4.9 模板分享与 Team Bot 发布

**模板：** 生成配置快照 → 选择团队/公共范围 → 链接预览 → 接收者创建自己的副本 → 补齐授权。原作者更新不会静默改变接收者已有 Bot。

**Team Bot：** 新建团队 Bot 或从个人 Bot 创建团队副本 → 选择插件、秘密、文件及可迁移记忆/例程 → 完善名称与描述 → 发布 → 成员从团队列表、名称搜索或链接打开同一 Bot。普通 New 搜索中名称长度门槛以目标版本核实，专项帮助当前描述至少 3 个字符。

每名成员有私有聊天；owner 只能管理配置，不可查看成员私聊。个人账号 Allow 卡提供本次、此 Bot、所有 Team Bots、跳过，并可撤销偏好。公共记忆更新可见；不得把成员私聊原文直接变成共同记忆。

Slack 接入在发布之后完成，包含管理员待审批、成员身份关联、DM 和频道提及。撤回与删除有不同含义；删除应明确全团队影响。管理员分发的团队 Bot 自动出现且不能隐藏。

### 4.10 三种语音

- **听写：** 点击/快捷键开始，停止后转成可编辑草稿，再由用户发送。按住说话的具体按键组合按当前平台冻结。
- **实时通话：** 空输入框出现入口 → Connecting/Calling → 通话 → 静音、显示文字、调音色/速度/语言/麦克风 → 挂断 → 时长、通话记录和可选好/差反馈。工具执行仍进入同一任务和审批链。
- **语音便笺：** 会话中的音频产物，支持播放/暂停和转写展开。

切换聊天保留通话，可以返回正在通话的 Bot。应用全局一次通话；启动第二通需确认结束前一通。群聊和同事的 Team Bot 不显示通话入口。挂断不自动取消已交办工作；断线重拨不重做已完成外部动作。

## 6. 移动端与桌面的差别

| 能力 | 移动端验收边界 |
| --- | --- |
| Bot/群聊和消息 | 触屏操作、分支/表情、消息恢复；分区能力按各平台版本冻结 |
| 上传/分享 | 相机、相册、文件和系统分享；iOS 多类型，Android 官方已确认至少文本 |
| 电脑 | 观看、触控操作、软键盘、控制权转移；不能仅提供静态截图 |
| 交互卡 | 审批、安全输入、个人账号 Allow、邮件/消息草稿全部可操作 |
| 语音 | 听写、实时通话、便笺；来电/耳机/后台与系统音频焦点 |
| 例程 | 查看、暂停/恢复、删除、历史；Add routine 进入预填聊天；Test/Edit 按平台范围 |
| Team Bot | 聊天和 Allow 卡；创建、发布、Slack 设置用桌面；同事 Bot 无通话 |
| 电脑维护 | 不捏造手机恢复/重置入口；提供明确桌面操作指引 |
| 推送 | 隐藏/静音/系统权限、跨账号深链接、被删除对象的失效提示 |
| 商业权益 | Cmb 内部组织权益适配单独列明；外部收费发行必须实现真实商店购买/恢复流程 |

## 7. 视觉与状态验收包

需要成对保存原版与 Cmb 截图/录屏，至少覆盖：

1. 首次登录、电脑准备、空列表、新 Bot、长名字和生成头像。
2. 多分区、隐藏列表、右键菜单、批量选择、管理员固定 Bot。
3. 空对话、长历史、流式输出、分支、搜索命中、排队和新指令。
4. 问题、审批、安全输入、编辑草稿、文件、错误、过期、已在另一端处理。
5. 看电脑、全屏、接管、登录、重连、电脑恢复失败。
6. Teach 录制、处理、保存/修改、试跑成功/失败；例程触发与运行历史。
7. 插件未授权/等待/失效、模板导入、Team Bot 发布与成员授权。
8. 三种语音、切换聊天继续通话、断线、通话结束记录。
9. 手机竖/横屏、键盘弹起、推送跳转、系统分享、后台恢复。
10. 浅/深主题、系统缩放、长中文、英文、键盘操作、读屏与减少动画。

视觉差异用截图检查，操作路径用脚本/录像检查，任务完成用真实结果检查。三类证据不能互相替代。原版已知问题如授权循环、偶发错误不作为要复刻的目标；记录后实现可恢复行为。
