# 代码量估算与完整交付方式

**适用性更新（2026-09-30）：以下行数保留为历史范围估算。用户已改为纯 Windows 本机首发、后续 Linux K8s，且未选择新增专用连接器；旧 5 万～9 万行基于远程 Host/电脑及 2～3 个连接器，不能直接作为当前报价。** Windows 原生多屏方案与双平台依赖闭包核验后再重估；仓库实测代码计数仍有效。当前设计见 [第 12 文档](12-windows-local-first.md)。

日期：2026-09-29。估算前提是按完整方案交付，包含桌面、后台运行、电脑、多 Bot 协作、记忆、Skills/Teach、插件/事件、Team Bots、移动端、语音和企业管理；执行代码复用与移植优先策略。

本估算对应全量范围。关于手机/语音等可选项与核心必做项的拆分，见 [必做与可选范围](10-scope-priorities.md)。选择较小范围后需要重估共享依赖，不能把这里的全部代码量理解为桌面 Bot 核心的最低投入。

**历史远程核心范围补充估算：新增产品源码约 5 万～9 万行，中值约 7 万行；加上测试和部署材料，新增约 6.5 万～12 万行。** 这是假设只实施核心范围时的预算，详见第 6 节。第 7 节是对本地 Grok 重建库的完整计数，区分运行源码与生成代码。

旧远程范围的工程契约仍需保留；新增的纯 Windows 原生电脑适配及 Linux 扩展改变了估算前提，不能继续写成“量级不变”。本轮不凭文档工作量编造新的行数。

## 1. 结论

**新增产品源码按约 8 万～15 万行准备，规划中值约 11 万～12 万行。** 其中约 5 万～9 万行来自现有项目移植并改造，约 3 万～6 万行为新写的适配层、服务整合和功能缺口。它们是估算分配，不是已经实现的复用比例。

另预计修改现有 Cmb 源码约 0.8 万～1.8 万行，以及新增/移植测试、部署脚本和配置约 2 万～4.5 万行。含验证与部署材料的新增量，按约 10 万～20 万行量级考虑。现有文件修改、纯文件搬移和净新增是不同指标，不应直接相加。

这不是依赖分析完成后的精确报价。当前属于量级估算，完整依赖移植、原版最新功能差异、实际移动端/电脑/语音接入验证都可能改变结果。一次代码格式化也会改变物理行数，开发工作量应结合接口和验收复杂度判断。

## 3. 按能力拆分的新增产品源码

包含移植代码与新写代码，不含测试和部署材料。划分的是主要归属；共享模块只计一次。

| 范围 | 预计新增 | 主要来源/处理 |
| --- | ---: | --- |
| Bot 服务端、持久任务、同步、Host 接入 | 1.2 万～2 万行 | Cmb 内核继续使用；移植 Rakazo 后台模块及 Grok 消息机制，补服务适配 |
| 协作、记忆、技能/Teach、例程和插件接入 | 1.5 万～2.5 万行 | 优先移植 Grok 实现并复用 Cmb 能力，补当前版本的事件与学习缺口 |
| 持久电脑、看屏/接管、本地设备桥 | 1 万～1.8 万行 | 复用已有协议/查看器/适配器，补自有电脑管理和多屏集成 |
| 桌面 Bot 工作区与完整交互 | 1.8 万～3 万行 | 复用 Cmb 消息组件，移植可用的 Grok UI，补未恢复和新增交互 |
| 移动端与三种语音 | 1.8 万～3 万行 | 评估移植 Rakazo 移动模块，接入媒体组件并补任务/权限联动 |
| Team Bots、企业策略与管理界面 | 1.2 万～2.2 万行 | 复用通用身份/资源/审计代码，补团队私聊、授权、分发和管理 |
| **合计** | **8.5 万～14.5 万行** | 对外按约 8 万～15 万行量级表述 |

区间不是统计置信区间。某块需要更多新实现时，移植量和新写量会相互变化，不能要求所有分项同时达到下限。连接器目录、移动端实际可移植程度和自有 VM 平台是主要不确定项。

## 4. 行数的计入口径

- 外部模块复制进项目并修改：计入新增源码，来源标为移植。
- 原有 Cmb 模块只修改：单列修改量，不把整个文件都计为新增。
- 原有 Cmb 文件换目录：记录迁移，纯搬移不计实质新增。
- npm/系统依赖、下载的原版编译产物、自动生成协议：不计手工实现量。
- 测试和部署代码：单列；它们可以一起移植，不要求全部新写。
- 删除旧实现：单列，不能用大规模删除抵扣新增功能的实际开发量。

## 5. 可以一次性交办完整目标

用户可以用一次任务明确要求完整实现，内部持续推进，不需要逐阶段重新发起或批准。原方案 P0～P5 是依赖顺序和内部检查点，不是要求用户分别购买/接受六个不完整版本。

执行时按模块连续集成：采用候选代码 → 改造依赖 → 跑通连接 → 对照验收 → 继续下一项，最终按完整矩阵交付。不能将所有代码一次堆入后只验证编译，也不能在中途某一阶段可用时擅自宣布完整完成。

**一次性交办不等于能够承诺单次模型运行就完成全部开发和验证。** 该量级可能需要持续执行和上下文接续。所需的测试账号、供应商授权、部署环境和各平台设备若缺失，应如实保留具体阻断项，同时推进不依赖它们的工作。不能用未接通的占位实现或只通过编译来替代完整交付。

本轮进行了本地源码规模统计与估算，未开始产品实现，也未执行产品功能测试。

## 6. 历史远程核心范围的估算（当前范围已变更）

### 范围前提

保留桌面 Bot 工作区、独立远程 Host、持久电脑与接管、多 Bot 直接通信和群聊、长期记忆、Skills 与示范学习、定时/事件执行、工具接入、审批、基本隔离和故障恢复。暂不实施手机、语音、公开市场、Team Bots 发布、独立企业管理门户和商业订阅。

预算按一个主要桌面平台和一种远程电脑部署方案，复用现有模型/Agent 内核、工具、企业身份及部署设施；连接器以 2～3 个目标系统及通用 Webhook 为假设，具体清单仍待确定。暂不新增员工本机执行桥、特殊硬件认证代理或自研虚拟化平台。现有 Cmb 支持的平台不能因修改而回归。这里是用户要求的条件估算，尚未开始实施，也不将全量清单中的可选项标为完成。

下表是未来新增规模的工程估算，包含移植后落入项目的代码；共享服务按主要归属计一次，不含已有 Cmb 文件的纯搬移。

### 新增与修改分别计量

| 计量项 | 估算 |
| --- | ---: |
| 移植并适配进入项目的产品代码 | 约 3 万～5 万行 |
| 新编写的整合、适配与功能缺口代码 | 约 2 万～4 万行 |

旧范围按约 7 万行新增产品源码、含验证和部署约 9 万行作过中值参考；当前原生本机范围不沿用此数作为承诺。不是精确报价或完成质量指标；电脑环境实际接入、示范学习泛化、Cmb 内核抽离及所选连接器会影响上下界。示范学习的效果还需要模型和真实任务验证，代码行数本身不能保证与原版相同。

因此对外可以表述为：**本地库约 21.1 万行非生成运行源码；把生成代码、测试和构建材料也算上，约 48.8 万行非空代码。** 此前第 2 节列的前端、Host、Electron 三部分不是整个库的总量，未包含 Agent 公共模块等。

旧的临时统计汇总曾包含 6,560 行 `.gen.*` / `.generated.*` 注册表；本次将其转入生成代码类别，总体代码没有因此减少。原第 2 节所列三个模块数值保持一致。

这是本地 0.18 非官方重建库的规模，不能据此推算官方完整产品、托管后端或模型服务的源码量。恢复源码中存在压缩行，也保留了公共工具实现；行数不能直接代表独有业务逻辑或开发工时。
