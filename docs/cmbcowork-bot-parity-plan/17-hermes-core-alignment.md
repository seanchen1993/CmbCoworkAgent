## 2. 新增功能与入口

### 私有技能维护

入口：Bot 资料库 → 私有技能 → **技能维护**。

- 可将指定技能纳入维护、固定保留、手动归档和恢复。
- 自动检查默认关闭；开启后也只处理明确纳入维护的私有技能。已有技能、共享库与安装技能不会自动获得维护授权。
- 默认每周检查、至少空闲两小时后运行；14 天未使用显示建议检查，30 天未使用可归档。新纳入维护、恢复、更新版本和重新配置后的观察窗口受到保护。
- 固定技能、未完成任务、正在录制的示范、仍在运行或等待停止确认的后台服务，以及启用或等待启用的例程所引用的技能，都受到保护。
- 归档保留原始步骤、历史版本、试跑证据和已发布的共享副本；当前版本停止作为可执行技能提供，恢复后可继续使用。
- 使用次数按实际 `read_skill` 读取记录（包含私有技能试跑的历史版本读取），同一任务重复读取只计一次，每次实际读取都更新最近使用时间；任务选择、排队和绑定技能不计作使用。
- 手动检查显示本次归档数量；超过单次处理额度时提示继续检查。

### 例程调度核对

入口：Bot 例程 → 执行历史 → **查看调度记录**。

- 显示原计划时刻及“已触发 / 合并到未完成任务 / 已跳过”，关联已完成、失败或待核对结果。
- 读取现有调度事件，不重新派发任务，也不创建第二套调度账本。
- 派发、入队和推进下一计划时刻仍处于原有事务中；回执写入失败时整体回滚。
- 停机错过的计划沿用现有合并策略；外部操作结果不明时保留待核对状态，不自动重放。

## 3. 存储与运行边界

- Schema 从 69 升至 70。新增维护策略、技能状态和实际使用回执表；升级前保存 69 数据库备份。旧数据内容、执行权和原请求回执保持不变。
- 实际使用回执随原运行记录删除而级联清理，统计更新与原技能读取记录共用事务。
- 自动维护接入原 Host 心跳：每分钟最多检查五个空闲 Bot、每个 Bot 每轮最多处理 200 个技能，余项留待下一轮。忙碌 Bot 在限额前被过滤，避免阻塞其他 Bot。
- 列表只读取有界元数据，不加载技能正文；例程记录分页读取。自动维护不消耗模型调用，没有新增定时器。
- 写操作验证 Bot 归属、当前版本、修订号和数据 epoch。响应丢失时使用原 nonce 核对，防止重复修改；备份恢复后旧界面操作失效。
- 新 UI 使用能力标识与旧 Host 兼容，沿用现有主题、图标、间距和减少动画设置。异步结果绑定当前 Bot、数据 epoch 和请求代次，防止旧请求覆盖当前界面。

## 6. 交付后复核与修正

此次源码复核发现并修复四处问题：

1. **重复读取时未刷新使用时间**：同一任务的使用次数仍只计一次，但最近使用时间跟随每次真实读取更新；同一时间戳的重复读取不增加持久行写入。
2. **私有技能试跑统计遗漏**：试跑读取历史版本的原有分支也记录实际使用，保留接受的历史版本，不替换成后续版本。真实执行图测试覆盖了两次分页读取与计数去重。
3. **归档错误码与旧逻辑不兼容**：归档复用既有 `skill_unavailable` 分类，同时给出明确的恢复提示。暂停例程可以继续读取和编辑，归档技能不能启动新任务，共享副本可独立使用。
4. **打开的面板可能停留在旧状态**：维护面板复用现有工作区事件游标刷新，只在展开且无未确认命令时读取；不新增轮询，不覆盖原请求回执。

以上修正已有针对性回归验证。正式安装包、Windows / K8s 原生环境及真实模型任务效果仍需在对应环境验收，不能从本机这些回归结果推导为完整生产验收通过。
