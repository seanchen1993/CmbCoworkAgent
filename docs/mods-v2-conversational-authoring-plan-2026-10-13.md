# 描述需求生成插件修改与项目节点组合

## 目标与边界

在 v30 基础上补齐普通用户仍须手改 Skill、寻找公开动作的缺口。唯一代码目录 `C:/ai/CmbCoworkAgent-mods-v2`，唯一分支 `codex/mods-v2`。保留既有未提交改动；UAT 与原 AutoBiz 只读。先两名 medium 评审通过，再实施相互关联的一批能力，集中完整回归。开发中仅做必要窄测。

## 用户完整流程

1. 选择 AutoBiz 等完整来源、填写新名称、创建独立副本。
2. 在“告诉我你想怎么改”填写业务目标，点“生成修改建议”。使用当前会话选定模型；无可用模型提示设置，不生成假成功。
3. 展示简短修改摘要、真实变化的技能文件、修改前后内容。用户可补充要求重新生成，或取消。此时副本、安装版本和项目均未改变。
4. 点“确认保存修改”才整体保存；随后检查、安装、启用、新建独立项目。手工源码编辑移至“高级修改”。仅修改说明备注不算生成成功。
5. “助手组合”增加“选择项目节点”明确入口。选择已绑定 AutoBiz 的项目，直接进入新需求的节点选择，不让用户自行公开动作或手写配置。展示真实节点的用途、输入输出和原顺序；选择目标节点后自动补齐必须前置节点，解释补齐原因，核对后创建需求并沿原入口执行。
6. 原节点组合使用同一项目绑定插件的原生流程，不支持把不同 AutoBiz 插件的状态文件混为一条链。已有“两插件一起使用 / 公开操作先后执行”保持可用，并用不同任务入口解释。此边界必须在界面和说明中清楚表达，不把普通公开动作流程冒充 AutoBiz 阶段链。

## A：真实模型生成与候选修改

- 在主进程提供独立的 `propose`、`applyProposal`、`cancelProposal` 能力，复用现有模型配置和提供者适配，模型只接收受限技能业务文本和用户目标，无文件/命令工具；不使用普通具写权限 agent，不产生聊天空消息或触发业务 Hooks。
- 只允许真实已存在 `skills/**/SKILL.md` 的业务补充和受限业务文本修改；初版保持原文本协议段落不删改，通过明确业务要求片段扩展实际 Skill，不能把 `MY-PLUGIN.md` 当唯一交付。结构、文件路径、命令与状态接口保持原样；宿主验证原有内容及原 frontmatter 完整保留，生成业务补充不得宣称跳过原检查。Hooks、脚本、工作流、状态机、身份清单、MCP、校验器字节不变。
- 模型输出严格结构化：摘要、文件路径、业务补充。只接受宿主提供的文件目录；拒绝路径逃逸、重复文件、未知文件、空修改、超限输出。模型输入不包含凭据、历史对话或无关代码。
- 上下文、输出、文件数、时间及并发均有界；用户操作才发请求，生成等待不持有副本写锁，取消可中断，失败可重试；无需全局轮询。
- 候选由主进程保存，绑定 window/frame/thread incarnation/workspace、copyId、baseDigest、请求ID；确认只传 proposalId，不信任 Renderer 回传修改内容。迟到/取消/切范围/来源改变均不得写入。生成期间可继续普通聊天。
- UI 保留按范围和副本划分的需求草稿，防止迟到结果覆盖新输入；逐文件展开差异。保存前再次核验整个副本摘要。已安装副本须再次衍生，沿用 v30 不覆盖在用包规则。

## B：整包确认与恢复

- 在既有 derivation mutex 内确认候选，复制原 snapshot 到同父目录的宿主暂存目录，仅覆盖候选修改，再静态检查完整包及受保护文件摘要。
- 发布前重新检查 scope、baseDigest、安装状态；不循环调用单文件 saveFile。使用同目录 source→backup、staging→source 的发布协议与持久恢复凭证，失败恢复完整旧目录。启动恢复只作用于宿主自己的副本目录，拒绝链接与越界。
- 更新 digest、status=changed、变更记录，撤销旧检查有效性；候选ID重复确认不得重复追加；恢复记录使中断后的文件与账本一致。安装仍走现有检查、create-only、启用和项目绑定。

## C：原生项目节点可视化组合

- 复用 `HarnessBoardView` 原新建需求/工作流表单与实际 `WorkflowNodeSelector`，通过范围绑定的一次性导航直接定位；目标项目必须属于当前可见授权目录，切项目后不重放。
- 从已安装并绑定项目的原 adapter 读取节点目录；现有宿主只有 templates 接口，本轮补主进程受限 closure adapter/IPC，将固定模式参数交原 AutoBiz closure 实现，绑定项目与安装来源并校验返回。不为预览执行未安装副本中的任意脚本。自动补齐依赖后展示最终有序节点，阻断必需输入缺失/未知/不兼容结果，仅允许并明确展示原目录声明的可选输入省略。没有原生支持的插件保留旧入口并说明原因。
- 确认提交完整闭包节点到原 `createHarnessFeature(workflowNodes)`，不只传用户勾选节点；实际命令提交前再次核验项目和源码指纹。实际开始仍走原会话、managed controller（如适用）、Hooks、阶段验证和人工审批。原生编译结果是事实依据，不允许模型或 UI 写 checkpoint。
- 真实 AutoBiz 的 `DETAIL_DESIGN.md` 为可选输入，即使完整前置闭包也可能未启用。双审认可兼容修订：仅原目录同节点同路径明确 `required:false` 的省略可通过，预览必须逐项显示；默认必需、未知路径或节点一律阻断。不改变原插件规则。
- 创建、预览不会自动执行；保存失败保留输入；原有项目模式默认表单、既有组合和 UAT 路径保持行为。
