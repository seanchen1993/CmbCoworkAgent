# 在自己的 Claw 中保留原有界面和操作

这一轮要解决的实际问题是：给回答、工具记录或提问加一段自定义说明时，仍然使用
应用原来的正文格式、展开操作、选项和提交按钮。以前主要是在旁边加自定义内容，
这一轮可以把原有内容放进组合后的布局里。

这一阶段的功能、真实桌面回检和性能检查已经完成。完整记录见
[阶段验收](mods-native-engine-stage-2026-10-05.md)。这不等于已经对齐 Claude 的全部功能；
跨插件替换组件的构造方式仍在下一阶段实施。

## 最容易感受到的例子

工程里的 `examples/native-content-wrapper` 是一个完整组件包。它为回答、工具组和
提问加上“我的 Claw”说明；下面的原有内容仍可阅读、展开和操作。

1. 把该目录内的 `plugin.json` 和 `hooks` 目录一起打包为 ZIP。不要再套一层文件夹。
2. 在 Claw 工作台导入组件，批准界面中显示的当前版本，再选入自己的 Claw 组合。
3. 保存组合并应用到一个项目对话。只保存草稿不会改变已运行的对话。
4. 在这个对话中正常发送任务。例如：“先查看项目结构，再给我三个改进建议。”
5. 回答上方会出现说明。执行工具时，原工具行继续显示；出现提问时，说明在上方，
   下面仍是原来的选项和提交按钮。关掉 Mods 后恢复原有界面。

这不是一个需要在聊天里输入名称才能启动的命令。它在这些界面出现时自动运行。
如果组合中的另一条规则已经把某块界面完全替换，它包装的是那条规则的结果。
规则顺序和是否保留后续内容共同决定最终效果。

## 作者只需写的代码

```ts
on("ui.render", async ($, event, next) => {
  if (event.component !== "AskUserQuestion") return next(event)
  const { Box, Text } = $.ui.resolve(event)
  return Box({
    flexDirection: "column",
    children: [Text({ children: "请确认后再继续" }), await next(event)]
  })
})
```

`next(event)` 表示让后面的规则和应用原来的展示继续处理，再把所得内容放在这个位置。
不要自己重新制作答题按钮，也不需要另写一条提交答案的接口。

提问只允许一套原有控件，而且必须位于组合末尾。可以在上方添加说明或交互组件，
不能重复放置、在下面添加内容，或用隐藏和裁剪布局遮住答案区域。老版本只添加说明、
没有明确放置原控件的写法仍有兼容处理，会自动在末尾补上原控件。

## 与真实任务的关系

这项能力调整的是展示。用户消息、模型收到的内容、工具执行参数、审批对象、
存储的结果和回答身份继续由原业务控制。改了显示文字，不会自动改变任务内容。
问答切换后，旧界面的按钮和组件不能再操作新的问题。

开启内容保护时，原生内容也经过保护。首次加载还没有安全画面时先等待；更新失败时
保留仍有效的上一份安全画面。不会因失败而直接显示未保护的原文。

本轮宿主版本为 v87，旧函数组件需要重新批准当前版本。传统 Plugin 项目模式和
原有 Harness 不靠这次函数授权运行，仍按原入口使用。

## 当前范围

支持本工程已有的回答、用户正文、工具详情和工具组、提问、输入提示、模式标签、
状态文字、耗时、通知、命令输出和面板位置。模式标签保留一个真实切换按钮；复杂
交互内容放在按钮旁边。独立交互组件不能自己嵌入原生位置。

超长正文、某些审批区域及未纳入这些位置的系统界面仍沿原路径显示。本轮不等于
整个应用所有内容都可替换或都经过模组保护，也没有补齐终端和远程界面。

本阶段验收文档分别记录实际 Electron 截图、受控回归和本地性能范围。
跨插件构造器替换尚未接入实际任务，不能把下面阶段的基础测试当作这里已经具备的能力。
