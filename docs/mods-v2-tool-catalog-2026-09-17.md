# Mods v2 真实工具目录与冷查询

基线 `51dbec50`，开发分支 `codex/mods-v2`，宿主修订 `desktop-tool-catalog-v18`。
仍以冻结的 Claude Code 2.1.273 为对齐依据。本批没有增加真实上游契约测试计数，
没有数据库迁移或新依赖；宿主修订改变后，旧摘要授权需要重新批准。

## 实现与底层边界

工具目录改为来自实际工具装配，而不是等待第一次模型请求。LangChain ReactAgent
合并显式 tools 和每个 middleware.tools；本工程采用相同来源投影 name/description/mcp。
主图构造成功后绑定现有私有实例；已知共享子代理使用各自 defaultTools、默认 middleware
和角色 middleware 的工具集合，在子实例执行前绑定。模型请求时仍更新动态目录。
注册工具继续由 FunctionSession 合并，未向 SDK 暴露原生执行函数、连接或凭据。

普通桌面冷会话通过生产定义工厂准备目录，共用 invoke/resume/interrupt 的前台工具开关。
Solo 不显示 task，桌面不显示默认禁用的 manage_skill；内存、LSP、MCP 与 deferred/code_exec
按当前设置决定。文件和任务工具仍由相同装配函数生成元数据；元数据模式的 backend 和
代理执行句柄明确拒绝执行，在 createAgent 之前返回，不构造模型、真实图、沙箱或实例授权。

冷查询使用真实 MCP snapshot 和共享 scopedMcpTools 规则；如需发现工具，可能初始化已配置
MCP 服务。它不调用 MCP 工具、不安装/覆盖执行绑定，也不关闭全局连接。仅供定义工厂读取的
接口拒绝 invoke、getTool、invalidate 和 close；查询完成前核对配置 fingerprint 与相关设置。
这些字段是查询快照，不构成调用许可；真实执行仍重新检查权限与当前工具定义。

只有普通桌面线程可走冷查询。已有 IM、scheduler、workflow 或子代理必须使用其实际运行
目录；冷 inbox、feature、定时和心跳会话拒绝推测普通桌面的工具。查询比较 workspace、
线程元数据、实例、绑定和目录版本，关闭会话或开始替代 runtime 会使在途查询失效。
查询句柄有 100 项上限并在 finally 释放，不能因从未构造 runtime 而漏掉关闭信号。

同时修复旧目录缓存达到 100 项时静默淘汰活跃条目：仅回收已过期条目，活跃容量满时拒绝。
清理时核对被清理项自己的运行身份，不拿当前 SDK 调用者身份误判其他代理。目录保留
原始名称供注册冲突检查，公开列表再按实际角色及构造时的禁用清单过滤。

- 37 项跨进程检查通过，Node/Web 类型检查通过。改动代码没有新增规范问题；原有
  runtime 显式 any 和 ipc/agent.ts 格式问题保留为基线问题。格式告警用未改动行与基线
  诊断范围核对，未把继承问题误写成全绿。

  均未放宽，最终冷查询用例单文件 5/5 通过后又扩展至 12 项并通过专项。
- 已补首次模型请求前的主/子目录、配置变化、取消、线程关闭、活跃查询容量、旧实例替换、
  cold transport 拒绝与已有远端目录直读。最终 Electron E2E 47/47 通过，普通构建已恢复。

  SDK 仍保留完整元数据。E2E 对比冷目录与首个真实模型请求的完整名称集合，查询不调用模型或写执行账本。
