## 目标与当前范围

在保留原项目、原产物与原检查记录的条件下，从一个可信的阶段进入快照创建独立调试分支。用户在原创作会话修改阶段实现，再确认新分支，复用原项目运行器执行目标阶段或后续阶段。

本次首先实现 Host 受控文件阶段。它是应用工具与文件范围约束，不是操作系统沙箱，也不声称能恢复数据库、发布、网络或 Git 状态。当前任何 `userConfig` / `userConfigSchema` 声明（含普通、空声明）、context 声明、Shared Mods 注册、MCP、动作或非空 Hooks 均会阻断调试；不会删掉这些行为后继续运行。

因此，现有 AutoBiz 的配置替换、动态知识、Hooks 与 workflow 尚不能直接进入这一调试范围；其完整阶段回退仍是后续目标。

当前恢复保证限于受控文件输入及明确核验的包依赖，不等于复现完整模型请求、原会话消息与记忆、动态 Mod 上下文、外部知识服务或非确定性模型输出。依赖这些输入的业务须先完成相应快照及映射协议，不能根据文件检查通过认定上下文完整或业务效果等价。

对应原方案 W9，本次接通受控文件场景的 L2 目标阶段隔离执行及 L3 后续范围重跑。受影响范围采用保守边界：只允许目标与后续未共享的 Skill 正文变化；新增、删除或调整流程节点，改变检查契约、配置或共享依赖时，需要对新候选从起点重新试用，尚未实现一般依赖图的细粒度失效与证据复用。

普通项目运行不依赖 S6 成功：单纯的快照捕获或存储初始化失败只记录诊断，不改变原运行器既有的执行与校验判定。原取消、来源和权限失效仍按原规则阻断。运行中、取消中、结果未知、未释放的操作不能作为可分支来源；已物理结束的失败阶段可以使用此前保存的进入快照，不要求先跑完整个流程。

历史分支显示其固定候选摘要。候选再次修改后，历史通过结果仍保留，但不会被解释为新候选已验收。单阶段范围检查通过也不等于整轮试用通过或插件业务验收完成。

重启后的未知分支可通过原生入口核对已有执行终态。核对要求真实原创作会话身份、持久分支归属、保留的固定包及操作记录一致，只读取实际执行终态并运行原文件检查，不注册试用、不恢复执行授权、不重新调用模型。没有可信终态时，即使输出文件已存在，结果仍保持未知，不能直接结束或重跑。

## 使用步骤

1. 在创造者模式准备 Host 项目并运行试用。新版本会在进入阶段时保存快照；没有历史快照的旧运行不能从当前产物反推出原始输入。
2. 打开“创作工作区 → 运行试用”，在原试用卡展开“按阶段修改与隔离调试”，选择阶段进入快照。高级入口位于“Mod 组件、聊天组合与高级制作设置 → 高级：独立项目试用 → 按阶段修改与隔离调试”。
3. 将修改要求发送回原创作会话，让助手保存新候选。保留共享知识、配置及检查契约；此次只调整允许变化的 Skill 实现。
4. 确认原运行已物理结束。若仍占用试用控制，按原入口停止、核对并结束试用；结果未知时先核对，不能直接重试。
5. 刷新、选择最新候选，选择“只调试所选阶段”或“重新验证后续阶段”，准备方案并在原生界面明确确认创建。
6. 在新建隔离调试分支的原生阶段操作区进行新的批准、文件操作确认和启动。查看真实检查及范围结果；效果仍不足时，继续使用原基线修改候选并创建下一分支。
7. 选中调试分支后，在其独立历史卡使用“结束此隔离调试分支（保留文件与结果）”释放试用占用。执行中或结果未知时不能结束；单阶段已通过的真实检查保留，不因结束试用而改为取消。
8. 如需核对产物变化，在所选分支的文件比较区域手动刷新。这里比较的是“阶段进入输入 → 当前分支文件”，不是两个执行版本的输出对比；正在执行、结果未知、包或输入发生变化时明确显示不可比较。
9. 局部效果满意后，在“运行试用”对最终候选完成整轮验收，再到“保存为插件”确认独立名称与版本，安装或导出。也可提前保存、安装或导出未完成验收的源码，但这些动作不代表验收通过；一次单阶段通过不计为当前候选整轮通过，正式使用前仍应完成整轮验收。

应用重启后，回到原创作聊天，或直接在工作区点击“重新进入创造者模式”，再查看保存的快照与调试历史。创作控制会话不会自动恢复，重新进入也不会恢复旧隔离分支的执行权限；旧分支仍保留重新确认限制。不能将未重新进入时的空创作区域解释为历史数据已丢失。

插件侧入口：在“添加功能 → 挑选使用 → 挑一个小帮手”示例列表中找到“阶段调试工作台”，点击“添加并使用”（已安装时为“用于当前聊天”），核对权限并确认应用到原创作会话。在插件侧栏入口打开工作台，刷新并选择快照与候选，准备方案，再请求原生复核。原生界面会重新读取事实并预选参数；用户仍需重新准备、勾选确认和创建。插件运行在原创作控制会话，不会因此允许隔离执行分支加载 Mods。接入协议及可调用边界见 [阶段调试 Mod 扩展协议](sparks/stage-debug-mod-extension.md)。

首次验证可以向创造者提出以下需求；这是创作输入示例，生成结果仍需通过正常候选检查和真实试用：

> 创建一个两阶段的 Host 文件审查项目插件。起草阶段生成 draft.md；复核阶段实际读取 draft.md，生成 reviewed.md，并设置各阶段原生文件产物检查。两个阶段使用不同 Skill，只使用 read_file、write_file、edit_file。此样例不声明用户配置、context、Hooks、SharedMods、MCP 或外部动作。先从起点完成真实试用，再让我修改复核阶段的表达规则，使用阶段进入快照仅重新验证复核。

若准备方案报不支持，先查看原生诊断。不能通过删除实际业务依赖来让现有 AutoBiz 包强行适用此样例范围；应等待相应公共适配能力完成。

不使用更改 checkpoint 文本、复制会话批准、导入绿色检查或更换显示状态来代替恢复和执行。

## 对开发方式的实际影响

| 对比项 | 上一步已具备 | 本次新增 |
| --- | --- | --- |
| 修改后的试用起点 | 创建新候选并从项目起点重新试用 | 在兼容性与隔离条件满足时，从原生保存的目标阶段输入开始 |
| 输入可重复性 | 保留原项目与实际执行记录 | 固定完整阶段进入文件，目标实现可变，输入基线及共享依赖保持不变 |
| 效果反馈 | 将整轮结果和反馈送回原聊天 | 针对具体阶段修改实现，独立执行所选范围，保留原结果供核对 |
| 检查可信度 | 原阶段检查与推进决定整轮通过 | 调试继续使用原检查、新批准和新回执，局部通过与整轮验收分开 |

因此，受支持场景可以减少重复执行未修改的上游阶段，并在相同文件输入下核对局部实现变化。这为缩短反馈周期和减少重复模型调用提供执行机制；本次未进行性能与 token 对比测量，不给出定量收益，也不以文件检查通过代替业务质量评价。

节约发生在反复调整局部实现的过程中；正式使用前应完成当前候选的完整验收。保存、安装或导出可以提前进行，但不改变验收结论。未来若要在最终验收中复用未受影响阶段的证据，需要额外的依赖、输入和版本等价证明，不能仅凭“代码看起来没变”沿用旧通过结果。

本轮同时优化通用请求预算账本：每次仍读取底层存储，仅复用原始文本完全相同的已校验历史，以写时复制更新当前记录；保留完整序列化、容量限制和原 CAS。缓存按真实设置对象隔离，每个对象最多保留 32 个键、4 MiB 原始文本，外部改写或 CAS 失败会失效。原 16×64 压力回归保持原超时，新边界回归验证引用隔离、外部改写、失败写入和容量淘汰。这是管理开销优化，不代表模型 token 或全应用时延已测得下降。

共享流验收另暴露两类开销：受控本地模型在完成 SSE 后仍下载外部分词表，以及来源读取反复拼接固定 SQL 列名。前者仅在集成测试 fixture 中明确采用本地辅助估算并禁止辅助外网请求，保留真实 HTTP、工具、检查点与全部原断言；没有改变生产模型的计费或估算策略。后者在通用原生来源读取器中预生成固定列名，每次仍查询实际 SQLite 并执行原校验。曾评估的 metadata 解释缓存被否决，以免固化源回调期间的伪解析结果；新增回归明确要求解析器恢复后拒绝坏代际。

## 与 Mods 的关系及后续适配

平台负责不可变输入、身份与版本、独立目标、原生确认、执行约束及真实证据。创造者负责依据反馈修改和组合阶段实现，插件声明实际流程、知识、配置与校验；这些职责不包含 AutoBiz 的文件名或业务 checkpoint 特例。

当前入口接入原生创作工具、工作区和有限 Mod 扩展协议。第三方 Mod 可以自行组织发现、方案准备和结果展示，并将用户引导到原生复核；创建、授权与执行仍由原状态持有者负责。尚未开放完整调试生命周期或订阅接口，不能表述为“任意 Mod 已能自行回退任意流程”。

后续仍需完成以下能力，不能记为此次已经交付：

1. **配置与知识映射**：在原生服务中筛选、冻结普通配置并生成跨分支映射证明；敏感配置、外部目录与知识快照重新取得适用范围的批准，不复制旧 grants。输入身份摘要不能代替配置正文。
2. **可声明的输入和副作用契约**：阶段声明读写闭包、上下文、校验和外部动作；平台验证并选择已受支持的适配器，不将声明本身当作安全证明。
3. **Hooks 与插件原运行器适配**：保留必需检查和人工门禁。AutoBiz 通过其原回退计划、活动批次和代码基线处理形成受控适配，不由平台重写业务规则；未知副作用不能自动补偿或重放。
4. **第三方调试 Mod 接口扩展**：在有限发现、准备和导航接口基础上，继续建设作用域受控的实时观察与订阅；不将通用动作成功当作执行批准。当前文件比较通过原生界面提供，尚未作为第三方接口开放。
5. **执行结果比较与调试分支恢复**：当前提供阶段输入与分支现状的逐文件摘要比较；两个执行版本的产物比较、重启后的重新确认执行以及更细粒度的依赖失效计算另行实现。
6. **证据容量管理**：补齐快照与分支容量可见性、受控清理和保留策略；被历史来源、活动操作、未知结果及租约引用的证据不能按年龄直接删除。

因此，本次是 S6 的首个受控执行范围，不表示 AutoBiz 阶段回退、任意 Function Mod 调试或全部 S6 验收目标已经完成。

下一轮优先完成版本化的输入与恢复适配协议，并用独立业务共同验收；随后接入普通配置与秘密引用分离、知识与角色上下文映射、必需 Hooks 的真实回执，再复用 AutoBiz 原回退计划及多 worktree 租约。平台负责通用身份、版本、隔离目标、授权和证据；`board_config.json`、Feature、`UI_CONTEXT.json`、活动批次和具体回退规则由插件或适配器解释，不能新增为平台业务特例。工作树进度展示已经具备的观测能力，不等于工作树恢复已经实现。

后续应扩展现有输入绑定、项目执行适配器与原运行记录，避免再建一套流程引擎。每项公共协议须至少由两个独立业务验证：缺少必需知识、配置失效、Hook 校验失败、活动工作树未结束及未知副作用时真实阻断；兼容场景保留原输入与产物校验，不能只以接口存在或静态清单完整验收。
