# 下一阶段：让模组接入真实配置

目标是让用户继续在原来的设置页改选项，同时让模组能列出这些选项、改善说明、限制或调整输入。插件作者也能声明自己的普通参数，上传后直接配置，不需要让用户编辑文件。此阶段不是再做一份没有实际作用的设置面板。

## 原版依据

官方 [插件配置声明](https://code.claude.com/docs/en/plugins/manifest-reference#user-configuration) 和校验过的 2.1.288 声明说明了 `userConfig`、`register(on, options)`、`config.describe`、`$.config.list()` 和 `$.config.set()`。本机原始资料位于 `output/claude-code-2.1.288-alignment-analysis-2026-10-03/`。

可读程序 `chunk-p8vbbyj7.js` 从真实设置行生成列表、执行显示说明的处理链，再让原写入器修改值。`chunk-7wjas382.js` 先保存插件参数，再尝试重新加载；不能马上加载时，明确提示已保存、稍后应用。原注册函数拿到的是当时的参数快照，不能假装旧函数闭包已经更新。

## 用户使用方式

- 原“Git 变更提示”开关继续保留，读取和修改同一份真实设置。模组可以改它的说明，或阻止、调整一次修改；页面必须显示实际保存的值和原因。
- 插件声明普通参数后，在已有右侧 Claw 配置区域增加参数表单，显示默认值、说明和当前值。保存后说明是否已经应用到当前组件；任务正在运行时不切断它的回答。
- 作者使用官方的 `userConfig` 和 `register(on, options)`。原包结构继续使用；普通值改变不要求用户重新批准代码。代码或字段定义变化仍必须重新批准。
- `$.config.list()` 返回当前真实可见设置行；`$.config.set({key,value})` 真实保存或返回拒绝原因。未知选项明确报错，不能返回假成功。

## 实现原则

1. 建立宿主自己的设置行清单，包含固定 key、类型、当前值、提供者、是否锁定及原写入器。首先接入确实存在的 `gitChangeNoticeEnabled`，不伪造 Claude 才有的选项。主题目前在界面本地存储，后续接真实界面桥后再提供，不填一个假的宿主主题。
2. `config.describe` 只允许改标签、说明和是否隐藏。key、提供者、类型、值、可选项和锁定状态都是宿主事实。隐藏只影响展示和列表，不禁止对这个真实 key 修改。
3. `config.set` 固定 key、修改前的值、提供者和来源；来源由真实界面或 SDK 入口填写。只允许调整待保存的值。类型不符、超过范围、锁定或处理链拒绝时零写入。SDK 入口跳过调用插件自己的整条配置处理链，其他插件继续参与；不能只跳过一个注册函数。
4. 界面和 SDK 共用同一写入器。最后保存前再次检查原会话、批准、设置版本、取消状态和当前实际值；同时到达的修改不能用旧值覆盖新值。写入失败不报告成功，不重复执行已经保存的修改。
5. 用户配置声明随不可变代码快照捕获。严格校验字段名、类型、默认值、选项、范围和必填条件。普通单值字段先闭合完整路径；敏感、多值及文件选择专用场景随后继续适配，不能送进普通配置处理链或把明文密码放进列表。它们是后续适配项，不是框架无法实现。
6. 参数值保存到宿主配置存储，和代码批准分开。新注册前从真实存储重新解析，填默认值；不合法的选择值按原版默认规则处理。必填项缺失时在加载前明确指出，不执行插件。原 Claw 组件参数保持原快照和组合规则，不能混作官方 `userConfig` 或让配置修改扩大能力批准。
7. 保存成功后返回真实确认，标记参数版本。不得在 `$.config.set` 尚未回传时销毁调用者。当前处理链保留原快照；下一安全外层入口或空闲点自动重建，期间页面明确“已保存，当前任务结束后应用”。应用失败保留已保存值并给出重试入口，不声称旧组件已经采用新参数。
8. 证据与检查结果立即标记配置已变化，不能继续展示旧配置的通过结论。重建只关闭自己的旧组件资源，不认领其他原生任务；撤权、切项目和配置变化继续检查原身份。
9. 原开关界面使用宿主回传的实际值更新，而不是把请求值直接填回页面。Mods 关闭或没有匹配处理函数时，沿用原保存行为。显示说明缓存如采用，必须包含真实配置版本和代码批准信息，支持 `$.ui.invalidate("config.describe")`；无法证明正确时先不缓存。

## 两位预审补充的落地约束

- SDK 列表和修改跳过调用插件的全部配置处理函数；SDK 说明不污染原设置菜单的缓存。`config.set` 明确固定修改前值、key、提供者和来源，显示说明不能改变类型或权限。
- 写入按实际存储作用域与 key 串行：全应用的 Git 开关使用全应用写入锁，不能按项目分别锁。最终检查当前值和私有版本；即使其他修改把值改回相同数，也不能误认原版本仍有效。严格读写失败向上报告，不能使用失败后默认返回开启的宽容读取证明保存成功。
- 宿主保存回执才证明已修改。重复 `next` 复用同一次保存；处理函数凭空返回 `{value}` 不能冒充保存，保存后也不能用伪造拒绝隐藏已发生的修改。实际界面使用最新真实回执，旧回执不能盖过较新的变化。
- 已有无 `userConfig` 的包继续使用原不透明 `options` 和 Claw 参数，不强加新的标量规则。普通参数声明必须严格校验；原版未必填、无默认的字段取未设置的空串，必填缺值拒绝加载。明确存储的 `false`、`0` 是有效值，不自动给必填字段制造它们；失效的字符串选项才按默认规则处理。
- 保存版本与实际运行参数版本分别记录。安全重建需要等待本会话所有已经入场的调用和流完成，不能仅等保存函数返回后在微任务里调用现有 `invalidate`。新组件构造成功后才替换并退休旧组件；失败保留旧有效版本，界面诚实显示已保存、等待应用或应用失败。相同值不重建。
- 配置保存立即使检查证据失效，并把参数保存版本加入真实检查配置摘要；同时取消或作废当前旧检查，不能只等待稍后文件监视重读。旧检查晚返回也不能把旧结果填成新配置的通过。已保存值的变化不修改代码/字段定义的批准摘要，撤权或切组合仍保留原设置版本检查。
- 新组件构造和替换继续复核原批准、不可变字段定义及当前真实 Claw 组件选择。参数只能调整声明的值，不能开启未选择的组件或获得额外工具权限。SDK 成功写入后广播原设置状态，让原 Git 变更提示和界面一起更新。
- 说明缓存只缓存标签、说明和隐藏状态，实际值每次读取；菜单缓存以加载版本及显式失效为边界，SDK 列表绕过该缓存。该语义在本阶段闭合，不把暂时不缓存作为最终完成。
- 敏感、多值、文件选择字段也严格验证声明和默认规则；没有适配真实专用输入前明确显示需要专用配置，必填缺值不得加载。不能忽略这些字段后把插件标作已完整配置。
- 普通配置的值、修改前值、标签和说明，在送入组件或页面前经过现有内容保护；缓存命中和返回同样保护并检查原身份。私有保存比较使用真实原存储值和版本，不能把脱敏后的公开值当作存储证据。敏感字段完全不进入普通列表及配置处理链。
- 检查证据采用同步作废及配置摘要复核。若保存参数的调用本身位于检查处理函数中，不立即取消它的父处理而切断已经保存的回执；旧检查不能发布有效证据，当前保存仍得到实际确认。

实施顺序为真实行与写入回执基础、非敏感声明与持久值、处理链和 SDK、原界面与参数表单、安全应用和证据失效。每一部分使用同一底层清单，不新建并行设置存储。

两位独立方案评审已通过以上正式约束，开始基础实现。此处记录的是方案通过，不表示尚未写出的界面或运行时已经验收。
