# Mods V6：关键能力链路补齐

本次在 `codex/mods-v2` 开发分支继续，兼容证据固定为本地 Claude Code
2.1.283 提取的声明和实现。目标是能实际运行的 DIY 流程，不以新增接口名称冒充完成。

## 实施范围与验收

1. 标准环境：AbortController/Signal、structuredClone、密码学随机数、摘要、单调时钟。
   用真实 QuickJS 和 Electron utilityProcess 验证；原有 CPU、内存和权限边界保持有效。
2. 会话和文件：真实应用版本、固定项目根、Markdown ancestors/include。
   文件读取继续走授权、稳定读取和内容发布保护，项目外路径明确拒绝。
3. HTTP：最终请求逐跳批准；请求重写后重新校验，重定向剥离敏感头，取消销毁连接。
   不把尚无凭据保险库的 auth 或 Unix socket 伪装成已实现。
4. 资源基础：模块生命周期与单次调用生命周期分开；独立资源通道只允许资源消费、
   关闭及明确列出的后台展示，不恢复过期 next、文件写入或模型调用权限。
   资源随插件卸载、撤权、会话关闭和宿主退出清理，全部资源有数量和缓冲上限。
5. 时钟：after/every 返回可取消句柄，回调在新调用帧执行；取消、拒绝和重载可观测。
6. 进程：argv 无 shell 执行、真实主机命令权限批准、输出背压、退出结果、提前结束和进程树清理。
   process.spawn 的资源拉取不继承已经结束的 hook RPC。
7. 消息及 Agent：以真实宿主能力为准；插件消息保留来源，不写成人类消息。
   send/receive 的拒绝、改写和消费必须在入队前生效，Agent 启动与完成分离并保留租约。
8. 自定义角色：`agent.register` 使用会话内、插件命名空间注册表；启动前冻结定义，
   原生批准后启动独立子任务。工具集合取父权限、宿主权限与角色限制的交集，
   maxTurns 在真实模型调用入口计数。冷命令先完整支持无工具的角色，避免虚构工具目录。
9. 作者工具：闭合 `manifest.types` 快照、生成本机支持子集、隔离类型检查，
   无类型声明的普通插件不增加 TypeScript 加载成本。

## 两轮评审

每项在实现前由 feasibility 与 quality 两位 agent 独立检查契约和安全边界；
实现后再次检查最终代码和失败路径。标准环境、只读接口和 HTTP 已通过方案评审。
资源协议、消息链路在各自具体设计审查通过后接入。

收尾评审通过：取消等待批准的进程、ACK 竞争、完成审计收尾、子 Agent 失败回收、
注册角色审批快照/工具限制/轮次上限、消息来源和真实消费、跨插件撤权。
peer 中间件曾增加图节点并造成既有 12 次递归预算失败；已折叠到已有生命周期回调，
保持原预算与原消息队列约定，通过原回归后才进入最终验收。
最后的冷命令方案也经两位 agent 复核：仅显式普通命令可创建短暂宿主身份，必须验证原始
物理租约、配置版本和授权；等待串行绑定期间出现新主运行时则拒绝。启动结束释放父身份，
不传递父写入上下文给独立子任务，不虚构工具目录。

`env.set` 不在本轮交付范围：会话隔离环境及共享 MCP 池需要单独架构迭代，
只实现进程局部 setter 不能兑现上游承诺。进程逐次 env 参数已支持。

## 验证与报告

先运行新增边界/取消/失败回归，再运行 Mods 兼容集、真实 utilityProcess、Electron E2E、
Node/Web 类型检查、生产构建及全量测试。全量结果与 V5 基线逐项比较；不修改旧断言
掩盖失败。性能检查关注空闲成本、资源数量、队列上限、关闭后残留、主线程阻塞。
交付报告列出真实接通、有限适配和仍不可宣称上游完全等价的项目，并给可操作示例。
