# 原生插件聊天组合：统一作用域实施方案

> 2026-10-14 范围更新：用户已明确组合在项目模式的对话内使用。后续以
> [项目内能力与流程组合方案](mods-v2-project-composition-plan-2026-10-14.md) 为准。
> 本文保留为历史分析，不再作为普通对话扩展的实施目标。

日期：2026-10-13  
状态：技术方案，未交付普通聊天双派生插件自由混搭。目录展示和原项目节点选择不等于聊天执行已支持。

## 1. 已有能力与缺口

当前代码提供了可靠的局部基础：

- `src/shared/mods/claw.ts`：保存的 Skill/MCP 来源包含 id、name、digest，应用组合有 revision/bindingRevision。
- `src/main/mods/claw-skills.ts`：Skill 来源由宿主解析，可限制文档读取和生命周期来源；当前来源 digest 主要约束技能文档，不代表整个脚本、Hook 和依赖包。
- `src/main/mods/claw-mcp.ts`：对工具调用和显式连接做选择校验；它借用底层连接池，不负责隔离底层连接建立。
- `src/shared/skill-visibility.ts`：派生插件仍要求绑定项目；不能直接放宽此判断作为组合实现。
- `src/main/hooks/scope.ts`：记录已激活插件/技能和持久 Hook，派生家族按绑定项目冻结。
- `src/main/plugins/runtime-source-scope.ts`：提供主进程 opaque token、线程 incarnation、子任务登记和延期生命周期继承，但当前来源绑定是单插件。
- `src/main/mcp/capability-service.ts`：当前派生过滤基于单个 boundDerivedPluginId。

因此，下拉框出现原生插件、技能目录可查看、Claw 保存成功，都不能证明 Skills、Hooks、MCP 在普通聊天内已按同一组合执行。

## 2. 能力必须先分类

| 类别 | 展示与选择 | 执行约束 |
| --- | --- | --- |
| 可复用技能 | 逐个选择，显示插件来源和技能名；同名技能不可按名字自动合并 | 宿主确认独立运行契约、内容与依赖快照，保留技能激活触发的原 Hook |
| 项目节点/阶段技能 | 显示所属绑定项目，跳转“组合项目步骤” | 在原项目引擎内运行，自动补齐前置节点、检查和人工确认；不能混排两个项目的阶段 |
| 插件级 Hook | 展示事件、触发条件和作用范围，作为选择技能的必要影响 | 不改事件/顺序/matcher/once/超时/返回处理；项目必需 Hook 不允许拆除 |
| MCP 连接器 | 展示服务名、所属插件及依赖关系，可逐个选择 | 选择目录不连接、不试跑；连接和调用继续经过原授权与宿主作用域检查 |
| Mods 可组合组件 | 沿用已有组件契约 | 保留已有摘要、配置、权限、互斥入口检查 |

“包含 SKILL.md”不足以认定可独立复用。宿主应解析现有项目元数据、节点引用、执行入口和已审计适配声明；无法确认是否依赖阶段上下文、项目状态或必需 Hook 的技能标为“需绑定项目”，不能悄悄按普通技能执行。

分类依据必须绑定安装身份、包内容摘要和适配规则版本，不能仅信任插件自己声称“安全/可复用”。可支持作者声明依赖，但宿主负责验证，无法满足的依赖禁止应用并给出可理解原因。

禁止“添加插件”自动选择全部技能、全部 Hook 和全部 MCP。用户选择一个技能时，系统展示它实际需要的依赖集合；若必须带入不可拆项目组，就转到原项目入口，而不是关闭检查后执行。

## 3. 最小可交付交互

1. 在同一目录卡展示插件概况、可复用技能、项目步骤、原有 Hook 和连接器，明确“目录”和“当前聊天已选”的区别。
2. 用户勾选具体可复用技能；默认不勾选兄弟技能。已有选择由真实当前聊天快照恢复。
3. 预览增加/移除的技能、必要 Hook、MCP、来源摘要变化及冲突。模型选择、已有流程、完成规则和无关能力保持原值。
4. 明确确认后保存并应用当前聊天组合；应用操作不触发模型请求、Hook 运行或连接器连接。
5. 保存修订与插件版本分开显示。运行中不得替换当前冻结组合；下轮使用新组合，撤权则阻止后续执行。
6. 项目步骤始终保持绑定项目、模板和阶段检查；入口不得把两个项目流程的自由混排描述为已支持。

## 4. 统一执行期作用域

新增主进程专用 `RunCapabilityScope`，与现有单插件项目 token 协同，而不是把 renderer profile 当运行授权。

建议冻结字段：

- threadId、thread incarnation、workspace 规范化身份、run/operationId、bindingRevision。
- 显式准入的插件集合：pluginId、packageDigest、宿主 sourceRoot、目录契约摘要。
- 精确技能引用集合：sourceId、skill digest、所属插件、依赖组身份。
- 必需 Hook 身份/内容摘要/原执行顺序，MCP provider 身份/配置摘要。
- scopeFingerprint、撤销代际、父子任务准入关系。
- 若处于项目模式：不可移除的 bound project、模板、stage 和原检查组。

宿主从安装目录、用户已确认的精确来源以及当前授权重建上述集合。来源根目录、原插件身份和家族关系不得由 renderer 提供。对外只给目录与预览信息；真正运行传递主进程 opaque token。

每个顶层运行都必须明确建立或清空作用域，避免 AsyncLocalStorage 继承上一任务。子任务按宿主登记的 incarnation 显式继承允许集合，不能扩大；延期 SessionEnd、HITL 恢复、重启恢复不得从不可信 metadata 猜测重建授权。

应用新组合只影响新运行。撤权、卸载、内容更新、线程/工作区变更在文档读取、Hook 执行、MCP 连接和调用边界使旧授权失效。若使用固定保留包允许已有运行继续，则该保留策略需明确且与撤权策略分开，不能静默回退到当前安装目录。

## 5. 三条执行链必须一致

### Skills

- 发现、提示词注入、技能文档/资源读取、路径/别名解析、显式技能调用、生命周期注册都消费同一作用域。
- 以 pluginId + canonical sourceId 标识，重名只影响展示，不复用同名来源。
- 技能摘要要覆盖将要读取/执行的资源依赖；仅固定 SKILL.md、却允许脚本在确认后改变，不足以证明同一版本。
- 保留 `ClawSkillPolicy` 现有路径/禁用检查，新增 scope 准入检查；不能因为目录可见而跳过 derivation/project 判断。
- 避免一轮内反复扫描整包：运行准入固定摘要，使用前做目标内容/安装代际复核，外部改动不能被缓存掩盖。

### Hooks

- 技能激活只引入该技能准入契约要求的插件/技能 Hook。必须保留原匹配条件、顺序、审批和错误语义。
- 未选择的兄弟技能 Hook 不得因全局启用插件而全部加入。若原插件 Hook 契约本来是不可拆的包级链，预览明确整组；不兼容普通聊天则要求原项目运行。
- `filterScopedHooks`、实际 command 执行和持久 Hook 恢复都要验证 scope，不只筛选一次目录。
- once/persistent 标识包含插件身份、内容摘要、运行 scope，避免两个派生版本彼此抑制或复用旧回执。
- 不通过删除 Hook、改弱检查、更改 state/checkpoint 或冒充阶段成功实现“组合”。

### MCP

- 来源准入发生在连接之前，不能先启动所有服务器再过滤返回工具。
- providerKey 使用插件稳定身份；工具别名重名必须消歧，不选择首项。
- 实例/缓存以 scope 指纹、来源摘要、配置代际和连接代际隔离；仅在授权集合等价且生命周期允许时复用底层连接。
- 选择目录不获取凭据、不连接服务。连接、调用和回执检查保留现有审批、取消、超时、断线代际保护。
- 两个聊天并行使用不同组合时，关闭一个 scope 不应关闭另一个仍使用的客户端，亦不能把另一个聊天的工具目录泄露进来。

## 6. 必要接口清单（拟议，尚未实现）

| 层 | 接口/类型 | 必须保证 |
| --- | --- | --- |
| shared | `NativeCapabilityCatalogEntry` | kind、plugin identity、digest、reusability、dependencies、project constraint；不暴露可写 sourceRoot |
| shared | `NativeCompositionSelection` | 精确 skills/MCP 引用，不用“全选插件”代替能力集合；旧 profile 缺字段默认不新增派生授权 |
| IPC | `nativeCapabilities.catalog(scope)` | scope 对齐；只读目录，无模型、Hook、连接器副作用；错误项局部可见 |
| IPC | `nativeComposition.preview(scope, expectedBindingRevision, selection)` | 返回新增/移除/必要依赖/冲突、精确摘要及有限寿命预览身份 |
| IPC | 扩展 `clawChange` 或单一 apply 接口 | 接受已核对预览与 CAS；原子写入，不先启用全局插件后再尝试聊天 apply |
| main | `resolveNativeComposition` | 校验安装、授权、分类契约、依赖闭包、项目不可拆组与冲突 |
| main | `issueRunCapabilityScope` / `withRunCapabilityScope` | 只能宿主签发，绑定 incarnation/运行/目录摘要 |
| main | `assertScopeSourceCurrent` | 文档读取、Hook 命令执行、MCP 连接/调用前后重新检查身份与撤销代际 |
| main | `registerScopeChild` / `captureScopeToken` | 子任务显式准入、延期生命周期使用原 token、销毁后不可再调用 |
| main | MCP scope service factory | 连接前过滤及缓存隔离，不能仅扩展返回工具列表 |
| persistence | 保存 profile / 运行 scope receipt | 保存和运行分离；重启恢复重验安装/摘要/授权，不自动扩大到“all” |

优先复用现有 Claw 来源 ID、CAS、skill policy 和 MCP refusal 语义，不另建第二套互相不一致的组合存储。新字段需要严格 parser、大小上限、重复引用与依赖循环检测。接口名称是设计建议，不表示已经存在。

## 7. 推荐实施顺序与交付门槛

### A. 目录与项目入口

展示原生能力分类、安装状态、当前聊天选择和绑定项目入口；来源更新显式检查，普通打开不读整包。保留全部原运行边界。本阶段只能称“目录与项目入口统一”。

### B. 可复用技能聊天通路

先支持有明确独立运行契约的少量技能，逐个选择，完整贯通真实文档读取/调用、所需原 Hook 和来源摘要检查。禁止用一键全启用跳过依赖分析。不能独立运行的技能继续留在项目入口。

即便 B 只包含技能，也必须将该技能实际带来的 Hook 副作用纳入预览与执行作用域；不能把 Hook 留给无范围的全局开关。

### C. 多插件依赖与 MCP

引入共享作用域和依赖闭包，在两个实际派生插件间验证多技能与 MCP 配合。项目节点仍不跨项目混排。完成此阶段后才可称受支持能力范围内的“原生插件聊天组合”。

### D. 生命周期与原链差分验收

验证子任务、取消、恢复、重启、更新和撤销；同一原项目输入对比原入口与新入口的 Hook/检查事件记录和产物，所有必需检查保留。无法覆盖的真实外部连接器、模型或业务原链明确列为未验收。

## 8. 回归矩阵与性能约束

- 两个派生插件，各选一个可复用技能；同名技能/工具仍按宿主身份执行。
- 未选择的兄弟技能和 Hook 不加载、不执行；缺必要 Hook/项目上下文时拒绝，不自动降级。
- 两聊天并发使用不同组合；切聊天、隐藏再返回、晚到 IPC、销毁/重建同 threadId 不串作用域。
- 来源内容、脚本、Hook、MCP 配置在预览后变化；apply 或运行拒绝旧摘要，不能自动授权新版本。
- 应用时 busy/CAS 变化只失败并保留现状；不产生部分全局启用状态。
- 撤权/卸载/更新发生在 Skill 读取、Hook 等待审批或 MCP 正连接时，后续执行按明确策略停止。
- 子任务与延期 SessionEnd、HITL、进程重启保留准确身份；不能借旧 metadata 获得来源。
- 两套同族项目原链仍只使用各自绑定包；模板必需节点、阶段检查和 checkpoint 无变化。
- 目录打开不发送模型请求、不执行 Hook、不连接 MCP；来源全量检查只在显式动作或必要准入边界执行。
- 单次全量快照已有限额（64MiB/4096文件），还需有界并发/取消过期读；避免连续重入累积 Buffer。
- 单测覆盖纯分类/依赖/CAS，IPC覆盖主进程身份，浏览器覆盖状态与确认，受控端到端覆盖实际技能/Hook/MCP执行；不使用真实业务或凭据补齐测试证据。

## 9. 当前账本应记录的边界

截至本方案编写，已交付的是宿主通用流程入口、官方示例真实状态、派生生命周期相关修复及其已有测试；原生目录后续修改以各自代码和测试报告为准。

普通聊天中任意两个派生原插件的 Skills/Hooks/MCP 自由混搭没有被本方案实现或验收。仅有目录可见、选项可保存、visibility 放开或静态测试通过，均不构成该目标完成证据。
