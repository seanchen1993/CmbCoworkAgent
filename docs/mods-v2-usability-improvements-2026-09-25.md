# Mods v2 核心易用性完善与验证

日期：2026-09-25。开发工作树：`C:\ai\CmbCoworkAgent-mods-v2`，分支：`codex/mods-v2`。起点为 `e81a634a`。本轮按用户要求优先实现主要目的，复杂、低收益的兼容边界暂缓；没有修改或合并 UAT，没有发布新安装包。

后续修订：本文保留 9 月 25 日的验证记录。9 月 26 日全面检视发现普通存储键兼容和不必要探测等问题，已按[两位 agent 批准的方案](mods-v2-review-optimization-plan-2026-09-26.md)修正。当前使用方式以[项目完成检查规则](mods-v2-application-completion-rules.md)为准：不再保留独立 `completion-config-source` 元数据键，普通同名数据照常读写；规则来源仅作为专用配置读取结果的界面提示。环境检查改为独立按需调用，普通配置读取不再启动外部进程。

## 用户实际能感受到的变化

1. **配置有快捷入口**：在「自定义 → Function Mods → 对应插件 → 完成检查规则」选择「只给检查报告」或「修复后再完成」，保存即可配置主要完成行为。前者评审本次改动并给报告；后者评审、运行单元测试，失败时请求原 Agent 修复后复检。模板不自动提高预算、不自动授权，也不自动推进业务阶段。
2. **配置入口不再互相冲突**：应用规则生效后，`/kanban` 显示只读规则及修改入口，不再展示会保存失败的编辑控件。应用接管发生在面板打开之后时，也会给出可理解的提示。尚未保存应用规则时，原插件内编辑方式保留。
3. **项目切换不再串表单**：项目 A 的保存请求迟到，不会覆盖项目 B 的草稿、保存提示或下一次保存内容。读取请求也按先后顺序丢弃过期响应。
4. **Autobiz 在配置时检查基础依赖**：缺少 Git、固定源码提交或 Python 3 时说明如何修复，不能新选不可用检查，但可取消旧选择或关闭规则。普通代码检查不受影响。源码目录可通过 `CMB_AUTOBIZ_SOURCE` 指定，Python 可通过 `CMB_AUTOBIZ_PYTHON` 指定，修改环境后重启应用。
5. **结果先给摘要**：折叠状态能看到下一步、修复请求轮数或阶段推进结果。重复推进明确显示「未重复写入」；仅报告模式显示「报告已记录」，不把允许任务结束误写为检查全部通过。详细证据仍可展开核对。

「当前文件」改成准确的「指定文件或目录」；范围无关字段隐藏；时间和 token 上限移入可展开区域，并解释输入、输出和修复上下文都计入预算。

## 体验步骤

使用本工作树的开发版本或当前构建；已安装的旧应用不会自动包含这些变更。开发启动命令为本目录下的 `npm run dev`，遵守项目 Node 版本要求。

1. 打开有真实代码和测试的项目任务，安装/更新具备代码评审处理器的 Mods，例如本工程 Autobiz 示例。更新插件源码会改变摘要，按界面重新授权。
2. 解锁 Function Mods 设置，明确开启应用总开关和项目 Mods，并授权该插件。
3. 打开完成检查规则，选择「修复后再完成」。检查范围默认是本次代码改动，检查项为代码评审和单元测试。打开「时间与用量上限」确认适合当前任务，然后保存。
4. 运行一个修改代码的任务。检查失败时，应看到修复请求和新一轮检查；最终查看任务底部摘要。要对比效果，将模式改为「仅报告」并保存，或明确关闭规则后运行对照任务。
5. 使用 `/kanban` 查看规则来源及项目产物。应用保存过规则时，在应用设置修改，再点击看板的「刷新真实状态」。

若需要验收后推进，看[项目完成检查规则](mods-v2-application-completion-rules.md)中的可选阶段配置。阶段起点仍需要按实际 Feature 工作流填写，未提供全自动工作流设计器。基础依赖就绪不代表项目产物或验收已经通过。

## 性能与暂缓范围

本轮性能检查为入口冒烟，1 轮、每组 100 样本、10 次预热，不是正式矩阵。单插件 p95 约 13.95ms；项目关闭对照约 -0.014ms；全局关闭对照约 +0.412ms / +21.33%，超过既有 5% 门槛。两种关闭状态均无插件发现和 runtime 启动。不能凭冒烟退出 0 声称性能达标，也不能凭小样本归因于本次修改。

原正式报告中的桌面首字延迟、长稳内存稳定性仍未关闭；本轮没有重跑两小时长稳或宣称解决内存问题。依赖探测仅在读取配置时执行，同时请求合并、单个外部探测限时 3 秒，不添加后台轮询或任务执行热路径探测。

按本轮范围暂缓：Claude Code 全量 API/UI 等价性、非 Windows 阶段提交、整个工作区原子事务、未知提交自动回放/回滚、环境自动安装、完整 Feature/阶段选择向导。这些不妨碍当前受支持环境中的“检查 → 修复 → 复检 → 按明确配置验收推进”闭环，但不能继续称为全量对齐。
