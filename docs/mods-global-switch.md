# 灵件开关、权限与统一使用入口

当前版本使用“自定义设置 → 基础功能 → 灵件与使用设置”，默认展示“我已添加”。
聊天工作台提供同名按钮。无需进入高级自定义，也没有旧版实验管理口令或逐窗口解锁步骤。

需要开启时，在带本地目录的目标聊天点击“启用应用和当前项目灵件”。这次明确操作复用
现有应用和目录开关，保留当前回答保护设置；不会切换到创造者模式、批准新源码、改变
原插件启停状态或自动执行任务。开启应用总开关会恢复其他已经批准且满足使用条件的灵件。

以下设置有不同范围，统一入口并不将其合并成一个授权：

| 设置 | 范围与作用 |
| --- | --- |
| 插件启用 | 整个应用的来源插件，影响其技能、工具连接、Hooks 和扩展；安装不等于启用。 |
| 应用灵件开关 | `modsGlobalEnabled`，新用户目录默认关闭；控制全应用灵件运行。 |
| 项目目录灵件开关 | 按规范化项目目录保存，使用同目录的聊天共用；不是仅当前会话生效。 |
| 精确源码权限 | 按项目与源码摘要核对，更新或替换源码后需重新检查；开关不能代替授权。 |
| 聊天搭配 | 为具体聊天选择已授权功能，不会自动创建项目，也不能扩大源码权限。 |

应用开关和目录开关仍可分别调整。关闭后保留安装文件、目录设置、授权与聊天绑定；
对应灵件停止运行，旧命令与待执行动作失效。重新开启按当前源码及有效授权创建新运行
上下文，不自动重放未知结果。普通原生功能继续走原生路径；依赖必需 Function Mod 的
项目操作仍会检查灵件条件，不能保证所有项目在关闭后继续执行。当前开关也不撤销
插件此前已经产生的文件修改或外部副作用。

安装和卸载无需开启灵件总开关。在“我已添加”选择完整 ZIP 或文件夹安装，核对来源
名称与版本；安装后再按卡片完成启用、参数、准确源码授权与使用入口检查。卸载必须
确认，移除整个来源插件及其注册内容，其他插件保留。聊天记录不因卸载而删除；保存的
搭配和流程模板仍可能引用已移除的来源，复用前须重新核对。审计和持久状态不因卸载
自动清空，不能把卸载当成清除全部历史数据。

验证时应使用隔离用户目录：默认开关关闭且可直接进入统一设置；浏览、导航不改开关；
明确开启才写入应用和准确目录，保留最新回答保护；目录、聊天或账号变化后不继续写入
旧目标；恢复异常时拒绝开启。然后分别验证实际授权、插件停用、全局关闭、重新开启
及卸载后的旧命令失效。不能仅以界面显示“已开启”证明业务运行通过。
