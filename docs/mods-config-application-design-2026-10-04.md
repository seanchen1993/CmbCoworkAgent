# 参数安全应用：实现细化

本节细化已通过两位评审的参数方案。保存成功和实际应用分开：保存返回真实回执，不等待自己触发的重载。原任务保留原参数，后续安全入口应用新参数。

## 活动与应用顺序

- 每个真实会话有私有活动门，不使用虚拟机或 IPC 自报的活动数。宿主调用、匹配器、插件调用和它们的每个宿主回调，从真实入场到 Promise 的 finally 都计数。
- 宿主统一包装会话业务入口，覆盖方法开始到最后的内容发布。嵌套操作钉住同一会话；同步方法保持同步，异步方法保持原来的错误和返回类型。调用返回流后，占用保留到迭代真正结束、return/throw 和清理完成，不用 result 提前完成冒充结束。
- Flow 范围保留到 dispose；完成检查返回的检查函数每次实际执行时保留。插件进程和后台助手在启动回执之后继续持有占用，直到真实结束通知与清理完成。
- 原生助手用真实执行租约和任务生命周期判断忙碌，覆盖两次模型调用之间的空档。取消、失败、完成和暂停恢复沿用已有身份，不能只看到没有流就换组件。
- 计时器只计已经进入的回调和处理函数；永久调度循环不是永久占用。应用开始后停止旧实例的新回调入场，已经开始的调用继续完成。
- 优先采用空闲时立即暂停的门：只有真实活动数为零、没有原生任务占用时，才同步暂停入场并开始候选构造。忙碌时继续原实例并显示等待，避免保存操作和自己的旧处理函数互等。暂停期间新宿主业务等待应用；控制回执和既有嵌套调用不能被新业务队列卡住。
- 私有候选使用独立进程、完整代码与参数快照，绝不提前写入当前会话清单。最后复核原实例、项目代次、代码批准、组件选择和所有参数版本，一次替换；然后只关闭自己的旧资源。撤权、切项目、参数再次变化或失败都销毁候选并保留正确状态。

## 启动期间的效果

候选完整执行实际注册和启动步骤。允许本实例的命令、工具、助手注册，以及既有获准范围内的只读读取；不得重放文件写入、存储写入、模型调用、工具执行、网络访问、启动进程/助手、用户输入、界面修改或配置保存等外部效果。

使用宿主私有的拒绝标记：任意不允许的尝试，都使候选失败，即使插件捕获错误、处理链恢复或伪造成功。启动中的任意处理函数异常同样严格失败，不能丢了命令仍标记成功。只读读取仍检查原批准和项目边界；注册不得扩大工具和组件权限。

失败显示真实“参数已保存，应用失败”与重试入口；保留旧实例。需要启动效果的插件提供明确的重启方式或作者迁移提示，不能因为安全热更新未完成就声称整个框架无法实现。

## 必须验证的反例

保存自身 SDK 回执不中断；正常任务连续两个模型流之间不换参数；流 result 先完成而迭代尚未结束时不能退休；真实宿主回调撤销后仍在 finally 时不能退休；进程与助手启动回执不等于完成；永久计时器不能永久阻止应用；Flow 等人期间保持身份；候选捕获禁止效果和可选处理函数恢复也失败；多包加载中参数变化、代码变化、组合变化、撤权与切项目零采用；应用失败旧实例可用；重复参数零重载；实际注册拿到新参数后才显示已应用。

本文件记录可实施方案，不表示安全应用已完成验收。最终仍需两位实现复审、真实 Electron 使用及性能回检。

## 源码采用检查的性能修订

实际 8 个插件、每个 128 个模块、总计约 15MiB 的压力测量中，逐文件重复解析整个真实路径耗时中位数 2038 毫秒。这不满足桌面使用需要；不能通过放宽测试阈值当作优化。

保留逐文件内容哈希和全包检查至采用之间没有异步等待的原则。编译时，从原稳定文件句柄同时保存设备与文件身份；采用时先验证打开的文件就是这个原身份，再读取。仅在这一次同步检查内共享父目录验证结果，检查非链接、目录身份及项目根；文件逐个检查名称、句柄身份、大小、哈希和读前读后的变化，结束再次检查父目录及缺席候选。不同文件即使内容相同也拒绝。缓存不跨检查、不由插件提供，不用只比较修改时间替代内容复读。

验证包含：原文件内容变化、同内容替换文件、父目录替换/链接、缺席候选出现、共享父路径、Windows 大小写、8 包压力及普通小包耗时。本边界保证宿主采用前所检查的来源，没有声明同时阻止外部程序的文件系统修改；这与原有文件边界一致。
