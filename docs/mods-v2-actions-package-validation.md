### 修复范围

- 稳定聊天授权上下文及导航器子树，避免输入、流式更新或滚动标记变化反复刷新整段历史。
  授权撤销、配置变化和工作区切换仍同步使旧票据失效。
- 历史虚拟列表按完整消息身份保留连续窗口及测量位置；分页、裁剪、重排和切换聊天有
  各自边界。取消固定短消息高度估计，使用虚拟列表原生测量及公开的相对索引定位接口。
- 组件卸载不再强制读取 Range 布局；挂载期间集中采样几何。用户长消息溢出使用
  ResizeObserver 提供的内部尺寸，保留折叠、展开、重新挂载及授权后替换的行为。
- 已完成 Markdown 只复用纯语法树解析结果，限制为 256 项、16 MiB；流式内容及自定义
  语法绕过。不会复用 React 节点、回调、权限或旧工作区文件预览，后续清理和高亮仍运行。
- 主进程界面读取按 owner 保序，不同消息允许并行；单例挂载按组件保序。慢的可选界面
  不再占住全部历史消息读取。保留物理在途上限及卸载、关闭、撤权、问题身份检查。
- 分页和会话位置恢复不再仅在第一帧定位丢失锚点；采用有界重试。结束恢复前要求挂载
  消息的受保护读取及重验证完成，再累计稳定帧，避免骨架短暂稳定后正文变高造成跳动。
  保留原有总帧预算及用户手势立即取消恢复的规则。
- 另修复左侧栏宽度调整时逐帧更新应用 React 状态的问题；预览通过样式变量更新，松手
  后一次提交。该项与本次用户明确的聊天区右侧滚动条分别验收。
  公共拖动组件还覆盖松手末帧、失焦与卸载取消，右侧面板在这些结束路径清理宽度基线，
  避免连续两次调整沿用上一次起点。

完整回归进一步要求明确区分长期 target 与单轮物理准入。长期后端仅登记自己的私有来源身份；每次真实新租约产生新的物理检查记录，Registry 按 target 与确切物理记录分别保存。旧记录及已签 proof 不更新，已准入独立子任务继续受自己的租约、来源和目标约束。物理入口恢复固定函数、原 receiver、单次来源及 scope 校验，并保留 getter、bind、重入与 ABA 攻击的拒绝。这项产品修复由原有失败回归验证，不能仅将旧测试中的“应拒绝”改成通过；只有长期 target 的前置假设按新生命周期更新。

取消子代理还暴露了另一个生命周期问题：真实模型流已关闭，但终态事件继承了已结束的内部 operation，被 `MODS_ENTRY_EXPIRED` 拒绝，丢失 `turn.complete` 通知。终态现按原已加载 session 的精确对象身份独立准入；普通旧操作仍拒绝，旧实例撤权或被替换后，迟到事件不能进入新实例，也不能启动新一代。主轮次通过原生生命周期的实际 signal 记录开始时的实例或未加载事实，延迟完成事件不依据调用时的当前实例推断归属；插件变更也不因此取消原生聊天。发布保护返回后再次核对实例身份。页面重载测试则等待真实会话历史恢复和输入框可交互后再发起一次检查，不将 DOMContentLoaded 当作业务已就绪，不自动重试命令。

`classic.Stop` 的真实续接验收发现另一项共用缺陷：宿主完成循环发起的修订被首次原生输入的防重入校验拒绝。现在由受控完成循环签发一次性输入凭据，绑定确切消息、线程、run、signal 与原物理 lease，供三个原生入口及恢复路径消费；复制、篡改、取消后使用、作用域替换和重放均拒绝。修订使用独立内部消息身份，继续经过完整内容保护、keeper 和持久化确认，不生成可见用户气泡，不清空或复用原输入的防重放状态。清理等待覆盖真实修订工作，原输入失效后也不能借续接恢复权限。这是完成门禁、PostSkillUse 与 Stop 共用的宿主能力，不按插件名称放行。

当前工具采用延迟发现协议。子代理功能验收分别等待真实发现及工具结果、父会话最终回答，每个阶段继续使用原 30 秒上限；请求、身份、实际用量、部分答案、取消连接及不重试断言继续保留。该功能判定与延迟指标分开。一次独立子代理场景的 Main 线程 CPU profile 采样约 56.6 秒，其中 idle 约 25.7 秒；主要非 idle 采样归因于 SQLite 查询、插件注册表读取和目录事实检查。该样本用于定位重复校验，不是业务性能基准，也不代表问题已解决。后续需在保留 fresh 授权、来源和目录身份校验的条件下引入精确的校验作用域契约，不能以时间缓存或删除保护换取速度。

独立性能复查确认，本轮队列、焦点状态及编辑器安装状态均采用有界状态，不增加常态轮询；压缩边界认证只在最近检查点消息无法匹配原 SQL 边界时进入，普通匹配路径不增加这组认证读取。该分支仍需要真实检查点、membership 和投影校验。上述结构性改进分别减少队列挤占、无效重绘和旧历史回灌，不能据此推导整机提速比例，也不代表已消除首次安全发布等待或全部文件与数据库读取热点。

重复观测轮次状态时，旧测试不断通过输入框提交查询，与真实模型终态更新竞争，触发输入快照已变化的保护。现保留一次完整输入框命令验收，后续轮询通过相同公开 SDK 命令的只读参数分支查询，并按各自任务 ID 等待结果；取消动作仍独立执行一次。流中导航测试则在真实模型服务端保持响应未结束，完成 A→B→A 后再释放响应，不再依赖受保护正文的原始首段提前显示。两者均保留真实请求次数、会话归属、最终正文及完整持久历史校验，不重试业务动作，也不更改生产发布保护。

用户提供的原始 AutoBiz ZIP 已只读进行完整静态复验。使用已有 `mod_business.example("autobiz-knowledge")` 提供的四文件闭包后，私有源码候选保留原 234 个文件的原字节。最终组装按受审适配器重建新插件身份和派生 board 配置；原 Hooks、脚本和知识资源闭包、非流程配置字段、八个业务节点及主干和动态分支顺序保持，静态组装不再缺少提供方，仍需绑定并核对外部知识。首次迁移还新增拒绝反转主干、改变动态分支顺序及注入额外节点行为的回归。该结论不包含真实八阶段业务执行验收；原生试用确认、知识目录、项目及 Feature 配置、Python/Node/collector 依赖和执行授权仍是运行条件。

完整 Electron 流程继续发现了第二个窗口：已接纳的发送意图正在等待旧发现结果，同会话新实例已提交、但被动效果尚未安装编辑器。此时不能仅同步检查 editor 引用。修复使用与实际布局提交绑定的安装 Promise，只衔接已经确认的同会话新实例，继续验证原发送意图。在等待新实例安装时，关闭、换会话、目标实例被替换和卸载均及时结束并释放准备锁，不追随后续未知实例。另以独立的组件／线程生命周期唤醒仍在等待旧发现或规则回执的提交；线程切回原 ID 也不能复活旧意图，迟到回执不能新增发送。独立浏览器测试保留旧路径的真实失败栈与新路径通过记录，同时核对同代规则错误不重试、旧实例不新增编辑 IPC、正常提交仅一次。此增量未宣称同一组件持续关闭时任意后端 IPC 均已具备取消协议。

授权信息刷新期间，尚未取得快照和确认关闭原先共用 `enabled=false`，导致有工作区的会话误走普通发送分支。现在区分“已确认关闭”和“正在读取／读取失败”，并在实际提交时重新验证当前作用域，而不只依赖上一帧按钮状态。真实 Hook 浏览器回归覆盖刷新、失败后重试、同步作用域失效、关闭／开启以及无工作区的普通聊天；保留旧实现可复现失败和修复后的通过证据。

混合历史还暴露了持久化解码缺陷：先关闭 Mods 聊天、再启用时，检查点可同时包含未标记的旧 AI 消息及带宿主凭据的新消息。Worker 没有复原 JsonPlus 的精确 `undefined` 标记，导致旧 AI 元数据参与摘要时与真实检查点不一致，合法历史被拒绝。修复只在私有原生消息复制路径恢复该标记，保留结构、原型、预算和完整 membership 摘要校验；公开 JSON 复制仍保留字面标记，不加载任意构造器。真实 Saver 回归复现旧代码失败，修复后通过，修改同一检查点元数据仍被拒绝。这是通用历史恢复修复，不作为所有输入未发送现象的唯一解释。

历史引导 IPC 原先还将证明失败、迁移失败及读取失败一律返回 `null`，使渲染端误报为取消。现在仅真正退役的读取返回取消，其余错误继续传播到有界恢复及诊断。实际注册 handler 的执行回归分别覆盖三个失败位置、真正取消、两种成功路径及读取进程重启；不会重放已经完成的引导工作。

连续流程另复现了原生子任务取消后的引导死循环：检查点包含已认证的 Mods 消息和原生中间件补出的普通工具结果，后者已经写入 SQL，却因不属于 canonical 成员而被要求再次迁移；旧迁移器又拒绝混入的 canonical 消息。新增只读覆盖证明核对完整检查点摘要、消息序号和身份、普通工具投影及全部 23 个 SQL 字段，并在最后来源回调后重新读取。只有完整匹配才免去迁移，不写入新的 canonical 凭据、确认或权限。证明按一 MiB 限额有界传递，使用集合避免普通消息与 canonical 成员的乘积扫描。

这条新增契约限于可无损投影的纯文本工具消息及空元数据。未知 Human／AI 混合历史、附加元数据、缺失或变化的普通投影仍保持失败关闭；普通 SQL 的时间和序号比较是同次读取的一致性检查，不是新增历史持久签章。真实 Saver 关闭重开、原生取消中间件、Worker 和 SQL 的回归覆盖成功与篡改拒绝，不能据此外推任意历史迁移均已完成。

修复后的连续源码流程已通过原失败位置：真实重启、设置中撤权、返回原聊天、填入草稿并单次点击，取得真实模型回答，下一次模型请求不再携带已撤权工具。被动记录观察到完整的 pointerdown／pointerup／click／submit，按压期间按钮保持可用，该段捕获的历史错误为空。记录本身不触发事件、重发消息或修改准备条件；此项通过仍需与后续完整流程结果分别报告。

公开的空闲会话压缩原先通过上一轮包装后的图读取状态，误继承已经释放的物理运行归属，在 `PreCompact` 执行前失败。修复使用仅供本次宿主编辑的检查点适配器，固定会话、来源、数据库、线程实例和变更租约；保留 canonical membership、历史及内容校验，不刷新旧运行凭据。准备摘要前和写入锁内比较完整状态及检查点身份，实际数据库写前再次检查取消和归属，覆盖锁等待、序列化和重试。真实 COMMIT 独立记录为宿主事实，提交后再发生的错误继续上报，但不能误删已被持久检查点引用的归档。这是共用会话能力，不属于 AutoBiz 特例，也不等于新增复杂业务阶段恢复。

手动压缩后，旧历史补齐逻辑因摘要没有原 SQL 消息 ID，会重新扫描并尝试重放已摘要的历史。宿主现在根据确切来源检查点及 membership、最后已覆盖原生消息和原 SQL 投影凭据建立私有边界；边界同时绑定目标检查点的完整内容摘要、分支及线程实例。下一轮只读取边界之后的真实尾部。公开摘要标记、guest 存储值及单独的 frontier 均不能制造该证明，历史篡改和跨分支复用继续拒绝。此协议限定于当前手动压缩入口，不外推为所有自动摘要生产者均已接入。

恢复保证还需区分完成与写入中断：本轮验证成功返回后的存储重开续接；检查点提交到 membership／边界记录持久化之间若进程退出，仍可能需要人工核对。检查点和归档必须保留，不能吞掉校验错误并改用裸历史。跨库预写意图、精确结果对账及缺失回执恢复属于下述通用未知结果恢复迭代，不标为本轮已完成的任意崩溃恢复。
