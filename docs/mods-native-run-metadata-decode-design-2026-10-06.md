# 运行检查的重复解析优化

状态：待两人设计评审，尚未实施。此项不代表性能门已经通过。

## 用户能得到什么

运行过程会反复确认任务仍属于同一个项目和同一次执行。本项减少相同存档文字的重复
解析，帮助复杂组合降低本地开销。每次仍读取当前数据库并检查真实项目目录和任务占用。

## 精确范围

只修改 `src/main/mods/native-conversation-run.ts` 的本次运行私有闭包。
创建时保存原数据库返回的 `metadata` 字符串、原解析出的项目路径和原 incarnation。
每次 `assertFacts` 仍调用原 `getThreadCore` 取得新行；仅当新行的完整 metadata 字符串
与原字符串严格相等时，复用原解析的路径和 token。原 token 为空时，仍比较新行的
`Number(created_at)` 和原时间；原 token 非空时，完整相同字符串包含相同 token。

字符串不同仍按原 `matchesThreadIncarnation` 和 `workspacePath` 完整解析，不更新
已保存字符串，不缓存新行或后续解析结果。每个运行只保存一份原数据，跨运行不共享。

原权限存活、DB 地址、真实目录 stat/realpath、任务占用和所有字段检查保留。
每个完整检查中的两次独立 `assertFacts` 和一次原 binding callback 保留。
callback 后必须重新读数据库和目录，不能借用 callback 前的结果。

这会减少内置 JSON 解析的调用次数，不承诺所有内部调用次数不变。原绑定回调次数不变。
解析结果只说明原字符串的内容，不能授予权限、延长有效期或替代新的实际检查。

## 回检

保留原运行证明的全部测试，新增真实 DB 的原字符串重复检查、相同字符串的旧时间
变化、字符串改变后的项目或 token 改变、callback 后撤销、读取次数与目录身份检查。
完整字符串相同才复用；其他 metadata 字段改变时也必须走原解析分支。
类型、源码两人检视、真实模型工具链及原 5 秒门均需独立通过。
此项可能只减少部分开销，不能代替共享子任务的第二项优化。
