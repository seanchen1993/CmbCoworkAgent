# 工作台分享与应用市场产品方案

状态（2026-11-02）：产品规划，尚未实施新的市场功能。当前开发者底座的功能补验和性能回归执行已收口，但原性能门槛未全部通过，见[最终性能记录](mods-final-performance-2026-11-02.md)。参考资料核对日期为2026-11-01；用户已确认 dsh 指 DeepSeek Harness，参考其官方仓库和文档。

## 产品定位

在现有应用市场增加“工作台”分类，让一个人的成熟定制成为其他人能直接使用的产品。首期先贯通单插件工作台：作者发布一个已保存版本，其他用户查看效果、补齐少量配置、汇总确认后直接打开。后续再开放多插件组合发布和项目模板发布。

市场、ZIP和分享链接使用同一份版本化发布物。普通用户看到一个工作台；依赖在后台解析，收在详情中。平台负责安装、配置、授权、启动、更新和恢复的通用流程，具体调试、测试或企业业务由插件实现。原项目创建、设置、Feature和执行页面继续沿用。

不新增第二套“Mods市场”，不要求消费者理解能力协议、Hook、源码摘要或助手组合。开发者仍可从高级详情查这些内容。

## 一个实际使用例子

作者在创造者模式定制“开发工作台”，包括源码定位、检查命令、结果面板和可选诊断。保存、试用后点击“发布到应用市场”，填写用途和快速上手，预览普通用户看到的页面，再发布固定版本。作者可自行扩展调试实现，此示例不宣称提供原生断点或DAP引擎。

另一位用户在市场点“使用”：当前聊天已有项目目录就直接采用；没有时选择一次目录。准备页只问缺少的必填配置，用日常语言汇总本版本及依赖的实际作用范围。用户确认后直接进入真实工作台，原草稿保留，不再跳到插件管理、组合创建或重复应用页面。

首次引导给出一项明确的小任务，例如“读取 Node 版本”，说明在哪里点击、成功时显示什么。诊断服务未启动时，显示“代码诊断尚未设置”及原设置入口，其他可用功能照常使用，不在后台安装语言服务或自动运行项目。

再次使用时，当前目标、实际源码/编译身份、依赖与配置未变、原授权仍有效且宿主兼容检查通过，就直接打开。源码、权限、策略、依赖、目录或宿主修订变化时，只汇总本次必要核对；应用版本号相同也可能因宿主能力更新而需要重新确认，普通提示可写“应用已升级，请重新确认工作台”。设备命令、写入、外部服务等操作继续沿原生策略；不能把安装确认解释成任意命令的永久放行。已被原策略允许的日常操作不增设工作台专属确认。

准备页用一句话说明“在哪里激活”和“原权限实际适用范围”。当前聊天激活与同目录共享来源授权属于不同边界，不能把目录级授权写成“仅本聊天”，也不因此新增确认页。

P1需要补齐普通用户的直接入口：市场“使用”、分享链接或ZIP安装完成，以及“已添加→打开/设置”，均进入同一真实使用准备协调器，不要求先进入创造者模式、灵件高级管理或手工创建搭配。需要的开关、必填配置、来源授权和绑定在本页按原生报告汇总，已有效步骤不重复。开关可能恢复目录或全局范围内的已有设置，必须说明实际影响，不能只写“本工作台”。创造者模式用于制作或用户主动定制副本；这属于后续实施目标，当前消费者设置仍在“创造者模式→灵件”分类中。

## 用户实际看到的界面

| 位置 | 保留 | 收到详情或去掉 |
| --- | --- | --- |
| 市场卡片 | 中文名称、一句用途、效果预览、作者、当前状态、一个主按钮 | SDK方法、组件摘要、依赖安装顺序、来源摘要和内部ID |
| 详情首屏 | 能完成什么、适用场景、实际前提、主按钮“使用” | 长篇机制说明、多个同义启动按钮、重复授权入口 |
| 使用准备页 | 当前目标、缺少的必填配置、简短作用范围、一个“启用并打开” | 原始JSON、完整权限枚举、多个连续弹窗和中间组合编辑页 |
| 工作台 | 作者定义的主要界面、清晰任务状态、设置和使用说明入口 | 首次进入就展示全部开发参数、协议和调试记录 |
| 已添加 | 打开、设置、更新、移除；必要时显示待完成事项 | 同一套依赖散成多个看似独立的主产品 |
| 作者工作区 | 继续修改、试用、保存版本、发布 | 要求用户在聊天和页面重复填写修改要求 |

“能力范围”“依赖组件”“版本变化”“开发者信息”分开按需展开。权限一直可查，主要界面只呈现用户需要作出的决定。配置字段使用作者声明的人类可读标题和说明；已有配置读回，敏感值进入本机安全存储，不显示或发布真实值。

状态从真实流程产生：待配置、准备中、可使用、部分功能待设置、当前应用不兼容。安装完成不冒称已经运行；结果未知时提供“核对结果”，不自动重放任务。

现有应用市场可先增加工作台筛选和已添加入口，保留其他资源使用方式。成熟后再统一市场导航，不同时重做所有市场页面。

每份发布物有一个明确的默认主入口；多个placement指向同一页面时，普通用户不应面对多个同名启动按钮。其他确有用途的入口按所在位置清楚命名，完整接口示例与普通用户首屏分开。

实施前先复查本轮记录中的通用热路径预算未达项。市场新增的安装、准备、打开和更新代码另做性能回归；现有底座的长稳结果不能代替未来市场功能的验收。受保护回答当前采用检查后整体显示，不把复杂的安全增量协议与首期市场复用捆绑开发。

## 指引详细，使用页面简洁

每个发布版本附独立用户指南，市场详情和工作台内都能打开。指南至少包含：

1. 适合谁、能完成什么、需要准备哪些条件。
2. 从市场到打开的具体步骤，使用实际界面名称和图片。
3. 一个可直接复制的测试任务、操作按钮和预期真实结果。
4. 如何更换目录、修改参数、查看运行记录与请求停止。
5. 缺少 Java、MCP或其他可选服务时，去哪个现有入口设置。
6. 更新、撤权、失败、结果未知、依赖冲突和移除时如何恢复。
7. 能否在创造者模式定制副本，以及作者允许的派生和再发布范围。

快速上手采用“打开→做第一件事→核对结果”三步。技术协议、权限依据和开发示例放在开发者文档；普通指南不要求阅读SDK。指引绑定具体发布版本，避免旧文案指向已不存在的按钮。

## 使用、组合与派生的边界

| 市场对象 | 携带内容 | 安装后进入哪里 |
| --- | --- | --- |
| 单插件工作台 | 已验证Plugin、配置声明和一个默认打开入口 | 原公共surface工作台 |
| 多插件组合工作台 | 固定发布版本的依赖引用、组件选择、可移植配置和模型/连接槽位 | 解析成本机新ID，沿原组合保存和应用，再打开默认入口 |
| 项目模板 | 项目声明、阶段内容、source-set或组合源及依赖锁 | 预选插件后进入原ProjectForm、设置和Feature流程 |

三者共用市场目录、发布身份和安装协调流程，各自保留实际安装与启动协议。不能直接上传本机ClawProfile并在另一台机器执行：其中的插件ID、digest、模型和连接绑定属于本机。

发布物不得携带旧grant、会话ID、本机绝对路径、账号密钥、模型凭证或用户项目数据。导入后用目标用户自己的目录、模型和连接重新绑定。依赖共享时按实际引用计数管理，移除一个工作台不删除其他工作台仍在使用的依赖，也不删除用户成果。

直接使用与定制副本分别呈现。已有市场内容保护继续遵守；只有作者允许派生的版本才显示“定制副本”，进入创造者模式时保留来源和版本血缘。作者发布更新与用户自己的定制版本分开，不覆盖用户修改。

日常设置只修改用户自己的配置，不生成新的发布版本；敏感值保存在本机。主动点击“定制副本”才从固定发布物及许可创建独立作者源，保留原安装、配置和项目引用；副本沿原试用、核验和保存流程自用，许可允许时才再发布。新源码、配置或授权范围变化仍按原身份与修订复核。

更新页显示本次目标、旧版与新版以及必要差异。默认只改变之后新打开时所选版本，存量聊天和项目继续绑定旧的不可变来源，定制副本不被覆盖。迁移已有目标时逐目标明确选择，沿原入口核对，失败保留原绑定。尚不具备版本保留底座时延期提供更新。

## 现有底座及必须补齐的断点

只读代码核查已确认：

- 已有插件发布、上传和更新表单，市场下载后可进入原ZIP安装器；`plugins.ts`的exportForMarket与market API是可复用入口。
- `PluginStartUseService`已能只读准备当前安装、核对精确源码、配置和依赖，并区分聊天、原生项目及插件项目目的地。准备不等于执行授权。
- 公共surface、配置、通用依赖分组和本轮“开发工作台”示例可作为首个真实产品，不能用只有说明文字的市场卡片代替实际可用性。
- 现有项目source-set支持项目源及普通依赖准备，尚无通用聊天组合的可移植发布协议。

成熟推广前必须补齐：

1. **发布身份和版本协议。** 客户端当前市场上传/更新仍有`Bearer your-api-token`占位header，不能从localStorage中的userId/IP推导作者权限；需要核对后端真实登录、发布所有权、可见范围和下载鉴权契约。当前代码不足以判断服务端的真实实施状态。
2. **可恢复更新。** 现market-plugin-update先删除旧插件再下载，下载失败可能失去旧安装。改为下载→摘要/兼容验证→暂存→差异确认→受保护切换；失败保留旧版本和配置。不可变版本目录、依赖锁与实际绑定引用保留是“不影响旧聊天/项目”的前提，不能靠原位覆盖和备份作此保证；尚无这层底座时先延期更新，不能静默替换正在使用的来源。
3. **受控发布清单。** 当前插件导出遍历整个插件目录，不能直接视为“只含适合发布的作者文件”。发布前展示实际清单，拒绝本机配置、密钥、日志、构建产物和用户数据；不能默默裁剪必要文件。ZIP摘要与实际文件集合绑定。
4. **安装到打开的完整协调。** 市场、安装器、使用准备、组合确认和打开入口目前分散。需要一个可取消、可恢复且绑定当前目标的安装使用计划，在一次汇总确认后协调原生步骤，不另造执行器。
5. **组合可移植性。** 需要版本锁、符号配置、连接/模型槽位、冲突策略和本机新ID映射；禁止复制其他用户的权限。
6. **许可、血缘和指南。** 发布、使用、允许派生及允许再发布分别记录；用户指南、默认入口和验证范围绑定固定版本。

关键代码：`src/main/ipc/plugins.ts`、`src/main/plugins/plugin-start-use.ts`、`src/shared/plugin-start-use.ts`、`src/renderer/src/api/market.ts`、`src/renderer/src/components/customize/MarketPanel/market-plugin-update.ts`、`src/shared/mods/claw.ts`、`src/main/plugins/project-source-set-install.ts`。

## 共同发布封套与原生协调

内部发布封套至少包含：稳定listing/release/publisher身份、artifactKind、不可变包摘要、版本、宿主/API兼容条件、默认入口、固定依赖引用、非秘密配置schema及默认值、用户指南、变更说明、许可和派生来源、范围明确的验证记录。协议字段由程序生成和核验，不让普通用户填写JSON。

可先复用现有plugin资源渠道，增加版本化元数据；客户端须验证与实际包一致，不能信任商品描述来授予能力。跨来源依赖有明确来源边界，不能静默从第三方地址补装。

首期明确采用“先非激活落地，再准备”的协调方式：解析目标与版本→下载验证并非激活安装到不可变目录→为本机最终ID、待提交配置生成真实使用计划→汇总确认→沿原生接口启用、授权和绑定→复核→直接打开。需要增加通用的非激活安装与准备适配；现有StartUse只接受已安装ID，不能假称今天已经支持安装前准备。确认前不进入实际使用会话，不运行Hook、连接MCP或启动命令；必要的隔离编译/声明预检不取得执行权限。

一次汇总确认绑定包SHA、最终本机依赖映射、实际编译摘要及宿主修订、目标incarnation、配置值摘要与修订。用户表单中待提交的配置也须进入同一计划预检。落地结果必须与确认计划一致；源码或绑定变化则停止并回到同一准备页重新核对，不能把旧确认延用到新身份。取消可保留明确标为“未启用”的安装供继续准备，或清理由本计划独占创建的暂存内容，不冒称已经可用。

每一步保留实际回执，失败从原记录核对，不靠重按按钮猜测。切换聊天或账号后不能把旧计划应用到新目标。版本号、发布者显示名和本机路径模糊匹配不能决定覆盖对象；使用稳定listing/release身份，旧安装关联不明确时保留原物并处理冲突。

列表和详情按需加载，不启动Mod、模型、扫描器、MCP或语言服务。打开工作台也不隐式运行作者检查命令。市场性能与工作台运行性能分别验收，不以静态卡片加载快证明运行开销达标。

## 迭代次序与交付门槛

| 次序 | 交付 | 必须验收 |
| --- | --- | --- |
| P0 可信发布与安全更新 | 对齐账号/后端契约、固定发布物、文件清单、下载验证、非激活安装、不可变版本与绑定保留 | 错作者不能覆盖、坏包拒绝、断网不丢旧版、旧配置保留、活跃旧绑定不被原位覆盖、未确认不激活新能力 |
| P1 单插件工作台复用 | 现有市场工作台分类、统一准备页、一次汇总确认、默认打开、详细指南 | 真实作者发布，另一全新用户环境从普通聊天开始，未进入创造者模式也能从市场下载、配置、打开，并从已添加再次打开和修改配置；源码ACK、无副作用检查及关闭清理通过，不依赖作者缓存/授权，不要求手工创建搭配 |
| P2 组合工作台分享 | 固定依赖、冲突恢复、连接/模型槽位、原组合绑定 | 缺依赖/已有同版/版本冲突/取消和部分失败均可恢复；新ID绑定正确，顺序和配置保留，无grant复制；真实组合动作及普通聊天有效 |
| P3 项目模板与定制传播 | 原项目入口衔接、允许派生的副本、血缘和版本更新规则 | 原ProjectForm与Feature首次衔接；再次派生和重打包；存量项目绑定旧版本，更新不改变其已运行流程 |

首发选择少量确实完成上述闭环的工作台。第一项用本轮通用开发工作台，随后由不同业务作者提供第二项，验证平台没有项目或语言特例。稳定分享链接与指南足以支持第一轮推广；推荐算法、积分、复杂社交和大型布局引擎后置。

每期具体协议先双agent评审，实施后由中等强度非作者回检。市场新开发不会与当前底层验收混成一个“已完成”声明；当前基线性能在现有能力收口后按原计划执行，未来市场代码另做对应性能回归。

## 官方参考及取舍

DeepSeek Harness把可安装bundle放进插件管理的Discover/Installed机制，单独展示长说明；市场是可选实验性能力，由用户添加索引，官方文档明确没有默认官方市场。DevClaw可借鉴“发现、已安装、详细指引分层”，并为普通用户直接提供已有市场入口，不要求先启用实验开关或手填索引。[官方市场指南](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/plugin-market.md)

DSH市场按版本给出兼容性、精确npm版本或Git commit来源及真实安装状态，市场查询是只读数据；这有利于把“发现商品”与“执行安装”分开。DevClaw应把宿主能力修订纳入兼容检查，默认提供可兼容的正式版本，不能仅凭固定的应用2.0.0版本号或商品描述判可用。[官方市场服务](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/boot/plugin-market/README.md)

DSH的插件管理工具会改变整个profile，安装可能运行允许的构建脚本；启用HMR的实例可即时应用，其他情况需要重启。DevClaw保留自己的隔离、精确来源授权与聊天/项目绑定，采用显式目标切换；可以借鉴清楚的nextStep和独立维护者详情，不复制这种全profile影响范围。[官方工具目录](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-catalog.md)、[插件管理](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/boot/plugin-manager/README.md)
