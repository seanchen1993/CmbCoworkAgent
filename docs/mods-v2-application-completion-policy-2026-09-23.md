# 应用内置的项目完成检查配置

选择已绑定工作区的任务，在“自定义 → Function Mods”解锁设置，授权插件后展开该插件的
“完成检查规则”。此入口属于应用，不需要安装 Autobiz 示例面板。

可设置关闭、仅报告、阻止完成、自动修复并复检；检查范围为当前文件、当前 diff、Feature
或整个项目。可以组合代码评审、单元测试、E2E、Autobiz validator，并设置最大修复次数、
最长时间和模型输入加输出的总 token 预算。修复仍受原任务完成循环的上限约束。
文件范围应填写项目内相对路径，Feature 范围填写 Feature ID。

点击“保存项目规则”后，规则按项目和插件保存到应用数据库，重启后继续生效。
同一项目的其他任务使用相同规则；其他项目独立。界面区分当前保存的生效规则和待保存字段。
没有保存应用规则时，继续沿用插件原有行为或插件配置，不自动迁移或开启门禁。

应用保存的规则优先于插件自带的 `completion-config`。插件仍可通过原 `$.store.get`
读取有效规则，但不能覆盖或删除应用规则；相应写入明确返回
`MODS_COMPLETION_POLICY_HOST_OWNED`。此后请在应用设置页编辑，而不是使用示例插件自己的保存按钮。

保存关闭模式会移除此插件的完成门禁，即使旧插件状态仍写着 repair，也不会重新启用。
其他插件的规则独立生效；应用总开关关闭仍移除整个 Mods 门禁。
规则变化会中止正在等待的完成检查、使旧证据重新核验；不会复用旧 PASS。
runtime 替换、任务关闭也会取消该检查的宿主进程/模型信号。

代码评审由插件提供 `completion.check` 处理器；缺少处理器会报告不可用。
单元测试、E2E 和 Autobiz validator 由宿主原有检查链执行，插件不能自报这些检查成功。
插件评审意见不等同于业务验收；Autobiz 还需真实需求、产物、固定版本 validator 和受保护的
checkpoint 提交。此设置页本身不自动推进 checkpoint。

这是 CMB 应用设置能力，继续复用 ModsManager、FunctionSession、授权、原完成循环和证据账本，
不将其声明为新增 Claude Mods SDK API。
