# Mods 长日志的实际文件写入

## 实际发现

真实桌面 `output/stage24-desktop-five-focus-current.log` 中，消息保存用例通过。
长日志用例在真实日志文件比较处失败：插件先处理完整 30000 字符，保护后的日志快照
保存 10000 字符，界面显示 2000 字符，这些检查通过；普通主进程日志对字符串的
2048 字符限制使最终文件再次截短。原失败证据保留，不改成通过。

## 实施范围和两个检查

保留其他模块的日志上限、脱敏、等级筛选、轮转、刷新和关闭行为。仅为实际桌面
Function Mods 的调试日志增加专用写入函数，接到原 FunctionSessionHost.debugLog，
不增加插件权限或 IPC 接口。这个函数不能证明任何会话、工具或消息来源。

Root 的方案检查为 DESIGN1；Official 已审查方向。以下精确方案还需第二位评审。
生产代码在当前桌面构建完成前保持冻结，方案通过后实施，再进行源码双检与实际测试。

## 精确行为

1. `logging.ts` 增加 `writeFunctionModDebugLog(plugin, text)`，实际 `ipc/mods.ts`
   创建 FunctionModsManager 时传入。Manager 把可选回调传给真实 FunctionSession。
   没有回调的旧测试和其他宿主仍走原 console.info 路径。
2. 专用函数只接受字符串，文本最多 10000 个 UTF16 单元。
   文本越界直接抛固定诊断错误，不扫描或打印原值。原已批准的长名称不得新增拒绝。
   长日志的诊断名称用原 redactAndTruncateSensitiveText(name,128,"") 先有界处理
   敏感截断尾，再安全投影到 128；不更改原运行名称或授予权限。
   短文本（最多 2000）保持原
   `console.info('[Function Mods] [' + plugin + ']', text)` 路径。
3. 长文本按原 INFO 等级，每个逻辑日志只调用一次原等级筛选。关闭的等级不产生
   任何文件记录。保留原采样语义，不能逐片抽样留下不完整记录。
4. 在分片前对完整有界文本调用原 `redactSensitiveText`，名称按第 2 步处理；不会按片脱敏，
   因而横跨分片边界的凭据仍整体处理。原内容保护和 10000 字符投影仍先执行。
   脱敏可能让文字变长，所以脱敏后再进行 UTF16-safe 的 10000 文本、128 名称投影。
   文件中的完整值明确为这份有界、脱敏后的文本；不把新增替换文字视为无限额度。
5. 最终有界脱敏文本分为最多 6 段，每段最多 2000 个 UTF16 单元；切点避开有效代理对。
   10000 字符在避免切开代理对时可能需要第六段，不能截掉尾部或写成最多五段。
   每段用 JSON.stringify 写固定结构：recordId、index、count、plugin、text。
   recordId 由宿主 randomUUID 创建，index 从 1 开始，count 在入队前固定。
   每个原单元最多六字符转义；加上最多 128 单元的名称和固定结构，单行小于原
   16384 字符上限。JSON 使换行、控制字符和名称无法伪造额外日志行。
6. 固定标记 `[Function Mods chunk] ` 后直接调用原 enqueueLine(mainPath,'INFO',
   JSON记录,true)，沿用 writeMainLog 在完整脱敏后使用的 alreadyRedacted 分支。
   全部原文字和名称在第 4 步完整脱敏，诊断编号及其他字段只来自宿主固定数据。
   不能按片再次扫描造成记录字段或文字二次变化，也没有生值直接入队。
   保留原内存上限、轮转和真实刷新。所有片在同一
   同步调用中连续入队。不绕过文件权限、磁盘关闭或原 writer 的失败处理。
   不再进入普通字符串 projector，也不扩大全局 2048/8192/16384 限额。
   这只是调试文件表示；界面快照、模型消息和调试日志权限不变。
7. 对最终日志文件逐条解析同 recordId 的所有片，核对完整 1..count、名称和完整文本。
   桌面测试仍检查快照 10000、界面 2000、HTTP 和消息内容未变；不能只查头部包含词。

## 验证和证据

新增真实临时日志文件测试：原短日志路径及普通 2048 限额；长日志的全文复原；
横跨切点的 token 和可扩长的 secret=x；代理对、引号、反斜杠和换行控制字符；
逐片 JSON 解析及全文比较脱敏后再有界的基线；每行实际长度；等级关闭不落片；
真实 flush/close 后片完整；原轮转、脱敏和未知值检查完整复验。
实际 Electron ui-log 必须复跑，通过后才更新结论。单测或源码检查不是桌面通过。
性能方面最多 6 个原入队操作，输入仍有界；不新增模型调用、文件同步写入或进程。
