本阶段已完成，在 `C:/ai/CmbCoworkAgent-mods-v2` 的 `codex/mods-v2` 实现。没有改动 UAT，没有提交或发布。整体 Mods 对齐继续进行。

## 用户现在怎样操作

在“自定义 → Function Mods → 插件参数”修改并保存。普通组件空闲时自动采用新参数。若组件启动时会保存数据、打开界面或启动服务，表单会保留原运行版本，并提供“重新加载当前组合”。

点击后重新启动当前对话的全部已启用组件，关闭这次组件界面；保存的参数和插件持久数据保留。有任务或真正执行中的组件调用时返回等待，不取消任务。启动失败会明确显示“当前组合已停止”，普通聊天仍可使用；修好参数后点击同一按钮明确重试。刷新界面、改参数或一般缓存刷新不会偷偷重跑失败的启动。

## 底层与边界

先只读核对完整组合的代码、选择、批准和参数版本，再关闭旧实例，等待实际清理后从同一快照启动新实例。任何成员缺失都不能悄悄少加载一个。原窗口、实际任务占用和版本在启动操作前后持续复核；作者捕获启动错误也不能误报成功。

后台进程以真正启动确认区分等待和打开；清理失败即使被作者捕获、资源条目已删除，仍阻止新实例。无处理函数的定时器原生等待可以关闭，长周期不再让重载永久等待；已进入定时器处理函数仍算忙，不中断它来假装空闲。唤醒与暂停竞争也不能让旧回调越过暂停。

目前启动过程中再次进入自己的任务处理链会立即拒绝，避免等待自身形成死锁；这是仍可继续适配的缺口，后续补专门路由。敏感、多项、文件和目录参数仍以当时表单支持范围为准；下一阶段继续专用输入。最终同步来源核对不承诺阻止外部程序随后改文件。

宿主版本升为 `module-resources-v74`，代码许可摘要随之变化，旧 Function Mods 需要按真实新摘要重新批准；没有自动替用户扩大许可。
