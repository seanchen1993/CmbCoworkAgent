# Mods 透明分组迁移说明

本页说明本轮已经落入源码的分组行为。当前正在与构造器自定义功能一起做回归，完整功能的验收以阶段报告为准。

## 哪些插件需要注意

如果你的界面只使用 `Box`、`Text`、`Button` 等组件，或者直接返回 `await next(e)`，使用方式不变。

如果你使用了 `<></>`、`Fragment` 或 `__functionFragment`，需要检查布局。它们现在只表示“这里放几项内容”，不会自动添加一层上下排列的容器。这让多个组件组合后仍保留原界面的布局。

例如，原先横排的左、中、右三个内容，不会因为中间两项被分组就突然变成上下排列。空分组也不会留下空白容器。

## 想上下排列，请明确使用 Box

下面的写法只分组，不规定内容怎么排列：

```tsx
return <>
  <Text>代码检视说明</Text>
  {await next(e)}
</>
```

如果你需要“说明在上、原界面在下”，请明确写出布局：

```tsx
on("ui.render", async ($, e, next) => {
  const { Box, Text } = $.ui.resolve(e)
  return <Box flexDirection="column" gap={1}>
    <Text>代码检视说明</Text>
    {await next(e)}
  </Box>
})
```

不用 JSX 的插件也可以写：

```ts
return Box({
  flexDirection: "column",
  gap: 1,
  children: [Text({ children: "代码检视说明" }), await next(e)]
})
```

分组本身没有颜色、宽高、按钮动作、原生内容编号或 Client 归属。需要这些设置时，应把它们放在相应的真实组件上。传输数据中的分组只允许 `type` 和 `children` 两个字段。

## 提问界面仍由原控件回答

你可以在真实提问控件前加说明，也可以用透明分组包住整个提问界面。原来的选项、自定义答案、翻页、提交、忽略和键盘操作仍由原控件负责；分组不能产生新的回答权限。

真实提问控件必须是整棵内容的最后一项。后面即使只有空分组、空文字或空容器，也会被拒绝。不要用空节点代替“没有后续内容”：应在条件分支中直接省略后续项。

```tsx
// 可以：说明在前，真实控件在最后
return <>
  <Text>请先确认范围</Text>
  {await next(e)}
</>

// 不可以：真实控件后仍有一个结构节点，即使看起来是空的
return <>
  {await next(e)}
  <></>
</>
```

正在显示的问题仍绑定原来的实际请求。旧问题的回调不能回答新问题。

## Client 和模式切换有哪些限制

Client 的独立界面可以使用透明分组，也可以保持原来的按钮和状态。但它不能借分组调用聊天区的原生提问、工具结果或其他原生控件。模块批准、组件归属、动作检查和容量限制继续生效。

模式切换按钮里的自定义文字可以分组，但不能在其中再嵌套按钮、输入框、选择框或 Client。点击与键盘操作仍由唯一的原模式按钮处理。

## 升级时怎么检查

1. 搜索插件中的 `Fragment`、`__functionFragment` 和 `<></>`。
2. 如果原先依赖自动上下排列，把分组换成显式 `Box flexDirection="column"`。
3. 检查提问控件后是否残留空分组或其他内容。
4. 实际点一次原按钮，检查原状态是否更新，再关闭、重开界面确认旧回调不能继续操作。

透明分组不会开放额外的模型、文件、提交或审批权限，也不会修改存量 Plugin 项目模式和 Harness 的使用入口。完整构造器自定义、跨插件调用与安全更新的验收另见 [Stage21 方案](mods-ui-resolve-design-2026-10-05.md)。
