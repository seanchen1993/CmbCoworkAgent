## 1. 本轮目标及不可回退项

- 以 beta 的完整产品与本地数据体系为基础，只做扩展。新建 Bot 与原服务专家使用同一 Bot 身份、配置、ChatContainer、输入框、右侧详情与本地 Runtime，不再依据来源选择另一套产品界面。

- 本轮不新增第二套 Agent 引擎、业务数据库或全局状态机；不恢复强制 PRD、成果版本、固定退回表单或所有消息都需审批。

## 3. 本地数据关系与扩展边界

保留现有 Bot/Thread/BotTask 标识与数据。新增轻量“工作”实体（建议 `BotWorkItem`，最终命名在实施检查点说明），表示一件可持续推进的工作：所属 Bot、独立 thread、标题、目标、来源/受众范围、主会话关联、生命周期及时间。一个工作有一个独立会话和多次执行；一次执行可产出多条消息/多个文件/外部操作结果，不建强制一对一成果实体。

- 普通聊天仍在既有主 thread，不因数据库里产生执行记录就增加工作条目。
- 所有持久化为 beta 现有 SQLite/消息存储的增量迁移。已有主 thread、模型选择、文件/记忆/例行任务及协作 ID 不重建、不全量重写。不能以改调用路径掩盖旧权限、文件边界或来源语义丢失。
- 工作执行明确携带 workId/threadId/来源范围；main 解析归属，renderer/模型不得指定任意本地路径或越权 thread。不要复用 groupId 假装任务隔离。
- 创建/转达使用既有 Runtime 可调用的窄工具和真实持久回执。工具结果能链接到真实工作，重复调用/丢回包仍指向同一工作和同一条请求。不要用强制 JSON 最终答复替代 beta 的普通回复与工具能力。
- 新任务只携入目标、相关消息/材料和明确文件引用；不复制整段主历史，不把后台结果当作新的用户授权。继续工作读取该工作自身历史，包含上次助手回复。
- 查询按 Bot/受众过滤，摘要分页、有界批取；正文仅按所选 thread 分页。无逐任务全历史扫描或空闲持续全量轮询。ES 若被触及，遵守项目性能约定；无必要不改 ES。

## 4. 何时建立独立任务

参考 Dots 官方行为：主对话可协调、独立任务有自身上下文、可以继续已有任务；公开文档未提供固定拆分算法。来源：https://learn.chatgpt.com/docs/dots/tasks-and-memory 和 https://learn.chatgpt.com/docs/dots 。以下为本产品规则：

1. 问答、解释、简短改写默认在当前会话完成。
2. 用户明确要求独立任务，或明确交办适合单独推进/多步骤/持续跟进的工作，可由 Bot 创建；同时保留右侧手动“新任务”入口。
3. 主对话留下任务入口和实际状态，创建后仍能继续交流。不得先显示成功卡后无真实持久对象。
4. 修改、补充、追问已有工作继续原任务；主会话可以向明确目标转达。目标歧义先澄清，不用“最近一个”跨受众猜测。
5. 不为每条 IM 消息建立任务。个人/群渠道会话与工作关联是入口关系，不能等同 Bot 身份。
6. 执行终态不等于业务验收或渠道送达。结果直接出现在聊天中；用户可明确完成/继续同一工作，需确认时显示真实待处理原因，普通回答不强制待确认。
7. 已完成后继续的工作保持 ID/历史，显式动作或明确针对该任务的继续指令打开原工作。停止精确作用于当前执行，不取消例行任务或删除整个 Bot。

## 5. UI 与既有功能保留

- 左侧没有服务专家专属区、嵌套任务列或额外产品入口；专家是一个具有职责配置的普通 Bot。
- 右侧保留 beta 头像、名称、标签、详情/资料库/电脑。将“最近工作”升级为真实工作入口，进行中/需要用户处理优先；提供有界展开/全部入口，不因六条上限永久隐藏任务。旧逐次执行记录可从工作/活动详情查看，不再混入任务列表冒充工作。
- 任务打开到同一中间 ChatContainer；主/任务均保留附件、流式消息、工具过程、文件交付、停止与输入行为。新工作可使用同一 Bot 已有能力，但必须按所属工作/渠道正确约束上下文和工具资源。
- 当前任务标题、运行状态和返回主对话入口清楚，输入框目标与界面一致；切换、重开、迟到回包、IME 和发送中继续输入不能串草稿/串消息。
- 右侧任务消息来源和 IM 模拟标识低干扰展示；不常驻 Run UUID、内部协议、Java 配置表单。右侧收起时由左侧 Bot 未读/待处理汇总和主对话入口保持任务可发现。
- 当前 Bot 的公共职责/资料与任务专属上下文要明确；不用切换任务改变 Bot 全局模型/职责/记忆。任务文件可沿用经授权的 Bot 工作区，不因新增会话削弱现有文件验证；不同受众的渠道工作不可直接共用私人文件/记忆范围。

## 6. 并发、恢复与来源

- 同一 thread 顺序执行/既有 steer 语义保留；主会话与独立任务可分别调度，受全局有界并发控制。不能让长任务占用整个 Bot 的所有会话。
- 对共享文件/浏览器等保留必要的资源互斥，不能把 botId 排他直接删掉就声称安全并发；现有群 workspace/浏览器与人工接管语义不变。
- 已接纳的消息先持久再派发，关闭/重开恢复；相同请求不重复创建工作、不重复执行。副作用结果未知保留核对状态，不自动重跑；已知失败可明确重试，状态要在当前界面及时发现，不需切页面才能看到新结果。
- 例行规则仍是规则，每次触发是执行；保留原静默、时区、下次运行、取消规则与停止单次执行的区别。
- 文件生成/模型结束与真实外部送达分开。渠道不支持附件则明确未送达，不把本地路径当成远程可用链接。

## 10. M05-01 接口审查决定

2026-10-19 root 已读实施者 `edbcc351` 的十五项能力矩阵及七组接口方案，允许进入 M05-02/03 产品实施，以下决定优先：

- 采用 `BotWorkItem`、既有主 thread 不变、既有 `BotTask` 仅增工作关联的关系。工作目录/命令回执/初次执行在 control.sqlite 同事务；消息库 thread 使用固定 ID 幂等确保并校验身份，初始化后丢失不能悄悄重建。新增字段必须有实际消费者，不建立未来功能占位表。
- Host 集中解析 main/work/原 group 目标，外部渠道由可信模拟 binding 内部解析；所有引用、回执、文件/预览、浏览器、草稿、后台命令、协作回传、历史裁剪、归档删除一并审查真实 thread，不能只改 send/open。回执与归档记录要保留 work/source fingerprint，过期正文清理不能失去目标校验。
- 工作工具是原 Runtime 的扩展，普通回复不变。创建工具限主对话或渠道主会话；工作内部可继续使用 beta 原有子任务/协作能力，不递归自动拆出无限可见工作。真实 tool-call 身份与持久命令关联，重复命令重放原回执；模型提供的 requestKey 不能代替可信来源或赋予权限。完成以用户明确动作/指令为依据，不因模型宣称 done 自动确认；在本工作运行内不得用 complete 绕过活动执行门禁。
- 本轮保持全局驻留执行硬上限 2（沿用 beta 默认），包含等待人工的图。新增独立工作最多占其中 1 槽，剩余槽可处理主会话；已有普通 beta Bot/群执行仍沿用原有有界调度能力。按 thread 排他、主会话优先，原工具级 workspace/browser 锁继续生效。暂不实现“等待人工释放运行配额、总驻留 4”的新机制：现有等待回调非异步准入，容易在同时恢复时突破实际并发上限。人工等待不得持共享工具锁。需扩并发以后独立评估，本轮不扩模型消耗上限。
- mock 外部入口先支持文字与同受众工作创建/跟进/完成；复用同一本地消息/任务/Runtime，但使用明确的来源能力策略。默认不暴露文件系统、shell、owner 浏览器、MCP/技能、私有记忆或全局配置工具。不要为模拟入口重构整个 Runtime 沙箱。本机主/任务仍具备 beta 全能力；渠道附件标记尚不支持，不伪造送达。未来启用外部工具前补齐真实平台授权及完整资源边界，列入 M06。
- 旧服务 journal 采用只读历史归档/导出，专家职责可通过现有 Bot 编辑器显式导入；不自动重放旧 pending/unknown，不自动把服务身份升级为桌面所有者权限。新主流程不依赖旧服务。未知执行可查看已有结果，用户明确继续时只接纳新的指令，旧执行保留未知事实；禁止“继续”等价于盲重试旧副作用，未处理补充不得被完成吞掉。

实施早审补充：工作发起的协作使用可信 `rootWorkId` 标识整条协作归属，单跳回传目标仍由 `returnWorkId` 表示。工作及其协作后代共同使用新增工作执行配额，不能占满两槽而间接阻塞主对话；原 beta 普通主会话/群协作的容量规则不变。完成门禁检查关联协作、待回传结果和后台命令；摘要优先反映仍在运行/等待的执行，不能被后来排队的补充覆盖。若目标已完成/删除，迟到回传保留可见事实并跳过派发，不自动重新运行，也不能抛错阻塞整个队列。上述查询只读有界元数据，不逐工作加载消息正文。

完成与停止的归属补充：动态 workflow/coordinator 仅检查或停止工作自身固定 thread；协作前台执行与待回传按可信 `rootWorkId` 归属，协作后台 shell 按 control 中 `source_task_id` 找到的固定 command IDs 归属。不得因为某 Bot 曾协作过，就扫描或取消其整个主 thread。LocalSandbox 既有取消入口可增可选 command-ID 过滤，原调用行为不变，未匹配命令的通知与恢复不变。协作 Bot 已返回后自行运行的独立 workflow 仍归它自己的主对话，本轮不宣称将这类后续后台工作聚合进原工作；未来需要时再扩展可信来源关联。验收覆盖历史协作 Bot 的无关后台运行既不阻止完成、也不被停止。

## 11. M05-04 模拟渠道接口与展示决定

转达授权补充：新增工作转达工具与创建/完成一样，只在当前直接用户指令的执行中接纳。后台通知、例行任务和协作回包不能借此向另一工作追加新指令；原 beta 协作工具行为不变。模拟渠道后续从可信事件/绑定识别用户来源，不靠模型自报来源扩大权限。

仅在 M05-02/03 本地切片冻结复验后进入产品实现。使用既有 control 库中的独立 mock binding/conversation/event/outbox 记录，运行仍走原 Runtime。开发 DTO 不改变生产 `RemoteImEventV1`，不新增 WSS 或 Java 服务。

- 当前 Bot 的更多菜单提供“模拟 IM 接入”入口，弹窗明确模拟身份与渠道；不在详情常驻大块调试表单，不新增左侧服务 Bot。工作仍在统一右侧列表，只有轻量来源标识。
- 绑定由桌面显式建立/撤销，固定 Bot、个人或群受众、允许调用者与授权版本。群消息仅在真实模拟事件的提及字段或同渠道 Bot 消息引用成立时触发，不由正文自称被提及取得权限。不同个人/群不共用主 thread，普通问答不建工作。
- binding + eventId + payload hash 固定去重；事件接纳和首 BotTask 同事务。来源和受众从 binding 解析并冻结到 Task/Work，不接受模型参数或 `origin=user` 提升权限。回复 outbox 固定原渠道会话与关联消息，执行完成不等于送达。
- 离线只持久排队，恢复不重复执行；未知投递不自动重发。解绑/撤销后拒新消息，停未开始的相关执行并阻止待回传自动发出，历史保留；不把撤销等同删数据。
- 事件接纳后 IPC 回执丢失，应使用原事件标识与完整 fingerprint 核对持久回执。即使随后撤销绑定，桌面 owner 仍可只读核对同一旧回执；没有匹配回执则不能借核对重新执行。未落盘且已撤销的事件提供显式结束核对入口并保留记录，不能永久阻塞其他模拟渠道，也不能自动清除未知事实。
- 模拟消息原文直接进入会话和模型，但可信 `RemoteTurnPolicy.disableMessageControls` 禁止把 `/goal`、coordinator/内部通知标记、显式技能或 Mods 文本解释为桌面控制。不得先写模式或启动第二调度器再依靠工具白名单拒绝。此可选开关仅由渠道适配器设置，默认不影响 beta/生产 IM 既有行为；未来真实网关接入需复用并验收该边界。
- 重启恢复先以冻结高水位和稳定游标分批补回执，每批最多40条元数据，批间让出事件循环；全部恢复完成后才允许历史维护删除源任务。已执行/未知送达不得通过恢复隐式重放。
- 外部仅文字与同受众工作工具；文件/shell/浏览器/MCP/技能/私人记忆/配置/子代理均不开放。桌面查看外部工作不自动使该会话获得 owner 权限，不跨受众复制文件、记忆或模型上下文。桌面私有主/工作完整 beta 功能不受此策略影响。
- 验收只证明本地客户端边界与模拟收发；真实群提及、身份校验、设备路由、附件、租约/permit、平台送达和生产授权留给 M06-IM。

实施接点已审：独立 `simulation:true` DTO 不接受 thread/audience/owner/path/model，由绑定解析。可在既有可信 `RemoteTurnPolicy` 增加可选工具/技能/专家 allowlist 与 `disableHooks`，默认 undefined 保持 beta 行为；mock 实际工具执行同样拒绝未列名工具，不能仅从模型列表隐藏。全局 hook 在 Runtime 构造前的 SessionStart/UserPromptSubmit 也要使用本轮 disabled HookScope，后续工具/Stop 继承；不修改用户全局 hook 设置。渠道独立空 workspace 不带 feature/project/plugin，上下文禁个人记忆和 AGENTS。设备离线只影响模拟入口与队列，不阻塞本机 beta。桌面向外部工作追加时仍沿原受众，并明确会回复该模拟渠道。
