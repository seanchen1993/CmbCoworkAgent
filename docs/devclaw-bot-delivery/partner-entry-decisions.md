# DevClaw 伙伴入口与专家绑定

2026-10-11。用户确认可以新申请“DevClaw伙伴”招乎机器人，并要求按此思路继续本地开发。本文记录本次产品决定，不代表已经接入真实招乎或授权访问真实内网。

## 已确定

- 现有 DevClaw 机器人保留个人远程操作用途；新 DevClaw伙伴是团队协作入口。复用网关和编程引擎，不新建第二套 Agent Runtime。
- 招乎机器人账号不等于领域专家 Bot。一个新账号可服务多个招乎群，各群配置自己的默认 AI 团队 Group。
- Group 独立于招乎群和 Thread；单专家用仅含一个专家的 Group 表达。专家配置继续使用已冻结 BotVersion，不新增 Bot 套 Bot 或递归团队。
- 绑定发生在入群后的显式配置与确认，不是入群即授权。设计上需同时核验招乎群管理权限和 DevClaw Group 管理权限；用户文字不能充当群管理员凭证。
- 首期每个招乎群最多一个有效 Group 绑定；绑定键必须包含平台/企业及机器人身份和群身份。更换机器人身份不能自动继承旧账号的绑定或权限。
- Group 被多个入口使用不等于入口间聊天自动共享。任务入口范围、共享规则和源码可见性在接入前明确，不能把个人记忆自动注入协作任务。
- 每个需求对应独立 Task，执行 Thread 按 Task/执行节点关联。群绑定不永久绑定某台电脑或单个 Thread。
- 团队对外统一汇总，内部按职责选择专家；不做每条群消息唤醒全部专家的自治循环。
- 提示词分为基础规则、已有工作模式、版本化专家配置、任务上下文、获授权的显式记忆和输出约定。代码/业务确认是权威输入，记忆不能覆盖正式需求。

## 用户已确认的首期交互与运行方式

1. 触发与任务识别：只响应 @；显式“新任务”创建需求、任务编号继续澄清。不默认关联最近任务或监听整个群。
2. 首期执行节点：开发负责人在本地 App 显式授权执行环境，业务人员只使用招乎；离线等待，不借用其他人的环境，不承诺全天候运行。
2026-10-11 用户明确接受上述两项。采用开发负责人提供本地执行环境，不把群绑定理解成永久绑定电脑，也不在离线时自动改用其他人的节点。任务编号沿用当前服务端生成的 TASK-数字，不新增第二套编号。

共享范围仍采用安全的本地试点默认：每个招乎群使用自己的 Group；群成员身份映射和显式加入必须由后续可信适配器核验，不自动开放源码、工具或历史任务。

## 接入前需补的外部信息

新机器人平台身份、回调鉴权/来源、群和发送人识别、@判定、群管理权限查询以及群消息发送授权。由平台正式契约或可信适配器提供；本地开发不等待申请，继续使用假招乎与虚构资料。凭据只交受控服务端配置，不写进聊天、Git 或提示词。

## 本次接续与边界

B00/B01/B02 Task/text/events 已验收，不重做。先做 R01-A1 纯提示词装配切片：消费现有 BotVersion/Group/Task/ModeRef，分离系统指令与任务数据、排除个人/错范围/未确认记忆，验证配置快照与来源。现有需求/原型/项目模式的真实提示词由后续适配器提供，不在新模块复制。

后续执行闭环顺序为：Run/节点/授权最小服务端切片 → DesktopRuntimeProvider 复用 AgentRunService → 模拟招乎群绑定/路由 → App 配置与需求模式演示 → 获新授权后真实招乎联调。这里只给顺序，不把本次继续自动扩为整条路线授权。

R01-A1 不调用模型、不派发 Run、不修改旧 IM、不开放 UI/自动记忆/附件/搜索，也不改变开发数据库和原三服务。定时续跑继续停用；串行由主代理直接实施，不创建子代理。

后续Runtime适配必须同时关闭现有个人记忆/用户身份的默认注入，并使用获准的协作上下文；新装配函数只过滤其自身入参，不能阻止旧Runtime在其他位置追加个人资料。模型工具权限、共享输出与撤权也必须在执行/投递边界复核，不能凭提示词快照当授权。

R01-A2 接续：先实现纯群消息任务意图解析及现有 Runtime 的显式 sharedTaskContext 开关，只关闭个人记忆/员工身份的默认读取、注入和本次运行的个人记忆维护。此开关不是全环境沙箱或完整权限方案，不能阻止代码、技能、Hook、MCP或旧Thread历史泄漏；执行适配器还必须使用专用协作Thread、获准工作区、权限和持续撤权检查。当前不开放真实群执行或把旧个人Thread复用为共享任务。
