## 目标与范围

让一个 AI 团队承接需求任务，团队成员追加澄清，客户端能够读取当前任务和后续活动。复用现有 Java 模块化单体、可信本地身份、MySQL 5.7、事务回执及 HTTP 测试工具，不新增服务、消息中间件、工作流引擎或通用框架。

仅实现冻结 OpenAPI 的四个操作：

| 操作 | 接口 | 成功 |
| --- | --- | --- |
| createTask | POST /api/bot/v1/tasks | 201 TaskResult |
| getTask | GET /api/bot/v1/tasks/{taskId} | 200 TaskSnapshotResult |
| createTaskMessage | POST /api/bot/v1/tasks/{taskId}/messages | 201 TaskMessageResult |
| getEvents | GET /api/bot/v1/events?after=…&limit=… | 200 EventsResult |

接口/状态来源是 `contracts/bot/v1/openapi.json`、`schemas.json`、`state-transitions.json`；不修改这些冻结文件。只扩展 Java 生成器的操作白名单和相应离线闭包/消费。沿用严格解析及原六接口，不另造一套 DTO、认证或 HTTP Server。

## 最少必要语义

- Task 从属于 Group，不属于招乎群或 Runtime。当前有效 Group 成员可创建、读取、澄清任务；Task 继承 Group 当前成员权限，撤权后连旧命令回执和事件都不能读取。作者仅来自 TrustedContext。
- Task 初始 active；五个阶段按 requirement、assessment、prototype、scope_confirmation、development 排列，第一个 active、其余 pending；currentStageId 指第一个。阶段只作为 Task 数据存储，首期不建模式引擎/阶段迁移器。任务编号在空间内唯一且持久，普通重启不改变。
- 首期文本输入：inputArtifactVersions/artifactVersions 为空时正常工作；非空时以 INPUT_CHANGED/409 明确拒绝（成果服务尚未实现），不能静默丢弃或接受虚构引用。targetBotId 若提供须是当前 Group 中的有效伙伴；仅记为消息目标，不创建 Run、不触发模型、不投递消息。
- 创建/追加复用 `(space,principal,commandId)` 回执作用域、规范化 fingerprint、7 日过期和 tombstone；当前资源授权先于回放。相同命令返回原 status/body/ID，不增加 TaskMessage、事件或 Outbox。与旧 Bot/Group 命令复用 commandId 不能造成第二次副作用。
- 追加消息的 expectedVersion 是 Task CAS；消息、Task version/updatedAt、不可变回执、活动引用/Outbox 同事务提交。失败整体回滚。重启后相同 commandId 恢复已提交结果，不另造 commandId 或宣称未知提交失败。
- getTask 的 Task 与 snapshotCursor 来自同一数据库一致性截面。事件有空间内持久单调提交顺序；不能以时间戳/UUID 排序或无序 AUTO_INCREMENT 最大值冒充安全 head。可用单个空间 head 行锁实现，保持简单。
- 游标不透明、服务端持久绑定空间与高水位，有限有效期（本地先统一 24 小时）；不含身份凭据。首次 getEvents 无 after 只返回空列表和当前 head。after 未知/过期/他空间为 CURSOR_EXPIRED/410；每次增量按当前 Group 权限过滤，分页扫描推进，不能因不可见事件卡住或泄露正文。limit 默认 200、1..200，仅本接口允许这两个有限查询参数；拒绝重复/未知参数、非法数值或编码。
- 活动只含冻结 Event 的实体引用，不含需求/消息正文或凭据。复用现有 mutation_outbox，必要字段通过 V2 增量迁移追加；无派发器、消费者、租约、重试调度或清理 daemon。
- 数据库不使用物理外键；V1 SQL 字节与历史不能修改。只新增 V2，固定两版本 readiness 和必要索引/参数化 SQL。任务/消息可以以有界 Schema 校验的 payload 存储，不必将五阶段拆成多表。保留 JDK 8 与现有固定依赖。
