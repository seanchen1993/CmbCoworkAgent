## 用户行为

1. 点击服务专家进入主对话，普通问答直接回复，不创建可见任务，不要求验收。主对话使用已明确选择的模型和现有服务授权，持久保存并在重开后恢复。
2. 用户明确交办需要独立推进的工作时，主对话能够经窄typed意图创建Task及独立任务会话，并显示可点击的任务卡与真实状态。也保留明确的新任务入口。不得仅给建议或假卡片，不能把每条普通聊天都自动建Task。
3. 用户可在任务会话直接补充，也可在主对话明确指向已有任务转达。两处落到同一请求/同一Task，不复制创建、不重复执行；目标不明时澄清，不靠模糊字符串任意猜Task。主对话显示转达记录和链接，任务会话显示实际指令及来源。
4. 任务成功回复就是聊天里的结果，不创建成果版本、不自动发布文本草稿；结果可以讨论、说明或其他文本，不强制需求说明/PRD模板。本片实际能力仍为提供材料内的文本处理，不伪造文件/代码/浏览器操作能力。
5. 用户在任务会话点击轻量“完成”结束当前工作，服务端Task真实completed。无成果版本号/确认文档选择，无模型调用。主对话本身不出现业务完成按钮。普通模糊“好”不得直接作为可信完成命令。
6. 修改意见直接发消息，不存在独立退回表单。已完成任务保留会话，通过“继续处理”受控重新打开同Task再补充；保留原上下文，不强迫新建任务。不把运行结束等同任务业务完成。
7. 运行中补充仍保留既有持久顺序规则；停止指向当前准确请求，不清除目标或历史。失败、离线、未知状态有清楚提示；未知不普通重试重新推理，已知失败的继续操作幂等，不能卡在无动作可用的隐藏状态。

## 主对话与任务接线

保留Java身份/权限/Task/Run、单worker和明确模型绑定，不让服务专家伪装为beta本地Bot或借用私人Thread。主会话可用隔离的内部执行容器复用队列，但必须有持久main/task角色；普通聊天不进入用户任务列表，不走任务完成/成果逻辑。

主对话的创建/转达采用有界、可校验的typed意图；实施先给root具体协议。模型只提出意图，main核对当前scope、Bot、角色及允许目标，服务端再验证权限。目标引用只能是已提供给本次主对话的同scope Task或main新建结果。创建/转达命令与父请求先持久再发HTTP；模型推理成功但副作用未知时重放原命令，不重新问模型、不新建命令。需要多个阶段时明确顺序和恢复点，禁止半条卡片指向未建立Task。

已冻结协议：主对话使用单次纯文本协调profile，closed JSON envelope为`{reply: string, intent: null | {kind: 'create_task', sourceRequestId: string, title: string, contextSourceIds: string[]} | {kind: 'append_task', sourceRequestId: string, targetTaskRef: string}}`，每轮最多一个意图。任务profile仍输出普通文本。模型不得提供actor、path、command、CAS、执行模型或重写后的副作用正文；main从原用户消息和明确带入的冻结上下文构造工作材料。sourceRequestId和目标白名单必须核验，解析失败不执行，显示明确错误；普通回复不覆盖命令真实状态。服务的窄协调事务验证source main Run/actor/profile并保存parentMainRequest→Task回执，后续执行走原outbox和单worker；丢回包恢复原command不重问模型。主对话任务卡只由真实回执投影。 创建意图的contextSourceIds必填，最多12个，只能指向本次freeze里的主会话消息，合计UTF8最多24K；当前末条用户消息始终作为新Task目标，不再重复携入。[]明确不带历史，不回退为整段主对话；所选source IDs随action持久，服务再次核验与复制原文。向运行中Task转达时，先保存精确目标和原命令，状态为下一轮待发，目标idle后再提交；父main请求在协调落实前保留pending，后续主消息不提前推进服务版本。完成的最后同步接纳点同时检查该Task的待发协调动作，unknown仍待核对而不重跑。

仅去掉框架强制的需求文档/修订模板，保留BotVersion里用户自己的专家职责instructions。purpose/profile持久纳入claim/attempt绑定，旧M03及升级时在途Run按旧快照恢复，不把旧输出解释为新主对话JSON，不绕过unknown。

主对话只使用自身交流、明确携入材料和当前Task摘要/必要回执；不默认注入全部任务正文。任务执行使用自己的目标和历史user/assistant内容及本次补充，携入主对话上下文明确且有界。冻结上下文范围、来源、角色、hash与截止点并纳入执行binding/attempt；不能执行时读取不断变化的整个journal。超限采用清楚可验证的预算/摘要或明确提示，不静默丢关键材料。至少验证“修改上一条答案”无需成果版本仍准确得到上条assistant正文。

显示会话与执行Thread保持明确映射，重开/切换/身份变化和迟到回包不能串消息、串目标。端口是传输位置，若预览重启端口变化造成同专家会话不可见，应在完整服务身份验证下处理稳定scope和历史关联；不得通过仅同名/仅Task号复用其他服务数据。
