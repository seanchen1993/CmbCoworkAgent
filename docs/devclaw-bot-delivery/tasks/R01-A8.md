## 私有控制接口 /api/bot/local/v1/control

沿用严格 JSON、闭合字段、回环/身份/header/并发/正文限制与原固定大写 ErrorCode。不新增公共 F03 API，不改冻结 schemas.json/openapi/生成 DTO。

记忆来源 Source 是闭合联合，只允许：

- `{kind:"manual"}`；操作者由认证身份取得，不接收自报作者。
- `{kind:"task",taskId,taskVersion}`；同一空间/Group 的当前 Task，版本必须与传入相等，否则 INPUT_CHANGED。不抓取URL/个人历史。
- `{kind:"result",runId}`；同一空间/Group 的已结算结果，当前请求者可读。未产生结果或他组记录拒绝。

GroupMemory 闭合字段：`id,spaceId,groupId,version,text,status,source,createdBy,updatedBy,createdAt,updatedAt`。status=`active|disabled`；日期 ISO UTC 字符串；版本为1..JS安全整数。服务端生成ID/作者/时间。MemorySnapshot=`null | {revision,memories:GroupMemory[]}`；null仅策略disabled，有效策略explicit_only即使无条目也返回非null快照。revision为0..JS安全整数，独立于Group.version。

控制操作固定 body `{operation,...}`：

- `listGroupMemories {groupId}` → `{revision,memories,botPolicies:[{botId,botVersionId,memoryPolicy}],canManage}`。当前成员可读、canManage只当前Group admin；列表包含有效及停用条目，确定排序、最多100条。botPolicies仅当前Group绑定版本，不隐式latest升级。
- `createGroupMemory {groupId,commandId,text,source}` → `{revision,memory}`。
- `updateGroupMemory {groupId,memoryId,commandId,expectedVersion,text,source,status}` → `{revision,memory}`。
- `disableGroupMemory {groupId,memoryId,commandId,expectedVersion}` → `{revision,memory}`，停用不物理删历史。
- `inspectMemorySnapshot {runId}` → `{memorySnapshot}`，必须当前该Run的Group读取授权。

写操作仅Group admin；Bot maintainer/节点owner不自动等于此Group admin。每次写入同事务核对Group、Source所属关系、CAS及命令重放前当前授权。命令需持久化幂等回执：同command同载荷返回原结果，不新增revision；异载荷/操作/目标拒绝COMMAND_CONFLICT；提交未知不换command盲重放。固定锁序，使用PK/unique/应用检查，不物理FK。

上限：最多100条存储记录、10条active；单条非空text最多512 UTF-16 code units，拒绝NUL/不成对surrogate。装配预算按实际`JSON.stringify([{scope:"group",sourceRef:"memory:<id>:v<version>",text},...]).replace(/[<>&`]/g,JSON unicode escape)`不超过10000 UTF-16单位。固定按memory ID排序，预算包含包装；超限拒绝发布PAYLOAD_TOO_LARGE，不静默截断。Java/TS统一该算法与Unicode负例；不涉及完整token路由。

## start 快照与在途变更规则

既有 start `{run,input}` 的 input 新增必需 `memorySnapshot` 字段；不在Run票据增加字段。首次成功start同事务保存有界快照（实际内容、版本、来源），重复start同Run/attempt返回相同快照；不得再取latest。disabled也需持久化“null已取”的状态，防后续策略/资料变更悄悄换输入。

策略explicit_only时，freeze当前Group revision及active条目；disabled返回null且不让记忆更新无意义地打断未使用记忆的任务。执行器只接受匹配当前space/Group、active、唯一ID及确定排序的合法快照，组装成group显式记忆。来源是资料不是指令，不扩工具/审批权限；原个人记忆关闭规则不变。

采用Astra保守首版规则：显式记忆的在途运行若revision改变，下一renew或首次settle拒绝旧输入并阻止结果发布；客户端停止当前图，不自动重跑。需要留下可读且终态的失败结果`outcome=failed,text=MEMORY_CHANGED`（内部新增固定失败原因），释放Group运行容量，不能把每次正常记忆编辑都变成永久占容量的outcome_unknown。实现前后都保留既有真正租约过期/结果未知不重跑语义；若租约已过期，不能用记忆变更掩盖未知。已成功结算的旧结果仍按当前授权幂等重交，不因新记忆重算。

运行记录是历史，不宣称停用抹除既有结果/快照/备份或已发模型上下文。服务端用当前授权和revision约束执行，提示转义不是防注入沙箱。

## App 行为

- 新建团队显式选择“使用团队记忆”，默认disabled，不暗改旧BotVersion。
- 既有专家启用：维护者发布仅将memoryPolicy改为explicit_only的新BotVersion，再由Group admin明确采用；若当前BotVersion与Group固定版本不一致，提示先核对专家版本，不偷偷采用latest或覆盖其他配置。多步操作保存原计划、command和CAS，失回执重放原载荷。
- 团队页显示policy、来源、条目状态、更新时间；手工新增/编辑/停用/重新启用，变化影响在途分析有明确提示。
- Task回复/结果可预填“记住到本团队”，但须用户整理并明确发布，不自动存整群文本；source taskVersion来自对应Task，不猜最近任务。
- Run详情展示使用的memorySnapshot及来源，包括历史快照；Runtime SQLite无团队记忆缓存，不离线借缓存执行。
