# F02 · 发布凭据隔离

任务单版本：1 · 2026-10-01 · 状态：accepted（受控边界范围），独立证据见 `../reviews/F02-acceptance.md`；真实发布连接器仍不可用。

## 目标

关闭需求凭据进入聊天/模型/会话/记忆/明文日志的程序入口；凭据仅由主进程受控适配器消费，不让 UI 或 Skill 重新取回原文。同步保留已有需求查询功能。

## 已核对的调用链与边界

- `RequirementConversationView.tsx` 的发布动作把 `getToken()` 结果拼进 queued message；`queueLeanstarToken` 是独立泄露旁路。
- `requirements.ts` 在需求 `index.json` 存明文 Token，`writeRequirementIndex` 会继续拷贝它。
- `leanstar-requirements.ts` 在 renderer 获取 Token 并发送 `Ls-Access-Token`，共六个已知只读业务操作（含两个 POST 查询）。
- `requirement-mode.ts` 允许 `requirement-to-prd`，但本仓库没有该 Skill 或正式发布 API 实现。不得猜接口、安装外部发布 Skill、发送真实凭据或伪造发布成功。

本轮交付是安全边界、受控发布接口和确定性 Mock 验证。生产连接器缺失时发布必须返回 `CAPABILITY_UNAVAILABLE`；此项在报告中保留为实际联调限制。既有需求生成、查询、原型等无关能力不应被移除。

## 设计决定

### 1. 主进程凭据存储

- 新增窄域 `RequirementCredentialStore`，归当前本地用户 profile，只服务 Leanstar 需求查询/发布，不创建通用密码管理器。
- 不透明 `credentialRef` 用于引用，引用本身不授予权限。对外仅返回 configured、可用性、引用和安全错误码，不返回 Token。
- 持久化用 Electron OS-backed `safeStorage`，拒绝 unavailable、Linux `basic_text`/unknown 等不安全后端；不提供明文 fallback。借鉴现有 trace/local-storage 的可用性检查，不引入整个 trace 存储。
- 密文文件置于主进程配置目录而非需求工作区，目录/文件权限收紧；原子写入、保存/迁移串行化，防止并发修改旧索引回写 Token。
- 旧索引 Token 只有在加密存储成功、核对可读后才能从旧索引移除；失败不丢失唯一副本、不新建明文备份，明确报告迁移失败且拒绝使用。保存新 Token 不把原文写回索引。
- 凭据只在受控操作内解析；不要通过工具参数、子进程环境、命令行、临时文件或聊天传递。有效性由上游返回判断，不捏造 Token 到期时间。

### 2. 窄 IPC 与 renderer

- 移除原文 `getToken` API/IPC；增加 `getCredentialStatus`。保留或改名 `saveToken` 均可，但输出仅为状态/引用。
- 管理凭据只打开密码输入框，保存后清空输入，取消也清空；UI 文案是“配置/更新凭据”，不再有“发送身份令牌”。
- 删除所有 Token 相关 `addQueuedMessage` 路径。发布按钮不再把发布动作交由模型带密钥执行，改为受控主进程入口；普通需求对话保持不变。
- 涉及凭据、代理查询、发布的 IPC 校验当前主 App WebContents、主 frame 和准确 renderer URL；来源来自 Electron event，不接受 payload 自报。可在 `registerRequirementHandlers` 注入 trusted-event 回调，生产 wiring 在 `main/index.ts` 绑定当前 mainWindow 和 trustedMainRendererUrl；默认必须拒绝。

### 3. 已有查询接口迁移

- renderer 现有 mock 数据保持开发演示兼容；真实查询调用受控 IPC，由主进程附加凭据。
- 输入使用六个操作的枚举/判别联合及必要字段，不接受任意 URL、headers、method 或任意网络 body。按现有 renderer API 的六个已知 endpoint 构造请求，保持响应封装兼容。
- 主进程网关地址来自明确配置（优先 runtime 环境 `LEANSTAR_REVIEW_GATEWAY_URL`，兼容原 VITE 配置需明确构建映射），必须为 HTTPS、不得含 userinfo/query/hash；未配置明确失败。使用 redirect:error，超时和响应大小上限；测试全部注入 fake fetch，不访问真实网络。
- 401/403、网络失败、非 JSON、超限和非法操作返回安全错误码/固定说明，不回传上游原文、URL、headers、Error.message/stack。成功数据中发现凭据回显也拒绝，不能把秘密回传到 renderer 后进入模型。

### 4. 受控发布契约

- 生产默认无发布适配器；不从 renderer 接受 endpoint 或执行脚本。测试注入 `RequirementPublisher` fake，真实适配待发布 Skill/API 确认。
- 发布通过 prepare/confirm 两步边界：prepare 校验需求与关联 Thread、正式 PRD 和文件版本，得到短时 requestId/准确输入摘要；confirm 由用户点击路径执行，验证 requestId、credentialRef、commandId、输入未变、授权未过期。作用域绑定当前 App/profile、reqId、threadId、凭据用途及输入摘要；不能换需求复用。
- 固定输入摘要必须覆盖实际 PRD 文件字节，不只 manifest 字段。拒绝路径逃逸和 symlink 越界读取；不把 caller 提供的本地绝对路径当权威输入。
- 只向适配器在内存中提供必要凭据与固定输入。授权过期、凭据缺失/失效、输入变化、连接器缺失返回明确错误；失败不得把 manifest 改成 published。
- 同 commandId+同载荷复用结果，同 ID 不同载荷拒绝；可能发生外部副作用后超时/中断返回 OUTCOME_UNKNOWN，不能自动重试。允许进程内批准票据和幂等记录，明确它们不提供跨重启 exactly-once；重启后旧 requestId 失效，不自动重放。
- 不添加给模型读取凭据的 tool。需求模式提示同步说明必须由用户使用受控入口，不要求用户向聊天粘贴 Token。

## 验收

- 哨兵凭据不进入 renderer 返回值、queued message、模拟模型/会话/记忆载荷、普通日志、需求索引或发布结果；通过真实边界测试，不只 grep。
- 加密不可用/坏密文/迁移失败/并发保存/权限错误、非主 frame 调用、未知凭据引用均有负向用例。
- 六个读取操作行为兼容；任意 URL/headers/路径注入、重定向、超时、401/403、错误或成功回显 Token 均有用例。
- 发布 fake 验证明确授权、输入变化、过期、幂等重复、重复 ID 不同载荷、未知结果不重放；生产缺适配器明确失败且不入聊天。
- 运行 node/web 类型检查，新增及 `src/main/ipc/requirements.test.ts` Vitest，`tests/requirement-*.spec.ts` 相关 tsx 回归；`tests/requirement-manifest-loading.spec.ts` 定位锚点若变化做语义等价调整。

## 非目标与停止条件

不重写企业凭据平台、不改全局认证、不接入真实内网或发布文档。需要扩大范围或无法确认外部副作用时，先报告。历史聊天中可能已泄露的旧 Token 不自动擦除，应由用户轮换并按既有保留政策处理。
