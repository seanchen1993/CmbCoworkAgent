# F02 · 发布凭据隔离

状态：draft，未派发。当前仅为可恢复的任务草稿；主代理完成调用链核对和接口设计后，才能转为 ready。

## 目标

消除需求发布 Token 进入聊天、模型请求、会话持久化、记忆和明文日志的路径，同时保留明确授权后的发布能力。

## 已知入口

- `src/renderer/src/components/requirement/RequirementConversationView.tsx`：`handlePublishToRequirementSpace` 和 `queueLeanstarToken`。
- `src/main/ipc/requirements.ts`：Token 获取/保存入口。
- 需要继续核对 preload 类型、实际发布 Skill/工具及外部发布接口。不得只删消息中的 Token 就宣称整个发布流程已修复。

## 主代理派单前需确定

1. 实际发布调用链与凭据当前的消费位置。
2. 受控发布入口、credentialRef 的归属、用途、有效期和错误处理；模型不能获取真实秘密。
3. 可修改的具体文件与新增测试位置。
4. 外部系统资料缺失时的边界：使用 Mock 验证，明确未验证项；不猜生产接口或读取真实凭据。

## 验收

- UI 操作不再向 queued message 拼入真实 Token，也不存在“发送身份令牌到对话”的旁路。
- 使用测试哨兵字符串验证模型输入、消息持久化、记忆和日志不含秘密。
- 缺少/失效凭据得到明确可恢复错误；不能静默视为发布成功。
- 发布仍需要明确用户授权，重试需核对副作用与幂等性。
- 类型检查、需求相关回归、发布路径正负向测试通过；主代理独立复验。

## 非目标与停止条件

不重写企业凭据平台、不改全局认证、不接入真实内网或发布文档。遇到接口缺失、必须扩大范围、无法确认外部副作用时，更新 attempt 报告并向主代理说明。
