# DevClaw 伙伴：专家优先的本地开发版（R01-A9）

本轮只用模拟模型，不使用已有API密钥，不调用真实模型/真实招乎。服务端是现有Java单体的可选开发启动入口，不是生产WSS/云Runtime。App是新独立“DevClaw伙伴”页，原机器人管理不变。

## 开发与合并顺序（2026-10-13 用户确认）

先保留 `services/bot-control` 独立本地开发与启动，把 App、控制服务、MySQL、假招乎和模拟模型闭环跑通；现阶段不引入原 IM 网关的内网专有依赖，避免本地开发被内部 BOM、认证和平台环境阻塞。

本地验证通过后，再将伙伴业务模块合入原 IM 网关工程。最终复用统一服务部署与已有 App WSS 连接，保留 IM 接入、伙伴协作、节点与 Runtime 的职责边界；HTTP 管理和执行控制接口可以继续使用，不另建重复生产 WebSocket。当前伙伴传输仍是 HTTP+轮询，并没有实现第二套 WSS。实际合并需网关工程和依赖环境到位，届时明确范围；本条记录不授权立即合并或连接内网。

## 启动

### 一键本地预览（自动连接；启停收尾验收中）

2026-10-15：本地测试已取消手动导入和“连接服务”步骤。启动脚本默认提供本机服务配置，App 自动核对负责人、业务测试身份和节点身份，并在主进程加密保存配置；不把凭据写进源码或返回页面。打开伙伴页后直接创建专家，无需手选目录。

启动、状态、重复启动、固定配置重开与显式 `stop:bot-preview` 已通过真实检查；Ctrl+C 的 Node25→Node22 引导进程退出收尾仍待修复。**目前请使用下面的 stop 命令，不依赖 Ctrl+C 关闭后端。** 此脚本尚未标记全部验收完成。

在下述集成工作树执行：

```sh
npm run dev:bot-preview
```

脚本自动复用本机已安装的 Node22，安全构建本地页面，启动独立 Partner MySQL 和 Java 控制服务，打开真实 DevClaw App 并定位到“DevClaw 伙伴”。命令在终端前台运行；再次启动不会重复创建 App 或控制服务。找不到 Node22 时会停止，可用 `DEVCLAW_NODE22=/absolute/path/to/node22 npm run dev:bot-preview` 明确指定；不自动下载或安装。JDK8、现有任务 Docker/Colima 环境和 Java 构建产物仍须已准备好；首次缺少 jar 时先执行 `npm run test:bot-service-build`（使用 Node22）。

App 使用任务私有目录中的固定 `preview-app/data` 与 `preview-app/electron`，保留自己的连接配置、任务和运行记录，不使用个人 App 配置/历史/API 密钥；HOME 不改变。每次重新构建会禁用环境文件中的远程页面、模型目录、更新和上报配置，浏览器只允许回环连接。默认连接配置由启动器的 `CMB_PARTNER_LOCAL_CONNECTION_FILE` 提供，仅未打包的本地预览生效；初始化失败会显示错误并在状态刷新时重试，不降级到远程地址或其他身份。**创建/绑定专家时自动准备专家数据目录，但不会自动授予执行权限、启用节点或运行任务**；已有手选目录不覆盖。

```sh
npm run status:bot-preview
npm run stop:bot-preview
```

`stop:bot-preview` 先关闭自己记录且核对了进程身份的 App，再停 Partner Java 服务和独立 Partner MySQL；**保留 App 数据、数据库卷和凭据**。不停止原 MySQL/ES/S3、任务 VM 或其他 DevClaw 实例，不 prune，不恢复定时续任务。发现 PID 复用、失去管理的 App 或未知状态时拒绝盲目强杀，保留记录供核对。

## 最简交互

App → 自定义 → 高级特性 → **DevClaw伙伴**：

1. 使用一键预览时，打开伙伴页即默认配置并连接本地服务，无需导入文件或点击连接。普通分步启动且未指定本地预览配置的 App 仍保留手动连接方式；打包版不启用此自动配置。
2. 填专家名称和职责，点击“创建专家”；支持手工确认的长期记忆，不自动学习。默认目录自动准备，点击“启用本机”确认24小时模拟执行授权即可。当前零工具、不读取代码；创建专家不自动启用。
3. 任务区模拟结构化 `@专家`，发送 `新任务：按日期查询交易，先澄清业务范围`。任务创建不会自动分析。
4. 按返回编号发送 `TASK-编号：仅查询本人有权限的交易`，点击分析需求。
5. 页面展示排队/执行状态和标明“模拟模型返回”的持久结果。没有真实分析、代码可行性判断或正式审批。

节点未启用时先排队等待，不借用其他人执行环境。新任务/澄清/分析分别对应明确操作；没有@的消息不读、不存，不猜最近任务，不依赖回复串。

“启用本机”内部依次登记节点、核对当前授权并启用轮询；失败不谎称已启用，已明确完成的授权不会被伪装为未发生。服务端沿用60秒心跳过期判定；刚停止后的短暂宽限期可显示排队，随后是waiting_node。Group仅为后台自动创建的任务/授权关系，界面包括高级设置均不展示；不提供旧版绑定、团队记忆或采用切换。高级设置仅保留连接诊断、目录、本机授权撤销与任务/执行查询，不要求用户配置团队。

## 停止与重开

页面“停止本机”停止轮询/心跳并等当前图清理，不假装一点击就终止。只允许取消未领取任务，已运行的用停止本机处理。高级撤销授权仍由服务端当前权限复核。结果未知不自动重跑或迁移。

一键预览重开 App 默认自动连接，但不会启用节点；连接后可看到上次执行的持久结果。控制服务 stop/start 可能更换回环端口，预览重开会自动读取当前默认配置；身份相同则保留 App 的工作区、团队与回执。普通分步启动未提供本地预览配置时仍默认不连接、不执行，需手动导入和连接。

```sh
npm run stop:bot-partner
```

stop保留本地控制库、私有凭据和数据卷，不删除数据。原MySQL/ES/S3和定时任务状态不受影响，自动续任务继续PAUSED。

写入请求先保存原command/版本/期限。若回执丢失，只能用完全相同内容重试；页面提示INPUT_CHANGED时不要换新内容盲目重放。跨期限未知写入暂需人工核对，不包含本轮自动协调恢复。

## 专家长期记忆与默认目录

长期记忆归已有专家Bot的稳定ID管理。当前专家维护者可手工新增、编辑、停用；保存的知识供已采用该专家记忆的任务共享，不是个人私有记忆。首版只接收手工说明，不自动把群消息、任务或模拟结果变成跨群知识。管理页支持轻量关键词检索，不引入ES或向量库。

MySQL5.7是唯一权威源。App默认在 `getCmbCoworkAgentDataRoot()/partner/<服务hash>/<空间与身份hash>/experts/<专家IDhash>/` 保存私有 `metadata.json`、`memory-cache.json` 与 `runtime/`；预览时根在专用 `preview-app/data`。目录使用稳定ID、不随专家名或版本改变；拒绝符号链接/越界。原有用户手选路径保留；更换运行目录不会搬迁专家数据或授予源码权限。

本地JSON只是有界、可重建的维护缓存，全量替换；不作第二个主库，不传入执行器。离线或维护权无法确认时不展示缓存正文、不积压本地写入；分析始终消费服务端start的冻结快照。

第一版不提供旧配置迁移/恢复入口，创建专家即使用专家记忆，不需单独选择采用策略。后台现有数据不因界面清理被删除，既有运行记录也不会被静默重解释。每次首次start冻结实际revision/内容，重复start不换资料。记忆变更只使对应范围的在途分析终态失效（MEMORY_CHANGED），不自动重跑；已完成结果不重算。停用不擦除历史快照、结果或备份。

首版上限仍为100条存储（含停用）、10条有效、每条512 UTF-16单位、包装转义后10000单位；固定顺序、不静默截断。没有自动学习、自动提炼或向量检索。专家指令和性格仍由已有不可变专家版本管理，版本术语不放进主流程。

Partner默认启动仅MySQL，不依赖ES/S3。原三服务环境及其独立验证入口保留；本轮没有删除或停止原ES/S3资源。若未来需搜索/附件存储，再接对应能力。
