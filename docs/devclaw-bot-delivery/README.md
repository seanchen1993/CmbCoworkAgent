## 1. 三种限制分开处理

| 情况 | 恢复方式 | 不允许的做法 |
| --- | --- | --- |
| 上下文接近窗口上限或发生压缩 | 更新检查点；从任务单、Git 和报告恢复必要上下文 | 把整段历史日志反复塞回提示，或假设压缩保留了所有细节 |
| 账号调用额度暂时用完 | 记录等待原因及平台给出的恢复时间；额度恢复后由当前会话后续唤醒核对并续做 | 创建更多代理、切换账号或模型绕过限额；自动购买额度/使用重置权益 |
| 用户设置的预算耗尽、主动暂停或停止 | 保存进展，等待用户明确调整/恢复 | 定时任务绕过预算或擅自恢复用户暂停 |

主代理与子代理的用量均计入适用的账号/模型额度；并行不是增加额度。查询结果缺失表示未知，不表示无限或已恢复。

## 2. 持久记录

| 文件 | 职责 | 写者 |
| --- | --- | --- |
| `state.json` | 基线、授权范围、任务状态、当前 attempt、唤醒配置、下一步 | 主代理 |
| `HANDOFF.md` | 人和恢复后的主代理可快速理解的当前进度、风险、接续步骤 | 主代理 |
| `tasks/Fxx.md` | 目标、范围、契约、验证、依赖和停止条件 | 主代理 |
| `attempts/<taskId>-<attemptId>.md` | 实施过程、实际修改、测试、未完成项和下一步 | 被指定的实施代理 |
| Git 提交与工作区 diff | 实际代码；检查点不完整时用于重建事实 | 各任务工作树的唯一写者 |

`state.json` 是调度索引，不是分布式数据库或权限凭据。不能同时开两个主调度会话修改它；如需转移主会话，先确认旧主调度停止并移交。记录与 Git 不一致时进入核对，不以 JSON 状态强行覆盖代码。

本文及同目录任务文件纳入 Git。根目录 `AGENTS.md` 是当前工作树的本地入口，受仓库原有忽略规则影响，不作为跨工作树恢复的唯一依据。派单时必须显式要求阅读本文；新工作树没有该入口时也遵守相同规则。

## 3. 主代理如何派单

1. 核对当前用户明确授权的任务范围。里程碑结束后不自动扩大到后续路线。
2. 明确任务目标、禁止范围、接口版本、验收条件与失败处理；任务单从 draft 进入 ready 后才能派发。
3. 从已验收集成基线准备独立工作树，向子代理提供准确目录、基线提交、任务单和可修改文件。
4. 派发前记录新的 `attemptId`、工作树和预计交付；创建后补上实际代理 ID。ID 是定位线索，不是恢复成功的前提。
5. 显式指定 `gpt-6.1-sol` 与用户最新选择的 `high`。自包含任务简报替代全历史复制，避免继承无关上下文和错误默认模型。
6. 子代理先阅读任务单和旧 attempt 报告，再检查 Git；不得仅凭摘要重新实现已有功能。

首轮最多一个实施写者；子代理不得自行派生更多代理。指定模型不可用时报告并等待，不自动替换模型。共享文件系统不等于自动隔离，后续并行必须明确工作树与文件归属。

若派发后、记录代理 ID 前恰好中断，先列出当前代理并核对任务名与工作树，不直接重复创建第二个写者。

## 4. 实施检查点协议

每完成一个可验证的小步骤、开始长测试前、测试返回后、遇到阻塞或需要交还任务时，更新 attempt 报告。至少包含：

```text
任务 ID / attempt ID / 任务单版本
模型与推理强度 / 实际代理 ID（若可得）
工作树 / 分支 / 基线与当前提交
已修改文件 / 未提交改动 / 新增未跟踪文件
已完成项 / 未完成项 / 下一个具体动作
测试命令、时间、退出码、对应代码版本或 diff 状态
仍在运行的命令及句柄（若有）
副作用是否发生、结果是否确定
阻塞原因 / 是否需要用户决策
```

检查点不保存真实 Token、Cookie、账号凭据、预签名 URL 或大段敏感日志。测试结果应说明对应哪个代码快照；修改后的代码不能沿用修改前的通过结论。

可审阅的小步提交有利于恢复；未完成改动可以保留并准确记录，不为制造“干净状态”而删除或提交未经检查的所有文件。共享集成分支由主代理独占管理。

## 5. 主代理与子代理的恢复步骤

### 主代理恢复

1. 阅读最新用户消息、`state.json`、`HANDOFF.md` 与当前任务单，检查暂停/预算/授权边界。
2. 核对工作树存在、Git 分支与提交关系；检查 dirty diff、未跟踪文件、未完成 merge 和运行中的命令。
3. 查看现有子代理状态，确认当前任务是否仍在执行。子代理已完成时先验收，不重新派发。
4. 若暂停原因是额度，查询当前适用额度；可用才推进。已知 `not_before_utc` 尚未到期时不启动新实现。
5. 处理唯一一个 ready/恢复中的任务，或处理待审查结果；每次唤醒不需要完成整个里程碑。
6. 更新持久记录。只向用户报告完成、实质风险、失败或待决事项，重复等待保持安静。

### 子代理恢复

- 原代理仍可用且未在执行：向该代理下发接续说明，保留同一任务。
- 原代理不可恢复且已经确认停止：保留原工作树与代码，为同一任务分配新 attempt 和新的 `gpt-6.1-sol` / `high` 代理。
- 用户明确更改推理档位且现有代理工具不支持就地修改时：先确认旧写者停止、当前额度允许，再保留原树/代码并记录配置变更的新attempt。此情形不能用于绕过额度限制。
- 无法确认旧代理是否仍写文件：标记 `writer_state_unknown`，不并发启动替代写者；先调查或请求介入。
- 额度中断与代码失败分开记录。额度恢复不清除真实测试失败，代码失败也不靠等待额度自动变好。

不能保证工具调用中途有机会写“最后一份摘要”；因此恢复必须能从上一个检查点和真实工作树补齐。涉及发布、推送、消息发送等外部副作用的未知结果，需要核对，不自动重做。
