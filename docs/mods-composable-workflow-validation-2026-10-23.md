# 可组合插件改造：实现与联合验收记录

日期：2026-10-23。分支：`codex/mods-v2`。应用版本：**2.0.0**，保持固定。

本文记录本地功能及联合回归；安装包是否可用，以同一提交的 GitHub Actions 构建及包内测试结果为准。

## 1. 实现范围

- 通用创造者新增 `read_workflow` / `transform_workflow`，支持插入步骤、修改技能和替换步骤，绑定实际来源、工作流摘要和草稿版本。
- 受保护基线来自真实原插件。作者尚未发布的新步骤可以多轮修改，原必要校验、知识、配置、Hooks 身份和原状态身份不能通过分次修改删除。
- 精确来源替换证明允许受审修改既有模块；普通同名模块仍拒绝。大原始资源使用摘要引用，不进入新增作者代码预算。
- 重新计算入口与依赖，原快捷入口不能绕过新前置步骤；变更后旧预览、试用和确认失效。
- AutoBiz 状态 Mod 使用原编译器的实际有效流程，保留原唯一写入器和双文件检查，不再固定七阶段。
- 新增 JSON Schema、命名空间内业务校验和上游物理回执核对。生产步骤的完整实际契约包含 Schema、版本及校验绑定，变化后不能复用旧证据。
- 原候选代码摘要规则显式用于 Mod 状态提交；准备、持锁检查和提交确认后的代码或决策变化均阻止写入，不在锁内触发旧回退副作用。
- 公共阶段回执维持原六字段。严格交接策略放在插件私有物理回执中并与检查摘要绑定，不扩展平台公共 Schema。
- 独立供应商业务使用同一套通用改造和组装入口，在原 Host 执行器中完成转换、资料整理与决策，不增加新的平台业务适配器。

## 4. 有效证据与限制

本地机器证据位于 `output/workflow-composition-regression/combined-result.json`、`output/workflow-composition-full-journeys.json` 和 `output/autobiz-function-state-journey/`。这些是本地运行产物，不作为业务源码提交。

自动化验收控制业务样例、模型响应及外部应用元数据，真实运行本地脚本和执行器。没有将其表述为远程模型完全自主创作、真实企业知识库接通或用户机器环境验收。

AutoBiz 状态提交适配器面向 Windows 本地 NTFS。新增严格产物交接目前限定为不超过 256 KiB 的普通文件。历史项目任意状态迁移、任意外部事务回滚和所有旧直接写入入口接管不在本轮承诺中。

本轮没有完成所有性能读链路收敛：Python 状态查询和每轮知识准备仍需按整体方案优化。后续平台/插件职责、统一项目投影、缓存与失效、创造交付和复杂恢复见[整体优化分析](mods-plugin-project-systematic-optimization-analysis-2026-10-23.md)；具体操作及安全边界见[创造与使用说明](mods-composable-workflow-creator-guide-2026-10-23.md)。
