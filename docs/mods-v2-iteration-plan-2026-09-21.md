## 目标和事实

原计划 `mods-v2-final-implementation-plan.md` 及兼容矩阵继续有效。
本计划补充业务闭环的实施顺序，不把业务完成等同于 Claude 全量兼容。
主工程已有 `runCompletionHooksWithRevision`，支持传统 Stop/PostSkillUse 请求修复。
缺口是 Function Mods 的受控接入、证据绑定、可靠恢复及业务状态提交，不能另建一套主 Agent 循环。
`turn.complete` 是结束后观察；完成前门禁必须在运行 lease 释放前执行。
独立 `model.complete` 不是主 Agent 的 `turn.step`，不得冒称兼容。

## 批次及验收

1. **执行控制基础**：复用现有完成循环，加入严格的完成门禁回调契约；区分通过、请求修复、阻止结束。
   门禁异常或无效输出不得当作通过；等待检查时取消不得触发修复或后续检查。
   有门禁时所有修复共享宿主预算，拒绝靠切换 Hook 重置预算。
   本批仅为宿主内部接口，不宣称插件已经可以使用。
2. **Function Mods 生产桥接**：绑定 workspace/thread/turn/authority/generation，把经过授权的插件检查接入完成前循环。
   明确所对齐的 Claude Stop 字段、执行时机、错误与 `next` 语义，更新兼容矩阵和授权摘要版本。
   required gate 不得复用可选观察 Hook 的异常放行语义；插件不能通过覆盖结果消除其他门禁失败。
   覆盖桌面、后台、远程支持范围；未接入的入口明确拒绝开启强制模式。
3. **证据与可恢复执行**：绑定本次 diff、需求、检查输出与版本指纹；修复后旧 PASS 失效。
   保存运行、检查与尝试记录，恢复后重新确认授权和工作树版本；不重复执行有副作用的推进。
   限制次数、时间及模型用量；用户停止、拒绝、撤权不自动重启。
4. **Autobiz 业务集成**：调用上游真实 validator；检查不通过反馈给原 Agent 修复。
   只有有效检查证据允许状态转换；校验和提交之间重新检查 checkpoint 与文件指纹。
   不将非空文件或模型自报 PASS 当作验收。保留 classic hooks，明确哪些启用，避免双执行。
5. **用户 DIY 体验**：提供“仅报告 / 检查并等待 / 自动修复复检”配置及项目作用域。
   展示当前生效规则、执行步骤、证据、预算和失败原因；关闭后行为恢复；配置重启后保留。
   同一任务分别关闭/开启模块录制对比，不能用手动命令替代自动流程验收。
6. **原对齐计划剩余项**：继续经典事件适配、主 Agent 控制、动态上下文分类、工具 schema、UI surface。
   每项保留“已验证 / 部分 / 未支持”证据，不以同名 API 或插件可加载认定 parity。
