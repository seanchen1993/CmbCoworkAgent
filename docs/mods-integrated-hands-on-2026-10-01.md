# 用 Autobiz 体验 DIY Claw

后续共享子任务、模型配置和提示词来源的能力扩展，见
[2.1.288 迭代说明与作者示例](mods-task-sources-delivery-2026-10-03.md)。

本轮可以体验：选择能力、给不同步骤分配模型、组合不同插件，按明确路径执行，再用真实
测试结果判断任务是否完成。仍需配置模型并完成项目权限审批。官方发布后的提示词组合与
内置上下文计量，另见[最新实现与使用说明](mods-official-launch-implementation-2026-10-02.md)。

## 先打开可以体验的项目

导入包：`output/autobiz-integrated-2026-10-01-final/AutobizDevOps_Plugin_Kanban_Mods.zip`。
同目录的 `autobiz-source-project` 是固定上游源码的独立副本，可以作为本地项目打开；
原 `C:\ai\autobiz_kanban` 不会被示例准备过程修改。

1. 新建本地项目对话，工作目录选择上述源码副本。
2. 打开“自定义 → Function Mods”，上传 ZIP，检查并批准当前代码版本，开启应用和项目 Mods。
3. 打开“My Claw”，创建组合，选择 Autobiz 包里的所需组件。只选状态就不会启用看板命令；
   选择看板时需同时满足状态依赖。原 Skills/MCP 按各自的选择区配置。

第一次建议只选“状态与产物检查”，不添加自动完成规则。避免第一次体验同时配置太多控制。

## 创建一条能看出区别的流程

1. 打开“自定义 → DIY 流程”，展开“Autobiz 实际项目预设”。
2. 先选 **Autobiz · 只检视**。给它命名，在步骤中检查 Agent 角色和模型。
3. 模型选择方式三选一：默认、Claw 模型角色、固定型号。比如检视使用强模型，
   汇报使用较便宜的模型；需要在应用模型配置里事先添加这些型号。
4. 保存流程，回到 Claw 组合选择这个流程，再保存组合。
5. 选择“在当前对话使用”，核对新增/移除的组件、模型、规则和流程，然后“确认应用”。

保存只保存模板；确认应用才改变当前对话的活动副本。应用前的差异清单不展示敏感参数值。
如果期间有人修改配置或工作目录，旧预览会失效，需要重新核对。

## 在对话中触发

打开右侧 Claw 面板，在聊天输入区选择 **执行流程**，输入目标并发送，例如：

> 检视 inspect_state.py 处理中间阶段和未知 checkpoint 的逻辑，读取相关测试，给出带文件位置的结论。

你会看到“检视 → 汇报 → 人工确认”的执行记录。它不会自动测试，也不会修复；
结果区会明确显示未执行原生项目测试。

**“运行已保存版本”只运行所选的已保存流程一次**，并非把所有将来的普通消息永久变成该流程。
应用 Claw 后，普通聊天会使用该组合选择的能力与模型，但要执行多步骤流程，仍要选择“执行流程”。
如果希望每次任务完成都必须检视，应另行配置项目完成规则或 Claw 附加规则，不能靠保存 Flow
就假定已经建立自动完成门禁。

## 比较第二、第三种组合

复制或新建预设后，仍需保存、选入 Claw、确认应用，再执行。

| 预设 | 用户能感受到的差异 |
| --- | --- |
| 只检视 | 读取真实文件、给出意见；不声称测试已通过 |
| 检视与测试 | 检视之后运行真实 unittest；失败就停止，不自动改代码 |
| 修复与复检 | 先运行同一测试，只有失败才修改实现并复测；最多两次修复，仍失败则停止 |

生成的源码副本已带 Python 检查配置，需要本机已安装 python。完整上游基线当前有
168 项中的 6 项失败/错误，涉及原有文件名、Windows 路径及策略断言，因此全套检查可能失败。
失败是有效结果，不应改弱测试或只凭模型文字当作通过。最终验收使用隔离副本故障注入，
用户体验目录没有预先注入故障。

## 把另一插件接到流程里

安装并批准另一个提供“汇报”动作的插件，加入 Claw 的能力选择，然后编辑最后的汇报步骤：

1. 步骤类型选择插件动作，动作提供者选择另一个插件。
2. “接收前置步骤输出”选择 **本次执行结果（有效检视与测试证据）**。
3. “执行结果写入字段”填写该动作接收文本的字段，例如 `text`；其他必填参数照常填写。
4. 保存流程和组合，核对变化后重新应用。

这样前面的 Agent/测试由宿主执行，后面的插件会收到当前有效的结果 JSON。它可以按自己的
格式汇报，却不能把历史 PASS、跳过测试或自己声称的成功变成宿主的测试通过证据。
这就是跨插件组合；无需把所有步骤写进一个插件。新插件仍需声明可调用动作和输入格式，
不能把任意旧插件的全部内部逻辑自动拆成步骤。

## 升级和项目规则

升级包后，先重新批准代码，再用升级修复入口核对组件和配置。能兼容的输入会保留；
删除组件、新增必填项会显示待处理。需要修改动作引用时创建新的 Flow 副本，不偷偷替换
其他组合正在使用的流程。

项目完成规则是底线；Claw 附加规则只能添加或收紧检查。同来源按严格规则合并，
附加规则不会授予阶段推进权；项目 repair 与附加规则合并后会收紧为 check，不自动修复。
这三条 Autobiz 预设默认不推进 checkpoint。
