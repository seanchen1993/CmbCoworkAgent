# 非多模态开放能力补齐与第三阶段方案

当前基线：`15492cc9f`，开发分支 `codex/mods-v2`，应用版本保持 `2.0.0`。
对照固定官方 2.1.316 内嵌声明和本分支实际提供者，不将方法数量、可登记事件或旧测试记录等同于功能完成。

## 结论和范围

第二阶段的重要能力已经接通，但不能宣称除多模态以外全部等价开放。本轮补齐桌面端适用的非媒体通用接口及使用断点，然后进入第三阶段。平台不加入 AutoBiz 分支，不增加项目创建、配置、需求或执行页面，不构建打包、不触发 Actions。

1. 补远程 MCP 独立连接：沿用当前选择来源和配置摘要，支持 stdio、Streamable HTTP、SSE；认证只留在宿主，不接受插件提供的 URL、命令、凭据。受控 fetch 禁止跨源和重定向，不自动回退协议或重放工具调用。取消同时关闭该 owned 连接，物理回收未确认时保留 unknown，不将取消等待当作服务停止。
2. 补 `prompt.paint`：文字装饰按真实输入框 text/revision 核验和回执；每个 source 只能覆盖或清除自己的装饰。输入、IME、重载、撤权及切换清理。virtualText 不改变草稿、光标、撤销和提交，读取草稿仍需原有读取权限。
3. 补交互子会话：保持旧 `ui.view` 默认只读，显式 `mode:"interactive"` 才进入 owned 活跃 child 的原生输入面板。普通聊天保留同一 TabbedPanel 和父输入框实例；面板激活回执后，父输入框禁止编辑、提交及排队并解除 prompt broker，子输入框才获焦。父草稿及附件保留，界面标明发送目标和返回按钮；关闭、终态、撤权和导航后恢复父输入。由主进程持有的 intent/owner/source/父运行实例/工作目录校验发送，序号去重，复用真实 peer inbox，不新建 runner、不自动重放。完成/停止后转只读并保留未发草稿。
4. 补 Placed 滚动：仅定位当前 source 的有效 requestId，虚拟列表真实挂载并可见后回执；失效、压缩、越界拒绝，不伪造 Placed 滚动 Hook。
5. 补桌面 UI 原语缺口：Input 多行和 IME，Text 方向及真实中间截断，Box 有界位置/显示/边框淡化，Button 文字 children/variant/role 与有限 hover。动作只接已登记的本机动作。Pane 的 columns/backgroundColor 生效，bodyColumns 来自真实测量；不静默忽略参数，不开放任意 DOM/style，更不能遮盖原生授权控件。
6. 补环境变量写入：按 literal 静态声明、source 和会话隔离，支持设置及删除，实际进入本插件之后的 process.run/spawn 子进程；显式进程 env 优先。不得改 Electron 全局 process.env、污染其他插件或任务。危险注入/宿主安全控制/凭据名字拒绝，大小和数量有界；env.get 对允许读取的本插件变量反映写入。说明这是桌面隔离适配，不宣称改变全应用工具环境。
7. 补通知、身份及诊断契约：ui.notify 默认遵从终端通道语义，desktop 如无终端返回 no-surface；显式 `surface:"desktop"` 作为本应用扩展，通过真实 Electron show/failed 和用户设置回执，随撤权关闭。show 只确认系统接收展示，不证明用户看见。session.identity 普通来源返回 deny，不伪造组织、邮箱或服务器验证；只有宿主已有可信策略才能提供对应字段，当前无对应可信组织策略时明确受条件限制。telemetry.log/mark 经过真实 Hook、输入和目的地校验，以实际本地诊断和 Hook 消费验证，本地诊断扩展不冒充 Anthropic/企业上传；没有已配置目的地时明确说明不发送。
8. 同步作者基座：准确补齐 SDK 类型、目标化查询、事件/方法清单、兼容说明和少量可运行例子；新增类型不能导致创作上下文每轮全量灌入。固定 2.1.316 证据版本，旧兼容 profile 不直接改名冒充全面升级。

## 生命周期和明确的宿主边界

审查真实提供者，存在现成对应生产流程的事件接在该流程上。`plugin.register` 必须在模块准入之前运行并允许阻止新模块注册，不能用事后通知冒充。`session.attach/detach` 仅代表真实桌面 surface 绑定/解绑，不把切页当远程客户端上线。模型切换、权限、配置、任务和消息事件只由实际相应动作触发，保留原身份和权限。

终端专属 Raster/ui.blit、ToolProgress，组织托管身份和 Anthropic 内部遥测，没有相同宿主的 Remote Control/worktree/elicitation/team 生命周期，必须明确标记适用条件或没有等价生产者；不得实现永远成功的空函数、假事件或新的业务引擎凑齐数量。attribution.text 仅在存在实际引擎自产 Git 文本的入口才可开放。图片、音频、视频、媒体附件仍排除。最终说明必须逐项列出剩余边界，不能写“Claude 全部 API 完全等价”。

## 分工与评审

产品改动前由 core 和 UI 两个独立 agent 对本方案正式评审。两位均已通过，无方案级阻断；关于父输入切换和通知语义的意见已纳入上文，然后才开始产品改动。

- Core：远程 MCP 与协议/取消/认证隔离回归，随后接入确认有真实提供者的生命周期事件。
- UI：prompt.paint、交互子会话、Placed 滚动及真实浏览器回归。
- 主 agent：环境/通知/身份/诊断、UI 原语和 Pane、作者目录与最终说明；共享大文件仅精确补丁，事先通知改动块。
- 验收 agent：当前源码隔离测试入口、完整 Git 树基线性能比较和第三阶段验收；不得使用旧 out 证明新源码。

完成后以新 medium agent 分别回检实际执行边界和用户连续使用路径，有阻断问题继续修复。

## 第三阶段和性能

测试入口在唯一临时目录用真实当前源码生成测试 bundle，不生成生产 out/dist/build，不读取 .env，不复制用户密钥。main/preload/utility/23 个 nodeWorker 引用保留真实实现和文件布局；资源白名单和源/产物哈希固定，无旧 out 回退。先无模型 native smoke，再受控单轮，最后真实商业模型。

真实模型覆盖通用 Mod 从零创建、非 AutoBiz 三阶段项目创建和提示词/阶段调整、AutoBiz 模板派生及再次派生、真实产物 ZIP 导出再导入，以及原项目创建/配置/需求/执行到下一阶段和完成的衔接。仅使用最小文本/JSON 成果，不重跑整套业务。Git 和审批环境单列；受控模型、真实模型和未验证节点分别记载。128K 配置验证宿主输入预算，不能用模型输出上限压低代替。

性能基线固定 `15492cc9f`，使用完整 Git 树加载 main/shared 和相关 JSON，同一测试负载及依赖，不允许基线缺文件时偷用当前源码。ABBA/BAAB，记录 source/fixture/bundle/依赖哈希及进程身份；模型网络时间不计为平台开销。

先窄回归与 smoke，再正式 runtime/ingress、桌面流量和长稳测试。沿现有门槛：单插件 p95 ≤15ms；关闭 Mods 入口 p95 ≤基线105%；空闲 CPU 差≤0.5个百分点；桌面 TTFT p95 增量≤40ms、吞吐比≥0.95。正式长稳需要300秒 idle、2小时 soak、至少10000事件；renderer heap 首尾各10分钟窗口，增长≤max(10MiB,初始中位数10%)。短测不写成长稳通过。
