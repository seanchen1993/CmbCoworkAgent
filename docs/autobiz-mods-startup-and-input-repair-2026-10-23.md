# AutoBiz Mods 启动与用户输入续接修复说明

## 问题定位

本机故障会话的首条请求携带安装目录下的 `autobiz-requirement-discuss/SKILL.md` 路径；项目运行使用固定版本快照目录。两个目录的原生完整包摘要相同，但显式技能准入严格匹配绝对路径，因此在进入模型前报“显式选择的技能不存在或已禁用”。技能文件并未缺失。

另通过真实 QuickJS、原生问题登记表和工具调用复现：组件调用超过期限后，原生问题仍可能保留在等待状态。外层工具已结束，内部输入请求尚未结束，会影响随后的交互。取消必须传递到实际问题生命周期，不能仅取消等待它的 Promise。

知识适配另有跨电脑风险：旧包首次会话可能安装 npm 依赖，安装期限为 300 秒，单次采集和内网元数据查询可等待 30 秒，与平台原有 15 秒上下文期限不一致。未取消的排队、目录锁及进程清理还可能继续占用执行位。这是独立缺陷，不能据此替代具体错误定位。

## 修复边界

1. 平台在安装 UUID、名称、版本、完整包摘要与相对技能路径一致时，将显式技能定位到本轮快照，并同步修正模型输入。继续保留线程、工作区、禁用目录、撤权、源码变化和取消校验；不按同名技能回退。
2. 原生问题合并所属运行与实际调用的取消信号。过期调用不能遗留输入请求，迟到答案不得恢复已结束任务。组件执行期限仍保留，不通过延长超时掩盖问题。
   `$.ui.ask` 与模型的 `request_user_input` 共用原生问题登记表，同时区分组件操作和整轮任务的归属：仅组件操作取消时释放等待；整轮任务取消时不将任务恢复为执行中。任务已取消时不再创建问题或发布等待状态。
3. 上下文准备从排队前计算总期限，支持队列、目录锁和正常聊天请求取消，复用原生进程树清理。物理退出未确认时保留资源隔离，不以释放锁冒充清理成功。
4. AutoBiz 1.0.5 知识扩展随包提供离线解析依赖及许可证，不在会话中执行 npm 安装。采集共用 8 秒预算，单次最多 3 秒，元数据查询最多约 1.25 秒；保留原脚本的业务选择和明确的本地知识回退。必需知识未装载时明确阻断。

本次取消修复保留现有 Mods 两分钟总等待期限；尚未将人工填写时间从各层组件墙钟期限中扣除。超过期限会明确结束并清理原生问题，不再留下可接受迟到答案的旧请求。它不等同于无限期等待用户答复。

AutoBiz 阶段图、状态决策、原始 Hooks、业务技能、产物检查和写入器未因本次修复而替换。状态 Mod 对非自有工具继续原调用链；普通文字“继续”不等于状态提交，也不等于提交选项答案。

## 使用和恢复

- 应用源码修复与插件资源修复是两个交付。仅安装 1.0.5 插件不能修复旧应用中的显式路径准入与原生输入生命周期。
- 应用版本升为 1.5.13，按用户确认通过当前开发分支的 GitHub Actions 构建；产物是否可安装以该次工作流的最终结果为准。旧安装包不包含本次源码修复，不能仅以插件版本判断应用是否已更新。
- 插件更新应通过原安装入口确认，并重新核对受影响的源码及权限。已有项目固定版本不会因更新全局安装而自动迁移；保留旧项目状态，按原项目版本更新入口处理，或在独立目录创建新项目验证。
- 出现知识缺失时，先查看具体缺失的发布单元、本地目录和 Node/Python 环境。不要为了消除提示而移除必需校验。
- 问题卡仍有效时提交该卡的答案；运行已结束时不得继续提交旧卡。手工修改脚本后需重新核对当前项目版本与源码授权，不能假设旧请求已自动切换到新代码。
- 业务提交若为未知结果，仍使用原请求键只读对账，不重复推进状态。

### 会话中修改插件的行为

项目绑定的固定版本快照与全局安装目录是不同来源。只修改安装目录时，原项目可继续使用其原绑定版本，修改不会自动成为当前项目的运行代码；重新选择已修改安装版的显式技能仍需通过版本一致性检查。直接修改当前执行的 Mod 源码、声明资源或快照，会在执行边界触发来源检查，旧授权不能直接用于新内容。

已进入模型上下文的 Skill 文字也不会因磁盘编辑而自动刷新，后续读取则可能看到不同内容。因此当前不承诺任务执行中的无缝热替换。应先结束当前执行，保存新版本、重新核对来源与权限；项目按版本更新入口切换后再开始下一轮。对话历史保留与代码版本切换应分别处理，不能将整个会话加载失败视为正常源码保护。

### Windows 冷环境补充修复

首次 Actions 的 Linux 构建通过，Windows 新增专项中的技能快照案例报 `PROJECT_HOST_DIRECTORY_INVALID`。本机真实 Windows 路径复现确认：同步和回调版 `fs.realpath` 与原生 `fs/promises.realpath` 对同一非符号链接目录可返回不同的大小写，例如 `C:\AI` 与 `C:\ai`。既有同步快照接收前者，新增异步读取若按后一种结果逐字比较会误拒绝。该机制不只属于测试夹具差异。

异步安全读取改为使用回调版 `fs.realpath` 的异步封装，与同步提交检查对齐，继续逐字核对路径并保留目录、符号链接、父链、硬链接、文件身份与读前读后变更校验。不通过统一小写、关闭安全检查或删除失败用例绕过问题。打包专项同时加入异步安全文件读取回归；失败构建保留在 Actions 历史中，最终交付以修复后的准确提交构建为准。

## 技能生命周期向 Mods 开放

`classic.PreSkillUse`、`classic.PostSkillUse` 接入原生技能生命周期，共用原技能身份、使用记录和必需业务检查。它们是本应用扩展，不更改已固定的外部兼容协议统计。用法及边界见 [事件与 API](sparks/events-and-api.md)。

宿主授权版本更新为 `v92`。原授权不会自动获得新增接口；更新应用后使用相关 Mods 需要核对源码与能力并重新确认。已新增旧版摘要不能直接复用、重新确认后方可执行的回归。

`PreSkillUse` 发生在已解析技能激活前；`PostSkillUse` 在本轮已激活技能完成校验时发生，不代表每个脚本退出都立即发送一次。后置阻断请求原完成循环进行修订，明确禁止继续才停止任务。模块可调用 `next(event)` 保留原 Hooks；必需检查仍由宿主在可选模块链外保证，事件开放不等于所有旧脚本已经自动转换。

后置检查要求修订时保留该技能的待验记录，修订后重新校验产物。产物持续不合格会耗尽原修订预算并失败，修好后须实际复验通过；正常通过或明确停止仍保留一次消费语义。

覆盖范围为现有技能激活与标准完成链。独立协调器 worker 的历史完成链仅运行 Stop，尚未统一接入技能后置检查，不声明所有特殊 worker 均已覆盖。
