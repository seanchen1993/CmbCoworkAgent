# Mods v2 原生子任务终态与轮次说明

基线 `a8975f89`，开发分支 `codex/mods-v2`，宿主修订 `desktop-turn-presentation-v24`。

## 效果与来源

明确的提供商拒绝现在使原生共享子任务以错误结束，父代理收到可恢复的工具错误，
可以决定后续处理。子任务的 Mods 完成原因仍为 `refusal`，父任务不被误判为拒绝。
该行为独立于 Mods 开关；预编译或不透明代理仍不通过返回文案猜测提供商状态。

`turn.complete` 返回的附加文本现在跟随实际回答所在行，空回答则定位到同轮可见行。
说明不再全部堆积在输入框上方。宿主提供消息锚点，插件事件与返回契约没有新增可写
定位字段。渲染器重载、消息分页、过滤空行及后续轮次不会把历史说明挪到新回答下。

依据冻结 Claude Code 2.1.273 还原产物：`CUn` 在轮次完成后把不同于回答且非空的
文本追加为说明（格式化 chunk 第 133427–133440 行）；`mzn` 独立分发子完成，
不把子返回文本追加到主会话。本工程采用 Electron 虚拟消息列表实现同类展示。
本批仍保留原有会话内 64 条 / 1 MiB 上限，不声称已经完成 Claude 的持久转录存储。

## 代码检视

- 原生任务使用私有 AsyncLocalStorage 保存当次结果，嵌套、并发和已结束调用隔离。
  实际取消优先于拒绝和其它错误；关闭作用域后，迟到回调不能重新写入终态。
- 子图在明确拒绝后跳过工具节点，包括同一响应同时携带工具调用的异常协议情形。
  Mods 观察实际响应，再由原生任务包装器抛出错误，保留原有账本与错误展示链路。
- 锚点从实际模型响应或已发布部分流中取得，和插件可改写的完成文本分开传递。
  消息 ID 规范化后，只允许在已知轮次内匹配唯一提供商 ID；缺失历史或分页缺口
  不用于猜测说明位置。
- 每个聊天容器只有一个通知订阅，虚拟行渲染为纯组件。切换会话与异步请求更新
  保留失效检查，新增行高由现有虚拟列表测量。
