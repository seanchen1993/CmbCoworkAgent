# 插件敏感参数的安全保存

专用列表、文件和目录之后继续这一阶段。目标是让用户填写令牌等私密参数，保存后照常聊天，已批准的实际插件收到对应参数；不用自己找配置文件。设计尚未等于功能完成。

依据为[官方插件参数说明](https://code.claude.com/docs/en/plugins/manifest-reference#user-configuration)及固定的 Claude Code 2.1.288 声明和配置实现：敏感参数不进入普通设置列表，输入遮蔽，使用系统安全存储。不能把现有模型凭据当成插件参数，也不自动向组件提供其他插件的参数。

## 同一套参数与保存版本

继续使用当前项目、插件身份、代码摘要和递增保存版本。普通参数原样兼容；敏感值放在同一个 SQLite 参数记录的加密部分，与普通值和保存版本一次写入、读回确认。不能先写另一个密钥表再写版本，也不能在加密失败时写明文。

加密能力由主进程注入 Electron safeStorage，不给 SDK 或 renderer 暴露解密接口。Windows/macOS 使用系统支持的安全保存；Linux 必须有已知安全的系统后端，basic_text、unknown、无法确定或不可用时拒绝敏感写入，表单说明原因。普通参数继续可用。错误消息只写固定错误码，不夹带系统异常里的参数内容。

加密内容包含格式版本、项目与插件身份以及敏感值，解密时再次核对身份；复制另一个项目或插件的密文不得取得其值。记录整体有容量边界，加密输出也设边界。原 read 只返回普通值及不透明密文；主进程私有 presence/resolve 在安全后端中解封，仅给表单布尔事实及给已批准的实际插件 options 提供值；merge 只合并不透明密文。其他插件和表单不能取得值或密文。所有运行前批准、取消、参数版本和来源复核继续保留。

普通字段不能读取此前加密的同名值；敏感字段不能继承旧记录中同名明文。若旧数据里存在明文敏感字段，宿主在下一次明确保存时清除它，不向表单或新实例返回。作者在包中明确提供的默认值仍按原加载规则处理；其可见性本来由包源码决定，不冒称已藏在安全存储中。

## 表单与使用

表单区分“已保存”“使用作者默认值”“当前运行已配置”，不返回旧值、默认值或实际运行值。presence 必须解密、核对身份和实际字段后决定，不能仅看密文是否存在；损坏或系统不可用以“无法读取安全保存”明确显示且不阻断普通表单。填写时遮蔽；成功保存回执到达后清空输入，迟到回执不能清除新填写的草稿。多项敏感文本仍逐项保留换行、逗号与顺序，不用分隔符猜值。文件/目录敏感项可以手填遮蔽路径，不开启文件选择器或读取内容。

敏感入口使用主进程严格验证的显式 set/clear 操作：没有实际编辑不允许点保存；set 传实际类型值，false、0、[] 都是合法值；clear 不带 value，删除该字段已存值，按原 loader 重新采用作者默认值/optional unset。required 没有默认值时清除后仍可显示待配置，但新实例必须在加载 VM 前失败。普通 set 不解密而保留其它字段的原密文；敏感 set/clear 仅替换或删除指定字段，其它敏感字段的密文原样保留。加解密目前使用本地 Electron 的同步 API；最终同步 CAS 写前仍复核原窗口、取消、源码与保存版本，不重试旧值。

实现收口采用同一记录中的逐字段密文对象：每个密文固定绑定项目、插件、字段名及 type/multiple，其他字段的密文原样保留，无需为了改一项解密所有其他项。这仍是一次 SQLite 原子提交，不是逐字段独立事务。普通字段明确保存时删除同名旧密文，以免普通值日后改成敏感声明时误复用历史秘密；其它秘密无需解密。敏感 clear 只删除指定字段密文，系统可用时允许清除损坏字段恢复使用，不读取它的旧值。系统不可用继续明确拒绝敏感操作。敏感声明的同名旧明文不进入 options/视图，下一次明确保存原子移除。字段类型改变的旧密文以“参数类型已改变，请重新填写”显示，不按新类型猜值；修改参数标题、帮助或默认值不会丢失仍兼容的已保存值。

保存敏感项使用原生参数入口，严格校验实际 schema 与同一原窗口/项目/代码/版本，不走普通 config.set Hook，也不把输入发布给其他插件。普通列表与 file/directory 的既有行为保持。SDK config.list/set 不提供敏感行或解密操作。插件只在自己的实际 register options 中取得所需字段；用户明确批准的作者代码主动输出参数属于作者行为，宿主不能承诺任意恶意代码永远不输出其获授权的数据。

敏感值不得进入宿主生成的配置视图、保存回执、配置通知、审计/诊断或错误文本；核对这些真实路径。任何存储错误、系统解密失败、密文损坏、旧项目回执、schema 改变都拒绝旧操作，不假成功或自动尝试明文。

系统安全保存的隔离边界按 [Electron 官方说明](https://www.electronjs.org/docs/latest/api/safe-storage)表述：Windows 的 DPAPI 保护其他系统用户，不能承诺隔离同一个系统用户的其他进程；项目/插件隔离由宿主解封身份及批准边界提供，不宣称 Windows 有跨应用绝对隔离。

## 验收与后续

两位独立 agent 先审设计，再审实际实现。真实 SQLite 回归验证原子写入、重开、项目/插件隔离、密文复制/损坏、后端不可用、加密失败、CAS、类型/容量、schema 改变、明文污染和普通参数兼容。真实 Guest 验证 options 中正确取值、敏感行没有被列出、保存/自动应用/明确重载正确且其他插件不取到它。浏览器验证遮蔽、已配置说明、空草稿不覆盖、清除、广播早于回执和切会话。真实 Electron 验证系统 safeStorage、实际 IPC/表单与插件运行；保存记录和宿主输出只查固定测试值是否出现，不读取用户秘密。基准记录加解密与参数保存实际耗时。

完成并验证后继续专门适配启动过程的模型调用，然后核对会话结束、更多消息/输入及仍未对齐能力。目前未确认敏感参数存在框架限制；不得以工作量大为由停止整体目标。

## 实现评审修正

安装检查也会执行 register，因此有已保存敏感值时必须先取得当前代码的精确有效批准，再解封；撤权后又重新批准不能复用旧批准版本。用户明确批准代码属于单独授权入口，解封前后及写入批准前仍核对原项目、源码、启用状态和版本。普通未配置秘密的安装检查继续保留原用法。

下一次明确保存时，原子删除实际 schema 已不存在或已普通化字段的旧密文，保留仍有效敏感项；避免旧版64项填满后永久无法升级。损坏的整体 JSON 记录只返回固定错误码，严格拒绝覆盖，不把旧明文带进诊断。

真正丢弃敏感草稿时同步清除已编辑标记；明确填成空或[]仍是新编辑，不可被广播吞掉。成功的旧版本回执只清除对应未再编辑的输入，保留页面已接收的较新版本；新输入及新项目不接受旧回执。整个原生参数表单排除桌面选择，Range 任何中间部分跨越可见排除区域也整体拒绝，不能把视觉遮蔽的 textarea 文本交给模组。
