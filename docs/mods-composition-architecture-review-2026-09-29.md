# 可组合 Claw 实施前架构与兼容性评审

日期：2026-09-29。评审目录 `C:\ai\CmbCoworkAgent-mods-v2`，开发分支 `codex/mods-v2`。
评审者：独立架构 agent。仅评审并新增本文，未修改生产代码、未操作 UAT。

## 结论

**有条件通过**《mods-composition-gap-and-sidebar-plan-2026-09-29.md》的增量方向。
这不是实现验收通过。进入编码前须把下列契约纳入收敛方案；交付前需对应测试。

本轮合理目标是：两个独立插件的显式动作、不同角色模型、可保存组合、当前对话绑定、
真实执行与右侧可见证据闭环。不是一次完成所有核心服务替换，也不承诺任意旧插件均可拆分。

底层已有隔离 guest、`engine.create` 跨提供者调用、模型边界、授权与撤销、流程门禁、
原子持久化及线程租约；应复用，不能通过新的 renderer 执行器绕开这些链路。

## 阻断点与必须明确的契约

### 1. 对话绑定不能只改存储和 UI

`FunctionModsManager.clawSelection()` 当前缓存键仅为 workspace；已有有效配置是项目级。
新增对话选择后，解析必须按 workspace + 线程身份/绑定版本区分，运行实例保留所用绑定快照。
保存项目模板不影响已应用绑定；应用 A 对话不能调用项目级 invalidate 而中止 B 的运行。
撤权、关闭 Mods、插件代码改变仍可项目级撤销，快照不能绕过安全失效。

`claw-scope.ts` 已验证内部 Flow 子线程的可信父链、同项目与循环边界，但只返回 boolean。
新增绑定必须沿这条可信父链找到宿主绑定，并给子运行显式传入或冻结父运行的配置。
不能让内部子线程因没有自己的绑定而重新落到项目默认值；普通用户构造 metadata 不应获得继承权限。
线程删除、重建、切项目后，旧异步请求和旧 UI 必须不能应用到新线程实例。

保留兼容语义：无绑定/legacy null 表示旧行为；明确空组合表示不加载可选 Function Mods。
经典 Plugin 项目、远程、Harness 不应因为有了默认 UI 状态被强行转换成普通 Claw 会话。

### 2. 最小动作协议必须是真调用，而非名称映射

同意本轮采用**显式 manifest exports → 已注册 command**，而不是任意反射 noun 或把 Hooks 当动作。

建议必要字段：schemaVersion、稳定 actionId、显示名称、command、受限输入/输出 schema。
来源绑定至少含 pluginId + runtimeName + approvedDigest + actionId。不存在导出的插件只能整包启用。
导出元数据本身必须进入已审批的代码/清单摘要，变化需重新校验授权。
目录读取只解析清单，不启动任意插件代码；首次运行加载后再核对 command 注册的实际 owner。
命名冲突、action 指向别家 command、隐藏导出被伪造、摘要过期一律拒绝。

建议固定输入 envelope `{version, input, config, task, runId, stepId, executionId}`，序列化为 command args；
输出 `{text?, output?}`，output 只允许有界 JSON。固定协议避免将字符串插值变成执行代码。
若需要业务失败分支，须明确 `passed` 的有效性及缺省值；异常/取消/权限失败绝不能伪装业务失败继续。
结果经过已有内容保护与发布路径；受保护输出不能直接落入共享 UI/日志/下一模型上下文。

`manager.runCommand()` 当前仅投影为 text；不能直接复用它然后声称支持结构化输出。
应新增受控的动作方法，复用 digest、grantEpoch、workspaceEpoch、modId 及当前会话校验，
在内部 `session.run()` 上保留原始有界结果。不能把整个 manager/session 暴露到 renderer。
动作走既有 command middleware，记录实际注册 owner 与参与链；显示名不足以证明提供者实际执行。

### 3. 每节点授权与绑定必须独立

`FlowDefinition.plugin` 目前是流程关联授权，不能替代新增 action 节点自己的提供者授权。
启动前对每个启用节点和依赖进行解析，节点执行前后还需检查 provider grant、会话存活、
workspace/thread/lease/incarnation 以及 cancellation。授权撤销不能只在首次加载时验证。
现有 `engine-nouns.ts` 的 caller/provider 身份链和敏感宿主能力交集不得被新入口绕开。
外部插件不能选择自己的 authority、修改 next step、创建宿主任意工具调用或扩大模型访问权限。

输入可以来自常量、目标及明确前步输出；不支持 JS 表达式/任意路径访问。
须拒绝 forward reference、循环、危险属性名、不存在路径、超过深度/大小的输入输出。
仅已完成、有效、当前执行分支的结果可被引用；重试/失败分支的失效输出不能复用。
流程定义 schema 变更应有向后读取兼容，旧 v1 流程保持原有执行语义。

### 4. 角色模型引用不等于模型版本快照

`NativeFlowHost` 已在 prepare 捕获角色对象，但模型仅保存 ref，节点执行时仍重新查询配置。
因此不能把现有行为宣传为精确模型配置快照。
本轮可行做法是冻结非密钥的模型选择与配置 fingerprint，执行时发现配置变化就明确中止，
而非静默换配置。凭据留宿主，读取时仍验证当前有效性，不写入 profile、FlowRun、导出文件或日志。

优先级固定：节点明确模型 > Claw 角色绑定 > 该运行捕获的默认模型。
明确配置但不存在/无凭据时失败，不悄悄回退默认。允许的 Mod 覆盖模型范围与最终模型需记录。
用于普通聊天的主模型也必须落实到 runtime 创建入口，不能只让 Flow 子 Agent 使用 Claw 模型。
当用户在输入区切换模型时，应清楚说明这是对当前任务覆盖还是修改组合，避免两个设置互相覆盖。

### 5. 运行快照与安全变化分开处理

本轮快照至少包含：配置版本/摘要、所选源摘要、节点和参数、输入绑定、角色说明、模型 ref/fingerprint。
完成规则当前是项目级且 `prepareFlowScope()` 对配置变化 fail-closed；可以保留这个行为并明确说明。
不要为实现“快照不变”取消已有动态安全检查或假装已经冻结全部组织策略。
进程重启后 `FlowManager.runs()` 会将未完成状态标为 interrupted，这是真实且可接受的恢复约定。
首轮不必自动重放有副作用的动作；没有幂等证明不能把 interrupted 自动重试当无损续跑。

### 6. 配置隔离与同项目并行执行不是一回事

`FlowManager.start()` 现有代码禁止同一个 workspace 同时运行两条 Flow。
这是工作目录写入/完成检查的一致性保护，本轮应保留。
“两个对话可以选不同 Claw”可以做到，但不能据此宣传同目录双流程并行安全。
验收应验证配置不同且先后实际执行无串线；同项目并发启动明确拒绝。
如要验证运行并发隔离，可使用不同项目；共享目录并行需独立设计资源锁/工作树，不在本轮偷拆限制。

### 7. 右侧栏迁移不得改变运行生命周期

新增现有 RightModule 的 Claw 模块，复用应用右侧调整宽度、显示、会话路由。
运行控制器继续由稳定会话拥有，侧栏只是视图。关侧栏、换 tab、换文件不能取消任务或重复启动。
不能 ChatContainer 和 RightPanel 同时挂载两份同一插件 UI 导致两次 site lifecycle/轮询。
保留 AbovePrompt/PromptHint/ToolUse 的语义位置和精简审批提醒；长面板/证据/进度迁移右侧。
异步完成只更新原 thread，不能自动抢占用户切到的 Git/文件，也不能作用于当前新 thread。
输入区仅一个目标输入框，发送绑定明确版本；保存、应用、执行三个动作独立。

### 本轮架构检视最终结论

**通过本轮实现的架构与兼容性检视**，范围为当前开发工作区的可组合动作、模型绑定和对话隔离主链路。
上文的禁用模型引用问题已由主实施者过滤并补测试；再次复核还补上了“隐式默认模型指针”冻结。
只读/人工确认流程在没有任何默认模型配置时可以准备，但不能在同一次运行中悄悄切换默认模型目标。

最后一轮定向测试中，动作契约 12 项、NativeFlowHost 19 项通过；此前真实双提供者、
撤权、输出保护、导出摘要、实际示例联调以及原 manager 53 项回归均已通过。
没有用此结论替代主实施者正在进行的完整回归、Electron E2E 与性能检查。

边界保持明确：组件动作复用 command，不任意反射 Hooks；同一插件仍整体加载；
Skill/MCP 细粒度选择、任意核心循环/存储/沙箱替换不在本轮完成范围；
同项目流程仍互斥，重启中的流程标记中断而非自动重放；请求模型与最终路由模型必须区分。

模型配置冻结的精确范围：**Flow 的整个执行计划**在准备时冻结角色模型配置与隐式默认指针，
跨节点检查一致；普通聊天则对主模型请求和每次独立 `$.model.complete` 等调用分别检查允许模型、
配置与授权。普通聊天的一次模型调用结束后、后续独立调用开始前，用户主动更改模型配置，
后者可能捕获新配置；本轮没有为所有普通聊天嵌套模型调用建立统一的整 turn 模型配置快照。
这是已明确的范围限制，不将“每调用校验”表述为普通聊天全部嵌套调用的精确重放保证。

### 最终 E2E 发现的模型选择器回归复核

真实 Electron 在已选中对话等待确认时重新加载，暴露了持久化模型已被移除的历史场景。
组件栈指向 ScrollArea，但独立核查发现 ModelSwitcher 的 metadata 水合与缺失模型回退
会在异步持久化完成前互相覆盖。真实组件浏览器回归保留旧 metadata、不立即写回，
已形成修复前失败、修复后通过的对照。

第二代码评审通过局部修复：按线程、路由模式与水合模型标识消费一次 metadata 来源，
先标记来源再恢复；真实来源变化或切换线程仍可恢复，手动选择与有效回退不再被旧值覆盖。
不替换 ScrollArea 或主聊天滚动架构。完整 Electron 原场景仍由最终回归门禁确认。
