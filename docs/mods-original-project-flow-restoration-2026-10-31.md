# 新版插件接回存量项目模式（2026-10-31）

## 纠正范围

用户要求优化插件，而不是替换项目模式。实施前由 architecture_review、delivery_review 两位 agent 评审通过：保留项目容器、原创建/编辑表单、配置、特性（需求）列表和执行详情；新版插件适配这些入口。普通新建项目不再分流到独立 CreateLocalProject/LocalProjectRun 页面。

创作、派生、阶段提示词编辑、依赖分组、精确范围的一次汇总授权保留。旧独立运行记录保留在“历史独立运行（兼容查看）”，不擅自迁移或删除。创造者的独立试用工具不替代项目入口。

## 实现边界

- 原项目保存原元信息及插件绑定；每条特性持久保存自身插件身份、需求正文、执行绑定、工作目录。真实执行首次启动时创建，不从项目描述或特性标题猜需求。
- Host 仍是新版插件阶段、检查、审批、操作和产物的唯一事实来源。旧看板仅投影状态；旧托管执行器不能同时驱动新版特性。
- 原“托管运行当前特性”对话填写需求正文，执行过程中可停止。阶段审批后继续运行至下一真实门禁；成果拒绝重试先结算旧操作；未知状态须核对，不能自动重跑。
- 配置和授权可在首次运行前完成，不依赖运行已开始。批准针对实际安装身份、源码摘要和实际目录；运行期间、源码变化、账号变化或迟到响应不能扩大权限。相同目录和源码可复用已有授权，新隔离目录须明确授权。
- Git 需求复用既有工作树服务，以保留源码相对路径并隔离执行；源仓库有未提交修改会明确拒绝，避免漏带修改。非 Git 需求使用独立产物目录。不会自动合并工作树或推送。
- 旧插件发布单元行为不变。新版插件按公开参数 schema 配置；不能把旧发布单元元数据假装已注入 Host，也不映射 AutoBiz 专属字段。多仓库和业务策略由插件实现。
- 项目创建、首次启动和后续命令均重新校验插件身份；已绑定需求不因插件替换静默改版本，活动或未知执行不可直接删除。

## 用户操作

1. 原“插件”上传完整 ZIP，主项目卡显示一个使用入口，依赖收在“依赖组件”。
2. 点击“开始使用”，或从项目模式“新建项目”选择插件。使用原表单填写项目编号、名称、说明、系统编号/名称、插件工作目录。
3. 进入项目，在原特性列表创建需求，填写名称并选择代码仓库目录。
4. 在需求详情完成插件参数和一次汇总授权，然后点击原“托管运行当前特性”。在原对话框的“启动会话的初始用户消息”填写目标和验收要求。
5. 在同一需求页面查看阶段、产物和会话，按真实门禁确认或停止。修改插件另走创造者草稿→编译/试用→保存，新需求使用新版本，已开始需求保持固定版本。

## 验收口径

沿用用户确认的流程衔接验收，不重新实现整套业务。使用生产 React 页面和受控 IPC 的浏览器测试检查原表单、导航、滚动、延迟响应、开始/停止和审批续跑；另以生产 Host、SQLite、真实临时 Git 工作树检查持久绑定、隔离、审批及完成。浏览器夹具不等同于真实模型端到端；本轮不声称重新完成真实模型业务验收。

应用版本保持 2.0.0。本轮不构建安装包；旧安装包仅重新导入 ZIP 不会获得此修复。
