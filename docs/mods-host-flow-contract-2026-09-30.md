# 宿主独立流程：实施契约

开发分支 codex/mods-v2。本轮实现无需所属 Function 插件的完整流程链路；组件级拆分先明确边界，
不把旧插件整体加载伪称为细粒度选择。架构与质量两位独立评审已通过以下设计后开始实施。

## 数据与用户操作

- 旧 schemaVersion:1 的 plugin 必填、序列化顺序、摘要和授权语义保持原样，不静默迁移。
- 新 schemaVersion:2 显式 execution:{kind:"host"}，拒绝 plugin 及伪造 execution 权限字段。
  新建默认宿主流程；旧版本复制保持版本，原有 Autobiz 专属模板仍保留。
- catalog.hostAvailable 表达 Mods 开关状态；零插件不等于禁用。保存、应用和发送各自有独立校验。
- 新流程支持 Agent、Skill、MCP、真实已授权插件动作、人工确认及 unit-test/e2e 原生检查。
  code-review 检查、Autobiz 验证和阶段推进本轮保留旧 v1 入口；v2 导入早期明确拒绝。
  代码评审可使用 Agent 步骤，但其结论不能伪装为原生测试或阶段验收证据。

## 执行与授权

- Flow scope 固定真实会话、Claw 选择、配置及现有插件摘要，即使没有任何插件也可成立。
- 新 HostFlowAuthority 是宿主内存中的不可伪造对象，与 runtimeAuthority、运行租约、工作区、
  thread、run、定义摘要和取消信号绑定；不写入 mods_grants，不伪造 Function 包，不向 IPC 暴露。
- 宿主 MCP 与项目检查沿生产工具分发、最终参数审批、内容保护和审计账本执行。
  无 modId 不能成为跳过写操作审批的理由。绑定/来源变化、撤权、关闭 Mods、取消后拒绝晚到结果。
- 插件动作仍由自己的来源身份和真实授权校验。旧 v1 MCP 的 owner grant 路径保持不变。
- 每次原生检查记录真实执行回执；最终完成重新验证当前产物，仍执行已有应用强制规则。
  重启不自动重放未知副作用；历史在原有规则下标记中断。

## 后续组件契约约束

组件必须有作者声明的稳定 ID、入口、类型、输入输出、依赖和配置；身份包含提供者与版本摘要。
依赖须显式展示并获得授权，选择、加载、撤权、审计必须使用同一个快照。
旧插件无声明时保持整包行为，不按 Hook 名称随意裁剪初始化或共享状态。
宿主 Flow 身份不能冒充组件身份，也不能替组件取得工具或模型权限。

传统 Plugin/Harness 已提前核查：其项目 adapter、调度、产物权限和阶段证明与普通子线程不同。
本轮不解除其入口限制；未来通过显式 adapter 动作桥接设计接入，不能将项目元数据改成普通模式。

## 验收与回归

必须覆盖零插件真实 Skill/MCP/模型/检查/人工确认与聊天启动；旧 v1 摘要不变；未授权动作零调用；
取消、失效身份、最终参数改变、Mods 关闭、重启中断、双会话租约隔离；旧 Plugin/Harness 运行不变。
设计双审后实施，再交叉检视，跑专项单元、类型/构建、浏览器与真实 Electron 回归，记录全量历史失败。
不得将本文的计划写成已通过验收；交付报告另列实际证据和未完成项。
