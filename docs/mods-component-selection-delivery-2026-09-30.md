## 这次能做什么

之前只能决定一个插件是否参与组合。现在，已声明组件的插件可以只启用其中一部分：
例如选择 A 插件的“代码检视”，不选 A 的“自动改写”，再选择 B 插件的“汇报整理”，
配上默认模型、Skill、MCP 和流程。业务会话只加载选中的组件入口及显式选择的依赖。

这不是任意插件的自动拆分。旧插件未声明组件时仍整包运行；组件不是独立权限主体，
同包共享原有授权和 guest。旧 Plugin/Harness 的使用方式不变，Flow adapter 尚未接入。

## 具体操作

1. 在普通本地项目会话开启 Mods，导入并授权插件。先用仓库里的
   [组件示例说明与源码](../examples/mods-component-kit/README.md) 即可体验，
   也可直接上传已打包的 [示例 ZIP](../output/mods-component-kit.zip)。
2. 打开“我的 Claw”，添加 `component-review-kit`。有组件声明的来源会展开组件配置区域。
   未声明的旧插件仍显示整包能力，不虚构可拆分项。
3. 将范围从“全部组件”切到“指定组件”，只保留“代码检视”，显式加入“示例说明”依赖。
   不选“汇报整理”。依赖不全时页面提示并阻止保存，可点击“加入所需依赖”。
4. 按需配置“检视重点”，例如“检查空值、数组边界和重复提交”，选择已配置的默认模型。
   参数表单支持 false、0、空字符串；无效 JSON 或未完成数字草稿不能保存。
5. 保存并应用到当前对话。保存只改模板，不更新已经生效的组合；运行中不能强行应用。
6. 在聊天输入 `/component-review function first(xs) { return xs[0].name }`。
   这时 `/component-help` 可用，`/component-report` 未在业务实例注册。
7. 再加入“汇报整理”，保存并重新应用，然后尝试
   `/component-report 已修复空数组问题，但尚未执行项目测试`。
8. 需要固定顺序时，在 DIY Flow 中加入插件动作，再绑定到 Claw，从聊天“执行流程”发送。
   编辑器可发现全部已授权来源的动作；绑定和运行会核对动作所属组件是否实际选中。

示例调用当前默认模型，只分析输入文本，不自动读取仓库或运行测试。
需要真实仓库检视时，使用能读取文件的 Agent 步骤，并添加原生检查和人工确认。

## 底层实现与兼容

- Native manifest 显式 `claw.componentsVersion:1`，组件含稳定 ID、独立 entry、依赖、动作归属
  和可选配置 schema；禁止与隐藏的旧统一 entry 混用。作者须主动迁移，见示例 README。
- 各入口独立编译。解析真实路径，拒绝直接或经 helper 导入另一个组件入口。公共 helper 可共享
  源码，但每个 bundle 的模块实例不同；依赖按确定拓扑顺序 register，且只执行一次。
- 完整源码决定真实包授权摘要；选择和配置另算运行摘要。运行从同次捕获的 bundle 投影，
  不重新读可变源码，也不生成假插件或假 grant。旧包摘要算法保持原样。
- 代码、客户端模块、环境声明和动作从同一组件集合投影；动作准备及执行均检查真实归属。
  命令、Hook、工具、站点和 provider 来自实际加载结果，不能通过隐藏目录代替加载限制。
- 配置只传给对应组件；审计与 Flow 计划记录宿主固定的有效组件集合及选集摘要，不写配置原文，
  不把 guest 自报值当执行身份，也不假称某次调用精确属于集合中的某一个组件。
- 设置强制 check/repair 规则使用当前线程真实绑定。此类规则要求整包模式；改变规则只关闭
  未包含目标插件、使用部分组件或无法读取绑定的同工作区实例，包含尚未完成加载的实例。
  整包、旧式实例和其他工作区保留原有生命周期；普通应用选择只关闭当前空闲会话。
- 授权撤销、开关变化、来源更新与原运行租约检查继续有效。移除组件不会撤销已发生的副作用，
  重启不会自动重放未知操作。

首次授权和主动兼容检查仍在独立 guest 中加载全包并检查 register，不调用业务 Hook。
因此“未选组件不执行”限定应用组合后的业务会话；目录发现本身仍只编译不执行。
作者仍须遵守现有注册约束，例如多个组件处理 session.start 时显式传 `{}` matcher。

## 尚未完成

- 任意旧插件不会自动拆分；需要作者迁移显式入口、依赖和动作声明。
- 组件依赖仅限同包；跨包通过 Claw 显式组合，不自动拉取、批准或执行另一插件。
- 组件不是独立沙箱或独立授权包；不提供任意副作用的事务回滚与自动恢复。
- 传统 Plugin/Harness 的 Flow adapter、插件升级修复引导以及其余 Claude 兼容 API 仍待迭代。
- 本轮是本工程的组合扩展，没有重新核验最新 Claude，也不宣称其官方采用同一组件格式。
- 两项既有提示文案仍待优化：已经绑定流程但模板列表暂空时仍提示先保存；无原生检查的已完成
  流程仍使用通用完成规则文案。它们不改变真实执行证据；本示例完成不表示执行过项目测试。
