## 相比 beta 增加的能力

| 能力 | 使用方式与结果 |
| --- | --- |
| 独立任务 | Bot 右侧详情新增任务列表、搜索、分页和新建入口；中间仍使用 beta 聊天界面，左侧保持 Bot/群列表。Bot 根据用户意图自主选择直接执行或创建独立任务。 |
| 修改、完成和继续 | 在原任务会话追加修改；回复结束仅表示本次执行结束。用户点击完成或明确要求完成后关闭业务任务，继续处理沿用原任务和历史。执行、审批或未结算后台工作会阻止提前完成。 |
| 主对话与任务切换 | 主对话的交办回执提供任务跳转；任务可返回主对话。任务每轮结果自动回到所属 Bot 主对话，带原任务入口。草稿、待发送消息、未读和停止操作按会话区分。 |
| 与对话模式关联 | 新任务可“在对话模式打开”；普通本机会话也可关联 Bot 任务。两个入口使用同一 Thread、消息、目录、模型设置和执行调度；关联本身不触发模型调用。 |
| 解除与删除 | 解除关联保留原会话和历史。删除 Bot 时保护用户原有的外部关联会话；有关联或未完成清理的会话不能被普通删除入口绕过保护。 |
| 模拟 IM | 在 Bot 菜单打开“模拟 IM 接入”，创建个人或群绑定，模拟收发、交办、修改、完成、继续、离线恢复及撤销。渠道工作同样出现在右侧任务列表。 |
| 模型选择 | 默认配置继续来自用户本地模型设置；已有会话沿用自己的模型。显式选中的模型不可用时报告明确错误，防止悄悄换到其他模型。 |

任务不限定产物类型，可以完成问答、文案、文件或其他实际工作，不要求需求文档、PRD、格式化成果或成果版本记录。内部 `version` 字段仅用于并发控制，不是面向用户的成果版本。

## 数据与执行关系

| 对象 | 职责 |
| --- | --- |
| `BotDefinition` | Bot 身份、职责和默认配置。 |
| `BotWorkItem` | 持续业务任务，保存目标、状态、来源、受众和会话引用。 |
| `Thread` | 真实消息历史、工作目录、模型、模式与检查点。两个入口不复制会话。 |
| `BotTask` | 一次排队、执行、回复或后台续接；完成一次执行不会自动完成业务任务。 |

新建本机任务支持明确目录、已登记项目目录或所属 Bot 的默认目录，创建时解析为真实绝对路径并固定保存；关联既有普通会话则保留其原有目录。项目目录按 beta 的父工作区与项目文件夹共同解析，不能把父工作区当作项目本身。并发文件操作按真实工作目录或 Bot 的既有队列串行，浏览器范围和会话收件箱按任务隔离。当前一个活动任务关联一个本机 Thread。

会话引用区分 `local_thread`、`project_session` 和 `cloud_session`。后两种仅保留类型扩展口，当前不支持创建或关联，也不会伪装为已经可用。

本地 Host 持有任务关系和执行授权，renderer 元数据不能自行取得运行权限。关联/解除有持久化中间状态、会话实例校验、执行锁和重试保护；有审批、Goal、执行或未结算检查点的会话需要先处理完当前活动。关联期间由同一 Bot 调度，Goal/Mods 的独立控制需先解除关联，普通未关联会话保持 beta 原行为。

## 模拟渠道边界

模拟数据保存在本机，不依赖 Java 服务，也不连接真实 IM。个人绑定固定一个身份，群绑定限定成员；来源、受众和授权版本在创建后不能被消息或前端改写。重复消息返回原接收记录，撤销和离线状态影响接收、执行与送达，状态可追踪。

模拟外部会话仅开放文字与同受众任务工具，不继承桌面私人记忆、员工身份、文件、浏览器、MCP、技能、Hooks 或子代理能力。即使从桌面打开渠道任务，这些约束仍成立；外部文本中的 `/goal`、模式前缀和技能标记不会成为桌面控制命令。

运行时仅接受主进程提供的能力白名单。为避免携带旧需求模式依赖，将可复用的技能范围约束和私人上下文控制独立成通用模块；没有显式限制的 beta 普通会话保持完整工具能力。

真实网关接入后续在 `LF39_devclaw_im_gateway_0821` 推进。本分支没有修改该仓库或 beta 的生产 IM 协议实现。

## 与最新 beta 的关键合并处理

- `BotStore` 保留 beta 的内联问题结果读取接口，将任务上下文批量读取放入独立参数，避免两个接口错位。
- 保留 beta 群消息交付、群成员关联、内联问题、检查点恢复、精确续接与前台命令结算。原有群/私聊调度仍串行；独立任务可在预留执行额度内与主对话并行，同一 Thread 不能重复执行。
- 工作流通知继续使用 beta 的运行实例标识去重，同时限定到对应任务；旧通知不会重新打开已完成任务。
- 停止任务只取消该任务及其协作链实际拥有的后台命令，不影响其他任务、主对话或群。非法混用群/任务目标会在任何状态修改前被拒绝。
- 适配 beta 新的工具记录折叠规则：有效的任务交办/生命周期回执保留为可点击卡片，避免创建成功却无法从主对话进入任务。
- `im-clean-cut` 原测试把所有源码中的英文 `takeover` 一律视为旧设备接管，误伤 beta 的浏览器人工接管功能。仅将这一断言限定到 IM 源码，其他旧协议检查不变。

## 合入 beta 后的兼容复查（2026-10-22）

以已合入 beta 的 `90f720a97` 为复查起点，对照 beta 开发者截至 `c0a995254` 的群聊、问题交互、历史搜索、文件、记忆、浏览器和恢复改动。发现并补齐以下组合场景：

| 场景 | 原问题与修复 |
| --- | --- |
| 自动创建任务后的忙时补充、输入框答题 | Host 转达的任务来源是 `work`，beta 原交互分支只接受 `user`/`introduction`，因此首轮执行和转达修改没有完整接入。现在同一 Bot、任务和 Thread 的补充沿用原运行时的接续/取消当前模型轮次机制，输入框答题同步启用；主对话和其他任务不能串入。该能力不增加配置修改或记忆写入授权。 |
| 转达“继续处理”后的停止记录 | `work` 来源遗漏 beta 的停止/中断事实提示。现在只读原任务所属 Thread 的有限记录，保留原终态并排除其他任务、群聊和主对话，供模型核查已做操作。 |
| 自选目录或关联会话中的跨 Bot 协作 | 原先给协作 Bot 的发送方目录固定为主 Bot 默认目录。现在从 Host 记录解析发起任务的固定目录，关联会话额外校验绑定及会话身份，不改写发起会话的配置。下一层协作和返回文件仍使用实际协作 Bot 的目录。 |

## 已完成与后续范围

### 独立任务向主对话反馈（2026-10-22）

原问题：任务执行结束只更新右侧状态和未读，主对话没有收到结果，所以 Bot 停留在“已交办”。

设计：独立任务每轮执行结束后，把这一轮的结果或失败原因回传同一 Bot 的主对话。主对话显示可返回原任务的轻量入口，并由 Bot 简要反馈实际结果；文件继续在原任务交付。沿用 beta 消息与调度体系，不自动切换用户正在看的会话。“任务有新结果”不代表用户已经确认完成。

回传与执行终态在同一事务保存，沿用现有 outbox，按执行 ID 去重；主对话忙时排队，重启恢复未投递回执。合并进同一次执行的补充消息只反馈一次，内部回传不再次触发回传。结果整理只生成文字，不重新执行原任务。模拟渠道继续走原受众的交付链路，不把渠道内容转发到本机私聊；已解除关联的任务不再投递。

- [x] 执行结果的持久化回传、去重和重启恢复。
- [x] 主对话结果反馈及返回原任务入口。
- [x] 新建/关联会话、修改、失败、忙时排队和隔离 App 验收。

实现入口：`BotStore.settle` 在终态事务中记录回执，`flushReplies` 复用已有待投递队列；`work_result` 来源驱动 Runtime 的文字反馈和主对话的原任务链接。每条回执包含本轮最多 16000 字符的结果、执行状态、已验证文件名及产生结果的请求上下文，不扫描历史全文；排队投递沿用单批最多 16 条的上限。补充消息合并执行、静默内部回执、模拟渠道和已解除关联均有专门处理。

## Bot 浏览器操作复用（2026-10-23）

原问题：Bot 仅用角色与名称定位，同一页面出现多个同名按钮时无法继续。现复用应用已有 Playwright 包中的 MCP 快照、元素引用和动作处理器；Bot 工具仍使用原入口，优先传入观察结果中的 `ref`。同名控件有各自引用，iframe 内的引用同样可用。旧 `role/name` 调用继续兼容；目标不唯一时返回错误与带引用的新快照，不自动点击第一个目标。

`src/main/browser/automation/owned-page.ts` 只接受宿主提供的单个 Page，调用既有 MCP 点击、填写、按键、表单、选择、悬停、拖拽、等待和页面内求值处理器。没有新建全局 MCP BrowserContext 或复制 Playwright 源码；没有新增依赖、浏览器安装或打包流程。普通会话原有浏览器接入保持原样。

页面创建、弹出页归属、工作目录、上传下载、弹窗和人工接管继续由 `BotBrowserService` 管理：Bot 私聊、群成员和独立任务保持各自页面范围；文件沿用真实工作目录。引用带页面及控制权标识，导航、关闭和人工接管后失效。多步动作在每步前复查控制权；归还控制权只返回新观察，不重放等待中的输入。长快照提供 `nextCursor`，后续读取同一份快照，不因截断漏掉末尾控件。网站登录仍沿用 beta 的本机 Bot 共享配置，不是每个任务独立账号。
