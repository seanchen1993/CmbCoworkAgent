# 设计会话后台运行与恢复

设计任务由主进程 `DesignRunManager` 托管。返回列表、切换会话和卸载
`DesignView` 只解除订阅；显式停止、删除会话或退出应用才结束任务。
同一会话只允许一个活动任务，全局同时运行两个任务，其余排队。

## 数据与事件

`DesignSessionStore` 使用现有应用 SQLite 数据库中的独立表：

- `design_sessions`：会话快照、工作目录、活动任务、序号和已读位置。
- `design_messages`：具有稳定 ID 的用户消息、助手消息及执行过程。
- `design_runs`：任务身份、唯一请求 ID、原始输入和终态，供幂等启动及重试使用。
- `design_session_events`：按会话序号写入的批次事件日志。
- `design_session_tombstones`：删除标记，防止旧 localStorage 记录再次导入。

开始执行前提交用户消息与助手占位；流式事件按固定 100 ms 批次提交，
终态、授权和提问结果立即提交。快照、消息、事件游标与任务终态在同一事务中保存。
提交成功后才推送页面。完整 HTML 和产物元数据由主进程保存；DOM 解析、
资源内联和多方案预览由页面按快照派生，用户编辑过的方案单独保留。

每次推送携带完整快照和递增序号，因此新快照也能覆盖前面漏收的更新。
无订阅者时只广播列表元数据。重新进入时，主进程先建立订阅，再同步获取快照，
两步之间没有异步让出；客户端提前安装监听，并忽略迟到的旧序号回复。
打开请求也有独立版本，旧页面的异步回复不会关闭新的订阅。

## 流程与边界

提问、设计系统下的自动继续、普通 Agent 生成、截图生成、重试和授权均使用
同一管理器。任务启动时捕获工作目录与配置；活动任务期间不允许切换该会话的工作目录。
停止与删除会先提交已有进度，再使任务失效，迟到事件无法覆盖新结果或恢复已删除会话。
授权状态通过现有 approval broker 的注册和移除事件同步。

旧 `design_index_v1` / `design_session_v2_*` 历史首次进入时导入数据库，保留会话 ID。
导入幂等，原 localStorage 数据保留；有产物文件时从文件恢复完整 HTML。

正常退出应用时，同步保存最后一批进度并标为 `interrupted`；异常退出后，
下次启动将数据库中残留的活动任务标为 `interrupted`，保留已提交历史。
模型和工具不会因为页面重进而重新执行。进程终止后的自动续跑不属于此功能。

## 验证

运行 `npm run test:design-sessions`，包括 SQLite 文件重开、事务回滚、
后台消息、会话隔离、授权、重试、取消、中断和真实 React 页面切换测试。
浏览器测试使用确定性模型替身与真实主进程管理器，不调用在线模型。
使用本机 Chrome 时可设置 `CHROMIUM_EXECUTABLE_PATH`。

另运行 `npm run typecheck`、`npm run build`、`npm run test:design-html`。
