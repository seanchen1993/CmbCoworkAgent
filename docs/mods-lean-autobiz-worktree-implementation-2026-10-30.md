# Mods 插件精简与工作树变更查看实施说明

> 本文保留第一轮实现与桌面观测记录。评审后新增的需求基线、规则独立替换及执行契约，以
> [详细新版说明](./mods-lean-plugin-explained-2026-10-30.md) 和
> [修订方案](./mods-lean-architecture-revision-2026-10-30.md) 为准。
> 下文四阶段耗时和旧样例字节数是历史观测，不代表修订后五阶段的最终性能结论。

应用版本固定为 2.0.0。本次在 `codex/mods-v2` 开发，不制作安装包、不触发 GitHub Actions。新版 AutoBiz 作者源与原版本并存，不改写已有项目的状态和固定依赖。

## 设计目标与实现分工

目标是以更少的上下文和操作完成业务任务，并允许独立替换某项能力。精简不等于删除知识、产物检查或人工确认。

| 层次 | 本次实现 | 可复用范围 |
| --- | --- | --- |
| 平台 | Native Composition 支持 `contextArtifactIds`；明确初始阅读材料，同时保留全部输入用于校验与失效检测 | 任意 Host 项目插件 |
| 平台 | `native.git/inspection@1.0.0` 提供目录确认、变更列表、单文件差异及撤销读取 | 任意授权 Mod；不负责工作树创建、合并和清理 |
| 平台 | `devclaw.surface/v2` 的只读查询交互可在任务执行时使用，支持取消旧请求、关闭收尾和迟到结果隔离 | 任意符合查询限制的扩展视图 |
| 平台 | 冷会话可由用户显式准备扩展视图；纯界面组件也能进入创造者依赖目录 | 任意界面 Mod |
| 平台 | 作者类型声明补齐运行时已有的 Input、Select、Code；安装指引区分界面组件与项目动作 | 任意通过创造者制作或复用的界面 Mod |
| 平台 | 流式输出按计算时间让出事件循环，避免每个 token 都等待 Windows 定时器 | 原生对话执行链 |
| 平台 | 同一次技能执行复用已核对的插件包快照，逐次验证文件身份；动作执行和最终提交仍完整核对 | 任意 Host 项目插件 |
| 插件 | 评审后 AutoBiz 调整为需求基线、需求定义、方案设计、代码实现、交付准备五阶段 | AutoBiz 作者源 |
| 插件 | 知识选择、业务规则和交付证据分别由三个独立 Mod 提供 | 可通过公开契约替换，不在平台按插件名称分支 |
| 插件 | `worktree-changes` 消费原 workflow 观察和通用 Git 接口显示差异 | AutoBiz 及其他原生 workflow 项目 |

平台不认识 Definition、Solution 等业务字段，也不判断 AutoBiz 的需求是否完整。字段和业务规则属于插件；平台负责按声明执行、保留实际证据、检查依赖身份和提交状态。

## 用户和插件开发者实际得到什么

| 使用环节 | 原实现的主要负担 | 本次变化 |
| --- | --- | --- |
| 查看当前进度 | 通过技能和脚本读取、更新业务状态，模型需要理解推进约定 | Host 引擎直接保存阶段、输入指纹、检查和接受结果；查询进度不运行旧 board 状态脚本 |
| 开始一个阶段 | 多份历史产物与组织材料重复进入初始上下文 | 作者明确初始阅读材料，知识 Mod 按显式阶段标签选择；校验仍读取全部必要输入 |
| 完成需求和方案 | 用户在多个准备步骤之间反复切换 | 将相关工作归为需求定义与方案设计；输出中仍保留业务字段、追踪关系和设计锁 |
| 换知识选择或业务规则 | 修改大插件中的多处提示词、脚本和状态约定 | 修改对应 Mod 的绑定并重新编译；其余模块沿用公开契约，原项目保持固定版本 |
| 查看子工作树修改 | 只能从任务日志推断，或要求平台定制业务面板 | 独立界面 Mod 读取通用 workflow 观察与 Git 差异接口；不消耗模型上下文，也不接管原任务 |
| 验收代码与交付 | 容易把模型叙述或命令成功当成业务完成 | 读取实际测试统计、生产文件指纹、原生执行回执和人工接受记录，任一证据过期即阻止推进 |

Mods 的作用是承载可替换的知识选择、业务规则、执行证据和界面。平台仍提供公共的执行、隔离、读取、校验和状态提交接口。阶段数量和业务产物由插件声明，平台没有固定 AutoBiz 四阶段或其他业务名称。

当前独立替换单位为知识 Mod、规则 Mod、交付证据 Mod 和工作树界面 Mod。编译、测试执行与回执校验暂属于同一个交付证据 Mod，并共享固定身份；不能把内部函数拆分误称为任意独立执行器已经可以无条件互换。

## 新版 AutoBiz 如何使用

1. 在创造者模式的作者源码导入入口选择 `resources/native-compositions/autobiz-lean` 目录。其 `devclaw.source-set.json` 同时声明项目源码和三个依赖 Mod。
2. 按原入口核对依赖并准备项目模板，完成需要的本机配置与源码授权。依赖安装 ID 和摘要由系统编译时写入锁定文件，不从别人的电脑复制。
3. 保存插件后进入项目模式使用。普通项目入口应识别生成的 Host 插件；无需另行运行旧 board 状态脚本。
4. 从需求定义开始执行。方案、代码和交付结果沿用声明的人工接受要求；知识缺失、业务检查不通过、上游内容变化均不能直接跳过。
5. 若要查看工作树差异，在创造者中要求添加 `worktree-changes`。系统可发现其源码并通过 `dependency_prepare` 准备安装。启用 Mods 并完成源码授权后，点击“打开扩展视图”；选择当前 workflow 工作树，再加载变更并确认目录读取范围。
6. 没有 workflow 记录时可手动填写：目录输入后点击“选择目录”，基准输入后点击“设置起点”，再点击“加载 / 刷新变更”。仅填写输入框不会提交。读取为手动刷新；目录内容变化导致比较过期时重新加载。

应用版本固定为 `2.0.0`，仅凭版本号不能判断是否已包含这些接口，须使用带有 Surface v2 与 `native.git` 能力的构建。本次宿主协议修订为 v93，旧源码授权摘要需要按现有原生入口重新核准；不会把旧授权直接视为新运行时的授权。

## 减少上下文为什么不会削弱校验

`inputs` 定义阶段必须依赖的全部产物；`contextArtifactIds` 只选择初始让模型阅读哪些输入。它必须是 `inputs` 的子集，不能修改校验动作收到的全部产物引用、摘要或来源权限。省略此字段沿用原行为。

例如 Code 初始读取 Solution，验收仍检查 Definition 和 Solution 的真实内容与摘要。已批准的 Solution 之后如果 Definition 改动，原检查与批准不能继续充当有效证据。

知识只有在作者明确声明合法阶段标签后才按阶段筛选。未标注材料仍然保留；配置、来源、最近 AGENTS 边界和缺失诊断不能用模型推测替代。该选择不压缩已存在的聊天历史，也不表示总 token 已减少同样比例。

## 怎样替换其中一项能力

替换知识或校验 Mod 时，在作者源中修改其公开 provider/action 绑定，由创造者重新读取真实能力目录并编译。执行逻辑、结果格式和声明输入必须匹配；原有项目继续使用原固定包和依赖身份。不能把编辑共享 Mod 文件直接等同于所有项目已经安全更新。

四阶段是这份插件作者源的选择，不是平台固定流程。其他插件可声明自己的阶段和输入输出。插入或替换阶段后，需要同步调整真实产物契约、下游依赖及校验，并重新验收。

## 工作树差异接口的行为

- 可选择 workflow 记录的工作树及固定基准，也可手动输入任意获准仓库或 linked worktree 与明确提交引用。首次成功读取将引用冻结为 SHA；缺少基准时明确提示，不自行猜测。不要求目录由平台创建或登记。
- 目录引用绑定工作区、会话、运行实例和调用 Mod 源码身份；撤权、释放或身份变化后的旧结果不能继续返回。
- Mod 查询客体只读取文件和明确允许的原生查询接口，不能调用模型、执行进程、联网、写文件或持久状态，也不能控制任务。`native.git` 的宿主实现运行固定的只读 Git 子进程，插件不能借此提交任意命令。
- 原 `surface/v1` 保留原动作队列。只有经宿主校验的 `surface/v2` 查询视图走并行读取路径。
- 列表按真实 JSON 字节预算分页，大内容预览明确标记截断；不会把接口超限显示为没有变更。
- 分页限制响应大小，不免除完整扫描成本。当前单文件超过 16 MiB、累计扫描超过 128 MiB、路径超过 20,000 或变更超过 4,000 会明确拒绝为 `QUERY_TOO_LARGE`；不承诺任意规模仓库都能浏览。
- 受保护文件不读取正文、不显示路径；仍可查看其余获准内容，同时显示未检查文件与子模块数量。部分列表为空仅表示获准范围内没有变更。权限变化使旧比较失效，撤权、取消或目录越界仍整体拒绝。
- Git 检查禁止外部 diff、textconv 和过滤器执行；前后检查目录、HEAD、索引等元数据。这里提供经过元数据核验的观察，不承诺整个仓库的事务快照。
- 正文使用原始字节及宿主有限的文本 CRLF 处理；自定义过滤器或编码转换未执行时有提示，结果可能与仓库自行转换后的 Git 差异不同。重命名仅识别内容完全一致的配对，不做相似度猜测。
- 工作树删除后不提供历史代码归档。需要保留历史差异，应另行设计明确的归档能力。

## 验证范围与结果

本节只记录已取得证据的结果。源码检查、受控模型和实际远端模型运行分别表述。

- 新旧 AutoBiz 源码均已通过实际依赖安装、授权、编译、保存、开始使用和普通项目目录识别的集成验证；不是仅检查 JSON schema。
- 查询界面浏览器 22 项通过；真实 QuickJS → Pane → native 查询 5 项通过，覆盖取消、关闭、迟到结果、客体内悬挂回调及旧版本串行兼容。
- 查询生命周期、原生能力和完整 Mod 调用桥的定向回归 44 项通过；追加真实子进程回归 6 项通过，验证查询限制跨进程传递，以及取消、资源迭代和未决调用收尾。最终 Git 服务与 provider 32 项、desktop 权限竞态 10 项通过。实际界面 Mod 集成通过，含受保护文件部分读取、Unicode 字节边界和取消先于替换回调的竞态；这些测试集合有交集，不累计为互不重复总数。
- 实际 Electron 中，原生任务持续运行时可手动选择真实 Git 目录、查看差异、快速切换并关闭视图；原任务租约未被替换，迟到结果未重新打开视图，最终消息正常保存。目录确认使用自动化返回的精确根路径，模型使用本地受控 SSE，使用默认无沙箱模式与原对话权限；此项不代表人工点击审批、远端模型或所有沙箱模式验收。382 像素侧栏内无横向溢出。workflow 目录选择桥另由注入观察记录、真实 linked worktree 和 Git 的集成测试验证，不能将两项描述为同一场真实 workflow 界面验收。
- 最终部分读取版本的实际 Electron 两文件仓库含受保护文件和子模块：列表约 1.41 秒、首次差异约 1.91 秒、快速切换约 1.94 秒；界面只显示排除数量，不显示受保护名称。502 文件仓库列表约 4.14 秒、首次差异约 7.49 秒、快速切换约 6.57 秒；同仓库修复前列表约 8.13 秒且正文查询超时。保留原权限检查、前后核对及 10 秒期限，采用最多四路受限并发读取；没有增加结果缓存或放宽超时。上述为当前机器有限样本，不能作为所有仓库的性能承诺。
- 九组聊天性能浏览器回归通过。
- 实际 Electron/SQLite 的 2,000 条持久消息回归中，普通模式与受保护模式均通过原标准。六次拖动后可读时间分别为约 6–30 ms 和 43–158 ms；观察到的最长无可读正文时间分别为 0 ms 和约 389 ms，后者可能包含受保护占位，不等同于像素全白。测试使用确定性持久消息，不调用远端模型；不是固定机器五轮对照或长期稳定性验收。
- 固定资料样例中，编译技能、真实知识回调和必读契约的合计输入从 89,485 字节降至 25,211 字节，约减少 71.8%；材料 API 读取由 42 次降至 20 次。这不包含全部模型历史、工具报告和 workflow 子代理上下文。
- 原生 LangChain/SQLite 的受控 128 片段回放中，逐片段定时器等待由约 2 秒降到约 0.1 秒。网络服务首字延迟和真实模型思考耗时不属于该指标。
- 四阶段真实 Host 引擎已走到 `completed`，覆盖业务检查失败后修正、上游变更拦截、实际两模块编译与 Node 测试、Git/workflow 回执、跨线程原证据和原生结果接受接口。模型生成内容与用户确认决定由测试提供，业务检查和状态提交执行实际实现；此项不是人工从头点击完整流程的验收。
- 实际旧 Hook 执行器与保留的 Python 安全规则 9 项通过，覆盖正常文件、敏感内容拒绝、四种损坏输入、工具匹配及工作目录同名脚本不替换插件规则。工具事件由测试注入，不依赖模型碰巧调用。
- Host 操作内快照优化后，同样 193 次 Code 包检查累计耗时从约 31.72 秒降至 2.89 秒，Code 验收总时间从约 75.00 秒降至 48.38 秒。最终四阶段验收用时约 220 秒；仍有工作流和产物验证成本，不能描述为即时完成。新增 8 项快照失效边界回归通过，保留字节变化、目录替换、撤权和不同操作之间重新核对。

追加三条完整 Host 路线已通过：Node 正常执行、显式 Java/Maven 适配，以及 Node 测试实际失败后修复代码并继续。随后审查补充了 Java 编译参数、原回执顺序与每批编译／测试摘要绑定的限制，负例回归已通过，受影响的 Java Host 路线再次完整通过，用时约 274 秒。

繁忙时关闭视图的清理动作使用独立的四个有界名额，普通、查询及打开动作仍共用十六个名额；清理不会获得额外效果权限。占满、取消与实际资源回收回归 23 项通过。

创造者能力说明改为在首个 support 页面提供公共约束，后续能力页显式引用首页面，避免重复说明挤满单次响应。完整发现及边界回归 29 项通过。
