# Mods v2 整应用 CPU 与流式性能测量

在 Mods v2 工作树使用 Node 22：

```powershell
node tests/run-mods-desktop-soak.mjs --performance
```

命令先构建普通 Electron 应用，再冻结 `out`、运行资源和应用入口到独立输出目录。
运行清单记录 bundle 与测试驱动 SHA-256、Git HEAD、工作树差异和进程信息。
不使用测试专属宿主桥接，不修改共享依赖，不执行安装包构建。
正式性能运行期间不要并行构建、E2E 或重负载测试。

## 测量范围

- 通过公开 IPC 安装并授权八个真实 Function guest，打开四个 Client pane。
- 空闲 CPU：关闭 Mods、开启 Mods 且关闭 pane 各测五分钟；冷启动排除。
  汇总 Electron 主进程、renderer 和 utility 的累计 CPU 秒，以单核百分点计。
  缺少计数器、进程集合变化或计数器倒退使结果失去验收资格，不以零代替。
- 流式：五轮交替顺序，每轮关闭/开启各十次，另有排除的冷调用。
  同一个受控本地 SSE 服务经真实 Agent、模型客户端、IPC 和原完成循环返回固定内容。
  开启组运行八个透传 `turn.step` hook 和四个 pane。
  每次要求恰好一个物理请求与完全一致的内容，拒绝用重试或修复掩盖失败。
- TTFT 从生产 preload 发起调用到收到首段文本；不代表外部推理延迟或最终绘制。
  吞吐采用相同载荷的字符/秒，不编造模型 token 用量。

## 固定判定

正式资格要求两组各五分钟稳定进程 CPU 数据和各 50 次流式样本。
CPU 增量不得超过 0.5 个百分点，TTFT p95 增量不得超过 40 ms，吞吐不得低于关闭组的 95%。
正式运行缺证据或超预算以非零退出；原始结果仍保留。

`--smoke` 仅验证测试链路，无论数值如何都不具备正式资格。
两小时/一万事件稳定性使用同一入口但不加 `--performance`，是另一项独立检查。
输出目录创建 `STOP` 文件可请求停止，保留已采集数据。

该性能测试使用协议服务控制载荷，不是外部模型或 Autobiz 真实业务验收。
真实业务报告必须另行证明需求、产物、validator、修复复检和 checkpoint 推进。
