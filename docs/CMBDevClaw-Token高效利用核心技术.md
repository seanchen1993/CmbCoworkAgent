# CMBDevClaw Token高效利用核心技术

以下内容仅基于 Sean Chen 和 w876249494 在 CMBDevClaw UAT 分支的源码及提交记录整理，重复能力已经合并。

## 1. 模型上下文分级压缩与大结果外置

**技术亮点：** 构建“源头限流、历史驱逐、会话摘要”三级治理机制，并根据模型窗口动态计算触发阈值。大型搜索结果和执行日志自动外置到文件，消息历史只保留摘要与读取路径；近期任务状态继续留在上下文中，避免简单截断造成关键信息丢失。

**效果：** 解决历史工具结果在后续每轮请求中被反复传输和计费的问题，使大结果从“长期占用上下文”变为“一次生成、按需读取”，在保留任务连续性的同时显著降低长会话Token消耗。

## 2. LocalSandbox大规模代码按需读取

**技术亮点：** 为Grep、Glob、目录遍历和文件读取建立独立的数量与字符预算，并结合流式读取、精确分页、超长行续读、编码识别和二进制拦截控制输出规模。结果被截断时仍返回真实总数和准确续读位置，保证证据可以继续追踪。

**效果：** 大型仓库、构建日志和超长文件不会一次性占满模型上下文，Agent只读取当前判断需要的代码片段；需要更多证据时从指定位置继续读取，减少无关输出和重复分页产生的Token消耗。

## 3. CMBDevClaw Agent Team独立上下文交接

**技术亮点：** 主Agent与Worker分别运行在独立线程和Checkpoint中，Worker的代码搜索、工具调用和构建日志不会直接回灌主上下文。主Agent只接收受限长度的任务通知与结果摘要，完整执行结果独立落盘，需要时再按路径分段读取。

**效果：** 将子任务的大量执行过程隔离在Worker上下文中，使主Agent能够集中Token完成任务拆解、进度判断和结果整合；同一Worker还可以沿用已有上下文继续任务，减少重复传递工程背景。

## 4. Task MMD长任务状态压缩

**技术亮点：** 从工具调用中提取受限长度的参数和结果预览，增量编译为Mermaid任务图，并通过模型调用中间件临时注入请求。任务图集中记录已完成、执行中和待处理事项，长度受到统一约束，不作为完整历史消息持续累积。

**效果：** 长任务经过上下文摘要后，Agent仍能通过任务图恢复执行进度，无需重读全部Tool Call确认“做到哪里”，减少重复搜索、重复验证和任务状态重建产生的Token消耗。

## 5. Contract Delivery与Compose Delivery任务级上下文工程

**技术亮点：** 根据需求中的模块、类、接口和业务关键词对代码文件进行相关性排序，并通过Schema限制Agent输入规模。需求、方案、任务和验收报告以工程文件交接，后续阶段只读取当前任务及其依赖产物；需求变化时只更新受影响任务。

**效果：** 将模型输入从“整个仓库的信息副本”收敛为“当前任务需要的代码证据”，减少不同阶段重复传递完整需求、文件清单和历史结论；已有勘察与设计结果可以持续复用，避免变更后从头生成。

## 6. Ultra Workflow Token预算与断点复用

**技术亮点：** 为工作流建立独立Token预算，并基于Prompt、Schema、模型和输入生成内容哈希，通过Journal持久化每个Agent节点的结果。恢复执行时直接复用哈希一致的已完成节点，同时通过脚本预校验、结构化输出重试上限和重复错误停止机制控制无效调用。

**效果：** 长任务中断后不必从头调用模型，只有输入变化或尚未完成的节点重新执行；错误脚本在模型调用前被拦截，相同结构化错误不会无限重试，从调用次数和恢复过程两方面减少Token浪费。

## 7. 插件MCP按作用域装载与结果投影

**技术亮点：** 按插件激活范围控制MCP工具可见性，未激活工具保持延迟状态；工具执行后再依据必要字段、字符上限和数组数量对结果进行确定性投影。Deferred MCP重试统一收敛到传输层，避免不同包装层重复执行同一次调用。

**效果：** 模型只接收当前任务相关的工具定义和业务字段，避免完整工具清单与大对象反复进入上下文；大结果能够在保留关键字段的同时大幅压缩，重复失败调用也能更快收敛。

## 8. Memory与Dream跨会话知识压缩

**技术亮点：** 将项目事实、用户偏好和历史反馈拆分为事实级记忆，通过项目与全局命名空间隔离，并使用FTS3、BM25、中文匹配和RRF完成融合检索。Dream离线合并重复事实、更新有效知识并归档长期未使用内容，每次召回的数量和长度均受到限制。

**效果：** 新会话无需重新加载完整历史对话，只注入与当前任务相关的少量项目知识；项目规范、历史结论和排障经验可以跨会话复用，减少重复说明背景、扫描代码和试错产生的Token消耗。

## 9. Tool Call异常修复与无效重试止损

**技术亮点：** 对流式Tool Call原始参数执行严格JSON终审，截断或语法错误的调用不会真实执行，而是转换为配对的错误ToolMessage。系统能够区分传输截断与格式错误，并保留有界诊断摘要；历史中的悬空调用只在发送模型前清理，不重写Checkpoint。

**效果：** 避免坏参数被宽松解析为空对象或半截内容后执行，解决异常调用引发的接口400、错误写入和重复调用死循环；模型可以根据明确诊断修复参数，不必重新生成整个工具调用。
