# Design 首次生成提速

实施日期：2026-10-29；回退排查与修正：2026-10-30。

## DESIGN.md 会话统一为单方案

在现有会话 JSON 中持久化 `singleVariant`，不新增数据库表。选择 DESIGN.md 或从已有产物/会话的设计系统元数据恢复时开启；同一对话内保持开启，刷新、重新打开、取消选择、重试及后续修改都不能清除。新对话继续独立判断。首次创建、旧修改提示、续写和校验修复统一遵循此规则。

后台在预览、正式产物提交和局部补丁的现有校验路径检查 `variation-a/b/c` 容器，违规时返回现有修复流程或错误并保留上一份有效页面。HTML 解析识别实际元素，不把脚本中的示例字符串当成多方案。界面复用已有单页展示。历史多方案产物需要修改时转完整生成通道合并成单页，不直接删除历史文件。

## 问卷逐题显示

模型继续返回 `question-form` JSON。主进程在每个顶层问题对象完整闭合时发送 `question` 事件，不等待整个问卷结束。解析器识别字符串转义、嵌套选项/卡片、思考块和重复 ID；旧 JSON 数组及最终容错解析继续兼容。

RunManager 收到问题立即持久化、发布；界面在 `asking` 状态下允许填写已经出现的问题，生成完毕后才开放提交。后续问题和最终 `done` 按 ID 追加，不重新创建已经显示的问题或清空答案。刷新/重新打开继续读取持久化状态。新一轮问卷才清空旧问答，取消后的旧事件被丢弃。

问卷按用户要求生成约 10 个问题，通常 8–12 个，按重要性排序，覆盖与当前需求相关的目标、用户、流程、结构、数据、交互、异常状态等信息，避免重复提问或凑数。继续使用精简提示和逐题显示。已有设计规范时继续过滤视觉方向问题；一个必要问题仍等待回答，零问题时才允许原有自动继续逻辑。

## 首次生成上下文

有当前 HTML 或来源产物时保留原完整修改提示。全新产物使用独立的创建提示和短基础指令，通过 Runtime 的可选 `baseSystemPrompt` 替代通用研发指令；未传该选项的其他调用行为不变。

首次生成保留当前需求、设计系统、所选技能/资源、工具参数、Tweaks、渐进预览和完成约束，去掉旧产物迁移、修改保护和重复文件工具说明。React/Vue 的受控数据编辑契约只在选择框架模板时追加。文件工具、审批、Hooks、模型选择及最终验证继续复用原机制。

普通首次生成关闭 Shell、代码执行、自动技能和子任务入口；显式选择技能时保留技能所需能力，提供参考 URL 时保留 MCP。只读取当前需求缺失的必要依赖，不探索其他功能或历史 Design 草稿，不自行进行截图审计；宿主仍执行最终浏览器校验。使用已有 Runtime 选项，不改通用研发调用。

问卷与首次创建使用精简提示。实际请求仍包含需求、工具说明、设计系统及适用的模板/技能内容，不能用主体提示字符数代替整个请求的 tokens。

## 首次写入预算

新建产物第一次 `write_file` 目标为 3–5 KB，复杂布局参考约 8 KB，均为建议值。内容包含实际标题、导航、主布局、基础颜色/字体和带稳定区块 ID 的未完成区域。首写前不生成详细图表、数据、完整样式或交互脚本。

已移除 8,192 字节硬性拒写：完整、可预览的框架超过参考值仍一次写入，不要求模型反复缩减。主进程继续在文件写入前检查有效路径对应的首写结构，包含 Hook 改写后的内容。结构错误时明确告知文件未写入，应先修正 `write_file`，避免接着 `edit_file` 导致文件不存在。后续按有意义的区块批量填充，避免把单个文案、图标、CSS 分成多轮调用。

首写必须通过现有文档结构检查，预览仍仅发布完整闭合的版本；最终产物必须移除 pending/building 标记并通过原有浏览器校验。

## 验证与观测

新增问卷首题、问卷完成、Runtime 就绪和模型首个消息块的时间点，结合现有首写、预览可见和最终完成时间定位等待阶段。Runtime 和模型首块只记录本次运行的第一次，不被续写覆盖。首写同时记录实际 `firstWriteBytes`。`firstQuestionAt` 是主进程接收时间，真正框架可见仍使用预览 ACK。

覆盖逐字符/分块解析、嵌套/转义/重复问题、边生成边答、刷新恢复、取消后的旧事件、单个必要问题、大于 8 KB 的有效首写、结构错误不落盘和后续大区块写入；单方案测试覆盖取消选择、重新加载、元数据兼容和违规产物保留旧页。真实 React/Chrome 回归覆盖逐题显示到答案提交的完整路径，以及原有预览、修改、导入和模板流程。

本地运行 `ds_7717fcd7` 证明存在实际回退：Runtime 就绪约 0.39 秒、模型首块约 2.65 秒、首写约 381.90 秒、框架可见约 383.19 秒。8 KB 硬限制连续拒绝了 7 次首写（从 9,983 缩减到 8,455 字节仍失败），模型还进行了大量 Shell 探索和截图检查。因此不是单纯等待模型首响；上述修正针对已观察到的重复工作。

修正后的真实在线耗时尚未重新测量，不承诺固定加速倍数；重启加载新代码后，需要使用相同需求和模型对比首写/可见时间。

## 执行步数与草稿恢复

Design 不再把 LangGraph 步数写死为 200，而是使用全局 `getAgentGraphRecursionLimit()`（默认 2000，遵循设置）。一次工具调用会经过多个图节点，因此图步数不等于工具调用次数。

触顶时只检查本次运行有成功写入记录的当前草稿；完整性、预期区块及 pending/building 检查通过后，继续原有浏览器校验与正式提交。未完成、陈旧、结构不合法、取消或其他异常不会被当成成功，也不无限续跑。A/B 方案使用不同的区块前缀；重复 ID 错误明确列出问题 ID，续写会收到结构反馈。

本地构建只更新磁盘文件；运行中的 Electron 主进程需要重启才能加载这些处理。早期 200 步触顶记录来自旧流程，但上面的 382 秒回退记录已有新埋点，确认发生在优化后的实现。

## 后续运行与校验修复（2026-10-30）

运行 `ds_7b9dcc8a`（FR11）最终完成，耗时约 25 分 20 秒：Runtime 就绪 0.09 秒，模型首块 1.44 秒，首次框架写入 120.29 秒、可见 120.39 秒（10,836 字节，一次成功）。该对话没有选择 DESIGN.md，按现有规则生成 A/B 两套。与上次运行需求不同，不能把耗时差异当成相同任务的基准测试。

首轮约 14 分 35 秒才开始浏览器校验，之前有 57 次 edit_file；早期框架区块已显示后，仍进行了较多细节补写、读取和搜索。校验明确报出 `accent 未引用 CSS 变量 --accent-b`：参数绑定存在，但样式只声明变量而没有实际引用。首轮浏览器耗时 1.16 秒。

旧修复提示虽然包含上述错误，却同时附加原需求，要求通读失败页面并向新文件重新写入完整 HTML，继续套用首次渐进生成提示。修复又执行了 1 次 write_file、14 次 edit_file 和 11 次 grep，耗时约 10 分 43 秒。最终复检 1.01 秒。两次浏览器检查合计约 2.17 秒，主要等待发生在模型生成和修复流程。

修正后，首次失败事件即显示详细错误；传给模型的同一报告包括失败项、实际来源/行列、相关源码和已知规则对应的修复要求。CSS 绑定错误会给出参数、变量与现有样式；运行时探针记录错误事件自身的行列与堆栈，能唯一匹配时映射到原始源码，否则明确标注校验副本，不猜测行号。错误项全部保留，详细片段最多为前 8 项生成。

宿主先复制完整失败页面到独立修复草稿，再由专用的简短修复提示要求模型使用 edit_file 定点修改。无需重新发送原需求、读取整页、搭骨架或重写整页；如需上下文，只读取相关行。模型结束后仍由宿主复检，失败不能替换正式产物。修复时保留会话单方案约束，并关闭无关探索工具。

回归覆盖真实 Chrome 的未使用 CSS 变量失败、报告给出的实际代码与修复要求、局部修改后复检通过、业务按钮交互保留，以及运行时错误行列回映；单测覆盖旧日志兼容和所有错误项保留。修复后的在线模型耗时仍需下一次运行验证。

## 生成、校验与提交闭环

自动续写上限收紧为 3 轮，连续 2 轮没有区块完成、结构错误减少或整页完成则停止并保留草稿。普通文案/颜色修改带来的预览 revision 增长不再视作有效进展。续写复用短文件指令，只传未完成区块和结构错误，保留同一线程的既有需求；不重复注入旧长文件操作说明。这个上限约束额外续写，不代表首轮模型工具调用次数的硬限制。

现有隐藏浏览器增加数值 Tweaks 样式检查：按真实 CSS 声明替换变量后检查属性有效性，覆盖 shorthand、calc 和缺少 px 等单位的情况；合法的 line-height、opacity、比例和零值不强加单位。再检查最多 3 个已声明为 tab 的可见切换控件，捕获点击错误及 aria-selected 未更新；跳过表单提交和链接。检查只改变临时浏览器中的页面，不改变待提交源码。它属于通用技术与基础交互检查，不能代替 PRD 业务验收。

每次浏览器校验的 8 秒期限覆盖加载、等待和全部 JS 检查，取消或超时都销毁窗口。结构、脚本、样式或交互错误进入一次定点模型修复；只有加载/崩溃/超时等环境错误时，宿主用新窗口复查一次，仍失败则展示真实原因，不要求模型猜测修改代码。原始 Tweaks 声明在宿主归一化前也接受结构检查，避免非法绑定被归一化过程隐藏。

正式 HTML 与元数据先写同目录临时文件，再替换，HTML 最后作为提交点。普通写入或替换失败时恢复已替换的元数据、保留旧 HTML，并清理临时文件；恢复本身失败时明确报告。只有确认保存成功后才更新缓存、发送 done。图片生成及手动保存复用同一保存入口。
