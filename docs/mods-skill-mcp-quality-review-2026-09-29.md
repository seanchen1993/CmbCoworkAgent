# Skill / MCP 组合质量与交互评审

评审范围：`mods-skill-mcp-implementation-contract-2026-09-29.md`。分支 `codex/mods-v2`。

## 设计评审结论

通过。MCP 本轮选择粒度是服务提供者，技能选择粒度是已注册技能；目录读取不连接 MCP。运行使用宿主共享连接，因此只承诺宿主调用范围过滤，不承诺服务进程或网络连接隔离。Skill 选择也不等于操作系统文件沙箱。

必须落实的语义：

- 缺字段或 `all` 沿用当前已启用来源；`selected` 空数组明确不提供此类能力。“全选当前”仍是固定名单。
- 保存的是来源身份与摘要，不通过名称匹配替换。来源删除、禁用或更新后必须显示问题，不能静默扩大权限。
- 草稿、已保存模板、已应用副本和执行任务分离。初次打开编辑已应用配置，背景刷新保留未保存草稿。
- 目录读取失败显示错误并允许重试，不能把错误当成空目录或全部允许。
- UI 不是权限边界，宿主必须约束实际调用、显式技能激活与可信子任务继承；旧 Plugin/Harness 和 Mods 关闭路径不受新筛选影响。

## Renderer 实现与使用方式

“我的 Claw”新增“技能 Skill”和“外部工具 MCP 服务”两个独立区域。

1. 选择“沿用已启用来源”，继续使用技能/MCP 设置中的现有启用规则，新启用来源也会参与。
2. 或选择“仅使用所选”，搜索名称、来源说明后勾选。相同名称按宿主来源身份分别选择。点击“清空”意味着应用后不提供该类能力。
3. “全选当前”保存当前目录的名单，不会自动加入以后安装或启用的来源。单类上限 512 项。
4. 保存能力组合，再应用到当前对话。修改保存不会改变已经应用的副本，也不会自动开始任务。
5. 回到聊天正常发送任务；若绑定显式流程，选择“执行流程”再发送目标。右侧配置显示已应用的技能和 MCP 模式摘要。

来源失效时可取消勾选移除；摘要变化时先移除，再重新选择并核对新版本。读取失败时保留已保存名单并提供“重试来源目录”。界面不提供连接地址、请求头、环境变量或凭据编辑入口。

新目录 API 只在组合编辑页读取；聊天和侧栏摘要只使用绑定副本。来源名单不保证每次一定调用，实际调用仍取决于任务、模型和既有授权。

## 验证范围

浏览器受控 IPC 回归覆盖初次加载已应用组合、显式空选、两类独立选择、同名不同来源、搜索、全选快照、目录移除/版本变化、读取失败、恢复继承及背景刷新不覆盖草稿。另检查聊天/侧栏不读取来源目录。

实施自检结果：既有 Flow/组合 17 组加新增来源 2 组共 19 组浏览器检查通过；来源场景定向复跑通过。增加 600 项目录夹具，初始只渲染 100 项、逐批展开，搜索覆盖完整目录，超过 512 项不允许“一键全选”生成无效配置。来源匹配用 ID 索引，不在每个可见卡片内重复扫描全部目录。

Renderer TypeScript 与定向 ESLint 通过。受控浏览器加载生产 CSS 的 1366/800 截图在 `output/mods-source-browser/`；800 宽度无水平溢出。这些是组件与受控 IPC 截图，不能冒充真实 Electron 宿主执行证据。

这是 renderer 实现者的自检记录，不能代替独立代码检视、真实技能/MCP 调用验证和最终 Electron E2E。最终结果由集成验证报告补充。

## 宿主集成独立复核与修复

审查 shared 来源解析、Claw IPC、runtime 主任务/子任务接线和 context-sources 元数据投影，并运行对应行为测试。解析、IPC、持久化和元数据投影 32 项通过；MCP scoped/SDK/fallback/真实 HTTP code-exec 桥 4 项通过。

发现并阻断过一个真实问题：deepagents SkillsMiddleware 会优先复用 checkpoint.skillsMetadata，跳过已筛选 backend，因此改变绑定后旧的未选技能可能继续进入实际模型提示词。单独调用真实 middleware，得到 `backendReads=0`、`excludedInActualModelPrompt=true`，并非只凭源码猜测。原 context-sources 的精确文档过滤只能修复观察信息，不能修复模型输入。

按主代理授权新增 `claw-skills-middleware.ts`：受限组合忽略旧 checkpoint 目录，通过当前筛选 backend 重新发现；空目录也不得回退到请求旧 metadata；每次模型调用前重新检查所选来源。无 Claw 限制时返回原 middleware。runtime 主任务和显式子任务 factory 均已接入，其他子 runtime 获得父任务来源选择。

真实 LocalSandbox、真实技能文件与真实 deepagents middleware 的 5 项测试通过：包含修复前对照、旧目录与旧描述淘汰、空选、发现后禁用/改文件、旧模式保持。新增修复由本评审者实施，因此该修复的最终代码批准需要主代理或另一评审者确认，不能以本段自检冒充独立批准。

复核还指出来源校验的一致性问题：IPC 的来源比对原先仅检查 id/digest，Skill 执行时还核对 name。已要求集成负责人统一规则，避免伪造名称保存成功而运行失败。最终结论需结合该问题关闭和最新生产 Electron 的实际允许/拒绝结果，不能仅以 renderer 或单元测试宣称交付完成。

技能斜杠菜单本轮继续展示既有缓存目录；选择受当前组合限制的技能会由宿主拒绝。未添加按名字过滤，避免同名不同来源混淆。UI 来源选择与说明不构成菜单过滤已实现的声明。

## 最终结论

**本轮 Skill / MCP 来源组合范围内通过。** 集成负责人已统一 id/name/digest 校验；另一架构评审补充发现的“子代理声明未注册来源”风险，已通过 discovery sources 与宿主选中来源取交集修复。最新真实 middleware 7 项及共享解析 10 项独立 fresh 复跑全部通过；模型前校验改为 policy.assertAllCurrent，避免重复路径发现。

审阅最终 `output/mods-claw-sources-e2e/report.json`：6 组生产 Electron 验证通过，errors 为空，覆盖脱敏且不启动 MCP 的目录、实际 QuickJS MCP 调用选择、真实模型提示词与显式技能拒绝、空选、同会话切换技能后淘汰 checkpoint 旧目录、刷新恢复。另目视生产 Electron 技能选择截图，布局和来源状态符合契约。模型供应商使用受控测试服务，不能把结果外推为所有远端服务实现的验证。

全量测试另外发现 composer guard 的 7 项 fixture 失配：生产 placeholder 新增显式聊天/流程模式依赖，而 AST 切片测试未绑定 useState 解构值 flowIntent，全部在执行断言前抛 ReferenceError。这不是旧基线，也不是守卫行为失效。仅补真实状态 fixture，保留原 7 项断言；新增流程模式下三种守卫与切线程恢复聊天的检查，fresh 8/8 通过，定向 ESLint 通过，无生产变更。

该通过结论不覆盖全仓既有失败，也不宣称完整 Claude Mods 等价、操作系统技能隔离或 MCP 进程/连接隔离；全部验证与基线差异以集成负责人最终报告为准。
