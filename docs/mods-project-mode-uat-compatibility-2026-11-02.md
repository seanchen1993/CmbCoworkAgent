## 必须保留的边界

- 新版插件与旧版插件的执行声明不同，平台按插件声明执行，不能伪造不支持的发布单元、多分支模板或已完成结果。
- 一次项目授权覆盖该项目登记的特性目录和固定版本的主包、依赖。源码变化、撤权及目录替换必须重新核实；创建特性、重试或新增会话不会自动打开用户关闭的功能。
- 纯配置插件不需要代码运行授权，不应因此开启应用或目录开关。
- 文件、进程、网络的实际操作规则，以及插件声明的业务审批、成果确认继续有效。
- 本轮不增加 AutoBiz 专用判断，不修改用户原 ZIP、个人配置或原业务仓库。

后续默认以原创建、编辑、特性、普通会话和托管入口为兼容基线。插件运行方式不同，应由适配层和能力声明处理；不能据此新增另一套项目创建页，或改变“新增会话”的含义。尚未支持的能力须作为缺口记录，优先补通用插件适配，不让用户改用一套替代流程。

知识入口的兼容分类也已只读核对：旧兼容模块保留历史 AutoBiz 命名，但按 board 资源、运行方式和声明的 context 判断，不按插件名称白名单判断。普通非 AutoBiz 旧 board 仍走通用配置检查；Host 插件不能未声明 context 就隐式退回旧执行器。该处无需为新插件增加业务特例。
