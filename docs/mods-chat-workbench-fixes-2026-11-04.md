# 聊天工作台修复与挂载位置

开发分支：`codex/mods-v2`；应用版本保持 `2.0.0`。本轮不改变项目模式创建、配置或执行流程。

## 灵件应该放在哪里

| 需求 | 接口 | 行为 |
| --- | --- | --- |
| 当前聊天顶部的状态条、小工具 | `ui.render` / `ChatHeader` | 新增桌面挂载点，位于消息滚动区之外；内容过长时独立滚动 |
| 输入框旁的操作区 | `ui.render` / `AbovePrompt` | 保留原位置；有界高度、独立滚动，消息滚动不移动它 |
| 多字段调试工作台、长报告 | `Pane`，或 capability surface 的 `sidebar` / `page` | 复用现有面板、侧栏、页面能力；无需塞入消息或输入框 |
| 随某条消息滚动的卡片 | `Placed` | 保留消息位置，不固定在窗口上 |

固定顶部指当前聊天内容区域顶部，不覆盖窗口标题栏、导航或原生审批。
创造者的 `support.sites` 现在列出全部实际位置，查询 `ui.render` 可获得位置选择说明和示例：

```ts
on("ui.render", { component: "ChatHeader" }, ($, event) =>
  $.ui.resolve(event).Text({ children: "工作台状态" })
)
```

`bodyColumns`、`maxRows` 是宿主提供的可用尺寸。完整 DOM 表单不应再次按 `scroll.offset` 裁剪内容，否则会与浏览器滚动叠加。
已有灵件不会被自动改写；更新代码后，可在创造者模式要求把原 `AbovePrompt` 状态条移到 `ChatHeader`，再试用新版。

## 本轮修复

- **滚动时工作台消失**：滚动位置改变触发新的受保护读取，过去清空旧 DOM 导致高度塌缩和滚动复位。现在保留同尺寸下已核对的呈现，新读取完成前旧动作不可用；来源撤销仍立即移除旧呈现。
- **停止试用后历史消息红错或灰白**：停止先等前台请求结束，再取消界面请求；等待授权的渲染可能永不结束。现在明确停止时先取消旧 UI 读取，随后等待真实清理。渲染请求也有独立取消信号。更新预检不走此分支，其他已安装灵件的呈现保护仍执行。
- **任务进展侧栏**：统一侧栏模块路由和选中状态，去掉独有的宽度强钳，切换模块时清理旧全屏状态。收起不销毁灵件输入。
- **重启后创造者工具消失**：按会话、工作目录和会话实例保存用户明确选择的模式。普通模式、创造者模式和关闭状态分别恢复，不恢复试用授权或自动执行。
- **回答问题时报输入编辑器不可用**：问题弹窗内单行输入的 Enter 曾冒泡提交外层聊天表单。现在只提交问题答案，保留聊天草稿；输入法组合、未答完整的问题不会误提交。

旧版本没有保存模式偏好，因此无法从草稿或已应用效果可靠判断旧会话最后选择了哪种模式。升级后的旧会话可能需要明确选择一次；此后重启可恢复。

## 重启后工作区与停止按钮的补充修复

- 重开聊天恢复用户选择的创造者模式，但不自动弹出插件创作工作区或历史业务试用对话框。工作区入口仍保留；本次会话新产生的确认、失败或阶段调试请求仍可提示。
- 原生历史试用记录增加可选 `historical: true`。它只表示从持久化记录读取，不代表旧外部操作已经完成，不恢复旧 guest，也不改变正式安装和授权。
- 历史记录不再提供无实际作用的“停止此组件试用”，也不再引导用户反复刷新等待停止。可以点击“管理此会话灵件”，打开聊天右侧高级设置，查看并停用正式启用的灵件。
- 当前进程的真实试用仍提供停止；点击后显示“正在停止试用…”，禁止重复提交，但允许状态刷新。状态读取与写操作使用独立代际，迟到的旧读取不能覆盖停止结果。
- 静默恢复阶段调试建议与新事件并发时，读取次序与展示去重分别处理，避免恢复读取吞掉真正的新提示。

补充验证：历史 SQLite 重启、运行时管理器、创作服务与 IPC 共 109 项通过；界面说明和下一步投影 24 项通过。实际 React 浏览器用例覆盖首次静默恢复、手动打开、历史管理入口、新权限请求、停止过程中刷新、迟到读取、阶段调试并发提示，以及原有创作工作区和入口恢复流程。Node/Web 类型检查、生产构建通过；定向 ESLint 无错误（既有文件仍有格式警告）。截图位于 `output/creator-workspace-restore-browser/`，完整创作流程截图位于 `output/creator-workspace-browser/`。

本补丁尚未提交或推送；本地开发需重新启动以载入主进程改动，已下载的安装包需后续构建发布后才包含修复。

## 任务进展侧栏拉伸补验

用户再次报告后确认，上轮仅调用宽度 hook 的测试漏掉了实际鼠标命中区域。App 的任务进展拖动条被独立 div 包裹，没有继承完整侧栏高度；1050px 以下还存在任务进展专属的绝对定位和隐藏拖动条规则，与其他模块不一致。

本次把普通聊天右侧所有模块放进同一 `RightPanelDock`，共享外层布局、容器 ref、宽度和实际 ResizeHandle；移除任务进展专属窄屏浮层规则。灵件 portal 仍保留挂载，收起、切换模块不会清空其未保存输入。不改变项目模式流程。

回归改为实际鼠标操作：1300/1000/800px 窗口，在拖动条顶部、中部和底部拉伸；比较任务、工作区、预览、Git、浏览器的上、下、右边界；验证连续拖动、收起重开和切换后草稿保留。拖动的每一帧只更新 DOM 宽度，不重渲染父页面。截图位于 `output/mods-task-sidebar-shell/sidebar-{width}.png`。另有原 ResizeHandle 生命周期和任务进展浏览器用例通过。

## 防止灵件审批持续阻塞应用

原 `process.run` / `process.spawn` 和 `http.fetch` 的原生审批对话框可能被定时轮询连续触发。用户即使拒绝一次，插件下一轮仍会再请求，使应用无法操作。

平台现在使用普通页面中的“灵件请求”收件区，不创建原生模态框、不自动展开或抢焦点。用户可以继续聊天、切换会话、打开设置和停止灵件。每个灵件/会话最多保留一个待确认请求，其他并发请求直接返回 `MODS_APPROVAL_PENDING`，不积累弹窗；全局待处理数也有界。

“拒绝并暂停”会记住当前工作目录、会话、灵件的暂停状态，后续命令和网络申请返回 `MODS_APPROVAL_PAUSED`；主动“恢复申请”仅允许以后再次申请，不重放或自动批准已拒绝的操作。暂停状态属于当前应用进程，重启或退出账号后清除；即便重新出现请求，也只进入非模态收件区。试用版本使用稳定组件身份，重新生成版本不绕过暂停。

“允许本次命令/请求”仍只批准当前不可变请求。完整命令参数的只读核对文件继续使用旧校验流程；平台的权限、来源、工作目录、操作规则仍需通过。跨 IPC 的确认恢复原生调用上下文，并重新核对当前授权。取消、停止或撤权会移除失效请求，不能接受迟到的允许。暂停请求不会自动停用灵件的本地界面，也不会结束已经开始的命令。

验收覆盖真实 React 界面接原生审批队列：新请求不抢聊天焦点，待确认期间可切换/输入；单次允许；拒绝后的 100 次重复申请不产生新提示；恢复不重放；停止立即移除请求。另有实际试用授权、重建版本仍暂停、请求完整性及进程生命周期回归。未改写用户已安装的 `worktree-diff-board` 源码；该插件自身的数据解析、点击与刷新问题仍需单独修复。

## 同类审批问题主动复查

继续沿插件能够触发的主进程确认入口检查，发现以下遗漏并修复：

- Git 仓库绑定、插件请求取消工作流、插件请求继续/停止/核对项目仍使用原生模态确认。统一接入非模态请求区；同一来源重复或并发申请受队列约束，拒绝后暂停申请。Git 已绑定目录继续复用原授权，恢复申请不会自动绑定或执行。
- 通用插件工具、MCP 和子代理启动原来仍通过独立原生弹窗确认。现在显式携带原调用的工作目录、来源和实时校验函数，使用同一请求区。停止、撤权、替换运行绑定后，失效请求可清理；迟到的允许不能执行工具。原引擎和 DIY 流程自身的确认入口保留，存量项目创建、配置和执行流程不变。
- 请求区较早的状态查询失败可能覆盖较新的成功结果。添加请求顺序与界面生命周期检查；旧连接的查询/操作结果不能污染新连接，也不再留下错误的刷新提示。

检查过的导入、导出、选择目录、配置迁移、手动核查入口仍由用户主动点击触发，没有改成插件可以自行弹出的入口。`ui.ask` 继续复用原生用户输入工具的取消信号和运行归属，未改变提问交互。

验证结果：`npm run test:mods:approvals` 的 12 个测试文件、160 项测试通过；浏览器回归通过，覆盖焦点、切换/输入、100 次拒绝后的重试、恢复不重放、停止、乱序查询、连接替换后的迟到错误、空闲无轮询。Git 用真实临时仓库验证；工作流/项目控制只验证权限与衔接，没有运行整套业务实现或调用真实模型。

专项命令与浏览器用例已接入 npm 测试及 Windows 构建工作流，避免只依赖人工使用发现这些问题。Node/Web 类型检查通过，改动文件 ESLint 无错误；大型历史文件仍有格式警告。本轮未提交、推送、打包或触发 Actions，版本保持 2.0.0。安装包不包含尚未发布的本地修复。
