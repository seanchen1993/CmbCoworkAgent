# 项目能力包接入指南

第一次开发请先阅读[插件开发一步一步做](sparks/plugin-cookbook.md)。它包含可安装的最小插件、
阶段说明的复制模板、跨插件动作串联，以及保留原 Hooks 和阶段链的迁移验收表。
应用内入口为“自定义助手 → 官方说明 → 插件开发入门”，支持离线阅读。

项目能力包复用现有插件安装机制、项目模式、Skills、Hooks 和灵件。插件根目录中的可选 `devclaw.project.json` 为项目详情提供使用帮助和阶段规则。没有该声明的插件继续使用原界面。

## 接入步骤

1. 保留已有 `board_core/board_config.json`、Skills、Hooks 与状态写入接口。
2. 在插件根目录增加 `devclaw.project.json`，参考 `examples/project-capability-minimal/devclaw.project.json`。节点 ID 必须对应自己的工作流节点，动态节点仅在实际流程中存在时显示。
3. 使用项目模式绑定这个插件。打开需求详情，在项目能力面板阅读说明、定位产物问题、查看历史 Hook 事件，点击“准备下一步会话”。
4. 新入口只准备原技能指令，发送后才执行。阶段前后校验、人工审批和状态提交由原执行链负责。

当前版本不自动从 Python 推导规则。声明不执行命令、不解析文件链接、不渲染 HTML，也不提供审批权限。内嵌帮助作为纯文本显示，用户无需另外下载文档。灵件开关不控制强制验证。

## 声明结构

```json
{
  "apiVersion": "devclaw.project/v1",
  "name": "文档交付项目",
  "description": "使用原项目流程完成文档交付。",
  "help": [{ "title": "如何开始", "body": "选择需求，准备阶段会话并发送指令。" }],
  "stages": [{
    "nodeId": "docs.draft",
    "guidance": "根据需求起草文档。",
    "before": ["核对目标读者与输入资料。"],
    "after": ["原验证器检查章节完整性并保存证据。"]
  }]
}
```

字段采用严格校验，未知字段、重复节点、错误版本及超限内容会显示局部诊断，不影响原项目入口。文件上限为 64 KiB，具体字段和数组限额以 `src/shared/project-capability.ts` 为准。声明仅从已绑定插件根读取，不能从工作区覆盖；不执行声明代码、不写状态。

`before` 和 `after` 是给用户阅读的规则，不是执行结果。产物状态与历史 Hook 事件来自现有项目适配器，面板不会把“文件存在”或“历史成功”升级为当前有效验收。未声明的动态节点仍可通过原项目流程使用。

## 与灵件和阶段链协作

- 项目模式继续管理项目、需求、工作区、会话、托管运行和审批。
- 灵件可以提供可选的辅助检视、领域展示和输入准备；辅助模型意见不作为强制门禁的替代证据。
- 项目插件继续提供权威工作流、下一步动作、领域验证器和唯一状态更新入口。
- 运行中的普通会话、托管运行或待确认门禁应先在原入口处理；新增能力面板不会自动开启第二次执行。
- 插件开发者无需为这些说明和状态再创建平行看板。需要定制专业界面时继续使用灵件 SDK，不能从界面直接修改业务状态。

## Autobiz 参考

`examples/autobiz-fullstack-mods` 是覆盖标准、精简和动态阶段的参考声明。专用打包器固定核对 `504e327d2f9a4d9e30e9f541c4432accf8000ad5 / 1.0.87`，加入声明及灵件，保留原 Hooks、Skills、工作流和验证器字节。上游漂移须重新审核，不能自动覆盖版本标记。

完整包仍通过原 Autobiz 运行链推进阶段；旧版原生 Autobiz validator 的固定提交不因此改变。不得把示例的状态面板或单文件模型检视描述成完整业务验收。

## 验证接入

新增插件至少覆盖无声明兼容、声明解析失败、未知节点、缺失产物、历史失败、当前阶段变化、已有运行及人工审批场景。必须独立回归原阶段前后 Hooks 和实际验证器；仅通过声明解析不能证明业务链正确。

仓库的 `src/shared/project-capability-examples.test.ts` 使用生产解析器检查两份示例。`tests/project-capability-package.spec.mjs` 对隔离导出的完整 Autobiz 包核对来源和原文件摘要，不连接真实业务服务。
