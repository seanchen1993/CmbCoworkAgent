## 2. 发现的问题与修复

### P2：离屏完成回答时恢复了过期展开状态

触发条件：

1. 思考流使消息自动展开，缓存记录 `autoOpened=true`、`autoCollapsed=false`。
2. 用户上翻，当前消息离开虚拟列表的挂载范围。
3. 消息不可见期间，正文或工具调用出现，随后流结束。
4. 用户返回消息。首轮状态函数在 `isStreaming=false` 时直接返回缓存，长思考仍然展开。

这属于首轮状态缓存引入的边界回归。修复前新增回归验证明确失败：1 项状态单测，以及正文、工具调用两项真实组件浏览器场景，均得到展开状态 `true`，预期为 `false`。

修复位于 `reasoning-expansion-context.ts` 和 `MessageBubble.tsx`：

- 只有流式阶段才能触发首次自动展开。
- 正文或工具调用出现后，对“已经自动展开、尚未自动收起”的状态补齐一次收起；恢复时不再仅依赖当前是否流式。
- 使用初始化器在首次 DOM 提交前计算状态，避免回挂后先显示长内容再收起。
- 仅思考的完成消息保持展开；普通历史消息的手动展开保持原样；自动收起后用户再次展开，后续 token 和重挂载都不会重复收起。

产品变更仅涉及这个状态判断和调用参数，未扩大滚动算法、消息协议或持久化范围。

### P2：非 Windows E2E 的用户目录隔离不完整

首轮脚本设置了 Windows 配置路径，但未提供 POSIX `HOME`。脚本包含非 Windows 启动分支；相关服务直接调用 `os.homedir()` 时，可能落到实际用户目录。

整改只作用于测试子进程：设置隔离的 `HOME`、`USERPROFILE`、XDG 配置/缓存/数据目录。Electron 启动后读取实际 `homedir()`、`tmpdir()` 和 `app.getPath("userData")`，逐一断言位于本次测试 profile 内。当前 Windows E2E 实测通过；没有在 macOS/Linux 上实际运行，跨平台结论限于代码路径检视。

### P3：性能插桩失效可能产生“零重绘”的假通过

原测试依靠字符串替换注入气泡重绘计数。若目标声明改名，替换可能不命中，计数会一直为零。

已增加两道断言：插桩标记必须恰好匹配一次；页面首次挂载后计数必须大于零。满足这两个条件后才检查重复更新是否使历史气泡重绘。

### 测量覆盖增强

原测试读取了实际行高和 Virtuoso 的 `data-known-size`，但只断言 margin 与相邻间隙。现在浏览器测试和 Electron E2E 都检查两者误差不超过 1px，容纳像素取整，同时保留零外边距断言。

## 3. 功能与性能边界

| 边界 | 处理及保护 |
| --- | --- |
| 同阶段 token | 返回同一个状态对象，不反复设置状态或写入缓存；单测执行 10,000 次同阶段更新 |
| Context 传播 | Map 只随 `threadId` 重建，token 更新不通过 Context 使所有历史气泡重绘 |
| 内存上限 | 每个列表最多缓存 500 个状态，只保存键和三个布尔字段；容量单测覆盖 10,000 个消息 |
| 超出缓存容量 | 最旧选择允许被淘汰；没有为无限历史保存无限状态 |
| 手动开合 | 保留原有一次性自动开合规则，并保护自动收起后的手动重开 |
| 行高 | 行间距位于可测量 item 内部；Header/Footer 不被 item 选择器命中 |
| 长文本 | 沿用既有 Markdown 和 64 Ki 字符预览策略；没有新增全文解析路径 |
| 调用开销 | `MessageBubble` 直接传正文/工具阶段布尔值，移除原临时参数对象 |

新增浏览器场景在行 `detached` 后推进正文或工具阶段并完成，明确断言完成时该行仍未挂载；返回后检查自动收起，随后手动展开并再次滚出/返回，检查选择保留。

新增 Electron 场景通过真实输入框发出第二条请求，使用新的 IPC 通道注入思考、正文和 `done` 事件。使用真实滚轮解除底部跟随，等待“停止生成”按钮消失且消息仍未挂载，再通过“回到会话底部”返回。没有用降低断言强度来绕过失败。

测试开发中修正了两项适配细节：Playwright 主进程求值环境不支持动态导入，改用当前 Node 22 的 `process.getBuiltinModule("os")`；同一请求内改变 chunk ID 会被既有流适配器归并，因此新场景使用第二次真实请求。
