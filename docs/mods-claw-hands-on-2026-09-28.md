## 三个入口分别负责什么

| 入口 | 用途 | 触发方式 |
| --- | --- | --- |
| Function Mods | 上传代码包、开启项目、核对授权、设置完成规则 | 命令用 `/命令 参数`；Hook 按声明的事件触发 |
| 我的 Claw | 命名、保存并应用一组 Function Mods | 应用后，在本项目普通聊天中正常发任务 |
| DIY 流程 | 配置必须遵循的步骤、检查和人工确认 | 明确点击“启动流程任务”或“运行已保存版本” |

“我的 Claw”选的是谁参与工作，不是每次都强行调用所有插件。查询插件只响应查询命令；评审插件才提供评审行为。只选择查询插件，普通模型回答可能完全一样，这是正常的。

## 以 Autobiz 为例

1. 在开发目录启动 `npm run dev`，打开一个以实际业务工程为工作目录的普通本地会话。
2. 进入“自定义 → Function Mods”，上传完整 Autobiz Mods ZIP，或选择打包后的完整插件文件夹。`examples/autobiz-kanban-mods` 只是覆盖到上游插件的模块源码，不能直接作为完整包安装。本次实操包在 `output/claw-walkthrough-20260928/package/AutobizDevOps_Plugin_Kanban_Mods.zip`；自行打包方法见 `examples/autobiz-kanban-mods/README.md`。业务工程目录与插件安装包目录是两个概念。
3. 开启应用及项目 Mods。核对插件能力与版本后授权。安装或勾选不会自动授权。
4. 进入“自定义 → 我的 Claw”。名称填“Autobiz 研发助手”，勾选已授权的 Autobiz 能力；需要查询信息时可同时加入查询组件。
5. 点击“保存能力组合”，再点击左侧对应组合的“应用组合”。保存只保存草稿，不悄悄更改当前行为。
6. 回到“上传、授权与完成规则”。先使用“仅报告 + 本次代码改动 + 代码评审”体验；需要严格交付时再选择“自动修复并复检”、单元测试等。真实测试需要项目具有可用脚本；Autobiz 验收还需要页面环境检查通过和实际 Feature 资料。
7. 点击“回到聊天使用”，正常输入：“实现订单导出，并说明验收结果”。模型仍在原会话完成任务，选中的 Hook 参与执行；完成前按配置检查。在完成证据/检查记录里核对真实调用，不以回答文案是否变化判断。
8. 普通追问仍发送在消息框里，不会因此启动一条新固定流程。插件提供的查询命令继续用 `/命令 参数`。

完成规则是项目共享设置，不是组合的版本快照。启用“阻止完成/自动修复”前，先把该能力加入当前组合；已有这类规则的能力不能直接从组合排除。先检查并调整规则，再修改组合。

## 确实需要“分析 → 实现 → 测试 → 人工确认”时

1. 到“DIY 流程”编辑并保存步骤。保存版本不等于已经运行。
2. 点击“到聊天启动此流程”，或在聊天的“按固定步骤办事 · 选择流程”中选择已保存版本。
3. 在单独的“流程本次任务”框输入这次需求，点击“启动流程任务”。这次需求只属于本次运行，不修改模板目标。
4. 就在聊天页面查看进度、同意、拒绝或取消。运行期间普通消息进入原有待发送队列。
5. 完成后，展开结果并点击“带运行摘要追问”。真实运行 ID、版本、任务、状态和近期步骤摘要会放到聊天草稿；可编辑后发送。摘要有长度与条数限制，完整证据仍在运行记录中。

“运行已保存版本”仍是立刻执行模板中保存的目标，适合固定检查；“启动流程任务”则使用本次输入的新目标。普通消息的发送按钮始终不会隐式启动工作流。

## 作用范围与失效处理

- 组合对本项目的普通聊天及其内部子任务生效；同项目其他普通会话也使用它。不是每个会话单独保存一套配置。
- 传统 Plugin、Harness、远程及后台任务的能力选择保持原机制。项目有任务或审批正在执行时，应用组合会提示先结束或取消，避免切换中影响任务。
- “恢复原配置”重新沿用原有已授权 Function Mods。保存并应用空组合则不加载这些 Function Mods；组织保护和传统 Plugin 不会被关闭。
- 插件更新、撤权、卸载后，旧组合会报告失效。重新核对授权，再编辑组合选择新版本并应用，不会自动替换成同名插件。
- 任意上传的 Hook、命令或面板不会自动成为可拖拽流程节点。当前节点仍是宿主提供的 Agent、检查、确认、Autobiz 阶段推进。
- 这是本工程的产品交互，不宣称 Claude 官方具有同样的可视化页面或所有 API 都已完全兼容。
