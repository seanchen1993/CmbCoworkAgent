## 当前阶段：项目规范与附加文本

设计依据：[官方事件说明](https://code.claude.com/docs/en/plugins/mods/events)、[官方接口说明](https://code.claude.com/docs/en/plugins/mods/api)，以及本地 Claude Code 2.1.288 类型声明。后续若发布版本改变，重新核对契约。

- `prompt.context`：提供实际加载且预算内的 AGENTS.md 文件、文件层级和内容。DevClaw 的 AGENTS.md 对应 Claude 的 `claudeMd` 名称，迁移来的处理函数无需改事件名。已有 Harness 提供的规范在没有可信文件内容时只提供文本，不伪造文件清单。
- 文件清单与文本在每一个处理环节同步；改了文本后，不再声称旧清单仍是它的来源。省略清单沿用下游清单。调整清单直接使用提供的文本，不根据路径读取磁盘。
- 只操作已经明确标记的规范来源，不根据总提示词中的字符串猜测边界。中间件整体改写后无法确认来源时省略 `instructionFiles`（来源未知），保留原提示词；不能用空数组冒充已知没有文件，也不能根据相似文字恢复来源。
- 为兼容现有项目和 Harness，规范仍放在 DevClaw 原来的系统提示位置；不会擅自改成用户消息。事件名称、文件控制和组合行为兼容，消息位置的差异单独说明。
- `prompt.attachment` 只处理宿主明确标记的附加文本；实际来源、类型、子代理身份和细节固定。图片或音频字节不作为文本暴露；模组不能借修改标签改变权限。
- 未安装处理函数或处理结果不变时保留原消息、元数据、工具结果关联和原始字节。每次实际模型请求只处理它携带的附件，不修改持久化历史。
- 经过原有内容保护、模型预算、取消和撤权检查；不能因新事件绕开它们。

## 紧接的下一阶段：复用处理结果与主动刷新

首阶段是每次模型请求重新处理，不能将其宣称为官方缓存已对齐。下一阶段补上安全复用及作者主动刷新：

- 由宿主为实际加载的规范和实际生成的提醒建立不可伪造的来源对象；根据真实来源对象及当前运行身份复用结果，不按相同文字猜测。
- 同一运行中的重试可复用已验证结果；新的运行、重新加载、恢复后的新消息对象不会借用上一运行的缓存。DevClaw 每次任务建立运行实例，与官方长期 CLI 会话有区别，跨任务是否复用必须单独说明。
- 缓存只保存冻结结果、不可变输入快照和来源标识，不保存旧处理函数、权限作用域或取消信号。首先只复用已完成结果，不共享携带首个调用权限的在途 Promise；同时调用各自完成各自的权限检查。
- `ui.invalidate("prompt.context")` 与 `ui.invalidate("prompt.attachment")` 清除对应复用结果；清除时仍走原操作权限与模组链。处理期间发生刷新时，旧结果不能写回缓存。
- 删除结果也能复用；内容保护仍在命中后执行，最终预算仍计算实际发送内容。取消、关闭、撤权后不得填充缓存。
- 刷新前已经开始的请求允许将结果用于本次，但不能回填或供后续请求使用；不自动重跑可能有副作用的处理函数。旧请求的清理不能删掉新一代缓存。
- 补 `$.prompt.context(input)`、`$.prompt.attachment(input)` 处理作者显式提供的内容；它们只计算和返回结果，不会自动发送任务、读取文件或伪造宿主实际附件。仍经过能力审批、处理链、内容保护及固定事实检查；不将这类显式试算加入真实来源缓存。
- 宿主调用绑定来源，SDK 试算没有来源绑定；相同文字也不会取得宿主缓存或继承文件权限。SDK 从当前处理链调用时跳过自己当前处理函数，保留同一插件的其他处理函数。
- 私有来源只能由实际宿主生成处注册，并通过可信来源复制保留；破坏性改写后丢弃来源标识，不能根据相同名字或文字重新认领。缓存命中与写入都复核当前宿主会话、许可、运行和取消状态。
- 仍明确提供 `MODS_PROMPT_COMPOSE_PREPARING`：准备规范和提醒时，不能借上一步已经过时的模型提示快照。独立分析可以使用自己的真实新快照。

验收：同一来源实际模型重试只处理一次；主动刷新重新处理；不同主/子助手和不同来源不串结果；删除结果、迟到刷新、取消/撤权、SDK试算、内容保护与最终预算覆盖。新增迭代不改变旧 Plugin、项目模式或 Harness 的原有开关与权限。

## 后续阶段设计：输入编辑与下一步建议

规范与附加说明首阶段、复用/刷新第二阶段已完成；第二阶段验收账本见 `mods-prompt-cache-stage-2026-10-04.md`。当前继续输入编辑与建议，方案已取得两个独立评审通过。

本阶段把规则放进实际输入框和建议入口。用户仍然使用原输入框；模组可以调整输入、阻止特定编辑，并在任务结束后建议下一步。建议需要用户接受，只填入输入框，不自动发送。

- 编辑保留官方的“编辑前文本、原光标、替换起止、插入文本”结构；来源固定为真实输入框。粘贴、输入法和合并的一串输入不伪造单个按键。直接回答原文本能阻止编辑，调用下游则应用改后的插入内容或最终文字。
- 本机输入先显示，模组异步结果只有在输入框所有者、版本、文本、选区、可编辑状态仍匹配时才应用。新输入取消旧处理；过期结果不能覆盖新字。输入法组合期间不处理半成品，结束后一次处理。
- 始终保留最后已通过规则的文本与光标作为基线；取消旧处理或合并输入时，新事件包含从该基线到当前显示内容的全部未处理变化。未经确认的字不能借后续输入变成已通过的旧文本。发送前验证整个未处理变化，补“被拒绝的字紧接新字”、粘贴紧接键入、输入法后立即发送的反例。
- 发送前完成当前输入规则，不能抢先发送尚未经过规则的旧字。无规则或 Mods 关闭时，沿用原输入，不创建运行身份或增加往返。
- 发送等待后重新检查当前输入版本；等待期间又编辑过就处理新的累计变化，不能发送等待前捕获的旧字。建议接受、程序填入、光标移动和输入法结束各自明确改变已验证基线或待处理变化的方式，不能静默跳过未验证内容；实际发送后的清空也只处理已提交的版本。
- 沿用现有输入框私有所有者与回执，不把所有者、版本或审批标识放进模组可改的事件。编辑准备使用独立、短期、只读的真实宿主身份，不替换正在执行的主助手，不因键盘输入授予写文件或工具执行权限。
- `$.prompt.suggest` 使用实际插件名称作为固定来源，经处理链后交给真实输入框。只有空白、可编辑、当前任务空闲的输入框可以显示；切会话、开启弹窗、开始输入或开始运行都需重新检查，过期建议不接受。
- 接受建议仍经过实际编辑规则；同时保留原快捷键、技能选择、附件、队列、Goal、项目模式和 Flow 的处理行为。先覆盖文字与光标；文字装饰必须按实际可用的桌面渲染支持并明确范围，不能用无效果字段冒充完成。

验收：实际键入、粘贴、输入法、光标移动、编辑拒绝/改写、多插件链、乱序、关闭/撤权、发送抢跑、选择技能和附件保留；真实建议显示、拒绝、接受不发送、非空/运行/弹窗场景；旧快捷键和任务队列回归。界面保持现有风格，使用说明展示在 Mods 能力说明与可运行示例中。
