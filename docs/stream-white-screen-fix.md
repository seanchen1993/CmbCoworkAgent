# 流式消息白屏修复

修复分支：`codex/fix-stream-snapshot-white-screen`，基线：`9577a7bf`。

## 已确认的问题

用户提供的 `hasLiveStreamMessageId → canReuseLiveStreamMessageNormalization → projectCumulativeFrame → commitHookEffectListMount` 堆栈已在本地复现。

复现顺序：两条工具结果 T1、T2，随后 AI 分片 A；`values` 快照变成 `[T1]`；再收到 A 的分片。SDK 1.8.0 保留 A 的旧位置 2，写出 `[T1, <空洞>, A]`。性能优化中的 `for...of` 访问空洞得到 `undefined`，读取 `.id` 抛错，React 根树被卸载。渲染进程与后台任务仍可能存活，因此低 CPU/低内存和后续日志都不矛盾。

这是已经证实的一条白屏原因，不代表其他进程崩溃、OOM 或图形故障都由它导致。工具消息是已复现序列的一部分，但该堆栈发生在工具卡片渲染之前。工具卡片的局部错误边界保护不到这段 effect。

## 方案与约束

1. `electron-stream.ts` 使用 SDK 公开的 `StreamManager`、`MessageTupleManager`，提供应用实际使用的 `submit/stop/messages/values/isLoading/error` 接口。通过 `getMessages/setMessages` 边界维护当前数组，写入前用 ID 校验缓存位置；失效时按当前快照建索引。保留 SDK 的消息分片和工具参数合并，避免复制整套 SDK 或修改 `node_modules`。
2. 普通 token 校验、更新单个位置。只有快照替换后首次需要查找时扫描当前快照，后续追加更新索引。稳定前缀对象引用保持不变。普通快照可能局部或落后，不能简单清空累计分片；显式重试回滚和新一轮提交才清理分片缓存。
3. `values` 未携带 `messages` 时保留现有消息；明确的 `messages: []` 才清空当前 SDK 视图。快照中的空洞、空值和无 ID 条目在发布前过滤，并只记录条目数量，不记录消息正文。
4. 归一化 ID 判断接受运行时空值；用 `Array.from` 把空洞纳入缓存有效性检查，避免 `.map/.every` 跳过空洞造成错误复用。别名替换也做相同防护。
5. `AppErrorBoundary` 围住 App，关闭对话框作为兄弟节点保留。发生 React 渲染/effect 异常时显示错误页面。不自动刷新、不自动重启任务；现有应用没有运行中刷新重连协议。
6. 主进程在渲染器崩溃、无响应或关闭提示 15 秒无响应时使用原生对话框。默认取消，不自动退出；同一时间只有一个原生提示。等待期间有任务启动或托盘消失时重新确认；窗口销毁、页面重载后的旧结果不再执行。

SDK 直接依赖固定为已验证的 `1.8.0`。升级时应运行本专项回归；适配层仅覆盖当前 IPC 用法，不扩展为 SDK HTTP 历史/分支接口。
