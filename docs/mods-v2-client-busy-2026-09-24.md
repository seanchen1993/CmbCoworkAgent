# Client控件并发与忙碌状态

输入变更和按钮操作可以同时等待宿主回复。现在每个尚未完成的按钮点击、提交和选择操作都保留自己的忙碌状态；较早的输入回复不会把仍在执行的操作提前解锁。全部受控操作结束后才恢复操作，输入本身保持原有非阻塞行为。

桌面Client控件继续保留焦点，通过原有aria-disabled/readOnly处理忙态。此改动没有允许额外的点击或自动重试；宿主原有队列、intent去重、实例/句柄、授权、generation和取消验证继续生效。关闭后旧Client销毁，新的实例独立计数，旧响应不能改变新实例。

验证使用真实安装并批准的Function插件，在原clock SDK延迟窗口内交叠输入和点击。旧普通Electron已在“输入结束不得解锁等待中的点击”断言失败；修复后的普通Electron确认保持忙态直至真实宿主ACK，关闭期间不推进取消的旧操作，原composer仍可编辑。详见[验证报告](../output/mods-v2-validation/2026-09-24-client-busy.md)。

这是独立复现并修复的并发问题。此前长稳第6408个事件缺少实际ACK的根因仍未确认；不能将本修复直接等同于两小时/10000事件或完整业务验收通过。
