# 配置「开发项目模式插件」入口

导航目标随现有发布清单 `cmbdevclaw-latest.json` 下发。应用市场继续提供独立技能目录和安装包。
发布清单使用 [现有的内置模型配置渠道](./managed-model-catalog.md)。自测客户端读取自己配置的
`cmbdevclaw-latest*.json`，可先在自测清单上验收。

## 配置和发布

1. 在客户端进入「应用市场 → 技能」，打开已上架的独立技能详情。
2. 使用应用市场管理员账号，打开「管理员模式」，点击「复制导航配置」。
   客户端会把条目 ID 和市场内部名称复制为 JSON。
3. 在现有发布清单中合并 `conversationShortcuts.projectPluginCreation`，
   沿用当前渠道的清单发布权限和发布流程。保留清单里的版本、包下载地址等其他配置。
   通过现有配置发布渠道上传更新后的清单即可，应用包版本可保持原值。
4. 切回客户端或等待下一次刷新。插件管理页会显示「开发项目模式插件」。
   对应的市场技能详情显示「当前开发技能」和「开始开发」，可用它核对发布结果。

复制的配置示例

```json
{
  "conversationShortcuts": {
    "projectPluginCreation": {
      "itemId": "market-417",
      "marketName": "project-plugin-author"
    }
  }
}
```

- **换目标**时用新技能复制的对象替换 `projectPluginCreation`，再发布清单。
- **撤下入口**时将 `projectPluginCreation` 设为 `null` 或删除该键，再发布清单。
- 如确认该技能的源码可向所有能看到导航的用户开放，在同一个 `projectPluginCreation` 对象里
  加入 `"allowSourceForAll": true`，同时填写该安装包实际的 SHA-256。此许可只适用于这条导航
  下载并通过校验的安装包。换包后需更新摘要，换目标时需重新确认是否开放。
  源码开放许可只接受客户端预置发布服务的清单。自测渠道切换到其他服务器时，导航仍可验收，
  新安装保持源码保护。
- 未开启此配置时，导航的新安装按受保护内容保存。市场作者和已获授权的用户仍可通过原有市场
  安装流程获取可编辑源码。已经安装的副本维持安装时的权限。
- 市场内部名称和包根 `SKILL.md` 的 frontmatter `name` 不同时，在目标对象里补上
  `"skillName": "<包根技能名>"`。
- 同一个市场名称对应多个条目时，在目标对象里提供实际安装包的 `sha256`，客户端对旧下载
  接口返回的字节做校验。包更新后同步更新该 SHA-256。未配置摘要的同名目标会隐藏。
- `VITE_ADMIN_YST_IDS` 用于客户端显示「管理员模式」。全局配置的生效权限沿用发布清单权限，
  复制配置只是本地剪贴板操作。

## 使用与排查

- 「插件」管理页、目标技能的市场详情和右侧「工作目录 → 插件」共用启动流程。点击后，在最近使用
  的工作目录打开新会话并预选技能。技能未安装时先确认安装，没有最近工作目录时可选择目录。
  原会话草稿保留，消息由用户发送。
- 「项目模式」的创建和编辑表单保留轻量引导，可就地安装。关闭引导后可继续填写表单。
- 未配置、市场条目缺失、已下架或当前账号不可见时，开发入口隐藏。
- 客户端定时检查发布清单，窗口重新获得焦点时也会检查。市场目录沿用客户端启动时和访问市场、
  技能面板等功能时发出的现有请求。市场的下架和权限变化在下一次已有目录请求后生效。
- 查询、安装失败时可在引导面板重试。同名本地技能的来源无法核对时，保留原件并提示冲突。市场作者
  和源码白名单用户可在技能管理中编辑、导出源码。
- 现有发布流程如果按模板重建清单，需要把导航配置合入实际发布的清单。

## 验收

用自测清单验证无配置、发布、换绑和撤下，核对权限账号和灰度限制账号的入口。分别从插件管理、
目标技能详情和右侧工作目录启动。有最近工作目录时核对新会话预选技能，无最近工作目录时核对目录选择。
从项目模式打开引导并安装，关闭后核对表单和插件选择仍保留。
确认市场请求仍使用现有目录和安装包接口。
