## 用户会得到什么

组件等待模型回答、读取文件或等待下游规则时，不会因为外层规则的短时间限制而提前失败。作者可以读取 next.budget，判断自己的规则还剩多少处理时间。主动睡眠仍占自己的时间，不能用睡眠无限拖住对话。取消、代码批准、额度、文件权限和内容保护继续有效。

## 已确认依据

本地实际 Claude Code 2.1.288 声明 4793–4829：普通规则自身10秒、恢复处理1秒；等待 next 或 SDK 不占自己的时间，clock 的等待除外。6193–6223 给出 next.budget.ms 与实时 remainingMs；engine.create 不计自身时间；session.end 用整链共同的短退出期限，不停钟。5833附近再次说明独立模型等待不占调用规则预算。

DevClaw 目前 guest-runtime.ts 的 expiresAt 计整个 frame 的绝对时间，没有扣除 SDK 等待；runtime-client.ts 也按原绝对时间设置 IPC 请求期限。启动分析刚补的共享120秒解决实际可用性，但不是官方这套自身计量。这里是可适配缺口，目前没有框架限制证据。

## 本阶段实现

1. 为宿主实际 invocation 增加独立的自身预算字段，普通10秒、恢复1秒、引擎组装0表示不计自身时间。旧明确 timeoutMs 仍是绝对宿主上限，不把调用者设置的小绝对期限偷偷变大；未启用新自身计量的私有旧 invocation 保留原语义。
2. 宿主用单调时钟计量每个实际 frame。记录正在等待的免费 SDK/next 数量，以重叠等待的并集计停钟，不把两个并行调用的时间重复扣除。clock.sleep 等主动等待计入自身时间。入口批准检查不算已经进入的用户规则时间。
3. SDK调用结束、失败或取消均关闭停钟区间；过期 frame 的迟到返回不能恢复预算或接纳结果。每个并行 frame 有自己的计量，不共享全局暂停开关，也不信任插件给出的时间或请求ID。
4. 保留独立的有界总等待。普通生产规则采用最多120秒总 frame 上限，启动仍另受整链共享120秒期限，模型仍每次最多60秒。未完成的免费宿主调用也不能永久占用资源。原CPU执行片段、内存和取消不放宽；这项桌面保护与官方更长模型请求范围分别记录。
5. next.budget 用宿主原生只读查询返回本次真实 frame 的新快照，普通为10秒、恢复为1秒、引擎为0及Infinity。不得异步发RPC读取预算、不得向插件暴露宿主对象或权限，也不得允许旧 frame 重新运行。next.error.budget 与恢复预算一致。
6. 常规分派和引擎组装先接入，保留匹配、准确跳过当前规则、一次有效下游与失败传播的原行为。实际宿主请求的IPC上限包含总等待，不能5秒先杀掉已停钟的子进程。SDK配额、账本、原结果协议保持不变。
7. 流式处理需要跨实际游标累计自己的运行片段，普通turn.step是整次响应累计，process.spawn按每个返回片段重置。下一阶段单独接同一计量基础和实际游标，不将本阶段的逐frame能力冒充流式完全一致。之后继续短退出生命周期、附件/提交等可适配项。

## 验收与质量

- 真QuickJS验证：SDK/next等待超过小自身预算仍成功，主动clock等待同等时长失败；并行等待只停一次，结束后自己的时间重新消耗。
- 不同frame互不暂停；guest启动免费请求后无限CPU仍被原执行片段终止，纯未完成Promise仍消耗自身时间。
- 模型5秒以上与两层组合的慢下游实际HTTP，实时预算读数不会被网络等待耗尽；恢复规则获得独立1秒，next错误字段一致。
- 固定硬期限、原取消、主动SDK取消、撤权、迟到回包、资源释放、嵌套next与流程控制回归；未被新规则选中的旧测试上限不变。
- 同步预算查询无IPC，不把多次读取变成新的宿主操作；补真实计量性能与内存收口检查。
- 两位独立设计和实现检视；受控广域、真实Electron及类型/lint检查后更新矩阵，再继续流式与生命周期，不在阶段末停止。

## 独立评审追加的必须条件

两位评审要求在实现前明确以下边界。先补方案，再取得最终通过，不提前标记完成。

- 总等待期限和原取消不仅覆盖 guest/IPC，还覆盖分派器在恢复前、保留下游结果及清理 issued 操作时的等待。已进入的下游即使忽略取消、永不返回，调用者仍须按期限拒绝；底层实际 Promise 由原活动令牌跟踪到真实 finally。不得重放下游、填回迟到结果或恢复旧 frame。
- 免费请求登记前同步结算自身时间并检查是否已耗尽，不只依赖25毫秒 watchdog。预算耗尽后不能借新 SDK 请求停钟续命；请求结束只撤销自己的等待回执，不重置已消耗时间。并行与迟到回执不能给同 frame 或新的恢复 frame 充值。
- 同步预算查询直接创建 QuickJS 数值对象；Infinity 不经过 JSON。查询绑定原 frame，而非全局当前 frame。clock.after/every 的主动等待不标记免费；clock.now 可以免费。
- 原明确短硬期限保持优先。恢复使用独立的新实际 frame、自身1秒及 next.error.budget=1000；旧 frame 不续命。原 CPU、内存、取消、模型与整链启动期限保持有效。
- 必测真实下游 core 永不完成且忽略 abort：宿主调用次数1，调用者到期拒绝，迟到完成不接纳。另测主动等待恰好耗尽后、watchdog 下一 tick 前的 SDK 请求调用0，以及并行免费回执重复关闭和旧 frame 迟到返回不影响恢复新 frame。
