日期：2026-10-14
状态：第 10 节补齐后，两名 medium 子 agent 均已通过方案评审，开始实施；不是已交付声明。
代码基线：`125fec68349e2ca6a3389c04b911ad70385872c9`，仅 `codex/mods-v2`。

## 1. 用户确认的边界

用户在一个项目里选择多个插件提供的独立能力或完整流程，通过该项目的对话使用。
普通对话不增加原生项目插件跨插件执行。平台提供通用机制，不硬编码 AutoBiz 或业务场景。
“项目内对话”与“普通对话”是不同场景；所有入口、状态和帮助都必须准确区分。
本方案替代 10 月 13 日方案中“普通聊天自由组合”的目标；旧文档保留历史及可复用的底层分析。

能力适用范围：

| 范围 | 普通对话 | 项目模式 |
| --- | --- | --- |
| 通用 | 可以 | 可以，但仍需满足项目依赖、检查与界面约束 |
| 仅限对话 | 可以 | 不可以 |
| 仅限项目 | 不可以 | 可以 |

分类细化到技能、功能组件和流程；同一插件允许混合范围。插件管理统一安装，当前场景的添加入口只提供适用能力。
作者声明是兼容条件，不是执行授权。宿主的项目约束、权限和原验证链优先。
未声明的旧函数组件保留已有适用行为；原生项目阶段及无法证明独立的衍生能力仍要求项目环境。

## 2. 用户操作

1. 进入项目，在“项目能力”中点“添加能力”。
2. 按插件来源查看“可单独使用的能力”和“完整流程”，选择需要的条目。
3. 独立能力选择“一起使用”；流程选择“按顺序执行”，指定前序流程的产物交接。
4. 预览新增能力、自动带上的必要步骤/检查、冲突以及影响范围，再保存。
5. 回到当前项目对话提出需求。在“运行过程”查看进度、当前执行来源、结果与待确认事项。
6. 失败后只修复和重试失效部分；原失败记录保留，审批不得沿用失效回执。

显示用户能理解的能力名、来源名和用途，不让用户填写 pluginId、digest 或公开 actionId。
没有适用能力时解释原因，不展示无法生效的保存按钮。切换模式必须重新检查，不能静默删除已选配置。
当前运行使用冻结配置；修改组合影响后续运行。存量项目未配置组合时保持原路径。

## 3. 复用现有实现

- `src/shared/mods/claw-components.ts`：组件声明、选择、依赖；增加可选适用范围并统一判断。
- `src/main/mods/claw-*`、保存组合与应用 IPC：读目录、预览、保存及实际应用均校验适用场景，不能只隐藏 UI。
- `src/shared/skill-visibility.ts`、`src/main/plugins/runtime-source-scope.ts`：保留旧项目绑定；新组合用显式运行来源集合，禁止全局放开派生能力。
- `src/main/hooks/scope.ts`、MCP capability service：消费同一宿主签发的组合来源，按精确技能/工具及必要 Hook 限定。
- `src/main/harness-board/project-runtime`：保留宿主与 legacy 引擎及原有终态、审批、校验逻辑；组合协调器调用这些真实入口，不自造成功结果。
- `NativeNodeComposer`、`NativePluginCapabilities`：扩展现有入口，避免再建一套重复的配置系统。

## 4. 能力目录与适用范围

函数组件增加可选 `usage: "universal" | "chat" | "project"`；缺省为兼容旧行为的 universal，严格拒绝未知值。
宿主向前端提供解析后的适用范围与不可用原因，配置、依赖解析、应用及运行边界使用同一规则。
组件依赖的适用范围也要检查；不能选择项目组件时偷偷带入仅限对话组件。
无组件声明的旧包继续旧路径，不以新增字段推断或扩大其原生项目权限。
原生技能和流程目录采用安装身份+能力身份+包摘要；同名能力按来源分别展示和执行。
项目阶段能力归类为 project；可独立使用必须有宿主验证的依赖契约，SKILL.md 存在并不代表独立。

## 5. 一个项目、多来源的执行模型

项目保持一个对用户可见的身份、工作目录和聊天入口；新增可选组合配置，不改写旧单插件绑定。
每次运行冻结选择版本、包摘要、精确技能/工具、必需 Hook、前置条件及父项目身份。
独立能力在父项目运行来源集合中准入。完整流程采用组合中的执行单元，各自保留包版本、阶段状态、产物和审批记录。
流程执行单元是平台内部上下文，不要求用户手动创建或切换多个项目。legacy 流程若依赖固定根状态路径，先检查隔离契约；无法隔离的组合明确拒绝并说明，不让两套脚本同时覆盖状态。
同一工作目录写入默认串行。并发仅用于已声明且宿主确认无写冲突的能力；首版完整流程按顺序执行。
各流程原 Hook 事件、顺序、匹配条件、once/persistent、超时与错误语义保留，不能把阶段检查转成模型自评。

## 6. 持久流程编排

组合定义包含有序执行单元、来源版本和显式产物映射；有界解析、唯一身份、依赖循环检测。
持久运行状态至少区分等待、执行中、等待审批、成功、失败、取消和恢复待确认。
创建任务返回成功不等于执行完成；只有原引擎可信终态和必需检查全部通过才进入下一流程。
交接记录保留原产物归属、路径约束、内容摘要、验证证据及输入输出映射；不把上一阶段完成文字当作有效产物。
幂等启动、CAS 状态更新及工作区租约防止双击/双窗口重复执行。崩溃恢复先核实真实任务状态；不明状态不得重放有副作用步骤。
取消阻止后续单元并传递给当前原引擎；审批暂停、拒绝和撤权不标成功。
来源更新、卸载或内容变化使旧预览失效；运行期更新策略与撤权策略分开，不悄悄切换版本。

## 7. 通用适配与 AutoBiz 保护

先按能力契约接入，不写死 AutoBiz 名称、技能名和目录。AutoBiz 只作为兼容样本。
原包与衍生包同族仍按明确来源取脚本、资源和 Hook，禁止同名回退及全家族自动启用。
依赖传统项目状态的完整流程必须通过原引擎/适配器运行，且在内部上下文与根路径可验证隔离后才准入组合。
作者可逐步声明能力范围、必要依赖和产物；旧插件无需迁移即可继续原单插件使用。
提供两个不同业务样例说明如何声明独立能力和完整流程，说明从创建、组合到执行结果；不冒称真实第三方插件验收。

## 8. 实施批次与门槛

采用关联能力集中实现，再做集中回归；编辑期间只做必要类型/边界检查，避免每个小改动跑全套。

2026-10-14 验收：下列四批已在已审来源范围内完成，最终候选为 candidate13。实包原审批、Host 产物交接、已审 AutoBiz→文档插件、失败恢复、中文配图与同构建长会话均有通过证据，两名 medium 回检无未关闭的确认 P2+。详见同日进度账本末尾；AutoBiz 兼容仅覆盖审定协议版本，未声明的动态产物不自动交接。候选随后经用户授权替换到 Downloads 安装目录，并通过安装后验证。

### P1：场景隔离及真实配置闭环

组件范围契约、目录展示、同一规则的依赖/应用检查、普通对话/项目入口分类和旧配置兼容。
首个交付门槛：在真实组件与主进程路径证明不适用的能力无法应用，旧包使用不变。

### P2：项目独立能力组合

项目精确多来源快照、Skills/Hooks/MCP 统一作用域、用户预览确认、运行记录。
门槛：原包与衍生包各一个独立能力在同一项目对话中真实执行，未选来源不加载，原检查保留。

### P3：完整项目流程串联

内部执行单元、持久协调器、原引擎终态接线、产物映射、审批/取消/恢复、可视化配置。
门槛：两个流程真实前后运行且产物交接有效；前序失败/等待审批时后序绝不能执行。

### P4：集中验收、体验与文档

两名 medium 持续代码及体验回检至已实施范围无未关闭的确认 P2+。

所有批次以实际接线和测试为完成条件；纯类型、纯协调器或目录可见均不能标为组合已完成。

## 9. 风险与控制

- 最大风险是旧插件共享根路径状态：先核实原插件契约，无法无损隔离时报告具体不兼容点，不绕过检查。
- mode 字段来自不可信渲染进程时，宿主从真实线程/项目绑定重建，不允许调用者伪装项目。
- 目录读取无模型、Hook 或外部连接副作用；使用已有缓存和版本订阅，来源扫描有界且不随每次渲染触发。
- 本次不更新用户安装包，直到最终候选包完成验收并确认应用退出；不修改其他工作树或分支。

## 10. 首轮双审补充：必须落实的接口边界

### 统一场景解析

新增主进程场景解析器，从数据库中的线程、父子关系和真实项目记录校验项目归属与工作目录，返回 chat/project 及上下文身份。
`isClawThread` 仅代表旧 Claw 入口适用性，`isOrdinaryFlowMetadata` 仅代表旧流程协议资格，二者都不能充当项目组合授权。
普通对话配置 P1 继续现有授权路径。项目添加入口必须在校验真实项目后启用；在 P2 接通前，不因添加 usage 字段就扩大旧 Claw applicable。
保存/应用/目录/运行统一使用此解析器；宿主源数据变化使进行中的预览失效，renderer 传入 mode 不产生权限。
运行来源还须覆盖 `getHarnessAgentContext`，不能只接 Skills/Hooks/MCP 后遗漏阶段提示与产物上下文。

### 逐能力作者契约与旧包策略

函数组件保留 `claw.components[].usage` 扩展。原生插件新增可选、静态的 `devclaw.capabilities.json`：
`apiVersion: devclaw.capabilities/v1`，`capabilities[]` 每项包含唯一 id、title、kind(skill/flow)、usage、entry、dependsOn。
skill entry 必须是包内真实技能路径；flow entry 必须指向本包真实运行声明或已注册的 legacy 适配器入口。路径穿越、重复、依赖循环与跨模式依赖拒绝。
独立技能声明不会移除原 Hook；宿主必须核对阶段引用与所需上下文、Hook 组。无法确认独立时返回“需要项目流程上下文”，不得按作者 universal 声明越权。
flow 只准 project；未知旧原生包不自动生成可独立复用能力。没有新增声明的旧项目运行完全保持。
通用目录与解析不依赖 `nativeClosureInvocation` 的 AutoBiz 专用检查脚本；旧节点组合继续原协议，新流程注册宿主/legacy 适配器后才准入。

### mixed 插件、all 与全局启用

已保存的显式 all 若包含当前模式不可用组件，保存/应用失败并显示具体条目，用户重新选择后预览确认；不静默删除已有选择。
新建组合默认只选适用项及其适用依赖，并明确列出所选内容；“全部”表示全部适用功能，不将其他模式条目混入隐含授权。
未应用组合的全局启用路径只投影当前模式可用组件；没有适用组件则不加载该插件。该行为只影响明确新增 usage 声明的包；旧无声明包行为不变。
显式 selected 的跨模式条目或跨模式必需依赖在真实执行前拒绝；试用、热更新、参数重载也必须检查，不能绕过主入口。

### 完整流程的终态与隔离

agent terminal success、单阶段检查通过、stage transitioned、完整 flow completed 是四个不同条件。
串联只接受适配器经原引擎核实的完整流程 completed；legacy operation succeeded 单独不够，必须关联原阶段/需求最终状态及全部必需检查。
宿主单元状态按父项目+单元 ID 独立保存，旧 host/legacy 工作区互斥不得删除或弱化。
legacy 根路径状态不能靠切换绑定轮流覆盖。适配器必须能把各单元指向独立状态根并保留原脚本语义；不支持时该来源暂不可作为完整流程单元，返回具体限制。
代码产物可共用父项目工作目录，但状态目录和交接产物归属分离，并以父项目写租约串行执行。所有层的真实调用与终态验证通过后才宣称完整串联交付。

### 补充：流程任务统一入口与实时展示（2026-10-14）

用户反馈选择、发送、结果分散，运行结果混杂且看不到当前步骤。两名 medium 只读审查确认现状并同意以下范围：

1. “流程任务”固定区域负责选择、独立任务输入、显式开始、进度、审批及结果；输入框只保留打开入口，普通聊天不再分流。保留 ChatContainer 原共享提交锁、已有任务/审批限制、作用域与版本校验。
2. 流程编辑器只负责保存并选择，到统一区域开始任务；原历史保留折叠。其他插件记录与流程当前执行区分开，避免插件更新抢走当前流程视图。
3. 默认显示全部启用步骤及最新有效尝试、当前步骤/用时、可获得的公开执行内容、需确认事项和成果。完整重试历史、原始证据按需展开并延迟读取。
4. 步骤内部观察只采集原运行器已有公开 assistant text/工具状态，设置大小和频率上限；不读思考链、不展示工具参数、不改变执行结果、权限或恢复依据，不逐token持久化整条流程历史。当前运行定向刷新。
5. 验收：普通发送/命令不启动流程；失败保留任务输入；统一位置启动→实时步骤→审批→结果；会话切换隔离；断开/停止晚到事件不覆盖终态；历史懒读取；小屏可用；长会话不闪屏/重复。
