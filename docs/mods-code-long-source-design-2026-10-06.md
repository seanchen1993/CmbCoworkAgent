# 长代码组件的兼容推进

用户效果：插件展示三万字符的代码时，面板可以正常打开；不能解析为差异的文字仍能
看到原文，不再使整个面板失败。代码、文件路径和模型消息的处理职责保持清楚。

依据是已校验的官方 2.1.290 包内 `CodeProps`（1567–1625 行）：源码不限长度，单次
绘制最多十万字符；无法解析为差异时显示无行号的普通代码，并记录原因。官方测试
工具明确不执行屏幕绘制。因此，原版实验只证明完整组件数据的接纳和钩子输入，不能
拿它证明十万字符的实际屏幕截断、行号或日志。屏幕行为按官方说明适配，再用本工程
真实 Electron 验证。

## 首个实现窗口

1. 只取消 `Code.source` 的旧一万字符拒绝；其他属性、控制字符、层级、节点数以及
   一 MiB 的原整体传输限制保持。必须检查完整源码，截断后看不到的尾部也不得藏
   控制字符。真实钩子、保护和原完整树继续接收完整源码。
2. 显示副本最多十万字符。扩展已有的 UTF-16 显示助手支持十万这一固定长度，保留
   表情字符和孤立代理项的处理。只截显示副本，不覆盖原树、不写回文件、不改变模型
   请求。路径继续只用于语言推断，不显示、不读取。
3. 同一个 `Element` 根绘制中的多个 Code 共享十万字符预算。根入口先按稳定节点
   路径计算只读显示表，再把表传给递归子元素，不靠 React 渲染顺序修改一个全局
   计数器。同一节点对象被放在两个位置仍按两个位置分别计数。重绘和不同面板有各自
   显示表。这张表只是界面数据，不承担权限或消息来源资格。
4. 对显示副本解析差异。合法差异保留完整行号和增删标记；截到半个差异段或原文
   不能解析时，整个显示副本回到普通代码，不显示差异标记或行号。控制字符及非法
   属性仍拒绝。回退日志只写固定原因，不打印源码、路径或凭据。
5. 高亮器只收到已保护的显示副本，允许十万输入字符；原队列容量、输出容量、缓存
   容量、实际工作完成前保留槽位和取消规则保持。超出高亮输出容量仍使用普通显示，
   不追加调用、不让旧结果覆盖新源码。

这个窗口只改变 Code，其他文字及输入控件继续使用原限制。官方整棵绘制树中文字
的统一预算、插件自带语法规则仍需后续独立验证和迭代；本窗口不宣称这些已经对齐。
尤其不因修改 Code 截断用户输入控件的值，也不扩展模型和消息正文限制。

## 验证要求

- 原版隔离实验保留真实包散列、版本与完整捕获状态，不使用模型凭据。三万、十二万、
  合法及非法差异、两个七万组件分别记录完整输入与已接纳树，不冒充实际绘制。
- 单元验证三万源码、十二万只显示十万、截断表情、完整尾部控制字符拒绝、差异回退
  无行号、HTML 转义、原路径不读取及整体传输超限拒绝。
- 多 Code 的稳定路径预算、重复节点、两次根绘制独立，原输入树必须严格不变。
- 原高亮队列、取消、晚回复、容量测试全部保留；增加已截显示输入的长度边界。
- 真实 Guest/Session 的完整长源码先钩子、保护再显示；取消、撤权后零晚显示。
- 真实 Electron 验证长代码、原高亮、回退效果与截图，检查原模型请求和保存消息不变。
- 两位独立方案评审后实施，两位源码检视后运行测试。原共享流、文件引用和性能失败
  仍分别跟进；本窗口通过不替代它们的验收。
