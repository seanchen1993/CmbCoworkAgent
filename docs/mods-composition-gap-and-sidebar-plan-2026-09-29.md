# Mods 组合能力复核与右侧栏设计方案

日期：2026-09-29。核查目录：`C:\ai\CmbCoworkAgent-mods-v2`，分支：`codex/mods-v2`。

本文交付调研、代码核验和交互设计，**不代表以下规划已实现**。本轮没有改动生产代码，也没有操作 UAT。

后续实现状态请看 [组合与侧栏交付记录](mods-composition-delivery-2026-09-29.md)。本文保留实现前调研语境，下面的“当前/尚缺”不是后续交付版本的状态。

## 1. 结论

用户对目标的理解基本正确：DIY Claw 应允许把不同来源的能力、模型、角色、工具和执行规则组合成一个可保存、可在对话中使用的助手。当前工程尚未完整达到这个产品目标。

但“目前只能在一个上传插件里面组合”不是底层的全部事实：我们已经支持多个 Function Mods 同时启用、跨插件服务调用、步骤指定模型以及受宿主约束的模型切换。缺口主要是**能力目录、声明式组合、组合的运行绑定及统一用户入口**。已有底层值得复用，不能以为全部缺失而再造一套运行时。

“一切皆插件”也不等于“所有东西都作为流程步骤”。模型是提供推理能力的服务；工具是可调用动作；Hooks 是事件处理；Skill 是知识或行为说明；审批是执行门禁。不同类型必须通过兼容的接口组合，不能用一条任意连线假装已经连通。

## 2. 官方能力到底是什么

### 2.1 Claude Mods：扩展引擎接口，并通过契约组合

2026-09-29 读取的官方 `mods/README.md` 已专门介绍跨 Mod 的 noun contract：提供者通过 `engine.create` 扩展 `$`，消费者引用同一份类型声明；`diff` 调用 `telemetry` 是官方实例。缺少提供者时，构建应报告缺失接口。[官方 README](https://github.com/anthropics/claude-code/blob/main/mods/README.md)

当前公开类型说明：`engine.create` 可以添加或收回接口，不能替换别的步骤已经添加的接口；`turn.step` 可以改变本次请求的模型与 effort。因此，它支持有约束的运行时扩展及模型路由，不能由此推导出“任意替换全部内核”或“官方已经有可视化自由拼装器”。[官方类型](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts)

它仍是 Early access；公开源码存在并不保证每个安装渠道、账号和发布版本都开放。同一个 API 名称也不保证失败语义、重载与权限行为完全兼容。本文不宣称我们与最新 Claude 全面等价。

### 2.2 DeepSeek Harness：核心能力本身也采用插件服务架构

官网明确把模型、工具、会话、存储、循环、沙箱及界面纳入插件化架构。其包结构要求消费者依赖服务定义，而非具体实现；模型调用通过统一服务及不同适配器提供。这比“给固定 Agent 加外部 Hooks”更深入。[官网](https://www.deepseek.com/harness/) · [官方包结构](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/README.md) · [模型服务](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/README.md)

Preset 可以挂载不同子插件组合，在同一进程中让不同 Agent 使用不同组合；已有 Agent 保留其当前组合。不能忽略边界：当前 Host 仍共享 Agent loop；旧实现不会跨进程重启永久保存；Preset 不是安全沙箱。其界面能读取组合 YAML，不等于可以把任意 YAML 编辑后直接提交；官方描述的新增方式是 bundle patch / Creator。[Preset registry](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-preset-registry/README.md)

对本工程的借鉴是“稳定服务契约 + 可替换提供者 + 有作用域的组合”，而不是照搬其宿主代码执行权限，或宣称其提供了我们设想中的拖拽界面。

### 2.3 证据版本与限制

本轮读取官网及官方仓库当前分支，源码快照放在 `output/mods-composition-research-20260929/`。GitHub commit API 遇到网络错误与限流，**未取得可靠的提交 SHA**；快照清单记录实际文件 SHA-256 和读取时间，不把它伪装成发布版本或提交号。此次研究主要依据公开源码，不是一次新的二进制反编译。

## 3. 本工程逐项核验

| 用户要做的事 | 当前事实 | 尚缺什么 |
| --- | --- | --- |
| 同时启用 A、B 两个插件 | 支持多个已授权 Function Mods，当前最多 8 个 | 界面应明确是跨来源选择，展示冲突与依赖 |
| A 插件调用 B 插件的方法 | `engine.create`、跨隔离 guest 调用及中间件已有实现和测试 | 用户可发现的能力导出、版本依赖、安装/启用前的组合诊断 |
| 只取 A 的检视能力，配 B 的测试能力 | 底层作者可以编写组合，但 Claw 当前按整个插件选择 | 细粒度组件声明、配置 schema、依赖闭包和明确的执行适配 |
| 给不同 Agent 步骤配不同模型 | 支持 `modelId`，优先于角色模型，再使用默认模型 | 把主助手、检视角色、模型绑定一起保存到 Claw，并在对话中显示实际生效值 |
| Mod 在模型请求边界切换模型 | 有受宿主解析与预算约束的实现；测试覆盖恢复默认模型 | 图形化路由规则和可解释诊断，不是凭一个模型名称就能访问任何提供商 |
| Plugin + Skill + MCP + 内置工具自由组合 | 这些能力各自存在，但不统一纳入当前 ClawProfile | 统一目录与宿主适配器；保留旧 Plugin 项目模式 |
| 任意插件动作串成流程 | 当前只有 agent、check、approval、autobiz-stage 四种步骤 | 可调用组件导出、输入输出绑定、每节点独立提供者与授权 |
| 两个对话同时用不同 Claw | 当前 active Claw 为项目级配置 | 对话绑定和每次运行的不可变快照，防止修改影响另一对话 |
| 自由替换 loop、存储、沙箱等内核 | 当前没有达到 DeepSeek 的完整服务化架构 | 按服务契约渐进拆分；安全裁决仍由宿主控制 |
| 清爽的对话体验 | 多种面板连续堆在输入区上方 | 右侧工作区、单一输入框、紧凑状态与详情分离 |

## 4. 用户最终应该怎样使用

以“Autobiz 研发 Claw”为验收案例，组件名称仅为目标示例，不代表对应导出目前都存在：

1. 安装 Autobiz 插件和一个独立的 Code Review 插件；已有模型在设置中完成配置。
2. 在 Claw 编辑器的统一能力库中，选择 Autobiz 的需求/阶段能力、Review 的代码检视、内置测试执行和人工确认；可再启用一个知识 Skill 或 MCP 工具。
3. 为“实现”角色绑定模型 A，为“检视”角色绑定模型 B。模型只引用宿主配置，不在组合文件中包含密钥。
4. 设置“实现 → 运行测试 → 代码检视 → 人工确认”。测试失败后进入明确、有限次数的修复路径；取消和基础设施故障不能走业务成功分支。
5. 保存为“Autobiz 研发 Claw v2”，选择“在当前对话使用”。这个动作只绑定配置，**不立即执行任务**。
6. 在唯一的对话输入框输入“给订单列表增加导出”。点击发送后，运行使用已保存版本和本次目标。
7. 右侧显示当前节点、真实执行者/模型、权限问题、产物和检查结果。用户能看到 A/B 插件实际调用记录，而不只是它们的名称。
8. 修改检视插件或模型后另存一个版本；旧运行继续使用原版本。可复制到新对话做比较。

普通对话与显式流程不能混淆：事件型 Mod 随匹配事件生效；命令型能力需命令/工具触发；显式流程需选择该流程并发送目标。提示应写“应用于下次任务”“执行当前流程”，避免含糊的“运行已保存版本”。

## 5. 底层方案：先定义组合，再扩展界面

### 5.1 统一能力目录 CapabilityCatalog

目录收录内置能力、Function Mods 显式导出、已有模型配置、Agent 角色、Skill、MCP 工具。插件仍是安装/升级/授权的包装单位，组件是用户选择和组合的单位。

每个描述包含：稳定命名空间 ID、来源与版本、kind、配置 schema、输入输出 schema、服务依赖、模型角色需求、权限和副作用标签。明确区分 action/service/hook/model/agent/skill/ui。没有导出声明的旧插件只能整体启用；不要猜测其中函数或把任意 hook 伪装成动作节点。

只停用一个组件时，必须处理共享注册、依赖服务和卸载顺序。优先让作者以独立模块声明组件；旧单文件模块不可被界面承诺为任意拆分。管理策略与强制检查不属于用户可关闭的普通组件。

### 5.2 ClawDefinition 与版本

统一保存所选组件、参数、角色→模型引用、工具/Skill/MCP 选择、触发方式、流程及服务依赖。区分项目模板、对话绑定、运行快照三层；保存不自动应用，应用不自动执行。

模型路由规则显式定义为：节点明确绑定 > Claw 角色绑定 > 已保存默认模型。Mod 若申请覆盖，只能在该运行授权的模型范围内，记录最终选择及原因；不能出现界面显示 A、实际静默使用 B。自动降级须预先配置允许列表，不能在模型缺失时暗中回退。

### 5.3 解析为不可变执行计划

启动前验证 ID/版本、依赖环、接口类型、模型可用性、权限、命名冲突；生成含组件、参数、模型配置版本、角色说明和规则引用的计划。原子发布：失败则保留旧配置，不留下半套新运行时。

现有 Flow 的 agent/check/approval/stage 作为首批适配器；新增明确的 component-action 步骤，每一步绑定真正提供者和输入输出。UI 排序、Hook 中间件顺序、业务节点顺序分别建模，不共用一个 order。

运行期间配置版本固定；安全撤权必须立即生效，不能被快照屏蔽。无法保留的旧插件实现、模型版本或凭据配置导致恢复失败时，标记“无法按原版本恢复”，不得静默替换后宣称精确复现。

### 5.4 复用运行时与安全链路

继续使用 FunctionSession、engine-nouns、现有模型边界、Flow 主机、取消、authority、审计和内容保护。跨组件调用保留 caller/provider 身份链；宿主敏感操作同时受调用链授权约束。

不要让界面配置获得绕过沙箱/权限/组织策略的能力。模型凭据留在宿主。将内部默认实现包装成服务提供者，不等于允许上传的任意插件接管所有安全裁决。

### 5.5 内核服务化的范围

本轮后续主线应先打通模型、Agent、工具/技能、完成检查和流程动作的组合，让用户真正获得跨插件 DIY。随后可将 context/compaction/loop 抽出稳定契约，由可信提供者选择实现。

任意替换存储引擎/沙箱后端、热迁移运行中的循环、任意并行图编辑器属于独立较大项目，不阻塞上述主要用户目标。未完成前必须称为“可组合 Claw”，不能宣传已经做到 DeepSeek 范围的“一切皆插件”。

## 6. 右侧栏交互设计

参考方式是借鉴信息结构，不照抄配色。VS Code 的 Secondary Side Bar 将辅助视图放在编辑区旁边；Langflow 将选中组件的参数放在右侧检查面板，常用参数优先、高级参数折叠。[VS Code 布局](https://code.visualstudio.com/docs/configure/custom-layout) · [Langflow 组件](https://docs.langflow.org/concepts-components)

### 6.1 日常使用

- 中间：消息记录和一个输入框。输入区仅保留当前 Claw、实际模型摘要、紧凑运行状态与“查看详情”入口。
- 右侧：在现有右侧模块中增加 Claw，内部“运行 / 配置 / 结果”三个页签。运行展示当前步骤和必要动作；配置展示来源、模型角色和保存版本；结果集中展示产物与测试证据。
- 工作、文件、Git、浏览器沿用现有入口。状态更新不抢占用户正在看的面板；主动点击运行/详情时才按约定打开。
- 桌面默认侧栏约 380px，可调整。窄窗口转抽屉，关闭后仍有状态入口；输入区不出现另一套流程目标输入框。
- “保存版本”“在当前对话使用”“发送并执行”职责不同、文案不同；版本尚未应用时清楚标记草稿。

### 6.2 编辑组合

右侧可做模型绑定、开关和少量参数调整；复杂编排打开专用编辑区。能力库可跨来源选择，已选列表标明提供插件及类型，点选后展示属性。初期用有序步骤和条件编辑即可，不先投入大型自由画布。

交互原型展示“侧栏日常运行 + 配置编辑”，其中 Review 等示例组件和模型绑定仅用于设计演示，未接入真实业务运行。

### 6.3 搬迁不能破坏插件 UI 语义

长面板、后台命令、完整证据和流程步骤移到右侧。AbovePrompt、PromptHint、ToolUse 等约定的内联插槽保留简短内容，过长部分折叠并提供详情；待审批/阻断信息不能只藏在关闭的侧栏里。

运行控制器放在稳定的会话作用域，侧栏只订阅数据。关闭侧栏不能取消任务，切换页签不能重复启动、重复订阅或触发错误的 UI mount/unmount 事件。审批只提交一次并校验 nonce 和运行版本。

## 7. 实施次序与验收

| 阶段 | 工作 | 完成判据 |
| --- | --- | --- |
| A | 明确服务/组件描述、ClawDefinition、迁移与解析契约 | 两个不同插件动作 + 两个角色模型解析为稳定计划，缺依赖/冲突/非法权限均可诊断 |
| B | 右侧 Claw 模块、共享控制器、精简输入区 | 现有任务可在侧栏运行；关闭/切线程不丢任务，审批和错误仍可发现 |
| C | 多来源目录、组件动作适配、角色模型绑定 | Autobiz + 独立 Review + 内置测试在一次任务中真正执行；返回值确实传递 |
| D | 保存/应用/对话绑定/运行快照闭环 | 两个对话使用不同版本；普通发送及显式流程入口清晰；重启恢复行为真实 |
| E | 回归、E2E、性能和可用性验收 | 满足下述矩阵，发布说明明确兼容范围和延期范围 |

开发前沿用此前要求：架构与兼容性、质量与测试分别交由两个 agent 评审，修正阻断问题后进入实现。**本轮没有执行双 agent 评审，不写成已通过。**

测试矩阵：

1. 单元/集成：跨来源组合、同名冲突、依赖环、组件拆分限制、输入输出不匹配、未配置模型、模型范围和预算、取消/撤权/重载、失败不污染旧版本。
2. 真正的组合 E2E：两个独立安装包，动作实际产生不同可验证文件/结构化结果；模型 A/B 用受控传输验证实际请求归属；不能只断言卡片名称。
3. 业务验收：经授权且环境有凭据时跑真实模型，验证业务结果；受控 fixture 测试不得冒称线上模型效果。
4. 两对话隔离：不同 Claw/模型/参数并行运行；修改模板不串线；重启后明确恢复或中断，不误报完成。
5. UI：开关侧栏、切文件/Git、长结果、多个插件面板、错误/审批、键盘与读屏；桌面/窄窗/缩放下输入框和发送按钮不被挤出。
6. 存量回归：未启用 Mods 的普通聊天、经典 Plugin 项目模式、Skills/MCP、Harness、目标/工作流、历史恢复、工具确认、取消和模型切换。
7. 性能：空 Mods 不新增 guest；目录按插件版本缓存；相同配置解析复用，按会话保持独立 authority；后台面板不重复轮询。先测当前启动、发送、流式渲染、目录解析和内存基线，再比较 p50/p95；以同机至少 30 次样本和事先设定阈值验收，不凭主观宣称提升。
