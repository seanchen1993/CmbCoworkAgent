# 对话内生成图片

评审基线为开发分支 `codex/chat-multimodal-attachments` 的 `332bc95e2`。本方案面向桌面端普通聊天、Bot 私聊和应用内群聊。

2026-11-27 完成三个独立方向的设计终审。模型与网关评审确认生成请求去重和原主体恢复约束，界面与数据评审确认群交付和消息读取边界，可靠性评审确认故障注入及真实验收条件。三方均通过。首个实现面向同步返回 PNG 的兼容服务，实际部署的出图能力需在该部署上另行验证。

## 用户能做什么

用户可以说“画一张蓝色鲸鱼的海报”，也可以在输入框选择“生成图片”后输入描述。自然语言走当前对话模型的工具调用。显式入口可以在当前聊天模型无法调用工具时直接执行，两种入口共享一次用户操作。普通问题、解释如何画画、附件或历史记录中的指令均不应自行触发生图。对调用意图有歧义时先澄清。聊天模型和生图服务可以分别配置。

首期每次生成一张静态图片。结果直接显示在对应回复中，可点击放大、保存原图，重开会话后可查看。群聊中的公开结果显示发送 Bot。“重新生成”由宿主创建新的用户动作并保留旧结果，同一次点击的重复事件复用动作 ID。图生图、编辑局部区域和批量生图有不同的输入和授权要求，单独评估。下一轮若要让视觉模型查看原图，首期可以显式另存并作为普通图片上传。对话中的显示权限不会隐式将产物送入下一轮模型上下文。本期验收仅涵盖桌面应用内群聊；外部 IM 回传图片需要对应渠道的媒体交付验证。

## 当前 DeepSeek 接口实测

2026-11-27 使用开发版已有直连配置，请求模型名为 `deepseek-v4-flash`，响应模型名为 `deepseek-flash`。同一服务的 `/models` 将其列为 DeepSeek-V4.1-Flash，声明输入为文本和图片，输出为文本。[官方模型目录说明](https://api-docs.deepseek.com/api/list-models/)

| 测试 | 观测结果 |
| --- | --- |
| 上传测试 PNG，只问左右各是什么颜色和形状 | 正确答出左侧紫色圆形、右侧橙色正方形 |
| 仅给文字描述，要求直接返回海上帆船 PNG | 返回文本说明无法返回实际 PNG，响应没有图片 |
| 提供 `generate_image` 工具定义，用自然语言要求画帆船 | 返回 `generate_image` 工具调用；本次仅验证调用选择，未执行出图服务 |
| 在 Electron 普通聊天发送“请画一张绿色森林的海报” | 真实 DeepSeek V4.1 Flash 从 14 个可用工具中选中了 `generate_image`。本地 HTTP 测试服务返回固定 PNG，已比对对话里的原图字节和重开后的结果 |

普通聊天和 Bot 可以继续使用此模型来理解请求、选择生图工具和看图。生图工具需连接一个实际返回图片的服务。开发阶段可以直接验证已有模型和可用的出图服务，无需等待内部 UAT 网关；指定 UAT 环境的最终验收仍单独记录。

## 在开发版配置出图服务

聊天模型继续使用已有配置。以下环境变量供 Electron 主进程启动时读取，更新后重启开发版。

| 变量 | 填写内容 |
| --- | --- |
| `CMB_IMAGE_GENERATION_ENDPOINT` | 生图服务的完整 HTTPS 请求地址，由部署方提供。回环地址可使用 HTTP 进行本地测试 |
| `CMB_IMAGE_GENERATION_MODEL` | 该服务接受的绘图模型或部署名 |
| `CMB_IMAGE_GENERATION_API_KEY` | 该服务的 Bearer 凭据，由本机环境注入 |
| `CMB_IMAGE_GENERATION_ENVIRONMENT` | 可选，标识 UAT 或生产等部署环境 |
| `CMB_IMAGE_GENERATION_RESPONSE_FORMAT` | 若该服务需要显式指定返回格式，填 `b64_json`；默认省略该请求字段 |

适配器发送 `model`、`prompt`、`n: 1`，从 `data[0].b64_json` 读取实际 PNG 字节。成功后在会话内同时保留原图和用于展示的缩略图。首版未接入仅返回下载链接或异步任务号的服务。同步响应中断且无法确认结果时，界面会提示结果待确认。

群聊有单独的存储边界。发布前，工具只在主进程内存暂存产物；发布时，在 Bot 控制库的同一个事务里写入群消息及该受众的 PNG 副本（最多 12 MiB）。群历史分页只读元数据，打开图片或另存时才通过正式群消息回执获取字节。工作线程删除后，已经发布的群图仍可读；撤回或删除群消息会清理相应副本。整个过程不会把图片放到群共享工作目录。

## 网关与执行

1. 部署端显式配置生图能力，区分 UAT 和生产环境，记录已验证的协议、部署标识、允许的尺寸和格式、返回方式、凭据引用、是否可按请求号查询及是否支持幂等。主进程解析可信配置和凭据，只向界面公开可用状态。现有模型目录的 `inputModalities` 继续表示输入。如果部署同时提供识图和生图，仍分别声明。未配置时显示原因，聊天/上传照常可用。
2. 首个适配器只实现部署端证实的一种实际协议。先取得网关契约及获授权的真实成功样例，覆盖鉴权、超时和交付格式。不能从聊天网关地址拼出生图地址，或复制聊天通道将模型改写为 pro/ultra 的逻辑。供应商支持异步任务时，保存任务号后轮询或恢复查询。无需为未上线的协议预建适配器。
3. 在主进程实现统一服务。工具 `generate_image` 只接受描述及部署支持的枚举选项。执行主体、当前用户回合、群工作归属、动作键、授权目标由宿主注入。普通聊天、私聊和群聊的前台主回合按授权启用，自主调度、内部委派、摘要和重放均不可隐式发起生成。显式 UI 入口与工具走相同的宿主校验。工具结果只返回状态和产物引用；识别失败、限流、服务拒绝等在当前消息上有可读反馈。
4. 宿主从本轮用户直接输入或显式入口取得生成授权，绑定原始消息、受众和一次操作。自然语言判断只使用该用户当轮直接指令，引用材料和工具输出不能产生授权；无法明确判定时展示“生成图片”动作让用户选择。工具注册和实际执行均校验回合来源。在 SQLite 中先占位提交，唯一约束处理点击竞态、重复 tool call、模型故障切换和流重放。普通/私聊的唯一键绑定会话实例、原始用户动作和槽位。群聊的唯一键绑定宿主、群实例、原始群消息和槽位，独立于各 Bot 的工作线程。显式指定单个 Bot 时由该 Bot 执行；多 Bot 同时被提及则由群调度选定一个承办 Bot，其他 Bot 跳过。首期要不同 Bot 各画一张需分别发起请求。
5. 保存本地动作 ID、环境、服务商、部署及配置版本、授权主体、远端请求号、提交阶段和产物引用。恢复只能以原部署和原主体查询，不保存密钥。缺少匹配配置时保持待确认。发出网络请求前持久化提交意图，只有明确未提交才能作为首次请求发送。连接中断或重启后只按网关契约查询；只有网关明确担保同键返回同一生成任务且仍在其有效期内，才可重放同键请求。否则显示“结果待确认”，不重新 POST 或切换供应商。用户可以明确另发一次，并获知前次任务可能仍在运行。取消立即显示“已停止等待”；仅有远端确认时显示“服务已取消”。取消、撤回或删除后的迟到结果无法取得发布权。

## 结果持久化与显示

- 图片字节只在主进程接收。流式限制响应字节，检查实际格式、尺寸、像素数和可解码性，仅接受部署批准的静态栅格格式。若部署只返回下载链接，主进程仅访问允许的 HTTPS 媒体来源，逐跳校验；下载不携带聊天网关凭据。临时链接不作为历史图片地址。日志只保存诊断必需的请求号、状态、耗时和字节数；不记录图像、签名链接、凭据和原始提示词。
- 用宿主管理的私有目录保存原图和缩略图，文件名由宿主生成。临时文件校验后原子改名，在动作记录中事务登记产物和待投递事件，再按动作 ID 幂等投影到消息存储。按原权限条件提交，恢复时重查事件、原消息及正式回执，处理跨库部分成功和孤立文件。已有原图可重建缩略图，有可重取的远端结果可恢复原图；同步只返回一次字节且落盘前失败时，显示“结果无法取回”或“结果待确认”。以上恢复路径均不得重新生图。会话、工作或群消息删除时撤销对应读取权，根据剩余合法引用回收。用户通过系统另存为对话框导出原图。
- 普通聊天和 Bot 私聊将产物挂到稳定的 assistant 消息/回复条目，支持只有图片的回复。工具调用 ID 用于关联事件，不能单独证明归属。新增受控 IPC 依当前窗口、会话实例、消息和有效产物回执核验，异步读取后再验证。读取历史图片不能赋予新任务或模型使用图片的权限。旧记录无需重写，纯文本、用户上传图和 DOCX 内嵌图沿用原表示。
- 处理临时 assistant 消息 ID 替换，以宿主回执将产物重绑定最终消息；仅图消息即使正文为空也参与持久化和渲染。分叉时只为已复制且允许继承的普通消息创建子会话自己的读取回执。Bot 工作与群受众授权均不随分叉复制。
- 应用内群聊先产生仅本工作可见的产物。给现有 `bot_deliver_files` 增加受限的生成产物引用，主进程校验当前工作回执并取得不可变文件快照，沿用既有审批/发布流程。正式群消息回执将产物关联到唯一群消息；没有公开回执时不在群里展示。为“原群动作 + 目标受众”建立唯一投递记录，发群成功但回执丢失时先查已发消息。已有结果的发布失败可单独重试，不再次请求生图。解绑、关联另一工作、关闭后重开仍以原始消息和有效受众为准。
- 复用现有图片画廊、灯箱和可见区域懒加载。消息元数据先提供宽高，避免图片加载将用户拉回最新回复。缩略图和原图分别读取；保存、放大和重试预览均不向生图服务发请求。

## 分阶段交付与验收

| 阶段 | 交付物 | 进入下一阶段的证据 |
| --- | --- | --- |
| 0 网关确认 | 目标出图服务契约、脱敏的最小调用结果、支持和不支持的操作 | 经授权的真实请求获得可解码图片，核对返回形式、错误及重复提交约定；若缺少真实服务则只可开发本地链路，功能默认关闭 |
| 1 服务与存储 | 能力配置、统一执行、持久动作与受控图片读取 | 契约测试及故障注入覆盖重复调用、超时、崩溃、取消、无权限、磁盘满、缺失文件、体积和像素上限，核对生成请求次数和产物数量 |
| 2 普通聊天和 Bot 私聊 | 自然语言和显式入口、回复内展示、重开、保存 | Electron 从 UI 发起，核对实际图像像素和原图尺寸；覆盖仅图/图文、流式重放、模型不支持工具、变更工作关联、跨窗口/会话隔离和滚动 |
| 3 应用内群聊与发布 | 成员身份、审批或交付回执、群消息展示 | 用两个 Bot 和两个群覆盖即刻交付、待审批、拒绝、交付失败重试、同名群、私聊委派；断言仅目标群收到一份结果，仅一次生图 |
| 4 回归与发布 | Windows Electron、Linux/Windows CI、真实模型验收证据 | 跑类型检查、lint、专项及全量测试，对照历史失败；保留原有识图、HTML 正文/表格、DOCX 图片和 Windows 符号链接用例。真实 UAT 在普通聊天、私聊和群聊分别按提示出图，人工核对描述、结果位置与重开，记录脱敏请求号、提交版本、受众及结论 |

真实验收可分别要求“白底红圆，圆右侧有蓝色方块”“黄底三棵绿色松树”“深蓝背景上一艘白色帆船”。本地固定图片用于断言 IPC、解码和像素；真实结果按颜色、对象和相对位置验收，同时核实网关确有该次请求。禁止用固定示例、Markdown 图片链接或模型声称已画好作为通过凭据。

评审要求补充下列回归用例。

- 在远端已受理未响应、同步图片返回未落盘、原图落盘未登记、回执登记未投递、群消息发出未确认五个位置中断。恢复后核对可见状态、调用计数、产物和消息数量。验证远端不支持查询、幂等有效期已过和切换同名部署/账号且远端任务号重号。
- 两个 Bot 在同群并发争用原始消息，验证只生成一次、只向目标群交付一次。覆盖拒绝公开、群消息撤回、重新绑定工作、删除后同 ID 重建、分叉、流式消息 ID 替换，以及图片读取期间撤权。
- 校验不同轮次同尺寸不同像素的图，排除占位图误判；验证预览失败再试和保存原图均不会增加生图请求。日志、checkpoint、工具结果与 IPC 广播不得含裸 `b64_json`、签名 URL 或鉴权头，只有经授权的媒体读取 IPC 可返回图片字节。
- 把用例加入 Windows 专项测试白名单及 Electron 工作流，手动对开发分支执行 `workflow_dispatch`，核对 run 的 `head_sha` 和各 job 结果。真实模型验收与 CI 固定响应分别记录。
