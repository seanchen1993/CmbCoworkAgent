# Design 页面直接编辑实现计划

日期：2026-10-29。状态：已实现，详见 [执行清单](./2026-10-29-design-direct-edit-execution.md) 和 [实现说明](../design-direct-edit.md)。

目标：页面生成后，用户可以双击修改文字，选中并删除深层元素或整个区块，撤销/重做；修改保存到正式源码，重新打开、导出和下一轮 AI 修改均使用修改后的版本。

## 1. 推荐方案

在现有 HTML 预览上增加**宿主控制的直接编辑层**，使用稳定节点 ID 和明确的编辑命令，由主进程修改已保存源码，并复用现有事务、文件投影与预览更新机制。

直接修改文字和删除元素不调用模型，也不启动完整生成。保留现有 HTML 产物格式。

首个可交付版本覆盖默认生成的静态 HTML、可定位源码的导入 HTML，以及 A/B 方案中的指定方案。React/Vue 动态内容单独通过绑定或源码映射适配，见第 9 节。

当前具体缺口：

- 编辑脚本没有 `dblclick` 处理或文字编辑器。
- 没有元素删除命令；`replace_fragment` 替换的是目标内部内容，且保护逻辑禁止删除业务标识等，不能直接充当删除节点。
- 选区用临时 `data-ed-id`，与主进程已有的 `data-design-node` 不统一。
- `__edit_html` 会序列化运行中的整页 DOM，再走保存逻辑；这会混入运行状态、预览处理过的资源和编辑装饰。
- 通用 `session.patch({html})` 会推进版本并失效已有局部撤销历史，不能作为新编辑器的主要提交接口。

### 借鉴 Workbuddy 的内容

参考 `/Users/liuxuyang/Downloads/workbuddy-design/skills/ardot-design-core/tool-usage/batch-edit.md`：

- `U(nodeId, {content})`：明确定位节点，只修改指定内容。
- `D(nodeId)`：删除指定节点及子树。
- 一批修改原子执行，失败回滚；普通编辑不需要重新生成页面。

本地 Workbuddy 材料描述的是画布操作协议，不包含编辑器双击事件的实现源码。本计划借鉴其节点寻址、操作语义和事务机制，并适配本项目 HTML 架构。

## 3. 用户交互

### 3.1 模式入口

- 顶部明确展示“预览 / 编辑 / 批注 / 绘制”。“编辑”不依赖“微调”开关。
- 新页面完成后建议默认进入编辑模式，并提示“单击选中，双击改文字，Delete 删除”；用户可以切换到预览测试业务交互。
- 重开已有会话时恢复上次模式；草稿生成期间仍为只读，不开放文字和结构直接编辑。
- 编辑模式拦截页面点击、双击和提交动作；预览模式按现有交互预览策略工作。
- 统一事件所有权，移除互相竞争的旧选区处理器。文本输入框、编辑浮层、属性面板和快捷键各自有明确作用范围。

### 3.2 修改文字

1. 双击标题、段落、按钮文字等，定位具体文字槽。
2. 在文字位置打开宿主所有的输入浮层，匹配当前字号、字体、颜色和宽度；不将整个容器设置为富文本编辑区。
3. 支持中文输入法、选择、剪贴板纯文本粘贴。
4. Enter 提交，Esc 取消，点击其他位置提交。明确支持多行的文字槽允许 Shift+Enter 换行；普通文本不自动产生浏览器自带的 `div/br` 结构。
5. 一次编辑会话形成一个撤销步骤，不按每次按键保存。
6. 提交中显示状态；失败保留输入内容并可重试，正式页面仍为已提交版本。

输入开始前保存 `sessionId + previewInstanceId + artifactRevision + nodeId + textSlotId`。提交时目标已变化则拒绝旧内容覆盖，保留用户文字并要求重新定位。

### 3.3 选择深层元素

- 单击选中命中的最内层可编辑节点；悬停虚线，选中实线。
- 展示简短层级路径，例如“主区域 / 指标卡 / 标题”，点击路径可切换到父容器。
- 浮动工具条提供“选父级、编辑文字、删除”；属性面板显示当前选择的标签、文字摘要和能力。
- 将不具备源码映射的 SVG 内部形状、伪元素、Canvas 绘制内容等，提升到有意义的可编辑父节点，或明确显示当前支持范围。
- 缩放、iframe 内滚动和外层滚动后，选框与工具条仍跟随实际元素。

### 3.4 删除

- 选中节点后按 Delete/Backspace，或点击浮动工具条的删除，删除该节点与子树。
- 正在输入文字时，Delete/Backspace 只处理字符；焦点在属性输入框、聊天框或业务输入框时不触发元素删除。
- 删除前高亮完整范围；工具条显示“删除标题 / 删除整张卡片”等目标说明。常规删除直接执行并可撤销。
- 删除子项后选中仍存在的父节点或相邻节点，避免选区指向失效 ID。
- 用户可通过层级路径选择并删除嵌套模块，不需要在聊天中描述位置。
- `html/head/body`、宿主运行层、协议声明和执行脚本不作为普通可删节点。

## 4. 核心链路与协议

```text
iframe 编辑层：选中 / 双击 / 输入 / 删除
    ↓ 目标 ID、文字槽和编辑意图
宿主编辑控制器：会话、预览实例、命令队列
    ↓ 类型化命令
主进程：读取正式源码 → 解析目标 → 应用操作 → 校验候选
    ↓
SQLite：源码 + Tweaks + journal + 命令回执 + outbox 同事务
    ↓
文件投影 / 会话快照 → 预览增量更新或一次重建 → ACK
```

建议新增独立协议 `design-edit/1`，与模型的 `design-patch/1` 区分：

```ts
interface DesignEditCommand {
  protocol: "design-edit/1"
  commandId: string
  baseRevision: number
  variationId: string | null
  operations: Array<
    | { type: "set_text"; nodeId: string; textSlotId: string;
        expectedHash: string; value: string }
    | { type: "delete_node"; nodeId: string; expectedHash: string }
    | { type: "set_style"; nodeId: string; expectedHash: string;
        declarations: Record<string, string> }
  >
}
```

建议提供 `sessions.inspectEditable()` 和 `sessions.edit()` 接口。inspect 返回宿主核定的节点能力、文字槽、hash、父级和绑定信息；edit 返回命令结果、最新快照和预览更新描述。

- 会话 ID 由宿主当前会话上下文补入；不接受 iframe 指定文件路径或正式 HTML。
- 主进程重新解析目标、核对版本、hash、方案范围及操作能力；不信任渲染层传来的源码偏移。
- iframe 消息校验来源窗口、消息结构、预览实例和版本，避免旧页面消息落入新会话。这些字段用于隔离和校验，不视为页面脚本不可伪造的授权凭据。
- 同一会话串行处理编辑；与生成、AI 补丁、撤销/重做共享修改互斥机制。校验结束后提交前再次核对状态。
- `commandId` 持久化幂等回执，同一命令重试不重复修改；历史已变化时返回当前快照及原命令结果，不能回灌旧快照。

## 5. 源码编辑

### 5.1 稳定身份

复用 `data-design-node`，逐步替换 `data-ed-id`。

当前没有显式 ID 的节点按树路径计算身份，删除前面的兄弟节点可能改变后续节点 ID。必须先解决这个问题：

- 新产物定稿/导入完成时，为可编辑源码节点补齐显式 ID。
- 老产物首次进入新版编辑器时，按现有映射补齐 ID，作为一次版本化初始化；重建选区和索引，旧版本锚点失效。
- 初始化只插入必要属性，不重新序列化整个文档，不改写脚本；不作为用户的一次文案修改撤销项。
- 新增节点分配新 ID，存活节点保留原 ID；不能在每次打开或预览更新时重新编号。

### 5.2 文字槽

不能直接对按钮或卡片整体设置 `textContent`，否则会丢失图标和嵌套结构。

- 纯文字叶子：定位其源码文字范围，做转义后的文本替换。
- `<button><svg>…</svg>保存</button>`：只修改“保存”所在文字槽，保留 SVG、事件和按钮属性。
- 嵌套 `<span>/<strong>/<em>`：各文本段单独有槽；首版按命中的文本段编辑，不把格式化段落整体拍平。
- 只有与源码能够唯一对应的文字才开放直接编辑。运行时计算或拼接的内容走声明式绑定或框架适配。
- 空值是合法文案修改；空文案不会自动删除父容器。
- 对应的 textarea/placeholder 属性编辑与普通可见文字分开处理；真实 input 的当前值不能直接当成设计文案写入源码。

使用 parse5 的源码位置和已有索引，按位置从后向前应用编辑；除身份初始化和实际涉及的声明外，目标外源码保持原字节。

### 5.3 节点删除

新增独立 `delete_node` 应用逻辑，删除完整源码范围，保留其余节点与共享 CSS。

- 不通过 `replace_fragment("")` 间接删除父容器内容。
- 同批父子重复删除合并；存在歧义或其他冲突操作则整批拒绝。
- 检查目标子树是否含执行代码、外部必需引用、表单关系或已知脚本绑定。普通静态内容可直接删。
- 对可验证的结构变化做隐藏浏览器运行与布局检查；发现新增运行错误则不提交。
- 无法保持行为契约的节点，显示具体原因，并提供转交 AI 结构改稿的入口；不将临时 `display:none` 当成删除完成。
- 删除一个 A/B 方案中的节点只影响该方案；始终基于完整规范源码提交，不能回收当前分屏预览 HTML 作为整份产物。

静态分析和有限浏览器检查不能证明任意脚本的全部行为。未具备可靠映射的动态区域按能力判断处理，不承诺任意网页节点均可直接删除。

### 5.4 Tweaks 同步

直接编辑必须与现有声明式参数共存，否则重进页面或重新应用参数时会把文案改回去。

- 文案唯一绑定到一个参数：直接更新对应参数值，并按 schema 验证。
- 一个参数控制多个位置：默认仅修改选中位置，通过拆分该位置的绑定实现；明确选择“应用到所有绑定”才修改共享参数。
- 删除节点时清理仅指向被删子树的绑定；还有存活绑定的参数继续保留。相关默认值、覆盖值和绑定变化与源码一同记入事务和撤销记录。
- 允许修改经过核定的惰性 Tweaks JSON 声明，执行脚本保持原字节。现有脚本保护需区分协议声明和执行脚本，不能为此整体放开模型补丁权限。

## 6. 提交、历史与保存

复用 `DesignRunManager` 的提交入口、`DesignPatchJournal` 和 outbox，抽出 AI 补丁与直接编辑共用的提交方法。

- 一次文字提交、一次删除、一次属性拖动结束各形成一个事务。
- journal 增加来源信息，例如 `user-direct / ai-patch`，支持按实际发生顺序撤销和重做；用户直接编辑不会再清空整条局部历史。
- 新编辑发生后使 redo 分支失效；删除后可恢复完整子树、节点 ID、参数和方案范围。
- SQLite 为正式状态来源；文件写入失败由现有 outbox 重试，状态区区分“已保存到会话”和“文件同步待重试”。
- 导出、开始下一轮 AI 修改、切换会话前，等待当前文字提交和保存队列完成。现有同步式 `flushArtifactEdits()` 需要升级为可等待的 Promise 屏障。
- 队列失败时保留未提交文字，明确提供重试或放弃；不得丢掉失败后又悄悄开始生成。
- 旧 `__edit_html` 保留为明确隔离的兼容入口，完成迁移后停用；新文字、删除和样式操作全部走命令通道。

## 7. 预览更新

- 文字和样式：扩展现有 live delta，对明确文字槽更新，保留节点、监听器、焦点和滚动。
- 首版结构删除可以在候选验证通过后重建一次预览，恢复滚动与合理选区，优先保证源码和运行状态一致。
- 第二步增加受控 remove delta：预检全部目标与父子关系后统一删除，任一目标不匹配则整页重同步，不能半批成功。
- 删除的撤销涉及重新创建节点和事件绑定，默认从正式源码重建预览；不能只插回 DOM 就声称事件已恢复。
- 沿用预览实例、基线版本、递增版本和 ACK；丢 ACK 时从最新已提交版本恢复。
- 编辑浮层、选框、临时属性和辅助样式属于宿主运行层，导出和正式源码不包含这些内容。
- 更新到达正在输入的文字槽时，冻结提交并保留输入，提示目标版本变化；不在用户输入中途替换编辑目标。

## 8. 样式面板与选区控制器整合

将当前内嵌 `EDIT_SELECT_INJECT` 拆成可测试的宿主运行模块，与 `DesignView` 分离：

- 运行层负责命中、悬停、双击、键盘、输入浮层和清理。
- 宿主控制器负责选区描述、层级导航、队列、命令结果和保存状态。
- `ElementPropsPanel` 继续承担属性编辑，增加文案和删除入口，使用相同 `nodeId`。
- 属性实时拖动可在本地显示暂态效果，结束后通过 `set_style` 提交一次；失败恢复已提交值。
- 切模式、切方案、iframe 重建、组件卸载时清理监听器和浮层，避免重复提交。

## 9. React/Vue 和动态模板

当前框架模板走完整源码修改，是为了避免 DOM 修改被组件重绘覆盖。新版直接编辑必须保留该边界，并增加实际适配能力：

1. **受控/新生成模板**：声明可编辑文案、列表条目和模块配置，建立“运行节点 → 参数或数据记录”的映射。更新源数据后由组件正常重绘；删除列表项或模块删除对应配置记录。
2. **可映射的 JSX/Vue 源码**：定位文字字面量、组件属性或完整组件节点；在原始源码做限定范围 AST 修改，经过编译及浏览器校验后加载。
3. **重复组件**：区分实例内容和共享定义。选中一行不能把所有行一起改；必须有记录 ID 或实例级数据绑定才能执行单项修改。
4. **任意导入的运行时 DOM**：没有可靠映射时显示受限能力，并允许用户通过现有 AI 改稿修改源码；不保存运行时 DOM 快照伪装成持久编辑。

静态 HTML 的首版上线后，按真实模板使用量增加框架适配。框架适配阶段单独验收“重绘后仍保留、重开仍保留、导出仍保留”，不以 DOM 当时变化作为通过依据。

## 11. 分阶段实施与验收

| 阶段 | 交付内容 | 验收门槛 |
| --- | --- | --- |
| M1：完整最小闭环 | 独立编辑模式、稳定 ID、叶子文字编辑、静态节点删除、主进程提交、撤销/重做、保存/导出一致性 | 改标题、删卡片后，重开、导出和下一轮 AI 修改都保留；直接操作模型调用为零。 |
| M2：深层与复杂文字 | 层级选区、带图标按钮的文字槽、中文输入、共享 Tweaks 拆分、属性面板统一提交 | 不丢图标和事件，不误改其他位置，50%/100%/150% 缩放下可操作。 |
| M3：预览与旧链路收敛 | 可验证静态删除的 remove delta、并发/保存错误恢复、旧 `__edit_html` 迁移 | 不串会话、不丢修改，普通文字修改不重载，删除撤销后交互正常。 |
| M4：框架模板适配 | 优先支持常用受控 React/Vue 模板的文案和模块数据绑定，再做源码映射 | 修改经过组件重绘、重开和导出后仍有效；不误改重复组件的其他实例。 |

M1–M3 是默认 HTML 页面的完整交付范围，M4 是框架模板的扩展范围。第一轮不扩展到任意拖拽排版或完整画布引擎。

## 12. 必须覆盖的测试

### 源码与事务测试

- 修改中文、特殊字符、空字符串；不注入 HTML，保留无关源码字节。
- 带图标按钮只改文字；复杂格式文本只修改选定槽。
- 删除嵌套子树、父子重复选择、方案隔离；删除兄弟节点后其他节点身份不漂移。
- Tweaks 单点/共享绑定修改、删除后绑定清理，撤销恢复 defaults/overrides/bindings。
- 版本冲突、重复命令、事务失败、文件投影失败与重启恢复。
- 用户直接修改与 AI 补丁交替发生后的撤销/重做顺序。

### 浏览器测试

- 通过真实双击、键盘和工具条完成改文字与删除，不只直接调用处理函数。
- 输入状态下 Backspace/Delete 不删节点；Esc 取消；提交与失焦不重复保存。
- 中文 composition 期间 Enter 不提前提交；自动化覆盖事件序列，并补一次真实中文输入法手测。
- 编辑模式点击按钮不触发业务动作，预览模式交互仍正常。
- 缩放、滚动、切方案、切会话、旧 iframe 迟到消息和生成期间禁止编辑。
- 保存后重新打开、导出 HTML/ZIP，并让下一轮 AI 读取修改后的源快照。
- React/Vue 适配额外测试重绘及重复实例隔离。

复用并扩展已有 `patch-lifecycle.test.ts`、会话测试与真实 React/Chromium fixture；新增直接编辑的源码和浏览器用例。相关验证命令：

```sh
npm run typecheck
npm run test:design-sessions
npm run test:design-html
npm run test:design-templates
npm run build
```

## 13. 演示验收脚本

1. 生成包含标题、图标按钮、三张卡片和折叠区的页面。
2. 双击标题改为中文新文案；双击图标按钮只改标签。
3. 单击卡片内文字，通过层级路径选中整张卡片并删除。
4. 撤销、重做，确认选区、其他卡片和按钮交互正常。
5. 切换预览，验证折叠等业务交互。
6. 关闭再打开，导出 HTML/ZIP，确认结果一致且无编辑装饰。
7. 对剩余内容继续提出 AI 修改，确认新文案与删除结果继续保留。

实现和验证结果已记录到执行清单。实际框架支持范围、交互行为和运行命令以实现说明为准。
