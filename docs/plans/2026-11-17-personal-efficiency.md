# 个人研发效能看板实施计划

**目标：** 在研发效能页面增加个人指标、带权排名和个人详情。

**实现方式：** 复用现有项目事实、精益非测试项目识别、采纳聚合、权限和工作日日历。个人查询、排名计算和详情组件分别放在新文件，保留当前工作区已有改动。

## 已确认口径

- 项目通过 `pm` 的姓名/sapId 归个人；按项目 `roomName` 和开发完成/立项日期筛选。
- 代码归本人，不限本人负责的项目；限定精益非测试项目，按生成时间及事件组织筛选。
- 人员为周期内有 PM 项目或合格个人代码记录的并集。
- 项目指标包括去重特性数、累计功能点、缺陷数、非功能问题数、缺陷密度及审批到开发完成平均工作日。
- 权重范围 -100 到 100，直接按原值加权求和，不转换为相对得分。负权重使该项数值越大的人员扣分越多。
- 权重为零不参与；需要的值缺失时不计算综合分；全部为零不排名。
- 自然月增加 IDE、CLI、DevClaw、累计 AI 入库、总 Push 和 AI 代码入库占比；各渠道入库占比和月度行数均进入排名权重配置。
- 个人月度事实保存在 `devclaw_gitee_push_info`，`orgLevel=user`，DevClaw 从遥测取得。

## 实施步骤

1. 新增共享个人指标契约与纯函数权重计算；测试负权重、缺失和全零权重。
2. 项目事实读取增加 pm；复用筛选和日历，查询并按 sapId 聚合项目、代码及个人月度数据。
3. 接入 dashboard IPC 和 preload 类型，沿用现有读取权限。
4. 增加个人列表、权重配置、搜索分页和个人详情；共享现有日期口径选择。
5. 补充内网个人月度写入契约，注明分母和渠道缺失规则。
6. 运行相关 Vitest、主进程/渲染层类型检查，只对本次修改文件运行 lint；不进行浏览器自动化或截图验证。

## 月度及加权口径

用户确认沿用已有累计 AI 入库代码占比（硅碳比）：个人 IDE、CLI、DevClaw 入库行数之和除以个人全部 Push 行数。百分比加权使用页面百分数，例如 80% 按 80 计算。

## 完成情况

客户端已实现个人列表、原值加权、指标排序、搜索分页及按需读取的个人详情，接入项目 PM、个人代码和自然月渠道数据。项目特性名称沿用统一读取逻辑，仅详情查询补充名称。

已通过 68 项相关测试、主进程及渲染层类型检查；只对本次修改涉及文件运行 lint，无错误，保留已有文件中无关的格式警告。未进行浏览器自动化或截图验证，尚未完成内网真实 ES 联调。

内网 Java 的个人月度写入接口仍需实施，字段及验收要求见[个人自然月代码入库数据契约](2026-11-17-personal-monthly-code-contract.md)。


## 组织与个人视图拆分

研发效能内部使用“组织效能”“个人使用”两个视图，顶部日期范围和“室筛选”保持共用，项目日期口径上移到两个视图共用的工具栏。

- 组织效能保留组织概览、自然月入库情况、项目趋势、项目对比、项目详情，以及采纳率和算力分析。
- 个人使用只显示个人指标、加权排名和人员详情；人员详情内保留负责项目与本人代码。
- 项目按 roomName、代码按 upperOrgLv1、个人月度记录按 roomName 筛选；不改变人员范围和权限，也不改筛选名称。
- 首次进入个人视图时再挂载个人区域；切换视图保留项目筛选、个人搜索和权重。
- 将日期选择器拆到新文件，ProjectMetricsSection 接收共用日期口径，移除内嵌个人区域。仅运行渲染层类型检查与修改文件 lint，不进行界面自动化。


拆分已完成：共用项目日期选择器，组织与个人区域分别展示，个人区域首次访问后保留挂载以保存搜索和权重。组织层级继续使用 upperOrgLv1 对应室、upperOrgLv2 对应团队。


## 个人明细与独立导出

人员详情仅保留“作为 PM 负责的项目明细”和“本人 DevClaw 项目代码明细”。列表中的汇总指标、计算说明和自然月渠道统计不在详情重复展示。

列表与权重配置统一使用“平均缺陷密度”“特性审批完成到开发完成耗时”，表头不附加单位后缀。个人项目数量、功能点和问题数量仍按累计口径，名称不改为平均值。

权重配置使用独立弹窗，按项目与代码指标、自然月指标排列数值输入框；保留恢复默认、取消和应用按钮，删除长段计算说明。

个人使用页通过“导出个人效能明细”提供独立 Excel 导出，按当前人员搜索、排序和权重导出全部匹配人员，包含个人指标、负责项目与本人代码三张工作表。人员详情提供当前人员两类明细导出。两种个人导出均与组织效能导出分开，复用现有保存工作簿能力。


## 完整月份区间展示

单个完整自然月或连续完整月份区间（包括季度）可展示月度指标；行数逐月相加，占比使用累计分子和累计分母重算。任一月份缺失时，不把已有月份冒充整个区间。组织效能和个人使用的页面与 Excel 使用相同规则。

包含不完整月份的区间，个人列表、权重配置和 Excel 隐藏月度专属指标；保存的月度权重保留，但不参与该区间排名。若此前按月度列排序，当前回退综合排名。

个人统计口径说明移入“个人使用情况”标题右侧 Tips，显示支持统计的自然月或完整月份范围。


最新验证覆盖完整季度累计、月份缺失、重复填报、非完整区间隐藏、隐藏指标不参与排名，以及组织 Excel 依据与公式复算。主进程与渲染层类型检查、修改文件的定向 lint 均无错误。个人月度写入仍需要内网按数据契约提供；尚未进行真实 ES 联调。


## 代码明细分行与室筛选核对

同一人员、同一室中的多个 Harness 项目可以绑定同一精益项目。代码明细保留各 Harness 项目的行，个人汇总将已 Push 采纳行数和对应有效生成行数分别相加，再计算入库率。仅因精益项目编号相同而分成多行，不会额外重复计数；PM 项目指标、月度累计和排名不受分行影响。已补充分行与合并输入产生相同汇总结果的回归测试，暂不调整明细粒度。

个人代码查询和组织代码概览统一复用已有室列表过滤函数，“未归类”匹配 upperOrgLv1 缺失、空字符串和采集占位值；混合选择真实室与未归类时按 OR 处理。空权限范围继续返回空结果。相关定向验证共 31 项测试通过。
