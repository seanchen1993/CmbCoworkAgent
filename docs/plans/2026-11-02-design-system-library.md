# design.md 设计系统库改造方案

## 目标和入口

- 新建设计：工作目录下方保留“设计系统”区域，以“选择 / 更换设计系统”打开统一选择窗口，展示名称、内置或我的来源和版本，支持不使用规范。
- 设计历史：右上角新增“设计系统库”，在不创建设计时管理规范。
- 编辑器：点击顶部设计系统标签，查看本次设计固定使用的规范和版本。
- 统一窗口：系统内置 / 我的双标签；左侧列表，右侧规范预览；顶部提供“上传 design.md”“从网页提取”。

## 用户流程

1. 上传：选择或拖入 .md → 校验格式和大小 → 修改名称和 Markdown、预览 → 保存到我的 / 保存并用于本次设计。
2. 提取：输入 HTTP(S) 链接，或使用内置浏览器当前页 → 读取真实页面计算样式 → 生成 design.md 草稿 → 在线修改或下载、本地修改后重新上传 → 保存到我的。需要登录时打开内置浏览器，完成登录并确认目标页面后重试。
3. 内置规范只读，可复制到我的并编辑；我的规范可编辑、上传新版本。新增上传始终创建新条目，不按同名文件自动覆盖。
4. 保存与选用分开；只有“用于本次设计”或“保存并用于本次设计”更新创建页的选择。取消导入不写入库。

## 数据和兼容

- 增加共享设计系统类型与 IPC API；沿用现有内置目录加载器、设计提示词与会话的 selectedDesignSystemId。
- 我的规范保存在应用用户数据的 design-system-library 中，不依赖工作目录或上传文件的原位置。
- 每次保存生成不可变版本 ID；旧 ID 始终读取原 Markdown。创建列表只展示最新版本，历史会话仍能解析旧版本及名称。
- 内置 / 我的由 ownership 区分，原 source、category 继续作为来源及分类信息，避免将来源网址当作所有权。
- 上传同时支持 DESIGN.md / design.md 及其他 .md 文件；限制为 1 MB，拒绝空内容、二进制内容和无效名称。主进程校验所有写入参数，保存采用临时目录加原子重命名，并对陈旧版本编辑给出冲突提示。

## 网页提取

- 复用 captureDesignPage 的隔离浏览器、登录态、渲染等待、访问限制识别和清理能力。
- 提取可见元素的计算样式：色彩、字体字号、间距、圆角、阴影及代表性组件；生成可编辑的事实型 Markdown，未观察到的规范明确标注待补充。
- 此流程只生成规范草稿，不创建页面设计、不下载页面资源、不调用模型。保留经过脱敏的来源 URL。
- 提供分阶段进度、取消、超时和窗口销毁清理；取消或关闭后迟到结果不得改变界面或保存文件。

## 实施顺序和验证

1. 共享协议、个人规范存储与不可变版本解析。
2. 网页样式提取、IPC 与 preload API。
3. 设计系统库窗口和三个入口，接通编辑、上传、下载和重新上传。
4. 存储及冲突测试、提取测试、真实浏览器交互验证、前后端类型检查与构建。测试覆盖重启持久化、旧版本不变、内置复制、文件替换、提取取消和受限页面、保存与选用分离。

## 实施结果

以上步骤已完成。新增 `npm run test:design-systems`，包含存储及 IPC 测试和真实浏览器流程；浏览器测试同时验证创建页、历史页入口、内置复制、上传及重新上传、下载、保存与选用分离、v1/v2 隔离、取消后忽略迟到结果、内置浏览器登录受限重试，以及真实页面计算样式的提取。

相关回归测试共 15 项通过，前后端类型检查、构建和新增代码静态检查通过。网页提取产物为基于当前页面样式的初稿，响应式规则和交互状态需要用户补充。
