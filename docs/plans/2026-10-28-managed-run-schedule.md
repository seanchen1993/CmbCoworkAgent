# 托管预约启动实施方案

目标：用户预先预约托管，应用到点后复用现有启动流程。

1. 在现有主数据库的 `managed_run_schedules` 表集中保存预约，复用 SQLite 连接、数据库初始化和 WAL 持久化。原有实际托管运行快照与事件保持现状。预约仅使用数据库存储。每个 Feature 最多一条预约，时间格式为 `YYYY-MM-DD HH:mm:ss`。
2. 复用现有调度器的每分钟检查入口，按状态与预约时间索引查询到点任务，不创建独立计时器。主进程负责启动、取消和修改时间。重启后未到点的预约继续等待，已过点的预约标记错过；运行期间休眠恢复后补启动。启动前持久化正在启动状态，重启时不重复执行。
3. 开始时间放在招乎管理选项下方，使用与会话来源一致的单选样式。默认立即开始，预约默认下一次 22:00。预约提示支持修改时间、退出托管模式。
4. 预约启动跳过 Feature 下其他运行会话的检查，保留已有托管运行检查和指定现有会话的空闲检查。立即启动仍使用原有检查。
5. 验证时间转换、持久化、到点执行、取消、修改、重启、重复启动与启动失败。只对修改文件执行 lint，不使用浏览器或截图验证。
