# 知识库配置服务端实施计划

**目标：** 在企业内网现有服务实现组织过滤后的知识库配置查询接口，交付可与 APP 联调的完整结果。

**架构：** Controller 接收身份字段，服务层读取并校验配置、完成组织匹配，响应 DTO 显式映射允许字段。复用目标服务的数据访问、认证、异常处理与测试设施，不新建服务或引入缓存、队列。

**技术栈：** 以企业内网现有工程为准；MySQL 5.7 兼容 SQL、JSON HTTP 接口。

**执行依据：** [接口定义](../knowledge-cloud-config-server-api.md)、[目标 DDL](../knowledge-cloud-config-mysql57.sql)、[总体设计](../knowledge-cloud-config-api-design.md)。按本计划逐项实施，遵守目标仓库的 AGENTS.md。当前仓库不含服务端工程，不虚构 Java 包名、框架或构建命令。

## 任务 1：确认工程入口和数据库现状

1. 阅读目标工程工作约定，定位现有 `/devclaw` Controller、业务响应封装、数据库访问、认证和定向测试入口。
2. 只读检查 `devclaw_knowledge_config` 是否存在、字段和索引是否符合目标 DDL，确认当前数据库 session 时区和 SQL mode。
3. 检查同名不同分支以及数据库排序规则视为同名的记录，记录结果；不得自动改名、删数据或改表。
4. 若需处理已有表和数据，先提交具体调整清单取得负责人确认。未获确认前继续独立的接口与单元测试开发，不依赖擅自改表。

交付：实际拟修改文件清单、工程测试命令、数据库差异及待确认事项。

## 任务 2：请求和响应 DTO

1. 定义 POST 请求的 `sapId`、`pathName`、`originPathId` 三个必填字符串字段，允许空字符串，拒绝缺失或错误类型。
2. 定义 `{code,message,data}` 响应，成功 data 只有 items；失败 data 为 null。
3. 逐项定义接口文档中的返回白名单，禁止直接返回实体或使用 SELECT * 后透传。
4. 添加请求边界和序列化测试，确认空列表、sshUrl=null、customConfig 字符串、GMT+8 日期格式及禁止列不会泄露。

验收：POST 正常解析，字段类型错误得到 40001，日期无 T，响应不存在 enableOrg 或 devopsKey。

## 任务 3：配置读取、校验和组织匹配

1. 查询所需数据库列。`enable_org` 仅供服务端匹配，不进入响应 DTO；无需读取 devops_key。
2. 将 enable_org 解析、校验和匹配实现为小型可测试函数，按完整路径段匹配并去重；空路径只匹配全局库。
3. 实现输出字段校验；名称不 trim、不自动修复，非法配置返回 50002。
4. 按 idKey 形成唯一完整结果，可按 id_key 升序稳定返回；不分页、不截断、不以跳过坏记录的方式成功返回。
5. Git 参数只校验格式，不执行 Git、不访问仓库。

验收：同仓库不同分支两条记录可同时返回；组织过滤只在服务端，APP 不需要 enableOrg。

## 任务 4：路由、错误和日志

1. 接入 `POST /devclaw/knowledge-config/query`，复用现有企业认证和数据访问方式。
2. 业务结果使用 HTTP 200，映射 40001、50001、50002；认证和网关错误沿用工程约定。
3. 读取异常不能返回 code=200/items=[]；配置不合法不能返回部分成功结果。
4. 响应超限复用工程已有限制；不存在既有应用层限制时，不自行添加分页或任意截断，先记录网关限制供联调确认。
5. 日志记录必要的错误定位信息，不打印 DevOps 凭据、完整身份文件、令牌或其他组织配置。

## 任务 5：定向验证

使用目标工程测试命令，仅执行与改动相关的测试。至少覆盖：

| 用例 | 预期 |
| --- | --- |
| 空表、没有组织匹配项 | 200，items=[] |
| 全局库、a组库、其他组织库并存 | 只返回全局与 a组 |
| a组 与 aa组 | 不发生子串误匹配 |
| pathName 多余分隔符和段首尾空白 | 按完整有效段匹配 |
| pathName 为空 | 只返回全局库 |
| 同记录命中多个组织名 | 只返回一次 |
| 缺字段、null、数字、数组请求 | 40001 |
| enable_org 非法或匹配记录非法 | 50002，data=null |
| 数据库不可用 | 50001，不能返回成功空表 |
| name 有首尾空白 | 50002，数据库和返回名称不被自动修正 |
| 两个分支使用同名（含大小写差异） | UNIQUE(name) 拒绝，在隔离测试数据中验证 |
| 同仓库不同分支使用不同 ID 和名称 | 可同时配置和返回 |
| 数据库含 devops_key 等内部列 | 响应字段严格符合白名单 |
| DATETIME 为 2026-10-21 10:00:00 | 原 GMT+8 时间输出，不增加 T 或二次时区偏移 |
| 响应超过服务已有限制 | 50002，不返回部分结果 |

不执行全项目格式化或 lint --fix；如需 lint，仅针对本次修改文件。

## 任务 6：交付给 APP 开发方

1. 提供实际部署环境的接口地址、已有认证接入方法和脱敏请求示例。
2. 提供成功、空结果、非法请求、读取失败、配置错误的响应样例和测试结果。
3. 说明组织匹配函数位置，便于未来只调整服务端规则。
4. 提供数据库现状及经确认的变更结果；未确认项明确列出，不能声称已完成迁移。
5. 联调确认 APP 不再本地过滤，服务端成功空结果能使本地历史记录变为“当前不可见”。

服务端工作不包括 APP 双目录、知识沉淀、插件命令、客户端状态迁移或 UI 修改。不要为这些能力增加服务端接口。
