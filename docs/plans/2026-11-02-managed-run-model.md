# 托管运行模型选择实施方案

**目标：** 立即托管与预约托管支持选择默认模型或内置 Ultra，预约创建后可以修改时间和模型。

**设计：** 模型选择保存到预约和托管运行记录。默认选项完全沿用现有会话模型与路由行为；Ultra 选项仅在本次托管执行时固定到 `builtin:idle-ultra`，不修改全局默认模型或已有会话保存的模型。复用公共执行路由入口覆盖启动、续跑、重试与审批恢复，禁止切换到其他模型。

**已有数据：** 经用户确认，缺少模型字段的预约与运行记录继续按默认模型处理。SQLite 新增默认值为 `default` 的字段，运行记录使用可选字段。

## 实施步骤

1. 新增共享模型选项类型和可复用选择组件，在托管启动弹窗传递模型选项。
2. 预约 SQLite 保存模型选项，沿用原更新接口和正在启动时禁止编辑的规则。预约卡片显示模型，“修改预约”弹窗同时修改时间和模型。
3. 托管运行记录保存选项；执行时依据会话关联的运行记录固定 Ultra，并校验可用配置。托管结束后恢复原有模型选择行为。
4. 增加预约持久化、旧数据迁移、运行记录、默认行为、Ultra 执行与恢复的相关测试；运行相关测试、类型检查及仅修改文件的 lint。不进行浏览器或截图验证。

**技术栈：** TypeScript、React、Electron IPC、SQLite、Vitest。

## 托管弹窗展示调整

经用户确认，常用字段改为标签与控件对齐的紧凑表单，去掉各字段重复的卡片边框。会话来源、模型和开始时间复用同一个单选组件，采用主题色细边框与中心圆点，保留原生单选的键盘行为。

模型选项横向展示为“默认模型”和“内置 Ultra”，附夜间标记；默认模型的详细说明放入提示，选择 Ultra 后展示服务时间。修改预约弹窗复用相同组件。

“通过招乎控制托管”以名称和开关一行显示；统一机器人未连接时禁止开启，原因通过开关区域的悬停或键盘焦点提示展示。初始用户消息直接展示输入框。现有选择、校验与提交逻辑保持不变。
