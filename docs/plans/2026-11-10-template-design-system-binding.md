# 模板关联设计系统：保留现有页面的最小改动方案

状态：已按用户确认的最小改动方案实现，保留现有页面样式和入口。

## 1. 页面与入口

沿用当前新建设计页、模板卡片样式、上传区域和全部既有入口。

- “选择模板 / 上传模板 / 不选模板”继续保留在模板区域原位置。
- 原型设计导航不展示需求列表的全局系统筛选。模板上下文来自新建页所选设计系统或当前设计会话绑定的设计系统，独立于需求列表的筛选状态。
- 上传模板继续是新建设计流程内的原有功能，不与“新建设计”并列。
- 按最新交互要求，在原“选择模板”区域增加“专属模板 / 公共模板”切换，专属排在公共之前；沿用既有卡片、预览和分页样式，不增加模板库入口或独立系统选择。
- 上传区只新增一行“关联设计系统”，复用原有下拉框样式。原文件选择按钮、说明、已导入模板、页面入口、预览及页面底部操作保持不变。
- 不增加名称表单、归属单选卡片、上传向导、保存按钮或设计系统详情页。

## 2. 模板可见规则

模板分为公共模板与设计系统专属模板。公共表示未关联任何设计系统，不改变现有访问权限。

```text
未选择设计系统：仅显示公共模板
选择设计系统 A：显示公共模板 + A 的专属模板
选择设计系统 B：显示公共模板 + B 的专属模板
```

上述规则同时应用于原“选择模板”卡片列表和原“已导入模板”下拉列表；保留内置模板、用户上传模板现有的展示位置，不合并或重排来源入口。

卡片选择区按“专属模板 / 公共模板”分别展示：有当前设计系统时默认专属，无设计系统时默认公共；恢复已有模板选择时自动打开其所属分类。专属为空时保留空态，提示可切换公共；未选系统时提示先选择设计系统。切换分类重置分页并清空原分类选择，避免使用隐藏模板；分页按当前分类计算。上传区的已导入列表继续显示公共与当前系统专属模板，上传关联方式保持不变。

- 过滤发生在分页之前，分页数量按过滤后的列表计算；切换系统回到第一页。
- 切换系统后，已选公共模板保留；已选专属模板只有属于新系统时保留，否则取消选择并在原区域提示“已取消原设计系统的专属模板，请重新选择”。
- 取消选择后不自动替换成另一个模板。用户仍可选择“不选模板”。
- “选择模板”显示为空时，复用原空态样式提示当前没有可用模板，不添加新的页面入口。
- 选择模板本身不自动更换设计系统，依靠列表过滤及提交校验保证匹配。

## 3. 上传区新增一行

在现有上传说明下方、“已导入模板”上方增加下拉框：

```text
关联设计系统  [公共模板（不关联设计系统） ▾]

选项：
  公共模板（不关联设计系统）
  系统内置规范……
  我的设计系统……
```

- 不关联设计系统即为公共模板，选择某个系统即为该系统的专属模板；不用再新增“模板类型”字段。
- 当前创建页选了 A 时，新上传默认关联 A，可手动改为公共或其他系统。未选择设计系统时默认公共模板。
- 设计系统下拉框使用现有系统列表及名称，系统身份按稳定 ID 关联；不增加规范版本选择流程。
- 上传 HTML、ZIP、文件夹沿用现在的导入方式，把关联值随导入请求一并保存，不增加保存步骤或按钮。
- 选取已导入模板时，下拉框回显它的实际关联。修改关联直接更新该模板元数据，沿用原有加载和错误反馈样式；处理中暂时禁用相关操作，失败保留原关联。
- 若新上传或修改后的归属不符合创建页当前设计系统，只保存在对应系统下，不自动选用、不改变创建页的设计系统，原区域提示“已保存到对应设计系统，切换后可选用”。
- 创建页切换设计系统时，未开始的新上传使用新的默认关联；正在进行的导入固定使用发起时的关联，完成后按最新创建页上下文判断能否选用，避免迟到结果覆盖选择。

## 4. 数据和过滤

模板摘要 / 包清单增加一个字段即可表达归属：

```ts
interface TemplateAssociation {
  // null 表示公共；有值表示只关联一个设计系统。
  designSystemKey: string | null
}

function isTemplateVisible(template, currentSystemKey) {
  return template.designSystemKey == null ||
    (currentSystemKey != null && template.designSystemKey === currentSystemKey)
}
```

- 用户规范用 `libraryId` 构造稳定键，内置规范用稳定目录 / catalog ID 构造键；区分内置与用户命名空间，不能用名称或安装路径关联。
- 专属归属属于整个设计系统，不因规范发布新版本而消失；本次设计仍使用创建页当前选定的规范版本。
- 既有会话固定规范版本、模板资源的机制保持不变，模板归属不反向改写历史设计。
- 历史模板缺少关联字段时按公共模板解释；不移动模板文件，不更换模板 ID。
- 内置模板默认公共，如需内置专属模板，在其已有元数据上声明关联；不从模板名字推断归属。

## 5. 实现范围

1. `src/shared/design-template.ts`：模板摘要增加可兼容旧数据的关联字段。
2. `src/main/services/design/template-packages.ts`：导入时写关联，读旧清单时归一为公共；支持只更新关联元数据，保留文件资源。
3. `src/main/ipc/design.ts` 与 preload：扩展原 `importTemplate` 接口接收关联，增加关联更新接口；主进程校验系统存在，并独立验证新会话 / 首次生成所选模板属于公共或当前系统。
4. `use-design-template-selection.ts`：接收当前设计系统，过滤两处列表、重置分页、清除不匹配选择，处理导入过程中的上下文变化。
5. `DesignTemplateSelector.tsx`：上传区插入关联下拉框，选择区增加专属 / 公共切换，复用原控件、卡片、分页及反馈样式。
6. `DesignCreationPage.tsx`、`DesignTemplateDialog.tsx`：传入当前设计系统上下文，复用同一套选择规则。

关联字段更新失败不把模板默认改为公共；模板关联已被其他窗口修改时，新建会话入口重新验证，提示刷新列表。恢复已有会话沿用历史引用，不使用新列表规则拦截恢复。

## 6. 验收

1. 原页面样式、入口、三段切换、文件选择方式和底部按钮保持原样；上传区新增关联下拉框，选择区增加专属在前的分类切换。
2. 无设计系统只见公共；选 A 只见公共和 A 专属；B 专属在卡片与已导入下拉中均不可见。
3. 上传时未关联保存为公共，关联 A 保存为 A 专属；重启后仍按归属过滤。
4. 切换 A 到 B：公共选择保留，A 专属选择清空；分页按过滤结果重算。
5. 当前 A 时上传到 B，不改变当前设计系统、不误选该模板，切到 B 后可见。
6. 修改已有模板关联后，列表与当前选择同步更新；更新失败保留旧值。
7. 系统改名或规范升级不丢模板，旧模板默认公共，历史会话正常恢复。
8. 导入中切系统、导入失败、关闭窗口等情况下，迟到结果不产生不匹配选择。
9. 专属 / 公共互不混入对方分类，切换分类分页回到第一页且清除隐藏选择；没有绑定系统时，专属页提示先选择系统。

## 7. 实施结果

- 在原上传区域增加关联下拉框；内置卡片、已导入模板和编辑器模板选择使用相同的公共 / 当前系统过滤规则，保持原样式和三段切换。
- 导入时保存关联，修改已导入模板归属时只原子更新清单；旧模板兼容为公共模板，设计系统跨版本按稳定身份关联。
- 新建会话、首次生成在主进程重新校验真实模板归属；已有产物与历史会话继续沿用既有资源。
- `npm run test:design-templates` 包含存储、归属校验、模板资源预览 / 导出和实际 React 组件的浏览器回归；新增浏览器覆盖分页、切换系统、规范版本、更新失败回滚、延迟导入和重载持久化。
