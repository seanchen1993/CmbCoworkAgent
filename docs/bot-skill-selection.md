# Bot 技能选择

创建 Bot 的「更多设置」以及「编辑 Bot」中提供「可用技能」。默认使用全部已启用技能，也可以选择指定技能；指定列表为空表示不使用技能。对话中的技能菜单同步过滤，配置保存后在后续执行开始时读取，已在运行的子任务保持启动时的配置快照。

## 数据契约与模板

`BotDefinition`、`CreateBotInput`、`UpdateBotInput` 增加可选字段 `allowedSkillNames?: string[] | null`：

- 创建时省略或 `null`：全部，包含以后新安装并启用的技能。
- `[]`：无技能。
- 名称数组：选择这些名称，大小写与已安装技能的规范名称一致。同名技能继续使用现有来源优先级。
- 更新时省略字段：保留原值，兼容旧客户端的重命名、记忆设置、归档等操作；显式 `null` 恢复全部。

SQLite `bots.allowed_skill_names_json` 存储选择；迁移后的旧记录为 NULL，不改变原行为。技能名最多 512 项，每项最多 256 字符，拒绝空名、NUL 和重复项。模板可以直接携带名称数组，不需要本机绝对路径；未安装或已禁用的名称会保留，UI 显示不可用，运行时不会自动安装或启用。加载列表失败不清空已有选择。本次提供模板的数据基础，不包含模板市场或安装流程。

## 运行入口

Bot host 在创建 run policy 时，将选择与原策略取交集。私聊、群聊、协作接收、定时任务、IM、独立任务和关联会话使用同一 adapter；模拟渠道、纯文本结果汇报继续保持空技能集。关联会话的工作目录和原模型策略保持现有逻辑。

技能目录发现、显式技能标记（含当前运行追加消息）、文件工具读取及 SDK 技能元数据下载使用该范围。task 子代理（含自带技能目录的专家）共享过滤后的目录和文件 backend；重新创建 runtime 的 workflow、coordinator worker、模型故障切换和 handoff 传递父执行范围。不同 Bot 之间委派仍使用接收方自己的配置。

显式选择技能的 Bot 不注入具有全库读写能力的 `manage_skill` 工具；技能库管理仍通过设置页进行。默认全部时保留原有管理行为。

现有全局禁用、插件启用与项目模式可见性规则继续生效。修改配置后恢复同一会话时，技能目录会重新构建，避免复用旧 checkpoint 的目录元数据。

## 边界

这是技能功能选择，不是操作系统安全隔离。它约束已注册技能的发现、激活和通过文件工具加载；不会撤销历史消息中已经出现的技能正文，也不阻止通用 shell、MCP 或其他获准工具访问同类文件或执行同类操作。工具权限、审批和沙箱仍由现有机制负责。运行中的后台任务不会因为修改 Bot 配置而被自动撤销。远程主机缺少对应目录接口时，不用本机目录替其配置。

## 验证

- `npm run test:bot-skills`：技能选择交集、显式激活、真实文件读取和下载、符号链接、恢复会话、真实 task 子代理、递归 runtime 传递，以及真实创建/编辑控件浏览器测试。
- `npm run test:bot-integration:core`：Bot 持久化迁移与旧客户端兼容、各任务入口、IM、群聊、工作会话和现有 Bot 行为回归。
- `npm run typecheck`、`npm run build`、`npm run lint`。

测试使用合成 Bot、临时技能目录和假模型；不连接真实 IM、不使用用户 Bot 数据、不调用付费模型。
