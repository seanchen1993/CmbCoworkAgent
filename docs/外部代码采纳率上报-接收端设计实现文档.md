# 外部代码采纳率上报 —— 接收端设计实现文档

> 面向：实现「外部代码采纳率上报」新接口的后端开发（建议与现有事件服务同仓、复用其 ES 写入通道）。
> 本文档自包含，按本文实现即可，无需阅读 DevClaw 客户端源码。配套《对接方接口文档》是对外契约，本文是我方落地实现。

## 0. 任务目标（一句话）

新增一个 HTTP 接口，接收外部系统上报的精简版 `code_gen` / `code_adopt` 事件，**校验 → 补全/派生为标准事件文档 → 写入 ES 索引 `devclaw_event`**，使其被现有运营面板的聚合查询直接命中。**不改动任何面板查询。**

## 1. 数据流

```
外部系统(多来源:标签/数据开发等)
   │  POST {BASE}/api/traces/external-code-events   （精简字段 + 令牌）
   ▼
本接口(新增)
   │  鉴权 → 校验 → 补全/派生为标准 CoworkEvent 文档
   ▼
ES 索引 devclaw_event   （与现有 /api/traces/events 落库形态一致）
   ▼
DevClaw 运营面板（聚合查询，无需改动）
```

## 2. 接口定义

| 项 | 值 |
|---|---|
| 方法/路径 | `POST /api/traces/external-code-events` |
| 鉴权 | Header `X-Devclaw-Source-Token` 认证身份，校验通过后得到该令牌**被授权的 source 集合**（如令牌A→{tag-platform}、令牌B→{data-platform}）。`source` 由调用方在请求体指定，须落在此集合内。无效/缺失令牌 → `401` |
| 请求体 | 单个事件对象，或事件对象数组（上限 200 条/批，超限 `400`） |
| 响应 | `200` + `{ accepted, rejected, errors[] }`；整体格式错误 `400`；鉴权失败 `401`；服务端异常 `5xx` |
| 落库目标 | ES 索引名取环境变量 `ES_INDEX_EVENT`（默认 `devclaw_event`），与面板读取的索引保持一致 |

> 令牌 → 授权 source 集合放配置。新增来源（如数据开发）= 发一个令牌并配置其授权 source，无需改代码；`source` 不假定为某一固定来源。

### 2.1 最简鉴权配置（token → source，直接放配置即可）

无需数据库 / 外部服务。接收端读一个环境变量（或配置文件），内容是 `token → source` 的 JSON。最简形态：**一个令牌绑定一个 source**（即「授权集合」退化为单值）：

```
EXTERNAL_REPORT_TOKENS={"tok_tag_live_9f3a":"tag-platform","tok_data_live_4b7c":"data-platform"}
```

校验逻辑（伪代码）：

```
# 请求级（一次）：校验令牌
token = header["X-Devclaw-Source-Token"]
allowed = CONFIG[token]              # 查不到 → 未知令牌
if token 为空 or allowed is None:
    return 401                       # 整请求拒绝

# 事件级（每条）：source 必须等于该令牌绑定的 source（见 §3.2 规则 2）
for event in body:
    if event.source != allowed:
        reject(event, "source not allowed for token")   # 进 errors[]，不影响同批其它条
    else:
        event.properties.source = event.source          # = allowed
```

- **新增一个对接方** = 在 JSON 里加一行（一个新令牌 + 它的 source），无需改代码、无需发版。
- 令牌放**环境变量 / 配置中心，不要提交进代码库**。
- 1:1 已够用；将来若要「一个令牌报多个来源」，把值改成数组、`!=` 改为「不在数组内」即可。

## 3. 输入 Schema 与校验规则

### 3.1 输入字段（精简版，来自对接方）

**通用/身份**：`eventType`(必), `source`(必), `clientEventId`(必), `sapId`(必), `userName`(必), `ystId`(建议), `pathName`(建议), `orgName`(可选), `harnessProjectId`(建议；DevClaw 项目 ID，对接方从 hook env `HARNESS_PROJECT_ID` 读取，两类事件都可带), `harnessFeatureSlug`(建议；DevClaw 特性 slug，对接方从 hook env `FEATURE_ID` 读取，决定项目列表里特性行的归属), `harnessAdapterName`/`harnessAdapterVersion`(可选；适配器名/版本，对接方从 hook env `HARNESS_ADAPTER_NAME`/`HARNESS_ADAPTER_VERSION` 读取，决定按适配器切片的归属)

**code_gen 专有**：`lineCount`(必,int≥0), `generatedAt`(必,ISO8601带偏移), `language`/`usedSkills`/`tool`/`modelName`/`relativeHint`/`threadId`(可选)

> 不接收文件全路径/内容(隐私)；`relativeHint` 仅叶子文件名。`traceId` 看板采纳口径不使用，无需接收。`threadId` 只需随 `code_gen` 接收，`code_adopt` 不必带（其值 = 配对 gen 的 threadId）。

**code_adopt 专有**：`genClientEventId`(必), `generatedLineCount`(必,int≥0), `adoptedLineCount`(必,int), `generatedAt`(必), `pushed`(必,bool), `pushedAt`(必,ISO8601), `effectiveGeneratedLineCount`(可选), `usedSkills`/`modelName`(可选)

### 3.2 校验规则（逐条）

对每个事件按顺序校验，任一不过 → 该条进 `errors[]`（不阻塞同批其它条）：

1. `eventType ∈ {"code_gen","code_adopt"}`；否则 `invalid eventType`。
2. 通用必填非空：`clientEventId / sapId / userName / source`；其中 `source` 还须 ∈ 当前令牌被授权的 source 集合（否则 `source not allowed for token`）。
3. 时间字段为可解析的 ISO8601 带时区偏移（`generatedAt`；adopt 还需 `pushedAt`）。
4. `code_gen`：`lineCount` 为整数且 `≥ 0`。
5. `code_adopt`：
   - `genClientEventId` 非空；
   - `generatedLineCount` 整数 `≥ 0`；
   - `adoptedLineCount` 整数且 `0 ≤ adoptedLineCount ≤ generatedLineCount`（越界则夹取到该区间并记一条 warning，或直接判错——二选一，建议夹取保证数据可用）；
   - `pushed === true`（当前只支持上线即已推送；为 false 时拒绝并提示 `pushed must be true`）。
6. 批量条数 `≤ 200`。

> 校验失败的 `errors[]` 项形如 `{ "clientEventId": "...", "reason": "..." }`。

## 4. 字段映射与补全/派生（核心）

把精简输入补全为**标准事件文档**（结构对齐我方 `CoworkEvent`：顶层身份字段 + `properties`）。

### 4.1 顶层字段

| 标准字段 | 取值 |
|---|---|
| `eventId` | `code_gen` → `"g_tag_" + clientEventId`；`code_adopt` → `"a_tag_" + clientEventId`。**同时用作 ES 文档 `_id`**（幂等） |
| `eventName` | = `eventType` |
| `eventCategory` | 常量 `"code_adoption"` |
| `eventTime` | `code_gen` → `generatedAt`；`code_adopt` → `pushedAt`（无则取接收时刻） |
| `userName` | = 输入 `userName` |
| `userIp` | 取请求来源 IP（无则空串 `""`） |
| `sapId` / `ystId` / `orgName` / `pathName` | 原样透传（缺省填空串/省略） |
| `upperOrgLv0..3` | 由 `pathName` 派生，见 §4.3 |

### 4.2 `properties`

**两类公共**：`source`（取请求体 `source`，已在 §3.2 校验属于该令牌授权集合后原样写入；**不要硬编码为某固定来源**）、`schemaVersion: 1`、`eventId`（同顶层 `eventId`）、`clientEventId`（原样存调用方的 `clientEventId`，供删除接口 §11 精确匹配）、`ingestedAt`（服务端**接收时刻** ISO8601，供删除接口按上报时间范围筛选）、`harnessProjectId`（**直通**输入 `harnessProjectId` 到 `properties.harnessProjectId`，不派生、不改写；可选，缺省则省略。**面板「项目运营概览」的代码聚合强制 `exists properties.harnessProjectId`**，故缺省的事件只进「平台运营概览」；带上才进「项目运营概览 → 生产效能代码指标」并可被其 source 下拉筛选）、`harnessFeatureSlug`（**直通**输入 `harnessFeatureSlug` 到 `properties.harnessFeatureSlug`，不派生；可选。面板的项目列表按 `properties.harnessProjectId` 分项目、再按 `properties.harnessFeatureSlug` 分特性——带上它，你方数据才出现在对应**特性行**；缺省则只汇总到项目级）、`harnessAdapterName` / `harnessAdapterVersion`（**直通**到 `properties.harnessAdapterName` / `properties.harnessAdapterVersion`，不派生；可选。面板按 `harnessAdapterName→harnessAdapterVersion` 两级切适配器维度——带上才计入适配器行/占比，缺省则不计入适配器维度）。

**code_gen.properties**：

| 字段 | 取值 |
|---|---|
| `lineCount` | 输入 `lineCount` |
| `createdAt` | 输入 `generatedAt` |
| `language` / `tool` / `modelName` | 透传（有则填） |
| `usedSkills` | 透传数组（无则省略或 `[]`）。约定格式 `<技能名>-v<版本>`（连字符分隔、`v` 前缀，如 `tag-codegen-v1.0.0`），与我方 `ensureVersionedSkillIdentifier` 一致 |
| `relativeHint` | 透传（叶子文件名）到 `properties.relativeHint`；有则填，无则省略。**不要存全路径/内容** |
| `threadId` | 透传到 `properties.threadId`；可选 |

> **关于 `relativeHint` / `threadId` 的现状**：面板里读这两个字段的逐条钻取（commit 采纳明细 / 未提交明细 / commit 汇总）入口均按 `commitSha` 或「无采纳」筛选；外部数据 `commitSha=null` 且有采纳，两头都不命中，故这两个字段**当前对外部数据无可见效果**，仅作前向兼容透传。取值口径：面板 `relativeHint` 取自 `code_gen`；`threadId` 现取自 `code_adopt`，但其值等于配对 `code_gen` 的拷贝，故**外部只需在 `code_gen` 带 `threadId`**，`code_adopt` 不必带、接收端也不必接收。将来若让外部数据展示「会话」维度，面板从配对 `code_gen` 取 threadId 即可。

**code_adopt.properties**：

| 字段 | 取值 |
|---|---|
| `genEventId` | `"g_tag_" + genClientEventId`（**必须**与对应 code_gen 的 `properties.eventId` 一致，否则关联断裂） |
| `generatedLineCount` | 输入 `generatedLineCount` |
| `effectiveGeneratedLineCount` | 输入有则用，**否则 = `generatedLineCount`** |
| `adoptedLineCount` | 输入 `adoptedLineCount`（已夹取） |
| `generatedAt` | 输入 `generatedAt`（原始生成时间） |
| `measuredAt` | 输入无 → `pushedAt` |
| `pushed` | `true` |
| `pushedAt` | 输入 `pushedAt` |
| `verdict` | 常量 `"committed"`（或约定 `"external"`，面板不强校验） |
| `measureSource` | 常量 `"external"` |
| `commitSha` | `null` |
| `usedSkills` / `modelName` | 透传 |

### 4.3 `upperOrgLv0..3` 派生算法（从 `pathName`，照此实现）

```
deriveUpperOrgLevels(pathName):
    empty = { lv0:"", lv1:"", lv2:"", lv3:"" }
    if pathName 不是字符串: return empty
    parts = pathName.split("/").map(trim).filter(非空)
    i = parts 中第一个「包含子串 "信息技术部"」的下标
    if i < 0: return empty
    lower = parts[i+1 .. 末尾]          # 信息技术部之后的层级
    if lower[0] 包含子串 "团队":
        lv0 = lower[2] or ""
        lv1 = lower[1] or ""
        lv2 = lower[0] or ""
        lv3 = "本部团队"
    else:
        lv0 = lower[3] or ""
        lv1 = lower[2] or ""
        lv2 = lower[1] or ""
        lv3 = lower[0] or ""
    return { lv0, lv1, lv2, lv3 }
```

> 与 DevClaw 客户端 `deriveUpperOrgLevels` 逻辑一致，保证你方事件与现有数据在组织维度对齐。

## 5. ES 落库

- 索引：`ES_INDEX_EVENT`（默认 `devclaw_event`）。
- 文档 `_id` = 顶层 `eventId`（`g_tag_*` / `a_tag_*`）→ **同 ID 重复上报覆盖而非新增，天然幂等**。
- 写入方式：单条用 `PUT /{index}/_doc/{_id}`；批量用 `_bulk`（`index` 动作 + `_id`）。
- 复用现有事件服务的 ES 客户端/连接配置（节点、basic auth）即可，无需新建。

## 6. 必须满足的面板契约（实现自检，逐条核对）

这些是面板聚合的硬条件，违反则你方数据不进统计：

1. **生成量**：面板对 `eventName="code_gen"` 按 `properties.lineCount` 求和，并按 `eventTime` 过滤时间。→ code_gen 必须有 `properties.lineCount` 且 `eventTime` 正确。
2. **已测量采纳率（分子/分母）**：面板对 `eventName="code_adopt"` 且 `properties.adoptedLineCount`、`properties.generatedLineCount`、`properties.effectiveGeneratedLineCount` **三者都存在**的文档聚合，按 `properties.generatedAt` 过滤时间。采纳率 = `Σ adoptedLineCount / Σ effectiveGeneratedLineCount`。→ 三个行数字段必须齐全，`generatedAt` 用原始生成时间。
3. **已推送采纳率**：在第 2 条基础上再加 `properties.pushed == true`。→ 你方 adopt 标 `pushed=true`，即同时进「已测量」与「已推送」两个口径。
4. **生成↔采纳关联**：面板用 `code_adopt.properties.genEventId` 反查 `code_gen.properties.eventId`。→ 两者必须相等（都是 `g_tag_{同一个 clientEventId}`）。
5. **用户/组织维度**：按顶层 `sapId` 与 `upperOrgLv*` 切片。→ 必须正确补全身份与派生层级。
6. **时间一致性**：`code_adopt.properties.generatedAt` 用上线时间会错桶——必须用原始生成时间。
7. **项目维度 + source 筛选**：「项目运营概览」的代码聚合强制 `exists properties.harnessProjectId`；「生产效能代码指标」的 source 下拉按 `properties.source` 收窄（原生事件无 source）。→ 直通 `harnessProjectId`、正确盖戳 `source`，你方数据才在该面板出现并可被单独筛选；`harnessProjectId` 缺省时仅进「平台运营概览」（不影响采纳率/漏斗正确性）。
8. **特性维度**：项目列表把项目下钻到特性时按 `properties.harnessFeatureSlug` 分桶（与项目级同口径、不卡 commit）。→ 直通 `harnessFeatureSlug`，你方数据才出现在对应特性行；缺省则只汇总到项目级、不分特性。
9. **适配器维度**：面板按 `properties.harnessAdapterName`→`properties.harnessAdapterVersion` 两级切适配器（适配器行 / 占比）。→ 直通这两个字段，你方数据才计入适配器维度；缺省则不计入（不影响项目/特性/采纳率正确性）。

## 7. 响应与错误处理

- 成功（含部分拒绝）：`200`，体 `{ "accepted": <int>, "rejected": <int>, "errors": [ { "clientEventId": "...", "reason": "..." } ] }`。
- 整体非法（非 JSON、超批量上限）：`400`。
- 鉴权失败：`401`。
- 服务端/ES 异常：`5xx`（让对接方退避重试；注意写入应尽量幂等，重试不致重复计数）。
- 落库失败的条目不计入 `accepted`，应能被对接方按 `clientEventId` 安全重发。

## 8. 验收测试（按步骤执行）

1. **鉴权**：不带/带错 `X-Devclaw-Source-Token` → 期望 `401`。
2. **校验**：上报一条缺 `lineCount` 的 code_gen → 期望 `200`，`rejected=1`，`errors[0].reason` 提示缺字段。
3. **派生**：上报 `pathName="招商银行/信息技术部/数据资产管理团队/标签组"` 的 code_gen → 落库文档 `upperOrgLv2="数据资产管理团队"`、`upperOrgLv1="标签组"`、`upperOrgLv3="本部团队"`、`upperOrgLv0=""`。
4. **落库 gen**：上报《对接方文档》§7.1 示例 → ES `devclaw_event` 出现 `_id="g_tag_..."`、`properties.lineCount=42` 的文档。
5. **落库 adopt**：上报 §7.2 示例 → 出现 `_id="a_tag_..."`、`properties.genEventId="g_tag_..."`（= 第 4 步 gen 的 `properties.eventId`）、三行数齐全、`pushed=true` 的文档。
6. **幂等**：把第 4 步原样重发一次 → ES 仍只有一条该 `_id` 文档（覆盖，不新增）。
7. **进面板**：在运营面板选包含 `generatedAt`（2026-06-22）的时间范围、定位到该用户/组织 → 生成量 +42；采纳率体现 `35/42`；「已推送采纳率」同样体现该样例；事件可按 `properties.source="tag-platform"` 检索到。

## 9. 与现有 `/api/traces/events` 的异同

## 11. 删除接口实现（外部联调数据清理）

| 项 | 值 |
|---|---|
| 方法/路径 | `POST /api/traces/external-code-events/delete` |
| 鉴权 | 同 §2.1：校验 `X-Devclaw-Source-Token`，得到令牌**被授权的 source 集合** |

### 入参校验
1. 令牌有效，否则 `401`。
2. `source` 必填且 ∈ 令牌授权集合，否则 `403`（防跨来源删除）。
3. **范围必给**：`from`/`to`（ISO8601）或 `clientEventIds`（≤ 1000）至少其一；都没有 → `400`（禁止 source-only 全删）。
4. `eventType`（可选）∈ {`code_gen`, `code_adopt`}。

### 删除：ES `_delete_by_query` on `devclaw_event`
`properties.source` 子句**永远存在**，再叠加调用方提供的范围/ids/eventType：
```jsonc
{
  "query": { "bool": { "filter": [
    { "term":  { "properties.source": "<已校验 source>" } },   // 永远存在，锁定调用方
    { "range": { "properties.ingestedAt": { "gte": "<from>", "lte": "<to>" } } }, // 给了 from/to 才加
    { "terms": { "properties.clientEventId": ["...", "..."] } },                  // 给了 ids 才加
    { "term":  { "eventName": "code_gen" } }                                      // 给了 eventType 才加
  ] } }
}
```
建议带 `?conflicts=proceed&refresh=true`（联调即时可见）。

### 前置：上报落库需多存两字段（见 §4.2）
- `properties.ingestedAt`：服务端接收时刻 ISO8601（范围删除按它筛选）。
- `properties.clientEventId`：原样存（精确删除按它匹配）。

### 响应
`{ "deleted": <int> }`（取 `_delete_by_query` 返回的 `deleted`）。

### 安全要点
- `properties.source` 过滤子句**强制存在** → 令牌只能删其授权 source 的数据，绝不允许跨来源或无 source 删除。
- 既无 `from/to` 又无 `clientEventIds` → 拒绝，防全量误删。
- 天然只动该 source 的事件，不触碰其它来源或我方自身数据。
