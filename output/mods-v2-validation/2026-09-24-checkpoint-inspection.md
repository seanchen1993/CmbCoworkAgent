# Read-only checkpoint recovery inspection — 2026-09-24

Based on `fdc44583`, only Mods v2. Adds an explicit recovery inspection action to host checkpoint evidence. The host resolves an existing transition record in the current workspace/thread, then reads that operation from the protected journal using SQLite read-only mode. The renderer cannot supply a workspace, database path, target file, or arbitrary commit authority.

The result contains only two fixed state-file paths and SHA-256 hashes. Bounded stable handles and a second read reject concurrent modification; missing, linked, oversized or unreadable files remain unavailable. The UI distinguishes before/after/mixed/changed/unavailable and displays observation time and concrete next steps. It does not mutate files, clear unknown journal entries, run validators, replay an operation or restore PASS. Epoch/scope/disabled checks reject invalidated reads; renderer lifetime tickets reject late replies.

Failing tests preceded implementation: missing recovery module and missing UI action (`2026-09-24-recovery-red.log`). Review identified the journal constructor could create an empty data directory during inspection; a further red test (`2026-09-24-recovery-readonly-red.log`) led to actual read-only opens with no directory/schema creation. File symlinks require unavailable Windows privileges on this host; the initial test failed EPERM and was replaced by a real hard-link rejection test, not skipped.
