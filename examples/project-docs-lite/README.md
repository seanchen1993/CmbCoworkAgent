# 两阶段文档项目

这是普通插件格式的轻量项目包：`plugin.json`、运行声明、一个 Skill、隔离合同样例。无需 Python 或企业字段。

在包含本轮 CLI 的构建中执行 `openwork plugin doctor <本目录>`、`openwork plugin test <本目录>`，再 `openwork plugin pack <本目录> --out <新的.zip文件>`。产物通过原插件安装入口导入。

起草阶段检查 `draft.md` 存在，复核阶段检查它及 `review.json` 的结构，并要求人工确认。文件存在和结构通过均不宣称业务质量合格。

运行声明是宿主接口；不要直接编辑项目数据库或伪造阶段状态。隔离测试只执行产物校验，不调用模型或批准阶段。完整创建、运行、拒绝、修复和重开场景需宿主入口验收。

参见仓库 `docs/sparks/project-plugin-cookbook.md`。

## 在项目里与其他插件搭配

与 `examples/project-harness-data` 分别安装并启用后，进入项目对话，点“项目能力”。

- 一起帮你分析：在“对话中使用”选择“整理项目需求”和“检查数据质量要求”，预览确认后回到项目对话提问。
- 按顺序交付：添加“起草并审核需求文档”，再添加“数据口径、开发与验收”。第二套流程的“前一套流程的需求文档”选择第一套的 `draft`。

填写本次目标，例如“整理订单日报需求，明确字段口径并生成数据开发和验收资料”。检查并预览后启动，遇到人工确认时先阅读产物，再决定是否批准。第二套流程只使用前一套流程通过检查后的结果。

`devclaw.capabilities.json` 声明可选择的独立能力和完整流程。原单插件创建、阶段检查和审批仍可照常使用。

0.2.0 提供可选的“前序已检查资料与源码变更”输入。搭配新 AutoBiz 组合副本时，
在资料下拉中显式选择前序 `verified-context`；宿主按已冻结的哈希将正文包复制到独立运行目录。
起草与复核均必须实际读取 `inputs/verified-context.json`，包括 files 的业务资料和 sourceChanges
中声明范围内真实变化的源码正文；在结果中列出使用的路径、摘要和基线范围。这不代表逐文件或业务质量验收。
没有选择资料时仍可独立起草，但结果须说明只根据任务文字，不得声称使用或验收了前序成果。
