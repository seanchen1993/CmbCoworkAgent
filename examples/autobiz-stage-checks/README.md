# AutoBiz 原阶段检查适配

本目录是 DevClaw 的宿主适配资源，由构建过程打包；插件作者不需要复制脚本或改写原 Hooks。

适配器保留原项目初始化、需求创建、动态流程编译、阶段推进、产物检查和人工审批。项目内的完整流程使用独立工作目录与原托管运行。组合只有取得真实终态、检查证据和有效产物后才会推进到下一流程。

## 接入方式

在应用的插件副本编辑页选择“用于完整流程组合”，预览后确认保存。宿主为通过兼容检查的新副本增加四个静态声明，不修改原技能、脚本和流程节点：

- `devclaw.project-runtime.json`：声明由原插件管理流程状态。
- `devclaw.capabilities.json`：声明项目内的完整流程入口。
- `devclaw.stage-checks.json`：选择经过检查的原阶段校验适配器。
- `devclaw.source-handoff.json`：显式声明源码观察范围（示例为 src）。宿主在原需求创建后、模型启动前把路径和哈希冻结到原生账本；完成时只比较此范围的基线与最终字节，不扫描整个工作区冒充成果。

新的固定 `verified-context` 出口包含原检查的业务资料正文与范围内源码变化正文、哈希和删除记录。
源码部分是宿主观察证据，与原阶段校验分开标记；不代表逐文件或业务质量验收。缺基线、范围变更、二进制或超限时拒绝交接，旧无声明运行不补造基线。

新增文件不是执行授权。安装包的代码、原命令模板、身份与摘要仍会在目录读取、预览和运行前检查。未匹配的插件版本继续原单插件入口，不自动降级为跳过检查的流程。

## 保留原验证链

`project_checkpoint` 在原状态文件上持锁，调用原阶段准备与检查逻辑。原检查成功后，宿主先核对实际产物和冻结合同，再允许写入状态；凭据不可信时不提交状态。

业务讨论和 PRD 的原校验要求当前处于对应的 `done` 阶段，因此在离开该阶段之前调用原 `biz_validate.py` 的校验函数。失败会阻止进入下一阶段。锁内状态读取使用原同步检查的只读模式，避免修复操作改写尚未授权的状态；章节、内容和阶段判定仍由原函数执行。

初始计划与完成计划的内容不同，不能在终态重新运行初始检查。适配器保存原检查实际通过时的产物摘要，并要求后续合法修改取得相应的新检查证据。通用存在性检查不能替代业务校验或人工批准。

技术约束：当前锁定提交适配使用 Windows 本地 NTFS。原插件代码的完整 Python 文件集合与命令模板必须匹配已验证的版本；新增原生扩展或未审代码不予准入。协议核对实现见 `src/main/plugins/autobiz-composition-protocol.ts`，验证样本固定为 Git 提交 `8db1ec937d6ed3d271cb9dc540310d6633c91e70`。

## 更新兼容版本

更新原插件后，先验证原初始化、创建需求、所有阶段、失败阻断、原审批和最终产物，再更新兼容指纹。代码与接口契约应一起复审；不得仅替换摘要来消除报错。

本地测试应使用隔离目录和本地模型回环，保留原脚本字节，不能连接真实业务或把模拟托管记录当成完整执行验收。
