# 可拆分组件示例

第一次操作请先看[插件开发入门](../../docs/sparks/plugin-cookbook.md)练习三，
按界面步骤选择组件、配置模型并验证效果；练习四说明复用旧阶段时如何保留 Hooks。

这是本工程的组件选择示例，不是 Claude 官方组件格式。它演示真正按选择注册命令，
不自动读写项目，也不自动执行测试。代码检视与汇报整理会调用你已配置的默认模型。

## 体验差别

1. 在普通本地项目会话开启 Mods，通过“上传、授权与完成规则”导入本目录并完成插件授权。
2. 打开“我的 Claw”，添加 `component-review-kit`，切换为选择部分组件。
3. 只选“代码检视”，页面会提示缺少“示例说明”依赖；显式加入它，不选“汇报整理”。
4. 可将检视重点填写为“重点检查空值、数组越界和重复提交”，选择默认模型，保存并应用。
5. 在聊天输入 `/component-review function first(xs) { return xs[0].name }`。
   `/component-help` 也可使用；`/component-report` 此时没有注册，不是只从列表隐藏。
6. 返回组合，加入“汇报整理”，保存并在会话空闲时重新应用，再使用
   `/component-report 已完成空数组检查，尚未执行项目测试`。
7. 同一个 Claw 还可以添加另一个已授权插件的组件、Skill、MCP 和显式 Flow。
   Flow 编辑器可以浏览全部已授权来源的动作；绑定组合和实际运行时只允许所选组件导出的动作。
   模型按现有默认/角色设置使用。

保存只更新模板；应用才更新当前对话。执行中的会话不能强行应用新组合，需完成或取消后操作。
移除组件不会撤销已经发生的外部操作；旧实例、命令引用和审批不能用于重新调用被移除的组件。

## 作者如何改造旧插件

- 原插件没有组件声明时保持整包行为。宿主无法自动判断某个 Hook 是否依赖另一个 Hook，
  所以不能直接把每个 Hook 变成勾选项。
- 在 native `mods/manifest.json` 使用 `claw.componentsVersion: 1` 和 `components`。
  同时移除原 `entry`，把它的行为移到显式组件中，避免存在用户看不见的统一入口。
- 每个组件以相对 manifest 目录的 `entry` 指向独立文件，导出同步 `register(on, options)`。
  `dependsOn` 声明同包依赖，宿主按拓扑顺序调用各组件 register，每个只调用一次。
- 同包多个组件处理同一事件时应显式给 matcher，例如 `on("session.start", {}, handler)`，
  并按原 Hook 规则调用 next；原有“同包同事件不能重复注册无 matcher 处理器”的检查仍保留。
- `actionIds` 必须唯一完整覆盖 `claw.actions`；没有动作的事件组件可使用空数组。
- `configSchema` 声明该组件的配置。配置平铺合并到该组件的 options，覆盖同名包级 options；
  不传给其他组件，不提供新的工具权限。必填配置必须由用户提供，不擅自填造业务值。
- 不要 import 其他组件入口，包括经辅助文件转引入。公共纯函数可放到独立 helper，
  但 helper 在各组件 bundle 中是不同模块实例。需要共享状态时使用现有、受权限约束的 SDK。
- 完整包源码共同决定授权摘要，修改未选组件也需要重新核对包版本。选集与配置另有运行摘要。
  同包组件共享原插件的授权和沙箱，不是独立安全主体。
- 目录发现只编译、不执行代码。首次授权及主动兼容检查保留独立的全包注册探针，会运行顶层
  代码和 register，但不调用业务 Hook 或授予执行权限；真正业务会话只加载已选组件。
- 插件有应用强制 check/repair 完成规则时必须使用全部组件，不能通过部分选择绕过规则。

本例的检视只分析提供的文本。要检视真实仓库，可在 Flow 中使用有文件读取能力的 Agent 步骤，
再加入原生测试和人工确认；不要把这里的模型文字当作真实代码读取或测试通过的证据。
