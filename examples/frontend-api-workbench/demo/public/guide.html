DEVCLAW · MODS 场景演示

让模型带着证据做联调

一个 Vue 订单运营台、一份接口文档、一张聊天顶部工作台。让当前模型操作真实页面，对照网络响应，说明哪里有问题、哪些功能已经验证。

打开被测 Vue 页面 ↗查看第一轮接口文档 ↗
1

打开工作台

在 DevClaw 普通聊天启用“前后端联调工作台”。表单直接出现在聊天顶部，可展开或收起。

2

填入演示，开始分析

点击“填入演示案例”，再点“开始联调分析”。填入动作本身不会调用模型。右侧浏览器用来观察实际页面。

3

在聊天里看证据

检查报告是否给出请求、响应和页面现象。可继续追问，也可换正确文档做第二轮对照。

本地服务已能返回此页面。首次使用内置浏览器控制时，请在应用“浏览器 → 控制配置”开启 Agent 控制并按提示重启。保持启动脚本窗口打开。

直接复制到工作台

默认端口可使用工作台的一键填入；更换端口时，以此处实际地址为准。

按这个顺序展示，效果更清楚

  1. 先打开订单页：确认这是能筛选、翻页、查详情的 Vue 应用。
  2. 回到聊天顶部，填入示例，点击一次开始；观察任务进入聊天。
  3. 看右侧浏览器实际操作，并在报告中找到对应的请求与页面证据。
  4. 追问：“哪些是文档冲突？哪些页面本身正常？请不要把所有差异都归因于后端。”
  5. 换正确文档再测：对照报告变化，而不是重复输出第一轮结论。

同一页面，两轮对照

第一轮 · 混合文档

一部分契约正确，一部分有偏差。检验模型能否发现差异，同时保留正常功能的结论。

打开第一轮文档 ↗

第二轮 · 正确文档

在工作台点击“换正确文档对照”，然后再次开始。页面保持不变，检验模型是否能区分文档修订与代码修复。

打开正确对照文档 ↗

演示数据全部虚构，业务操作均为只读。完成后再自行查看材料包中的“验收答案-请勿提交给模型.txt”；这个页面不会展示答案。没有实际打开页面、没有响应证据的部分，应明确写为未验证。
