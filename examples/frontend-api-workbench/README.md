# 前后端开发与联调工作台 1.1.0

从半成品前端源码和接口文档开始，使用当前聊天选择的模型补齐代码、运行检查、打开内置浏览器联调，发现问题后修复并复测。工作台位于聊天顶部，可收起配置；实际改动和验证证据显示在聊天中。

## 第一次试用

1. 在应用的插件导入入口上传 `frontend-api-workbench.zip`。这是一个普通聊天灵件，不是项目模式插件；更新同名包会保留插件身份。
2. 将单独的 `frontend-api-starter.zip` 解压到可编辑目录。在这个源码目录开始普通聊天，并启用“前后端联调工作台”。使用独立副本，助手会修改其中的前端代码。
3. 开启应用的内置浏览器 Agent 控制；首次配置后若应用要求重启，先重启。仅打开浏览器页面不等于已开启控制。
4. 点击“填入演示案例”，确认“源码目录”确实指向解压后的 `frontend-api-starter`。预设使用当前聊天目录，不会猜测你的安装位置，也不会启动任务。
5. 点击“补齐代码并联调”。助手先读源码和契约，补齐前端，运行检查并启动本地服务，然后在内置浏览器操作页面。首次工具权限按应用原有机制确认。
6. 在聊天查看改动文件、命令结果、页面交互和接口证据；在内置浏览器查看实际效果。提交成功只代表请求已处理，是否通过要以真实验证结果为准。

示例默认配置：

| 字段 | 值 |
| --- | --- |
| 源码目录 | 解压后的 `frontend-api-starter` 完整路径 |
| 页面地址 | `http://127.0.0.1:4179/` |
| 接口文档 | `docs/api-correct.txt`；服务启动后也可用 `http://127.0.0.1:4179/api-docs-correct` |
| 启动命令（可选） | `npm run dev` |
| 检查命令（可选） | `npm run build` 和 `npm test`；留空由助手读取 package 脚本 |

示例无需安装依赖，但需要可用的 Node.js。服务由项目的启动命令运行；重启应用不会替你启动它。原始半成品的测试失败是待开发内容，不能直接当作完成版。详细需求见源码包的 `TASK.md`，验收要求以其清单为准。

## 用自己的项目

填写源码目录、启动后的页面访问地址（无需预先启动）以及接口文档正文、URL 或本地文件路径。相对文档路径按源码目录解析；长文档建议填文件路径。在“补充需求”填写本次要补齐的功能；已有标准脚本时不用填写运行命令。

“使用当前目录”仅填入这个聊天的实际工作目录。输入其他路径不会切换聊天工作目录或授予额外权限；若目标不可访问，先将聊天绑定到正确目录或按原有工具流程处理权限。执行前助手会核对真实路径、项目约定和已有改动，避免覆盖用户工作。

默认可以修改目标项目中的前端源码、运行现有检查和服务、执行只读页面交互；后端、接口契约、mock 与验收测试保持只读。不默认授权业务写操作、部署、Git 提交或推送。所有执行仍遵守原有工具权限，没有额外模型或后台自动执行器。

## 停止、继续与排查

- 使用聊天的停止按钮停止任务。文件改动会保留，不自动回滚。继续时直接在聊天说明，或查看当前任务后再次点击工作台，从现有文件和服务状态接着做。
- 点击后显示“正在提交”时不要重复点击；聊天忙时会排队。恢复输入、切换页面或重启不会自动重跑。
- 页面连接被拒绝：查看聊天中的服务启动结果和端口，不要只重启应用。端口占用时先确认服务身份，不应杀掉其他项目的进程。
- 浏览器不可用：检查 Agent 控制配置以及当前聊天的工具选择。没有实际浏览器验证的结果只能算部分完成。
- 文档冲突：默认正确文档适合完整开发演示；想测试识别冲突时手动改为 `/api-docs` 或 `docs/api-challenge.txt`。不能把更换文档或放宽测试当成修复。
- 完成报告应包含文件改动、实际命令退出码、真实页面/请求证据、未完成项和服务停止方式；只有口头“完成”不算验收。

## 开发与分发

插件包只包含 `plugin.json`、`hooks/` 和本说明。`demo/` 是仓库保留的旧只读分析示例，不随新版插件分发；独立半成品项目位于 `../frontend-api-starter`，另行打包。不要将完整实现或验收答案混入半成品源码。

工作台通过公开的 `ChatHeader`、`session.cwd`、会话存储和异步 `prompt.submit` 提交到当前聊天；文件读写、命令和浏览器都由现有通用工具执行。不依赖新增的平台业务适配，不改变项目模式流程或应用版本。平台的通用性能修复需更新应用代码，仅导入灵件 ZIP 不会更新平台。
