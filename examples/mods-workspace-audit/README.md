# 用实际 Git 检查体验 DIY

在 Mods 中从本地目录导入此插件，在目标项目启用并批准当前源码版本。
项目需要 Git；这个示例只读取工作区，不提交、不切分支。

在 Autobiz 项目的会话中依次体验：

1. `/claw-audit status`：只执行工作区状态检查。
2. `/claw-audit whitespace,summary`：先检查补丁空白问题，通过后再生成变更统计。
3. `/claw-audit summary,status`：同一组组件按另一顺序执行，日志和结果顺序随之变化。
4. `/claw-audit-stop`：停止当前检查，关闭流和进程，并取消进度定时器。

每次命令启动会展示真实 argv、工作目录等批准内容。允许后才执行；拒绝不会启动命令。
日志中的 `Starting`、stdout/stderr 和最终退出码用于核对实际执行，不靠模型口头描述。
定时器显示运行时间；非零退出码会拦住后续步骤。

DIY 的位置是 `checks` 中的组件，以及用户输入的选择和顺序。你可以在插件里增加新的
检查组件，也可以另写 `process.spawn` hook 对某一类检查改写参数、转换输出或直接拒绝。
这些扩展使用同一套宿主审批、资源清理和日志机制，无需再写 Electron IPC 或进程管理器。
需要模型代码检视和人工发布关卡时，继续使用已有 Autobiz Flow 编辑器配置对应步骤；
此示例用于单独验证新增的真实命令、流、定时器链路，不把 Git 空白检查称作完整代码检视。

本例按步骤等待结果，以保证顺序和停止门槛。SDK 也支持在后台消费已启动的流；
后台消费只保留日志/状态展示能力，不能沿用结束任务的文件写入或工具授权。
