# 用 Autobiz 差异体验自定义检视角色

## 在助手组合中搭配独立检视动作

完整路径见[导览实战：Autobiz + 独立 Review](../../docs/sparks/plugin-cookbook.md#导览实战autobiz--独立-review)：
安装与授权两个来源 → 创建两步流程 → 保存并应用组合 → 明确发送任务 → 查看单文件意见。
应用内互动导览使用演示数据，不会替你完成这些真实操作。

这个完整插件目录可直接安装，也可压缩为 ZIP 导入；当前 1.2.0 增加参数表单说明和可选 configSchema，更新后需要重新批准摘要。
新增 `review-input` 显式动作，可以接收 Autobiz `prepare-review` 的输出：
`path`、`source` 必填，`context` 可选，其他前步属性不会作为权限或指令。

在“自定义助手 → 按步骤执行”添加“独立 Review：检视前一步文件”，选择前置 Autobiz 动作为输入来源，
选择“完整输出对象”，不设置固定覆盖字段。动作配置不设置模型时沿用默认模型；需要指定时，可在表单开启“检视模型引用”，填写 `custom:已配置模型ID`（高级 JSON 等价于 `{"model":"custom:已配置模型ID"}`）；
并在助手组合的模型设置中允许该模型；省略使用组合默认模型，再落到宿主默认。
模型引用不包含密钥，调用仍受宿主授权、预算和取消保护。
请用实际模型设置中的 ID，不要填写示例文字。

该动作通过 `$.model.complete` **等待单次真实模型调用结束**，返回 `output.review` 和范围说明。
它只检视不超过 4000 字符的单个文件，不运行测试、不修改文件、不作阶段提交。
失败直接停止流程。返回的 `output.model` 表示请求模型，若其他 Mod 做模型路由，最终请求以宿主记录为准。
原先的 `/claw-review` 是独立后台 Agent 检视命令，使用说明如下，两种入口的完成语义不同。

需要本机已配置可用模型、Autobiz 为 Git 项目，并运行本开发分支的 V6 版本。
在“自定义助手 → 添加功能 → 我已添加”选择“从文件夹安装”，导入 `examples/mods-review-agent`，
核对源码与权限。回“助手组合”选择这个来源，保存后“应用到当前对话”并确认。
安装不等于当前聊天已启用；保存、应用都不会自动发送任务。
可以从尚未发送过模型消息的新会话直接使用；这些启动命令走普通任务队列，获得真实线程租约，
启动后子任务独立运行。即时查询命令 `/claw-review-status` 只读状态，不启动任务。

1. 对已跟踪的 Autobiz 文件保留一小段未暂存修改。
2. `/claw-review concise working`：选择简短检视角色，只看明显逻辑问题。
3. 批准实际 `git diff` 读取，再批准独立子 Agent 启动。审批展示的是这次真实参数。
4. 命令返回启动 ID 后，子任务继续执行；输入 `/claw-review-status` 查看运行状态和结果。
5. `/claw-review strict working`：对相同差异选择更全面的正确性、权限和失败路径检视。
6. 只想检视暂存区时，使用 `/claw-review strict staged`。

这里的自定义体现在真实角色选择和范围选择：插件先注册两个不同角色，随后 `agent.spawn`
选择对应定义，而不是给同一个命令随意换一句展示文字。你可以修改 `roles` 的注册配置、
增加领域检视者、调整 maxTurns，或加入前置 Git 检查和人工关卡。

本例不给子任务任何工具，保证只分析已经读到的差异；它不修改文件、不提交，也不声称运行过
测试。模型回答可能不同，但验收依据是实际 Git 参数、子任务 ID、选择的角色和最终完成结果，
不是要求两次回答一定使用不同措辞。超过 48000 字符明确拒绝，不把截断差异冒充完整检视。

注册和结果属于当前插件会话；重载或撤权会取消其后台资源，重新注册角色，清空本例的内存结果。
关闭应用也不会恢复这次子任务。正式业务的步骤历史、失败重试和人工关卡请使用已有 Autobiz 项目流程。
