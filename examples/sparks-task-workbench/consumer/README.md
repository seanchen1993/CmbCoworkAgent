# 个人任务工作台：独立界面包

先安装并在同一聊天授权 `../provider` 与本目录。启用后打开“个人任务工作台”，使用“启动实际任务”，在表格中核对真实状态；运行时可取消。示例不使用模型或真实外部服务。

此包只通过 `$.platform` 发现和调用 `task-workbench-provider/tasks@1.0.0`，可在注册参数 `ref` 中换成实现相同协议的其他提供方。平台源码没有示例名称判断。

静态 `on.capability` 的 `presentation` 注册页面、导航、侧栏、操作入口及设置。`open` 动作才打开原生受控 Pane；`close` 仅取消本包的刷新计时器并退订，不结束另一个包已经启动的任务。关闭、切换和隐藏不会重建原聊天。关闭清理失败会显示宿主诊断，而不会假称资源已经释放。

表格、树、图表、列表、日志和表单都是受控数据组件。表单回调收到有界 JSON 字符串；宿主先验证字段，再使用原有回调凭据调用作者。保存的标题属于该聊天的私有设置。

任务动作沿原有文件、进程权限及用户审批执行。消费方与提供方都须有动作声明需要的权限；跨包调用不会继承提供方全部权限。切换工作区或聊天不能通过自行传目标 ID 获取别处状态。未知动作结果应检查真实状态，不使用新请求键自动重跑。

工作台的“核对通知样式”和“核对输入建议”按钮分别进入真实通知与输入建议处理链。可在“行为设置”预览两个替代作者包的冲突、选择一个并确认应用，再用按钮核对显示；停用行为后重新点击即可核对原生呈现。按钮不会发送聊天消息或创建任务。

消费方的 `task-start`、`task-cancel` 是真实转发动作，静态声明提供方需要的完整权限；表单通过消费方动作再调用提供方，用户批准时可以看到跨包用途。缺少任一方权限会拒绝，不会靠提供方授权绕过消费方检查。默认任务使用已安装的 `node` 读取并列出工作区最多 16 个真实文件的属性；可通过参数 `argv` 指定另一个获准的本地任务。
