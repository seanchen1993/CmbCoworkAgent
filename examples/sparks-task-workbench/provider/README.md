# 独立任务提供包

此包只提供 `task-workbench-provider/tasks@1.0.0`。独立消费包通过
`$.platform.read/subscribe/poll/act` 使用它，不导入此包源码，也不继承它的权限。
将两个包加入同一聊天并批准当前源码。发现列表不会启动进程或模型。

`start` 输入为 `{taskId, argv, title?, path?, text?}`，`argv` 是实际进程参数数组，
`path` 可选，存在时先通过宿主已授权 `fs.write` 写入文件。进程沿现有沙箱、工作目录、
进程确认和资源归属执行。消费者同样必须批准所需文件、进程、定时器及状态权限。

`start` 返回 `running` 只表示任务已登记。之后读取能力状态中的任务列表核对真实结果。
一次受控定时回调执行任务并发布输出；没有自建 Agent 循环。最多保留 8 项、每项最后
1200 字符输出，宿主另有限制状态和订阅预算。

`cancel` 输入 `{taskId}`，等待原进程流实际关闭及后台回调结束后才返回。
停用、升级、关闭聊天沿既有资源清理路径取消任务。源失效或应用重启后的旧状态显示
`unknown`，不会自动重启任务。重复 `requestKey` 返回原回执；结果未知时必须核对实际
文件和进程，不要换键盲目重放。
