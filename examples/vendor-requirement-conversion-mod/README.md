# 独立业务的需求转换与技能替换样例

此来源与 AutoBiz 无关，配合 `examples/vendor-onboarding-mods` 验证同一套创造者改造与组装接口。

目标流程：原始需求 → 需求转换 → 主体资料 → 准入报告。需求转换新增独立产物
`normalized-request.json`；主体资料替换成实际消费该产物的 Skill，保留原 `dossier.json`
Schema、原准入知识、配置和宿主阶段检查。只有结构正确且检查通过的真实产物才能推进状态。

使用创造者的工作流改造操作前插 `vendor.requirement-convert`，并替换
`vendor.dossier` 的 Skill。新来源需经检查、原生试用批准、验证和安装确认。
普通同名组合仍拒绝重复模块，只有绑定两端精确来源摘要的显式替换才可生成新候选。
修改已安装源码不会让旧项目自动切换版本；旧项目保留其冻结快照，应创建新的插件版本与项目验证。

`run.mjs` 是回归验收使用的确定性执行器，通过真实子进程读写产物，不模拟远程模型。
它读取候选插件中保留的原知识文件及明确配置，只写工作区产物，不直接修改项目数据库。
实际使用时，三个 Skill 仍由原生 Agent、权限和 Hooks 生命周期执行。
