# 半成品 Vue 前后端联调示例

这是交给模型完成的源码，**不是已经修好的成品**。页面布局可打开，接口与部分交互待实现，
初次 `npm test` 失败是预期结果。使用本地 Vue 3.5.24 global build（许可证见 vendor），
不是 Vite/SFC 工程。Node.js 22+ 即可，无需安装依赖、联网下载或配置真实账号。

1. 将整个目录解压到可写位置；聊天工作目录选择这个目录。
2. 在应用中启用“前后端联调工作台”。在聊天顶部填写源码目录。
3. 文档填写本目录 `docs/api-correct.txt` 的完整路径，页面填写 `http://127.0.0.1:4179/`。
4. 点击“补齐代码并联调”。目标可填“完成 TASK.md 的全部验收，实际改代码、启动、浏览器复测”。
5. 在聊天看真实执行与必要权限提示。最终按 TASK.md 检查，并在浏览器保留页面查看结果。

内置浏览器需先在应用控制配置中启用 Agent 控制；首次启用后重启应用。
模型可以读取 package.json 自动发现命令：`npm run dev` 启动；`npm run build` 检查语法并
复制静态资源到 dist；`npm test` 运行真实 HTTP 接口与前端 adapter 的验收断言。
测试不是浏览器交互的替代，筛选/分页/详情仍需模型在内置浏览器验证。

可先双击 `start-demo.cmd` 看未接入的页面骨架；保持终端开启，Ctrl+C 停止。默认端口4179，
占用时不会杀其他程序；换端口可先设置 `WORKBENCH_DEMO_PORT`，同时修改工作台页面地址。
应用重启不会替你启动这个 Node 服务。不要同时启动旧版同端口演示。

进阶挑战：将接口文档改为 `docs/api-challenge.txt` 或 `/api-docs`，其中有意混入错误字段、
枚举和金额单位。模型应对照实际响应发现冲突、说明证据，而不是修改文档或后端作弊。
首次试用请用正确版，以便体验从实现到联调的完整流程。

仅 src/** 和必要页面样式属于本次开发范围。server.cjs 是固定的9类GET mock，
tests/** 是验收标准，docs/** 是外部提供契约；均不应由本次前端任务改写。
本包不含完成版源码，重复试用时请重新解压原ZIP到一个新目录。
