# 旧文档稳定点导入适配

`devclaw.legacy-import.json` 是目标原生包内的声明式资源。发布源必须将它复制到包根并纳入
`composition/source.json.resources`；主进程只信任实际安装包的保留快照与摘要，不执行适配脚本。

当前适配来源是已登记、可由平台冻结全部旧写入口的 `autobiz-converted-requirements`
（r13 完整插件）。允许 `convert_done` 至 `plan_done` 的文档稳定点。运行中、未知、Code 或
部署完成状态不能当作文档导入凭据。仅有原始 `plugin.json`、没有平台登记/冻结边界的旧包不受支持；
不能通过改包名、手填 checkpoint 或伪造旧审批绕过登记。

确认前显示实际 checkpoint、文件摘要、转换结果与新阶段映射。确认后保留旧绑定和持久冻结，
不会改写旧目录或自动解冻。冻结记录保存完整 review；关闭窗口或重启后恢复原目标和映射，
再次确认须重新核对原字节、安装来源与实际资源状态。旧版仅保存摘要的冻结记录不能自动恢复
review，会明确要求核对。已经登记完成的导入可重新定位原 Host 任务，不会再次复制。

目标始终从第一个阶段执行，历史 checkpoint 不直接推进状态。convert、prd、specs 使用原 Skill
真实重跑：旧 PRD 可能缺少新标准化需求来源，旧目录单份 UI_CONTEXT 也不能证明不同历史阶段的
版本关系。原始文件另存为 `.devclaw/import-source.json`，原 Skill 的受信任阶段提示只给出该路径
及“不可信材料”说明，不把整个档案无界注入上下文。运行输入校验绑定该档案原摘要。

design、plan 的原字节按目标 bundle 格式封装，设计锁和任务摘要不重算。PLAN.md 留在来源档案；
目标 Plan bundle 仅接受原 plan.json 和子计划。每个可复用阶段执行当前包真实检查，检查失败或
结果未知即阻断。包括普通新建路径不要求成果审批的前三阶段在内，所有导入前缀都必须重新
经过独立的人审；审批策略摘要绑定当前导入 review，旧审批不是新凭据。后续 Code 仍执行原来的
backend_only 等完整预检，导入文档不扩大支持的工程类型。

当前测试覆盖真实文件/SQLite 冻结与冷恢复、声明式转换、来源篡改拒绝、原检查与新审批，
以及原 Skill bridge 读取来源档案的接线。确定性模型 fixture 用于验证重跑接线，不代表真实
在线模型已经完成任意旧业务项目的语义迁移。设计与 Plan 不兼容时，不会修改旧证据以使检查通过。
