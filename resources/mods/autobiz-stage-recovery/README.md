# AutoBiz 插件侧阶段恢复适配器

此目录是插件作者资源。平台通过 `devclaw.stage-recovery-adapter.json` 读取通用协议，不按插件名称识别或自动注入能力。

适配器实际调用原插件的 `hooks/rollback_stage.py --dry-run/--apply --json`，使用 `PLUGIN_WORKSPACE`、`PROJECT_DIR`、`FEATURE_ID` 定位独立副本。原脚本继续负责阶段状态、产物归档、流程语义及校验；适配器不直接写 checkpoint，也不生成校验通过标记。

原生准备与执行流程：

1. 只读检查原生试用已经结束，物理进程已确认退出，冻结插件、配置、知识与上下文身份。
2. 展示精确插件、适配器及输入摘要；用户明确批准运行计划命令。
3. 完整复制受限项目输出目录，由插件适配器重定位项目内引用并运行原脚本生成真实计划。
4. 展示计划及受影响产物，再次确认后在受限 Windows 沙箱执行原脚本，验证真实状态和知识、上下文保留情况。
5. 复用原生试用 owner 接管独立副本，重新进行配置、上下文及来源审批；继续运行时不再调用项目、需求初始化脚本。

执行结果未知时，平台保留原准备入口并阻止重新准备。只有原生记录证明原 apply 的实际退出码为 0，用户重新批准后，才允许运行 verify 并恢复原生接管；不会重放 apply。文件修改、进程状态不确定或输入发生变化均不能冒充恢复成功。

原生确认接管后，未启动的恢复项目具有独立的配置、知识副本和上下文绑定。应用重启后，用户重新确认核实该副本即可继续；原项目之后的产物、配置、知识变化不会撤销已经完成的独立接管。尚未确认接管的未知操作仍须严格匹配原输入。敏感配置通过原生机制重新密封绑定，不写入适配器请求或普通上下文，也不继承原项目的执行授权。已经启动的恢复项目不能通过此入口再次重置。

若环境或沙箱准备失败且命令尚未启动，原生记录将其标为准备失败；修复环境后可以重新检查、准备并重新批准。已经实际启动而退出结果未知的命令保持未知保护，不以进程消失推断成功或未执行。

当前配置为 `codeSource: keep`。存在 `.git`、活动执行、非空并行 worktree 记录或外部仓库映射时，必须明确阻断并重新绑定；不复制 Git 指针、不清理原 worktree、不修改原仓库。完整 Git 源码恢复需要独立私有 clone 与仓库映射协议，不能据此声明已经支持。

组装包必须通过所选扩展的 `stageRecoveryAdapter` 字段与 `resources` 声明携带适配器，并重新生成完整锁文件。不能向已有已锁定 ZIP 直接追加脚本。显式重建工具：

```text
npx tsx scripts/prepare-autobiz-stage-recovery-source.ts <只读来源> <新的输出目录> <已有扩展ID> <新的插件名称>
```

具体命令参数以工具的 usage 为准。原始来源、既有插件、Hooks 和 board_core 不会被原地修改。
