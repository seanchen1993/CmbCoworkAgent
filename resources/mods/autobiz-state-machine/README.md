# AutoBiz 可执行状态扩展

本组件是现有 Function Mods SDK 上的业务扩展，不需要新增状态机 SDK 或平台专用 API。
它作为业务 catalog 的常驻扩展加入完整 AutoBiz 插件，原业务模块、依赖闭包、组合源码、
资源锁、知识配置及原 Hooks 保留。

`register.ts` 注册读取、预检、推进和只读对账工具及对应 slash 命令，并在技能激活时
提供状态推进规则。`compiled_contract.py` 读取原编译器针对当前 Feature 的实际有效流程；
`graph.ts` 在隔离 JavaScript 运行时根据该流程选择业务边，不固定阶段数量。
`adapter.py` 真正调用原 AutoBiz 业务校验，
`commit.py` 在准备结果后持有 Windows 本地 NTFS 双文件独占句柄，写入规范 state.json
及 STATE.md。`journal.py` 持久记录本次请求和物理回执。未知结果不自动重放。

辅助 Skill `autobiz-mod-state-control` 提供使用说明，参见 [SKILL.md](SKILL.md)。读取、
预检、执行和对账仍经过现有原生命令权限，安装或启用组件不会自动批准进程。

新增步骤通过业务 catalog 声明 Skill、输入输出、必要校验、状态和依赖；平台通用
创造者负责受审的步骤插入或替换，插件状态 Mod 复用原编译器和唯一状态写入器。
插件命名空间内的 `validatorBindings` 提供新增业务校验；声明支持的 JSON Schema
断言会真实执行，不支持的断言明确失败。原检查、知识和配置不会被空成功实现替代。

合法的相邻边仍必须通过原 Python transition/lifecycle、产物、Hooks 与 postcheck
校验。源码或有效流程变化会使旧证据失效。新增受检产物进入后继步骤时还需核对已
提交的产物摘要及当前生产步骤完整有效契约（包括 Schema、版本和校验绑定），不能在
检查后替换内容，也不能通过工作区覆盖配置改变契约后复用旧证据。已发布的严格衔接
不会因删除 Schema 或校验绑定而退回旧检查路径；需要重新执行生产步骤校验。
公共阶段回执保持 `devclaw.stage-check/v1` 的既定字段；严格衔接标识由提交器从真实
已检节点派生，存入插件私有物理回执，并与本次阶段证据一同绑定摘要。
此新增严格衔接目前支持不超过 256 KiB 的普通文件和结构化 JSON，不支持目录或大型
产物跨步骤认证。未知结果只读对账，不能重放提交。

SDK 进程调用不会自动重放普通工具的全部 Hooks。状态 Mod 因而显式复用原候选摘要
规则：当前或目标处于原校验定义的已验证状态，并存在含 `diffDigest` 的原
`VERIFY_DECISION.json` 时，比较原计算器得到的实际代码摘要。准备过程绑定决策文件
原始字节和实际摘要，持锁校验及收到提交确认后、写入状态前再次核对；任一变化阻止
提交。这里执行只读验证，不在状态锁内触发原 Hook 的回退副作用。原普通工具 Hook
仍保留并按自身条件执行；本组件不会据文件存在或进程返回码宣称所有业务校验通过。

初始化、新建 Feature 仍使用原入口，并读取重新组装后的流程起点；可选分支的选择、
历史回退和既有项目状态迁移不因增加一个步骤自动完成。原 Hooks 按其真实事件与条件
执行，不能宣称所有 Hooks 在每次动作中均执行。归档物理移动与 checkpoint 推进不构成
统一原子事务。插件提供普通工具调用的引导和明确可识别的旧 writer 调用拦截，不承诺
拦截任意脚本或直接文件写入，也不获得宿主权威状态或绝对文件隔离。
